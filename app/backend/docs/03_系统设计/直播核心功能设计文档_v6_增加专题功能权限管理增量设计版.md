## 1. 核心设计原则 (Core Principles)

本设计严格遵循《直播核心功能设计文档_v6_增加权重设计版(非独立版).md》的五条核心原则，任何代码实现均不得违背：

1.  **Public 开放原则**：标记为已发布（`status='published'`）的专题，必须允许**匿名用户**访问，以支持 SEO、分享和传播。
2.  **Private 隐私原则**：标记为草稿或已归档（`status='draft'` 或 `status='archived'`）的专题，仅 **创建者（user_id）** 和 **Admin** 可见。
      * *关键约束*：对于无权访问的 Private 专题，必须返回 **404 Not Found**，严禁返回 403，以防止恶意用户通过枚举 ID 探测资源的存在性。
      * *字段说明*：`user_id` 字段存储的是用户的 `public_id`（从JWT的`user_id`字段提取），创建者即为资源的Owner。**创建者包括Regular用户自己创建的专题**，Regular用户可以管理（修改、删除、上传横幅等）自己创建的专题。
3.  **写操作严控原则**：所有 CUD（创建、修改、删除）及敏感信息读取，必须**强制登录**（Strict Auth）。
4.  **管理员上帝视角**：Admin/SuperAdmin 角色拥有全系统的读写权限，不受资源 `status` 属性的限制。
5.  **职责分层原则（架构红线）**：
      * **API 层 (Controller/Dependency)**：仅负责 **Authentication (认证)** —— 解析"你是谁"（User 还是 Anonymous）。
      * **Service 层 (Domain Logic)**：全权负责 **Authorization (鉴权)** —— 判定"你能看吗/你能改吗"。
      * **CRUD 层 (Repository/Data Access)**：负责在 **SQL 层面应用权限过滤逻辑** —— 禁止内存过滤，业务筛选条件与权限过滤条件使用 AND 关系组合。
**⚠️ 专题功能特殊说明**：

专题功能的可见性判断基于`status`字段而非`is_private`字段：
- `status = 'published'` → 公开资源（相当于`is_private = false`）
- `status = 'draft'` 或 `status = 'archived'` → 私有资源（相当于`is_private = true`）

## 2. 身份模型与鉴权策略 (Identity & Strategy)

### 2.1 用户状态模型

系统基于《用户模块》的 JWT 体系，将请求上下文分为三类状态（与Room模块完全一致）：

| 状态 | 判定条件 (API 层行为) | 权限基线 |
| :--- | :--- | :--- |
| **Anonymous (匿名)** | 请求头 **无 Token** 或 Token 为空 | 仅可读 `status='published'` 的专题 |
| **Regular (普通用户)** | 携带有效 Token，Role=`REGULAR` | 可读 Published + 读写 Own 专题 |
| **Admin (管理员)** | 携带有效 Token，Role=`ADMIN/SUPERADMIN` | 全局读写，无视 status 限制 |

### 2.2 双轨鉴权模式 (Dual Auth Patterns)

为了在不拆分接口的前提下支持匿名访问，API 层引入两种依赖注入模式（与Room模块完全一致）：

#### 模式 A：Strict Auth (强制鉴权)

  * **行为**：
      * 无 Token → **401 Unauthorized**
      * Token 无效 → **401 Unauthorized**
  * **适用场景**：所有写操作（创建、修改、删除专题/分类/关联）。
  * **对应依赖**：`get_current_user` (v6 原有逻辑)。

#### 模式 B：Optional Auth (可选鉴权)

  * **行为**：
      * 无 Token → 返回 `None` (视为匿名用户)。
      * **Token 无效/过期** → **401 Unauthorized**。
      * *注意*：这里必须报错，**严禁**降级为匿名用户。否则已登录用户在 Token 过期时会莫名其妙看不到自己的私有专题，导致前端状态错乱。
  * **适用场景**：专题详情、专题列表、分类列表、分类下的直播间列表。
  * **对应依赖**：`get_current_user_optional` (新增逻辑)。

## 3. 全量 API 接口改造详单 (API & Service Matrix)

**实施说明**：请对照下表，逐一修改 Controller 的依赖注入和 Service 的方法签名。

### 3.1 专题管理模块 (Topic Domain)

该模块负责处理专题的元数据。核心字段为 `status` (ENUM: draft/published/archived) 和 `user_id`（存储创建者的public_id）。

**权限映射关系**：
- `status = 'published'` ↔ `is_private = false`（公开）
- `status = 'draft'` 或 `status = 'archived'` ↔ `is_private = true`（私有）

#### 接口 1: 创建专题

  * **Path**: `POST /api/v1/topics`
  * **Auth 策略**: **Strict** (强制登录)
  * **API 层依赖**: `current_user: Dict = Depends(get_current_user)`
  * **Service 方法签名**:
    ```python
    async def create_topic(
        self,
        data: TopicCreate,
        user_id: UUID,
        role: str
    ) -> Topic:
        """
        创建专题
        
        Args:
            data: 创建专题的数据
            user_id: 当前用户的public_id（从JWT的user_id字段提取）
            role: 当前用户的角色
            
        Returns:
            创建的专题对象
        """
    ```
  * **权限逻辑**: 所有登录用户均可创建专题，`topic.user_id` 自动设置为 `user_id`（创建者即owner）
  * **实现要点**:
    1. 生成专题UUID
    2. 设置 `topic.user_id = user_id`（创建者即owner）
    3. 设置 `status` 默认值（根据请求体或默认为'draft'）
    4. 调用 CRUD 层创建记录

#### 接口 2: 上传专题横幅

  * **Path**: `POST /api/v1/topics/{topic_id}/banner`
  * **Auth 策略**: **Strict** (强制登录)
  * **API 层依赖**: `current_user: Dict = Depends(get_current_user)`
  * **Service 方法签名**:
    ```python
    async def upload_topic_banner(
        self,
        topic_id: UUID,
        file: UploadFile,
        user_id: UUID,
        role: str
    ) -> Dict[str, str]:
        """
        上传专题横幅（专题创建者包括Regular用户，或Admin）
        
        Args:
            topic_id: 专题ID
            file: 上传的文件
            user_id: 当前用户的public_id
            role: 当前用户的角色
            
        Returns:
            {"topic_id": str, "banner_url": str}
            
        Raises:
            TopicNotFoundException: 专题不存在（404）
            PermissionDeniedException: 无权上传（403）
        """
    ```
  * **权限逻辑**: 
    1. 检查专题是否存在
    2. 调用 `_check_write_permission(topic, user_id, role)`（专题创建者包括Regular用户，或Admin）
    3. 执行文件上传逻辑

#### 接口 3: 获取专题列表 (核心修改)

  * **Path**: `GET /api/v1/topics`
  * **Auth 策略**: **Optional** (可选鉴权)
  * **API 层依赖**: `current_user: Optional[Dict] = Depends(get_current_user_optional)`
  * **Service 方法签名**:
    ```python
    async def list_topics(
        self,
        pagination: PageParams,
        status: Optional[str] = None,
        title: Optional[str] = None,
        topic_id: Optional[UUID] = None,
        user_id: Optional[UUID] = None,
        role: Optional[str] = None,
        current_user_id: Optional[UUID] = None
    ) -> Tuple[List[Topic], int]:
        """
        获取专题列表（支持匿名访问）
        
        Args:
            pagination: 分页参数
            status: 状态筛选（可选）
            title: 专题标题筛选，支持模糊匹配（可选）
            topic_id: 专题ID筛选，精确匹配（可选）
            user_id: 用户ID筛选，用于业务筛选特定用户的专题（可选）
            role: 当前用户的角色（匿名时为None，用于权限过滤）
            current_user_id: 当前用户的public_id（匿名时为None，用于权限过滤）
            
        Returns:
            (专题列表, 总数)
        """
    ```
  * **权限逻辑与 SQL 策略**:
      * **Admin**: `SELECT * FROM topics WHERE ... (业务筛选条件) ...` (无权限过滤，可查看所有状态)
      * **Regular User**: `SELECT * FROM topics WHERE (status='published' OR (status IN ('draft', 'archived') AND user_id={current_user_id})) AND ... (业务筛选条件) ...`
      * **Anonymous**: `SELECT * FROM topics WHERE status='published' AND ... (业务筛选条件) ...`
      * *业务筛选条件*：包括title（模糊匹配）、topic_id（精确匹配）、status（状态筛选）、user_id（用户筛选）等。
      * *注意*：列表查询的筛选和权限过滤必须在 Repository 层通过 SQL 过滤，禁止查出所有数据在内存过滤（性能陷阱）。业务筛选条件与权限过滤条件使用AND关系组合。
  * **实现要点**:
    1. API层提取：`current_user_id = UUID(current_user.get("user_id")) if current_user else None`
    2. API层提取：`role = current_user.get("role") if current_user else None`
    3. API层提取查询参数：`title`（专题标题，可选）、`topic_id`（专题ID，可选）、`status`（状态筛选，可选）、`user_id`（用户ID筛选，可选）
    4. 调用Service层并传递所有参数（包括业务筛选参数和权限参数）
    5. CRUD层先应用业务筛选条件（title、topic_id、status、user_id），再根据role和current_user_id构建权限过滤条件（AND关系）

#### 接口 4: 获取专题详情 (核心修改)

  * **Path**: `GET /api/v1/topics/{topic_id}`
  * **Auth 策略**: **Optional** (可选鉴权)
  * **API 层依赖**: `current_user: Optional[Dict] = Depends(get_current_user_optional)`
  * **Service 方法签名**:
    ```python
    async def get_topic_detail(
        self,
        topic_id: UUID,
        user_id: Optional[UUID] = None,
        role: Optional[str] = None
    ) -> Topic:
        """
        获取专题详情（支持匿名访问）
        
        Args:
            topic_id: 专题ID
            user_id: 当前用户的public_id（匿名时为None）
            role: 当前用户的角色（匿名时为None）
            
        Returns:
            专题对象（包含层级化的分类和直播间）
            
        Raises:
            TopicNotFoundException: 专题不存在或无权访问（404）
        """
    ```
  * **权限逻辑流程**:
    1.  `topic = await self.crud.get(topic_id)`，若不存在抛 `TopicNotFoundException`
    2.  调用 `self._check_topic_visibility(topic, user_id, role)`
    3.  若检查不通过，**抛出 TopicNotFoundException (404)**（隐藏私有资源的存在性）

    5.  返回数据（包含层级化结构）
  * **实现要点**: 见 4.2 节的 `_check_topic_visibility` 守卫函数
  * **⚠️ 重要**：`TopicNotFoundException` 应继承自 `NotFoundException`，以保持与Room模块的一致性

#### 接口 5: 更新专题

  * **Path**: `PATCH /api/v1/topics/{topic_id}`
  * **Auth 策略**: **Strict** (强制登录)
  * **API 层依赖**: `current_user: Dict = Depends(get_current_user)`
  * **Service 方法签名**:
    ```python
    async def update_topic(

        topic_id: UUID,
        data: TopicUpdate,
    ```

```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from typing import Optional, Dict

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token", auto_error=False)

# 1. 强制鉴权 (Strict) - 用于写操作
async def get_current_user(token: str = Depends(oauth2_scheme)) -> Dict:
    """
    强制鉴权依赖注入（与Room模块完全一致）
    
    Returns:
        用户信息字典 {"user_id": str(UUID), "role": str, "username": str}

        HTTPException(401): Token缺失或无效
    """
    if not token:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Missing authentication credentials",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    user = verify_token_service(token)
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Could not validate credentials",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return user

# 2. 可选鉴权 (Optional) - 用于读操作
async def get_current_user_optional(
    token: Optional[str] = Depends(oauth2_scheme)
) -> Optional[Dict]:
    """
    可选鉴权依赖注入（与Room模块完全一致）
    
    Returns:
        - None: 匿名用户（无Token）
        - Dict: 用户信息字典（有有效Token）

        HTTPException(401): Token无效或过期（但不能降级为匿名）
    """
    # 场景 A: 无 Token → 返回 None，视为匿名用户
    if not token:
        return None
    
    # 场景 B: 有 Token → 必须验证
    user = verify_token_service(token)
    if not user:
        # 场景 C: Token 过期/伪造 → 必须报错！
        # 严禁降级为匿名，否则已登录用户看不到自己的私有资源
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid or expired token",
            headers={"WWW-Authenticate": "Bearer"},

    验证JWT Token并返回用户信息（与Room模块完全一致）

    try:
        import jwt
        from app.core.config import settings
        
        payload = jwt.decode(
            token,
            settings.JWT_SECRET_KEY,
            algorithms=["HS256"]
        )

        if payload.get("type") != "access":
            return None

        user_info = {
            "user_id": payload.get("user_id"),  # 与v6主文档一致
            "role": payload.get("role", "REGULAR"),  # 默认为REGULAR
            "username": payload.get("username"),
        }
        
        # 验证必要字段
        if not user_info["user_id"]:
```

### 4.2 Service 层通用守卫函数

```python
# app/services/topic_service.py
from typing import Optional
from uuid import UUID
from app.core.exceptions import (
    NotFoundException,
    PermissionDeniedException,
)
from app.exceptions import TopicNotFoundException  # TopicNotFoundException继承自NotFoundException
from app.models.topic import Topic

class TopicService:
    """专题服务（包含权限守卫函数）"""
    
    def _check_topic_visibility(
        self,
        topic: Topic,
        user_id: Optional[UUID],
        role: Optional[str]
    ) -> None:
        """
        统一的专题可见性校验逻辑（基于status字段）
        
        Args:
            topic: 专题对象
            user_id: 当前用户的public_id（从JWT的user_id字段提取，匿名时为None）
            role: 当前用户的角色（匿名时为None）
            
        Raises:
            TopicNotFoundException: 专题不存在或无权访问（404）
        """
        # 1. 已发布专题：直接通过（相当于is_private=false）
        if topic.status == 'published':
            return
        
        # 2. 草稿/已归档专题且未登录：拒绝（返回404隐藏存在性）
        if not user_id:
            raise TopicNotFoundException("Topic not found")
        
        # 3. 管理员：上帝视角通过
        if role in ['ADMIN', 'SUPERADMIN']:
            # ✅ 记录Admin查看Private资源的审计日志（INFO级别）
            if topic.user_id != user_id:
                logger.info(
                    f"Admin查看Private专题: admin={user_id}, role={role}, "
                    f"topic_id={topic.id}, owner={topic.user_id}, status={topic.status}"
                )
            return
        
        # 4. 资源创建者：通过
        # 注意：topic.user_id存储的就是创建者的public_id
        if topic.user_id == user_id:
            return
        
        # 5. 其他已登录用户：拒绝（返回404隐藏存在性）
        raise TopicNotFoundException("Topic not found")
    
    def _check_write_permission(
        self,
        topic: Topic,
        user_id: UUID,
        role: str
    ) -> None:
        """
        写操作权限校验（修改/删除）
        
        Regular用户可以修改/删除自己创建的专题（topic.user_id == user_id），Admin可以修改/删除所有专题。
        
        Args:
            topic: 专题对象
            user_id: 当前用户的public_id
            role: 当前用户的角色
            
        Raises:
            PermissionDeniedException: 无权修改（403）
        """
        # 管理员：上帝视角通过
        if role in ['ADMIN', 'SUPERADMIN']:
            return
        
        # 资源创建者：通过
        # 注意：topic.user_id存储的就是创建者的public_id
        if topic.user_id == user_id:
            return
        
        # 其他用户：拒绝（返回403，因为已登录）
        raise PermissionDeniedException(
            "You don't have permission to modify this topic"
        )
```

### 4.3 Repository 层查询优化

**原则**：尽可能下推过滤逻辑到数据库，避免内存过滤。

```python
# app/crud/topic.py
from typing import Optional, List, Tuple
from uuid import UUID
from sqlalchemy import select, or_, and_, func
from sqlalchemy.ext.asyncio import AsyncSession
from app.models.topic import Topic

class TopicCRUD:
    """专题数据访问层"""
    
    async def get_multi(
        self,
        session: AsyncSession,
        current_user_id: Optional[UUID],  # ← 修改：权限参数（当前用户的public_id）
        role: Optional[str],  # ← 权限参数（当前用户的角色）
        page: int,
        size: int,
        status: Optional[str] = None,  # ← 业务筛选参数
        title: Optional[str] = None,  # ← 新增：业务筛选参数（专题标题）
        topic_id: Optional[UUID] = None,  # ← 新增：业务筛选参数（专题ID）
        user_id: Optional[UUID] = None  # ← 业务筛选参数（筛选特定用户的专题）
    ) -> Tuple[List[Topic], int]:
        """
        查询可见的专题列表（带权限过滤和业务筛选）
        
        Args:
            session: 数据库会话
            current_user_id: 当前用户的public_id（匿名时为None，用于权限过滤）
            role: 当前用户的角色（匿名时为None，用于权限过滤）
            page: 页码（从1开始）
            size: 每页大小
            status: 状态筛选（可选，业务筛选条件）
            title: 专题标题筛选，支持模糊匹配（可选，业务筛选条件）
            topic_id: 专题ID筛选，精确匹配（可选，业务筛选条件）
            user_id: 用户ID筛选，筛选特定用户的专题（可选，业务筛选条件）
            
        Returns:
            (专题列表, 总数)
        """
        # 构建基础查询
        stmt = select(Topic)
        
        # 1. 先应用业务筛选条件
        business_filters = []
        if title:
            # 专题标题模糊匹配（不区分大小写）
            business_filters.append(Topic.title.ilike(f'%{title}%'))
        if topic_id:
            # 专题ID精确匹配
            business_filters.append(Topic.id == topic_id)
        if status:
            business_filters.append(Topic.status == status)
        if user_id:
            business_filters.append(Topic.user_id == user_id)
        
        # 2. 再应用权限过滤条件（根据用户身份决定可见范围，独立于业务筛选条件）
        permission_filters = []
        if role in ['ADMIN', 'SUPERADMIN']:
            # 管理员：无权限过滤，可查看所有状态的专题
            pass
        elif current_user_id:
            # 普通用户：Published OR (Draft/Archived AND Own)
            # 无论业务筛选条件中是否指定了status，权限过滤都需要确保用户只能看到自己有权访问的专题
            permission_filters.append(
                or_(
                    Topic.status == 'published',
                    and_(
                        Topic.status.in_(['draft', 'archived']),
                        Topic.user_id == current_user_id
                    )
                )
            )
        else:
            # 匿名用户：Only Published
            permission_filters.append(Topic.status == 'published')
            # 如果业务筛选条件中指定了非published状态，与权限过滤条件（Only Published）冲突，结果集自然为空
        
        # 3. 合并业务筛选条件和权限过滤条件（AND关系）
        all_filters = business_filters + permission_filters
        if all_filters:
            stmt = stmt.where(and_(*all_filters))
        
        # 计算总数（必须应用相同的WHERE条件）
        count_stmt = select(func.count()).select_from(stmt.subquery())
        total_result = await session.execute(count_stmt)
        total = total_result.scalar_one()
        
        # 应用分页和排序
        stmt = stmt.order_by(Topic.created_at.desc())
        stmt = stmt.offset((page - 1) * size).limit(size)
        
        # 执行查询
        result = await session.execute(stmt)
        topics = result.scalars().all()
        
        return list(topics), total
```

## 5. 审计与安全补充 (Security & Audit)

### 5.1 安全机制

1.  **404 伪装机制**：
      * 在 Service 层，对于 `_check_topic_visibility` 失败的情况，必须抛出 `TopicNotFoundException`（继承自`NotFoundException`）。
      * 原因：如果返回 403，攻击者可以通过遍历 ID，根据返回码（404 vs 403）判断哪些 ID 是真实存在的私密专题。
      * **⚠️ 重要**：与Room模块保持一致，`TopicNotFoundException` 应继承自 `NotFoundException`，确保异常处理的一致性。

2.  **敏感操作审计**：
      * 以下操作建议记录审计日志（Audit Log）：
          * 管理员修改/删除非自己的专题
          * 管理员查看 Draft/Archived 专题的详情
          * 任何用户创建/修改/删除专题
          * 专题创建者管理分类和关联

3.  **缓存策略影响**：
      * Published 专题接口（匿名访问）非常适合 CDN 缓存或服务端缓存
      * Draft/Archived 专题接口（带 Token）**严禁**被公共 CDN 缓存
      * 在实现 `GET /topics/{id}` 时，需注意 `Vary: Authorization` 头的使用

### 5.2 双重权限过滤场景

专题功能中存在需要同时考虑专题权限和直播间权限的场景：

1. **获取分类下的直播间列表**：
   - 专题可见性：专题必须是published，或用户是专题Owner/Admin
   - 直播间可见性：直播间必须是public，或用户是直播间Owner/Admin
   - 实现：先检查专题可见性，再在查询直播间时应用Room模块的权限过滤

2. **获取直播间关联的专题列表**：
   - 直播间可见性：直播间必须是public，或用户是直播间Owner/Admin
   - 专题可见性：专题必须是published，或用户是专题Owner/Admin
   - 实现：先检查直播间可见性，再在查询专题时应用Topic模块的权限过滤
