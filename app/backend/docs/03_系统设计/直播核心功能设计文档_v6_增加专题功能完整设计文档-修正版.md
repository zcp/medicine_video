    finally:
        # 清理资源

### 7.3. 专题聚合模型 (新增)

为实现类似内容聚合页面的功能（例如，将多个直播间组织到一个带有统一横幅的活动下），我们引入一个独立于核心业务表的"组织层"。该模型由三个新表构成，它们负责定义内容的组织和呈现方式，而不会修改任何现有的表结构，完全遵循"开闭原则"。

#### **设计原则**:
* **组织与内容分离**: `topics` (专题) 和 `topic_categories` (专题内分类) 负责内容的组织结构；`live_rooms` 表依然只负责直播间自身的核心业务数据。
* **多对多关联**: 通过一个纯粹的关联表 `topic_category_rooms`，实现直播间与专题分类的灵活关联，允许同一个直播间被收录到多个不同的专题活动中。
* **规范一致性**: 新增各表严格遵循文档中已定义的 UUID 主键（应用层生成）、`TIMESTAMPTZ` 时间戳、ENUM 类型、命名规范等原则。
* **用户权限隔离**: 所有业务实体表包含 `user_id` 字段，通过JWT Token应用层验证保证引用完整性和数据隔离。

### 7.3.1. Schema DDL (修正版)

```sql
-- LiveCore Service - 专题聚合模型 Schema (V6 新增 - 修正版)

-- 枚举类型定义
CREATE TYPE topic_status AS ENUM ('draft', 'published', 'archived');

-- 表 4: topics (专题表 - 顶层实体)
CREATE TABLE topics (
    -- 核心标识 (在应用层通过 uuid.uuid4() 生成)
    id UUID PRIMARY KEY,
    
    -- 用户ID，通过JWT Token应用层验证保证引用完整性
    -- 由于采用微服务架构，user_id无法跨数据库外键关联，通过JWT Token验证用户存在性
    user_id UUID NOT NULL,
    
    title VARCHAR(100) NOT NULL,
    description TEXT,
    banner_url VARCHAR(255),
    
    -- 专题状态: draft(草稿), published(已发布), archived(已归档)
    status topic_status NOT NULL DEFAULT 'draft',

    -- 时间戳字段：使用数据库级默认值（对应 SQLAlchemy 的 server_default=func.now()）
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_topics_user_id ON topics(user_id);
CREATE INDEX idx_topics_status ON topics(status);
CREATE INDEX idx_topics_created_at ON topics(created_at DESC);

COMMENT ON TABLE topics IS '专题活动表，用于聚合多个分类和直播间，实现类似聚合页面的功能。';
COMMENT ON COLUMN topics.user_id IS '创建者用户ID，通过JWT Token应用层验证';
COMMENT ON COLUMN topics.status IS '专题状态: draft(草稿), published(已发布), archived(已归档)';

-- 表 5: topic_categories (专题内分类表 - 中层实体)
CREATE TABLE topic_categories (
    -- 核心标识 (在应用层通过 uuid.uuid4() 生成)
    id UUID PRIMARY KEY,
    
    topic_id UUID NOT NULL REFERENCES topics(id) ON DELETE CASCADE,
    name VARCHAR(50) NOT NULL,
    sort_order INT DEFAULT 0,

    -- 时间戳字段：使用数据库级默认值（对应 SQLAlchemy 的 server_default=func.now()）
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_topic_categories_on_topic_id ON topic_categories(topic_id);
CREATE INDEX idx_topic_categories_on_sort_order ON topic_categories(topic_id, sort_order);

COMMENT ON TABLE topic_categories IS '专题下的分类表，如按省份、按科室等。一个专题可以包含多个分类。';
COMMENT ON COLUMN topic_categories.sort_order IS '分类的显示顺序，数值越小越靠前';

-- 表 6: topic_category_rooms (关联表 - 关系层)
CREATE TABLE topic_category_rooms (
    -- 核心标识 (在应用层通过 uuid.uuid4() 生成)
    id UUID PRIMARY KEY,
    
    category_id UUID NOT NULL REFERENCES topic_categories(id) ON DELETE CASCADE,
    room_id UUID NOT NULL REFERENCES live_rooms(id) ON DELETE CASCADE,
    sort_order INT DEFAULT 0,
    
    -- 时间戳字段：使用数据库级默认值（对应 SQLAlchemy 的 server_default=func.now()）
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    -- 确保同一个直播间在一个分类下只关联一次
    UNIQUE (category_id, room_id)
);

-- 索引
CREATE INDEX idx_tcr_on_category_id ON topic_category_rooms(category_id);
CREATE INDEX idx_tcr_on_room_id ON topic_category_rooms(room_id);
CREATE INDEX idx_tcr_on_category_sort ON topic_category_rooms(category_id, sort_order);

COMMENT ON TABLE topic_category_rooms IS '专题分类与直播间的"多对多"关联表，用于定义聚合页面的内容结构。';
COMMENT ON COLUMN topic_category_rooms.sort_order IS '直播间在该分类下的显示顺序，数值越小越靠前';
```

### 8.X.1. 权限控制规则

* **失败响应示例** (`400 Bad Request` - 参数错误):
  ```json
  {
    "code": 4001,
    "message": "参数校验失败",
    "data": {
      "field": "room_ids",
      "error": "最多支持一次查询100个直播间"
    },
    "timestamp": "2025-10-15T11:05:05Z"
  }
  ```
* **实现流程描述**:
  1. 定义 FastAPI 路由函数，接收 Pydantic 模型 `BatchStatusRequest` 和数据库会话 `db`。
  2. **JWT Token验证**: 通过 `Depends(get_current_user)` 验证用户身份。
  3. **参数验证**: 检查 `room_ids` 列表长度不超过100（防止性能问题）。
  4. **批量查询直播间**: 查询 `live_rooms` 表确认所有直播间存在。
  5. **批量查询场次状态**: 
     - 查询 `live_sessions` 表，对每个 `room_id`，获取最新的场次。
     - 优先返回 `status = 'live'` 的场次，其次是 `status = 'scheduled'`。
  6. **批量查询观看人数**: 对于 `status = 'live'` 的场次，查询 `session_statistics` 表获取 `current_viewer_count`。
  7. **组装结果**: 为每个直播间构建状态对象。
  8. **日志记录**: 记录DEBUG级别日志，包含查询的直播间数量。
  9. **构建响应**: 返回批量状态列表。
