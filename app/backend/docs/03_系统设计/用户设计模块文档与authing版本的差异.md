# 用户模块设计文档版本差异对比 (修正版)

本文档根据您的反馈进行了修正，旨在更精确地对比两个版本的设计文档。
- **原始版本 (V1)**: `用户模块设计文档.md`
- **更新版本 (V2)**: `用户模块设计文档authing版.md`

---

## 1. 核心差异：认证体系与功能扩展

* **认证体系**: V2 最大的变化是引入了 **Authing** 作为统一身份认证服务，从而增加了对 SSO 和第三方社交登录（微信、Apple等）的支持。
* **功能完善**: V2 增加了手机号绑定功能，并对登录、OTP发送等核心认证流程进行了优化和增强。
* **安全强化**: V2 对密码策略进行了明确和强制性的定义。

---

## 2. 各章节详细差异

### 1. 概述 (Overview)

**变更**: V2 在模块职责中明确增加了通过 Authing 集成社会化身份源的说明。

* **V1**: 支持用户通过本地密码或社交媒体进行注册和登录。
* **V2**: 增加了“...并通过统一身份认证服务 (Authing) 集成多种社会化身份源（如微信、Apple 等）进行登录和账户绑定”。

### 2. 技术栈 (Tech Stack)

**新增**: V2 增加了一项新的技术选型，以支持与 Authing 服务的后端集成。

* **V2 新增**:
    | 分类 | 技术选型 | 用途说明 |
    | :--- | :--- | :--- |
    | **身份认证服务** | `authing-sdk-py` | 用于在后端安全地验证由 Authing 颁发的 id_token... |

### 3. 安全规范 (Security Specification)

**新增**: V2 为新增的 `sso-login` 接口增加了速率限制的要求。

* **V2 在速率限制列表中增加了**: `POST /api/v1/auth/sso-login (SSO 及第三方登录回调)`。

### 4. 数据库设计 (Database Design)

**变更**: `users` 表的物理结构未变，但 V2 更新了两个字段的注释，以反映与 Authing 的集成逻辑。

* **`social_provider` 字段注释**: V2 明确指出，通过 Authing 登录的用户，此字段统一记为 `'authing'`。
* **`social_id` 字段注释**: V2 明确指出，当 provider 为 `'authing'` 时，此字段存储 Authing `id_token` 中的 `sub` 字段。

### 6. API 接口规范

#### 1. 认证与验证码 (Authentication & Verification)

* **1.2 发送OTP验证码**:
    * **变更**: V2 对实现流程的描述更加严谨。它详细说明了需要对 `channel` 和 `scenario` 的组合进行校验（如绑定手机场景必须使用SMS通道），并根据不同场景（注册、重置密码、绑定手机）执行差异化的前置业务检查。V1 的描述则较为笼统。

* **1.3 用户登录**:
    * **变更**: V2 扩展了登录方式。
        * **V1**: `username` 字段仅支持用户名登录。
        * **V2**: `username` 字段支持 **用户名、邮箱或手机号** 三种格式登录，实现流程也相应更新。

* **1.6 修改密码 (用户已登录)**:
    * **强化**: 您指出的关键点在这里，V2 强化了密码安全策略。
        * **V1**: 请求体中只列出了 `current_password` 和 `new_password` 字段，未定义密码的具体规则。
          * **V2**: 在请求体描述中，明确增加了对 `new_password` 的 **强制性强度要求**（最小长度、大小写字母、数字、特殊字符）。
            新密码必须符合以下所有规则**：
              * 最小长度为8位。
              * 必须包含至少一个大写字母 (A-Z)。
              * 必须包含至少一个小写字母 (a-z)。
              * 必须包含至少一个数字 (0-9)。
              * 必须包含至少一个特殊字符 (例如: `!@#$%^&*()`)。
* **(新增) 1.8 SSO & 第三方登录 (Authing)**:
    * **新增**: 这是 V2 中 **真正新增** 的核心接口，是集成 Authing 的关键。
        * **Endpoint**: `POST /api/v1/auth/sso-login`。
        * **功能**: 接收 Authing 的 `id_token`，在后端进行验证，并实现用户的自动查找、绑定或创建，最终返回系统自身的业务 Token。

#### 2. 用户 (Users) - 公开接口

* **2.1 用户注册**:
    * **强化**: 与修改密码接口类似，V2 在此接口中也明确了密码强度要求。
        * **V1**: 请求体中未定义密码的具体规则，示例为 `"strongpassword123"`。
        * **V2**: 请求体中明确列出了与修改密码接口 **完全相同的密码强度规则**，并更新了示例为 `"StrongP@ssw0rd!"`。实现流程也增加了对该策略的校验步骤。
            新密码必须符合以下所有规则**：
              * 最小长度为8位。
              * 必须包含至少一个大写字母 (A-Z)。
              * 必须包含至少一个小写字母 (a-z)。
              * 必须包含至少一个数字 (0-9)。
              * 必须包含至少一个特殊字符 (例如: `!@#$%^&*()`)。
* **2.2 获取当前用户信息**:
    * **变更**: V2 的响应体中增加了手机号相关信息。
        * **V1**: 响应数据中不包含 `phone_number` 和 `is_phone_verified`。
        * **V2**: 响应数据中新增了 `phone_number` 和 `is_phone_verified` 字段。

* **(新增) 2.5 绑定手机号**:
    * **新增**: 这是 V2 中 **真正新增** 的用户功能接口。
        * **Endpoint**: `POST /api/v1/users/me/phone`。
        * **功能**: 允许已登录用户通过 OTP 验证码绑定或更换手机号。

### 7. API 接口总览列表

**变更**: V2 的总览列表准确地反映了上述 API 的增减变化。

* **V2 新增的端点**:
    * `POST /api/v1/auth/sso-login` (SSO & 第三方登录)
    * `POST /api/v1/users/me/phone` (绑定手机号)
* **V2 列表中存在，V1 中也存在的端点 (之前分析有误)**:
    * `POST /api/v1/users/me/password` (修改密码)
    * `POST /api/v1/auth/password-reset-request` (请求密码重置)
    * `POST /api/v1/auth/password-reset` (执行密码重置)
