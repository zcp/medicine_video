# 媒体文件路径问题分析与解决方案

**问题日期**: 2025-12-19  
**问题描述**: 后端部署到云上时，访问 `mp.dayilive.com/media/rooms/...` 报错，路径不存在

---

## 🔍 问题分析

### 1. 当前实现分析

#### 文件存储逻辑（`file_handler.py`）

```python
# 第20行：从环境变量读取，默认是相对路径
ROOM_MEDIA_ROOT_PATH = os.getenv("ROOM_MEDIA_ROOT_PATH", "./media")

# 第93行：文件系统路径（容器内）
fs_dir = os.path.join(ROOM_MEDIA_ROOT_PATH, relative_dir)  # 例如：./media/rooms/{room_id}

# 第97行：URL路径（返回给前端）
url_path = f"/media/{relative_dir}/{filename}"  # 例如：/media/rooms/{room_id}/cover_xxx.jpg
```

**问题点**：
- ✅ 文件保存到容器内的 `./media` 目录（相对于容器工作目录）
- ❌ URL路径 `/media/...` 需要Nginx提供静态文件服务
- ❌ **Nginx配置中缺少 `/media/` 路径的静态文件服务配置**

#### Nginx配置分析（`nginx.conf`）

**当前配置**：
- ✅ 配置了前端静态资源（`/assets/`、`/live-center/`等）
- ✅ 配置了API代理（`/api/core/`、`/api/users/`等）
- ❌ **没有配置 `/media/` 路径的静态文件服务**

**结果**：
- 当用户访问 `https://mp.dayilive.com/media/rooms/xxx/cover_xxx.jpg` 时
- Nginx找不到对应的静态文件配置
- 可能返回404或尝试代理到后端API，导致错误

#### Docker Compose配置分析（`compose-app.yml`）

**当前配置**：
- ✅ `live_core_service` 容器：没有挂载媒体文件目录的volume
- ✅ `nginx` 容器：只挂载了前端静态文件，没有挂载后端媒体文件

**问题**：
- 后端容器内的 `./media` 目录与Nginx容器不共享
- Nginx无法访问后端容器内的媒体文件

|------|------|------|--------|

## ✅ 推荐方案：Docker Volume + Nginx配置（方案1）

### 方案概述

1. **使用Docker Volume**：将媒体文件目录挂载为共享volume
2. **修改Nginx配置**：添加 `/media/` 路径的静态文件服务
3. **环境变量配置**：使用绝对路径，支持本地开发和远程部署

### 详细实施步骤

#### 步骤1：修改 `compose-app.yml`

**添加media volume和挂载**：

```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    restart: unless-stopped
    ports: ["8000:8000"]
    environment:
      POSTGRES_DB: "live_core_test"
      # ← 新增：设置媒体文件绝对路径
      ROOM_MEDIA_ROOT_PATH: "/app/media"
    env_file: .env.docker
    volumes:
      # ← 新增：挂载媒体文件目录（支持本地开发和远程部署）
      - media_files:/app/media
    depends_on: []
    networks:
      - live-network

  nginx:
    image: nginx:alpine
    restart: unless-stopped
    ports: ["80:80","443:443"]
    volumes:
      # 现有挂载...
      - /var/www/html/user-service:/var/www/html/user-service:ro
      - /var/www/html/media-download:/var/www/html/media-download:ro
      - /var/www/html/live-center:/var/www/html/live-center:ro
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/ssl:/etc/nginx/ssl:ro
      - ./data/srs:/var/www/srs:ro
      - /var/www/mp.dayilive.com:/var/www/mp.dayilive.com:ro
      - /var/www/certbot:/var/www/certbot:ro
      # ← 新增：挂载媒体文件目录（与live_core_service共享）
      - media_files:/var/www/media:ro

volumes:
  pgdata:
  media_download:
  frontend-dist:
  user-frontend-dist:
  # ← 新增：媒体文件volume
  media_files:
```

**说明**：
- `media_files` volume在容器间共享
- `live_core_service` 写入到 `/app/media`
- `nginx` 读取自 `/var/www/media`
- 使用 `:ro`（只读）确保Nginx不会意外修改文件

#### 步骤2：修改 `nginx.conf`

**在HTTPS server块中添加 `/media/` 配置**：

```nginx
# ========================================================================
# 媒体文件静态服务（后端上传的文件）
# ========================================================================
location /media/ {
    alias /var/www/media/;
    expires 30d;
    add_header Cache-Control "public";
    
    # 允许跨域（如果需要）
    add_header Access-Control-Allow-Origin *;
    
    # 安全：只允许图片文件
    location ~* \.(jpg|jpeg|png|gif|webp)$ {
        try_files $uri =404;
    }
    
    # 其他文件类型返回404
    location ~* \.(?!jpg|jpeg|png|gif|webp) {
        return 404;
    }
}
```

**放置位置**：建议放在 `location /static/` 之后，`}` 之前（第273行之后）

#### 步骤3：修改 `file_handler.py`（可选，提高健壮性）

**改进路径处理**：

```python
# 第20行：改进环境变量读取，支持绝对路径和相对路径
ROOM_MEDIA_ROOT_PATH = os.getenv("ROOM_MEDIA_ROOT_PATH", "./media")
# 如果是相对路径，转换为绝对路径（相对于项目根目录）
if not os.path.isabs(ROOM_MEDIA_ROOT_PATH):
    # 获取项目根目录（假设file_handler.py在app/core/目录下）
    project_root = Path(__file__).parent.parent.parent
    ROOM_MEDIA_ROOT_PATH = str(project_root / ROOM_MEDIA_ROOT_PATH)

# 确保目录存在
os.makedirs(ROOM_MEDIA_ROOT_PATH, exist_ok=True)
logger.info(f"媒体文件根目录: {os.path.abspath(ROOM_MEDIA_ROOT_PATH)}")
```

**说明**：
- 支持相对路径（本地开发：`./media`）
- 支持绝对路径（远程部署：`/app/media`）
- 自动创建目录

#### 步骤4：环境变量配置

**本地开发（`.env.local` 或 `.env.development`）**：
```bash
# 使用相对路径（相对于项目根目录）
ROOM_MEDIA_ROOT_PATH=./media
```

**远程部署（`.env.docker` 或 Docker环境变量）**：
```bash

ROOM_MEDIA_ROOT_PATH=/app/media
```

## ⚠️ 注意事项

### 1. 文件权限

- **容器内用户**：确保 `live_core_service` 容器有写入权限
- **Nginx用户**：确保Nginx容器有读取权限（使用 `:ro` 只读挂载）

### 2. 文件持久化

- **Volume持久化**：Docker volume默认持久化，即使容器删除，文件也会保留
- **备份策略**：建议定期备份 `media_files` volume

### 3. 性能优化

- **缓存策略**：Nginx配置了30天缓存，减少后端压力
- **CDN集成**：未来可以考虑将媒体文件迁移到CDN

### 4. 安全考虑

- **文件类型限制**：Nginx配置只允许图片文件
- **访问控制**：如果需要，可以添加认证中间件

## 🎯 总结

**问题根源**：
1. ❌ Nginx没有配置 `/media/` 路径的静态文件服务
2. ❌ 后端容器和Nginx容器没有共享媒体文件目录

**解决方案**：
1. ✅ 使用Docker Volume共享媒体文件目录
2. ✅ 在Nginx中配置 `/media/` 路径的静态文件服务
3. ✅ 使用环境变量配置路径，支持本地和远程部署

**实施优先级**：
- **P0（必须）**：修改 `compose-app.yml` 和 `nginx.conf`
- **P1（建议）**：改进 `file_handler.py` 的路径处理
- **P2（可选）**：添加文件访问日志和监控
