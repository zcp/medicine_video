## 数据库变更

### live_room_categories 增量 DDL

在主文档 §2 中新增 **2.4 live_room_categories**，与 session_tags、categories 风格一致。首版可不实现 is_primary 与 live_rooms.category_id 的同步。

```sql
CREATE TABLE live_room_categories (
    room_id UUID NOT NULL,
    category_id UUID NOT NULL,
    is_primary BOOLEAN DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    PRIMARY KEY (room_id, category_id),

    CONSTRAINT fk_live_room_categories_room_id
        FOREIGN KEY (room_id) REFERENCES live_rooms(id) ON DELETE CASCADE,
    CONSTRAINT fk_live_room_categories_category_id
        FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
);

CREATE UNIQUE INDEX idx_live_room_categories_room_primary
    ON live_room_categories (room_id)
    WHERE is_primary = true;

CREATE INDEX idx_live_room_categories_room_id ON live_room_categories(room_id);
CREATE INDEX idx_live_room_categories_category_id ON live_room_categories(category_id);

COMMENT ON TABLE live_room_categories IS '直播间与分类的多对多关联表';
COMMENT ON COLUMN live_room_categories.room_id IS '直播间ID，关联 live_rooms 表';
COMMENT ON COLUMN live_room_categories.category_id IS '分类ID，关联 categories 表';
COMMENT ON COLUMN live_room_categories.is_primary IS '是否为该直播间的主科室（可选）';
```

## Schema 变更

- **LiveRoomCategoriesSetRequest**：category_ids: List[UUID]（min_length=1, max_length=50），mode: Literal["replace","append"]；category_ids 唯一性校验（与 SessionTagsSetRequest 一致）。
- **LiveRoomCategoriesSetResponse**：data 含 room_id、mode、categories: List[CategoryItem]（或 CategoryBriefItem）。
- **LiveRoomCategoriesListResponse**：code、message、data: List[CategoryItem]、timestamp（与主文档统一响应结构一致）。
- 可选 **CategoryBriefItem**：id、name、slug（与 TagBriefItem 对应）；列表可复用 CategoryItem。

## API 变更

### 新增端点 1：GET /api/v1/rooms/{room_id}/categories

- **描述**：获取某直播间关联的已启用分类列表。
- **认证**：公开（Optional Auth，与主文档读操作一致）。
- **路径参数**：room_id (UUID)。
- **响应**：200 + data: List[CategoryItem]；房间不存在或无关联返回 2001（补全：与主文档业务码一致）。
- **执行流程**：1）校验 room_id 对应房间存在（查 live_rooms）；2）联表 live_room_categories + categories，条件 room_id、categories.is_active=true，按 sort_order、name 排序；3）返回统一响应结构。

### 新增端点 2：POST /api/v1/admin/rooms/{room_id}/categories

- **描述**：批量设置某直播间的分类（replace/append）。
- **认证**：JWT + ADMIN/SUPERADMIN。
- **请求体**：LiveRoomCategoriesSetRequest（category_ids、mode）。
- **响应**：200 + LiveRoomCategoriesSetResponse；房间不存在 2001；category_id 无效 4001（补全）。
- **执行流程**：1）权限检查 _check_admin_permission；2）校验房间存在；3）校验 category_ids 均在 categories 且 is_active=true；4）replace：删该 room 的 live_room_categories 后批量插入；append：仅插入，冲突忽略；5）返回当前房间分类列表。

### 新增端点 3：DELETE /api/v1/admin/rooms/{room_id}/categories/{category_id}

- **描述**：删除某直播间的单个分类关联。
- **认证**：JWT + ADMIN/SUPERADMIN。
- **路径参数**：room_id、category_id。
- **响应**：200 + 删除确认；关联不存在 2001。
- **执行流程**：1）权限检查；2）删除 live_room_categories 中 (room_id, category_id)；3）不存在则 2001。

## 集成与验证要点（步骤 6）

- **数据库**：需创建 `live_room_categories` 表（见上文 DDL）；若使用 Alembic，请根据 Model `LiveRoomCategory` 生成并执行迁移。
- **启动**：启动应用后确认路由已挂载：`GET /api/v1/rooms/{room_id}/categories`、`POST /api/v1/admin/rooms/{room_id}/categories`、`DELETE /api/v1/admin/rooms/{room_id}/categories/{category_id}`。
- **联调**：1）用有效 room_id 调用 GET，应返回 200 及 data 数组（可为空）；2）用不存在的 room_id 调用 GET，应返回 404、code 2001；3）管理员 JWT 调用 POST（body: category_ids, mode），应返回 200 及设置后的 categories；4）POST 传入不存在或未启用的 category_id，应返回 400、code 4001；5）DELETE 有效关联返回 200，关联不存在返回 404、code 2001。
- **回归**：确认既有内容管理接口（tags、categories、session-tags）行为未变；必要时再次执行《增量开发设计文档与主设计文档一致性检查提示词母版》。
