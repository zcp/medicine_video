## 1. 问题分析

### 1.1 当前代码中发现的问题

#### 问题1: CORS配置硬编码

**位置**: `app/main.py` 第41行
```python
allow_origins=["*"],  # 在生产环境中应该限制为特定域名
```

**问题描述**:
- CORS配置直接硬编码在代码中，无法根据环境（开发/生产）灵活配置
- `config.py` 中已定义了 `BACKEND_CORS_ORIGINS`，但 `main.py` 未使用
- 生产环境使用 `["*"]` 存在安全风险

#### 问题2: 数据库密码硬编码

**位置1**: `app/core/config.py` 第25行
```python
POSTGRES_PASSWORD: str = os.getenv("POSTGRES_PASSWORD", "CHANGE_ME")
```

**位置2**: `app/database.py` 第16行
```python
POSTGRES_PASSWORD = os.getenv("POSTGRES_PASSWORD", "CHANGE_ME")
```

**问题描述**:
- 数据库密码在代码中设置了默认值，存在安全风险
- `database.py` 和 `config.py` 中重复定义数据库配置，维护不便
- 如果环境变量未设置，会使用不安全的默认值

#### 问题3: 数据库连接URL日志泄露

**位置**: `app/database.py` 第26行
```python
logger.info(f"尝试连接数据库: {DATABASE_URL}")
```

**问题描述**:
- 日志中打印完整的数据库连接URL，包含用户名和密码
- 日志文件可能被未授权访问，导致敏感信息泄露

#### 问题4: JWT密钥默认值不安全

**位置**: `app/core/auth.py` 第17行
```python
secret_key = os.getenv("JWT_SECRET_KEY", "my-key")
```

**问题描述**:
- JWT密钥使用了不安全的默认值 "my-key"
- 如果环境变量未设置，系统将使用弱密钥，存在严重安全风险

#### 问题5: 配置重复定义

**问题描述**:
- `database.py` 和 `config.py` 中都定义了数据库连接配置
- 代码维护困难，容易出现不一致

## 2. CORS配置优化方案

### 2.1 修改 `app/core/config.py`

**当前代码**（第44-45行）:
```python
# CORS配置
BACKEND_CORS_ORIGINS: List[str] = ["*"]
```

**修改方案**:
```python
# CORS配置
# 从环境变量读取，支持逗号分隔的多个域名
# 格式: "http://localhost:5175,https://example.com"
CORS_ORIGINS_STR: str = os.getenv("CORS_ORIGINS", "*")
BACKEND_CORS_ORIGINS: List[str] = [
    origin.strip() 
    for origin in CORS_ORIGINS_STR.split(",") 
    if origin.strip()
]
```

**说明**:
- 从环境变量 `CORS_ORIGINS` 读取配置
- 支持多个域名，用逗号分隔
- 默认值仍为 `["*"]`（开发环境），生产环境必须通过环境变量设置

### 2.2 修改 `app/main.py`

**当前代码**（第38-45行）:
```python
# 添加CORS中间件
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # 在生产环境中应该限制为特定域名
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**修改方案**:
```python
# 添加CORS中间件
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.BACKEND_CORS_ORIGINS,  # 从配置读取
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**说明**:
- 使用 `settings.BACKEND_CORS_ORIGINS` 替代硬编码
- 配置统一由 `config.py` 管理

## 3. 敏感信息硬编码问题修复方案

### 3.1 修改 `app/core/config.py`

#### 3.1.1 移除数据库密码默认值

**当前代码**（第23-27行）:
```python
# 数据库配置
POSTGRES_SERVER: str = os.getenv("POSTGRES_SERVER", "localhost")
POSTGRES_USER: str = os.getenv("POSTGRES_USER", "postgres")
POSTGRES_PASSWORD: str = os.getenv("POSTGRES_PASSWORD", "CHANGE_ME")  # ❌ 不安全
POSTGRES_DB: str = os.getenv("POSTGRES_DB", "live_core_test")
POSTGRES_PORT: str = os.getenv("POSTGRES_PORT", "5432")
```

**修改方案**:
```python
# 数据库配置
POSTGRES_SERVER: str = os.getenv("POSTGRES_SERVER", "localhost")
POSTGRES_USER: str = os.getenv("POSTGRES_USER", "postgres")
# ⚠️ 生产环境必须设置此环境变量，不允许使用默认值
POSTGRES_PASSWORD: str = os.getenv("POSTGRES_PASSWORD", "")
POSTGRES_DB: str = os.getenv("POSTGRES_DB", "live_core_test")
POSTGRES_PORT: str = os.getenv("POSTGRES_PORT", "5432")

# 验证必需的环境变量
def _validate_database_config(self):
    """验证数据库配置完整性"""
    if not self.POSTGRES_PASSWORD:
        raise ValueError(
            "POSTGRES_PASSWORD 环境变量未设置。"
            "生产环境必须设置此变量，不允许使用默认值。"
        )
```

**说明**:
- 移除不安全的默认密码
- 添加配置验证方法，确保生产环境必须设置密码
- 在 `Settings` 类初始化时调用验证

#### 3.1.2 修改JWT密钥配置

**当前代码**（`app/core/auth.py` 第17行）:
```python
secret_key = os.getenv("JWT_SECRET_KEY", "my-key")
```

**修改方案1**: 在 `config.py` 中统一管理
```python
# JWT配置
JWT_SECRET_KEY: str = os.getenv("JWT_SECRET_KEY", "")
JWT_ALGORITHM: str = os.getenv("JWT_ALGORITHM", "HS256")

# 验证JWT配置
def _validate_jwt_config(self):
    """验证JWT配置完整性"""
    if not self.JWT_SECRET_KEY:
        raise ValueError(
            "JWT_SECRET_KEY 环境变量未设置。"
            "生产环境必须设置此变量，且长度应至少32个字符。"
        )
    if len(self.JWT_SECRET_KEY) < 32:
        raise ValueError(
            "JWT_SECRET_KEY 长度不足32个字符，存在安全风险。"
            "请使用更长的密钥（推荐64字符以上）。"
        )
```

**修改方案2**: 修改 `app/core/auth.py` 使用配置类
```python
from app.core.config import settings

class JWTAuth:
    @staticmethod
    def _get_jwt_config():
        """延迟获取JWT配置，避免模块导入时的问题"""
        secret_key = settings.JWT_SECRET_KEY
        algorithm = settings.JWT_ALGORITHM
        return secret_key, algorithm
```


- 移除重复的配置定义
- 统一使用 `config.py` 中的配置

#### 3.2.2 修复日志泄露问题

**当前代码**（第26行）:

**修改方案**:
```python

logger.info(

    f"server={settings.POSTGRES_SERVER}, "
```

**说明**:
- 日志中不包含密码信息
- 仅打印服务器、端口、数据库名、用户名等非敏感信息

#### 4.2.3 配置验证和启动检查

**修改 `app/core/config.py`**:
```python
class Settings:
    # ... 现有配置 ...
    
    def __init__(self):
        """初始化配置并验证"""
        self._validate_database_config()
        self._validate_jwt_config()
        self._validate_cors_config()
    
    def _validate_database_config(self):
        """验证数据库配置"""
        if not self.POSTGRES_PASSWORD:
            raise ValueError(
                "POSTGRES_PASSWORD 环境变量未设置。"
                "生产环境必须设置此变量。"
            )
    
    def _validate_jwt_config(self):
        """验证JWT配置"""
        if not self.JWT_SECRET_KEY:
            raise ValueError(
                "JWT_SECRET_KEY 环境变量未设置。"
                "生产环境必须设置此变量，且长度应至少32个字符。"
            )
        if len(self.JWT_SECRET_KEY) < 32:
            raise ValueError(
                "JWT_SECRET_KEY 长度不足32个字符，存在安全风险。"
            )
    
    def _validate_cors_config(self):
        """验证CORS配置"""
        if self.DEBUG is False and "*" in self.BACKEND_CORS_ORIGINS:
            import warnings
            warnings.warn(
                "生产环境（DEBUG=False）检测到CORS配置为 '*'，存在安全风险。"
                "请通过 CORS_ORIGINS 环境变量设置具体的允许域名。"
            )
```

### 4.3 敏感信息泄露防护

#### 4.3.1 日志脱敏

**创建日志工具函数** (`app/core/logging_utils.py`):
```python
import re
import logging

def sanitize_log_message(message: str) -> str:
    """对日志消息进行脱敏处理"""
    # 移除数据库连接URL中的密码
    message = re.sub(
        r'postgresql[+a-z]*://[^:]+:([^@]+)@',
        r'postgresql://***:***@',
        message,
        flags=re.IGNORECASE
    )
    
    # 移除JWT密钥（如果意外出现在日志中）
    message = re.sub(
        r'JWT_SECRET_KEY["\']?\s*[:=]\s*["\']?([^"\'\s]+)',
        r'JWT_SECRET_KEY="***"',
        message,
        flags=re.IGNORECASE
    )
    
    return message

class SanitizedFormatter(logging.Formatter):
    """脱敏日志格式化器"""
    def format(self, record):
        record.msg = sanitize_log_message(str(record.msg))
        return super().format(record)
```

#### 4.3.2 错误消息脱敏

**修改异常处理**:
```python
# 在异常处理中，不要暴露敏感信息
try:
    # 数据库操作
except Exception as e:
    logger.error(f"数据库操作失败: {type(e).__name__}")
    # 不要打印完整的异常信息（可能包含连接字符串）
    raise HTTPException(status_code=500, detail="内部服务器错误")
```

## 6. 最佳实践建议

### 6.1 环境变量命名规范

- 使用大写字母和下划线：`POSTGRES_PASSWORD`
- 使用有意义的名称：`CORS_ORIGINS` 而非 `CORS`
- 分组前缀：`POSTGRES_*`, `JWT_*`, `CELERY_*`

### 6.2 敏感信息管理原则

1. **永远不要**:
   - ❌ 在代码中硬编码密码、密钥
   - ❌ 将 `.env` 文件提交到版本控制
   - ❌ 在日志中打印敏感信息
   - ❌ 在错误消息中暴露敏感信息

2. **应该做**:
   - ✅ 使用环境变量或密钥管理服务
   - ✅ 提供 `.env.example` 模板
   - ✅ 在启动时验证必需配置
   - ✅ 对日志进行脱敏处理

### 6.3 不同环境的配置策略

| 环境 | 配置方式 | 安全级别 |
|------|---------|---------|
| **本地开发** | `.env` 文件 | 低（仅本地访问） |
| **开发服务器** | 环境变量注入 | 中（团队共享） |
| **测试环境** | 密钥管理服务 | 高（接近生产） |
| **生产环境** | 密钥管理服务 + 加密存储 | 最高（严格保护） |

### 6.4 密钥生成建议

**JWT密钥生成**:
```bash
# 生成64字符的随机密钥
openssl rand -hex 32

# 或使用Python
python -c "import secrets; print(secrets.token_hex(32))"
```

**数据库密码生成**:
```bash
# 生成强密码（16字符）
openssl rand -base64 16

# 或使用密码生成工具
pwgen -s 16 1
```

### 6.5 配置变更检查清单

在每次部署前，检查：

- [ ] 所有敏感信息都从环境变量读取
- [ ] 生产环境CORS配置为具体域名（非 `*`）
- [ ] JWT密钥长度至少32字符
- [ ] 数据库密码已设置且足够强
- [ ] `.env` 文件未提交到版本控制
- [ ] 日志中不包含敏感信息
- [ ] 配置验证已启用

| 问题 | 风险等级 | 影响范围 | 紧急程度 |
