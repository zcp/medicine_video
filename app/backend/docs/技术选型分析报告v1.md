# 系统架构设计与技术选型分析报告（面向直播 SaaS 平台）

## 一、架构设计：合理分层 + 可扩展性强

- ✅ **分层结构**：清晰划分客户端、前端、后端、媒体服务、数据存储和 DevOps，有助于后期扩展与维护。
- ✅ **微服务模块化**：虽然初期不一定要完全微服务化，但"适度拆分"的策略允许你逐步模块化关键服务（如直播流控制、聊天服务、回放服务等），利于横向扩展。
- ✅ **技术组合**：FastAPI + Vue + PyCharm + PostgreSQL + SQLAlchemy + Pydantic + RDS，适配医疗行业直播SaaS的高安全性、高并发与快速交付需求。

| 模块         | 技术选型                             | 评估说明 |

### 2.1 前端技术栈规范
- Vue 3 + JavaScript
- 使用组合式API（Composition API）
- 使用ESLint + Prettier进行代码格式化
- 使用Vite作为构建工具
- 使用Pinia进行状态管理
- 使用Tailwind CSS进行样式开发

### 2.2 代码质量指标
- 代码复杂度：圈复杂度不超过10
- 代码重复率：不超过5%
- 测试覆盖率：>80%
- 代码审查：至少一个审查者批准
- 静态代码分析：通过所有检查
- 代码可维护性：遵循SOLID原则
- 代码可读性：清晰的命名和注释

### 2.3 日志规范
- 日志级别：
  - ERROR：系统错误、业务异常
  - WARNING：警告信息
  - INFO：重要业务操作
  - DEBUG：调试信息
- 日志格式：
  - 时间戳
  - 日志级别
  - 模块名
  - 函数名
  - 行号
  - 消息内容
  - 异常堆栈（如果有）
- 日志存储：
  - 按日期分割
  - 定期归档
  - 敏感信息脱敏
  - 使用ELK进行日志管理

### 2.4 异常处理规范
- 异常分类：
  - 系统异常：系统级错误
  - 业务异常：业务逻辑错误
  - 参数异常：输入参数错误
  - 权限异常：访问权限错误
- 异常处理原则：
  - 明确异常类型
  - 提供详细错误信息
  - 记录异常日志
  - 优雅降级处理
  - 避免异常吞没
- 错误码规范：
  - 系统错误：5xx
  - 业务错误：4xx
  - 成功：2xx

## 五、Cloudflare R2 对象存储选型分析

### 1. 什么是 Cloudflare R2？

Cloudflare R2 是兼容 Amazon S3 的对象存储，特点如下：

- ✅ 零出口带宽费用（Zero egress fee）
- ✅ 全球高可用，CDN 深度集成
- ✅ 支持版本控制、生命周期策略

### 2. R2 在直播平台的典型场景

| 对象类型           | 示例说明 |
|--------------------|----------|
| 回放视频（.mp4）   | 上传 OBS 流转码后的录制内容 |
| 视频封面图         | 视频预览图、首帧图 |
| 用户头像/教学课件  | 图片、PDF、素材等 |
| 回放截图           | FFmpeg 生成后上传 R2 |

### 3. 与其他对象存储对比

| 特性         | R2                  | MinIO             | 阿里云 OSS / 腾讯云 COS |
|--------------|---------------------|--------------------|--------------------------|
| 计费模式     | 无出口流量费 ✅     | 免费但需自运维      | 流量费用高 ❌            |
| 性能与 CDN   | 内建 CDN ✅         | 部署依赖            | CDN 支持好 ✅            |
| 兼容性       | S3 完全兼容 ✅      | 限部分 S3 特性      | SDK 适配                 |
| 可维护性     | 云托管 ✅           | 自部署 ❌           | 云托管 ✅                |

### 4. 集成建议

- FastAPI 使用 boto3 调用 R2 API
- 支持上传预签名 URL（客户端直传）
- 视频/封面图通过 CDN 加速访问
- 设置生命周期管理自动清理

### 5. 注意事项

- ❌ 不适合存储实时聊天消息或直播数据流
- ✅ 适合直播结束后的视频资源、截图、课件等非结构化内容

## 六、R2 不适合实时直播流的原因

| 项目         | R2 的表现       | 原因 |
|--------------|------------------|------|
| 实时推流支持 | ❌ 不支持 RTMP/WebRTC/HLS |
| 写入延迟     | ❌ 秒级延迟，不适合毫秒级传输 |
| 播放启动延迟 | ⛔ 不支持边推边播 |
| 并发读取     | ✅ CDN 分发点播支持强 |

### 正确架构搭配建议

#### 实时直播阶段：

- OBS / 手机 → 推流至 SRS
- SRS → HLS/WebRTC 实时分发

#### 回放与转码阶段：

- SRS → 本地录制 → FFmpeg 转码
- 后端上传 MP4 / m3u8 / 封面图 至 Cloudflare R2
- 用户点播访问由 CDN 加速

---

## ✅ 最终结论

Cloudflare R2 是适合用于 **直播后资源管理** 的对象存储，
但不适用于直播实时分发路径。建议：

- 实时：RTMP/WebRTC → SRS（低延迟流）
- 回放：上传转码后内容至 R2 → CDN 分发点播
