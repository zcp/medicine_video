# 直播推流与播放功能模块设计文档（V3.0）

## 1. 概述
本模块是直播SaaS平台的核心组成部分，专注于直播内容的推流、播放、回放录制及多平台分发。设计采用渐进式开发策略，初期聚焦核心功能，预留扩展接口，确保系统具备良好的可维护性与可扩展性。

## 2. 系统架构
### 2.1 系统架构图
*(此处应有架构图)*

### 2.2 设计原则与服务职责
#### 服务职责
- 管理直播生命周期（创建、开始、结束）
- 管理直播基本信息（标题、描述、封面等）
- 管理直播分类和标签
- 管理直播存储配置
- 管理直播录制设置

#### 设计原则：保持责任单一
- **直播统计是直播的固有属性**：统计数据与直播记录强相关，统计功能是直播服务的核心功能之一。
- **减少服务数量**：避免了创建独立的统计服务，减少了服务间通信，简化了系统架构。
- **提高性能**：统计查询可以直接在直播服务中完成，避免了跨服务调用，减少了网络开销。
- **简化开发维护**：减少了服务数量，简化了部署流程，降低了维护成本。

## 3. 功能模块详细设计
### 3.1 视频存储规范

#### 3.1.1 视频ID命名规范
- 格式：`{room_id}_{uuid4后缀}`
- room_id：10或16位随机数
- uuid4后缀：4位uuid
- 示例：`8723901837_f22d`

#### 3.1.2 文件命名规范
- 格式：`{资源类型}_{video_id}_{操作类型}_{时间戳}.{文件后缀}`
- 资源类型：video, cover, thumbnail等
- video_id：遵循3.1.1规范
- 操作类型：upload, transcoded等
- 时间戳：ISO格式无符号，如20250528T153000
- 文件后缀：mp4, jpg, webp等
- 示例：`video_8723901837_f22d4c_upload_20250528T153000.mp4`

#### 3.1.3 存储目录结构
```
/media/video_{video_id}/
├── images/                    # 图片资源目录
│   ├── cover_{video_id}_{操作类型}_{时间戳}.jpg
│   └── thumbnail_{video_id}_{操作类型}_{时间戳}.webp
├── raw/                      # 原始视频目录
│   └── video_{video_id}_{操作类型}_{时间戳}.mp4
├── hls_{清晰度}_{码率}/      # HLS视频目录
│   ├── index_{video_id}_{操作类型}_{时间戳}.m3u8
│   └── ts/                   # TS分片目录
│       └── segment_{序号}_{video_id}_{操作类型}_{时间戳}.ts
├── mp4/                      # MP4视频目录
│   └── video_{video_id}_{操作类型}_{清晰度}_{时间戳}.mp4
└── metadata.json            # 元数据文件
```

#### 3.1.4 元数据管理
- metadata.json必须包含字段：
  - video_id：视频唯一标识
  - room_id：直播间ID
  - title：视频标题
  - created_at：创建时间
  - updated_at：更新时间
  - status：视频状态

#### 3.1.5 资源访问控制
- 所有资源必须通过签名URL或中转服务访问
- 禁止直接暴露存储路径
- 实现防盗链机制
- 支持访问权限控制

### 3.2 直播推流（RTMP 推流）
#### 推流流程
1.  推流鉴权（Token或推流密钥验证）
2.  推流处理
    -   使用 `nginx-rtmp` 接收推流
    -   验证流是否合法
    -   提交流信息至转码任务队列

#### 技术说明
-   **推流协议**：RTMP
-   **流媒体服务器**：`nginx-rtmp`
-   **鉴权机制**：JWT

### 3.3 直播播放（HLS / WebRTC）
#### 播放策略
-   默认采用 HLS（延迟容忍度高，兼容性强）
-   可选使用 WebRTC（低延迟）

#### 技术说明
-   **HLS 实现**：ffmpeg 分片 + m3u8
-   **WebRTC 实现**：P2P / SFU
-   **前端播放库**：hls.js / WebRTC API

### 3.4 回放录制与转码
#### 录制功能
-   **自动录制**：流开始时记录视频片段
-   支持直播结束后转码为 MP4、HLS
-   支持转码至不同码率
-   遵循3.1节定义的存储规范

#### 技术说明
-   使用 `ffmpeg` 执行录制与转码
-   存储至本地文件系统或 MinIO
-   数据索引写入 PostgreSQL
-   文件命名和存储路径遵循3.1节规范

## 4. 数据库设计
### 4.1 直播服务数据库

```sql
CREATE TABLE live_stream (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id INT NOT NULL,
    title VARCHAR(100) NOT NULL,
    description TEXT,
    cover_url VARCHAR(255),
    stream_key VARCHAR(255) NOT NULL,
    storage_type VARCHAR(20) NOT NULL,  -- local, s3, etc.
    stream_path VARCHAR(255) NOT NULL,  -- 遵循3.1.3存储目录结构
    storage_bucket VARCHAR(100),        -- 存储桶（如果使用对象存储）
    video_id VARCHAR(50) NOT NULL,      -- 遵循3.1.1视频ID命名规范
    status VARCHAR(20) DEFAULT 'created',
    start_time TIMESTAMP,
    end_time TIMESTAMP,
    is_private BOOLEAN DEFAULT false,
    is_recorded BOOLEAN DEFAULT true,
    category_id INT,                    -- 直播分类
    sub_category_id INT,                -- 直播子分类
    thumbnail_url VARCHAR(255),
    scheduled_time TIMESTAMP,
    permission_level INT DEFAULT 0,     -- 权限级别
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 6. API 设计
### 6.1 通用响应格式
所有接口统一返回如下格式：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    // 实际数据内容
  }
}
```

### 6.2 状态码说明
| 状态码 | 含义             |
| :----- | :--------------- |
| 200    | 成功             |
| 400    | 请求参数错误     |
| 401    | 未授权（登录失效） |
| 403    | 禁止访问         |
| 404    | 资源不存在       |
| 500    | 服务器内部错误   |

### 6.3 API 详细设计
#### 6.3.1 推流相关
* **创建推流**
    `POST /api/stream/start`
    *请求体：*
    ```json
    {
      "title": "直播标题",
      "description": "直播描述",
      "cover_url": "封面图片URL"
    }
    ```
    *成功响应：*
    ```json
    {
      "code": 200,
      "message": "推流创建成功",
      "data": {
        "stream_id": "stream_123",
        "rtmp_url": "rtmp://your-server.com/live",
        "stream_key": "stream_key_123",
        "expire_time": "2024-03-20T10:00:00Z"
      }
    }
    ```
* **结束推流**
    `POST /api/stream/stop`
    *请求体：*
    ```json
    {
      "stream_id": "stream_123"
    }
    ```
    *成功响应：*
    ```json
    {
      "code": 200,
      "message": "推流已结束",
      "data": {
        "stream_id": "stream_123",
        "end_time": "2024-03-20T10:30:00Z",
        "duration": 1800,
        "viewer_count": 100
      }
    }
    ```
* **获取推流状态**
    `GET /api/stream/{stream_id}/status`
    *成功响应：*
    ```json
    {

      "message": "success",
      "data": {

        "viewer_count": 100,
        "bitrate": 2000,
        "fps": 30,
        "resolution": "1920x1080"
      }
    }
    ```

## 7. 安全与优化
### 安全机制
-   JWT 认证
-   防盗链验证（Referer 或签名机制）
-   内容审核（可接入第三方如阿里云视频审核）
-   HTTPS / TLS 加密

### 性能优化
-   缓存策略（如 Redis 存储播放链接、状态）
-   数据库索引优化（直播查询等）
-   文件分块与存储路径优化（防止 I/O 瓶颈）
