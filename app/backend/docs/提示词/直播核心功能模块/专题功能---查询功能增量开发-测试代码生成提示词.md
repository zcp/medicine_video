### 2.1 核心测试原则（⚠️ 必须严格遵守）

1. **不修改已有测试原则**：
   - ✅ **只创建**新的测试文件或测试函数

2. **测试独立性原则**：
   - 每个测试必须**完全独立**，不依赖数据库中的已有数据

4. **引用现有代码原则**：

### 5.3 测试模式 (AAA Pattern)

**所有测试必须遵循 Arrange-Act-Assert 模式**：

#### **1. 准备 (Arrange)**

- 使用 `faker` 生成随机测试数据
- 创建必要的依赖数据（如测试专题、测试用户等）
- Mock认证（API层测试）

```python
async for db in db_session:
    from faker import Faker
    import uuid
    from app.crud import topic as crud_topic
    from app.schemas.topic import TopicCreate
    from app.models.topic import TopicStatus
    
    fake = Faker()
    user_id = uuid.uuid4()
    
    # 创建测试数据（使用随机生成的title，避免冲突）
    topic_in = TopicCreate(
        title=f"{fake.catch_phrase()}_{uuid.uuid4().hex[:6]}",  # ✅ 使用随机值
        description=fake.text(max_nb_chars=100),
        banner_url=fake.image_url(),
        status=TopicStatus.PUBLISHED
    )
    topic = await crud_topic.create(db, topic_in, user_id)
```

#### **2. 执行 (Act)**

- 调用被测试的函数或API端点

```python
    # 调用被测试的函数
    topics, total = await crud_topic.get_multi_and_total(
        db,
        skip=0,
        limit=10,
        title="测试关键词",  # ← 测试新功能
        current_user_id=None,
        current_user_role=None
    )
```

#### **3. 断言 (Assert)**

- 验证返回值、数据库状态、权限控制等

```python
    # 断言 1: 验证返回结果
    assert topics is not None
    assert isinstance(topics, list)
    
    # 断言 2: 验证业务逻辑
    assert len(topics) > 0
    for topic in topics:
        assert "测试关键词" in topic.title.lower()  # title模糊匹配验证
    
    # 断言 3: 验证权限控制（如需要）
    for topic in topics:
        assert topic.status == TopicStatus.PUBLISHED  # 匿名用户只能看到published
```

## 7. 测试数据隔离规范

### 7.1 唯一性字段随机生成规则

为了防止测试之间因违反数据库 `UNIQUE` 约束而产生冲突，所有唯一性字段**必须**是随机生成的。

#### **实现要求：**

* **推荐使用 `faker` 库**: `pip install Faker`
* 所有生成的随机数据**必须**严格遵守 `app/schemas/topic.py` 和 `app/models/topic.py` 中定义的验证规则

#### **具体字段要求（从实际代码中读取）：**

**专题 (Topic) 相关字段：**

* **`title`**:
  - **规则**: 必须符合 `max_length=100`（从 `app/models/topic.py` 中读取）
  - **Faker 示例**: `f"{fake.catch_phrase()}_{uuid.uuid4().hex[:6]}"`
  - **禁止**: 硬编码如 `"测试专题"`

* **`description`**:
  - **规则**: 可选字段，文本类型
  - **Faker 示例**: `fake.text(max_nb_chars=200)`

* **`banner_url`**:
  - **规则**: 可选字段，`max_length=255`（从实际代码中读取）
  - **Faker 示例**: `fake.image_url()`

* **`status`**:
  - **规则**: TopicStatus枚举类型（从 `app/models/topic.py` 中读取）
  - **有效值**: `TopicStatus.DRAFT`、`TopicStatus.PUBLISHED`、`TopicStatus.ARCHIVED`（从实际代码中读取）

* **`user_id`**:
  - **规则**: UUID类型，必填字段
  - **示例**: `uuid.uuid4()`

#### **禁止事项：**

- ❌ 在测试的 Arrange 阶段使用硬编码的字符串（如 `'专题A'`）作为唯一性字段的值
- ❌ 重复使用相同的测试数据导致 `IntegrityError`
- ✅ 所有测试必须能独立运行且不依赖执行顺序
