## 2. 错误详细分析

### 2.1 Expert CRUD测试错误

#### 错误1: `test_get_featured_experts`

**错误信息**:
```
AssertionError: assert UUID('12ef2f60-c7cf-4459-b90c-4b89cc9e47ed') in [UUID('29242459-4364-4646-9957-c55f11a0f507'), ...]
```

**错误原因**:
- 测试创建了2个推荐专家（featured1, featured2）和1个非推荐专家（non_featured）
- 断言期望featured1和featured2的ID在结果列表中
- 但数据库中可能存在其他测试留下的推荐专家数据，导致结果集不符合预期

**根本原因**: 测试数据隔离问题，数据库中存在其他测试的残留数据

**修复建议**:
- 修改断言逻辑，只验证featured1和featured2在结果中，而不是验证结果集的完整性
- 或者在测试前清理experts表的所有数据

#### 错误2: `test_get_experts_multi_and_total_with_filters`

**错误信息**:
```
assert False
```

**错误原因**:
- 测试按名称筛选（name="张"），期望至少找到1个专家
- 但筛选结果为空或不包含expert1

**根本原因**: 筛选逻辑可能不正确，或者数据库中的数据未正确保存

**修复建议**:
- 检查CRUD函数`get_experts_multi_and_total`的筛选逻辑（name参数）
- 确认测试数据是否正确提交到数据库

#### 错误3: `test_get_experts_multi_and_total_with_sort`

**错误信息**:
```
AssertionError: assert [datetime.dat...one.utc), ...] == [datetime.dat...one.utc), ...]
```

**错误原因**:
- 测试期望按创建时间排序，但实际结果顺序不符合预期
- 可能是因为数据库中存在其他测试的数据，导致排序结果包含额外记录

**根本原因**: 测试数据隔离问题

**修复建议**:
- 修改断言逻辑，只验证expert1和expert2的相对顺序，而不是验证整个列表的排序

#### 错误4: `test_update_expert_duplicate_user_id`

**错误信息**:
```
Failed: DID NOT RAISE <class 'app.exceptions.DatabaseIntegrityException'>
```

**错误原因**:
- 测试期望更新expert2的user_id为expert1的user_id时抛出`DatabaseIntegrityException`
- 但实际未抛出异常，说明CRUD函数未正确处理唯一性约束冲突

**根本原因**: `update_expert` CRUD函数未捕获`IntegrityError`并转换为`DatabaseIntegrityException`

**修复建议**:
- 检查`app/crud/experts.py`中的`update_expert`函数
- 添加`IntegrityError`异常处理，转换为`DatabaseIntegrityException`

### 2.2 UserExpertSubscription CRUD测试错误

#### 错误5: `test_get_user_subscriptions`

**错误信息**:
```
AssertionError: assert UUID('ba0e357e-fda7-4bd0-bba2-30123c297789') in [UUID('dd20d211-0e6a-469c-bb6d-40cf7847b717'), UUID('7f5d83f3-0f01-46bf-b4c2-4500160d5c82')]
```

**错误原因**:
- 测试创建了3个专家（expert1, expert2, expert3），并关注了expert1和expert2
- 断言期望结果中包含expert1和expert2的ID
- 但实际结果中的ID不匹配

**根本原因**: `get_user_subscriptions` CRUD函数返回的是`Expert`对象列表，而不是`UserExpertSubscription`对象列表

**修复建议**:
- 检查`get_user_subscriptions`函数的返回值
- 确认是否正确使用了`selectinload`加载关联的`Expert`对象

### 2.3 LiveSessionExpert CRUD测试错误

#### 错误6-10: 所有LiveSessionExpert测试失败

**错误信息**:
```
sqlalchemy.exc.IntegrityError: (sqlalchemy.dialects.postgresql.asyncpg.IntegrityError) <class 'asyncpg.exceptions.ForeignKeyViolationError'>: 
向表 "live_session_experts" 违反外键约束 "live_session_experts_session_id_fkey"
```

**错误原因**:
- 测试中使用了`uuid.uuid4()`生成的`session_id`
- 但`live_session_experts`表有外键约束，要求`session_id`必须存在于`live_sessions`表中
- 测试未创建对应的`LiveSession`记录

**根本原因**: 测试数据准备不完整，缺少外键依赖的`LiveSession`记录

**修复建议**:
- 在测试中先创建`LiveSession`记录，然后使用其ID创建`LiveSessionExpert`记录
- 或者修改测试策略，使用Mock数据库会话来绕过外键约束
