## 3. 核心实现规范（继承测试母版）

- **函数式测试**：禁止类式测试，所有测试函数直接定义在模块级别。  
- **async for 解包**：`async for db in db_session`、`async for client in async_client`。  
- **Service 层 Mock**：`db` 使用 `AsyncMock()`；`crud_room.get`、`crud_user_behavior.get_favorite` 使用 `mocker.patch(..., new_callable=AsyncMock)`；调用链上被调用的 CRUD 均须 Mock。  
- **事务**：测试函数内默认不 `commit`；API 测试中若需父对象（LiveRoom）对请求可见，可在 Arrange 中对该父对象 `commit`。  
- **API 用户身份**：从 JWT 解析 `user_id` 创建数据，请求头使用 `Authorization: Bearer {regular_user_token}`，保证与 Token 一致。  
- **外键**：先创建 LiveRoom，再创建 UserFavorite 或调用 is-favorited；禁止用随机 UUID 作为 room_id 且该 room 不存在。

## 4. 测试用例规划（仅增量）

### 4.1 Service 层增量（check_is_favorited）

| 测试函数名 | 场景 | 预期 |
|------------|------|------|
| `test_check_is_favorited_true` | Mock room 存在、get_favorite 返回 is_active=True 的记录 | 返回 `{"is_favorited": True}` |
| `test_check_is_favorited_false` | Mock room 存在、get_favorite 返回 None 或 is_active=False | 返回 `{"is_favorited": False}` |
| `test_check_is_favorited_room_not_found_raises` | Mock crud_room.get 返回 None | 抛出 `NotFoundException` |

**Mock 要点**：`check_is_favorited` 内先调 `crud_room.get(self.db, room_id)`，再调 `crud_user_behavior.get_favorite(self.db, current_user_id, room_id)`；须同时 Mock 这两处，避免对 mock_db 做 await 导致错误。

### 4.2 API 层增量（GET /api/v1/rooms/{room_id}/is-favorited）

| 测试函数名 | 场景 | 预期 |
|------------|------|------|
| `test_check_is_favorited_api_true` | 已存在房间且当前用户已收藏 | 200，`data.is_favorited === true` |
| `test_check_is_favorited_api_false` | 已存在房间且当前用户未收藏 | 200，`data.is_favorited === false` |
| `test_check_is_favorited_api_room_not_found` | room_id 不存在 | 404，`code === 2001`，message 资源不存在 |
| `test_check_is_favorited_api_unauthorized` | 无 Token | 401 |
| `test_check_is_favorited_api_invalid_uuid` | 路径中 room_id 非 UUID | 422 |

## 5. Mock 与测试数据策略

- **Service**：`mock_db = AsyncMock()`；patch `app.services.user_behavior_service.crud_room.get` 与 `app.services.user_behavior_service.crud_user_behavior.get_favorite`；get_favorite 需返回具 `is_active` 属性的对象或 None（可用真实 Model 或 Mock 对象，若 Mock 则需配置 `is_active`）。  
- **API**：使用 `db_session` 创建 LiveRoom（并视需 commit）；使用 `regular_user_token` 与从 JWT 解析的 `user_id` 创建 UserFavorite（测试 true 时）；同一 room、不创建收藏即测试 false。
