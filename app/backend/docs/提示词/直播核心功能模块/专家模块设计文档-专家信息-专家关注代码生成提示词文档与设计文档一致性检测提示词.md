#### **3. 审计清单 (Audit Checklist) - (!!! 必须逐项检测 !!!)**

##### 3.1. 功能覆盖度 (Function Coverage)

* **检测点 1.1 (功能完整性)**：`Doc-Design` 中提及的所有功能点、API 接口、或业务逻辑（例如 `create_expert`, `get_experts_list`, `follow_expert`），是否都在 `Doc-CRUD` 或 `Doc-API` 中被**完整覆盖**？
* **检测点 1.2 (功能冗余)**：`Doc-CRUD` 或 `Doc-API` 中是否存在 `Doc-Design` **未提及**的"额外"功能或 API？

##### 3.2. 业务逻辑与执行流程 (Business Logic & Flow)

* **检测点 2.1 (步骤一致性)**：`Doc-API` 和 `Doc-CRUD` 中描述的函数执行流程（例如：1. 验证参数 -> 2. 调用 Service -> 3. Service 调用 CRUD -> 4. CRUD 操作数据库）是否与 `Doc-Design` 中描述的业务步骤**完全一致**？
* **检测点 2.2 (数据流转)**：`Doc-Design` 中描述的数据处理逻辑（例如："Service 层需要过滤 URL"，"CRUD 层负责填充默认值"）是否在对应的文档中得到准确体现？
* **检测点 2.3 (事务边界)**：`Doc-Design` 中（明示或暗示）的事务处理范围（例如："创建专家和更新用户订阅必须是原子的"）是否在 `Doc-CRUD` 中被正确实现？

##### 3.3. 数据库规范 (Database Specifications)

* **检测点 3.1 (字段名称)**：`Doc-CRUD` 中提到的数据库 Model 字段名，是否与 `Doc-Design` 中的**字段名**（例如 `title`, `hospital`, `department`）完全一致？
* **检测点 3.2 (字段类型)**：`Doc-CRUD` 中提到的数据库 Model 字段类型（例如 `String(255)`）是否与 `Doc-Design` 中的**类型定义**完全一致？
* **检测点 3.3 (字段约束)**：`Doc-CRUD` 中提到的约束（如 `nullable=False`, `unique=True`, `server_default`）是否与 `Doc-Design` 中的**约束要求**完全一致？

##### 3.4. API 结构规范 (API Structure)

* **检测点 4.1 (路由 URL)**：`Doc-API` 中的 API 路由（例如 `/api/v1/experts`, `/api/v1/experts/{expert_id}/follow`）是否与 `Doc-Design` **完全一致**？
* **检测点 4.2 (HTTP 方法)**：`Doc-API` 中的 HTTP 方法（`POST`, `GET`, `PUT`, `DELETE`）是否与 `Doc-Design` **完全一致**？
* **检测点 4.3 (请求体 Schema)**：`Doc-API` 中的请求体（Request Body）结构、字段名、类型、是否必填，是否与 `Doc-Design` **完全一致**？
* **检测点 4.4 (查询参数)**：`Doc-API` 中的查询参数（Query Params）名称、类型、默认值，是否与 `Doc-Design` **完全一致**？

##### 3.5. 响应与异常处理 (Response & Exception Handling)

* **检测点 5.1 (成功响应)**：`Doc-API` 中定义的**成功响应**结构、字段名、和 `success_response` 规范，是否与 `Doc-Design` **完全一致**？
* **检测点 5.2 (业务异常)**：`Doc-Design` 中提及的业务异常情况（例如"专家不存在"、"已经关注过该专家"、"不能取消关注未关注的专家"），是否在 `Doc-API` 或 `Doc-Service` 中有**对应的异常抛出**（例如 `ExpertNotFoundException`）？
* **检测点 5.3 (错误码 Code)**：`Doc-API` 中返回的错误码（Message Code）是否与 `Doc-Design` 中定义的**消息码规范**完全一致？
* **检测点 5.4 (HTTP 状态码)**：`Doc-API` 中返回的 HTTP 状态码（`400`, `404`, `500`）是否与 `Doc-Design` 中定义的**完全一致**？

##### 3.6. 跨层规范 (Cross-Cutting Concerns)

* **检测点 6.1 (安全规范)**：`Doc-Design` 中提及的安全要求（例如："此接口需要用户登录"、"用户只能查看自己的关注列表"）是否在 `Doc-API` 中得到体现（例如 `Depends(get_current_user)`）？
* **检测点 6.2 (日志规范)**：`Doc-Design` 中提及的日志记录点是否在对应的文档（`Doc-API` 或 `Doc-CRUD`）中有明确的日志记录指令？
* **检测点 6.3 (隐式规范)**：`Doc-Design` 中所有**隐式**的规范（例如，设计文档通篇使用 `public_id` 而非 `id`，软删除使用 `is_active`）是否在 `Doc-CRUD` 和 `Doc-API` 中得到了**严格遵守**？

##### 3.7. 多对多关系处理 (Many-to-Many Relationship)

* **检测点 7.1 (中间表操作)**：`Doc-CRUD` 和 `Doc-API` 是否正确处理了 `live_session_experts` 中间表的操作？
* **检测点 7.2 (查询逻辑)**：专家模块涉及通过 `live_session_experts` 关联查询 `live_sessions` 的逻辑是否在 `Doc-CRUD` 和 `Doc-API` 中得到正确体现？
