## 四、测试规范与要求

### 4.1. 通用测试规范

**测试原则：**
- **隔离性**: 每个测试函数独立运行，不依赖其他测试
- **可重复性**: 测试结果必须可重复，不受运行顺序影响
- **清晰性**: 测试意图明确，通过函数名和注释就能理解测试目的
- **完整性**: 覆盖正常流程、边界情况和异常情况

**测试覆盖要求：**
- **成功场景**: 正常业务流程的测试
- **失败场景**: 各种错误情况的测试
- **边界情况**: 文件大小限制、文件类型限制等
- **权限验证**: 用户权限控制的测试

### 4.2. 单元测试规范

**Mock使用原则：**
- 所有外部依赖（数据库、文件系统、其他服务）必须Mock
- 使用 `mocker.patch()` 进行Mock，而不是手动创建Mock对象
- Mock的返回值必须符合真实数据的结构
- 验证Mock被正确调用（参数、次数）

**单元测试结构（严格遵循现有风格）：**
```python
@pytest.mark.asyncio
async def test_<method_name>_<scenario>(mocker, mock_test_user):
    """
    测试<功能描述>
    - <前置条件>
    - <执行操作>
    - <验证结果>
    """
    # 准备测试数据和Mock
    mock_data = ...
    mock_method = mocker.patch("app.module.method", return_value=mock_data)
    
    # 执行测试
    result = await service.method(...)
    
    # 断言结果和调用
    assert result == expected_result
    mock_method.assert_called_once_with(...)
```

### 4.3. 集成测试规范

**集成测试特点：**
- 使用真实的数据库连接（测试数据库）
- 通过HTTP客户端发送真实请求
- 验证完整的请求-响应流程
- 验证数据库状态变化
