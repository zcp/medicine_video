### 3.5. 测试数据创建与外键依赖规范 (MANDATORY)

**🚨（关键）数据库外键约束问题**

当测试中创建有外键约束的对象时，**必须**先创建被引用的对象。

**问题场景**：
- 创建 `SessionTag` 时使用随机 `session_id=uuid.uuid4()` 和 `tag_id=uuid.uuid4()`，但这些 ID 在数据库中不存在
- 导致 `ForeignKeyViolationError`

**禁止行为**：
- ❌ **严禁**直接使用 `uuid.uuid4()` 作为外键值（如 `session_id`, `tag_id`）
- ❌ **严禁**假设外键值已经存在于数据库中
- ❌ **严禁**跳过创建被引用的对象

**正确做法**：
```python

from app.models.content_management import Tag

# 1. 创建直播间

    id=uuid.uuid4(),

    title=fake.company(),
    stream_key=f"stream_{uuid.uuid4().hex[:12]}"

db.add(room)
await db.flush()

# 2. 创建场次

    id=uuid.uuid4(),
    room_id=room.id,  # 使用已存在的 room_id
    status="scheduled",
    start_time=fake.date_time_this_year()
)
db.add(session)
await db.flush()

# 3. 创建标签
tag = Tag(
    id=uuid.uuid4(),
    name=f"标签_{uuid.uuid4().hex[:8]}"
)
db.add(tag)
await db.flush()

# 4. 创建关联

    session_id=session.id,  # 使用已存在的 session_id
```

#### 3.7.2. 增量数据库验证规范 (MANDATORY)

**🚨 关键原则**：在增量测试模式下，数据库中可能已经包含数据，因此**必须使用增量判断方式**验证数据库操作，而不是基于数据库总数判断。

**✅ 正确的增量验证模式**：

```python
@pytest.mark.asyncio
async def test_create_tag_success(db_session):
    """测试创建标签（增量验证）"""
    async for db in db_session:
        # ===== Arrange (准备) =====
        # [关键] 记录测试前的记录数量（基线）
        from sqlalchemy import select, func
        from app.models.content_management import Tag
        
        # 查询测试前的记录总数
        count_stmt = select(func.count(Tag.id))
        result = await db.execute(count_stmt)
        initial_count = result.scalar()
        
        # 准备测试数据
        tag_name = f"标签_{uuid.uuid4().hex[:8]}"
        tag = Tag(
            id=uuid.uuid4(),
            name=tag_name
        )
        
        # ===== Act (执行) =====
        db.add(tag)
        await db.commit()
        await db.refresh(tag)
        
        # ===== Assert (断言) =====
        # [关键] 验证增量：记录数应该增加1
        final_count_stmt = select(func.count(Tag.id))
        final_result = await db.execute(final_count_stmt)
        final_count = final_result.scalar()
        
        assert final_count == initial_count + 1, f"记录数应该增加1，但实际增加了{final_count - initial_count}"
        assert tag.name == tag_name
        assert tag.id is not None
```

#### 3.7.4. 增量验证时的查询 limit 处理规范 (MANDATORY)

**🚨 关键问题**：当数据库中存在大量旧数据时，使用默认 `limit` 的查询可能导致新创建的测试数据被截断，无法出现在查询结果中。

**✅ 正确的增量验证方式（使用足够大的 limit）**

```python

async def test_get_tags_list(db_session):
    """测试获取标签列表（增量验证）"""
    async for db in db_session:
        # ===== Arrange (准备) =====
        # [关键步骤1] 记录测试前的ID集合和数量（基线）
        from sqlalchemy import select
        from app.models.content_management import Tag
        
        initial_stmt = select(Tag.id).where(Tag.is_active == True)
        initial_result = await db.execute(initial_stmt)
        initial_ids = set(row[0] for row in initial_result.all())
        initial_count = len(initial_ids)
        
        # 创建2个标签
        tag1 = Tag(id=uuid.uuid4(), name=f"标签_{uuid.uuid4().hex[:8]}")
        tag2 = Tag(id=uuid.uuid4(), name=f"标签_{uuid.uuid4().hex[:8]}")

        await db.commit()
        await db.refresh(tag1)
        await db.refresh(tag2)
        
        # ===== Act (执行) =====
        # [关键步骤2] 传递足够大的 limit（如 1000），确保包含新创建的标签
        from app.crud import content_management as crud_content
        tags = await crud_content.get_tags(db, is_active=True, current_user_id=None, role=None)
        
        # ===== Assert (断言) =====
        # [关键步骤3] 验证增量：新创建的标签应该出现在列表中
        current_ids = set(tag.id for tag in tags)
        assert tag1.id in current_ids, "新创建的标签1应该出现在列表中"
        assert tag2.id in current_ids, "新创建的标签2应该出现在列表中"
        
        # [关键步骤4] 验证增量：列表长度应该至少增加2
```

### 3.8. Mock 对象配置规范 (MANDATORY for Service Layer Tests)

**🚨（关键）Service 层测试的特殊要求**

> **⚠️ 关键原则**：
> - Service 层测试中的 `db` 参数**必须是 `AsyncMock()` 对象**
> - Service 层方法调用 `await db.execute(...)`，因此 `db.execute()` 必须是异步方法
> - **禁止**使用 `Mock()` 作为 `db` 对象（会导致 `TypeError: object Mock can't be used in 'await' expression`）
> - **禁止**使用 `mocker.patch.object(db, "execute", ...)` 替换 `execute` 方法（会破坏 Mock 链）
> - **推荐**直接设置 `db.execute.return_value = mock_result`

> **正确的 Mock 配置示例**：
> ```python
> # ✅ 正确：使用 AsyncMock()
> from unittest.mock import AsyncMock, Mock
> db = AsyncMock()  # ← AsyncMock，不是 Mock()
> 
> # 简单调用链：.scalar_one_or_none()
> mock_tag = Mock(id=uuid.uuid4(), name="测试标签", is_active=True)
> mock_result = Mock(scalar_one_or_none=Mock(return_value=mock_tag))
> db.execute.return_value = mock_result  # ← 直接设置 return_value
> 
> # 复杂调用链：.scalars().all()
> mock_tags = [Mock(id=uuid.uuid4(), name=f"标签{i}") for i in range(3)]
> mock_result = Mock(scalars=Mock(return_value=Mock(all=Mock(return_value=mock_tags))))
> db.execute.return_value = mock_result  # ← 直接设置 return_value
> 
> # ❌ 错误：使用 Mock()
> db = Mock()  # ← Mock() 不支持 await
> 
> # ❌ 错误：使用 mocker.patch.object
> mocker.patch.object(db, "execute", new_callable=AsyncMock, return_value=mock_result)
> # ← 替换 execute 方法会破坏 Mock 链
> ```

## 4. 按层级生成的断言规范 (Assertion Rules by Layer)

你必须根据"核心测试哲学"（第 2 节）生成对应的断言逻辑。

### 4.1. 实用派测试 (Pragmatic: CRUD & API)

* **A. API 响应验证 (针对 API 测试)**:
  - **必须**同时验证 HTTP 状态码和完整的 JSON 响应结构（`code`, `message`, `data`）。
  - **必须**验证业务状态码（`response.json()["code"]`）和 `"data"` 内部的关键字段。
  - 对于失败响应，**必须**验证业务错误码（例如 `assert response.json()["code"] == 2001`）。

* **B. 数据库状态验证 [关键修改]**
  * **(针对 CRUD 层测试)**:
    - 在**同一个** `db_session` 中执行的 `create()`, `update()`, `delete()` 操作，**必须**在操作后立即使用 `await db.refresh(obj)` 或**再次查询**，来验证数据已正确持久化。
    - **[增量测试模式]**：对于涉及记录数量或列表查询的测试，**必须使用增量判断方式**（见 `3.7.2` 节）。在测试前记录基线状态（记录数、ID集合等），测试后只验证增量变化。
    - **[基于实际代码]**：**必须**根据实际模型的字段名来验证数据，**严禁**猜测字段名。

  * **(针对 API / Endpoint 层测试)**:
    - **[关键禁令]**：在 `await client.post(...)` 或 `await client.patch(...)`（它们使用*独立会话*）之后，**严禁**使用*原始的* `db_session`（用于 Arrange 阶段）来 `get()` 或查询对象。这样做**必定**会读取到 SQLAlchemy 身份映射（Identity Map）中的**陈旧缓存**，导致测试失败。

  * **[API 层正确验证方案]**: 要验证 API 调用后的数据库*真实*状态，**必须**选择以下两种方法之一：
    1. **(首选 - 验证响应)**: **只断言** API 返回的 `response.json()["data"]` 中的内容是否正确（例如 `assert response.json()["data"]["name"] == "新标签"`）。
    2. **(次选 - 验证数据库)**: **必须**导入 `async_session_factory`，创建一个**全新的、独立的会话**（`async with async_session_factory() as new_db:`），并使用这个 `new_db` 会话执行显式的 `select()` 语句来查询数据库，以获取**最新**数据。
    - **[增量测试模式]**：如果涉及记录数量验证，**必须使用增量判断方式**。在API调用前记录基线状态，调用后验证增量变化。

### 4.2. 学院派测试 (Academic: Service)

* **A. 异常逻辑验证**:
  - **必须**使用 `with pytest.raises(PermissionDeniedException):` 来验证在特定条件下是否正确抛出了**自定义业务异常**。

* **B. 行为验证 (Mocks)**:
  - **必须**使用 `mock_crud.assert_called_once_with(...)` 来验证依赖是否被正确调用。
  - **[关键] Mock 路径规范 (MANDATORY)**:
    - 假设 Service 层使用别名导入 (`from app.crud import content_management as crud_content`)。
    - 测试代码在 `mocker.patch()` 中**必须**使用**原始模块路径** (`"app.crud.content_management.create_tag"`)。
    - **必须**为异步函数使用 `new_callable=AsyncMock`。
  - **[关键] Mock 断言参数格式规范 (MANDATORY)**:
    - **断言参数必须与实际调用方式完全一致**：
      - 如果 Service 层调用时使用**位置参数**（如 `await crud_content.create_tag(db, tag)`），则断言必须使用**位置参数**（`mock_create.assert_called_once_with(db, tag)`）。
      - 如果 Service 层调用时使用**关键字参数**（如 `await crud_content.create_tag(db=db, tag_in=...)`），则断言可以使用**关键字参数**（`mock_create.assert_called_once_with(db=db, tag_in=...)`）。
    - **⚠️ 常见错误**：使用关键字参数断言（`db=db`），但实际调用使用位置参数（`db`），会导致断言失败。
    - **正确做法**：**必须**先检查实际Service层代码的调用方式，然后使用相同格式的断言。
