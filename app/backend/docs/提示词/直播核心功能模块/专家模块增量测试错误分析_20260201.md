## 🔍 详细错误分析

### 1️⃣ FeaturedExpertItem Schema 缺少 is_active 字段

**错误信息**:
```
assert response.status_code == 200
assert 500 == 200
```

**错误原因**:
- API 层 `get_featured_experts` 在 line 150 调用 `FeaturedExpertItem.model_validate(expert)`
- 但 `FeaturedExpertItem` Schema（line 74-83）缺少 `is_active` 字段
- Pydantic 验证失败导致 500 错误

**修复方法**:
```python
# app/schemas/experts.py line 74-83
class FeaturedExpertItem(BaseModel):
    """首页推荐专家简要Schema"""
    model_config = ConfigDict(from_attributes=True)
    
    id: uuid.UUID
    name: str
    title: Optional[str] = None
    hospital: Optional[str] = None
    avatar_url: Optional[str] = None
    is_active: bool = True  # ✅ 新增此行
```

**教训**: Model 新增字段后，必须同步更新所有相关 Schema。

### 2️⃣ 角色名不匹配（USER vs REGULAR）

**错误信息**:
```
assert response.status_code == 404
assert 403 == 404
WARNING: 权限不足: 需要用户资源操作权限，当前角色=USER
```

**错误原因**:
- `conftest.py` line 337 定义 `regular_user_role = "USER"`
- 但 `expert_service.py` line 94 的 `_check_user_resource_permission` 检查的是 `['REGULAR', 'ADMIN', 'SUPERADMIN']`
- 权限检查在可见性检查**之前**执行（line 736 先调用 `_check_user_resource_permission`，line 740 才调用 `_check_expert_visibility`）
- 因此返回 403 而非 404

**修复方法**:
```python
# tests/conftest.py line 335-337
@pytest.fixture
def regular_user_role() -> str:
    """普通用户角色"""
    return "REGULAR"  # ✅ 改为 REGULAR
```

**教训**: 
1. 角色名必须从设计文档或源码读取，不得臆造
2. 权限检查与业务逻辑检查的顺序影响 HTTP 状态码

---

### 3️⃣ UUID 对象无法 JSON 序列化

**错误信息**:
```
assert response.status_code == 201
assert 500 == 201
ERROR: 批量导入异常: user_id=b15356a0, file=experts.csv, error=TypeError
```

**错误原因**:
- `expert_service.py` line 427 将 UUID 对象添加到列表：`created_expert_ids.append(expert.id)`
- API 层 line 303 访问 `result["created_expert_ids"]` 并尝试 JSON 序列化
- UUID 对象无法直接序列化为 JSON，导致 TypeError

**修复方法**:
```python
# app/services/expert_service.py line 423-427
expert = await crud.create_expert(self.db, expert_data)
await self.db.commit()
success += 1
if len(created_expert_ids) < 100:
    created_expert_ids.append(str(expert.id))  # ✅ 转为字符串
```

**教训**: Service 层返回字典时，所有 UUID/datetime 等对象必须序列化为字符串。

## 📚 文档改进建议

### 1. 测试母版补充

在 `测试代码生成提示词母版.md` 中新增：

#### 3.X 角色与权限测试规范
- JWT Token 中的角色字段必须从设计文档或 `conftest.py` 读取
- 禁止臆造角色名（如 USER、user、GUEST）
- 权限检查顺序：参数验证（400）→ 资源可见性（404）→ 权限检查（403）

#### 3.Y UUID 序列化规范
- Service 层返回字典时，UUID 字段必须转为字符串
- 批量操作的 `created_ids` 列表必须是字符串类型

### 2. 增量测试提示词母版补充

在 `增量开发_测试代码生成提示词---生成指令母版.md` 的 **Section 4.2** 补充：
- **角色枚举定义**：提取所有有效角色名（REGULAR、ADMIN、SUPERADMIN）
- **权限检查顺序**：明确执行顺序，测试断言须与实际顺序一致

在 **Section 5.5.2** 新增：
- **返回值序列化规范**：UUID/datetime 必须转为字符串

在 **Section 6.4** 补充：
- 第 4 点：从 conftest.py 提取角色枚举值，避免臆造
- 第 8 点：检查 Schema 字段是否与 Model 同步

在 **Section 6.5** 补充检查项：
- 角色枚举是否从源码读取
- 权限检查顺序是否正确
- UUID 是否已序列化
- Schema 字段是否已同步

### 3. 设计文档补充

在专家模块设计文档中明确：

#### 权限检查顺序规范
1. **优先级1**: 参数格式验证（400）
2. **优先级2**: 资源存在性与可见性检查（404）
3. **优先级3**: 权限检查（403）

**例外**: 如果权限检查不依赖资源查询，可先执行以提高性能。
