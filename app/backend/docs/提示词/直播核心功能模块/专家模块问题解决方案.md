@router.patch("/experts/{expert_id}", response_model=ExpertItem)  # 改为 PATCH
async def update_expert(
    expert_id: UUID,
    expert_update: ExpertUpdate,
    db: Session = Depends(get_db),
    current_user: dict = Depends(get_current_user)
):
    """
    更新专家（仅管理员，使用PATCH方法）
    """
    # 解析用户身份
    user_id = uuid.UUID(current_user.get("sub"))
    role_str = current_user.get("role", "REGULAR")
    user_role = LiveRoomUserRole.get(role_str, LiveRoomUserRole.REGULAR)
    
    try:
        expert = await expert_service.update_expert(
            db=db,
            expert_id=expert_id,
            expert_update=expert_update,
            user_id=user_id,
            user_role=user_role
        )
        return success_response(data=expert)
    except ExpertNotFoundException as e:
        return error_response(status_code=404, code=4004, message=str(e))
    except PermissionDeniedException as e:
        return error_response(status_code=403, code=3003, message=str(e))
    except Exception as e:
        return error_response(status_code=500, code=5000, message="服务器内部错误")

**文件**：`docs/提示词/直播核心功能模块/专家模块设计文档-专家信息-专家关注---Service层和API层代码生成提示词.md`

**添加**：
```markdown
### 5.6. 日志脱敏规范

根据设计文档 Section 1.4.1（日志脱敏规范），所有API接口在记录日志时必须对以下敏感信息进行脱敏：

**脱敏对象**:
- JWT Token完整字符串
- Authorization请求头
- 数据库连接URL中的密码
- 专家的联系方式（contact_info字段）

**实现方式**:
- 使用统一的日志脱敏工具函数 `sanitize_log_message()`
- JWT Token仅记录前8个字符：`token[:8] + "..."`
- contact_info字段仅记录字段存在性，不记录具体内容

**示例**:
```python
# ❌ 错误：直接记录完整Token
logger.info(f"User {user_id} created expert with token {token}")

# ✅ 正确：脱敏记录Token
logger.info(f"User {user_id} created expert with token {token[:8]}...")
```
```

#### 4. 修复问题5：缺少 `include_live_status` 参数

**文件**：`docs/提示词/直播核心功能模块/专家模块设计文档-专家信息-专家关注---Service层和API层代码生成提示词.md`

```python
@router.get("/experts/followed")
async def get_followed_experts(
    page: int = 1,
    size: int = 20,
    include_live_status: Optional[bool] = True,  # 新增参数
    db: Session = Depends(get_db),
    current_user: dict = Depends(get_current_user)
):
    """
    获取关注的专家列表（分页，需登录）
    
    参数:
        page: 页码
        size: 每页数量
        include_live_status: 是否包含直播状态，默认true
    """
    # 解析用户身份
    user_id = uuid.UUID(current_user.get("user_id"))
    
    try:
        skip = (page - 1) * size
        
        # 根据include_live_status参数决定返回内容
        if include_live_status:
            # 包含直播状态
            subscriptions, total = await expert_service.get_followed_experts_multi_and_total(
                db=db, user_id=user_id, skip=skip, limit=size
            )
            
            # 获取直播状态
            result = await expert_service.get_followed_experts_with_live_status(
                db=db, user_id=user_id
            )
        else:
            # 不包含直播状态
            subscriptions, total = await expert_service.get_followed_experts_multi_and_total(
                db=db, user_id=user_id, skip=skip, limit=size
            )
            result = subscriptions
        
        return success_response(data={
            "items": result if include_live_status else subscriptions,
            "total": total,
            "page": page,
            "size": size
        })
    except Exception as e:
        return error_response(status_code=500, code=5000, message="服务器内部错误")
```

## 不修复问题1和问题7的理由

### 问题1：API路径不一致

**不修复理由**：
1. **设计文档的API路径设计不合理**：
   - `/api/v1/admin/experts` 不符合REST最佳实践
   - `/api/v1/featured-experts` 违反资源层级
   - `/api/v1/experts/{expert_id}/sessions` 设计不够清晰

2. **提示词文档的API路径更合理**：
   - `/api/v1/experts` - 更RESTful
   - `/api/v1/experts/featured` - 符合资源层级
   - `/api/v1/experts/{expert_id}/follow` - 更RESTful

3. **建议后续优化**：
   - 在统一的API规范文档中明确API路径设计规则
   - 统一所有模块的API路径风格

**结论**：提示词文档的API路径更合理，建议保留。

### 问题7：错误码扩展未定义

**不修复理由**：
1. **设计文档的错误码体系不完整**：
   - 缺少HTTP状态码规范
   - 锺少部分业务错误码（3003、4004、5000）

2. **提示词文档的错误码更符合实际需求**：
   - 3003：权限不足（比3002更具体）
   - 4004：资源不存在（与2001区分）
   - 5000：服务器内部错误

3. **建议后续优化**：
   - 在设计文档中补充完整的错误码体系
   - 统一所有模块的错误码规范

**结论**：提示词文档的错误码扩展是合理的，建议在后续统一错误码体系时正式定义。
