## 更新指南

### 9.1. 更新内容模板

每个提示词文档需要添加的安全配置 Section 应包含以下内容：

```markdown
## X. 全项目安全配置规范（适用于所有模块）

### X.1. 环境变量配置安全规范

#### X.1.1. CORS 配置规范

**核心内容**：
- **禁止**在代码中硬编码 CORS 配置（如 `allow_origins=["*"]`）
- **必须**从环境变量读取 CORS 配置
- **配置格式**: 支持逗号分隔的多个域名（如 `http://localhost:5175,https://example.com`）

**实现示例**：
```python
# config.py
CORS_ORIGINS_STR: str = os.getenv("CORS_ORIGINS", "*")
BACKEND_CORS_ORIGINS: List[str] = [
    origin.strip() 
    for origin in CORS_ORIGINS_STR.split(",") 
    if origin.strip()
]

# main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.BACKEND_CORS_ORIGINS,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**生产环境要求**: CORS 配置**必须**为具体域名，**严禁**使用 `["*"]`

#### X.1.2. 敏感信息配置规范

**核心内容**：
- **禁止**在代码中硬编码以下敏感信息:
  - 数据库密码、用户名
  - JWT 密钥（`JWT_SECRET_KEY`）
  - 第三方服务密钥（如 Redis、Celery broker）
- **必须**通过环境变量读取所有敏感配置
- **禁止**为敏感信息设置不安全的默认值

**正确和错误的示例对比**：
- ❌ 错误: `POSTGRES_PASSWORD = os.getenv("POSTGRES_PASSWORD", "CHANGE_ME")`
- ❌ 错误: `JWT_SECRET_KEY = os.getenv("JWT_SECRET_KEY", "my-key")`
- ✅ 正确: `POSTGRES_PASSWORD = os.getenv("POSTGRES_PASSWORD", "")`

#### X.1.3. 配置验证规范

**核心内容**：
- **必须**在应用启动时验证必需的敏感配置
- **缺失配置**必须抛出明确的异常，而非使用不安全的默认值
- **数据库密码验证**: 检查密码是否为空
- **JWT 密钥验证**: 检查密钥长度（≥32字符）

**实现示例**：
```python
class Settings(BaseSettings):
    POSTGRES_PASSWORD: str = os.getenv("POSTGRES_PASSWORD", "")
    JWT_SECRET_KEY: str = os.getenv("JWT_SECRET_KEY", "")
    
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        self._validate_required_configs()
    
    def _validate_required_configs(self):
        """验证必需的敏感配置"""
        if not self.POSTGRES_PASSWORD:
            raise ValueError("POSTGRES_PASSWORD 环境变量未设置。")
        if len(self.JWT_SECRET_KEY) < 32:
            raise ValueError("JWT_SECRET_KEY 长度不足32个字符。")
```

### X.2. 日志安全规范（适用于所有模块）

#### X.2.1. 禁止在日志中打印敏感信息

**核心内容**：
- ❌ **禁止**: 打印完整的数据库连接 URL（包含密码）
- ✅ **必须**: 只打印非敏感的连接信息

#### X.2.2. 日志脱敏规范（推荐实现）

**核心内容**：
- 创建日志脱敏工具函数 `app/core/logging_utils.py`
- 实现脱敏日志格式化器 `SanitizedFormatter`
- 自动脱敏数据库连接 URL 和 JWT 密钥

#### X.2.3. 错误消息脱敏

**核心内容**：
- **禁止**在异常处理中暴露敏感信息
- **必须**只返回通用的错误消息给客户端

### X.3. 环境变量文件管理规范（适用于所有模块）

#### X.3.1. `.env.example` 模板文件

**核心内容**：
- **必须**提供 `.env.example` 模板文件
- **必须**包含所有必需的环境变量（包括说明和示例）

#### X.3.2. `.gitignore` 规范

**核心内容**：
- **必须**在 `.gitignore` 中忽略所有环境变量文件
- **必须**保留 `.env.example` 模板文件

### X.4. 生产环境安全规范（适用于所有模块）

#### X.4.1. 密钥管理服务（推荐）

**核心内容**：
- 生产环境**强烈建议**使用密钥管理服务，而非环境变量
- **支持的密钥管理服务**: AWS Secrets Manager、Azure Key Vault、GCP Secret Manager、HashiCorp Vault

#### X.4.2. 环境变量注入（Docker/K8s）

**核心内容**：
- 使用环境变量注入或密钥管理服务，而非在镜像中包含 `.env` 文件

#### X.4.3. 文件权限控制（Linux/Unix）

**核心内容**：
- **必须**设置环境变量文件的权限，防止未授权访问

### X.5. 密钥生成最佳实践（适用于所有模块）

#### X.5.1. JWT 密钥生成

**核心内容**：
- **推荐长度**: 64 字符（128位加密强度）
- **生成方式**: `openssl rand -hex 32` 或 `python -c "import secrets; print(secrets.token_hex(32))"`

#### X.5.2. 数据库密码生成

**核心内容**：
- **推荐长度**: 16-32 字符
- **生成方式**: `openssl rand -base64 16` 或 `pwgen -s 16 1`

#### X.5.3. 密钥命名规范

**核心内容**：
- 使用大写字母和下划线：`POSTGRES_PASSWORD`, `JWT_SECRET_KEY`
- 使用有意义的名称：`CORS_ORIGINS` 而非 `CORS`
- 分组前缀：`POSTGRES_*`, `JWT_*`, `CELERY_*`
```
