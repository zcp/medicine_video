## 🎯 使用场景

当你需要为新的功能模块生成 SQLAlchemy 模型和 Pydantic Schema 的代码生成提示词时，可以使用此母版。

**适用情况**:
- ✅ 新增功能模块，需要创建新的数据库表和Schema
- ✅ 已有设计文档，需要生成代码生成提示词
- ✅ 需要确保生成的提示词符合项目规范和最佳实践

## 📝 使用步骤

### 步骤1: 准备设计文档

确保你已经有了完整的设计文档，包含以下内容：

**必需内容**:
- ✅ 数据库设计（表结构、字段、索引、外键约束）
- ✅ API设计（请求响应Schema定义、字段验证要求）
- ✅ 编程规范（编码规范、命名规范、项目结构规范）

**设计文档示例位置**:
- `docs/03_系统设计/直播核心功能设计文档_v6_[模块名]设计文档.md`

### 步骤2: 使用母版生成提示词文档

#### 方式1: 直接使用AI助手（推荐）

**提示词模板**:

```
请严格按照以下母版文档的要求，根据我提供的设计文档，生成SQLAlchemy模型和Pydantic Schema的代码生成提示词文档。

**母版文档**: @docs/提示词/提示词母版/SQLAlchemy模型和Pydantic Schema代码生成提示词母版.md

**设计文档**: @docs/03_系统设计/[你的设计文档路径].md

**要求**:
1. 默认同时生成两种提示词文档（SQLAlchemy模型 + Pydantic Schema）
2. 必须完全遵循母版文档中的所有要求和规范
3. 必须提取设计文档中的所有相关规范和要求
4. 必须支持增量开发模式
5. 生成的提示词文档必须可以直接用于指导AI生成代码

**输出**:
- 文档1: `[功能模块名称]数据库模型代码生成提示词.md`
- 文档2: `[功能模块名称]Pydantic模型代码生成提示词.md`
```

#### 方式2: 手动参考母版编写

如果你选择手动编写，请按照母版文档的结构逐一填充内容：

1. **文档头部** - 填写模块名称、版本、日期
2. **角色定义** - 根据母版要求定义AI角色
3. **任务目标** - 明确要生成的文件和类
4. **核心上下文信息** - 提取设计文档中的规范
5. **代码生成具体要求** - 按照母版要求详细说明
6. **完整性检查清单** - 列出所有必须满足的条件
7. **最终交付** - 说明交付物和使用步骤

## 🔄 完整工作流程

### 阶段1: 准备阶段

1. **确认设计文档完整**
   - 检查设计文档是否包含数据库设计和API设计
   - 确认设计文档中的规范要求清晰明确

2. **确认项目结构**
   - 确认 `app/models/` 目录结构
   - 确认 `app/schemas/` 目录结构
   - 确认现有模型文件作为参考

### 阶段2: 生成提示词文档

1. **使用母版生成提示词**
   - 使用方式1（AI助手）或方式2（手动编写）
   - 确保同时生成两种提示词文档

2. **验证提示词文档**
   - 使用检查清单验证完整性
   - 确保所有关键内容都已包含

### 阶段3: 使用提示词生成代码

1. **生成SQLAlchemy模型代码**
   - 使用生成的SQLAlchemy模型提示词文档
   - 生成 `app/models/[模块名].py` 文件
   - 更新 `app/models/__init__.py`

2. **生成Pydantic Schema代码**
   - 使用生成的Pydantic Schema提示词文档
   - 生成 `app/schemas/[模块名].py` 文件
   - 更新 `app/schemas/__init__.py`

3. **初始化数据库**
   - 运行 `python app/init_db.py` 创建数据库表

## ⚠️ 注意事项

### 1. 增量开发模式

**重要**: 生成的提示词文档必须明确说明增量开发模式：

- ✅ 只能新增文件，不能修改现有文件
- ✅ 只能追加导入语句到 `__init__.py`
- ❌ 不能修改 `database.py`、`init_db.py` 等现有文件

### 2. Base类导入

**关键**: 必须在提示词中明确说明：

```python
from app.database import Base  # 正确
# from app.models.base import Base  # ❌ 错误：base.py 不存在
```

### 3. 数据库初始化脚本

**推荐**: 使用 `init_db.py`（自动识别新模型）

**不推荐**: 使用 `create_tables.py`（需要修改脚本，违反增量开发原则）

### 4. 同时生成两种文档

**默认行为**: 除非用户明确指定，否则必须同时生成两种提示词文档。

**原因**: 
- SQLAlchemy模型和Pydantic Schema是配套的
- 先有模型，再有Schema
- 同时生成可以确保一致性

## 🔍 常见问题

### Q1: 如果设计文档中没有某些规范，怎么办？

**A**: 按照母版文档中的优先级规则：
1. **设计文档规范为最高优先级** - 如果设计文档中有，必须使用
2. **SQLAlchemy/Pydantic最佳实践为次优先级** - 如果设计文档中没有，使用标准规范
3. **项目现有代码风格为参考** - 参考现有代码，但以设计文档为准

### Q2: 可以只生成其中一种提示词文档吗？

**A**: 可以，但需要在提示词中明确指定：

```
**要求**: 只生成SQLAlchemy模型代码生成提示词文档（不生成Pydantic Schema）
```

或

```
**要求**: 只生成Pydantic Schema代码生成提示词文档（不生成SQLAlchemy模型）
```

### Q3: 如何确保生成的提示词文档质量？

**A**: 使用检查清单验证：
- 检查是否包含所有必需章节
- 检查是否包含所有关键观察点
- 检查是否包含完整的示例代码
- 检查是否包含增量开发说明
- 检查是否包含最终交付说明

### Q4: 生成的提示词文档可以直接使用吗？

**A**: 是的，生成的提示词文档可以直接用于指导AI生成代码。但建议：
1. 先验证提示词文档的完整性
2. 确认所有示例代码正确
3. 确认增量开发说明清晰
4. 确认最终交付说明完整
