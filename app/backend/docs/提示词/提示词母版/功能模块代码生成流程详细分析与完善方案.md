### 2.2. 问题2: 修复流程缺少重新检测步骤

**问题描述**:
- 步骤3和步骤5的修复流程中，修复后需要重新执行一致性检测
- 但是当前流程描述中，修复后直接标记为"COMPLETED"，没有明确说明需要重新执行检测
- 这可能导致修复后的问题没有被验证

**修复流程应该是**:
```
发现问题 → 分析问题 → 修复问题 → 重新执行检测 → 验证修复效果
```

**当前流程**:
```
发现问题 → 分析问题 → 修复问题 → 标记为COMPLETED ❌
```

**修复方案**:
在修复流程中明确说明：
1. 修复后必须重新执行一致性检测（步骤3.2或步骤5.2）
2. 只有当重新检测通过后，才能标记为"COMPLETED"
3. 如果修复后仍有问题，继续修复循环（最多max_fix_iterations次）

2. 分析问题根本原因
3. 执行修复（修复代码或提示词文档）

5. 如果检测通过 → 标记为COMPLETED，退出修复循环

   - 如果迭代次数 < max_fix_iterations → 返回步骤2，继续修复

## 5. 自动修复流程 (Auto-Fix Process)

### 5.1. 修复触发条件

当一致性检测发现问题时，如果 `auto_fix=True`，自动进入修复流程。

### 5.2. 修复迭代流程

**修复循环**:
```python
fix_iteration = 0
while fix_iteration < max_fix_iterations:
    # 1. 读取一致性检测报告
    issues = extract_issues_from_report(report_path)
    
    if not issues:
        # 没有问题，退出循环
        mark_step_as_completed()
        break
    
    # 2. 分析问题根本原因
    root_causes = analyze_root_causes(issues)
    
    # 3. 执行修复
    fixes_applied = apply_fixes(root_causes)
    
    # 4. 重新执行一致性检测
    new_report = re_run_consistency_check()
    new_issues = extract_issues_from_report(new_report)
    
    # 5. 验证修复效果
    if not new_issues:
        # 修复成功，退出循环
        mark_step_as_completed()
        break
    else:
        # 仍有问题，继续修复
        fix_iteration += 1
        if fix_iteration >= max_fix_iterations:
            # 达到最大迭代次数，标记为失败
            mark_step_as_failed()
            break
```

### 5.3. 修复策略

#### 策略1: 模型代码修复（步骤3发现问题）

**修复流程**:
1. 读取一致性检测报告，提取问题列表
2. 分析每个问题的根本原因（提示词文档问题 vs 代码生成问题）
3. **如果问题在提示词文档**:
   - 更新步骤1生成的提示词文档
   - 重新执行步骤2生成代码
   - 重新执行步骤3.2检测
4. **如果问题在代码**:
   - 直接修复代码文件
   - 重新执行步骤3.2检测
5. 验证修复效果：
   - 如果检测通过 → 标记步骤3为COMPLETED，继续步骤4
   - 如果检测未通过 → 继续修复循环（最多max_fix_iterations次）

#### 策略2: 提示词文档修复（步骤5发现问题）

**修复流程**:
1. 读取一致性检测报告，提取问题列表
2. 分析每个问题：缺失 vs 不一致 vs 冗余
3. **对于缺失项**: 在步骤4生成的提示词文档中添加相应内容
4. **对于不一致项**: 修改步骤4生成的提示词文档使其与设计文档一致
5. **对于冗余项**: 评估是否需要保留（如果设计文档未提及但符合最佳实践，可保留）
6. 重新执行步骤5.2检测
7. 验证修复效果：
   - 如果检测通过 → 标记步骤5为COMPLETED，继续步骤6
   - 如果检测未通过 → 继续修复循环（最多max_fix_iterations次）
