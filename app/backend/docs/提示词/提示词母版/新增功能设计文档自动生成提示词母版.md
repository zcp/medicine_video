## **2.6 编码规范（Service/CRUD 层结构）**

**【关键架构：必须严格遵守“学院派”分层】**

### CRUD 层 (智能层)：

  * **必须封装原子性数据库操作**。
  * **必须在写操作（create, update, delete）函数内部处理事务**。
  * **必须包含 `try...except IntegrityError/Exception...finally` 块**。
  * **必须处理 `db.commit()` 和 `db.rollback()`**。
  * **必须处理数据库错误日志** (`logger.error`)。
  * **必须**遵循“2.10 安全规范”中的“安全异步异常处理”原则。
  * 不做业务逻辑或权限检查。

**示例：CRUD 层的事务处理（必须遵循此模式）**

```python
async def create(db: AsyncSession, obj_in: Schema) -> Model:
    # 提前提取日志所需变量
    obj_data_for_logging = obj_in.model_dump() 
    
    try:
        db_obj = Model(**obj_data_for_logging)
        db.add(db_obj)
        await db.commit()
        await db.refresh(db_obj)
        logger.info(f"创建成功: {db_obj.id}")
        return db_obj
    except IntegrityError as e:
        await db.rollback()
        logger.error(f"创建失败 (完整性错误): data={obj_data_for_logging}, error={e}", exc_info=True)
        # 抛出自定义异常或返回 None，由 Service 层处理
        raise DatabaseIntegrityException("创建资源时发生唯一键冲突")
    except Exception as e:
        await db.rollback()
        logger.error(f"创建失败 (未知DB错误): data={obj_data_for_logging}, error={e}", exc_info=True)
        raise DatabaseOperationException(f"数据库操作失败: {e}")
```

### Service 层 (业务逻辑层)：

  * **必须只负责业务逻辑**（权限检查、规则校验）。
  * **严禁控制事务** (`db.commit()` / `db.rollback()` 均禁止)。
  * **严禁抛出 `HTTPException`**。
  * **必须抛出自定义 Python 异常**（例如 `raise RoomNotFoundException(Exception)` 或 `raise PermissionDeniedException(Exception)`）。
  * 负责调用一个或多个 CRUD 函数来组合业务。

### router 层 (API 接口层)：

  * 只负责参数绑定、依赖注入、调用 Service。
  * **必须使用 `try...except` 块捕获 Service 层抛出的自定义异常**。
  * **必须将自定义异常转换为统一的 `JSONResponse` 错误**（调用 `error_response()`）。
  * **必须**遵循“2.10 安全规范”中的“安全异步异常处理”原则。

## **2.9 异常处理规范**

**【学院派异常处理流程：必须遵守】**

1.  **CRUD 层**：捕获数据库异常（如 `IntegrityError`），`rollback` 事务，记录 `logger.error`，然后 `raise` 一个自定义的数据库异常（如 `DatabaseIntegrityException`）。
2.  **Service 层**：执行业务检查。如果失败（如权限不足），`raise` 一个自定义的业务异常（如 `PermissionDeniedException(Exception)`）。Service 层**不**捕获 CRUD 层的数据库异常（任其上浮）。
3.  **API (Endpoint) 层**：**必须**使用 `try...except` 块。
      * `except PermissionDeniedException as e:` -\> `return JSONResponse(status_code=403, content=error_response(code=3002, ...))`
      * `except RoomNotFoundException as e:` -\> `return JSONResponse(status_code=404, content=error_response(code=2001, ...))`
      * `except DatabaseIntegrityException as e:` -\> `return JSONResponse(status_code=400, content=error_response(code=4001 或 2002, ...))`
      * `except DatabaseOperationException as e:` -\> `return JSONResponse(status_code=500, content=error_response(code=1xxx, ...))`（CRUD 层非 IntegrityError 的 DB 异常须抛此异常）
      * `except Exception as e:` -\> `return JSONResponse(status_code=500, content=error_response(code=1xxx, ...))`

## **2.13 列表类接口分页规范（必须继承）**

凡返回**列表**的 GET 接口（如管理端列表、用户侧列表、某资源下的子资源列表），**必须**采用分页机制：

## **2.13.1 列表筛选与搜索规范（通用，必须继承）**

凡返回**列表**的 GET 接口若需支持搜索（管理端列表、或前端《列表筛选与搜索规范》要求），**必须**在设计文档 API 设计中包含以下约定，且**保持通用性**（不写死字段名）。列表 GET 若支持搜索，**默认**须同时支持 **ID 精确查询**（q + search_type=id）与**字符串字段模糊查询**（对可配置的字符串搜索字段做模糊匹配）；字符串搜索字段由设计文档按模块指定（如 name、title、slug、displayName 等），不限定为 name。

  * **Query 参数**：`q`（可选，关键词）、`search_type`（可选，如 `id` | `keyword` 或未传表示关键词）。当 `search_type=id` 且 `q` 非空时，`q` 按主键 UUID 精确匹配，API 层须校验 `q` 为合法 UUID，非法则 400。
  * **字符串模糊**：当 `search_type` 非 `id`（或未传）且 `q` 非空时，对「**本接口在设计文档中指定的字符串类型字段**」做模糊匹配（如 SQL `ILIKE`）。**设计文档的 API 设计章节必须写明本列表的「字符串搜索字段」**（如 name、title、slug 等，由业务决定，不同模块可能不同；禁止在母版或文档中写死为 name）。若该列表支持搜索却未写明，须在 API 设计章节中**明确配置**该列表的字符串搜索字段（可多列），不得省略。
  * **CRUD 层**：同一套 WHERE 条件（含 q/search_type 条件）用于总数查询与分页列表查询；与前端《列表筛选与搜索规范》对齐。
