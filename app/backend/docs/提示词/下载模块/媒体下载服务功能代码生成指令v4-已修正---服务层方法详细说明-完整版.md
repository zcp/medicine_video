### 6.1.1. 服务层方法实现通用流程（核心规范）

**所有服务层方法必须遵循以下流程，确保代码的一致性、健壮性和可维护性**：

---

#### 🔹 第一步：变量提取（安全异步异常处理）

**【规则】**：如果方法需要在异常处理中访问ORM对象（如`task`, `user`）的属性进行日志记录或错误处理，这些属性**必须在进入`try`块之前**被提取并存储到局部变量中。

**【适用场景】**：
- 需要在`except`块中记录包含ID、状态等信息的日志
- 需要在异常后访问对象属性进行错误处理
- 涉及数据库操作且可能抛出`SQLAlchemyError`

**【不适用场景】**：
- 纯工具方法（不涉及ORM对象）
- 不执行数据库操作的方法
- 不需要在异常处理中访问对象属性

**【实现示例】**：
```python
def example_method(self, task_id: uuid.UUID, user_id: uuid.UUID) -> DownloadTask:
    # ✅ 第一步：变量提取
    user_id_for_logging = str(user_id)
    task_id_for_logging = str(task_id)
    
    # 继续后续流程...
```

**【提取原则】**：
- 所有在`except`块中使用的ID字段
- 所有需要记录到日志中的关键信息
- 使用`str()`转换UUID为字符串（便于日志记录）

---

#### 🔹 第二步：记录开始日志

**【必须】**：使用`logger.info`记录方法调用开始，包含关键参数信息。

**【格式】**：
```python
logger.info(f"方法名: 关键参数={参数值}")
```

**【示例】**：
```python
logger.info(f"Creating download task for user {user_id_for_logging}: {task_data.model_dump()}")
```

---

#### 🔹 第三步：try-except包裹

**【必须】**：将所有数据库操作包裹在`try...except`块中。

**【必须包含的except块】**：
1. `except SQLAlchemyError` - 捕获数据库相关异常
2. `except Exception` - 捕获其他未知异常（根据需要）

**【基本结构】**：
```python
try:
    # 业务逻辑
    pass
except SQLAlchemyError as e:
    # 数据库异常处理
    logger.error(f"Database error - 用户ID: {user_id_for_logging}, 错误: {str(e)}", exc_info=True)
    self.db.rollback()
    raise DatabaseError(f"Database error: {str(e)}")
except Exception as e:
    # 其他异常处理
    logger.error(f"Unexpected error - 用户ID: {user_id_for_logging}, 错误: {str(e)}", exc_info=True)
    self.db.rollback()
    raise
```

---

#### 🔹 第四步：执行业务逻辑

**【在try块中执行】**：

1. **权限验证**（如需要）：
   ```python
   task = self.db.query(DownloadTask).filter(DownloadTask.id == task_id).first()
   if not task:
       raise TaskNotFoundError(f"Task {task_id} not found")
   if str(task.user_id) != user_id_for_logging:
       raise TaskNotFoundError(f"Task {task_id} not found")
   ```

2. **数据库操作**：
   - 查询：`self.db.query(...).filter(...).first()`
   - 创建：`obj = Model(...); self.db.add(obj)`
   - 更新：`obj.field = new_value`
   - 删除：`self.db.delete(obj)`

3. **【必须】提交事务**（如有修改操作）：
   ```python
   self.db.commit()
   ```

4. **【可选】刷新对象**（获取数据库生成的值）：
   ```python
   self.db.refresh(obj)
   ```

5. **记录成功日志**：
   ```python
   logger.info(f"Successfully completed operation for task {task_id_for_logging}")
   ```

---

#### 🔹 第五步：异常处理

**【必须】在except块中执行**：

1. **【必须】使用提取的局部变量记录日志**：
   ```python
   logger.error(
       f"Error - 用户ID: {user_id_for_logging}, 任务ID: {task_id_for_logging}, 错误: {str(e)}",
       exc_info=True  # 包含完整堆栈跟踪
   )
   ```

2. **【必须】执行rollback**（如涉及数据库修改）：
   ```python
   self.db.rollback()
   ```

3. **【可选】刷新对象**（恢复对象到数据库状态）：
   ```python
   self.db.refresh(task)  # 仅当对象已加载时
   ```

4. **【必须】抛出适当的异常**：
   ```python
   raise DatabaseError(f"Database error: {str(e)}")
   # 或
   raise  # 重新抛出原始异常
   ```

---

#### 🔹 第六步：返回结果

**【必须】**：返回ORM对象、Dict或基本类型。

**【禁止】**：不要在服务层返回HTTP响应对象（如`JSONResponse`）。

**【返回类型】**：
- ORM对象：`DownloadTask`, `DownloadFailure`, `DownloadedVideo`
- 列表：`List[DownloadTask]`
- 字典：`Dict` (包含total和items)
- 基本类型：`int`, `bool`, `str`

```python

    """
    示例方法：展示标准的服务层方法实现流程
    """

    # ============ 第三步 & 第四步：try-except + 业务逻辑 ============
    try:
        # 4.1 查询任务
        task = self.db.query(DownloadTask).filter(DownloadTask.id == task_id).first()
        if not task:
            raise TaskNotFoundError(f"Task {task_id} not found")
        
        # 4.2 验证权限
        if str(task.user_id) != user_id_for_logging:
            raise TaskNotFoundError(f"Task {task_id} not found")
        
        # 4.3 执行业务逻辑
        task.status = TaskStatus.PROCESSING
        task.updated_at = datetime.utcnow()
        
        # 4.4 提交事务
        self.db.commit()
        
        # 4.5 刷新对象
        self.db.refresh(task)
        
        # 4.6 记录成功日志
        logger.info(f"Successfully updated task {task_id_for_logging}")
        
        # 第六步：返回结果
        return task
        
    # ============ 第五步：异常处理 ============

        # 5.1 记录错误日志（使用提取的变量）

        )

        self.db.rollback()
        # 5.4 抛出异常
        raise DatabaseError(f"Database error: {str(e)}")
    
    except Exception as e:
        # 5.1 记录错误日志（使用提取的变量）
        logger.error(
            f"Unexpected error - 用户ID: {user_id_for_logging}, "
            f"任务ID: {task_id_for_logging}, 错误: {str(e)}",
            exc_info=True
        )
        # 5.2 rollback
        self.db.rollback()

```

#### 🎯 特殊场景处理

##### 场景1：不涉及数据库的方法（如download_hls）
- ✅ **不需要**变量提取（无ORM对象）
- ✅ **不需要**rollback（无数据库操作）
- ✅ 仍需要日志记录和异常处理

##### 场景2：纯查询方法（如count_download_tasks）
- ✅ 需要变量提取
- ✅ 需要try-except
- ❌ **不需要**commit（只读操作）
- ❌ **不需要**rollback（查询失败不影响数据）

##### 场景3：嵌套方法调用（如start_download_task）
- ✅ 主方法管理事务
- ✅ 子方法不执行commit
- ✅ 主方法统一commit和rollback

##### 场景4：批量操作方法（如batch_import_tasks_from_csv）
- ✅ 使用批量commit提高性能
- ✅ 逐行错误处理，不中断整个流程
- ✅ 在最后统一commit

#### ⚠️ 常见错误和注意事项

##### ❌ 错误1：在except块中访问ORM对象属性
```python
# ❌ 错误示例
try:
    task = self.db.query(DownloadTask).filter(...).first()
    # ... 数据库操作 ...
except SQLAlchemyError as e:
    logger.error(f"Error for task {task.id}")  # ❌ task可能已失效
```

```python
# ✅ 正确示例
task_id_for_logging = str(task_id)  # 提前提取
try:
    task = self.db.query(DownloadTask).filter(...).first()
    # ... 数据库操作 ...
except SQLAlchemyError as e:
    logger.error(f"Error for task {task_id_for_logging}")  # ✅ 使用局部变量
```

##### ❌ 错误2：忘记rollback
```python
# ❌ 错误示例
try:
    self.db.add(task)
    self.db.commit()
except SQLAlchemyError as e:
    logger.error(f"Error: {str(e)}")
    raise  # ❌ 忘记rollback，session污染
```

```python
# ✅ 正确示例
try:
    self.db.add(task)
    self.db.commit()
except SQLAlchemyError as e:
    logger.error(f"Error: {str(e)}")
    self.db.rollback()  # ✅ 清理session
    raise
```

##### ❌ 错误3：在服务层返回HTTP响应
```python
# ❌ 错误示例
def create_task(self, ...):
    # ...
    return JSONResponse(status_code=201, content={...})  # ❌ 服务层不应返回HTTP响应
```

```python
# ✅ 正确示例
def create_task(self, ...):
    # ...
    return task  # ✅ 返回ORM对象，由API层构建HTTP响应
```

   - 记录错误日志: `logger.error(f"Database error creating task for user {user_id_for_logging}: {str(e)}")`  # 使用提取的变量

**实现流程**（完整异常处理）:
1. **【核心规范2.1.2】整个函数包裹在try-except块中**

     * 抛出`ValueError("重试次数已达上限")`

   - **智能重试策略**:
     * **检查是否存在m3u8/mp4/image级别的失败**:
       - `has_m3u8_failure = any(f.resource_type == 'm3u8' for f in failures_to_retry)`
       - `has_mp4_failure = any(f.resource_type == 'mp4' for f in failures_to_retry)`
       - `has_image_failure = any(f.resource_type == 'image' for f in failures_to_retry)`
     * **如果存在主资源失败**: 全量重新下载

### 6.2.4.1 start_download_task

**方法签名**:
```python
def start_download_task(
    self,
    task_id: uuid.UUID,
    user_id: uuid.UUID,
    retry_flag: bool = False
) -> DownloadTask:
```

**功能描述**: 启动指定的下载任务,包括视频去重检查、下载执行和结果处理

**参数说明**:
| 参数名 | 类型 | 必填 | 默认值 | 描述 |
|:---|:---|:---|:---|:---|
| `task_id` | `UUID` | 是 | - | 任务ID |
| `user_id` | `UUID` | 是 | - | 当前用户ID |

**返回值**:
| 类型 | 描述 |
|:---|:---|
| `DownloadTask` | 更新后的任务ORM对象(状态为PROCESSING或COMPLETED/PARTIAL_COMPLETED/FAILED) |

**抛出异常**:
| 异常类型 | 触发条件 |
|:---|:---|
| `TaskNotFoundError` | 任务不存在或不属于当前用户 |
| `InvalidTaskStatusError` | 任务当前状态不能启动(非PENDING状态) |
| `SQLAlchemyError` | 数据库操作失败 |
| `DatabaseError` | 数据库错误的包装异常 |

**实现流程**:
1. **提取变量**: 提取task_id_str用于日志记录
2. **记录日志**: `logger.info(f"Starting download task: {task_id}")`
3. **try块(主流程)**:
   - **获取并验证任务**: `task = self.get_download_task(task_id, user_id)`
   - **验证任务状态**: 如果`task.status != TaskStatus.PENDING`,抛出`InvalidTaskStatusError`
   - **更新任务状态**: `task.status = TaskStatus.PROCESSING`, `task.started_at = datetime.utcnow()`
   - **提交并刷新**: `self.db.commit()`, `self.db.refresh(task)`
   
   - **【视频去重检查】** (try-except块1):
     * 查询`downloaded_videos`表: `existing_video = self.db.query(DownloadedVideo).filter(DownloadedVideo.video_url == task.resource_url).filter(DownloadedVideo.status.in_(['completed', 'partial_completed'])).first()`
     * 如果找到现有视频:
       - 记录日志: `logger.info(f"Worker Deduplication Hit: video_url={task.resource_url}, existing_status={existing_video.status}")`
       - 将任务状态标记为与现有视频相同: `task.status = TaskStatus.COMPLETED或TaskStatus.PARTIAL_COMPLETED`
       - 设置`task.completed_at = datetime.utcnow()`
       - 创建新的`DownloadedVideo`记录(复用存储路径):
         + `task_id = task.id`
         + `video_id, liveroom_id, liveroom_title, liveroom_url, video_url, storage_path, file_size, duration, resolution, format`复用`existing_video`
         + `status`与`existing_video.status`相同
       - `self.db.add(new_video)`
       - `self.db.commit()`, `self.db.refresh(task)`
       - **返回task**(跳过下载逻辑)
     * **except SQLAlchemyError**: 记录日志并`rollback()`, `refresh(task)`,继续下载流程(降级处理)
     * **except Exception**: 记录日志并`rollback()`, `refresh(task)`,继续下载流程(降级处理)
   
   - **【执行下载】**:
     * 根据`task.resource_type`:
       - `"hls"`: 调用`download_hls()`
       - `"mp4"`: 调用`download_mp4_image()`
     * 保存结果到`result`变量
   
   - **【处理下载结果】**:
     * 根据`resource_type`调用对应的结果处理方法:
       - `"hls"`: `_process_download_m3u8_result(task, result)`
       - `"mp4"`: `_process_mp4_result(task, result)`
     * 提交事务: `self.db.commit()`
     * 刷新对象: `self.db.refresh(task)`
   
   - **返回task**

4. **except Exception块(主异常处理)**:
   - **执行rollback和refresh**: `self.db.rollback()`, `self.db.refresh(task)`
   - **提取错误信息**: `error_msg = str(e)`
   - **记录错误日志**: `logger.error(f"Error starting download task {task_id_str}: {error_msg}", exc_info=True)`
   - **更新任务状态**: `task.status = TaskStatus.FAILED`, `task.completed_at = datetime.utcnow()`, `task.error_message = error_msg[:500]`
   - **try-except嵌套块**(创建失败记录):
     * **try**: 调用`create_download_failure()`创建失败记录
     * **except**: 记录日志"Failed to create download failure record"
   - **提交事务**: `self.db.commit()`
   - **刷新对象**: `self.db.refresh(task)`
   - **返回task**

**数据库操作**:
- **涉及的表**: `download_tasks`, `downloaded_videos`, `download_failures`
- **操作类型**: UPDATE, SELECT, INSERT
- **是否需要commit**: 是(多次)
- **是否需要rollback**: 是(在多个异常处理点)

**日志记录**:
- **Info级别**: "Starting download task: {task_id}", "Worker Deduplication Hit: ..."
- **Error级别**: "Database error during deduplication check", "Error starting download task"

### 6.2.4.2 download_m3u8

**方法签名**:
```python
def download_m3u8(
    self,
    task: DownloadTask,

) -> Dict:
```

**功能描述**: 下载HLS(m3u8)视频流,包括master/variant playlist解析、TS分片下载、合并等

**参数说明**:
| 参数名 | 类型 | 必填 | 默认值 | 描述 |

**返回值**:
| 类型 | 描述 |
|:---|:---|
| `Dict[str, Any]` | 下载结果字典,包含:<br>- `status`: 'completed'/'partial_completed'/'failed'<br>- `output_path`: 合并后的视频文件路径<br>- `failed_segments`: 失败的分片列表<br>- `total_segments`: 总分片数<br>- `downloaded_segments`: 成功下载的分片数<br>- `file_size`: 文件大小(字节)<br>- `duration`: 视频时长(秒)<br>- `error_message`: 错误信息(如果有) |

| 异常类型 | 触发条件 |
|:---|:---|
| `DownloadError` | 下载过程中的各种错误 |
| `M3U8ParseError` | m3u8文件解析失败 |
| `Exception` | 其他未知错误 |

**实现流程**:
1. **记录日志**: `logger.info(f"Downloading HLS video: {task.resource_url}")`
2. **创建目录结构**:
   - 视频根目录: `{download_dir}/{task.video_id}/hls/`
   - TS分片目录: `{video_root}/ts/`
   - m3u8文件目录: `{video_root}/m3u8/`
3. **下载m3u8文件**:
   - 使用`requests.get()`下载主m3u8文件
   - 解析m3u8内容,判断是master还是variant playlist
   - 如果是master playlist,选择最高清晰度的variant
   - 下载variant m3u8文件
4. **解析TS分片列表**:
   - 从variant m3u8中提取所有`.ts`文件URL
   - 生成标准化的文件名(seg_001.ts, seg_002.ts...)
5. **多线程下载TS分片**:
   - 使用`ThreadPoolExecutor(max_workers=self.max_workers)`
   - 对每个TS分片执行下载,带重试机制
   - 记录失败的分片到`failed_segments`列表
6. **判断下载状态**:
   - 如果`len(failed_segments) == 0`: 状态为'completed'
   - 如果`len(failed_segments) / total_segments <= self.hls_failure_tolerance`: 状态为'partial_completed'
   - 否则: 状态为'failed'
7. **合并TS分片**(如果状态为completed或partial_completed):
   - 使用`ffmpeg`合并所有成功下载的TS文件
   - 生成最终的`.mp4`文件
   - 计算文件大小和视频时长
8. **清理临时文件**:
   - 删除所有TS分片文件
   - 保留m3u8文件(用于调试)
9. **返回结果字典**

**数据库操作**:
- **涉及的表**: 无(此方法不直接操作数据库)
- **操作类型**: 无
- **是否需要commit**: 否
- **是否需要rollback**: 否

**日志记录**:
- **Info级别**: "Downloading HLS video", "Downloaded {count}/{total} segments", "Merging TS segments"
- **Warning级别**: "Failed segment: {url} - {error}"
- **Error级别**: "Error downloading HLS video: {error}"
