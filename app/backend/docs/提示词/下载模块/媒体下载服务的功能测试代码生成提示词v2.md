
### **用于生成 FastAPI 应用全覆盖测试的终极提示词**

#### **1. 角色与目标**

你是一位资深的Python后端测试工程师，是为包含复杂业务流程的FastAPI应用编写高覆盖率集成测试的专家。

你的核心任务是为我提供的一个下载管理应用，编写**两份独立但完整的`pytest`测试文件**：
1.  `test_download_workflows.py`: 专门测试所有与**MP4和HLS核心下载及重试相关的业务流程**。
2.  `test_management_apis.py`: 专门测试所有**通用的任务管理API**（如创建、查询、删除、失败记录管理等）。

每个测试文件都必须严格验证API响应、状态码，以及操作后**数据库中所有相关表（`download_tasks`, `download_failures`, `downloaded_videos`）的数据状态变更**是否与业务逻辑完全一致。

#### **2. 项目上下文与关键文件摘要**

* **技术栈**: FastAPI, SQLAlchemy, Pydantic, Pytest。
* **API路由注册**: @live-streaming-saas/backend/media_download_service/app/api/v1/api.py
* **被测核心文件**: @live-streaming-saas/backend/media_download_service/app/api/v1/endpoints/download.py
* **业务逻辑核心**: @live-streaming-saas/backend/media_download_service/app/services/download_service.py
* **数据模型与Schema**: 定义在 @live-streaming-saas/backend/media_download_service/app/models/download.py 和 @live-streaming-saas/backend/media_download_service/app/schemas/download.py
* **测试数据源**: @live-streaming-saas/backend/media_download_service/tests/conftest.py 中已定义多种`fixture`，测试代码应充分利用它们来准备数据。

#### **3. 关键业务逻辑摘要 (用于指导测试断言)**

* **创建任务**: `POST /api/v1/download/tasks` -> 任务初始状态为 `pending`。
* **开始任务**: `POST /api/v1/download/tasks/{task_id}/start` -> 任务状态立即变为 `processing`，下载完成后根据结果更新为最终状态。
* **MP4下载逻辑**: 成功则`Task.status`变为`completed`；失败则变为`failed`；重试成功则删除`DownloadFailure`记录。
* **HLS下载逻辑**: 失败情况多样，`Task.status`可能变为`failed`或`partial_completed`，并可能产生多条`ts`类型的`DownloadFailure`记录。
* **删除/取消任务**: `DELETE /api/v1/download/tasks/{task_id}` 只能操作非`COMPLETED`状态的任务。

    * **断言**: 状态码`400 Bad Request`或`409 Conflict`。

#### **5. 断言模板与最佳实践**

##### **A. 标准断言结构**

每个测试函数都应该遵循 **AAA模式** (Arrange-Act-Assert):

```python
def test_example(client, db_session):
    # Arrange (准备)
    task = create_test_task(db_session)
    
    # Act (操作)
    response = client.post(f"/api/v1/download/tasks/{task.id}/start")
    
    # Assert (断言)
    # 1. API响应断言
    assert response.status_code == 200
    response_data = response.json()
    assert response_data["status"] == "completed"
    
    # 2. 数据库状态断言
    updated_task = db_session.query(DownloadTask).filter_by(id=task.id).first()
    assert updated_task.status == TaskStatus.COMPLETED
    
    # 3. 关联数据断言
    video_record = db_session.query(DownloadedVideo).filter_by(task_id=task.id).first()
    assert video_record is not None
```
