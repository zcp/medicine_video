## 三、核心功能实现

### 3.1. 下载功能概述
- **HLS视频流下载**
- **MP4视频文件下载**
- **图片资源下载**
- **并发下载控制**
- **断点续传**

### 3.2. HLS视频文件下载功能需求

#### 3.2.1. 下载功能
- 支持下载m3u8索引文件。
- 支持下载ts分片文件。
- 支持断点续传，记录已下载字节数。
- 支持下载失败重试（最多重试3次）。
- 支持下载进度实时更新（每下载1MB更新一次进度）。
- 支持并发下载控制（最大并发数可配置）。
- 支持分片并发下载（可配置并发数）。

#### 3.2.2. 存储路径与命名规范
- **基础路径**：`/media/video_{video_id}/`
- **HLS文件路径**：`/media/video_{video_id}/hls_{resolution}_{bitrate}/`
- **文件命名格式**：
  - **m3u8文件**：`index_{video_id}_{operation_type}_{timestamp}.m3u8`，存储在HLS文件路径下。
  - **ts目录**：在HLS文件路径下新建 `ts/` 目录。
  - **ts文件**：`segment_{index}_{video_id}_{operation_type}_{timestamp}.ts`，存储在 `ts/` 目录下。
- **时间戳格式**：`YYYYMMDDTHHMMSS`
- **操作类型**：`upload`, `download`, `transcode` 等。
- **清晰度**：`1080p`, `720p` 等。
- **路径处理**：如果存储路径不存在，自动创建；路径生成需跨平台兼容（Windows/Linux）。

#### 3.2.3. 视频分析与路径修正流程
1.  **视频分析**：如果整个HLS视频下载成功，使用 `ffmpeg` 分析第一个ts分片，获取：
    - 实际分辨率
    - 实际码率
    - 编码格式
    - 帧率
2.  **路径修正**：如果下载时使用了默认分辨率/码率，需在分析后进行路径修正：
    - 根据 `ffmpeg` 分析结果修正目录名。
    - 移动已下载文件到正确的路径。
    - 更新数据库中的存储路径。

#### 3.2.4. 数据记录
1.  **下载成功**：
    - 将视频信息写入 `downloaded_videos` 表。
    - 使用 `schemas/download.py` 中定义的 **`DownloadedVideoBase`** 模型。
    - 包含字段: `video_id`, `liveroom_id`, `video_type`, `video_url`, `storage_path` (修正后的路径), `file_size` (所有ts文件总和), `resolution`, `bitrate`, `format` (HLS), `status`, `download_start_time`, `download_end_time`, `download_task_id`。
2.  **下载失败**：
    - 将失败信息写入 `download_failures` 表。
    - 使用 `schemas/download.py` 中定义的 **`DownloadFailureBase`** 模型。
    - 包含字段: `task_id`, `resource_url`, `expected_path`, `resource_type` (如 'ts', 'm3u8'), `failure_type`, `error_message`, `retry_count`。

### 3.3. MP4视频文件下载功能需求

#### 3.3.1. 下载功能
- 支持直接下载MP4文件。
- 支持断点续传，记录已下载字节数。
- 支持下载失败重试（最多重试3次）。
- 支持下载进度实时更新（每下载1MB更新一次进度）。
- 支持并发下载控制（最大并发数可配置）。

#### 3.3.2. 存储路径与命名规范
- **基础路径**：`/media/video_{video_id}/`
- **MP4文件路径**：`/media/video_{video_id}/mp4/`
- **文件命名格式**：`video_{video_id}_{operation_type}_{resolution}_{timestamp}.mp4`
- **时间戳格式**：`YYYYMMDDTHHMMSS`
- **操作类型**：`upload`, `download`, `transcode` 等。
- **清晰度**：`1080p`, `720p` 等。
- **路径处理**：如果存储路径不存在，自动创建；路径生成需跨平台兼容（Windows/Linux）。

#### 3.3.3. 视频分析与路径修正流程
1.  **视频分析**：如果下载成功，使用 `ffmpeg` 分析视频信息，获取：
    - 实际分辨率
    - 实际码率
    - 视频时长
    - 编码格式
    - 帧率
2.  **路径修正**：如果下载时使用了默认分辨率/码率，需在分析后进行路径修正：
    - 根据 `ffmpeg` 分析结果修正文件名。
    - 移动文件到正确的路径。
    - 更新数据库中的存储路径。

#### 3.3.4. 数据记录
1.  **下载成功**：
    - 将视频信息写入 `downloaded_videos` 表。
    - 使用 `schemas/download.py` 中定义的 **`DownloadedVideoBase`** 模型。
    - 包含字段: `video_id`, `liveroom_id`, `video_type`, `video_url`, `storage_path` (修正后的路径), `file_size`, `resolution`, `bitrate`, `format`, `duration`, `fps`, `status`, `download_start_time`, `download_end_time`, `download_task_id`。
2.  **下载失败**：
    - 将失败信息写入 `download_failures` 表。
    - 使用 `schemas/download.py` 中定义的 **`DownloadFailureBase`** 模型。
    - 包含字段: `task_id`, `resource_url`, `expected_path`, `resource_type` ('mp4'), `failure_type`, `error_message`, `retry_count`。

### 3.4. 图片资源下载功能需求
- **功能**：支持下载封面图和缩略图，支持格式转换、压缩和失败重试。
- **存储目录**：`/media/video_{video_id}/images/`
- **命名格式**：
  - **封面图**: `cover_{video_id}_{操作类型}_{时间戳}.jpg`
  - **缩略图**: `thumbnail_{video_id}_{操作类型}_{时间戳}.webp`
- **路径处理**：路径不存在则自动创建，且需跨平台兼容。

### 3.5. 统一存储目录结构规范
- **Video ID 命名规范**：
  - **格式**：`{liveroom_id}_{4位_uuid_后缀}` (liveroom_id为10或16位随机数)
  - **示例**：`8723901837_f22d`
- **目录结构示例**：
  ```bash
  /media/video_8723901837_f22d4c/
  ├── images/
  │   ├── cover_8723901837_f22d4c_upload_20250528T153200.jpg
  │   └── thumbnail_8723901837_f22d4c_upload_20250528T153210.webp
  ├── raw/
  │   └── video_8723901837_f22d4c_upload_20250528T153000.mp4
  ├── hls_1080p_4Mbps/
  │   ├── index_8723901837_f22d4c_transcoded_20250528T154500.m3u8
  │   └── ts/
  │       └── segment_000_8723901837_f22d4c_transcoded_20250528T154501.ts
  ├── mp4/
  │   └── video_8723901837_f22d4c_transcoded_1080p_20250528T155000.mp4
  └── metadata.json
  ```

### 3.6. 任务与状态管理

#### 3.6.1. 任务管理
- 下载任务管理
- 资源存储管理
- 失败任务重试
- 下载状态检查
- 失败记录管理

#### 3.6.2. 状态管理
- `pending`：等待下载
- `processing`：下载中
- `completed`：完全成功
- `partial_completed`：部分成功
- `failed`：失败
- `cancelled`：已取消

### 3.7. 失败处理与并发控制

#### 3.7.1. 失败处理
- **失败类型**：
  - `network_error`：网络错误
  - `timeout`：超时错误
  - `invalid_content`：内容无效
  - `storage_error`：存储错误
  - `permission_error`：权限错误
- **重试策略**：
  - **最大重试次数**：3次
  - **重试间隔**：指数退避（1分钟、2分钟、4分钟）
  - **HLS分片失败容忍度**：5%
  - **失败记录保留时间**：7天

#### 3.7.2. 并发控制
- **全局限制**：
  - **最大并发下载任务**：100
  - **任务队列容量**：1000
- **单任务限制**：
  - **最大并发下载数**：10
- **资源限制**：
  - **内存使用限制**：2GB/任务
  - **CPU使用限制**：50%/任务
  - **磁盘IO限制**：100MB/s
  - **网络带宽限制**：10MB/s

from datetime import datetime

from sqlalchemy.dialects.postgresql import UUID

from app.database import Base

class DownloadTask(Base):
    """下载任务表"""
    __tablename__ = "download_tasks"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid4)
    video_id = Column(UUID(as_uuid=True), nullable=False, comment="视频ID，格式：{liveroom_id}_{uuid4后缀}")
    liveroom_id = Column(String(20), nullable=False, comment="直播间ID")
    liveroom_title = Column(String(255), nullable=True, comment="直播间标题")
    liveroom_url = Column(String(255), nullable=True, comment="直播间URL")
    video_url = Column(String(255), nullable=False, comment="视频播放URL")
    video_type = Column(String(20), nullable=False, comment="hls, mp4")
    status = Column(
        String(20),
        nullable=False,
        default='pending',
        comment="pending, processing, completed, partial_completed,failed, cancelled"
    )
    progress = Column(Float, nullable=False, default=0, comment="下载进度（0-1）")
    retry_count = Column(Integer, nullable=False, default=0, comment="重试次数")
    last_error = Column(Text, nullable=True, comment="最后错误信息")
    created_at = Column(DateTime, nullable=False, default=datetime.utcnow, comment="创建时间")
    updated_at = Column(DateTime, nullable=False, default=datetime.utcnow, onupdate=datetime.utcnow, comment="更新时间")
    completed_at = Column(DateTime, nullable=True, comment="完成下载时间")

    # 关系
    failures = relationship("DownloadFailure", back_populates="task", cascade="all, delete-orphan")
    video = relationship("DownloadedVideo", back_populates="task", uselist=False, cascade="all, delete-orphan")

    __table_args__ = (
        # 约束
        CheckConstraint(
            "status IN ('pending', 'processing', 'completed', 'partial_completed', 'failed', 'cancelled')",
            name="check_status"
        ),
        CheckConstraint(
            "progress >= 0 AND progress <= 1",
            name="check_progress_range"
        ),
        # 索引
        Index("idx_download_tasks_video_id", "video_id"),
        Index("idx_download_tasks_liveroom_id", "liveroom_id"),
        Index("idx_download_tasks_status", "status"),
        Index("idx_download_tasks_created_at", "created_at")
    )

    def __repr__(self):
        return f"<DownloadTask(id={self.id}, status={self.status})>"

class DownloadFailure(Base):
    """下载失败记录表"""
    __tablename__ = "download_failures"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid4)
    task_id = Column(UUID(as_uuid=True), ForeignKey("download_tasks.id", ondelete="CASCADE"), nullable=False)
    resource_url = Column(Text, nullable=False, comment="原始资源地址（URL）")
    expected_path = Column(Text, nullable=False, comment="希望保存的路径（用于重试时定位）")
    resource_type = Column(
        String(20),
        nullable=False,
        default='ts',
        comment="枚举值: 'ts', 'mp4', 'image'"
    )
    failure_type = Column(
        String(50),
        nullable=False,
        comment="network_error, timeout, invalid_content, storage_error, permission_error"
    )
    error_message = Column(Text, nullable=False, comment="错误信息")
    retry_count = Column(Integer, nullable=False, default=0, comment="重试次数")
    next_retry_time = Column(DateTime, nullable=True, comment="下次重试时间")
    status = Column(
        String(20),
        nullable=False,
        default='pending',
        comment="pending, retrying, abandoned"
    )
    created_at = Column(DateTime, nullable=False, default=datetime.utcnow, comment="创建时间")
    updated_at = Column(DateTime, nullable=False, default=datetime.utcnow, onupdate=datetime.utcnow, comment="更新时间")

    # 关系
    task = relationship("DownloadTask", back_populates="failures")

    __table_args__ = (
        # 约束
        CheckConstraint(
            "retry_count >= 0 AND retry_count <= 3",
            name="check_retry_count_range"
        ),
        CheckConstraint(
            "resource_type IN ('ts', 'mp4', 'image')",
            name="check_resource_type"
        ),
        CheckConstraint(
            "failure_type IN ('network_error', 'timeout', 'invalid_content', 'storage_error', 'permission_error')",
            name="check_failure_type"
        ),
        CheckConstraint(
            "status IN ('pending', 'retrying', 'abandoned')",
            name="check_failure_status"
        ),
        # 索引
        Index("idx_download_failures_task_id", "task_id"),
        Index("idx_download_failures_status", "status"),
        Index("idx_download_failures_next_retry_time", "next_retry_time")
    )

    def __repr__(self):
        return f"<DownloadFailure(id={self.id}, failure_type={self.failure_type})>"
