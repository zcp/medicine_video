三、核心功能实现
1. 下载功能
- 实现以下功能：

* HLS视频文件下载功能需求：

1. 下载功能：
   - 支持下载m3u8索引文件
   - 支持下载ts分片文件
   - 支持断点续传，记录已下载字节数
   - 支持下载失败重试（最多重试3次）
   - 支持下载进度实时更新（每下载1MB更新一次进度）
   - 支持并发下载控制（最大并发数可配置）
   - 支持分片并发下载（可配置并发数）

2. 存储路径规范：
   - 基础路径：`/media/video_{video_id}/`
   - HLS文件路径：`/media/video_{video_id}/hls_{resolution}_{bitrate}/`
   - 文件命名格式：
     * m3u8文件：`index_{video_id}_{operation_type}_{timestamp}.m3u8`
     * m3u8文件存储在HLS文件路径下
     * 在HLS文件路径下新建一个名为ts文件夹，所以下载的ts文件存储到该文件夹中
     * ts文件：`segment_{index}_{video_id}_{operation_type}_{timestamp}.ts`
   - 时间戳格式：`YYYYMMDDTHHMMSS`
   - 操作类型：upload, download, transcode等
   - 清晰度：1080p, 720p等
   - 如果存储路径不存在，自动创建
   - 路径生成需要跨平台兼容（Windows/Linux）

3. 视频分析流程：
   - 如果整个hls视频下载成功，请使用ffmpeg分析第一个ts分片：
     * 获取实际分辨率
     * 获取实际码率
     * 获取编码格式
     * 获取帧率
   
   - 路径修正：
     * 在整个hls视频下载成功之后，如果下载时使用了默认分辨率/码率
     * 根据ffmpeg分析结果修正目录名
     * 移动已下载文件到正确的路径
     * 更新数据库中的存储路径
     * 继续下载剩余分片到新路径

4. 数据记录：
   - 如果整个hls视频下载成功：
     * 将视频信息写入 downloaded_videos 表
     * 使用 schemas/download.py 中定义的 DownloadedVideoBase 模型
     * 包含字段：
       - video_id: 视频ID
       - liveroom_id: 直播间ID
       - video_type: 视频类型
       - video_url: 视频URL
       - storage_path: 存储路径（修正后的路径）
       - file_size: 文件大小（所有ts文件总和）
       - resolution: 实际分辨率（ffmpeg分析结果）
       - bitrate: 实际码率（ffmpeg分析结果）
       - format: 格式（HLS）
       - status: 状态
       - download_start_time: 下载开始时间
       - download_end_time: 下载结束时间
       - download_task_id: 下载任务ID
   
   - 下载失败：
     * 如果由部分ts片段下载视频，将失败信息写入 download_failures 表
     * 使用 schemas/download.py 中定义的 DownloadFailureBase 模型
       * 包含字段：
        - task_id: 关联的任务ID
        - resource_url: 失败资源的原始URL (例如 https://.../seg_001.ts)
        - expected_path: 资源本应保存的本地路径
        - resource_type: 资源类型 (例如 'ts', 'm3u8')
        - failure_type: 失败类型 (例如 'network_error', 'timeout')
        - error_message: 详细的错误信息
        - retry_count: 已重试次数
