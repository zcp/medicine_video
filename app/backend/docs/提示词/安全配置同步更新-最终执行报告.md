## 安全配置更新详细内容

每个提示词文档都添加了以下 5 个核心子节：

### 1. 环境变量配置安全规范（适用于所有模块）

#### 1.1. CORS 配置规范
- 禁止硬编码 CORS 配置
- 必须从环境变量读取 CORS 配置
- 配置格式：支持逗号分隔的多个域名
- 生产环境要求：必须为具体域名，严禁使用 `["*"]`
- 包含完整的代码示例

#### 1.2. 敏感信息配置规范
- 禁止硬编码数据库密码、用户名、JWT 密钥、第三方服务密钥
- 必须通过环境变量读取所有敏感配置
- 禁止为敏感信息设置不安全的默认值
- 包含正确和错误的示例对比

#### 1.3. 配置验证规范
- 必须在应用启动时验证必需的敏感配置
- 缺失配置必须抛出明确的异常
- 数据库密码验证：检查密码是否为空
- JWT 密钥验证：检查密钥长度（≥32字符）
- 包含完整的 Settings 类实现示例

---

### 2. 日志安全规范（适用于所有模块）

#### 2.1. 禁止在日志中打印敏感信息
- 禁止：打印完整的数据库连接 URL（包含密码）
- 必须：只打印非敏感的连接信息
- 包含正确和错误的示例对比

#### 2.2. 日志脱敏规范（推荐实现）
- 创建日志脱敏工具函数 `app/core/logging_utils.py`
- 实现脱敏日志格式化器 `SanitizedFormatter`
- 自动脱敏数据库连接 URL 和 JWT 密钥
- 包含完整的代码示例

#### 2.3. 错误消息脱敏
- 禁止在异常处理中暴露敏感信息
- 必须：只返回通用的错误消息给客户端
- 包含完整的代码示例

---

### 3. 环境变量文件管理规范（适用于所有模块）

#### 3.1. `.env.example` 模板文件
- 必须提供 `.env.example` 模板文件
- 必须包含所有必需的环境变量（包括说明和示例）
- 包含完整的模板文件结构示例

#### 3.2. `.gitignore` 规范
- 必须在 `.gitignore` 中忽略所有环境变量文件
- 必须保留 `.env.example` 模板文件
- 包含完整的配置示例

---

### 4. 生产环境安全规范（适用于所有模块）

#### 4.1. 密钥管理服务（推荐）
- 生产环境强烈建议使用密钥管理服务，而非环境变量
- 支持的密钥管理服务：AWS、Azure、GCP、HashiCorp
- 包含 AWS Secrets Manager 集成示例

#### 4.2. 环境变量注入（Docker/K8s）
- 使用环境变量注入或密钥管理服务，而非在镜像中包含 `.env` 文件
- 包含 Docker Compose 示例

#### 4.3. 文件权限控制（Linux/Unix）
- 必须设置环境变量文件的权限，防止未授权访问
- 包含命令示例

---

### 5. 密钥生成最佳实践（适用于所有模块）

#### 5.1. JWT 密钥生成
- 推荐长度：64 字符（128位加密强度）
- 生成方式：`openssl rand -hex 32` 或 `python -c "import secrets; print(secrets.token_hex(32))"`

#### 5.2. 数据库密码生成
- 推荐长度：16-32 字符
- 生成方式：`openssl rand -base64 16` 或 `pwgen -s 16 1`

#### 5.3. 密钥命名规范
- 使用大写字母和下划线：`POSTGRES_PASSWORD`, `JWT_SECRET_KEY`
- 使用有意义的名称：`CORS_ORIGINS` 而非 `CORS`
- 分组前缀：`POSTGRES_*`, `JWT_*`, `CELERY_*`
