# Docker Compose 部署重建指南

## 重要说明：PostgreSQL 镜像和 Volume

# 使用默认 superuser 连接默认库 postgres
 docker exec -it live-streaming-saas-v2-postgres-1 /bin/bash
psql -U postgres

# 指定数据库名（按你项目配置改）
psql -U postgres -d your_database_name

# 需要密码时（一次性环境变量）
PGPASSWORD=你的密码 psql -U postgres -d your_database_name

### PostgreSQL 镜像
- ✅ **不需要重新 build**
- 使用的是官方镜像 `postgres:15-alpine`，只提供数据库服务，不包含应用代码
- 数据库结构变更是在应用层面，不是镜像层面

### PostgreSQL Volume
- 一个 `pgdata` volume 包含**多个数据库**：
  - `live_core_test` - live_core_service 使用
  - `media_download_test` - media_download_service 使用  
  - `users_service_test` - user_service 使用
- **如果只修改了某个服务的数据库**，可以选择：
  - **开发/测试环境**：删除整个 volume 重建（简单但会丢失所有数据库数据）
  - **生产环境**：只针对特定数据库进行迁移（保留其他数据库数据）

## 场景分类

### 场景 1：仅修改代码逻辑（不涉及数据库结构）

**操作步骤：**

```bash
# 1. 停止并删除 live_core_service 容器
docker-compose -f compose-app.yml stop live_core_service
docker-compose -f compose-app.yml rm -f live_core_service

# 2. 重新构建镜像（不使用缓存，确保获取最新代码

# 3. 启动服务
docker-compose -f compose-app.yml up -d live_core_service
```

**或者使用一条命令：**

```bash
docker-compose -f compose-app.yml up -d --build --force-recreate live_core_service
```

**说明：**
- ✅ **不需要**删除 PostgreSQL volume
- ✅ **不需要**重新构建 PostgreSQL 镜像
- ✅ 数据库数据会保留

---

### 场景 2：修改了 live_core_service 的数据库结构（开发/测试环境）

一般使用方案A， 但是不需要删除卷操作
**方案 A：删除整个 volume 重建（简单，但会丢失所有数据库数据）**

```bash
# 1. 停止所有服务
docker-compose -f compose-app.yml down

# 2. 删除 PostgreSQL volume（⚠️ 会丢失所有数据库数据：live_core_test, media_download_test, users_service_test）
docker volume rm live-streaming-saas_pgdata

# 3. 重新构建 live_core_service 镜像
docker-compose -f compose-app.yml build --no-cache live_core_service

# 4. 启动所有服务（会自动运行 init-db.sh 和 init_db.py）
docker-compose -f compose-app.yml up -d

# 5. 等待数据库初始化完成（查看日志）
docker-compose -f compose-app.yml logs -f postgres
docker-compose -f compose-app.yml logs -f live_core_service
```

**方案 B：只删除 live_core_test 数据库（保留其他数据库数据）**

```bash
# 1. 停止 live_core_service（保持数据库运行）
docker-compose -f compose-app.yml stop live_core_service

# 2. 删除 live_core_test 数据库
docker-compose -f compose-app.yml exec postgres psql -U postgres -c "DROP DATABASE IF EXISTS live_core_test;"

# 3. 重新创建 live_core_test 数据库
docker-compose -f compose-app.yml exec postgres psql -U postgres -c "CREATE DATABASE live_core_test;"

# 4. 重新构建 live_core_service 镜像
docker-compose -f compose-app.yml build --no-cache live_core_service

# 5. 启动 live_core_service（会自动运行 init_db.py 创建表结构）
docker-compose -f compose-app.yml up -d live_core_service

# 6. 等待初始化完成
docker-compose -f compose-app.yml logs -f live_core_service
```

**说明：**
- ✅ **不需要**重新构建 PostgreSQL 镜像（使用的是官方镜像）
- 方案 A：会丢失所有数据库数据（仅适用于开发/测试环境）
- 方案 B：只删除 `live_core_test`，保留 `media_download_test` 和 `users_service_test` 的数据

---

### 场景 3：修改了 live_core_service 的数据库结构（生产环境 - 保留数据）

**操作步骤：**

```bash
# 1. 备份数据库（重要！）
docker-compose -f compose-app.yml exec postgres pg_dump -U postgres live_core_test > backup_$(date +%Y%m%d_%H%M%S).sql

# 2. 停止 live_core_service（保持数据库运行）
docker-compose -f compose-app.yml stop live_core_service

# 3. 重新构建 live_core_service 镜像
docker-compose -f compose-app.yml build --no-cache live_core_service

# 4. 启动 live_core_service
docker-compose -f compose-app.yml up -d live_core_service

# 5. 进入容器执行数据库迁移
docker-compose -f compose-app.yml exec live_core_service python app/init_db.py

# 或者手动执行 SQL 迁移脚本（如果有的话）
docker-compose -f compose-app.yml exec postgres psql -U postgres -d live_core_test -f /path/to/migration.sql
```

**说明：**
- ❌ **不要**删除 PostgreSQL volume
- ✅ **不需要**重新构建 PostgreSQL 镜像
- ✅ **保留所有数据**
- ⚠️ 需要手动处理数据库结构变更（添加列、修改列类型等）

## 常用命令速查

```bash

```

### 查看日志
```bash
# 查看所有服务日志
docker-compose -f compose-app.yml logs -f

# 查看特定服务日志
docker-compose -f compose-app.yml logs -f live_core_service
```

### 进入容器
```bash
# 进入 live_core_service 容器
docker-compose -f compose-app.yml exec live_core_service bash

# 进入 postgres 容器
docker-compose -f compose-app.yml exec postgres psql -U postgres -d live_core_test
```

### 清理所有（⚠️ 危险操作）
```bash
# 停止并删除所有容器、网络、volume
docker-compose -f compose-app.yml down -v
```

## 数据库结构变更处理

### 当前机制

项目使用 SQLAlchemy 的 `Base.metadata.create_all()` 方法：
- ✅ 会创建**不存在的表**
- ❌ **不会修改已存在的表结构**
- ❌ **不会删除表**

### 如果修改了表结构（添加列、修改列类型等）

#### 方法 1：手动 SQL 迁移（推荐用于生产环境）

```sql
-- 示例：添加新列
ALTER TABLE live_rooms ADD COLUMN external_room_id VARCHAR(64);

-- 示例：添加索引
CREATE UNIQUE INDEX uq_live_rooms_user_external_room 
ON live_rooms(user_id, external_room_id) 
WHERE external_room_id IS NOT NULL;
```

执行方式：
```bash
docker-compose -f compose-app.yml exec postgres psql -U postgres -d live_core_test -c "ALTER TABLE live_rooms ADD COLUMN external_room_id VARCHAR(64);"
```

#### 方法 2：删除表重建（仅用于开发/测试）

修改 `app/init_db.py`，在创建表之前先删除表：

```python
def init_db():
    """初始化数据库，创建所有表"""
    try:
        # 删除所有表（仅用于开发/测试）
        Base.metadata.drop_all(bind=engine)
        # 创建所有表
        Base.metadata.create_all(bind=engine)
        logger.info("数据库表创建成功")
    except Exception as e:
        logger.error(f"数据库表创建失败: {str(e)}")
        raise
```

然后执行：
```bash
docker-compose -f compose-app.yml exec live_core_service python app/init_db.py
```

## 快速重建脚本

已创建重建脚本，提供两种重建模式：

### Linux/Mac 用户
```bash
./rebuild.sh --code-only  # 或 -c：仅重建代码（保留数据库）
./rebuild.sh --full      # 或 -f：完整重建（删除数据库 volume）
```

### Windows 用户
```cmd
rebuild.bat --code-only  # 或 -c：仅重建代码（保留数据库）
rebuild.bat --full       # 或 -f：完整重建（删除数据库 volume）
```

**说明：**
- `--code-only` / `-c`：仅重建 `live_core_service` 和 `celery_worker`，保留数据库数据
- `--full` / `-f`：完整重建，删除数据库 volume，适用于开发/测试环境

**注意：** 脚本会自动处理 `live_core_service` 和 `celery_worker` 两个服务（它们使用相同的代码库）

## 注意事项

1. **Volume 名称**：根据项目目录名，volume 名称可能是 `live-streaming-saas_pgdata` 或 `compose-app_pgdata`
   - 查看所有 volumes：`docker volume ls`
   - 查看 compose 使用的 volumes：`docker-compose -f compose-app.yml config --volumes`

2. **数据备份**：生产环境修改数据库前，务必先备份
   ```bash
   docker-compose -f compose-app.yml exec postgres pg_dump -U postgres live_core_test > backup.sql
   ```

3. **Celery Worker**：如果修改了代码，也需要重建 celery_worker
   ```bash
   docker-compose -f compose-app.yml up -d --build --force-recreate celery_worker
   ```

4. **网络问题**：如果遇到网络问题，确保 `depends_on` 配置正确，或使用 `wait-for-it.sh` 脚本等待数据库就绪
