# 远程部署媒体文件路径问题解决方案

## 问题分析

### 当前实现架构

1. **代码层面**：
   - `app/core/config.py`: 定义了 `ROOM_MEDIA_ROOT_PATH`，默认值为 `"./media"`
   - `app/core/file_handler.py`: 文件保存到 `{ROOM_MEDIA_ROOT_PATH}/rooms/{room_id}/cover_{timestamp}.{ext}`
   - `app/main.py`: 通过 FastAPI 的 `StaticFiles` 挂载 `/media` 路径到 `ROOM_MEDIA_ROOT_PATH` 目录
   - 返回的 URL 格式：`/media/rooms/{room_id}/cover_{timestamp}.{ext}`

2. **部署架构**：
   - `live_core_service` 容器运行 FastAPI 应用
   - Nginx 容器作为反向代理，处理所有外部请求
   - 当前 Nginx 配置中**缺少 `/media/` 路径的映射**

### 问题根源

1. **路径问题**：
   - 容器内使用相对路径 `./media`，路径是相对于容器工作目录 `/app`
   - 容器重启后，如果没有 volume 持久化，文件会丢失
   - 远程服务器上可能缺少 `media/rooms` 目录结构

2. **Nginx 配置缺失**：
   - 当前 `nginx.conf` 中没有配置 `/media/` location
   - 访问 `/media/rooms/...` 时，Nginx 无法找到对应的静态文件
   - FastAPI 的静态文件服务在生产环境中效率较低

3. **容器隔离**：
   - `live_core_service` 容器内的文件系统与 Nginx 容器隔离
   - Nginx 无法直接访问 `live_core_service` 容器内的文件

## 解决方案（不修改代码）

### 方案一：Nginx 直接提供静态文件服务（推荐）

**优点**：
- 性能最佳，Nginx 专门优化了静态文件服务
- 减少 FastAPI 应用负载
- 支持缓存和压缩等高级特性

**实施步骤**：

#### 1. 修改 `compose-app.yml`

在 `live_core_service` 服务中添加 volume 挂载和环境变量：

**当前配置**（第 2-11 行）：
```yaml
live_core_service:
  build: ./backend/live_core_service
  restart: unless-stopped
  ports: ["8000:8000"]
  environment:
    POSTGRES_DB: "live_core_test"
  env_file: .env.docker
  depends_on: []
  networks:
    - live-network
```

**修改后**：
```yaml
live_core_service:
  build: ./backend/live_core_service
  restart: unless-stopped
  ports: ["8000:8000"]
  environment:
    POSTGRES_DB: "live_core_test"
    ROOM_MEDIA_ROOT_PATH: "/app/media"  # 新增：使用绝对路径（覆盖 .env.docker 中的配置）
  env_file: .env.docker
  volumes:
    - /var/www/html/live-core-media:/app/media  # 新增：挂载到宿主机，实现持久化
  depends_on: []
  networks:
    - live-network
```

**说明**：
- `ROOM_MEDIA_ROOT_PATH: "/app/media"` 使用容器内的绝对路径，确保路径一致性
- 这个环境变量会覆盖 `.env.docker` 中的 `ROOM_MEDIA_ROOT_PATH=./media` 配置
- `/var/www/html/live-core-media:/app/media` 将宿主机目录挂载到容器内，实现文件持久化
- 使用绝对路径 `/var/www/html/live-core-media` 与你的 nginx volumes 配置保持一致
- 容器内创建的文件会同步到宿主机的 `/var/www/html/live-core-media` 目录

#### 2. 修改 `nginx/nginx.conf`

在 HTTPS 服务器配置（443 端口）中添加 `/media/` location。

**重要**：根据你当前的 `nginx.conf`，`/media/` location 应该插入在 **第 183 行（`@live_center_fallback` 结束）之后，第 185 行（`# ========================================================================`）之前**，或者至少要在 `/api/core/`（第 203 行）之前。

**推荐插入位置**：在第 183 行 `@live_center_fallback` 部分之后，第 185 行 `# API 代理服务` 部分之前添加：

```nginx
        # ========================================================================
        # 直播核心服务媒体文件（必须放在所有 /api/ 路径之前）
        # ========================================================================
        location /media/ {
            alias /var/www/html/live-core-media/;
            expires 7d;  # 缓存7天
            add_header Cache-Control "public";
            access_log off;  # 静态文件不记录访问日志，提升性能
            
            # 支持图片格式
            types {
                image/jpeg jpg jpeg;
                image/png png;
                image/gif gif;
            }
            
            # 如果文件不存在，返回 404（不转发给后端）
            try_files $uri =404;
        }

        # ========================================================================
        # API 代理服务
        # ========================================================================
        # 图片代理（必须放在 /api/core/ 之前，避免被其他 location 匹配）
        location /api/image {
            # ... 原有配置保持不变 ...
        }

        # 直播核心服务 API
        location /api/core/ {
            # ... 原有配置保持不变 ...
        }
```

**完整修改示例**（基于你的实际配置文件）：

在你的 `nginx.conf` 第 183-185 行之间（`@live_center_fallback` 之后，`# API 代理服务` 之前），插入以下配置：

```nginx
        # ========================================================================
        # 直播核心服务媒体文件
        # ========================================================================
        location /media/ {
            alias /var/www/html/live-core-media/;
            expires 7d;
            add_header Cache-Control "public";
            access_log off;
            
            types {
                image/jpeg jpg jpeg;
                image/png png;
                image/gif gif;
            }
            
            try_files $uri =404;
        }

        # ========================================================================
        # API 代理服务
        # ========================================================================
        # 图片代理（必须放在 /api/core/ 之前，避免被其他 location 匹配）
        location /api/image {
            proxy_pass https://a2.vzan.com;
            # ... 原有配置保持不变 ...
        }
```

**注意**：
- `/media/` 是普通前缀匹配，必须放在所有可能冲突的 location 之前
- 由于 `/media/` 和 `/api/` 是不同的前缀，理论上放在 `/api/core/` 之前即可
- 但为了清晰和避免未来冲突，建议放在所有 API 代理之前

#### 3. 修改 Nginx 容器的 volume 挂载

在 `compose-app.yml` 的 `nginx` 服务中添加 media 目录挂载：

**当前配置**（第 86-106 行）：
```yaml
nginx:
  image: nginx:alpine
  restart: unless-stopped
  ports: ["80:80","443:443"]
  volumes:
    # 挂载远程前端文件到容器
    - /var/www/html/user-service:/var/www/html/user-service:ro
    - /var/www/html/media-download:/var/www/html/media-download:ro
    - /var/www/html/live-center:/var/www/html/live-center:ro
    - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
    - ./nginx/ssl:/etc/nginx/ssl:ro
    - ./data/srs:/var/www/srs:ro
    # SSL 证书目录（自定义位置）
    - /var/www/mp.dayilive.com:/var/www/mp.dayilive.com:ro
    # Certbot webroot 验证目录（用于 Let's Encrypt 续期）
    - /var/www/certbot:/var/www/certbot:ro
  depends_on: [srs]
  networks:
    - live-network
```

**修改后**：
```yaml
nginx:
  image: nginx:alpine
  restart: unless-stopped
  ports: ["80:80","443:443"]
  volumes:
    # 挂载远程前端文件到容器
    - /var/www/html/user-service:/var/www/html/user-service:ro
    - /var/www/html/media-download:/var/www/html/media-download:ro
    - /var/www/html/live-center:/var/www/html/live-center:ro
    - /var/www/html/live-core-media:/var/www/html/live-core-media:ro  # 新增：挂载媒体文件目录
    - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
    - ./nginx/ssl:/etc/nginx/ssl:ro
    - ./data/srs:/var/www/srs:ro
    # SSL 证书目录（自定义位置）
    - /var/www/mp.dayilive.com:/var/www/mp.dayilive.com:ro
    # Certbot webroot 验证目录（用于 Let's Encrypt 续期）
    - /var/www/certbot:/var/www/certbot:ro
  depends_on: [srs]
  networks:
    - live-network
```

**说明**：
- 使用绝对路径 `/var/www/html/live-core-media` 与你的其他前端文件挂载方式保持一致
- 该路径与 `live_core_service` 的 volume 挂载路径必须一致
- 只读挂载（`:ro`）确保 Nginx 只能读取文件，不能修改

#### 4. 创建目录并设置权限

在部署服务器上执行：

```bash
# 创建媒体文件目录（使用绝对路径，与 compose-app.yml 中的配置一致）
sudo mkdir -p /var/www/html/live-core-media/rooms
sudo mkdir -p /var/www/html/live-core-media/topics

# 设置权限（确保容器可以读写）
# 注意：根据你的容器用户，可能需要调整用户和组
sudo chmod -R 755 /var/www/html/live-core-media
sudo chown -R www-data:www-data /var/www/html/live-core-media  # 或者根据实际情况调整用户组
```

**说明**：
- 使用绝对路径 `/var/www/html/live-core-media` 与 `compose-app.yml` 中的配置一致
- 权限设置需要根据实际的容器用户调整（nginx 容器通常是 `www-data` 或 `nginx` 用户）
- 如果使用 Docker，可能需要根据容器内的用户 ID 设置权限

#### 5. 设置环境变量（可选）

**方式一**：在 `compose-app.yml` 中直接设置（推荐，已在上面的步骤1中完成）
```yaml
environment:
  ROOM_MEDIA_ROOT_PATH: "/app/media"
```

**方式二**：在 `.env.docker` 文件中设置（如果需要在多个地方使用）
```bash
# 直播核心服务媒体文件路径（容器内绝对路径）
# 注意：如果 compose-app.yml 中也设置了，会覆盖此配置
ROOM_MEDIA_ROOT_PATH=/app/media
```

**说明**：
- 根据你的 `fix_env_example.py`，`.env.example` 中默认是 `ROOM_MEDIA_ROOT_PATH=./media`（相对路径）
- 生产环境建议使用绝对路径 `/app/media`
- `compose-app.yml` 中的 `environment` 配置会覆盖 `.env.docker` 中的配置

#### 6. 重启服务

```bash
# 使用你实际使用的 compose 文件
docker-compose -f compose-app.yml down
docker-compose -f compose-app.yml up -d

# 或者如果你使用了其他文件名，请相应调整
```

### 方案二：通过 FastAPI 提供静态文件（备选）

如果不想修改 Nginx 配置，可以确保 FastAPI 的静态文件服务正常工作，但需要：

1. **确保路径正确**：设置 `ROOM_MEDIA_ROOT_PATH` 为容器内绝对路径 `/app/media`
2. **确保目录存在**：在容器启动时创建目录
3. **确保 Nginx 转发**：在 Nginx 中确保 `/media/` 请求被转发到 `live_core_service`

**Nginx 配置修改**（在 `/api/core/` location 之前添加）：

```nginx
# 媒体文件请求转发到 FastAPI（备选方案）
location /media/ {
    proxy_pass http://core_api/media/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**注意**：此方案性能较差，不推荐用于生产环境。

## 常见问题排查

### 问题 1：404 Not Found

**可能原因**：
- Nginx location 配置错误
- 文件路径不匹配
- 文件不存在

**排查步骤**：
```bash
# 检查文件是否存在
ls -la /var/www/html/live-core-media/rooms/<room_id>/cover_*.jpg

# 检查 Nginx 配置语法
docker exec -it <nginx_container_id> nginx -t

# 检查 Nginx 错误日志
docker logs <nginx_container_id> 2>&1 | grep error
```

### 问题 2：403 Forbidden

**可能原因**：
- 文件权限不足
- Nginx 用户无法访问文件

**解决方案**：
```bash
# 设置正确的权限
chmod -R 755 ./data/live_core_media
chown -R 101:101 ./data/live_core_media  # Nginx 容器默认用户 ID
```

### 问题 3：文件上传成功但无法访问

**可能原因**：
- 容器内路径与 Nginx 路径不一致
- Volume 挂载路径错误

**排查步骤**：
```bash
# 检查容器内文件
docker exec -it <live_core_service_container_id> ls -la /app/media/rooms/

# 检查宿主机文件（使用绝对路径）
ls -la /var/www/html/live-core-media/rooms/

# 检查 Nginx 容器内文件
docker exec -it <nginx_container_id> ls -la /var/www/html/live-core-media/rooms/

# 验证 volume 挂载是否正确
docker inspect <live_core_service_container_id> | grep -A 10 Mounts
docker inspect <nginx_container_id> | grep -A 10 Mounts
```

### 问题 4：路径大小写问题

**注意**：Linux 文件系统区分大小写，确保：
- URL 中的路径大小写与实际文件路径一致
- 代码中生成的路径大小写正确

## 最佳实践建议

1. **使用绝对路径**：始终使用容器内的绝对路径 `/app/media`，而不是相对路径 `./media`
2. **持久化存储**：使用 volume 挂载确保文件持久化，容器重启不丢失
3. **Nginx 提供静态文件**：生产环境使用 Nginx 直接提供静态文件，性能最佳
4. **设置缓存**：为静态文件设置适当的缓存时间，减少服务器负载
5. **监控磁盘空间**：定期检查媒体文件目录大小，避免磁盘满
6. **备份策略**：定期备份媒体文件目录

## 总结

**推荐方案**：使用方案一（Nginx 直接提供静态文件服务）

**关键修改点**：
1. ✅ `compose-app.yml`: 
   - `live_core_service` 添加环境变量 `ROOM_MEDIA_ROOT_PATH: "/app/media"` 和 volume 挂载 `/var/www/html/live-core-media:/app/media`
   - `nginx` 添加 media 目录 volume 挂载 `/var/www/html/live-core-media:/var/www/html/live-core-media:ro`
2. ✅ `nginx/nginx.conf`: 在 HTTPS 服务器中添加 `/media/` location（放在 API 代理之前）
3. ✅ `.env.docker`: 可选，设置 `ROOM_MEDIA_ROOT_PATH=/app/media`（已在 compose-app.yml 中设置，会覆盖）
4. ✅ 创建目录 `/var/www/html/live-core-media` 并设置权限

**路径映射关系**：
```
客户端请求: https://mp.dayilive.com/media/rooms/{room_id}/cover_xxx.jpg
    ↓
Nginx location /media/ → alias /var/www/html/live-core-media/rooms/{room_id}/cover_xxx.jpg
    ↓
宿主机路径: /var/www/html/live-core-media/rooms/{room_id}/cover_xxx.jpg
    ↓
Volume 挂载（live_core_service）: /var/www/html/live-core-media → /app/media
    ↓
live_core_service 容器内: /app/media/rooms/{room_id}/cover_xxx.jpg
```

**Volume 挂载说明**：
- `live_core_service`: `/var/www/html/live-core-media` (宿主机) → `/app/media` (容器内)
- `nginx`: `/var/www/html/live-core-media` (宿主机) → `/var/www/html/live-core-media` (容器内，只读)

**无需修改代码**：所有修改都在部署配置层面，代码保持不变。
