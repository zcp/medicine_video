# V6 模型字段缺失修复指南

## 问题分析

当前集成测试失败的主要原因是：**数据库模型（ORM）中缺少 V6 新增的字段**。

### 错误表现

1. **AttributeError**: `type object 'LiveRoom' has no attribute 'external_room_id'`
2. **HTTP 500 错误**：当代码尝试访问或写入这些字段时，会触发服务器内部错误
3. **数据库操作失败**：尝试写入不存在的字段会导致数据库错误

### 根本原因

在 `app/models/live_core.py` 中：
- `LiveRoom` 模型**缺少** `external_room_id` 字段
- `LiveSession` 模型**缺少** `playback_url_hash` 字段
- 两个模型都**缺少**对应的部分唯一索引定义

虽然 CRUD 层和 Service 层已经支持这些字段，但 ORM 模型定义不完整，导致：
- SQLAlchemy 无法识别这些字段
- 数据库迁移时不会创建这些字段
- 运行时访问这些字段会抛出 AttributeError

## 修复步骤

### 1. 修改 `app/models/live_core.py`

#### 1.1 为 `LiveRoom` 添加 `external_room_id` 字段

在 `LiveRoom` 类中，找到 `category_id` 字段定义之后（约第 66 行），添加：

```python
# 分类ID
category_id = Column(UUID(as_uuid=True), nullable=True)

# V6 新增：外部直播间ID（用于批量导入幂等）
external_room_id = Column(String(64), nullable=True, comment="外部直播间ID（如第三方平台直播间ID）")

# 时间戳
created_at = Column(TIMESTAMP(timezone=True), nullable=False, server_default=func.now())
```

#### 1.2 为 `LiveRoom` 添加部分唯一索引

修改 `LiveRoom` 类的 `__table_args__`（约第 73-75 行），从：

```python
# 索引定义
__table_args__ = (
    Index("idx_live_rooms_user_id", "user_id"),
)
```

改为：

```python
# 索引定义
__table_args__ = (
    Index("idx_live_rooms_user_id", "user_id"),
    # V6 新增：部分唯一索引（仅对非空 external_room_id 生效）
    Index(
        "uq_live_rooms_user_external_room",
        "user_id",
        "external_room_id",
        unique=True,
        postgresql_where=text("external_room_id IS NOT NULL"),
    ),
)
```

**注意**：需要在文件顶部导入 `text`：

```python
from sqlalchemy import Column, String, Text, Boolean, Integer, BigInteger, TIMESTAMP, ForeignKey, Enum as SAEnum, Index
from sqlalchemy.sql import text  # 添加这一行
```

#### 1.3 为 `LiveSession` 添加 `playback_url_hash` 字段

在 `LiveSession` 类中，找到 `playback_url` 字段定义之后（约第 114 行），添加：

```python
# 回放地址（持久化字段）
playback_url = Column(String(1024), nullable=True)

# V6 新增：playback_url 规范化后的哈希值（用于幂等导入）
playback_url_hash = Column(String(128), nullable=True, comment="playback_url 规范化后的哈希值")

# 时间戳
created_at = Column(TIMESTAMP(timezone=True), nullable=False, server_default=func.now())
```

#### 1.4 为 `LiveSession` 添加部分唯一索引

在 `LiveSession` 类中，添加 `__table_args__`（在 `playback_url_hash` 字段定义之后，约第 119 行之后）：

```python
# V6 新增：playback_url 规范化后的哈希值（用于幂等导入）
playback_url_hash = Column(String(128), nullable=True, comment="playback_url 规范化后的哈希值")

# 索引定义（V6 新增）
__table_args__ = (
    # V6 新增：部分唯一索引（仅对非空 playback_url_hash 生效）
    Index(
        "uq_live_sessions_room_playback_hash",
        "room_id",
        "playback_url_hash",
        unique=True,
        postgresql_where=text("playback_url_hash IS NOT NULL"),
    ),
)

# 时间戳
created_at = Column(TIMESTAMP(timezone=True), nullable=False, server_default=func.now())
```

### 2. 执行数据库迁移

修改模型后，需要执行数据库迁移脚本（如果使用 Alembic）或直接执行 SQL：

#### 2.1 如果使用 Alembic

```bash
# 生成迁移文件
alembic revision --autogenerate -m "Add V6 external_room_id and playback_url_hash fields"

# 执行迁移
alembic upgrade head
```

#### 2.2 如果直接执行 SQL

执行以下 SQL 脚本（与设计文档 `2.2` 节一致）：

```sql
-- 1) live_rooms 新增 external_room_id（外部直播间标识）
ALTER TABLE live_rooms
ADD COLUMN IF NOT EXISTS external_room_id VARCHAR(64) NULL;

-- 为同一 user 下的 external_room_id 建部分唯一索引（仅对非空值生效）
CREATE UNIQUE INDEX IF NOT EXISTS uq_live_rooms_user_external_room
ON live_rooms (user_id, external_room_id)
WHERE external_room_id IS NOT NULL;

COMMENT ON COLUMN live_rooms.external_room_id IS
'外部直播间ID（如第三方平台导出中的直播间ID），用于批量导入时按 (user_id, external_room_id) 维度复用房间';


-- 2) live_sessions 新增 playback_url_hash（回放地址幂等哈希）
ALTER TABLE live_sessions
ADD COLUMN IF NOT EXISTS playback_url_hash VARCHAR(128) NULL;

-- 为 (room_id, playback_url_hash) 建部分唯一索引（仅对非空hash生效）
CREATE UNIQUE INDEX IF NOT EXISTS uq_live_sessions_room_playback_hash
ON live_sessions (room_id, playback_url_hash)
WHERE playback_url_hash IS NOT NULL;

COMMENT ON COLUMN live_sessions.playback_url_hash IS
'playback_url 规范化后的哈希值，用于按 (room_id, playback_url) 维度实现幂等导入';
```

## 注意事项

1. **导入语句**：确保在文件顶部导入 `text`：
   ```python
   from sqlalchemy.sql import text
   ```

2. **数据库兼容性**：部分唯一索引使用 `postgresql_where`，这是 PostgreSQL 特有的语法。如果使用其他数据库，需要调整。

3. **测试数据库**：修复后，需要重新创建测试数据库表，或者运行迁移脚本。

4. **向后兼容**：这些字段都是 `nullable=True`，不会影响现有数据。
