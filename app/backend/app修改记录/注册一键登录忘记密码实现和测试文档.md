## 一、后端实现总览

### 1.1 密码基础设施

**文件：** `app/core/password.py`

| 函数 | 说明 |
|:---|:---|
| `hash_password()` | bcrypt 哈希（`$2b$` 前缀，60 字符） |
| `verify_password()` | 自动兼容 bcrypt + 旧 SHA-256 |
| `is_legacy_sha256_hash()` | 检测旧哈希，用于登录时自动升级 |

登录成功时通过 `_upgrade_password_hash_if_needed()` 静默升级旧 SHA-256 到 bcrypt，用户无感知。

### 1.3 核心请求 Schema

**`POST /auth/verification-codes`**
```json
{"channel":"SMS","recipient":"+8613800138000","scenario":"REGISTER|RESET_PASSWORD|LOGIN|BIND_PHONE","captcha_id":"...","captcha_solution":"..."}
```

**`POST /auth/verification-codes/verify`**
```json
{"channel":"SMS","recipient":"+8613800138000","scenario":"REGISTER|RESET_PASSWORD|BIND_PHONE","code":"123456"}
```
→ 返回 `{"ticket":"...", "expires_in":600}`

**`POST /auth/login`** → `{"login_id":"...","password":"...","captcha_id":"...","captcha_solution":"..."}`

**`POST /auth/login/phone`** → `{"login_ticket":"..."}`

**`POST /auth/one-tap-login`** → `{"carrier_token":"...","provider":"aliyun"}`
→ 返回 `{"access_token","refresh_token","is_new_user","phone_masked"}`

**`POST /auth/password-reset`**（双路径）
```json
// 邮箱链接路径
{"reset_token":"...","new_password":"NewPass@123"}
// OTP ticket 路径
{"reset_ticket":"...","new_password":"NewPass@123"}
```

**`POST /users/register/phone`**
```json
{"register_ticket":"...","password":"NewPass@123","nickname":"用户昵称"}
```

### 1.4 统一 Ticket 机制

所有身份验证场景共用同一票据模型：

```
Redis 存储: ticket:{purpose}:{ticket_id} → JSON payload
TTL: 600s (10 分钟)
单次使用: 读取后立即删除
```

| 场景 | 发码 | 校验 | 消费 |
|:---|:---|:---|:---|
| REGISTER | `send_otp_code` | `verify_otp_and_issue_ticket` | `register_by_phone_ticket` |
| LOGIN | `send_otp_code` | `verify_otp_and_issue_ticket` | `login_by_phone_ticket` |
| RESET_PASSWORD | `send_otp_code` | `verify_otp_and_issue_ticket` | `perform_password_reset` |
| BIND_PHONE | `send_otp_code` | `verify_otp_and_issue_ticket` | `bind_phone_number` |

### 1.5 关键安全机制

| 机制 | 实现 |
|:---|:---|
| 密码哈希 | bcrypt，向下兼容旧 SHA-256，登录时自动升级 |
| 弱密码拒绝 | 8 位 + 大写 + 小写 + 数字 + 特殊字符 |
| OTP 尝试锁定 | 最多 5 次错误，超限后删除 OTP |
| IP 限流 | 同一 IP 每小时最多 5 次 OTP 请求 |
| 防枚举 | 密码重置请求时用户不存在/被封禁仍返回成功 |
| 会话吊销 | 密码重置/修改密码后写入 `user_sessions_revoked:{public_id}`，refresh 时比较 `iat` |
| 日志脱敏 | OTP/邮箱/手机号均掩码后记录 |
| 验证码一次性 | 图形码和 OTP 均使用后即删 |

## 三、Bug 修复记录

### 3.1 Bug 1：修改密码后旧会话未吊销

**现象：** `change_password` 调用 `_blacklist_user_tokens(user_id)` 写入 `user_tokens_blacklisted:{id}` key，但**没有任何代码读取该 key**。

**修复：** 改为写入 `user_sessions_revoked:{public_id}`（带时间戳、7 天过期），与 `_revoke_user_sessions` 使用同一 key，`_is_user_sessions_revoked` 在 refresh 时实际检查。

### 3.2 Bug 2：`_is_user_sessions_revoked` 未比较时间戳

**现象：** 方法只检查 key 是否存在，导致密码重置后新签发的 refresh token（`iat` 在吊销之后）也无法刷新。

**修复：** `_is_user_sessions_revoked` 增加 `token_iat` 参数，比较 `iat < revocation_time`。`refresh_access_token` 提取 JWT payload 中的 `iat` 传入。

### 3.3 日志脱敏

**修复范围：** 修复了 `auth_service.py`（6 处）和 `user_service.py`（9 处）的日志明文暴露问题，所有 recipient/email/phone 均使用 `_mask_recipient()` 掩码后记录。

## 五、问题与解决方案

### 5.1 pytest conftest 发现路径问题

**现象：** `ModuleNotFoundError: No module named 'app.database'`

**根因：** pytest 7.4.3 conftest 发现机制使用独立解析器，不继承 `sys.path`。

**解决：** 创建 `run_preload.py` 预加载脚本（与 Tab 测试相同方案）。

### 5.2 `run_preload.py` Settings 缓存策略

**现象：** 清除 `app.core.config` 缓存后，模块级 `settings = Settings()` 在测试收集阶段用 Docker 环境变量重跑，触发生产配置校验，阻断了整个测试套件。

**解决：** 移除 `del sys.modules['app.core.config']` 缓存清除逻辑，改为 `os.environ.setdefault("ENVIRONMENT", "development")`。`Settings.__init__()` 的 92-102 行在实例化时重新读取 `os.getenv()`，monkeypatch 天然生效。
