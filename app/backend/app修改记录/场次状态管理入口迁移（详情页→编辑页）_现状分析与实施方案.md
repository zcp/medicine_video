## 一、执行摘要

### 1.1 背景

V15（外部直播流创建与手动开播）上线后，external 场次的手动状态切换能力**已在详情页 detail.vue 的每条场次卡片上落地**（按钮组：开播/停播/转回放/恢复开播/发布回放），且编辑页 edit.vue 同时存在一个**残缺的"场次状态"区块**——仅 status `scheduled` 时可选 `scheduled/ready`，其余状态只读并提示"该状态请在直播间详情页管理"。

用户反馈：**状态切换入口放错了位置**。详情页职责应是"查看相关信息"，而"编辑"与"状态切换"应统一归口编辑页。本轮讨论据此定稿：把 external 场次的状态管理入口从详情页迁移到编辑页，详情页净化。

### 1.2 核心结论

1. **后端契约完整存在且前端已匹配**（纠正早前"前端独造接口"误区）：`POST /api/v1/sessions/{session_id}/status` 由提交 `d1d8707` 引入（`api/v1/endpoints/session.py:182-261`），`api.py:27` 已挂载；`switch_external_status`（`session_service.py:449-553`）承载全部状态机逻辑（仅 external、房主/Admin、矩阵 :40-45、播放地址守卫 :519-522、乐观锁 409）。
2. **前端链路完整且一致**：`api/session.ts:69-77` → `store/session.ts:245-281` → `detail.vue:235-761`。**本方案不新增接口、不修改后端**，纯粹是**前端入口归位 + 修复编辑页半成品**。
3. **编辑页存在 3 个硬伤**：①`currentStatusLabel`（`edit.vue:654`）恒为空字符串 → 非 scheduled 场次的状态行显示**空白**（bug）；②状态仅 `scheduled/ready` 两态（:629-632），且仅 `scheduled` 可选（:653），live/finished 场次在编辑页**零状态操作能力**；③保存流与状态机耦合（:1229-1264）——external PATCH 带 `status` 会整体转发 `switch_external_status`，**静默丢弃 start_time/end_time 修改**。
4. **"详情页踢皮球"闭环**：edit.vue 提示"请到详情页管理"，详情页依赖 `isExternalSession` 又受 `source_type` 归属影响，存量导入通道场次（push）两者都无入口 → 用户感知"切换功能没实现"（真因见 §5.1 P3）。
5. **方案定为 B（迁移）**：状态操作按钮组迁入编辑页并即时生效（不走主保存流），详情页删除按钮区；配套修复 currentStatusLabel 空串 bug、移除 scheduled/ready 选择器。后端零改动。

### 1.3 范围界定

| 范围 | 内容 |
|------|------|
| ✅ 本次实施 | 前端 App 端：edit.vue 状态区改造（当前状态展示 + external 操作按钮组 + 保存流解耦）；detail.vue 净化（删按钮区与相关函数）；复用既有 `updateSessionStatus` API/store；后端契约核验标注（零改动） |
| ⏸️ 暂缓 | 存量 push 场次（导入回放/CSV 批量导入通道创建）的 `source_type` 归属修正（属另一个数据治理主题，见 §12 S2）；h5 管理端同款能力（`pages/h5/room/RoomManage.vue` 等，核验确认**无**同款按钮，暂不改）；detail.vue 增加"跳转编辑页"入口（可选项，见 §12 S3） |
| ❌ 不实施 | 后端任何改动；pick 式"选择目标状态"交互（状态机是"当前态→目标态"，按钮组才准确）；详情页保留状态切换能力（本次明确移除）；`statusOptions`/`isStatusSelectable`/`statusValue` 旧选择器逻辑（随本方案删除） |

### 1.4 预期效果

| 维度 | 现状 | 改造后 |
|------|------|--------|
| 状态管理入口 | 详情页每条场次卡片内嵌按钮组（误触风险、职责错位） | **编辑页"场次状态"区**（当前状态 + 操作按钮组，即时生效） |
| 详情页职责 | 查看 + 内嵌写操作 | 纯查看（保持跳转 LiveView/关联信息展示） |
| edit.vue 状态区 | 仅 scheduled 可选（scheduled/ready 两态）；只读时显示**空白** | 全状态展示（修复空串 bug）；external 显示完整操作按钮组；push 显示"系统流程生成"只读提示 |
| edit.vue 保存流 | status 与 title/时间/地址同请求提交，PATCH 转发会**静默丢时间字段** | 资料保存（title/时间/playback_url）与状态切换**完全解耦**，各走各的通道（PATCH / POST status） |
| 存量 push 场次 | 详情/编辑均无状态操作入口（感觉"没实现"） | 编辑页明确只读提示 + 归属修正列入暂缓（S2） |

## 四、后端契约核验（代码为准）

> 结论先行：**后端零改动即可支撑本方案**；以下为支撑性核验，实施阶段不再触碰后端。

### 4.1 手动状态切换端点

- `POST /api/v1/sessions/{session_id}/status`：`api/v1/endpoints/session.py:182-261`，`api.py:27` 挂载 `prefix="/sessions"`
- 请求体 `SessionStatusUpdate {status, playback_url?}`：`schemas/live_core.py:100-103`
- 异常映射（端点内）：404/2001、403/3002、403/2004（业务拒）、409/2006

### 4.2 状态机（`services/session_service.py`）

- `switch_external_status`（:449-553）：
  - 权限：`_check_write_permission`（:490）→ 房主或 Admin（`core/permissions.check_room_owner_or_admin`）
  - **仅 external**：push 直接拒绝（:493-497）
  - 矩阵（:40-45，V15 V2.0 修订）：`scheduled→live/ready`；`live→finished/ready`；`finished→live/ready`；`ready` 终态
  - 守卫（:519-522）：转 live/ready 必须存在 playback_url（无则 4001/2004）
  - 时间维护（:524-532）：转 live 清空 end_time；转 finished/ready 补 end_time；幂等（目标==当前直接返回 :499-502）；乐观锁 409（:539-549）
- `lazy_promote_if_due`（:555-579）：external + scheduled + `start_time<=now` → 条件更新转 live（**惰性补转**，仅访问时触发；调用点 :286、`room.py:357-367`）——与手动开播不冲突

### 4.3 `source_type` 归属（决定按钮是否可见）

| 创建通道 | source_type | 依据 |
|----------|------------|------|
| 页面三态创建 `POST /rooms/{room_id}/sessions` | **EXTERNAL** | `schemas/live_core.py:94-97` 默认 `SourceType.EXTERNAL`（注释："用户接口固定 external"）；`session_service.py:168` 兜底 `or EXTERNAL`；创建时初始状态仅允许 scheduled/live/ready（:146-153），live 强刷 start_time=now（:156-158） |

### 5.3 交互口径（定稿）

2. push 场次：只读 + "该状态由系统流程生成，不能手动切换"
3. 转 live/ready 时：优先携带表单 `playback_url`（已填则用）；为空则 toast 提示"请先在回放地址填写直播流/视频地址"（对齐后端守卫）
4. 主保存流（title/时间/playback_url/封面/标签）后续**永不提交 status**，与状态机彻底解耦
