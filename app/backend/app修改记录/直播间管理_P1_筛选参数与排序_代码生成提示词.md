## 1. 角色定义 (Role Definition)

你是一名精通 SQLAlchemy 2.0 async + PostgreSQL 的 Python 后端工程师。你熟悉本项目"学院派"分层架构（CRUD → Service → Endpoint），以及项目现存的编码规范——`success_response`/`error_response` 响应格式、`get_current_user`/`get_current_user_optional` 鉴权模式、`check_admin_permission` 守卫函数。

你的任务是为 `GET /api/v1/rooms` 端点新增 3 个筛选参数（`status`、`created_after`、`created_before`）和 1 个排序扩展（`sort=start_time`），并在 `LiveSession`/`LiveRoom` 模型中补上 4 个缺失的查询索引。

**四个必须**：
- 必须使用 EXISTS 子查询（而非 LEFT JOIN）处理 `status` 筛选，避免产生重复行和性能退化
- 必须在枚举转换之前先做合法性校验，拒绝无效 status 值（返回 400/4001）
- 必须对三个 CRUD 函数（`get_multi_and_total`、`get_multi_and_total_by_owner`、`list_with_search`）**全部**应用新筛选条件，不得遗漏任何一个
- 排序中的 `nulls_last()` 必须正确使用，确保没有 Session 的房间排在列表末尾

#### 4.4.1 公共辅助：status 校验 + 筛选 Builder

在 `app/crud/room.py` 文件开头（函数外部）新增一个模块级私有函数，供三个查询函数复用：

```python
def _apply_status_filter(query, status_list, LiveRoom, LiveSession, LiveSessionStatus):
    """对查询应用 status EXISTS 筛选；返回可能修改后的 query 或抛 InvalidParameterException"""
    if not status_list:
        return query
    valid_statuses = {e.value for e in LiveSessionStatus}
    invalid = [s for s in status_list if s.lower() not in valid_statuses]
    if invalid:
        raise InvalidParameterException(f"无效的状态值: {invalid}", code=4001)
    status_enum_values = [LiveSessionStatus[s.upper()] for s in status_list]
    query = query.where(
        exists().where(
            and_(
                LiveSession.room_id == LiveRoom.id,
                LiveSession.status.in_(status_enum_values)
            )
        )
    )
    return query
```

**Step 2 — 扩展 `start_time` 排序**（替换现有的排序处理块，第 294-315 行）：

```python
        # ← 修改：排序处理（扩展支持 start_time）
        if sort:
            sort_parts = sort.split(':')
            if len(sort_parts) == 2:
                field_name, direction = sort_parts[0], sort_parts[1].upper()
                if direction not in ('ASC', 'DESC'):
                    query = query.order_by(LiveRoom.created_at.desc())
                elif field_name == 'start_time':
                    # 标量子查询：每个房间取最新 session 的 start_time
                    latest_start = (
                        select(LiveSession.start_time)
                        .where(LiveSession.room_id == LiveRoom.id)
                        .order_by(LiveSession.start_time.desc())
                        .limit(1)
                        .correlate(LiveRoom)
                        .scalar_subquery()
                    )
                    if direction == 'DESC':
                        query = query.order_by(latest_start.desc().nulls_last())
                    else:
                        query = query.order_by(latest_start.asc().nulls_last())
                elif hasattr(LiveRoom, field_name):
                    field = getattr(LiveRoom, field_name)
                    if direction == 'DESC':
                        query = query.order_by(field.desc())
                    else:
                        query = query.order_by(field.asc())
                else:
                    query = query.order_by(LiveRoom.created_at.desc())
            else:
                query = query.order_by(LiveRoom.created_at.desc())
        else:
            query = query.order_by(LiveRoom.created_at.desc())
```

**关键说明**：
- `start_time` 不属于 `LiveRoom`，不能用 `hasattr(LiveRoom, field_name)` 判断，需要在条件分支中单独处理
- 使用 `correlate(LiveRoom)` 将子查询与外层查询关联（correlated subquery），翻译为 `SELECT start_time FROM live_sessions WHERE room_id = live_rooms.id ORDER BY start_time DESC LIMIT 1`
- `.scalar_subquery()` 确保子查询返回标量值，可用于 `.order_by()`
- `.nulls_last()` 确保没有 Session 的房间排在最后，不干扰正常排序
