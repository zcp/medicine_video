## 1. 角色定义 (Role Definition)

你是一名精通 SQLAlchemy 2.0 异步查询 + FastAPI + PostgreSQL 的 Python 后端工程师。你熟悉本项目的学院派分层架构（`models/ → schemas/ → crud/ → services/ → api/v1/endpoints/`），严格遵循安全异步异常处理模式。

Sprint 3 的核心职责是**数据治理 + 运营工具**：清理历史遗留的非标准种子数据，补齐管理员日常运营所需的批量审核和统计看板能力，为每个自动创建的科室添加可追溯的来源标记。

**五个必须**：
- 必须严格遵循已有 CRUD 层的 `try/except IntegrityError` 事务模式和分页查询的 `count + offset/limit` 模式
- 必须遵循已有 API 端点的异常处理链（自定义异常 → JSONResponse 映射）
- 所有新增/修改的 DDL 迁移必须使用 `IF NOT EXISTS` / `IF EXISTS` 保证幂等性
- 公开接口的分类数据必须附带 `expert_count` 和 `room_count` 字段
- Service 层调用 `_resolve_department_and_category` 自动创建科室时必须写入 `source` 字段

**三个不允许**：
- 不允许修改 `_match_broad_category` 和 `_resolve_department_and_category` 的核心匹配逻辑（Sprint 1/2 已修）
- 不允许修改已有 API 端点的 URL 签名和请求/响应 Schema 的字段名（只能加新字段，不能删改旧字段）

## 4. 架构约束 (Architecture Constraints)

### 4.1 分层职责铁律

| 层 | 能做什么 | 不能做什么 |
|:--|:------|:---------|
| **Model** | 定义列/索引/relationship | 不包含业务逻辑 |
| **CRUD** | `db.add()` / `db.flush()` / `db.refresh()` / `try/except IntegrityError` / 标量子查询 | `db.commit()` / 业务逻辑 |
| **Service** | 权限检查 / 业务校验 / 组装查询 / 调用 CRUD | `db.commit()` / 捕获裸 Exception / 直接操作 ORM 列 |
| **API** | 提取 JWT / 调用 Service / `try/except` 转 JSONResponse / 日志 | 业务逻辑 / 直接调用 CRUD |

### 4.2 SQL 迁移幂等性铁律

```
所有 DDL 必须可重复执行:
  ✅ ALTER TABLE ... ADD COLUMN IF NOT EXISTS
  ✅ CREATE INDEX IF NOT EXISTS
  ✅ DELETE FROM ... WHERE name IN (...)  — 先 SELECT 确认存在，再 DELETE
  ✅ UPDATE ... SET ... WHERE ... AND EXISTS (SELECT 1 FROM ...)
  ❌ TRUNCATE / DROP COLUMN（不可逆操作需单独确认）
```

### 4.3 向后兼容约束

```
公开接口 GET /content/categories:
  ✅ 只新增字段（expert_count, room_count）
  ❌ 不修改已有字段名
  ❌ 不删除已有字段
  ❌ 不修改字段类型

Schema 扩展:
  ✅ ExpertDepartmentItem 新增 source, created_by（Optional, 默认 None）
  ❌ 不修改已有字段的类型和名称
```

### 5.1 新建 `migrations/V8_clean_department_seed.sql`

**文件路径**：`backend/live_core_service/migrations/V8_clean_department_seed.sql`

**此迁移必须在 Sprint 2 完成（21 条分类全部存在）之后执行。**

**迁移内容**：

```sql
-- 分类优化 V8：清理 expert_departments 表中的非标准科室种子数据
-- 背景：V4 迁移插入的部分种子数据存在命名不规范问题（审查报告问题 6）
-- 前置条件：categories 表中 21 条根分类全部存在（Sprint 1 + Sprint 2 已完成）
-- 幂等性：所有 UPDATE/DELETE 使用 EXISTS 守卫

-- 1) 移除「外科门诊」——这是服务类型，不是医学科室名
DELETE FROM expert_departments
WHERE name = '外科门诊'
  AND EXISTS (SELECT 1 FROM expert_departments WHERE name = '外科门诊');

-- 2) 移除「肝外科/超声医学科/介入超声专科」——三个科室拼在一起的复合名
DELETE FROM expert_departments
WHERE name = '肝外科/超声医学科/介入超声专科'
  AND EXISTS (SELECT 1 FROM expert_departments WHERE name = '肝外科/超声医学科/介入超声专科');

-- 3) 拆分「口内修复科」→「口腔内科」+「口腔修复科」
-- 3a. 先重命名现有的「口内修复科」→「口腔内科」
--     口腔内科是口腔科的亚专业，与「口内修复科」语义最接近
UPDATE expert_departments
SET name = '口腔内科',
    synonyms = synonyms || '["口内修复科"]'::jsonb
WHERE name = '口内修复科'
  AND EXISTS (SELECT 1 FROM expert_departments WHERE name = '口内修复科');

-- 3b. 再创建「口腔修复科」（如果尚不存在）
--     先获取口腔科的 category_id，然后插入新记录
DO $$
DECLARE
    cat_id UUID;
BEGIN
    SELECT id INTO cat_id FROM categories WHERE name = '口腔科' AND is_active = true LIMIT 1;
    IF cat_id IS NOT NULL THEN
        INSERT INTO expert_departments (id, name, category_id, synonyms, is_verified)
        SELECT gen_random_uuid(), '口腔修复科', cat_id, '["口腔修复"]'::jsonb, true
        WHERE NOT EXISTS (SELECT 1 FROM expert_departments WHERE name = '口腔修复科');
        RAISE NOTICE '口腔修复科: 已插入或已存在';
    ELSE
        RAISE WARNING '分类"口腔科"不存在，无法插入口腔修复科种子数据——请先执行 Sprint 2';
    END IF;
END $$;

-- 4) 清理「显微创伤外手科」→ 添加标准同义词（不改 name，保持现有记录）
UPDATE expert_departments
SET synonyms = synonyms || '["手外科", "创伤骨科"]'::jsonb
WHERE name = '显微创伤外手科'
  AND NOT (synonyms @> '["手外科"]'::jsonb)
  AND EXISTS (SELECT 1 FROM expert_departments WHERE name = '显微创伤外手科');
```

**需要确保的（5 个强制要求）**：

1. ✅ **幂等性**：所有 `DELETE`/`UPDATE` 前带 `EXISTS` 守卫，可重复执行
2. ✅ **原子性**：整段在一个事务中执行（SQL 文件默认行为）
3. ✅ **不影响专家关联**：被删除/重命名的科室如果有关联专家，`experts.department_id` 的外键是 `ON DELETE SET NULL` → 关联专家的 `department_id` 自动变 NULL（不会丢失专家数据）
4. ✅ **日志可见**：使用 `RAISE NOTICE` 和 `RAISE WARNING` 输出执行状态
5. ✅ **synonyms 合并**：改名时用 `synonyms || '["旧名"]'::jsonb` 追加旧名到同义词列表，保留匹配能力

### 5.2 新建 `migrations/V9_add_department_source.sql`

**文件路径**：`backend/live_core_service/migrations/V9_add_department_source.sql`

```sql
-- 分类优化 V9：expert_departments 表新增来源追踪字段
-- 背景：自动创建的 is_verified=false 科室无法追溯来源（审查报告问题 8）
-- 前置条件：V8 已执行（非严格依赖，但建议按顺序执行）
-- 幂等性：所有 DDL 使用 IF NOT EXISTS

-- 1) 新增 source 字段
ALTER TABLE expert_departments
ADD COLUMN IF NOT EXISTS source VARCHAR(50);

COMMENT ON COLUMN expert_departments.source IS
'科室创建来源：auto_match=自适应匹配, csv_import=CSV批量导入, manual_create=手动创建专家, admin_api=管理员API直接创建';

-- 2) 新增 created_by 字段
ALTER TABLE expert_departments
ADD COLUMN IF NOT EXISTS created_by UUID;

COMMENT ON COLUMN expert_departments.created_by IS
'创建人 user_id。自适应匹配时为 NULL（无用户上下文），管理员手动创建时记录';

-- 3) 索引
CREATE INDEX IF NOT EXISTS idx_expert_departments_source ON expert_departments(source);
CREATE INDEX IF NOT EXISTS idx_expert_departments_created_by ON expert_departments(created_by);

-- 4) 回填历史数据：所有现有 is_verified=true 的标记为种子数据
UPDATE expert_departments
SET source = 'seed_v4'
WHERE source IS NULL
  AND is_verified = true;

-- is_verified=false 的历史数据标记为 unknown（无法追溯）
UPDATE expert_departments
SET source = 'unknown_legacy'
WHERE source IS NULL
  AND is_verified = false;
```

```python
async def get_categories(
    db: AsyncSession,
    current_user_id: Optional[UUID],
    role: Optional[str]
) -> List[Category]:
    """获取分类列表（公开接口），附带每个分类的专家数和直播间数。"""

    # 标量子查询：每个分类下的启用专家数
    expert_count_subq = (
        select(func.count(Expert.id))
        .where(
            Expert.category_id == Category.id,
            Expert.is_active == True,
        )
        .correlate(Category)
        .scalar_subquery()
        .label("expert_count")
    )

    # 标量子查询：每个分类下的关联直播间数
    room_count_subq = (
        select(func.count(LiveRoomCategory.room_id))
        .where(LiveRoomCategory.category_id == Category.id)
        .correlate(Category)
        .scalar_subquery()
        .label("room_count")
    )

    query = (
        select(Category, expert_count_subq, room_count_subq)
        .where(Category.is_active == True)
        .order_by(Category.sort_order.asc())
    )

    result = await db.execute(query)
    rows = result.all()

    categories = []
    for cat, expert_cnt, room_cnt in rows:
        cat.expert_count = expert_cnt   # 动态附加到 ORM 对象
        cat.room_count = room_cnt       # 动态附加到 ORM 对象
        categories.append(cat)

    logger.info(f"查询分类列表（公开），返回{len(categories)}条记录")
    return categories
```

```python
async def get_categories_stats(
    db: AsyncSession,
) -> List[dict]:
    """
    获取分类统计看板（管理员接口）：每个分类的专家数、科室数、直播间数。

    Returns:
        [{"category_id": UUID, "category_name": str, "expert_count": int,
          "department_count": int, "room_count": int}, ...]
    """
    # 专家数：按 category_id 分组
    expert_subq = (
        select(
            Expert.category_id,
            func.count(Expert.id).label("expert_count")
        )
        .where(Expert.is_active == True)
        .group_by(Expert.category_id)
        .subquery()
    )

    # 科室数：按 category_id 分组
    dept_subq = (
        select(
            ExpertDepartment.category_id,
            func.count(ExpertDepartment.id).label("department_count")
        )
        .where(ExpertDepartment.is_active == True)
        .group_by(ExpertDepartment.category_id)
        .subquery()
    )

    # 直播间数：按 category_id 分组
    room_subq = (
        select(
            LiveRoomCategory.category_id,
            func.count(LiveRoomCategory.room_id).label("room_count")
        )
        .group_by(LiveRoomCategory.category_id)
        .subquery()
    )

    # 主查询：以 categories 为主表，LEFT JOIN 三个子查询
    query = (
        select(
            Category.id.label("category_id"),
            Category.name.label("category_name"),
            func.coalesce(expert_subq.c.expert_count, 0).label("expert_count"),
            func.coalesce(dept_subq.c.department_count, 0).label("department_count"),
            func.coalesce(room_subq.c.room_count, 0).label("room_count"),
        )
        .outerjoin(expert_subq, Category.id == expert_subq.c.category_id)
        .outerjoin(dept_subq, Category.id == dept_subq.c.category_id)
        .outerjoin(room_subq, Category.id == room_subq.c.category_id)
        .where(Category.is_active == True)
        .order_by(Category.sort_order.asc())
    )

    result = await db.execute(query)
    rows = result.all()

    stats = [
        {
            "category_id": str(row.category_id),
            "category_name": row.category_name,
            "expert_count": row.expert_count,
            "department_count": row.department_count,
            "room_count": row.room_count,
        }
        for row in rows
    ]

    logger.info(f"查询分类统计，返回{len(stats)}条记录")
    return stats
```

**需要确保的（4 个强制要求）**：

1. ✅ **LEFT JOIN**：使用 `outerjoin` 而非 `join`，确保分类即使计数为 0 也会出现
2. ✅ **`func.coalesce(..., 0)`**：处理 NULL → 0 转换（当 LEFT JOIN 没有匹配时子查询列返回 NULL）
3. ✅ **`Category.is_active == True`**：只返回启用的分类

**修改 2：新增 `batch_verify_departments` 方法**

```python
async def batch_verify_departments(
    self,
    department_ids: List[uuid.UUID],
    current_user_id: uuid.UUID,
    role: str,
) -> dict:
    """批量审核科室：将指定科室的 is_verified 设为 true。

    Args:
        department_ids: 需要审核的科室 ID 列表
        current_user_id: 当前用户 ID
        role: 用户角色

    Returns:
        {"verified_count": int, "not_found_count": int}

    Raises:
        PermissionDeniedException: 非管理员
    """
    check_admin_permission(role)
    user_id_log = str(current_user_id)[:8]

    verified = 0
    not_found = 0
    for dept_id in department_ids:
        dept = await crud_dept.get_department_by_id(self.db, dept_id)
        if dept is None:
            not_found += 1
            continue
        if dept.is_verified:
            verified += 1    # 已是 verified，算作成功
            continue
        dept.is_verified = True
        await self.db.flush()
        verified += 1

    self.logger.info(
        f"批量审核科室完成: verified={verified}, not_found={not_found}, "
        f"total_requested={len(department_ids)}, user_id={user_id_log}"
    )
    return {
        "verified_count": verified,
        "not_found_count": not_found,
    }
```

**需要确保的（3 个强制要求）**：

1. ✅ **权限检查**：最前面调用 `check_admin_permission(role)`
2. ✅ **部分成功语义**：不因单个科室不存在而整体失败——逐个处理，分别计数 `verified` 和 `not_found`
3. ✅ **idempotent**：已审核的科室再次调用不报错，计入 `verified`
