### A4 — P1-4：直播间主分类

| 属性 | 值 |
|:---|:---|
| 文件 | `migrations/V11_fix_live_room_primary.sql`（新增）+ `crud/content_management.py` `delete_live_room_category` |
| 改动 | 迁移 SQL 修补存量数据 + 删除主分类时自动递补 |
| 行数 | +15 SQL + +10 Python |
| 风险 | 🟢 低。迁移 SQL 有 NOT EXISTS 守卫；递补逻辑纯增量 |

```
迁移 SQL（一次性）:
  UPDATE live_room_categories lrc1
  SET is_primary = true
  WHERE lrc1.created_at = (
      SELECT MIN(lrc2.created_at) FROM live_room_categories lrc2
      WHERE lrc2.room_id = lrc1.room_id
  ) AND NOT EXISTS (
      SELECT 1 FROM live_room_categories lrc3
      WHERE lrc3.room_id = lrc1.room_id AND lrc3.is_primary = true
  );

代码改动（delete_live_room_category）:
  删除后：若被删除的是 is_primary 且该房间还有其他分类
  → 选 created_at 最早的那个 → 设为 is_primary=true
```

> **注意**：若存在相同 `created_at` 的多行（同一事务），`MIN(created_at)` 子查询可能返回多行。建议 `LIMIT 1` 兜底：`SELECT MIN(lrc2.created_at) ... LIMIT 1`。

**验证方式**：
- 迁移后查询：所有有分类的房间至少有一个 `is_primary=true`
- 删除主分类后：自动选出新的 `is_primary=true`
