### 🟡 P1 — 1 个问题

**问题 P1-1：Category.name 移除 unique=True 后缺少"当前数据库状态"说明**

P1 §5.3 让 AI 把 `name = Column(String(100), nullable=False, unique=True)` 改为去掉 `unique=True`。但 `categories_name_key` 约束当前仍存在于数据库中（261 条数据 + 约束）。P4 的 V5 迁移 SQL 负责 `DROP CONSTRAINT`。

**风险**：AI 生成的 ORM 模型和实际数据库存在不同步——ORM 说"无 unique=True"，但数据库里 `categories_name_key` 仍存在。这本身没问题（SQLAlchemy 不会自动删除数据库约束），但 AI 如果不理解这个时序，可能会认为删了 `unique=True` 就能插同名子分类——而实际上在 V5 迁移前插入同名的子分类会触发 `IntegrityError`。

**建议**：在 P1 末尾追加一段"部署前注意"中的一行：
```
⚠️ ORM 模型中已移除 unique=True，但数据库中的 categories_name_key 约束仍然存在。
  V5 迁移 SQL 会执行 DROP CONSTRAINT。在此之前，不要尝试插入同名子分类。
```

**问题 P3-3：merge_departments 中物理删除代码冗余且有 Bug**

P3 §5.1 改动 E 中：
```python
# 5. 物理删除源科室
await self.db.execute(sa_update(...).values(is_active=False))  # 行1：先软删
await self.db.execute(sa_update(...))                           # 行2：空操作！
from sqlalchemy import delete                                   # 行3：import 在函数体内
await self.db.execute(delete(ExpertDepartment).where(...))      # 行4：物理删
```

问题：
- 行 2 是空操作（没有 `.values()`）
- `from sqlalchemy import delete` 放在函数体内（应放到文件头部）
- 逻辑上先软删再物理删是冗余的——既然要物理删除就一步到位

**建议**：简化为：
```python
# 5. 物理删除源科室
await self.db.execute(delete(ExpertDepartment).where(ExpertDepartment.id == source_id))
```

### 🔴 P4 — 2 个问题

**问题 P4-1：Python 迁移脚本中 `text("experts")` 写法错误（阻断级）**

P4 §5.3 的 `run_migrate` 函数中：
```python
await session.execute(
    sa_update(text("experts"))          # ← text("experts") 作为表名传入 sa_update
    .where(text("id = :eid"))           # ← 用 text 传入 WHERE
    .values(department_id=dept_id, ...)
)
```

`sa_update(text("experts"))` 在 SQLAlchemy 2.0 中的行为不确定。正确的写法是：
```python
await session.execute(
    text("UPDATE experts SET department_id = :dept_id, category_id = :cat_id WHERE id = :eid"),
    {"dept_id": dept_id, "cat_id": cat_id, "eid": expert_id}
)
```

或使用 ORM：
```python
await session.execute(
    sa_update(Expert.__table__)
    .where(Expert.__table__.c.id == expert_id)
    .values(department_id=dept_id, category_id=cat_id)
)
```

**建议**：改为 `text("UPDATE experts SET ...")` 原生 SQL——更简单、更少语法歧义。

**问题 P4-2：Python 迁移脚本的 DATABASE_URL 硬编码**

```python
DATABASE_URL = "postgresql+asyncpg://postgres:postgres@localhost:5432/live_core_test"
```

生产环境不会用这个连接串。P4 的迁移脚本是独立脚本（不用 `app.database.get_db`），但至少应该支持环境变量覆盖。

**建议**：改为：
```python
import os
DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+asyncpg://postgres:postgres@localhost:5432/live_core_test")
```
