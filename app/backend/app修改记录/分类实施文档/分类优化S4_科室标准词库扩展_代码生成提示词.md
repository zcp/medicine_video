### 3.3 方案核心原理

```
                    匹配路径                              种子数据扩展的影响
              ┌─────────────────┐
输入科室名 →   │ 1. 精确匹配 name    │  ← 🎯 29%→45%（+16pp）
              │ 2. 同义词 synonyms  │  ← 🎯 10%→18%（+8pp）
              │ 3. 启发式(子串+MAP) │  ← 📉 51%→27%（负担减轻）
              │ 4. 自动创建          │  ← 📉 10%→5%（管理员审核量减半）
              └─────────────────┘

扩展的不是"总匹配率"（95%→97%，几乎没变），而是"匹配结果的质量"：
  种子数目   21 条(is_verified=true) → 160+ 条(is_verified=true)
  精确命中   29% → 45%（命中自带正确分类，不需要走启发式）
  同义词命中 10% → 18%（命中自带标准名，管理员不需要再 review）
```

### 3.4 数据编制原则

```
编制范围:
  ✅ 国标一级科目（外科/内科/妇产科…）→ 直接录入，name=科目名
  ✅ 国标二级科目（普通外科/神经外科…）→ 直接录入，name=科目名
  ✅ 三甲医院常见亚专科（乳腺外科/脊柱外科/冠脉介入…）→ 录入，name=亚专科名
  ✅ 常见别名/缩写/变体 → 不作为独立 name，而是记入对应标准科室的 synonyms
  ❌ 无对应根分类的 → 暂不录入（如呼吸内科——平台无此根分类，需业务决策）
  ❌ 医院自创的非标准名 → 不录入（留给自适应创建兜底）
  ❌ 复合科室名（含斜杠/拼接）→ 不录入（Sprint 3 V8 已清理）

每条种子的数据完整性:
  必须包含: name（标准科室名，全局唯一）
  必须包含: category_name（指向 21 个根分类之一的名称）
  可选包含: synonyms（list of str，变体/别名/缩写）
  固定值:   is_verified=true（已审核标准词）
  固定值:   is_active=true
  固定值:   source='seed_s4'
```

### 3.5 种子脚本的执行流程

```
1. 导入 app.database.SessionLocal（同步会话）
2. 查询 categories 表 → 构建 {category_name: category_id} 映射
3. 遍历 DEPARTMENT_SEED 列表：
   a. 通过 category_name 查找 category_id（查不到 → 跳过并 WARNING）
   b. 检查 expert_departments 是否已有同名记录（有 → 跳过）
   c. 生成 UUID → 构造 ExpertDepartment 对象
   d. 插入 + session.flush()
4. session.commit()
5. 输出统计：成功 N 条 / 跳过（已存在）M 条 / 跳过（无分类）K 条
```

#### 参考 D：`app/crud/expert_departments.py` — `create_department` 函数

```python
async def create_department(
    db: AsyncSession,
    department_data: ExpertDepartmentCreate,
) -> ExpertDepartment:
    dept_id = uuid.uuid4()
    dump_data = department_data.model_dump()
    if "is_active" not in dump_data:
        dump_data["is_active"] = True
    if "is_verified" not in dump_data:
        dump_data["is_verified"] = False
    department = ExpertDepartment(id=dept_id, **dump_data)
    try:
        db.add(department)
        await db.flush()
        await db.refresh(department)
        return department
    except IntegrityError:
        await db.rollback()
        raise DatabaseIntegrityException(f"科室名称已存在: {department_data.name}")
```

**关键观察点**：
- 这是**异步**函数——种子脚本是同步脚本，**不能复用这个函数**
- 种子脚本需要直接使用 `session.add()` + `session.flush()` + `session.commit()` 的同步模式
- 冲突处理：种子脚本应**在插入前做幂等检查**（先用 name 查询是否存在），而非依赖 IntegrityError 回滚

6. ✅ **与现有 V4 种子不冲突**——种子脚本在插入前做幂等检查，V4 已有的记录（如"乳腺外科"）会被跳过

#### 5.1.3 主函数

```python
def seed_departments(session: Session) -> dict:
    """
    种子: 专家科室受控词表

    返回: {"success": int, "skipped_existing": int, "skipped_no_category": int}
    """
    # 1. 构建 category_name → id 映射
    categories = session.query(Category).filter(Category.is_active == True).all()
    cat_mapping = {cat.name: cat.id for cat in categories}

    print(f"已加载 {len(cat_mapping)} 个启用分类: {list(cat_mapping.keys())}")

    if "其他" not in cat_mapping:
        print("ERROR: 兜底分类'其他'不存在——请先执行 seed.py (Sprint 1)")
        return {"success": 0, "skipped_existing": 0, "skipped_no_category": 0}

    success = 0
    skipped_existing = 0
    skipped_no_category = 0

    for item in DEPARTMENT_SEED:
        name = item["name"]
        category_name = item["category_name"]
        synonyms = item.get("synonyms", [])

        # 1a. 校验 category_name
        if category_name not in cat_mapping:
            print(f"  [SKIP] 分类'{category_name}'不存在 → 科室'{name}'")
            skipped_no_category += 1
            continue

        # 2. 幂等检查
        existing = session.query(ExpertDepartment).filter_by(name=name).first()
        if existing:
            skipped_existing += 1
            continue

        # 3. 插入
        dept = ExpertDepartment(
            id=uuid.uuid4(),
            name=name,
            category_id=cat_mapping[category_name],
            synonyms=synonyms,
            is_active=True,
            is_verified=True,
            source="seed_s4",
        )
        session.add(dept)
        success += 1

    session.commit()
    return {
        "success": success,
        "skipped_existing": skipped_existing,
        "skipped_no_category": skipped_no_category,
    }
```

**需要确保的（6 个强制项）**：

1. ✅ **同步 Session**：使用 `session.query()`（同步模式，与 seed.py 一致），不使用 `await`
2. ✅ **幂等检查**：`filter_by(name=name).first()` → 存在则跳过（不覆盖 V4 的已有记录）
3. ✅ **UUID 生成**：`uuid.uuid4()` 在应用层生成（与 ExpertDepartment 模型一致）
4. ✅ **source 固定值**：`'seed_s4'`
5. ✅ **`commit()` 在整个循环之后**：一次性提交，不在循环内 commit
6. ✅ **"其他"缺失时提前报错**：不继续执行，避免所有 seed 都被 skipped_no_category
