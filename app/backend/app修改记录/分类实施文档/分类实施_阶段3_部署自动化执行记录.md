## 一、执行内容

### K7：部署自动化（entrypoint.sh + Dockerfile ENTRYPOINT）

| 文件 | 改动 |
|:---|:---|
| `entrypoint.sh`（新增） | 启动 5 步：① init_db 建表 → ② run_migrations 迁移 → ③ seed_categories() 函数级（仅 35 条分类，**不含专家/房间种子**）→ ④ seed_expert_departments（128 条）→ ⑤ audit 体检（异常仅告警不阻断）→ `exec "$@"` |
| `Dockerfile` | +COPY entrypoint.sh +ENTRYPOINT（CMD 保持 uvicorn，compose 零改动） |

**设计决策（阶段 3 确认）**：
- 只 seed 分类+科室，不跑全量 seed.py（避免生产库混入种子专家/直播间——专家为真实数据，部署后经 CSV 导入恢复）
- 建表/迁移/分类种子失败 → 容器退出（restart 重试，数据安全优先）
- audit 异常 → 告警继续启动（测试残留不阻断）

### M1：audit 部署后必跑 + Celery Beat 每周定时（决策 2-A）

| 文件 | 改动 |
|:---|:---|
| `app/tasks/audit_task.py`（新增） | `audit_weekly` 任务：调用 audit_category_integrity.main()，返回 `{exit_code, summary}`（日志 + 结果，决策 3-B 无外部告警通道） |
| `app/tasks/celery_app.py` | +beat_schedule：`category-audit-weekly`（每周日 03:00 UTC，crontab）；broker 沿用环境变量（未改变现有 worker 行为） |
| `compose-app.yml` | +celery_beat 容器（同镜像，`celery -A app.tasks.celery_app beat`，depends_on redis）；worker command 追加 `--include=app.tasks.audit_task` |

### M2：同步检查 Gate（决策 4-B 本地脚本）

| 文件 | 改动 |
|:---|:---|
| `scripts/check_consistency.py`（新增） | 逐条对照：① 35 条常量分类是否在库；② standard 一致性；③ 层级一致性（逐条 parent 匹配，不受测试分类干扰）；退出码 0/1 |

### CheckList 更新（方案文档 10.3）

- 纳入 K7 自动执行步骤 + 首次部署 `--baseline` 说明
- 新增"运营数据恢复"步骤：专家 CSV 批量导入（batch-import API 自动匹配归类）、直播间业务创建
- 新增 check_consistency Gate 验证步骤、celery_beat 确认步骤

## 四、⚠️ 注意事项（下次部署时）

1. **celery_beat 需 `docker-compose up -d celery_beat` 启动**（或整体 up -d 重建时自动创建）
2. **首次部署**（全新库）需先执行 `python scripts/run_migrations.py --baseline` 标记历史迁移，或确认 init_db 已建表后由 entrypoint 自动执行未应用迁移
3. **专家数据恢复**：部署后执行 CSV 导入（CheckList 第 6 步），匹配算法自动归类
4. 当前开发库**不重建容器**（避免打断并行开发）；K7 全链路验证在下次重建/线上部署时完成
