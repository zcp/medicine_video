### 3.2 核心匹配算法流程图

```
输入：自由文本科室名（如"心内科-冠脉介入组"）、可选的 category_id/name
  │
  ├─ 步骤 1：显式 category_id 或 category_name 传入？
  │   └─ YES → 验证分类存在且 is_active=true → 直接使用
  │   └─ NO  → 继续
  │
  ├─ 步骤 2：department_text 精确匹配 ExpertDepartment.name？
  │   └─ YES → 返回 (department_id, department.category_id)
  │   └─ NO  → 继续
  │
  ├─ 步骤 3：department_text 匹配 ExpertDepartment.synonyms[]？
  │   └─ YES → 返回 (department_id, department.category_id)
  │   └─ NO  → 继续
  │
  ├─ 步骤 4：启发式匹配 _match_broad_category()
  │   ├─ 4a：别名表精确匹配 — DEPARTMENT_CATEGORY_MAP 32 条规则
  │   │   （人工审核过的规则，优先级最高。修复前此步被子串匹配短路——见问题 5）
  │   └─ 4b：子串包含 — department_text 包含某个 ROOT_CATEGORIES？
  │       ⚠️ 固有限制："心脏大血管外科"→ 包含"血管外科"子串 → 错误归入血管外科
  │       （医学上"心脏大血管外科"是心胸外科范畴，需新增 MAP 条目解决，非优先级 bug）
  │
  ├─ 步骤 5：全部未命中 → 自动创建新科室
  │   └─ INSERT INTO expert_departments (name, category_id, is_verified=false)
  │   └─ category_id = 启发式结果或回退到"其他"
  │   └─ 并发冲突 → rollback + 重查已存在记录
  │
  └─ 最终兜底：resolved_category_id 仍为空？
      └─ YES → 查询 categories WHERE name='其他' AND is_active=true
          └─ 不存在 → 抛出 ValueError（seed.py 缺失时触发）
```

| 维度 | 详情 |

| **DDL 层** | V5 迁移已创建 `categories.parent_id` 列 + `uq_root_category_name` / `uq_sub_category_name` 部分唯一索引。**DDL 设计正确。** |

| 维度 | 详情 |

```python
# crud/content_management.py get_categories() 增加两个子查询
expert_count_subq = (
    select(func.count(Expert.id))
    .where(Expert.category_id == Category.id, Expert.is_active == True)
    .correlate(Category)
    .scalar_subquery()
    .label("expert_count")
)
room_count_subq = (
    select(func.count(LiveRoomCategory.room_id))
    .where(LiveRoomCategory.category_id == Category.id)
    .correlate(Category)
    .scalar_subquery()
    .label("room_count")
)
```
前端逻辑：
```typescript
const visibleTabs = categories.filter(
  c => c.expert_count > 0 || c.room_count > 0
);
```

## 附录 C：科室标准词库扩展实施方案

### C.1 方案原理

```
国标标准科室名（160 条）       平台现有 expert_departments 表

"心血管内科专业"      →       name: "心血管内科"

                                is_active: true
```

**不需要新增表、不需要改匹配算法。唯一做的就是往已有表中新增数据。**

### C.3 与 V4 迁移的关系

```
V4 迁移：32 条种子（V8 清理后 31 条有效），用于 DDL 创建 + 初始化
  ↓
S4 种子脚本：127 条标准科室，用 ON CONFLICT (name) DO NOTHING 跳过已存在
  ↓
结果：expert_departments 表同时保留 V4 的 31 条 + S4 新增的 127 条 = 158 条
```

**使用 Python 脚本而非 SQL 迁移的原因：**
- JSONB synonyms 在 Python 中天然可读（列表），SQL 中需要拼接 JSON 字符串
- UUID 由 Python 生成，跨环境可重现
- 可复用现有 CRUD 函数，自动处理冲突
