## 1. 角色定义 (Role Definition)

你是一名精通学院派（Clean Architecture）分层架构的 Python 后端架构师。你的核心任务是**消除权限守卫函数的重复定义**——当前 8 个 Service 文件中各自定义了自己的 `_check_admin_permission` / `_check_write_permission` 私有方法，它们逻辑相同但分散在各处。你需要将所有这些守卫函数集中到 `app/core/permissions.py` 中，各 Service 改为 import 调用。

**三个必须**：
- 必须保持函数签名和行为完全一致（不改变调用方的传参方式）
- 必须保持异常类型完全一致（`PermissionDeniedException`）
- 必须删除旧的私有方法定义（不留死代码）

```python
from typing import Optional
from uuid import UUID
from app.models.live_core import LiveRoom
from app.exceptions import PermissionDeniedException, NotFoundException


def check_room_owner_or_admin(room: LiveRoom, user_id: UUID, role: str) -> None:
    """写操作权限校验 → 403"""
    if role in ('ADMIN', 'SUPERADMIN'): return
    if room.user_id == user_id: return
    raise PermissionDeniedException("需要管理员或房间创建者权限")


def check_room_visibility(room: LiveRoom, user_id: Optional[UUID], role: Optional[str]) -> None:
    """读操作可见性校验 → 404伪装"""
    if not room.is_private: return
    if not user_id: raise NotFoundException("Room not found")
    if role in ('ADMIN', 'SUPERADMIN'): return
    if room.user_id == user_id: return
    raise NotFoundException("Room not found")
```

## 4. 架构约束 (Architecture Constraints)

### 4.1 守卫函数职责与签名

| 函数名 | 签名 | 入参条件 | 判定规则 | 异常 |
|:------|:-----|:---------|:--------|:----|
| `check_admin_permission` | `(role: Optional[str]) -> None` | role 必须为大写字符串 | `role not in ('ADMIN', 'SUPERADMIN')` → 403 | `PermissionDeniedException("需要管理员权限")` |
| `check_resource_owner_or_admin` | `(resource, user_id: UUID, role: str) -> None` | resource 必须有 `user_id` 属性 | Admin 放行；resource.user_id == user_id 放行；其余 403 | `PermissionDeniedException("权限不足，无权操作该资源")` |
| `check_authenticated_user` | `(role: Optional[str]) -> None` | role 必须为大写字符串 | `role not in ('REGULAR', 'ADMIN', 'SUPERADMIN')` → 403 | `PermissionDeniedException("需要登录")` |

### 4.2 分层铁律

- **权限守卫函数只能定义在 `permissions.py`**（唯一入口）
- Service 层不再定义任何 `_check_admin_permission` 或 `_check_write_permission` 私有方法
- 删除私有方法时，**必须将每个调用点从 `self._check_admin_permission(role)` 改为 `check_admin_permission(role)`**
- 所有使用 `_check_write_permission` 的地方改为 `check_authenticated_user`（语义更准确）

### 4.3 `live_features_service.py` 的特殊处理

该 Service 的 `_check_admin_permission` 是 async 且参数类型是 `LiveRoomMessageUserRole` Enum。需确认：
- 如果该方法的实际调用者已经传入了字符串 role（通过 `role=role_str`），则直接改用新的同步 `check_admin_permission`
- 如果调用者只传了 Enum 类型，需要改造调用方传字符串

**优先保留现状**：如果该函数被调用的行数和改动风险较大，可以保留该函数但注释标记"【P1-2】建议替换为 check_admin_permission"。

## 5. 代码生成要求 (Code Generation Requirements)

### 5.1 修改 `app/core/permissions.py` — 新增 3 个函数

在文件末尾（`check_room_visibility` 之后）追加：

```python
# ==================== P1-2 新增公共守卫函数 ====================


def check_admin_permission(role: Optional[str]) -> None:
    """通用管理员权限校验 → 403"""
    if role not in ('ADMIN', 'SUPERADMIN'):
        raise PermissionDeniedException("权限不足，需要管理员权限")


def check_resource_owner_or_admin(
    resource,
    user_id: UUID,
    role: str,
) -> None:
    """通用资源所有权校验（要求 resource 有 user_id 属性）→ 403"""
    if role in ('ADMIN', 'SUPERADMIN'):
        return
    if hasattr(resource, 'user_id') and resource.user_id == user_id:
        return
    raise PermissionDeniedException("权限不足，无权操作该资源")


def check_authenticated_user(role: Optional[str]) -> None:
    """仅检查是否已登录（非匿名）→ 403"""
    if role not in ('REGULAR', 'ADMIN', 'SUPERADMIN'):
        raise PermissionDeniedException("需要登录")
```

**注意**：
- `check_admin_permission` 不调用 `self.logger`（permissions.py 不是类，也不持有 logger）
- `check_resource_owner_or_admin` 使用 `hasattr(resource, 'user_id')` 做鸭子类型判断，兼容 LiveRoom、Topic 等不同模型
- `check_authenticated_user` 的异常消息为"需要登录"（与 content_management_service 原消息一致）
