# 环境变量配置迁移指南

## 📋 从公共 .env.docker 迁移到模块化配置

本指南帮助你从使用单个 `.env.docker` 文件迁移到模块化的环境变量配置。

---

## 🎯 目标配置结构

```
live-streaming-saas/
├── .env.shared              # 共享配置（数据库、JWT、Redis等）
├── .env.live_core           # live_core_service 特定配置
├── .env.user                # user_service 特定配置
├── .env.media_download      # media_download_service 特定配置
└── compose-app.yml          # 使用多个 env_file
```

---

## 📝 步骤 1：创建共享配置文件

创建 `.env.shared` 文件（从现有的 `.env.docker` 提取共享配置）：

```bash
# ============================================
# 共享配置 - 所有服务共用
# ============================================

# 环境标识
ENVIRONMENT=development

# 数据库配置（所有服务共享）
POSTGRES_SERVER=localhost
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_secure_password_here

# JWT 配置（live_core 和 user 服务共享）
JWT_SECRET_KEY=your_jwt_secret_key_here_min_32_chars
JWT_ALGORITHM=HS256

# CORS 配置（live_core 和 user 服务共享）
CORS_ORIGINS=*

# Celery 配置（live_core 和 media_download 服务共享）
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0

# 通用配置
DEBUG=true
```

---

## 📝 步骤 2：创建服务特定配置文件

### 2.1 创建 `.env.live_core`

```bash
# ============================================
# Live Core Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=live_core_test

# 应用特定配置
ROOM_MEDIA_ROOT_PATH=/app/media
UPLOAD_MAX_SIZE=10485760
UPLOAD_ALLOWED_EXTENSIONS=jpg,jpeg,png,gif
PLAYBACK_BASE_URL=http://localhost:8000
```

### 2.2 创建 `.env.user`

```bash
# ============================================
# User Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=users_service_test

# 用户服务特定配置
VITE_CLIENT_ID=your_client_id
USER_POOL_SECRET=your_user_pool_secret
APP_HOST=https://yourdomain.com
REDIRECT_URL=https://yourdomain.com/callback
ISSUER=https://yourdomain.com
```

### 2.3 创建 `.env.media_download`

```bash
# ============================================
# Media Download Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=media_download_test

# 下载服务特定配置
DOWNLOAD_DIR=/app/storage
VZAN_USERNAME=your_username
VZAN_PASSWORD=your_password
VZAN_TOKEN=your_token
VZAN_COOKIE=your_cookie
CRAWLER_TIMEOUT=10
CRAWLER_TEMP_DIR=/tmp/vzan_crawler
```

## 📝 步骤 3：修改 compose-app.yml

将 `compose-app.yml` 中的 `env_file` 配置修改为：

```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    restart: unless-stopped
    ports: ["8000:8000"]
    environment:
      POSTGRES_DB: "live_core_test"
      ROOM_MEDIA_ROOT_PATH: "/app/media"
    env_file:
      - .env.shared           # 共享配置
      - .env.live_core        # 服务特定配置
    volumes:
      - /var/www/html/live-core-media:/app/media
    depends_on: []
    networks:
      - live-network

  media_download_service:
    build: ./backend/media_download_service
    restart: unless-stopped
    ports: ["8001:8001"]
    environment:
      POSTGRES_DB: "media_download_test"
    env_file:
      - .env.shared
      - .env.media_download
    volumes:
      - media_download:/media_download/storage
    networks:
      - live-network

  user_service:
    build: ./backend/users
    restart: unless-stopped
    ports: ["8002:8002"]
    environment:
      POSTGRES_DB: "users_service_test"
    env_file:
      - .env.shared
      - .env.user
    networks:
      - live-network

  celery_worker:
    build: ./backend/live_core_service
    restart: unless-stopped
    env_file:
      - .env.shared
      - .env.live_core  # 与 live_core_service 相同
    command: celery -A app.tasks.celery_app worker --include=app.tasks.session_processing -l info -c 10
    networks:
      - live-network

  postgres:
    image: postgres:15-alpine
    restart: unless-stopped
    ports: ["5432:5432"]
    env_file:
      - .env.shared  # 只需要共享配置
    volumes:
      - ./init-db.sh:/docker-entrypoint-initdb.d/init-db.sh:ro
      - pgdata:/var/lib/postgresql/data
    networks:
      - live-network
```

## 📝 步骤 4：更新 .gitignore

确保 `.gitignore` 包含所有 `.env*` 文件（除了 `.example` 文件）：

```gitignore
# 环境变量文件
.env*
!.env*.example
```

## ✅ 验证步骤

1. **创建配置文件**：
   ```bash
   # 从现有 .env.docker 提取配置
   cp .env.docker .env.shared
   # 然后手动分离到各个服务配置文件
   ```

2. **测试启动**：
   ```bash
   docker-compose -f compose-app.yml up -d
   ```

3. **验证服务**：
   ```bash
   # 检查服务是否正常启动
   docker-compose -f compose-app.yml ps
   
   # 查看日志
   docker-compose -f compose-app.yml logs live_core_service
   docker-compose -f compose-app.yml logs user_service
   docker-compose -f compose-app.yml logs media_download_service
   ```

4. **验证环境变量**：
   ```bash
   # 进入容器检查环境变量
   docker-compose -f compose-app.yml exec live_core_service env | grep POSTGRES
   docker-compose -f compose-app.yml exec live_core_service env | grep ROOM_MEDIA
   ```

## ⚠️ 注意事项

### 1. 环境变量优先级

Docker Compose 中环境变量的加载顺序（后加载的覆盖先加载的）：

```yaml
env_file:
  - .env.shared      # 先加载
  - .env.live_core   # 后加载，会覆盖 .env.shared 中的同名变量
```

### 2. 配置同步

- 修改共享配置（如数据库密码）时，所有使用 `.env.shared` 的服务都会自动更新
- 修改服务特定配置时，只影响对应的服务

### 3. 向后兼容

如果需要保持向后兼容，可以：
- 保留 `.env.docker` 文件（作为备份）
- 逐步迁移，先迁移一个服务，验证后再迁移其他服务

## 📊 配置对比

### 迁移前（单个 .env.docker）

```yaml
services:
  live_core_service:
    env_file: .env.docker  # 所有配置混在一起
  user_service:
    env_file: .env.docker  # 所有配置混在一起
```

**问题**：
- ❌ 所有服务配置混在一起
- ❌ 难以区分哪些配置属于哪个服务
- ❌ 修改一个服务的配置可能影响其他服务

### 迁移后（模块化配置）

```yaml
services:
  live_core_service:
    env_file:
      - .env.shared      # 共享配置
      - .env.live_core   # 服务特定配置
  user_service:
    env_file:
      - .env.shared
      - .env.user
```

**优势**：
- ✅ 配置清晰分离
- ✅ 易于维护和管理
- ✅ 符合微服务架构理念
- ✅ 团队可以独立管理自己的配置

---

## 🎯 总结

**推荐使用模块化配置方案**，因为：

1. ✅ **模块化**：每个服务配置独立，符合微服务架构
2. ✅ **安全性**：敏感信息分散，降低风险
3. ✅ **可维护性**：配置清晰，易于查找和管理
4. ✅ **团队协作**：不同团队可以独立管理自己的配置
5. ✅ **灵活性**：可以为不同服务设置不同值

**实施建议**：
- 先创建配置文件并测试一个服务
- 验证无误后再迁移其他服务
- 保留 `.env.docker` 作为备份，直到所有服务迁移完成
