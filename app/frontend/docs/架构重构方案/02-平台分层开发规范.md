## 核心理念

### 设计原则

1. **通用优先**：能跨平台共用的代码放在 `common/`
2. **按需分层**：只有差异大于30%时才创建平台专属版本
3. **条件编译补充**：小差异用条件编译，大差异用分层
4. **职责清晰**：每个组件只负责一个平台或通用逻辑

### 关键概念

| 概念 | 说明 | 示例 |
|------|------|------|
| **通用组件** | 跨平台无差异 | 按钮、卡片、文本 |
| **平台组件** | 特定平台实现 | H5播放器、App播放器 |
| **条件编译** | 代码内差异处理 | `#ifdef H5` |
| **分层架构** | 目录级差异处理 | `components/h5/` vs `components/app/` |

### 完整目录结构

```
src/
├── components/
│   ├── common/              # ✅ 通用组件（H5/App/MP共用）
│   │   ├── AppButton.vue
│   │   ├── RoomCard.vue
│   │   ├── ModalDialog.vue
│   │   └── UserInfoHeader.vue
│   ├── h5/                  # ✅ H5专属组件
│   │   ├── VideoPlayerH5.vue
│   │   ├── ImageUploaderH5.vue
│   │   └── MapViewH5.vue
│   ├── app/                 # ✅ App专属组件
│   │   ├── VideoPlayerApp.vue
│   │   ├── ImageUploaderApp.vue
│   │   └── MapViewApp.vue
│   └── mp/                  # ✅ 小程序专属组件（可选）
│       └── VideoPlayerMP.vue
├── utils/
│   ├── platform.ts          # ✅ 平台工具（新增）
│   ├── security.ts          # ✅ 通用工具
│   └── request.ts           # ✅ 通用工具
├── pages/                   # ✅ 页面统一，内部用条件编译
│   ├── room/
│   │   ├── RoomList.vue
│   │   └── RoomDetail.vue
│   └── live/
│       └── LiveView.vue

    └── auth.ts
```

### 目录职责说明

| 目录 | 职责 | 何时使用 |
|------|------|---------|
| `components/common/` | 跨平台通用组件 | 组件无平台差异 |
| `components/h5/` | H5专属组件 | H5特有实现（如hls.js） |
| `components/app/` | App专属组件 | App特有实现（如原生video） |
| `components/mp/` | 小程序专属组件 | 小程序特有实现（可选） |
| `pages/` | 页面文件 | 统一存放，内部用条件编译 |
| `utils/` | 工具函数 | 通用工具，必要时可分层 |

## 组件分层决策

### 决策流程图

```
创建新组件
    ↓
是否有平台差异？
├─ 否 → ✅ 创建到 components/common/
│        例如：AppButton.vue, RoomCard.vue
│
└─ 是 → 差异有多大？
    ├─ < 10行代码 → ✅ 创建通用组件 + 条件编译
    │                例如：跳转方式、样式微调
    │
    ├─ 10-50行代码 → ⚠️ 评估：条件编译 or 分层
    │                考虑可维护性和代码可读性
    │
    └─ > 50行代码 → ✅ 创建平台专属组件
                     例如：VideoPlayerH5.vue + VideoPlayerApp.vue
```

### 实际示例决策

#### ✅ 示例1：通用组件（无需分层）

**组件**：`AppButton.vue` - 按钮组件  
**差异**：无差异  
**决策**：放在 `components/common/`

```vue
<!-- components/common/AppButton.vue -->
<template>
  <button :class="buttonClass" @click="onClick">
    <slot></slot>
  </button>
</template>

<script setup lang="ts">
// 完全通用，无平台差异
</script>
```

#### ✅ 示例2：条件编译（小差异）

**组件**：`NavigationBar.vue` - 导航栏  
**差异**：状态栏高度不同（< 10行）  
**决策**：通用组件 + 条件编译

```vue
<!-- components/common/NavigationBar.vue -->
<template>
  <view class="nav-bar" :style="{ paddingTop: statusBarHeight + 'px' }">
    <slot></slot>
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'

const statusBarHeight = ref(0)

// #ifdef H5
statusBarHeight.value = 0  // H5不需要状态栏高度
// #endif

// #ifdef APP-PLUS
const systemInfo = uni.getSystemInfoSync()
statusBarHeight.value = systemInfo.statusBarHeight || 0
// #endif
</script>
```

#### ✅ 示例3：平台分层（大差异）

**组件**：`VideoPlayer` - 视频播放器  
**差异**：H5用hls.js（100+行），App用原生video（50+行）  
**决策**：创建平台专属版本

```
components/
├── h5/
│   └── VideoPlayerH5.vue    # 基于hls.js实现
└── app/
    └── VideoPlayerApp.vue   # 基于原生video实现
```

## 命名规范

### 文件命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 通用组件 | PascalCase.vue | `AppButton.vue`, `RoomCard.vue` |
| H5组件 | PascalCase + H5.vue | `VideoPlayerH5.vue` |
| App组件 | PascalCase + App.vue | `VideoPlayerApp.vue` |
| 小程序组件 | PascalCase + MP.vue | `VideoPlayerMP.vue` |

### 组件命名

```typescript
// ✅ 推荐命名
components/common/AppButton.vue       // 通用按钮
components/h5/VideoPlayerH5.vue       // H5播放器
components/app/VideoPlayerApp.vue     // App播放器

// ❌ 不推荐命名
components/h5/VideoPlayer.vue         // 缺少H5后缀，容易混淆
components/app/AppVideoPlayer.vue     // 冗余前缀
```

## 代码示例

### 示例1：页面中使用平台组件

```vue
<!-- pages/live/LiveView.vue -->
<template>
  <view class="live-view">
    <!-- ✅ 通用头部组件 -->
    <NavigationBar>
      <text>{{ roomInfo.title }}</text>
    </NavigationBar>
    
    <!-- ✅ 平台差异化播放器 -->
    <!-- #ifdef H5 -->
    <VideoPlayerH5 :src="streamUrl" :poster="coverUrl" @play="onPlay" />
    <!-- #endif -->
    
    <!-- #ifdef APP-PLUS -->
    <VideoPlayerApp :src="streamUrl" :poster="coverUrl" @play="onPlay" />
    <!-- #endif -->
    
    <!-- ✅ 通用评论区 -->
    <CommentList :comments="comments" />
  </view>
</template>

<script setup lang="ts">
import { ref } from 'vue'
import NavigationBar from '@/components/common/NavigationBar.vue'
import CommentList from '@/components/common/CommentList.vue'

// #ifdef H5
import VideoPlayerH5 from '@/components/h5/VideoPlayerH5.vue'
// #endif

// #ifdef APP-PLUS
import VideoPlayerApp from '@/components/app/VideoPlayerApp.vue'
// #endif

const streamUrl = ref('https://example.com/stream.m3u8')
const onPlay = () => {
  console.log('播放开始')
}
</script>
```

### 示例4：API层平台适配

```typescript
// api/live.ts
import { getPlatform, PlatformType } from '@/utils/platform'
import { get, post } from '@/utils/request'

/**
 * 获取直播流配置
 * 不同平台返回不同的流地址
 */
export const getLiveStreamConfig = (roomId: string) => {
  const platform = getPlatform()
  
  return get<{ url: string; type: string }>('/live/stream/config', {
    roomId,
    platform  // 告诉后端当前平台
  })
}

/**
 * 获取播放器配置
 * 根据平台返回不同配置
 */
export const getPlayerConfig = () => {
  const platform = getPlatform()
  
  if (platform === PlatformType.H5) {
    return {
      type: 'hls.js',
      options: {
        enableWorker: true,
        lowLatencyMode: true
      }
    }
  } else if (platform === PlatformType.APP) {
    return {
      type: 'native',
      options: {
        controls: true,
        autoplay: false
      }
    }
  }
  
  return {
    type: 'default',
    options: {}
  }
}
```

## 最佳实践

### ✅ 推荐做法

#### 1. **通用优先原则**

```typescript
// ✅ 好：先尝试通用实现
components/common/ImageUploader.vue  // 通用上传组件

// 只有在差异太大时才分层
components/h5/ImageUploaderH5.vue    // H5特殊需求
components/app/ImageUploaderApp.vue  // App特殊需求
```

#### 2. **条件编译 + 分层结合**

```vue
<!-- ✅ 好：小差异用条件编译，大差异用分层 -->
<template>
  <view>
    <!-- 小差异：样式调整 -->
    <view :class="platformClass">
      通用内容
    </view>
    
    <!-- 大差异：组件级差异 -->
    <!-- #ifdef H5 -->
    <VideoPlayerH5 />
    <!-- #endif -->
    <!-- #ifdef APP-PLUS -->
    <VideoPlayerApp />
    <!-- #endif -->
  </view>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import { isH5 } from '@/utils/platform'

// 小差异：样式类
const platformClass = computed(() => isH5() ? 'h5-style' : 'app-style')
</script>
```

#### 3. **统一导入入口**

```typescript
// utils/components.ts - 统一导出平台组件
import { getPlatform, PlatformType } from './platform'

export const VideoPlayer = (() => {
  const platform = getPlatform()
  
  switch (platform) {
    case PlatformType.H5:
      return require('@/components/h5/VideoPlayerH5.vue').default
    case PlatformType.APP:
      return require('@/components/app/VideoPlayerApp.vue').default
    default:
      return require('@/components/common/VideoPlayer.vue').default
  }
})()

// 使用时
import { VideoPlayer } from '@/utils/components'
```

### ❌ 避免的做法

#### 1. **过度分层**

```typescript
// ❌ 差：按钮这种通用组件不应该分层
components/h5/AppButtonH5.vue
components/app/AppButtonApp.vue

// ✅ 好：统一放在 common/
components/common/AppButton.vue
```

#### 2. **分层不彻底**

```vue
<!-- ❌ 差：已经分层了还用条件编译 -->
<!-- components/h5/VideoPlayerH5.vue -->
<template>
  <view>
    <!-- #ifdef H5 -->
    <div>H5播放器</div>
    <!-- #endif -->
  </view>
</template>

<!-- ✅ 好：既然是H5专属文件，就不需要条件编译 -->
<!-- components/h5/VideoPlayerH5.vue -->
<template>
  <div>H5播放器</div>
</template>
```

#### 3. **重复代码**

```typescript
// ❌ 差：两个组件有大量重复代码
// components/h5/VideoPlayerH5.vue - 200行
// components/app/VideoPlayerApp.vue - 200行
// 重复代码占80%

// ✅ 好：提取通用逻辑
// components/common/VideoPlayerBase.vue - 通用逻辑（160行）
// components/h5/VideoPlayerH5.vue - 继承Base + H5特殊（40行）
// components/app/VideoPlayerApp.vue - 继承Base + App特殊（40行）
```

## 常见问题

### Q1：如何判断差异是"大"还是"小"？

**A：使用以下量化标准**

| 差异大小 | 代码行数 | 处理方式 |
|---------|---------|---------|
| 微小 | < 5行 | ✅ 条件编译 |
| 小 | 5-20行 | ✅ 条件编译 |
| 中等 | 20-50行 | ⚠️ 评估：条件编译 or 分层 |
| 大 | > 50行 | ✅ 分层架构 |
| 巨大 | > 100行 | ✅✅ 必须分层 |

### Q2：页面文件需要分层吗？

**A：通常不需要**

页面文件统一放在 `pages/` 目录，内部使用条件编译或引入平台组件：

```
✅ 推荐：
pages/live/LiveView.vue  （内部用条件编译加载H5/App组件）

❌ 不推荐：
pages/h5/live/LiveView.vue
pages/app/live/LiveView.vue
```

### Q3：工具函数需要分层吗？

**A：只有在平台差异巨大时才分层**

```
✅ 大部分情况：通用工具
utils/security.ts
utils/request.ts

⚠️ 特殊情况：平台工具
utils/platform.ts
utils/h5/hlsPlayer.ts    （H5专属：hls.js封装）
utils/app/nativePlayer.ts （App专属：原生播放器封装）
```

### Q4：如何迁移现有组件到分层架构？

**A：分步迁移**

```bash
# 步骤1：识别差异组件
grep -r "#ifdef" src/components/

# 步骤2：评估差异大小
# 如果 #ifdef 块 > 50行，考虑分层

# 步骤3：创建平台组件
mv src/components/VideoPlayer.vue src/components/h5/VideoPlayerH5.vue
cp src/components/h5/VideoPlayerH5.vue src/components/app/VideoPlayerApp.vue

# 步骤4：重构App版本
# 修改 VideoPlayerApp.vue，移除H5特有代码

# 步骤5：更新引用
# 在页面中更新导入路径
```

### Q5：阶段零的代码需要调整吗？

**A：完全不需要**

阶段零的工具模块（logs/, utils/security.ts, common/constants.ts）都是平台无关的，无需任何调整。

### Q6：现有的条件编译会冲突吗？

**A：完全不会**

条件编译和分层架构是互补关系：
- **小差异**：继续用条件编译（如路由跳转、样式微调）
- **大差异**：新增分层架构（如播放器组件）

## 📝 检查清单

### 新增组件时的检查清单

- [ ] 判断是否有平台差异
- [ ] 评估差异大小（< 30% or > 30%）
- [ ] 选择合适的处理方式（条件编译 or 分层）
- [ ] 遵循命名规范（通用组件无后缀，平台组件加后缀）
- [ ] 添加完整的 JSDoc 注释
- [ ] 测试多平台兼容性

### 迁移现有组件时的检查清单

- [ ] 备份原代码（git commit）
- [ ] 分析条件编译块的行数
- [ ] 决定保留条件编译还是改为分层
- [ ] 创建新的目录结构
- [ ] 更新所有引用路径
- [ ] 测试功能正常
- [ ] 提交代码（清晰的 commit message）
