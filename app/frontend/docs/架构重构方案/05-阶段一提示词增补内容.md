```markdown
### 4.9 平台分层架构约束

#### 4.9.1 组件分层决策规则

**在生成任何组件之前，必须先判断是否需要分层**

\`\`\`
创建新组件/工具/类型
    ↓
是否有平台差异？
├─ 否 → ✅ 放在通用目录
│        components/common/
│        utils/
│        types/
│
└─ 是 → 差异有多大？
    ├─ < 30% → ✅ 通用实现 + 条件编译
    │           \`#ifdef H5\` \`#ifdef APP-PLUS\`
    │
    └─ > 30% → ✅ 创建平台专属版本
                components/h5/XXH5.vue
                components/app/XXApp.vue
\`\`\`

#### 4.9.2 API层平台适配规则

**所有API函数必须考虑平台差异**

❌ **错误示例**（未考虑平台）：

\`\`\`typescript
// api/live.ts
export const getLiveStreamUrl = (roomId: string) => {
  return get<{ url: string }>('/live/stream', { roomId })
  // ❌ 问题：H5和App可能需要不同的流地址
}
\`\`\`

✅ **正确示例**（考虑平台）：

\`\`\`typescript
// api/live.ts
import { getPlatform } from '@/utils/platform'

export const getLiveStreamUrl = (roomId: string) => {
  const platform = getPlatform()
  
  return get<{ url: string; type: string }>('/live/stream', { 
    roomId,
    platform  // ✅ 告诉后端当前平台，获取适配的流地址
  })
}
\`\`\`

#### 4.9.3 类型定义平台适配

**通用类型**：放在 `types/` 目录

\`\`\`typescript
// types/common.ts, types/room.ts, types/session.ts
// ✅ 这些是数据结构类型，与平台无关
export interface Room { ... }
export interface Session { ... }
\`\`\`

**平台特定类型**：根据需要分层

\`\`\`typescript
// types/player.ts - 如果H5和App的播放器配置差异大
export interface H5PlayerConfig { ... }
export interface AppPlayerConfig { ... }

export type PlayerConfig = H5PlayerConfig | AppPlayerConfig
\`\`\`

#### 4.9.4 工具函数分层规则

**通用工具**：放在 `utils/` 目录

\`\`\`typescript
// utils/security.ts - ✅ 脱敏逻辑与平台无关
// utils/request.ts - ✅ 网络请求封装（底层用uni.request）
// utils/storage.ts - ✅ 存储封装（底层用uni.getStorage）
\`\`\`

**平台特定工具**：可选分层

\`\`\`typescript
// 如果平台差异巨大，可以分层
utils/
├── platform.ts          # ✅ 平台检测工具（通用）
├── h5/
│   └── hlsPlayer.ts     # H5专属：hls.js 封装
└── app/
    └── nativePlayer.ts  # App专属：原生播放器封装
\`\`\`

#### 4.9.5 禁止事项

❌ **禁止1**：在通用文件中硬编码平台逻辑

\`\`\`typescript
// ❌ 错误：在通用类型文件中使用条件编译
// types/room.ts
export interface Room {
  id: string
  // #ifdef H5
  h5SpecificField: string  // ❌ 不应该在类型定义中区分平台
  // #endif
}

// ✅ 正确：使用可选字段或联合类型
export interface Room {
  id: string
  platformSpecificData?: Record<string, any>  // ✅ 通用方式
}
\`\`\`

❌ **禁止2**：在平台专属文件中使用条件编译

\`\`\`typescript
// ❌ 错误：h5/ 目录下的文件不应该有条件编译
// components/h5/VideoPlayerH5.vue
<template>
  <!-- #ifdef H5 -->
  <div>H5播放器</div>
  <!-- #endif -->
</template>

// ✅ 正确：h5/ 目录下的文件天然就是H5环境
// components/h5/VideoPlayerH5.vue
<template>
  <div>H5播放器</div>
</template>
\`\`\`

❌ **禁止3**：过度分层

\`\`\`typescript
// ❌ 错误：简单组件不应该分层
components/h5/AppButtonH5.vue
components/app/AppButtonApp.vue

// ✅ 正确：按钮是通用组件
components/common/AppButton.vue
\`\`\`
```

```markdown
### 步骤1：生成通用类型定义（P0 - 最高优先级）

**📁 文件：\`src/types/common.ts\`**

**⚠️ 平台分层检查（新增）**

在生成类型定义前，必须判断类型是否需要平台差异化：

\`\`\`
类型定义是否有平台差异？
├─ 否 → ✅ 放在 types/ 目录（通用类型）
│        例如：ApiResponse, PaginatedResponse, Room, Session
│
└─ 是 → 评估差异程度
    ├─ 小差异 → ✅ 使用联合类型或可选字段
    │            例如：platformData?: H5Data | AppData
    │
    └─ 大差异 → ✅ 分别定义
                 例如：H5PlayerConfig, AppPlayerConfig
\`\`\`

**类型定义原则**：

1. **数据结构类型**（通用）
   - Room, Session, Brand, Expert等业务数据
   - ApiResponse, PaginatedResponse等响应结构
   - ✅ 这些类型放在 \`types/\` 目录

2. **配置类型**（可能需要分层）
   - PlayerConfig, UploadConfig等
   - 如果H5和App差异 > 30%，使用联合类型或分别定义

3. **平台特定类型**（分层）
   - H5VideoElement, AppNativePlayer等
   - ✅ 放在 \`types/h5/\` 或 \`types/app/\` 目录

**验证点**（新增）：

- [ ] 所有类型定义是否都是平台无关的？
- [ ] 如有平台特定字段，是否使用了可选字段 \`?\` 或联合类型？
- [ ] 是否避免了在通用类型中使用条件编译？
```

```markdown
// utils/h5/hlsPlayer.ts
import Hls from 'hls.js'

export class HlsPlayerManager {
  private hls: Hls | null = null
  
  init(video: HTMLVideoElement, url: string) {
    if (Hls.isSupported()) {
      this.hls = new Hls()
      this.hls.loadSource(url)
      this.hls.attachMedia(video)
    }
  }
  
  destroy() {
    if (this.hls) {
      this.hls.destroy()
      this.hls = null
    }
  }
}
\`\`\`
```
