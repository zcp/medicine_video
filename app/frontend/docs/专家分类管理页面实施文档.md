## 四、数据流

### 列表加载

```
loadDepartments(refresh)
  ├─ refresh=true → page=1, departments=[]
  ├─ params: { show_all:true, page, size=20, q?←搜索 }
  ├─ getDepartments(params)
  ├─ res.data.items → departments (refresh? 替换 : 追加)
  └─ res.data.total → total → hasMore = page*size < total
```

### 搜索

```
searchKeyword (watch, 300ms防抖) → loadDepartments(true)
变化 → 重置分页 → 重新请求
```

### 树/平铺双模式（前端分组，无额外 API 请求）

```
groupedDepartments (computed)
  ├─ searchKeyword 为空 → 树模式: 按 category_name 分组
  │     key = dept.category_id, name = dept.category_name
  │     分类行显示: expandState[catId] !== false 展开/折叠
  │     分类等级专家数 = reduce(dept.expert_count)
  └─ searchKeyword 有值 → 平铺模式: 直接渲染 departments
       卡片 inline 显示 category_name 标签
```

### CRUD 操作后

```
创建科室/编辑科室: loadDepartments(true) — 全量刷新
删除科室: departments.value = departments.filter(...) — 本地移除
审核科室: dept.is_verified = true — 就地更新
合并科室: loadDepartments(true) — 全量刷新
批量审核: exitSelectMode() + loadDepartments(true)
创建根分类: closeCatForm() + loadCategories() — 分类表刷新
编辑根分类: closeCatForm() + loadCategories() — 分类表刷新 + 科室列表刷新（category_name 变更）
```

### 状态覆盖

```
首次加载: isLoading && departments.length===0 → 4 张骨架卡片
加载失败: error && departments.length===0   → ⚠️ + 错误消息 + [重试]
空数据:   !isLoading && departments.length===0 → 📂 + 差异化文案
已加载:   departments.length>0                 → 正常列表
```

## 八点一、树/平铺双模式详解（v1.1 新增）

### 设计动机

原始布局将根分类（4 个）作为下拉筛选器、科室平铺，导致：
- 根分类不可见、不可操作、与科室是割裂的
- "全部分类/待审核" 两个 Tab 与搜索、分类筛选共 4 个 OR 条件，操作繁琐
- 科室与分类的关系需要跨 UI 控件才能感知

### 树模式（搜索为空时）

```
expandState[catId] !== false → 展开显示该分类下所有科室
expandState[catId] === false → 折叠隐藏科室，仅显示分类行
```

- 分类行：▼/▶ 箭头 + 名称 + 专家数 + [编辑分类]
- 科室卡片：缩进 0，在分类行下排列
- 每组分隔：`[＋ 新增科室]` 虚线按钮
- 默认所有分类展开

### 平铺模式（搜索有文本时）

- 科室卡片直排，不分组
- 每张卡片左上角 inline 显示 `category_name` 标签
- 与原始布局兼容，搜索体验不变

### 下拉刷新 / loadMore

- 刷新：`loadDepartments(true)` → page=1，展开状态保留
- loadMore：`page++`，新数据追加到 `departments`，`groupedDepartments` computed 自动重新分组

## 八点二、`expert_count = 0` 问题 — 成因与修复

### 成因（链路分析）

```
CRUD 层:  d.expert_count = 26  ✅ 动态赋值成功
          ↓
Pydantic: model_validate(d)   ❌ 不加 from_attributes=True 时不读非 Column 的动态属性
          ↓ 读取的是 class 默认值 expert_count = 0
前端:     expert_count: 0      ❌
```

### 修复

**后端**（Pydantic Schema）:

```python
# 修复前
return DepartmentResponse.model_validate(d)

# 修复后
return DepartmentResponse.model_validate(d, from_attributes=True)
```

显式走属性模式读取 `getattr(d, 'expert_count')`，返回真实值。

**前端**：无需任何修改。类型声明、模板渲染、删除警告全部使用同一字段 `expert_count`，后端修好后直接生效。

### 验证

容器日志中应有：
```
expert_count 批量查询: dept_ids=50, count_map={'d53ef4b7': 26, '3e1bcbfe': 18, ...}
```

## 八、已知限制

| 限制 | 影响 | 后续计划 |
|------|------|------|
| 合并目标只能选当前页科室 | 目标科室在第二页时无法合并 | 可改为搜索式下拉，跨页查找 |
| `loadMore` 失败后 page 不降回 | 极低频，失败后下拉刷新即重置 | 后续加 `finally` 中 page-- |
| 搜索防抖 timer 未在组件销毁时清理 | 销毁后可能触发一次无效请求 | 后续加 `onUnmounted` 清理 |
| 根分类无 `expert_count` 直接字段 | 分类行专家数来自科室 `expert_count` 求和，正确但需后端真实值 | ✅ 后端已修复（Pydantic `from_attributes=True`） |

### 已修复的问题

| 问题 | 修复日期 | 修复方式 |
|------|---------|---------|
| `scroll-view` 高度硬编码 `380rpx` 导致分类行遮挡 | 2026-07-28 | 改为 `260rpx` |
| Tab 栏与顶栏重复（"全部分类"/"待审核"） | 2026-07-28 | 移除 Tab 栏，搜索为空时树模式按分类折叠 |
| 分类下拉筛选占用筛选栏空间 | 2026-07-28 | 移除分类下拉，分类信息作为行标题自然展示 |

| 卡片展开详情冗余（创建时间 + 关联专家） | 2026-07-28 | 移除展开功能，简化交互 |
| `expert_count` 始终为 0 | 2026-07-28 | **后端**: Pydantic `from_attributes=True`；**前端**: 无需改动 |
