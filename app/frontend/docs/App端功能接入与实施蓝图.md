# App 端功能接入与实施蓝图（实施后效果评估）

> **文档版本**：v1.0
> **创建日期**：2026-08-09
> **前置文档**：`App端与小程序端全量对比分析报告-终版.md`（v2.0，31 项冲突）、`小程序端管理功能接入App端实现方案设计文档.md`（接入方案）、`小程序端与App端管理端页面对比报告.md`
> **分析原则**：每个功能点先评估「是否适合 App 端实现、是否合理」——**不盲目照搬小程序**；App 端工程范式（守卫/ModalDialog/useSwiperTabs/无限滚动）为基线，小程序作为功能参考源
> **状态**：实施蓝图

## 〇、实施原则（先立规矩，再列功能）

| 原则 | 说明 |
|------|------|
| **范式保持 App** | 所有新页面按 App 现有范式：`useAdminGuard` + `ModalDialog` + `useSwiperTabs` + 无限滚动 + 骨架三态 |
| **功能借鉴 MP** | 小程序的价值在功能（内容安全/品牌成员/留言归一化/3D 焦点图/认证），App 的价值在架构——单向参考，不复制文件 |
| **契约以 MP 为准** | 小程序端是后端最近联调方（注释自证对齐最新 OpenAPI），契约冲突以 MP 为基准，App 修正 |
| **先修内部 bug** | App 端有 5 个可立即修复的内部缺陷（`?redirect=` 断链/PUT/PATCH/孤儿页/room-tabs 入口/生产 Mock），不依赖任何人 |
| **产品决策前置** | 品牌成员/商品、H5 直播创建归属、分类双体系——确认前不动作 |

## 二、每项功能的「当前实现 vs 接入后变化」明细

### 2.1 直播间留言板（P0，最高优先）

**当前实现**：`LiveView.vue` 的聊天/问答/推荐由 `LIVEVIEW_API_MODE.useMockData.chat=true` 控制（LiveView.vue:680），消息仅本地 push，页面显示"演示模式"提示条（LiveView.vue:227）。

**接入后**：
- 聊天 Tab 接真实 `/messages` 公开接口（`api/message.ts` 已有 `getRoomMessages`/`sendRoomMessage` 封装）
- 迁移 MP `roomMessageNormalize` 昵称归一化（user 快照 → 回退 → D3 `账号已注销` 占位）
- 长按留言删除/复制 + `我`标识（MP `MessageItem.vue`）
- 内容安全文案映射（2004/2005 人话化）

**为什么**：核心直播互动功能 mock 上线 = 假象；后端已融合，接口已就绪，纯前端工作量。

**缺陷修正**：无（新功能接入）。

### 2.2 首页焦点图 3D（P1）

**当前实现**：`FeaturedCarousel.vue` 平面 swiper，露边 56rpx，无 3D 缩放/变暗；autoplay 常开无触摸暂停；单横幅恒 circular；跳转仅 room/session/topic(H5 外跳过)/external。

**接入后**：
- 移植 MP `Banner3D` 的 `getCardClass` 缩放（center scale(1) + 侧卡 scale(0.85)/opacity(0.65)/brightness(0.82)/z-index）
- 触摸暂停 + 松手 8s 恢复
- 侧卡点击先居中再导航
- 单横幅禁用 circular
- `handleCampaignClick` 补 expert/brand 分支；`featured/index.vue` 表单补 expert/brand/session 目标类型

**为什么**：主流 OTT cover-flow 视觉；**保留 App 差异化**（预告混排 + CTA + swiperKey Android 兼容）。

**缺陷修正**：修复「管理 UI 造不出运行时能跳的 banner」不自洽。

### 2.3 管理端三模块 + 留言单删（P2/P3）

**当前实现**：App 无内容安全/品牌成员/品牌商品；留言页仅批量删除 + 清空房间。

**接入后**：
- 内容安全：规则+日志双 Tab（App 范式，非 MP 三页）+ `groupContentSafetyRules` 分组算法 + 2004/2005 映射
- 品牌成员/商品：新页 + 复用 `getAdminUsers` + brand-commerce 类型
- 留言单删：`api/message.ts` 补 `deleteMessage` + 页内单条操作

**为什么**：管理能力对齐；内容安全为合规必需。

**缺陷修正**：留言单删缺失。

### 2.4 认证补齐（P1）

**当前实现**：login 三 Tab（oneTap/密码/手机验证码）；account-security 邮箱换绑为死链（"开发中" toast）；注销仅单确认弹窗无验证码（index.vue:177-190）。

**接入后**：
- 邮箱登录（MP ticket 流程）+ 邮箱绑定（补死链）
- 注销账号 + 图形验证码三重确认（对齐后端契约）
- `useOtpTicket` 组合式函数（MP 三处复用）

**为什么**：合规（图形码）+ 功能完整；App 保留 429 锁定/隐私协议优势。

**缺陷修正**：邮箱死链、注销无验证码。

### 2.5 我的直播（P1）

**当前实现**：`tabbar/my-live/index.vue` 占位页（51 行），onShow 跳首页。

**接入后**：复用 `live-manage/list.vue` 的 manage 模式（或独立列表页），真实房间列表 + 编辑/删除。

**为什么**：用户无法到达直播管理的路径缺口。

**缺陷修正**：占位死胡同。

### 2.6 专家认领 MyExpert（P2）

**当前实现**：App 无 `/experts/me` API 封装，无认领页。

**接入后**：新增 API + MyExpert 页（专家资料认领/更新，对齐 MP）。

**为什么**：专家生态功能；`/experts/me` 后端已上线。

### 2.7 请求层健壮性（P0，基建）

**当前实现**：`request.ts` 2xx 直接 resolve（不校验 body.code）；无参数清洗；5s 超时；每请求 debug 日志。

**接入后**：业务码校验 + `cleanQueryParams` + acceptCodes（MP W13 精华）+ 超时 10s + 日志收敛。

**为什么**：**消除静默失败**——现在后端报业务错误前端当成功，用户看到"操作成功"实际没生效。

**缺陷修正**：业务码不校验、undefined 序列化。

## 六、实施后效果总结

### 功能层面（实施后 App 端拥有）

1. **管理端 12 模块**（+内容安全/品牌成员/品牌商品/留言单删）——运营能力与小程序端对齐
2. **直播间真实互动**（留言板/长按治理/归一化/内容安全文案）——核心功能不再 mock
3. **认证完整**（邮箱登录/绑定/注销图形码）——合规 + 功能全
4. **我的直播可用**——路径缺口修复
5. **专家认领**——专家生态
6. **首页 3D 焦点图** + expert/brand 跳转——视觉对齐 + 信息密度保持
7. **契约对齐后端**——31 项冲突消解，App 不再是"旧契约"

### 架构层面

- 地基（守卫/组件化/图片/token 刷新）**保持**——App 领先项不被覆盖
- 请求层健壮性补齐——静默失败消除
- 样式/日志治理——工程卫生

### 预计工作量

| 阶段 | 内容 | 工作量 |
|:----:|------|:------:|
| 阶段 0 | 修内部 bug（?redirect=/PUT→PATCH/孤儿页/room-tabs/关 Mock） | 0.5d |
| 阶段 1 | 契约对齐会（31 项，以 MP 为基准） | 0.5d |
| 阶段 2 | 功能融合（留言板/焦点图/管理三模块/认证/我的直播） | 4-5d |
| 阶段 3 | 工程治理（请求层/样式/日志/单测） | 1-2d |
| **合计** | | **6-8d** |
