## 一、背景与结论先行

焦点图（Featured Content）为首页核心运营位，两端（App/小程序）共用同一后端。经对**后端实际源码**逐行核实，得到三个修正既有认知的关键结论：

| # | 结论 | 依据 | 影响 |
|:-:|------|------|------|
| 1 | 公开接口 `GET /featured-content` 返回 **`data: 裸数组`**（非 `{items}`） | `homepage_search_service.py` `get_featured_content_list` 直接 `model_dump` 数组 | **App 端本就正确**（`res.data \|\| []`），文档冲突 #14 无需改 App；MP 的 `{items}` 兼容属防御性写法（无害） |
| 2 | 上传接口字段名 **`image`**（非 `file`） | endpoint `image: UploadFile = File(...)` | **App 端 `api/featured.ts:78` 必挂**（冲突 #8 实锤） |
| 3 | 后端 `target_type` **只支持 5 类**：room / session / topic / brand / external，**不支持 expert** | `_validate_target_resource` 枚举校验 | **MP 表单的 expert 选项是两端唯一错误选项**（选了带 target_id 必 400）；App 补齐类型时应含 session/brand 但**跳过 expert** |

**总实施量估算**：约 4-5.5 人日（含 0.5d 契约对齐会 + 0.5d 真机回归），分 5 个阶段（阶段 0 为契约与前置核对，之后每阶段有独立核查清单与退出条件，未达标不得进入下一阶段）。

## 二、后端焦点图契约全景（源码核实）

### 2.1 端点契约（7 个）

| 端点 | 说明 |
|------|------|
| `GET /api/v1/featured-content` | 公开，无参数；仅 `is_active=true` 且在有效期（start_at ≤ now ≤ end_at）；`sort_order` 升序；最多 10 条；返回 `data: [裸数组]` |
| `GET /api/v1/admin/featured-content` | 分页：`page`(≥1) / `size`(1-100) / `q` / `search_type`(id=精确, 其他=标题/副标题模糊) / `is_active` / `status`(active/upcoming/expired/inactive)；返回 `data: {total, page, size, items[]}`，每条带动态 `status` 字段；查询前**惰性下线**（过期 active 记录自动翻转 `is_active=false`） |
| `GET /api/v1/admin/featured-content/{id}` | 详情，返回 `data: item` |
| `POST /api/v1/admin/featured-content` | 创建，返回 `data: item` |
| `PATCH /api/v1/admin/featured-content/{id}` | 部分更新（`exclude_unset`），返回 `data: item` |
| `DELETE /api/v1/admin/featured-content/{id}` | **物理删除**（非软删）+ 清理 `/media/featured_content/{id}/` 目录 |
| `POST /api/v1/admin/featured-content/{id}/image` | multipart 字段名 **`image`**；jpg/jpeg/png/gif + MIME 校验 + ≤5MB（`UPLOAD_MAX_SIZE=5242880`）；保存至 `/media/featured_content/{id}/image_{ts}.{ext}` 并**自动回写 `image_url`**，返回完整 item（`data.image_url` 可解析） |

### 2.2 字段与校验约束

| 字段 | 约束 |
|------|------|
| `title` | 必填，≤255 |
| `subtitle` | 可选，≤512 |
| `image_url` | 必填，≤512，**须 `http(s)://` 或 `/` 开头**（否则 422） |
| `target_type` | 可选，≤50，**无枚举/DB CHECK 约束**；带 `target_id` 时 Service 层校验资源存在，**仅支持 room/session/topic/brand/external 5 类** |
| `target_id` | 可选，UUID 类型（非 UUID 传 422） |
| `target_url` | 可选，≤512，URL 校验同 `image_url`；仅 external 使用 |
| `sort_order` | ≥0，默认 0，升序排列 |
| `is_active` | 默认 true |
| `start_at` / `end_at` | TIMESTAMPTZ，可选，支持定时上下线 |

### 2.4 阶段 0 契约核实结论（v1.2 新增，源码+实测）

| 项 | 结论 | 依据 |
|----|------|------|
| A3 brand 详情路由 | ✅ **无阻碍**：`/pages/app/brand/detail?id=`（detail.vue `onLoad` 读 id；tabbar/brand/index.vue:116 同款跳转） | 源码 |
| B6 room 列表 | ✅ `GET /rooms?page&size&q&sort`（支持 q 关键词）；App `getRoomList` 需补 q 参数透传 | room.py:106-114 |
| B6 brand 列表 | ✅ `GET /brands?limit&q`（**参数为 limit/q，返回裸数组非分页**——App `getBrands` 声明 PaginatedResponse 不符，选择器按裸数组适配） | brand.py:42-66 + brand_service |
| B6 session 列表 | ⚠️ **无全量接口**（仅 `/rooms/{id}/sessions`、`/sessions/{id}`）→ 采用**房间选择器方案**（见下） | session.py 路由清单 |
| 房间场次排序 | ✅ `GET /rooms/{id}/sessions` 按 `created_at desc`，第一条即最新场次（"一房一场次"业务模型成立） | crud/session.py:342-344 |
| D1 联调环境 | ✅ **`http://10.105.136.235:8080/api/core`**（`.env.development.local` 已配置，`VITE_USE_MOCK=false`，无需改 env）；实测 `/api/core/featured-content` 返回 200 与基线一致 | 实测 curl |
| 线上域名 | ⚠️ `mp.dayilive.com` 的 /api/core、/api/v1 为 Spring Boot 风格 404，**非 Python 后端**，联调勿用 | 实测 curl |
| 数据基线 | ✅ 9 条 active（8×`测试焦点图_*` + 1×`包含关键词_*`，全占位图，无真实运营数据），已记入登记表（docs/焦点图实施测试数据登记表.md） | 实测 curl |

**B6 session 方案定稿（结合"一房一场次"业务模型）**：
- session 类型的选择器 UI 呈现为"**选择房间**"：搜索 `GET /rooms?q=`（复用 `getRoomList` 扩展 q）→ 选中房间 → 调 `GET /rooms/{id}/sessions?page=1&size=1` 取**最新场次**（created_at desc 第一条）作为 `target_id`
- 边界处理：房间无场次 → 提示"该房间暂无场次"且不允许选中；防御性取 `items[0]`
- 与运行时一致：App LiveView 按 roomId 查最新场次的逻辑相同，跳转闭环 ✅
- 显示名：展示房间名（如 `房间名（场次·直播中）`，副标题取场次 status）

## 五、测试数据管理规范（F1，全阶段生效，实施前必读）

> 原则：**最小化、可辨识、全登记、可清理、防误删**。实施期间创建的所有测试数据必须可追踪、可在结束后一键核对清理，且**绝不允许误删既有正确数据**。

### 5.1 环境优先原则

1. 功能验证**优先在联调/预发环境**进行；仅在无法提供独立环境时才允许在（类）生产环境做最小冒烟验证，且必须走完 5.2-5.5 全部流程。
2. 阶段 0 记录**数据基线**：公开接口当前 `active` 条数 + 管理端列表快照（数量与代表条目标题），作为实施结束后的核对基准。

### 5.2 可辨识命名

所有测试创建的焦点图标题**必须带统一前缀**：`[TEST]`（如 `[TEST]A1上传验证-0820`），便于列表检索与批量识别。前端联调时禁止用真实运营标题。

### 5.3 全量登记（记录表模板）

实施期间每创建一个测试数据，立即在实施日志/登记表追加一行（建议表格）：

| 登记字段 | 示例 |
|----------|------|
| 数据 ID | `9f3c...uuid` |
| 标题（含前缀） | `[TEST]A1上传验证-0820` |
| target_type / target_id | `room / 真实房间UUID`（**仅引用，不创建**） |
| 创建时间 / 创建入口 | 2026-08-12 10:30 / 管理页表单 |
| 用途（关联实施项） | A1 上传字段验证 |
| 清理状态 | 待清理 / 已清理(时间) |

> 关联真实资源（room/session/brand）时**只引用其 UUID，不复制、不修改**该资源本身；禁止修改既有焦点图记录来"模拟"测试（如需改后还原，必须登记原值并验证还原）。

### 5.4 清理时机与方式

1. **每阶段退出条件**中增加清理核查：本阶段登记表内的 `[TEST]` 记录全部清理完毕（调用 DELETE 端点物理删除），未清理不得进入下一阶段。
2. **全部实施结束**后统一终检：登记表无"待清理"项 + 公开接口数量与阶段 0 基线一致。
3. 清理方式：管理端删除或直接调 `DELETE /admin/featured-content/{id}`（后端物理删除记录 + 自动清理 `/media/featured_content/{id}/` 目录，按 content_id 隔离，不会波及其他记录）。

### 5.5 防误删核对（删除前三查）

1. **查 ID**：与登记表逐条比对，仅删除登记过的 ID；
2. **查标题**：删除前核对标题仍含 `[TEST]` 前缀；**若前缀已被修改或无法辨认，立即停止删除**，人工确认归属后再处理；
3. **查归属**：确认该记录不是既有运营数据（`created_at` 在实施窗口内、标题含前缀、与基线快照不重叠）。

### 5.6 风险声明

| 风险 | 概率 | 影响 | 缓解 |
|------|:---:|:---:|------|
| 测试数据残留：`[TEST]` 焦点图暴露在首页 | 中 | 中（生产视觉污染） | 5.3 登记 + 5.4 阶段清理 + 终检基线比对 |
| 误删真实数据：删除接口是物理删除 | 低 | **高（不可恢复）** | 5.5 三查 + 登记表先行 + 前缀核对中断机制 |
| 误改真实记录：编辑测试时改到真实数据 | 低 | 中 | 5.3 只新建不修改既有记录原则 |
