# 登录弹窗修复与匿名浏览设计方案

> **文档版本**：v1.2
> **最后更新**：2026-07-24
> **变更说明**：v1.2 — 新增统一登录提示三级方案（P1 Foundation → P2 功能触发 → P3+P4 页面守卫），新增通知模块后续实现章节

---

## 1. 文档目标

本文档旨在为直播 SaaS 移动端 App 提供统一的登录引导策略，解决以下问题：

1. **登录弹窗阻塞体验** — 首页加载后弹出模态框询问"是否登录"，干扰正常浏览
2. **重复跳转冗余** — 弹窗中点击"立即登录"时已处于登录页，造成二次跳转
3. **无匿名浏览支持** — 用户无明确登录意愿时仍被反复引导至登录页

## 3. 设计方案

### 3.1 设计原则

1. **先内容，后登录** — 首页优先展示内容，不强求用户登录
2. **一次选择，session 有效** — 用户选择"稍后再说"后，本次启动不再弹出引导
3. **非阻塞引导** — 用页面内横幅替代模态弹窗，不打断操作
4. **轻量功能提示** — 功能级触发使用 `showToast` + 自动跳转，不给二选一

### 3.2 改造一：启动引导——横幅替代模态

#### 当前

```
home onMounted → uni.showModal(阻塞弹窗)
```

#### 改后

```
home onMounted → 检查 isAuthenticated + in-memory dismiss 标记
                 → 未登录且未标记已关闭
                     → 在首页顶部显示一个可关闭的引导横幅
                     → 点击 [登录] → navigateTo(/login) + 存 redirectPath
                     → 点击 [×]   → 隐藏横幅 + 设 in-memory 标记（本次 session 不再出现）
```

**dismiss 标记方案**：在 `authStore` 中增加 `loginBannerDismissed: ref(false)`。用户点击"×"后设为 `true`。App 关闭后自动重置为 `false`（内存标记生命周期 = 进程生命周期），自然实现"每次启动提醒一次"的效果。无需 `uni.setStorageSync` 持久化。

### 3.3 改造二：功能级触发——直接跳转 + 兜底

#### 当前

```
用户点击收藏(isAuthenticated=false)
    → uni.showModal({title:'登录提示', confirmText:'立即登录', cancelText:'取消'})
    → 用户必须选一个
```

#### 改后

```
用户点击收藏(isAuthenticated=false)
    → uni.setStorageSync('loginRedirectPath', 当前URL)
    → uni.navigateTo({ url: APP_LOGIN_PATH, fail: 兜底处理 })
```

用户感知：点击收藏 → 直接跳登录页 → 登录完成 → 回到收藏前页面

不额外加 Toast，不延迟跳转。`requireAuth()` 已在 `utils/auth.ts` 中践行此模式并验证有效。

### 3.4 改造三：移除 `showLoginPrompt()` 及相关

移除 `authStore.showLoginPrompt()` 方法和 `utils/auth.ts` 中的 `showLoginPrompt()` 函数（已是死代码）。

## 4. 详细实现

### 4.1 首页引导横幅组件

**新建文件**：`src/components/app/LoginGuideBanner.vue`

```vue
<template>
  <view v-if="visible" class="login-guide-banner">
    <text class="banner-text">登录后可享受收藏、点赞、订阅等完整功能</text>
    <view class="banner-actions">
      <text class="banner-btn banner-btn--login" @click="handleLogin">登录</text>
      <text class="banner-btn banner-btn--close" @click="handleDismiss">×</text>
    </view>
  </view>
</template>

<script setup lang="ts">
import { ref, onMounted } from 'vue';
import { APP_LOGIN_PATH, APP_HOME_PATH } from '@/constants/routes';
import { useAuthStore } from '@/store/auth';

const authStore = useAuthStore();
const visible = ref(false);

onMounted(() => {
  if (!authStore.isAuthenticated && !authStore.loginBannerDismissed) {
    visible.value = true;
  }
});

function handleLogin() {
  visible.value = false;
  uni.setStorageSync('loginRedirectPath', APP_HOME_PATH);
  uni.navigateTo({
    url: APP_LOGIN_PATH,
    fail: () => {
      uni.showToast({ title: '跳转失败，请重试', icon: 'none' });
    }
  });
}

function handleDismiss() {
  visible.value = false;
  authStore.loginBannerDismissed = true;
}
</script>
```

**引用方式**：在 `home/index.vue` template 顶部加入 `<LoginGuideBanner />`，移除 `onMounted` 中对 `showLoginPrompt()` 的调用。

```diff

```

并在 `setup` 的 return 中暴露该字段。

### 4.3 `utils/auth.ts:showLoginPrompt()` → 移除

### 4.5 功能级触发点改动（6 处）

**通用改写模式**（以 LiveView.vue 收藏为例）：


## 6. 变更后交互流程

### 正常流程（未登录首次启动）

```
App 启动 → 首页 → 顶栏显示引导横幅
                    ├── [登录] → 跳转登录页 → 登录成功 → 回到首页 → 横幅不显示
                    └── [×]    → 横幅隐藏 → session 内不再出现
```

### 功能触发流程

```
匿名用户点击收藏
    → 直接跳转登录页
    → 登录成功 → handleAuthRedirect → 回到收藏前页面
```

### 已登录用户

```
App 启动 → 首页 → 无横幅（isAuthenticated=true）
```

## 7. 风险与注意事项

| # | 风险 | 缓解措施 |
|---|------|---------|
| 1 | 横幅组件在首页滚动时可能遮挡内容 | 横幅跟随页面滚动（非 fixed），或添加 `position: sticky` |
| 2 | in-memory 标记在页面 keep-alive 时可能不重置 | 横幅用 `onMounted` 判断，页面激活时不重复显示；标记为 session 级（`authStore` ref），组件卸载再挂载仍可读取 |
| 3 | 首次登录后 `loginBannerDismissed` 仍为 false，但不用清除 | 因为 `isAuthenticated = true` 后横幅根本不会显示，标记状态无关紧要 |
| 4 | `live/index` 已删除，`LiveView.vue` 中 redirect 路径需确认 | 当前用 `/pages/app/live/LiveView` 已注册 pages.json，路径正确 |

## 9. 通知模块：游客通知访问（后续实现）

**当前状态**：通知页面（`src/pages/app/notifications/index.vue`）无登录状态检查，所有通知为前端 mock 数据，后端未实现。

**问题**：后续后端实现通知系统时，游客不应看到针对特定用户的个人通知（如 @提及、私信、订单状态等），仅应展示系统级全局公告。

**后续实现建议**：

| 事项 | 说明 |
|------|------|
| 后端 API | `/notifications` 接口需支持 `scope` 参数：`global`（全用户可见）vs `personal`（需登录 + 用户匹配） |
| 前端过滤 | `notificationStore.loadNotifications()` 根据 `authStore.isAuthenticated` 决定请求参数：游客 `scope=global`，已登录用户 `scope=all` |
| 页面守卫 | 通知页面可在 `onMounted` 中调用 `loadNotifications()` 时自动传参；无需额外跳转拦截（游客可自由访问通知页，但只看到全局公告） |
| 入口显示 | 首页右上角通知图标始终可见；未登录用户看到红点仅表示全局公告未读；个人通知仅在登录后可见
