## 纪律（强制）

1. **创建即登记**：任何手动验证数据（resolve 自建词 / 场次绑定 / Admin 停用词 / legacy >5 夹具）生成后**立即**补登本表，禁止事后补忆。
2. **逐条精确清理**：仅按登记清单 `WHERE 主键` 删除；先删关联表（session_tags），再删主表（tags）。
3. **残留核验**：每个阶段 Gate 前按本表反查，输出「已清理 / 残留 0」结论；未清零不得过 Gate。
4. **自动测试数据**（pytest/vitest 生成、随测试库/临时态清零）不登记。
5. **规则表不做业务清理**（tag_name 内容安全规则为结构性数据，执行前备份策略见后端 §9.3）。

## 清理顺序约束

1. `session_tags` 关联行先删，`tags` 主行后删；
2. 涉及房间/场次的验证数据，先确认测试归属（专用前缀/登记在案），不满足登记条件不得删除；
3. 任何批量删除意向先对照本表逐条列出，经人工复核后执行；
4. legacy >5 夹具（编辑回显超限用例）属 DB 级直插，登记时注明插入语句与归属，清理用同一主键反向删除。
