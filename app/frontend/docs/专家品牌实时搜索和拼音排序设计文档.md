## 2. 业务需求分析

### 2.1 专家页面需求（完整功能实现）

#### 功能1：拼音字母排序

**业务场景**：用户希望像查通讯录一样快速定位专家

**核心需求**：
- 专家按姓名拼音首字母 A-Z 排序
- 相同首字母的专家，按完整拼音排序（"丁一" < "丁之明"）
- 右侧字母索引快速定位（A-Z + #）
- 点击字母时屏幕中央显示悬浮提示（参考微信通讯录）

**用户价值**：
- 提升查找效率（无需滚动大量列表）
- 符合移动端用户习惯（参考iOS通讯录、微信好友列表）

#### 功能2：局部实时搜索

**业务场景**：用户在专家列表中快速筛选目标专家

**核心需求**：
- 不跳转页面，在当前页面实时过滤
- 输入"丁"时，列表自动变为所有丁姓专家
- 过滤后的结果仍按拼音首字母排序
- 支持汉字、拼音、拼音首字母三种搜索方式
  - 输入"丁" → 匹配"丁一"、"丁之明"
  - 输入"ding" → 匹配"丁一"、"丁之明"
  - 输入"dy" → 匹配"丁一"（拼音首字母）

**用户价值**：
- 无网络延迟，秒级响应
- 支持多种输入习惯（汉字、拼音、首字母）

### 2.2 品牌页面需求（精简功能实现）

#### 功能：局部实时搜索

**业务场景**：用户在品牌列表中快速查找目标品牌

**核心需求**：
- 不跳转页面，在当前页面实时过滤
- 输入品牌名称时，列表自动过滤匹配项
- 支持汉字和拼音搜索
- **暂不实现**字母排序和字母索引（业务需求优先级低，保持现有网格布局）

**用户价值**：
- 快速查找品牌，减少滚动操作
- 保持原有简洁布局

### 2.3 需求差异对比

| 功能模块 | 专家页面 | 品牌页面 | 原因说明 |
|---------|---------|---------|---------|
| 实时搜索 | ✅ 必需 | ✅ 必需 | 核心需求，提升查找效率 |
| 拼音排序 | ✅ 必需 | ❌ 不需要 | 专家页面类似通讯录，品牌按权重排序 |
| 字母索引 | ✅ 必需 | ❌ 不需要 | 专家页面数据多，品牌保持网格 |
| 分组显示 | ✅ 必需 | ❌ 不需要 | 专家按字母分组，品牌按权重 |
| 悬浮提示 | ✅ 必需 | ❌ 不需要 | 专家页面增强交互体验 |

## 3. 技术方案设计

### 3.1 架构分层设计

按照《直播SaaS平台移动端前端设计文档》的架构规范，本功能涉及以下三层：

```
┌─────────────────────────────────────────────┐
│  表现层 (Presentation Layer)                │
│  - src/pages/app/tabbar/expert/index.vue   │ ← 专家页面
│  - src/pages/app/tabbar/brand/index.vue    │ ← 品牌页面
│  - src/components/business/ExpertCard.vue  │ ← 专家卡片组件
│  - src/components/business/LetterIndex.vue │ ← 字母索引组件
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐
│  业务逻辑层 (Business Logic Layer)          │
│  - src/store/expert.ts                      │ ← 专家状态管理（Pinia）
│  - src/store/brand.ts                       │ ← 品牌状态管理（Pinia）
│  - src/utils/pinyin.ts                      │ ← 拼音工具函数
└─────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────┐

└─────────────────────────────────────────────┘
```

**职责划分**：
- **表现层**：负责UI渲染、用户交互、手势识别
- **业务逻辑层**：负责数据过滤、排序、分组、缓存管理
- **数据访问层**：负责接口调用、数据转换、错误处理

### 3.2 技术选型

#### 3.2.1 拼音处理库

**选择**：pinyin-pro

**理由**：
- **体积小**：~50KB 原始大小，gzip 后约 15KB
- **功能完善**：支持多音字、姓氏特殊读音
- **性能好**：纯 JavaScript 实现，无需 WebAssembly
- **维护活跃**：GitHub 3000+ stars，持续更新

**安装命令**：
```bash
pnpm add pinyin-pro
```

**备选方案**：
- `pinyin`：体积更小但功能受限
- `pinyinjs`：已停止维护

#### 3.2.2 状态管理

**选择**：Pinia

**理由**：
- Vue 3 官方推荐，替代 Vuex
- TypeScript 支持友好
- 模块化设计，代码简洁
- 支持 devtools 调试

#### 3.2.3 性能优化工具

| 优化场景 | 技术方案 | 说明 |
|---------|---------|------|
| 长列表渲染 | uni-virtual-list | 虚拟滚动，减少DOM节点 |
| 搜索防抖 | lodash-es/debounce | 300ms防抖，减少计算频率 |
| 图片懒加载 | uni-app内置 lazy-load | 减少首屏图片加载 |
| 内存优化 | 精简数据结构 ExpertBrief | 减少80%内存占用 |
| 缓存管理 | Store缓存 + 时间戳 | 5分钟缓存，减少网络请求 |

### 3.3 方案优势

1. **无需改后端**：利用现有 API 接口，前端独立实现
2. **实时响应**：无网络延迟，用户体验佳（< 50ms 响应）
3. **快速上线**：仅需修改前端代码，无需后端改造
4. **适合数据量**：专家 < 1000 条，品牌 < 500 条
5. **灵活实施**：专家页面完整功能，品牌页面精简实现

### 3.4 方案局限性与对策

#### 局限性1：数据量限制（扩展性问题）

**适用范围**：< 1000 条数据

**触发条件**：数据量 > 2000 条时：
- 内存占用显著增加（≈ 响应大小 × 2-3 倍）
- 排序耗时 > 100ms（影响用户体验）
- 搜索防抖延迟明显

**对策（分阶段）**：
1. **短期兜底**（< 2000条）：
   - 虚拟滚动（uni-virtual-list）减少 DOM
   - Web Worker 执行排序（避免主线程阻塞）
   - 分批加载（首屏 50 条 + 滚动加载）

2. **中期优化**（2000-5000条）：
   - 后端预分组：返回 `{ A: [...], B: [...] }`
   - 按需加载：携带 `letter=A` 参数

3. **长期迁移**（> 5000条）：
   - 迁移后端实现
   - 后端添加 `sort_by=pinyin` 参数
   - 前端退化为简单搜索

**监控指标**：
- 排序耗时 > 50ms → 启用 Web Worker
- 数据条数 > 2000 → 启用虚拟滚动
- 数据条数 > 5000 → 迁移后端排序

#### 局限性2：多音字误差（准确性问题）

**问题描述**：pinyin-pro 无法 100% 准确识别特殊姓氏读音

**误差率**：约 5%（1000 名专家中约 50 名可能有误）

**错误案例**：

| 姓名 | 正确拼音 | 可能错误 | 影响 |
|------|---------|---------|------|
| 解文 | Xie Wen | Jie Wen | 分组到J，应该在X |
| 单医生 | Shan | Dan | 分组到D，应该在S |
| 仇医生 | Qiu | Chou | 分组到C，应该在Q |

**对策**：
1. **白名单机制**（已设计实现）：
   - 配置文件：`src/config/pinyin-whitelist.json`
   - 动态加载：`loadPinyinWhitelist()` 异步加载
   - 优先级：白名单 > pinyin-pro 自动识别

2. **用户反馈机制**：
   - 页面底部"排序有误？点击反馈"
   - 收集错误案例更新白名单

3. **定期维护**：
   - 每月审核 TOP 100 高频专家
   - 人工修正拼音错误

**监控指标**：
- 白名单命中率（每日统计）
- 用户反馈案例（每周处理）
- 多音字误差率（目标 < 3%）

#### 局限性3：内存压力（性能问题）

**问题描述**：前端缓存完整列表，低端设备可能卡顿

**内存占用分析**：

| 数据量 | 未优化 | 已优化 | 低端设备表现 |
|--------|--------|--------|-------------|
| 500条  | 250KB  | 100KB | ✅ 流畅 |
| 1000条 | 500KB  | 200KB | ✅ 流畅 |
| 2000条 | 1MB    | 400KB | ⚠️ 偶尔卡顿 |
| 5000条 | 2.5MB  | 1MB   | ❌ 明显卡顿 |

**对策**：
1. **数据结构精简**（已实现）：
   ```typescript
   interface ExpertBrief {
     id: string;        // 必需（详情页跳转）
     name: string;      // 必需（显示+搜索+排序）

   }
   ```

2. **图片懒加载**：
   ```vue
   <image :src="avatar" lazy-load mode="aspectFit" />
   ```

3. **定时清理缓存**：
   ```typescript
   onUnmounted(() => {
     expertStore.clearCache(); // 页面卸载时清理
   });
   ```

4. **虚拟滚动**：数据量 > 1000 时启用

**监控指标**：
- 页面内存占用（Chrome DevTools）
- 低端设备崩溃率（< 2GB 设备）
- 滚动帧率（目标 > 55 FPS）

#### 局限性4：缓存过期风险（数据一致性问题）

**问题描述**：5 分钟缓存可能导致数据延迟

**影响场景**：

| 场景 | 延迟 | 影响程度 |
|------|------|---------|
| 新增专家 | 最多 5 分钟 | ⚠️ 用户看不到新专家 |
| 修改姓名 | 最多 5 分钟 | ⚠️ 搜索结果错误 |

| 修改头像 | 最多 5 分钟 | ✅ 影响较小 |

**对策**：
1. **支持下拉刷新**（已实现）
2. **缩短缓存时间**（可选）：高频更新场景 1-2 分钟
3. **WebSocket 更新通知**（高级方案）：后台推送更新通知
4. **版本号机制**（高级方案）：API 返回版本号对比

**监控指标**：
- 缓存命中率（每日统计）
- 数据更新频率（后台统计）
- 用户手动刷新频率

#### 局限性5：搜索性能瓶颈

**问题描述**：
- 搜索遍历完整列表（O(n) 复杂度）
- 1000 条数据搜索耗时 10-20ms

**对策**：

**监控指标**：
- 搜索耗时（目标 < 50ms）

## 4. 实现细节

### 4.1 基础设施层：拼音工具函数

**文件位置**：`src/utils/pinyin.ts`

**职责**：
- 拼音转换（汉字 → 拼音）
- 首字母提取（汉字 → A-Z/#）
- 拼音排序（三级排序逻辑）
- 按首字母分组（A-Z 分组 + # 分组）
- 实时搜索过滤（支持汉字、拼音、首字母）
- 白名单动态加载（多音字修正）

**完整代码实现**：

```typescript
// src/utils/pinyin.ts

import { pinyin } from 'pinyin-pro';

/**
 * 多音字/特殊读音白名单（医疗领域常见姓名修正）
 * 优先级：白名单 > pinyin-pro自动识别
 * 使用场景：医疗领域特殊读音、用户反馈的错误拼音
 * 
 * 维护方式：
 * 1. 通过后台管理系统配置
 * 2. 通过 loadPinyinWhitelist() 动态加载
 * 3. 用户反馈后人工审核添加
 */
const PINYIN_WHITELIST: Record<string, string> = {
  // 示例：
  // '解文': 'xiewen',
  // '单医生': 'shanys',
  // 实际使用时通过配置文件或API动态加载
};

/**
 * 获取汉字的拼音首字母（大写）
 * @param text 汉字文本
 * @returns 拼音首字母，如 "丁" → "D"
 * 
 * 规则：
 * 1. 英文字母：直接返回大写 (Dr.Smith → D)
 * 2. 中文汉字：转拼音取首字母 (张三 → Z)
 * 3. 数字/特殊符号：归类到 # (123 → #)
 * 
 * 性能：O(1) 复杂度，单次调用 < 1ms
 */
export function getFirstLetter(text: string): string {
  if (!text) return '#';
  
  const firstChar = text.charAt(0);
  
  // 1. 处理英文字母（优先级最高）
  if (/^[a-zA-Z]$/.test(firstChar)) {
    return firstChar.toUpperCase();
  }
  
  // 2. 处理中文字符
  if (/[\u4e00-\u9fa5]/.test(firstChar)) {
    // 检查白名单（完整名字优先匹配）
    if (PINYIN_WHITELIST[text]) {
      return PINYIN_WHITELIST[text].charAt(0).toUpperCase();
    }
    
    // 获取拼音首字母
    const py = pinyin(firstChar, { 
      pattern: 'first',  // 只取首字母
      toneType: 'none'   // 无音调
    }).toUpperCase();
    
    return py || '#';
  }
  
  // 3. 其他字符（数字、符号等）归类到 #
  return '#';
}

/**
 * 获取完整拼音（用于排序和搜索）
 * @param text 汉字文本
 * @returns 完整拼音，如 "丁之明" → "dingzhiming"
 * 
 * 特性：
 * - 支持多音字白名单覆盖
 * - 去除音调
 * - 全小写输出
 * - 连续拼接（无分隔符）
 * 
 * 性能：O(n) 复杂度，n 为字符数，单次调用 < 5ms
 */
export function getPinyin(text: string): string {
  if (!text) return '';
  
  // 优先检查白名单（完整名字匹配）
  if (PINYIN_WHITELIST[text]) {
    return PINYIN_WHITELIST[text].toLowerCase();
  }
  
  // 使用 pinyin-pro 转换
  return pinyin(text, { 
    pattern: 'pinyin',
    toneType: 'none',
    type: 'array'
  }).join('').toLowerCase();
}

/**
 * 按拼音排序（进阶版：三级排序规则）
 * @param items 要排序的数组
 * @param getNameFn 获取姓名的函数
 * @returns 排序后的数组（新数组，不修改原数组）
 * 
 * 排序规则（优先级从高到低）：
 * 1. 拼音字典序比较（"dingyi" < "dingyishan"）
 * 2. 拼音相同时，按原始汉字Unicode比较（"李芳" vs "李方"）
 * 3. 较短前缀排在前面（"丁一" < "丁一山"）
 * 
 * 技术细节：
 * - 使用 String.localeCompare() 的 'zh-Hans-CN' locale
 * - sensitivity: 'accent' 区分重音符号
 * - 时间复杂度：O(n log n)
 * - 空间复杂度：O(n)（创建新数组）
 * 
 * 性能：1000条数据排序耗时 < 50ms
 */
export function sortByPinyin<T>(
  items: T[], 
  getNameFn: (item: T) => string
): T[] {
  return items.slice().sort((a, b) => {
    const nameA = getNameFn(a);
    const nameB = getNameFn(b);
    
    // 1. 获取完整拼音序列
    const pinyinA = getPinyin(nameA);
    const pinyinB = getPinyin(nameB);
    
    // 2. 拼音比较（使用中文locale，区分重音）
    const pinyinCompare = pinyinA.localeCompare(pinyinB, 'zh-Hans-CN', { 
      sensitivity: 'accent' 
    });
    
    // 3. 拼音相同时，回退到原始汉字比较（解决同音字排序）
    if (pinyinCompare === 0) {
      return nameA.localeCompare(nameB, 'zh-Hans-CN');
    }
    
    return pinyinCompare;
  });
}

/**
 * 按首字母分组（参考iOS通讯录）
 * @param items 要分组的数组
 * @param getNameFn 获取姓名的函数
 * @returns 分组后的对象，键为首字母，值为该组的数据
 * 
 * 分组规则：
 * - A-Z: 按拼音首字母分组
 * - #: 数字、特殊符号、无法识别的字符
 * 
 * 返回示例：
 * {
 *   'D': [丁一, 丁香, 丁之明],
 *   'L': [李芳, 李方, 刘德华],
 *   '#': [123, @admin]
 * }
 * 
 * 性能：O(n) 复杂度，1000条数据分组耗时 < 10ms
 */
export function groupByFirstLetter<T>(
  items: T[],
  getNameFn: (item: T) => string
): Record<string, T[]> {
  const groups: Record<string, T[]> = {};
  
  items.forEach(item => {
    const name = getNameFn(item);
    const letter = getFirstLetter(name);
    
    if (!groups[letter]) {
      groups[letter] = [];
    }
    groups[letter].push(item);
  });
  
  return groups;
}

/**
 * 获取排序后的字母列表（包含 #）
 * @param groups 分组后的数据
 * @returns 排序后的字母数组
 * 
 * 排序规则（参考微信/iOS通讯录）：
 * 1. A-Z 按字母顺序排列
 * 2. # 始终排在最后
 * 
 * 示例：['A', 'B', 'D', 'L', 'Z', '#']
 * 
 * 用途：用于字母索引组件的渲染和定位
 */
export function getSortedLetters(groups: Record<string, any[]>): string[] {
  const letters = Object.keys(groups);
  
  // 分离普通字母和特殊符号
  const normalLetters = letters.filter(l => l !== '#').sort();
  const hasSpecial = letters.includes('#');
  
  // # 排在最后
  return hasSpecial ? [...normalLetters, '#'] : normalLetters;
}

/**
 * 实时搜索过滤（支持拼音和汉字）
 * @param items 要搜索的数组
 * @param keyword 搜索关键词
 * @param getNameFn 获取姓名的函数
 * @returns 过滤后的数组
 * 
 * 搜索规则（优先级从高到低）：
 * 1. 支持汉字模糊匹配："丁" 匹配 "丁一"、"丁香"
 * 2. 支持拼音模糊匹配："ding" 匹配 "丁一"、"丁香"
 * 3. 支持拼音首字母匹配："dy" 匹配 "丁一"
 * 4. 不区分大小写
 * 
 * 性能：O(n) 复杂度，1000条数据搜索耗时 < 20ms
 * 
 * 用户体验：
 * - 配合 300ms 防抖使用，避免频繁计算
 * - 支持中英文混合输入
 * - 清空关键词时返回完整列表
 */
export function searchByPinyin<T>(
  items: T[],
  keyword: string,
  getNameFn: (item: T) => string
): T[] {
  if (!keyword.trim()) return items;
  
  const kw = keyword.toLowerCase().trim();
  
  return items.filter(item => {
    const name = getNameFn(item);
    const nameLower = name.toLowerCase();
    const fullPinyin = getPinyin(name);
    
    // 1. 汉字匹配
    if (nameLower.includes(kw)) return true;
    
    // 2. 完整拼音匹配
    if (fullPinyin.includes(kw)) return true;
    
    // 3. 拼音首字母匹配（可选，性能优化可注释）
    const initials = pinyin(name, { pattern: 'first', toneType: 'none', type: 'array' })
      .join('').toLowerCase();
    if (initials.includes(kw)) return true;
    
    return false;
  });
}

/**
 * 动态加载多音字白名单配置
 * @param configUrl 配置文件URL或本地路径
 * 
 * 使用场景：
 * - 用户反馈某医生名字拼音错误
 * - 运营人员可通过后台配置修正
 * - 无需发版即可更新白名单
 * 
 * 调用时机：
 * - 应用启动时（App.vue onLaunch）
 * - 专家页面首次加载时（onMounted）
 * 
 * 错误处理：
 * - 加载失败时使用默认配置（空白名单）
 * - 不影响主流程正常运行
 * - 记录警告日志便于排查
 */
export async function loadPinyinWhitelist(configUrl?: string): Promise<void> {
  try {
    // 可从远程配置或本地JSON加载
    const config = configUrl 
      ? await fetch(configUrl).then(r => r.json())
      : await import('@/config/pinyin-whitelist.json');
    
    Object.assign(PINYIN_WHITELIST, config);
    console.log('[Pinyin] 白名单加载成功:', Object.keys(PINYIN_WHITELIST).length, '条');
  } catch (e) {
    console.warn('[Pinyin] 白名单加载失败，使用默认配置:', e);
  }
}

### 4.2 业务逻辑层：专家Store状态管理

**文件位置**：`src/store/expert.ts`

**职责**：
- 专家列表数据管理（加载、缓存、清理）
- 实时搜索过滤逻辑（响应式getter）
- 拼音排序逻辑（响应式getter）
- 按首字母分组（响应式getter）
- 缓存策略管理（5分钟有效期）

**完整代码实现**：

```typescript
// src/store/expert.ts

import { defineStore } from 'pinia';
import { getFeaturedExperts } from '@/api/expert';
import { sortByPinyin, searchByPinyin, getFirstLetter, getSortedLetters } from '@/utils/pinyin';
import { resolveMediaUrl } from '@/utils/media';

/**
 * 专家精简信息（减少内存占用）
 * 详细信息通过详情页API懒加载
 * 
 * 内存优化：
 * - 精简前：~500B/条
 * - 精简后：~100B/条
 * - 内存减少 80%
 */
export interface ExpertBrief {
  id: string;           // 必需（详情页跳转）
  name: string;         // 必需（显示+搜索+排序）
  avatar: string;       // 必需（显示）
  title: string;        // 可选（显示）
  department: string;   // 可选（显示）
  // 详细信息在详情页加载：bio, specialization, stats等
}

/**
 * 专家Store
 * 
 * 核心功能：
 * 1. 数据加载与缓存管理
 * 2. 实时搜索过滤（响应式）
 * 3. 拼音排序（响应式）
 * 4. 按首字母分组（响应式）
 * 
 * 性能优化：
 * - 5分钟缓存，减少网络请求
 * - 数据结构精简，减少80%内存占用
 * - 响应式getter，自动缓存计算结果
 * - 防抖搜索，减少计算频率
 */
export const useExpertStore = defineStore('expert', {
  state: () => ({
    /** 原始专家列表（精简版，减少内存） */
    allExperts: [] as ExpertBrief[],
    
    /** 搜索关键词 */
    keyword: '',
    
    /** 科室筛选 */
    specialty: '',
    
    /** 数据缓存时间戳 */
    cacheTimestamp: 0,
    
    /** 加载状态 */
    loadingList: false,
    
    /** 错误信息 */
    error: null as null | { message: string },
  }),

  getters: {
    /**
     * 过滤后的专家列表（应用搜索和筛选逻辑）
     * 性能优化：使用computed自动缓存结果，只有依赖变化时才重新计算
     * 
     * 执行顺序：
     * 1. 科室筛选
     * 2. 关键词搜索（支持汉字和拼音）
     * 3. 拼音排序
     * 
     * 性能：1000条数据过滤+排序耗时 < 50ms
     */
    filteredExperts(): ExpertBrief[] {
      let result = this.allExperts;
      
      // 1. 科室筛选
      if (this.specialty && this.specialty !== '全部') {
        result = result.filter(e => 
          e.department.includes(this.specialty)
        );
      }
      
      // 2. 关键词搜索（支持汉字和拼音）
      if (this.keyword.trim()) {
        result = searchByPinyin(
          result, 
          this.keyword, 
          (e) => e.name
        );
      }
      
      // 3. 拼音排序（三级排序规则）
      return sortByPinyin(result, (e) => e.name);
    },
    
    /**
     * 按首字母分组的专家列表
     * 返回格式：{ 'D': [...], 'L': [...], '#': [...] }
     * 
     * 用途：
     * - 页面渲染（按字母分组显示）
     * - 字母索引（计算每个字母的数据）
     * 
     * 性能：已过滤和排序的数据直接分组，耗时 < 10ms
     */
    groupedExperts(): Record<string, ExpertBrief[]> {
      const groups: Record<string, ExpertBrief[]> = {};
      
      this.filteredExperts.forEach(expert => {
        const letter = getFirstLetter(expert.name);
        if (!groups[letter]) {
          groups[letter] = [];
        }
        groups[letter].push(expert);
      });
      
      return groups;
    },
    
    /**
     * 所有首字母列表（A-Z排序，#在最后）
     * 参考微信通讯录规则
     * 
     * 用途：
     * - 字母索引组件的渲染
     * - 字母定位逻辑
     * 
     * 示例：['A', 'D', 'L', 'Z', '#']
     */
    letterList(): string[] {
      return getSortedLetters(this.groupedExperts);
    }
  },

  actions: {
    /**
     * 获取专家列表（一次性加载，带缓存）
     * 性能优化：5分钟缓存，减少网络请求
     * 内存优化：只加载必需字段
     * 
     * 缓存策略：
     * - 缓存有效期：5分钟
     * - 缓存检查：通过时间戳判断
     * - 手动刷新：调用 clearCache() 后重新加载
     * 
     * 错误处理：
     * - 网络错误：显示错误提示，保留旧数据
     * - 数据格式错误：记录日志，清空列表
     * - 超时错误：显示超时提示，支持重试
     */
    async fetchExperts() {
      // 缓存检查（5分钟内不重复请求）
      const CACHE_DURATION = 5 * 60 * 1000; // 5分钟
      const now = Date.now();
      
      if (
        this.allExperts.length > 0 && 
        now - this.cacheTimestamp < CACHE_DURATION
      ) {
        console.log('[ExpertStore] 使用缓存数据，剩余有效期:', 
          Math.floor((CACHE_DURATION - (now - this.cacheTimestamp)) / 1000), '秒');
        return;
      }
      
      this.loadingList = true;
      this.error = null;

      try {
        console.log('[ExpertStore] 开始获取专家列表');
        
        // 调用API获取所有专家（limit=1000）
        const res = await getFeaturedExperts({ limit: 1000 });
        
        if (res.code !== 200 || !Array.isArray(res.data)) {
          throw new Error(res.message || '获取专家失败');
        }

        // 映射数据（只保留必需字段，减少内存占用）
        this.allExperts = res.data.map((x: any) => ({
          id: x.id,
          name: x.name,
          avatar: resolveMediaUrl(x.avatar_url) || '/static/images/default-avatar.png',
          title: x.title || '',
          department: [x.hospital, x.department].filter(Boolean).join(' | '),
          // 详细信息在详情页懒加载
        }));

        // 更新缓存时间戳
        this.cacheTimestamp = now;
        
        console.log('[ExpertStore] 专家列表加载成功:', this.allExperts.length, 
          '条，内存占用约', (JSON.stringify(this.allExperts).length / 1024).toFixed(2), 'KB');
      } catch (e: any) {
        this.error = { message: e?.message || '加载专家列表失败' };
        console.error('[ExpertStore] 加载失败:', e);
        
        // 显示用户友好的错误提示
        uni.showToast({
          title: '加载失败，请稍后重试',
          icon: 'none',
          duration: 2000
        });
      } finally {
        this.loadingList = false;
      }
    },
    
    /**
     * 设置搜索关键词（触发实时搜索）
     * 性能优化：无需重新加载数据，getter会自动过滤
     * 
     * 使用方式：
     * - 页面组件调用 expertStore.setKeyword(keyword)
     * - filteredExperts getter 自动响应变化
     * - 页面自动重新渲染
     * 
     * 建议配合防抖使用：
     * ```typescript
     * const handleInput = debounce((keyword) => {
     *   expertStore.setKeyword(keyword);
     * }, 300);
     * ```
     */
    setKeyword(keyword: string) {
      this.keyword = keyword;
      console.log('[ExpertStore] 搜索关键词:', keyword, 
        '，过滤结果:', this.filteredExperts.length, '条');
    },
    
    /**
     * 设置科室筛选
     */
    setSpecialty(specialty: string) {
      this.specialty = specialty;
      console.log('[ExpertStore] 科室筛选:', specialty, 
        '，过滤结果:', this.filteredExperts.length, '条');
    },
    
    /**
     * 清空缓存（用户手动刷新时调用）
     * 
     * 调用场景：
     * - 下拉刷新
     * - 数据更新后需要重新加载
     * - 页面卸载时清理内存
     */
    clearCache() {
      this.allExperts = [];
      this.cacheTimestamp = 0;
      console.log('[ExpertStore] 缓存已清空');
    }
  }
});

### 8.3 FAQ

**Q1：为什么不在后端实现拼音排序？**

A：当前数据量（专家<1000，品牌<500）适合前端实现，优势：
- 实时响应，无网络延迟
- 无需改后端，快速上线
- 支持离线搜索

**Q2：多音字误差如何解决？**

A：通过白名单机制兜底：
- 配置文件：`src/config/pinyin-whitelist.json`
- 动态加载：支持远程配置更新
- 用户反馈：收集错误案例更新白名单

**Q3：数据量增长后如何优化？**

A：分阶段优化：
- < 2000条：虚拟滚动 + Web Worker
- 2000-5000条：后端预分组
- > 5000条：迁移后端排序

**Q4：品牌页面为什么不实现字母排序？**

A：业务需求明确：
- 品牌按合作权重排序更合理
- 品牌数量少（<500），无需字母索引
- 保持现有网格布局，减少开发成本
