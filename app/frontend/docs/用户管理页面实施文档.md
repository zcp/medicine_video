# 用户管理页面实施文档

> **文件**：`src/pages/app/admin/users/index.vue`
> **角色**：系统管理员 / 运营主管
> **对象**：平台用户（`users`）
> **实施日期**：2026-07-30
> **实施方式**：一阶段完整实施（API + 类型 + 页面）

---

## 一、页面定位

| 维度 | 说明 |
|------|------|
| 核心问题 | "平台上有哪些用户？谁需要封禁或限制开播？用户角色是否合理？" |
| 使用者 | 超级管理员 / 运营主管 / 内容管理员 |
| 频率 | 中频（日常运营+突发事件响应） |
| 依赖关系 | 无（独立页面，不依赖其他管理页面） |
| 入口 | "我的"页面 → 管理功能菜单 → "用户管理" |

**页面边界**：

| 包含 | 不包含 |
|------|--------|
| 用户列表查看、搜索、筛选 | 用户注册/密码重置（由认证服务处理） |
| 用户状态管理（封禁/解封） | 用户资料编辑（由用户自行维护） |
| 用户角色管理（修改角色） | 用户财务/订阅管理 |
| 开播权限管理（`can_stream` 开关） | 用户删除（仅支持封禁+注销） |

### 3.2 Tab 切换规则

| Tab | 触发方式 | 筛选条件 | 数据来源 |
|:---:|---------|---------|---------|
| `all` | 默认 | 无额外筛选 | `getAdminUsers({})` |
| `banned` | 点击 Tab | `status=BANNED` | `getAdminUsers({ status: 'BANNED' })` |
| `nostream` | 点击 Tab | `can_stream=false` | 前端过滤（API 不支持该参数时降级） |

### 3.3 卡片区域说明

每张用户卡片包含 4 行信息：

```
行 1: [头像占位] 用户名 (昵称)
      左上角带序号标记（仅在搜索时有用）

行 2: [角色标签] [状态标签]   开播: ✅/❌
      角色标签颜色: REGULAR=灰, MODERATOR=蓝, ADMIN=绿, SUPERADMIN=金
      状态标签颜色: NORMAL=绿, BANNED=红, DELETED=灰, PENDING_REVIEW=黄

行 3: email · 注册于 YYYY-MM-DD
      email 缺失时只显示注册时间

行 4: 操作按钮区（根据用户状态和角色决定可用操作）
```

### 3.4 操作按钮规则

| 用户角色 | 用户状态 | 可用操作 | 说明 |
|---------|---------|---------|------|
| REGULAR / MODERATOR | NORMAL | [封禁] [开播] [编辑] | 正常运营操作 |
| REGULAR / MODERATOR | BANNED | [**解封**] [开播] [编辑] | 封禁后可解封 |
| REGULAR / MODERATOR | DELETED | 只读（无操作按钮） | 已注销用户不可操作 |
| ADMIN | 任意 | [开播] [编辑] | 不能封禁同级ADMIN |
| SUPERADMIN | 任意 | 只读（"不可操作"文字） | 最高权限不可控 |

操作按钮文案：

| 按钮 | 默认文案 | 状态切换后文案 |
|------|---------|--------------|
| 封禁/解封 | 用户 NORMAL → 点击"封禁" | 用户 BANNED → 按钮变为"解封" |
| 开播 | `can_stream=true` → 点击"关闭开播" | `can_stream=false` → 点击"允许开播" |
| 编辑 | 打开编辑弹窗 | — |

### 3.5 选择模式

| 操作 | 交互 |
|------|------|
| 进入 | 点击顶部 **[选择]** |
| 选择 | 每张卡片左侧出现圆形 checkbox，点击切换选中 |
| 全选/取消 | 底栏 **[全选]** |
| 批量操作 | 底栏 **[批量封禁]** / **[批量关闭开播]**（0 项时灰显） |
| 退出 | 顶部 **[取消]** / 操作完成自动退出 |

## 四、数据流

### 4.1 列表加载

```
loadUsers(refresh)
  ├─ refresh=true → page=1, users=[]
  ├─ params: { page, size=20 }
  │   ├─ activeTab === 'banned' → { status: 'BANNED' }
  │   ├─ searchKeyword → { username: keyword }（优先） 或 { email: keyword }
  │   ├─ selectedRole → { role: selectedRole }
  │   └─ selectedStatus → { status: selectedStatus }
  ├─ 调 getAdminUsers(params)
  │   └─ 返回 { code, data: { total, items[] } }
  └─ 赋值到 users ref
```

### 4.2 操作流程

```
用户点击"封禁" → uni.showModal 确认 → updateAdminUser(id, { status: 'BANNED' })
  ├─ 成功 → 更新本地卡片状态（status='BANNED'，按钮变为"解封"）
  │         → 后端自动触发 session revocation（旧 token 失效）
  └─ 失败 → 403 → toast "不能修改更高权限用户"
            → 其他 → toast error.message

用户点击"开播" → uni.showModal 确认 → updateAdminUser(id, { can_stream: true/false })
  ├─ 成功 → 更新本地卡片状态（can_stream 切换，图标变化）
  └─ 失败 → 同封禁

用户点击"编辑" → ModalDialog 弹出 → 选择角色 → updateAdminUser(id, { role: '...' })
  ├─ 成功 → 更新本地角色标签
  └─ 失败 → 同封禁
```

## 五、接口定义

### 5.1 GET /admin/users — 用户列表

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|:----:|:----:|------|
| `page` | int | 否 | 1 | 页码 |
| `size` | int | 否 | 10 | 每页数量（最大 100） |
| `sort` | string | 否 | `created_at:desc` | 排序字段 |
| `username` | string | 否 | — | 用户名模糊搜索 |
| `email` | string | 否 | — | 邮箱精确搜索 |
| `role` | string | 否 | — | REGULAR/MODERATOR/ADMIN/SUPERADMIN |
| `status` | string | 否 | — | NORMAL/BANNED/DELETED/PENDING_REVIEW/REJECTED |

**成功响应**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 100,
    "page": 1,
    "size": 10,
    "items": [
      {
        "public_id": "uuid",
        "username": "user1",
        "nickname": "用户一",
        "email": "user1@example.com",
        "phone_number": null,
        "avatar_url": null,
        "bio": null,
        "role": "REGULAR",
        "status": "NORMAL",
        "can_stream": true,
        "is_email_verified": true,
        "is_phone_verified": false,
        "last_login_at": "2026-07-29T10:00:00",
        "created_at": "2026-01-15T08:00:00",
        "updated_at": "2026-07-29T10:00:00"
      }
    ]
  }
}
```

**错误响应**：
- `500 { "code": 1002, "message": "数据库查询错误" }`

### 5.2 PATCH /admin/users/{public_id} — 修改用户

| 请求字段 | 类型 | 必填 | 说明 |
|---------|------|:----:|------|
| `role` | string | 否 | REGULAR/MODERATOR/ADMIN/SUPERADMIN |
| `status` | string | 否 | NORMAL/BANNED |
| `can_stream` | bool | 否 | true/false |

**成功响应**：`{ code: 0, data: { ...updated UserResponse } }`

**错误响应**：
- `404 { "code": 2004, "message": "用户不存在" }`
- `403 { "code": 3002, "message": "无权修改更高权限用户" }`
- `500 { "code": 1002, "message": "数据库查询错误" }`

## 七、管理能力与后端支持度对照

| 管理能力 | 后端支持 | 实现方式 |
|---------|:--------:|---------|
| 用户分页列表 | ✅ | `GET /admin/users?page=&size=` |
| 用户名搜索 | ✅ | 参数 `username`，后端模糊搜索 |
| 邮箱搜索 | ✅ | 参数 `email`，后端精确匹配 |
| 角色筛选 | ✅ | 参数 `role` |
| 状态筛选 | ✅ | 参数 `status` |
| 封禁用户 | ✅ | `PATCH { status: 'BANNED' }` + 自动吊销 |
| 解封用户 | ✅ | `PATCH { status: 'NORMAL' }` |
| 切换开播权限 | ✅ | `PATCH { can_stream: true/false }` |
| 修改角色 | ✅ | `PATCH { role: '...' }` |
| 权限保护（不能改 SUPERADMIN） | ✅ | 后端返回 403/3002 |
| 会话吊销 | ✅ | status/role/can_stream 变更自动触发 |
| `can_stream` 筛选 | ⚠️ 参数存在但 CRUD 层未 wiring | 通过 Tab + 前端过滤降级 |
| 昵称搜索 | ❌ 后端不支持 | 通过用户名搜索间接覆盖 |

## 八、约束与风险

### 8.1 权限约束

| 约束 | 处理方式 |
|------|---------|
| ADMIN 不能修改 SUPERADMIN | 后端返回 403/3002，前端展示"不能修改更高权限用户" |
| ADMIN 不能提升他人为 SUPERADMIN | 编辑弹窗中隐藏 SUPERADMIN 选项 |
| 管理员不能操作自己 | 前端检查 `authStore.user?.user_id !== item.public_id` |
| 已注销（DELETED）用户不可操作 | 卡片不显示操作按钮，只展示只读信息 |

### 8.2 风险

| 风险 | 概率 | 缓解 |
|------|:----:|------|
| `can_stream` 参数后端未 wiring | 中 | 前端 Tab「无开播权限」从全量数据中过滤 |
| `updateAdminUser` 返回 3002 且无法区分具体原因 | 低 | toast 展示后端 message 原文 |
| 用户列表数据量大（上千用户） | 低 | 分页默认 20 条/页，后端限制最大 100 条 |
| `code: 0` 与前端常用的 `code === 200` 不一致 | 中 | `AdminApiResponse` 类型兼容两种 code |
