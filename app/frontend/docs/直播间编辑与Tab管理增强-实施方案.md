## 一、背景与目标

### 1.1 需求来源

用户端/管理员端编辑直播间时，目前只能编辑：标题、简介、封面、私密状态（及编辑页内已有分类/场次时间等）。缺失以下运营能力：

| # | 能力 | 归属建议（用户确认） |
|:-:|------|---------------------|
| 1 | 标签添加/去除 | 编辑页（edit.vue） |
| 2 | 分类调整 | 编辑页（**已有**，确认保持） |
| 3 | 关联专家调整（去除/更换） | Tab 管理页 |
| 4 | 关联品牌调整（去除/更换） | Tab 管理页 |

### 1.2 已核实的关键事实（2026-08-12 源码复核）

1. **Tab 类型**：后端 `live_room_tabs.content_type ENUM('text','image','mixed')`，无 list 类型；专家/品牌/聊天 Tab 本质是**数据驱动 Tab**。
2. **占位记录真相**：创建直播间流程（`create.vue:1230-1290`）在关联专家/品牌后会创建**占位 Tab 记录**（`tab_key='experts'/'brands'`，title"专家介绍"，content_type mixed，text_content 为占位文字），chat Tab 始终创建。LiveView 渲染按 `tab.key` 分支接管（`LiveView.vue:157-173`），**占位文字永不展示**——TabManager 中编辑这些文字无实际作用（改造动因）。
3. **LiveView 兜底**：`LiveView.vue:1162-1218` 若无对应 Tab 记录但关联数据存在，自动注入 fallback Tab（`fallback-experts` 等）——删除数据 Tab 记录不会导致卡片消失。
4. **API 全部就绪**（后端无需改动）：

| 能力 | 读 | 写 | 路由 | 权限 |
|------|-----|-----|------|------|
| 标签 | `getSessionTags` | `setSessionTags`(replace) | POST /sessions/{id}/tags | 登录用户（后端仅校验登录，无 owner 校验） |
| 专家 | `getSessionExperts` | `setSessionExperts` | POST /experts/sessions/{id}/experts | ✅ 房主/管理员（check_room_owner_or_admin） |
| 品牌 | `getRoomBrands` | `bindRoomBrands` | POST /admin/rooms/{id}/brands | ✅ 房主/管理员（v1.1 已确认，原"待验证"解除） |
| 分类 | `getRoomCategories` | updateRoom `category_ids` / `removeRoomCategory` | PATCH /rooms/{id} | 房主 |

5. **创建页可复用参考**：`create.vue` 的专家多选（上限 5，主讲/嘉宾 role）、标签多选（上限 5）、品牌多选（`getBrands({limit:100})`）、`getExperts({page:1,size:100})`、`getTags()` 选择器交互。

## 二、后端核查结论（v1.1 新增，2026-08-12 只读核查 `D:\live-streaming-saas-v2-main`）

### 2.1 权限模型：所有写接口统一 `check_room_owner_or_admin`（permissions.py:32-52）

**规则：ADMIN/SUPERADMIN 或 `room.user_id == user_id`（房主）放行，否则 403（code 3003）**。唯一例外是标签接口（见 2.2）。

|------|---------|------|------|
| `bind_room_brands` POST /admin/rooms/{id}/brands | brand.py:644 → brand_service.py:609-626 | owner/admin（`check_room_owner_or_admin`） | ✅ **C1 解除** |

| `set_session_tags` POST /sessions/{id}/tags | content_management.py:774 → content_management_service.py:1087 | 仅登录用户（REGULAR 即可） | ⚠️ 宽松点 |
| Tab 管理（列/建/改/删） | live_features.py:79/155/195/279/360 → live_features_service.py:194 | owner/admin | ✅（与 room-tabs 页前端放行一致） |

### 2.2 业务细节确认

1. **品牌绑定**：`brand_ids` 允许空=清空（天然支持"去除全部"）；批量校验 `is_active=True`；房间不存在 404
2. **专家设置**：角色白名单 **`["主讲","主持","嘉宾"]`**（创建页仅用"主讲/嘉宾"，"主持"为后端合法角色）；上限 100 人；校验专家存在且 `is_active`
3. **标签设置**：校验 tag_ids 全部存在（**不校验 is_active**——前端需自行过滤禁用标签）；**无 owner 校验**（任何登录用户可改任意场次标签，前端按房主/管理员展示 UI 即可）
4. **Tab 类型**：`LiveRoomTabContentType = text/image/mixed`（models/live_features.py:28-32），无 list 类型
5. **公开读 Tabs**：`get_active_by_room_id` 只返回 **is_active=True**（live_features.py:873）→ **C2 解除：数据 Tab 的"启停"开关有效**
6. **公开读**：品牌 `get_room_brands_public`（brand.py:729）、专家 `get_session_experts`（experts.py:1079）、标签 `get_session_tags`（content_management.py:820）均 Public + Optional Auth

### 2.4 标签写权限结论（v1.2，用户确认：本次不加后端校验）

**后端现状**：
- **创建标签**（标签库）：仅管理员（`check_admin_permission`，content_management_service.py create_tag）
- **关联标签**（给场次挂标签）：仅校验登录（`_check_write_permission`，REGULAR 即可），**无 owner 校验**（content_management_service.py:1090）

**前端入口不可达论证（2026-08-12 全局排查）**：
- App 端 `setSessionTags` 调用点仅 2 处：`create.vue:1277`、`CreateLiveDrawer.vue:1264`——均为**房主操作自己刚创建的房间**
- 编辑页（edit.vue）仅能从自己的 live-manage 列表进入；Tab 管理页有 owner 校验（room-tabs/index.vue:30-55）；管理端需 admin 角色
- 后端无其他内部调用（endpoint→service→crud 单链路）

**结论：当前业务风险为零（宽松点不可达），本次不加后端 owner 校验**。理由：改动需后端协作/部署，为防御当前不可达的风险点投入产出比不划算；且公开的标签库读取接口（get_tags）不受任何校验影响，不存在"关联不了"问题。

**已知事项登记（未来触发条件）**：若未来新增任何**非房主可管理他人直播间**的前端入口（如管理端批量运营、讲师协作），必须先补 `set_session_tags` 的 `check_room_owner_or_admin` 校验（与专家/品牌对齐，约 2-3 行），否则该入口将无校验。

**本次前端约束（无成本）**：编辑页标签区块与 Tab 管理页的可编辑 UI 仅房主/管理员展示（与 room-tabs 页同思路），后端保持现状。
