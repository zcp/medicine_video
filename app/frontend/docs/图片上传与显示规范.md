## 一、规范概述

### 1.1 适用范围

本规范适用于所有需要上传和显示图片的功能模块，包括但不限于：
- 品牌Logo上传与显示
- 专家头像上传与显示
- 直播间封面图上传与显示
- 直播间 Tab 图上传与显示（LiveView 内 Tab 图片，与封面独立接口，多 Tab 多图互不覆盖）
- 专题横幅图上传与显示
- 其他图片资源的上传与显示

### 1.2 技术栈要求

- ✅ **uni-app + Vue3** 项目（支持H5、小程序、APP等多端）
- ✅ **Vue3 + Element Plus** 项目（H5管理后台）
- ✅ 其他基于 Vue3 的前端项目

### 1.3 核心原则

1. **统一API实现**：优先使用 `uni.uploadFile` API，兼容所有uni-app平台
2. **相对路径转换**：后端返回相对路径时，前端必须转换为完整HTTP URL
3. **文件验证**：前端必须进行文件类型和大小验证，兼容blob URL场景
4. **错误处理**：提供清晰的错误提示和重试机制
5. **用户体验**：提供图片预览、上传进度提示等交互反馈
6. **多端适配**：确保在所有平台（H5、小程序、APP）正常工作

## 二、多端支持说明

### 2.1 uni-app 多端支持

#### 2.1.1 统一实现方式（推荐）

**核心原则**：使用 `uni.uploadFile` API，它在所有uni-app平台（H5、小程序、APP）都能正常工作。

**优势**：
- ✅ 一套代码，多端运行
- ✅ 无需环境判断
- ✅ 自动处理平台差异
- ✅ 代码简洁，易于维护

**实现方式**：
```typescript
// 统一使用 uni.uploadFile，适用于所有平台
uni.uploadFile({
  url: uploadUrl,
  filePath: filePath,  // uni-app会自动处理不同平台的路径格式
  name: 'file',
  header: {
    Authorization: `Bearer ${token || ''}`,
  },
  success: (res) => {
    // 处理响应
  },
  fail: (error) => {
    // 处理错误
  },
});
```

#### 2.1.2 平台差异说明

| 平台 | 文件路径格式 | uni.uploadFile支持 | 备注 |
|------|------------|-------------------|------|
| H5 | `blob:http://...` 或本地路径 | ✅ 完全支持 | blob URL会自动处理 |
| 微信小程序 | 临时文件路径 | ✅ 完全支持 | 自动处理临时文件 |
| APP | 本地文件路径 | ✅ 完全支持 | 自动处理本地文件 |
| 其他小程序 | 临时文件路径 | ✅ 完全支持 | 自动处理临时文件 |

**结论**：`uni.uploadFile` 在所有平台都能正常工作，无需特殊处理。

### 2.2 纯H5项目（非uni-app）

#### 2.2.1 使用 FormData + fetch（可选）

如果项目不使用uni-app，而是纯Vue3 + Element Plus的H5项目，可以使用 `FormData` + `fetch`：

```typescript
// 仅适用于纯H5项目（非uni-app）
export const uploadImageH5 = async (
  entityId: string,
  file: File
): Promise<{ image_url: string }> => {
  const { getToken } = await import('@/store/auth');
  const token = getToken();
  const { getEnv } = await import('@/utils/env');
  const BASE_URL = getEnv('VITE_BASE_API_URL', 'http://localhost:8000/api/v1');
  const uploadUrl = `${BASE_URL.replace(/\/+$/, '')}/admin/entities/${entityId}/image`;
  
  const formData = new FormData();
  formData.append('file', file);
  
  const response = await fetch(uploadUrl, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${token || ''}`,
      // 注意：不要设置 Content-Type，让浏览器自动设置（包含boundary）
    },
    body: formData,
  });
  
  const data = await response.json();
  if (data.code === 200 && data.data) {
    return data.data;
  } else {
    throw new Error(data.message || '图片上传失败');
  }
};
```

**注意**：此方式仅适用于纯H5项目，不适用于uni-app项目。

## 三、图片上传规范

### 3.1 API封装规范

#### 3.1.1 统一使用 uni.uploadFile（uni-app项目）

**要求**：所有uni-app项目的图片上传API必须统一使用 `uni.uploadFile`。

**API函数模板**：

```typescript
/**
 * 上传图片（示例：品牌Logo）
 * POST /api/v1/admin/brands/{brand_id}/logo
 * @param brandId 品牌ID
 * @param filePath 文件路径（uni.chooseImage返回的tempFilePaths[0]）
 * @returns Promise<{ brand_id: string; logo_url: string }>
 */
export const uploadBrandLogo = async (
  brandId: string,
  filePath: string
): Promise<{ brand_id: string; logo_url: string }> => {
  // 1. 获取Token
  const { getToken } = await import('@/store/auth');
  const token = getToken();
  
  // 2. 获取API基础URL
  const { getEnv } = await import('@/utils/env');
  const BASE_URL = getEnv('VITE_BASE_API_URL', 'http://localhost:8000/api/v1');
  const uploadUrl = `${BASE_URL.replace(/\/+$/, '')}/admin/brands/${brandId}/logo`;
  
  // 3. 统一使用 uni.uploadFile（适用于所有uni-app平台）
  return new Promise((resolve, reject) => {
    uni.uploadFile({
      url: uploadUrl,
      filePath: filePath,
      name: 'file',  // 后端接收的文件字段名
      header: {
        Authorization: `Bearer ${token || ''}`,
      },
      success: (res) => {
        try {
          const data = JSON.parse(res.data || '{}');
          if (data.code === 200 && data.data) {
            resolve(data.data);
          } else {
            reject(new Error(data.message || '图片上传失败'));
          }
        } catch (error) {
          reject(new Error('解析响应失败'));
        }
      },
      fail: (error) => {
        reject(new Error(error.errMsg || '图片上传失败'));
      },
    });
  });
};
```

#### 3.1.2 文件位置

- API函数应放在对应的 `src/api/{module}.ts` 文件中
- 例如：品牌Logo上传 → `src/api/brand.ts`
- 例如：专家头像上传 → `src/api/expert.ts`

**直播间相关接口**：封面使用 `POST /rooms/{room_id}/cover`；Tab 图使用 `POST /admin/rooms/{room_id}/tabs/image`（返回 `image_url`）。二者均返回相对路径，前端按 §4 转换；Tab 图与封面独立接口，多 Tab 多图互不覆盖。

### 3.3 文件验证规范

#### 3.3.1 文件类型验证

**允许的格式**：
- JPG / JPEG
- PNG
- GIF

**验证实现**：

```typescript
const selectImage = () => {
  uni.chooseImage({
    success: (res) => {
      const filePath = res.tempFilePaths?.[0];
      if (!filePath) {
        ElMessage.error('未选择文件');
        return;
      }
      
      // ⚠️ 重要：浏览器（H5）环境下，uni.chooseImage 可能返回 blob URL
      // blob URL 没有文件扩展名，需要特殊处理
      const isBlobUrl = filePath.startsWith('blob:');
      if (!isBlobUrl) {
        // 非 blob URL 时，通过扩展名验证文件类型
        const ext = filePath.split('.').pop()?.toLowerCase();
        const allowedExts = ['jpg', 'jpeg', 'png', 'gif'];
        if (ext && !allowedExts.includes(ext)) {
          ElMessage.error('仅支持JPG、PNG、GIF格式的图片');
          return;
        }
      }
      // blob URL 时，跳过扩展名验证，uni.uploadFile 会自动处理文件类型
      
      // 继续文件大小验证...
    },
  });
};
```

**关键点**：
- ✅ 必须检测 blob URL（`filePath.startsWith('blob:')`）
- ✅ blob URL 时跳过扩展名验证
- ✅ 非 blob URL 时进行扩展名验证
- ✅ 小程序和APP环境下，通常会返回有扩展名的路径，可以直接验证

#### 3.3.2 文件大小验证

**最大文件大小**：5MB（5 * 1024 * 1024 bytes）

**验证实现**：

```typescript
// 文件大小验证
uni.getFileInfo({
  filePath: filePath,
  success: (fileInfo) => {
    const maxSize = 5 * 1024 * 1024; // 5MB
    if (fileInfo.size > maxSize) {
      ElMessage.error('图片大小不能超过5MB');
      return;
    }
    
    // 验证通过，设置预览和路径

    selectedImagePath.value = filePath;
    ElMessage.success('已选择图片，保存时将自动上传');
  },
  fail: () => {
    ElMessage.error('获取文件信息失败');
  },
});
```

**平台支持**：
- ✅ H5：支持
- ✅ 小程序：支持
- ✅ APP：支持

### 3.4 上传流程规范

#### 3.4.1 创建时的上传流程

```typescript
const handleSave = async () => {
  // 1. 先创建实体（不带头像/Logo）
  const result = await store.createEntity({
    ...formData,
    image_url: undefined, // 创建时不带图片
  });

  const entityId = result.entity_id;
  
  // 2. 如果有选择的图片，上传图片
  if (selectedImagePath.value) {
    try {
      uploadingImage.value = true;
      const uploadResult = await uploadImage(entityId, selectedImagePath.value);
      
      // 3. 上传成功后更新实体的image_url
      if (uploadResult.image_url) {
        await store.updateEntity(entityId, {
          image_url: uploadResult.image_url,
        });
        ElMessage.success('创建成功，图片已上传');
      }
    } catch (uploadError: any) {
      console.error('图片上传失败:', uploadError);
      ElMessage.warning(`创建成功，但图片上传失败：${uploadError.message || '未知错误'}`);
    } finally {
      uploadingImage.value = false;
    }
  } else {
    ElMessage.success('创建成功');
  }
};
```

#### 3.4.2 编辑时的上传流程

```typescript
const handleSave = async () => {
  // 1. 如果有新选择的图片，先上传图片
  if (selectedImagePath.value) {
    try {
      uploadingImage.value = true;
      const uploadResult = await uploadImage(entityId, selectedImagePath.value);
      
      // 2. 上传成功后更新 formData.image_url
      if (uploadResult.image_url) {
        formData.image_url = uploadResult.image_url;
      }
    } catch (uploadError: any) {
      console.error('图片上传失败:', uploadError);
      ElMessage.error(`图片上传失败：${uploadError.message || '未知错误'}`);
      return; // 图片上传失败，不继续更新其他信息
    } finally {
      uploadingImage.value = false;
    }
  }
  
  // 3. 更新实体基本信息（包含 image_url）
  await store.updateEntity(entityId, formData);
  ElMessage.success('更新成功');
  
  // 4. 重新加载数据，确保显示最新的图片
  await loadEntityData();
};
```

## 四、图片显示规范

### 4.1 URL转换规范

#### 4.1.1 问题说明

**后端返回的图片URL格式**：
- 相对路径：`/media/brands/{brand_id}/logo_{timestamp}.jpg`（常见）
- 绝对路径：`https://example.com/media/brands/.../logo.jpg`（较少见）

**浏览器限制**：
- 浏览器无法直接加载相对路径的图片
- 需要将相对路径转换为完整的HTTP URL

**平台差异**：
- **H5**：必须转换为完整URL
- **小程序**：必须转换为完整URL（使用网络图片）
- **APP**：必须转换为完整URL（使用网络图片）

**结论**：所有平台都需要URL转换，确保统一处理。

#### 4.1.2 转换函数模板

```typescript
import { BASE_API_URL } from '@/constants/api';

// 默认图片
const defaultImage = '/static/default-image.png';

/**
 * 图片URL转换函数（适用于所有平台）
 * @param url 后端返回的图片URL（可能是相对路径或绝对路径）
 * @returns 完整的HTTP URL
 */
const getImageSrc = (url?: string | null) => {
  // 1. 如果URL为空，返回默认图片
  if (!url) return defaultImage;
  
  // 2. 如果已经是完整的HTTP/HTTPS URL，直接返回
  if (/^https?:\/\//.test(url)) return url;
  
  // 3. 相对路径：转换为完整URL
  const base = BASE_API_URL.replace(/\/+$/, ''); // 移除末尾斜杠
  const origin = base.replace(/\/api\/.*/, ''); // 提取origin（如 http://localhost:8000）
  return origin + (url.startsWith('/') ? url : '/' + url);
};
```

**平台适配**：
- ✅ H5：正常工作
- ✅ 小程序：需要使用网络图片URL，此函数返回的完整URL可直接使用
- ✅ APP：需要使用网络图片URL，此函数返回的完整URL可直接使用

#### 4.1.3 使用场景

**必须使用转换函数的场景**：
- ✅ 列表页面（BrandList、ExpertList等）
- ✅ 详情页面（BrandDetail、ExpertDetail等）
- ✅ 编辑页面（BrandEdit、ExpertEdit等）
- ✅ 创建页面（BrandCreate、ExpertCreate等）

### 4.5 图片显示尺寸分层规范（上传预览 vs 正式展示）

同一张图片、同一 URL 在不同使用场景下可采用不同显示尺寸。需区分**上传/编辑时的预览尺寸**与**正式展示时的显示尺寸**，兼顾表单紧凑性与展示体验，并适配多分辨率、多终端。

#### 4.5.1 分层原则

| 场景 | 说明 | 尺寸策略 |
|------|------|----------|
| **上传预览（Preview）** | 创建/编辑表单内的上传区、选择后的预览图 | 固定或受限尺寸，统一规格，便于表单内对齐 |
| **正式展示（Display）** | 直播页、详情页、列表卡片、Tab 内容区等 | 可更大，响应式，随容器或屏幕适配 |

#### 4.5.2 响应式断点（与项目 UI 规范一致）

| 断点 | 范围 | 典型设备 |
|------|------|----------|
| 移动端 | <768px | 手机竖屏 |
| 平板 | 768~1200px | 平板、小屏 PC |
| 桌面 | ≥1200px | PC、大屏 |

#### 4.5.3 上传预览尺寸（按终端与分辨率）

**直播间封面、Tab 图、简介图等 16:9 场景：**

| 终端/分辨率 | 建议尺寸 | 单位 | object-fit |
|-------------|----------|------|------------|
| PC/平板 (≥768px) | 240×135 | px | cover |
| 移动端 (<768px) | 100% 宽，max-width: 200px，aspect-ratio: 16/9 | px | cover |
| 小程序 | 480×270 或 width: 100%; max-width: 480rpx; aspect-ratio: 16/9 | rpx | cover |

**品牌 Logo、专家头像等 1:1 场景：**

| 终端/分辨率 | 建议尺寸 | 说明 |
|-------------|----------|------|
| PC/平板 | 60~80px | 列表/编辑区紧凑预览 |
| 移动端 | 56~64px 或 100% 宽 max-width: 80px | 避免占满屏宽 |
| 小程序 | 120rpx 或按设计稿 | 随屏幕缩放 |

**要点**：
- 同类型图片在同一场景使用统一尺寸，保持视觉一致
- 上传预览区使用 `object-fit: cover`，保证预览区域填满
- 移动端避免固定大尺寸占满屏，建议 `max-width` 限制或 `width: 100%` 配合 max-width

#### 4.5.4 正式展示尺寸（按终端）

| 终端 | 策略 | 说明 |
|------|------|------|
| H5/PC | 响应式：max-width: 100%，高度按 16:9 或 auto | 可大于预览尺寸，随容器缩放 |
| 小程序 | rpx 或 width: 100%，随屏幕适配 | 适配不同机型 |
| APP | 同 H5 | 考虑安全区域 |

**要点**：
- 正式展示可大于上传预览尺寸
- 优先响应式布局，避免固定大图导致溢出

#### 4.5.5 实现示例（H5/PC 响应式）


| 平台 | 建议单位 | 说明 |
|------|----------|------|

```typescript
export const uploadBrandLogo = async (
  brandId: string,
  filePath: string

  const { getToken } = await import('@/store/auth');

        }
      },
```

## 六、常见错误与解决方案

### 6.1 错误一：图片上传失败（"仅支持JPG、PNG、GIF格式的图片"）

**错误现象**：
- 选择JPG/PNG图片后，提示"仅支持JPG、PNG、GIF格式的图片"
- 图片本身是有效的，但验证失败

**错误原因**：
- H5环境下，`uni.chooseImage` 返回 blob URL（如 `blob:http://localhost:8080/xxx`）
- blob URL 没有文件扩展名，使用 `filePath.split('.').pop()` 无法提取扩展名
- 导致验证失败

**解决方案**：
```typescript
// ✅ 正确：检测 blob URL
const isBlobUrl = filePath.startsWith('blob:');
if (!isBlobUrl) {
  const ext = filePath.split('.').pop()?.toLowerCase();
  const allowedExts = ['jpg', 'jpeg', 'png', 'gif'];
  if (ext && !allowedExts.includes(ext)) {
    ElMessage.error('仅支持JPG、PNG、GIF格式的图片');
    return;
  }
}
```

### 6.2 错误二：列表页面图片不显示

**错误现象**：
- 列表页面Logo/头像列显示灰色占位符
- 后端返回正确的 `logo_url`/`avatar_url` 字段
- 详情页面可以正常显示

**错误原因**：
- 后端返回的是相对路径（如 `/media/brands/.../logo.jpg`）
- 列表页面直接使用相对路径，所有平台都无法加载

**解决方案**：
```typescript
// ✅ 正确：使用转换函数
const getLogoSrc = (url?: string | null) => {

  if (/^https?:\/\//.test(url)) return url;

  const origin = base.replace(/\/api\/.*/, '');
  return origin + (url.startsWith('/') ? url : '/' + url);
};

// 在模板中使用
<el-avatar :src="getLogoSrc(row.logo_url)" />
```

### 6.3 错误三：小程序图片不显示

**错误现象**：
- 小程序平台图片不显示
- H5平台正常

**错误原因**：
- 小程序要求所有网络图片必须配置域名白名单
- 未配置域名或域名配置错误

**解决方案**：
1. 在小程序后台配置域名白名单
2. 确保使用完整URL（使用 `getImageSrc` 函数转换）

### 6.4 错误四：APP平台上传失败

**错误现象**：
- APP平台上传失败
- H5和小程序正常

**错误原因**：
- APP平台可能需要特殊权限配置
- 网络请求配置问题

**解决方案**：
1. 检查APP的网络权限配置
2. 确保使用 `uni.uploadFile`（不要使用 `fetch`）
3. 检查API URL是否正确

## 九、注意事项

### 9.1 平台差异

1. **文件路径格式**：
   - H5：可能是 blob URL 或本地路径
   - 小程序：临时文件路径
   - APP：本地文件路径
   - **处理方式**：`uni.uploadFile` 自动处理，无需手动判断

2. **网络图片域名**：
   - 小程序：必须配置域名白名单
   - H5：无限制
   - APP：无限制（但需要网络权限）

3. **图片缓存**：
   - 小程序：会自动缓存，可能需要添加时间戳参数
   - H5：浏览器缓存，可添加时间戳参数
   - APP：系统缓存，可添加时间戳参数

### 9.2 环境判断

**原则**：优先使用统一实现方式（`uni.uploadFile`），避免环境判断。

**仅在必要时使用条件编译**：
```typescript
// #ifdef H5
// H5特定代码
// #endif

// #ifdef MP-WEIXIN
// 微信小程序特定代码
// #endif

// #ifdef APP-PLUS
// APP特定代码
// #endif
```

### 9.3 最佳实践

1. **统一API实现**：使用 `uni.uploadFile`，适用于所有uni-app平台
2. **URL转换**：所有从后端获取的相对路径图片URL都必须转换
3. **blob URL处理**：H5环境下必须特殊处理 blob URL，不能通过扩展名验证
4. **错误处理**：上传失败时，要区分是创建失败还是上传失败，给出不同的提示
5. **数据同步**：编辑后要重新加载数据，确保UI显示最新的图片
6. **平台测试**：在所有目标平台（H5、小程序、APP）进行测试
