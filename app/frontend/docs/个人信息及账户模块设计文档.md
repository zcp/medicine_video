## 1. 文档目的与架构思想

### 1.1 文档目的
本文档旨在为“个人信息展示及账户安全管理”功能提供标准化的开发依据，确保该模块在移动端的视觉层级、交互体验（如滑动吸顶）及API整合符合全站统一规范，避免与现有“我的”Tab页功能耦合与冗余。

### 1.2 架构思想（B站模式）
本模块采用公私域严格分离的设计模型：
- **私域操作台（Dashboard）**：复用现有的 `my/index.vue`，作为纯粹的个人功能入口集散地（操作设置、观看历史、安全入口等）。
- **公开名片页（Profile）**：新建 `profile/index.vue`，作为内容和社交资产的沉淀主页（粉丝数、直播墙、收藏夹等），重在“展示”。

**顶部导航约束（本期）**：
- 视觉参考 B 站导航栏排布，但不实现搜索和分享按钮。
- 保留返回和标题，右侧操作区暂时留空。
- 为保持当前项目风格一致，优先使用 uni-app 标准导航栏能力，不做沉浸式透明导航。

**交互核心：锚点吸顶 (Sticky Scrolling)**
- **场景**：用户上滑屏幕查看 Tab 内的内容列表时。
- **效果**：`ProfileHeader` 会随页面上滑而移出视口，当 `ContentTabs` 触碰到导航栏下沿时，变为 `position: sticky` 固定在屏幕上方。
- **实现**：采用 `scroll-view` 或页面级别 `onPageScroll`，利用 CSS `sticky` 结合自定义导航栏高度实现。

### 3.2 统计数据来源 (Stats Row)

## 4. API调用规范

前后端分离环境调用规则：**前端实际调用路径无需拼接 `/api/v1` 前缀。**

### 4.1 基础资料 API
- **获取当前用户**：
  - 后端：`GET /api/v1/users/me`
  - 前端：`GET /users/me`（已实现：`getCurrentUser`）
- **修改公开资料**：
  - 后端：`PATCH /api/v1/users/me`
  - 前端：`PATCH /users/me` (Payload 仅限 `nickname`, `avatar_url`, `bio` 等展示字段)

**头像能力边界（当前后端现状）**：
- 当前用户模块明确支持的是 `avatar_url` 字段更新（URL写入），不等价于“用户头像文件上传接口”。
- 注册阶段不包含头像上传流程，头像通常在后续编辑资料时通过 `PATCH /users/me` 设置。
- 当前前端可落地能力：
  - 支持填写或选择头像 URL 并提交 `avatar_url`。
  - 不支持直接将手机相册本地文件上传到“用户头像专用端点”（该端点当前未明确提供）。
- 若后续补充用户头像上传API，可复用《图片上传与显示规范》中的 `uni.chooseImage + uni.uploadFile + URL回填 avatar_url` 流程。

### 4.2 安全与凭证 API
- **修改密码**（安全页）：
  - 后端：`POST /api/v1/users/me/password`
  - 前端：`POST /users/me/password` (需验证原密码，新密码强制大、小写+数字+特殊字符，≥8位)
- **换绑手机**（安全页）：
  - 后端：`POST /api/v1/users/me/phone`
  - 前端：`POST /users/me/phone` (依托于先发送 OTP 验证码: `POST /auth/verification-codes`)

### 4.3 内容资产 API (用于 Tabs 数据加载)
- **直播** Tab：`GET /rooms`（当前阶段直接使用通用直播间列表与返回总数）
- **收藏** Tab：`GET /users/me/favorites`（已实现）
- **订阅** Tab：`GET /users/me/subscriptions`（已实现）
- **喜欢** Tab：本期用 `GET /rooms` 的通用返回取前几条作为 Mock 占位。

### 4.4 分阶段实施说明
- **一期（当前）**：完成个人空间页与编辑资料页；直播Tab和直播统计统一使用通用 `/rooms` 数据；喜欢Tab使用通用 `/rooms` 数据Mock占位；粉丝数点击仅提示未开发。
- **二期（后续）**：与忘记密码流程统一实现 `security/index.vue` 与 `账号与安全` 入口；评估并接入按用户维度的直播统计与粉丝/获赞真实数据。

## 5. 移动端开发标准与安全性

### 5.1 CSS 吸顶体验保障 (Sticky Tab)
禁止使用 JS 频繁监听高度并在 DOM 中强行插入/移除节点导致的页面闪动 (Layout Shift)。  
**推荐方案**：
```css
.sticky-tabs {
  position: -webkit-sticky;
  position: sticky;
  /* 此处的top需要结合 uni-app 提供的 var(--window-top) 和 自定义导航栏的高度 */
  top: calc(var(--window-top) + 44px); 
  z-index: 100;
  background-color: var(--bg-primary); /* 吸顶时必须有背景色，防止穿透重透 */
}
```

### 5.2 XSS 与 数据安全性
由于 `bio`（个人简介）和 `nickname`（昵称）完全由用户自由输入并在公开空间页展示，需执行以下约束：
1. **输入限制**：`nickname` 限定 ≤ 50字符，`bio` 限定 ≤ 200字。
2. **渲染安全**：所有展示文字必须采用 Vue 双大括号 `{{ }}` 渲染，**严禁在名片页使用 `v-html`**，从根本上防止跨站脚本注入。
3. **敏感脱敏**：在 `security/index.vue` 展示当前绑定的手机号和邮箱时，必须借助自定义脱敏函数（保留前3后4，如 `138****8000`）；虽然接口已有脱敏能力，前端应执行二次二次兜底逻辑。
