# 直播简介与图文混合 — 统一方案（含 RoomCreate / LiveView）

**版本**: 1.3  
**日期**: 2025-02-02  
**实施**: 已完成（RoomCreate 简介非必 + 始终创建直播介绍 Tab；RoomBasicSettings 解析 Tab 列表兼容 data.items；LiveView 动态列表排除 intro、默认展示「直播介绍」、直播介绍 Pane 图文排版；直播简介图片区「更换图片」按钮）；**直播简介映射到固定 Tab** 见下文。

## 一、后端与设计文档结论

### 1.1 房间 (live_rooms)

- **description**: `TEXT`，设计文档未限定格式。**直播简介采用固定 Tab 后**，对「直播简介」内容而言该字段冗余；可保留做兼容或弃用，不再作为直播简介数据源。
- **封面**: `POST /api/v1/rooms/{room_id}/cover` 上传封面，返回 `cover_url`。无「简介内图片」或通用图片上传接口。

### 1.2 直播间 Tab (live_room_tabs)

- **content_type**: `text | image | mixed`（设计文档 V3 / V6 一致）。设计文档 V3 明确：Tab 用于展示「直播间简介」「医生简介」等。
- **text_content**: `TEXT NULL`；**image_url**: `TEXT NULL`，单图 URL。
- Tab 创建/更新仅接收 `text_content`、`image_url` 等字段。**Tab 图片上传**：`POST /api/v1/admin/rooms/{room_id}/tabs/image`（已实现），返回相对路径 `image_url`，与房间封面上传独立，多 Tab 多图互不覆盖。
- **直播简介 = 固定 Tab**：约定一条固定 `tab_key='intro'`、`title='直播介绍'` 表示「直播简介」；与其它 Tab 同表同结构，支持 text/mixed、文本 + 图片（本地/URL）。**创建房间后前端始终调用 createRoomTab 创建该条**（无内容时传空 text_content/image_url），保证 LiveView 总能从后端取到一条直播介绍 Tab。

### 1.3 最小幅度与一致性

- **Tab 图片本地上传**：使用专用接口 `POST /admin/rooms/{room_id}/tabs/image`，不再复用房间封面上传，避免覆盖房间封面及多 Tab 互相覆盖。
- **直播简介**：通过固定 Tab 编辑/展示，与其它 Tab 一致（类型 + 文本 + 图片 本地/URL）；RoomCreate/RoomBasicSettings 编辑该 Tab，LiveView 固定「直播介绍」Tab 从后端 Tab 列表取该条展示。

### 1.4 行为约定（避免多 Tab、重复展示）

- **RoomCreate**：创建房间后**始终**调用 createRoomTab 创建一条「直播介绍」Tab（无内容时传空），保证 LiveView 总能从后端获取该条。
- **RoomBasicSettings**：解析 getRoomTabList 时兼容 `data.items` 或 `data` 为数组，正确找到 intro 后 updateRoomTab，避免每次保存重复 createRoomTab 导致多个「直播介绍」Tab。
- **LiveView**：动态 Tab 列表（v-for）使用 `customTabs = roomTabs.filter(t => t.tab_key !== 'intro')`，仅固定 Pane 展示「直播介绍」，避免重复展示与布局错乱。

## 二、方案范围与约束

| 项目 | 内容 | 说明 |
|------|------|------|
| 直播简介数据源 | 固定 Tab（约定 tab_key） | 与其它 Tab 同表同结构；不再用 live_rooms.description 存直播简介内容 |
| RoomCreate / RoomBasicSettings 直播简介 | 非必填；支持图文混合 | 编辑固定 Tab：类型 text/mixed、文本、图片「本地选择」「输入URL」；与 LiveView Tab 编辑一致 |
| LiveView 固定「直播介绍」Tab | 展示直播简介 | 从后端 Tab 列表（`roomDetail.tabs` 或 Admin `getRoomTabList`）取 `tab_key=intro` 的那条展示；**动态 Tab 列表（v-for）排除 intro**，仅固定 Pane 展示直播介绍，避免多个「直播介绍」Tab |
| LiveView Tab 编辑 | 类型 text / image / mixed 不变；图片支持「本地选择」「输入URL」 | 与封面一致的双模式；本地上传调用 Tab 专用接口 `POST /admin/rooms/{room_id}/tabs/image` |
| Tab 图片本地上传 | 使用 Tab 图片上传接口 | **与房间封面上传独立**，存储路径为 `/media/rooms/{room_id}/tabs/`，多 Tab 多图互不覆盖 |

### 2.1 与《图片上传与显示规范》的对应关系

- **后端**：图片相关接口**统一返回相对路径**（如 `/media/rooms/{room_id}/cover_xxx.jpg`）。封面上传响应、房间/列表的 `cover_url`、Tab 的 `image_url` 均以相对路径返回，由前端负责转换为完整 HTTP URL。
- **前端**：使用规范中的 **getImageSrc** 逻辑（基于 `BASE_API_URL` 推导 origin）：空→默认或空串；已是 `https?://`→直接返回；否则相对路径→`origin + (url.startsWith('/') ? url : '/' + url)`。所有展示处（列表/详情/编辑/直播页 Tab、封面）均经此转换后再用于 `<img>` / `el-image`。
- **上传与校验**：本地上传统一用 `uni.uploadFile`；文件类型 jpg/jpeg/png/gif，兼容 blob URL（H5 下不做过扩展名校验）；大小 ≤ 5MB；展示优先级：本地预览 > 服务器图片（转换后）> 占位符。
- **效果**：「返回再进入」、多环境、代理场景下图片显示稳定，且与《图片上传与显示规范》一致。

## 三、前端修改（最小幅度）

### 3.1 RoomCreate.vue（ADMIN_FORM）

- **直播简介（固定 Tab）**  
  - 直播简介采用**固定 Tab** 存储，与 LiveView Tab 同结构。  
  - 编辑区：类型（text / mixed）、文本（RichTextEditor 或 textarea）、图片「本地选择」「输入URL」；本地上传调用 `POST /admin/rooms/{room_id}/tabs/image`，得到 `image_url` 写入该 Tab。**本地选择且已有图片时**，在图片下方提供「更换图片」按钮（与点击上传区等效），符合《图片上传与显示规范》3.6。  
  - **提交**：创建房间后**始终**调用 `createRoomTab` 创建一条「直播介绍」Tab（`tab_key=intro`，`title='直播介绍'`）；有内容则带 text_content/image_url，无内容则传空字符串，保证 LiveView 总能从后端获取该条并展示。  
- **与 uni-ui-beauty_v2**  
  - 保持 ADMIN_FORM、分组、label-width、主按钮 Primary；直播简介编辑区（文本+图片）按 ADMIN_FORM 紧凑（min-height 约 160/140px、gap 8px），符合 Profile C；图片区与封面/Tab 一致（本地/URL 双模式），上传区与「更换图片」按钮同容器（如 `.intro-image-block`）。

### 3.2 LiveView.vue（LIVE_VIEW + Tab 编辑弹窗）

- **固定「直播介绍」Tab 内容来源**  
  - 从后端 Tab 列表（`roomDetail.tabs` 或 Admin `getRoomTabList`）取 `tab_key=intro` 的那条展示；无则回退 `roomDetail.description` 或「暂无简介」。展示方式与其它 Tab 一致（按 content_type 展示 text_content、image_url，image_url 经 processImageUrl 转完整 URL）。**默认选中「直播介绍」Tab**（`activeTabKey` 初始为 `builtin-intro`），不点击也可见；无内容时展示「暂无简介」；watch 仅在被删自定义 Tab 时重置回 `builtin-intro`。  
- **直播介绍 Pane 图文排版**  
  - 固定「直播介绍」Pane 内使用 `.intro-tab-card`：正文段落间距（`.intro-text p`）、图片区样式（`.intro-image-wrap` / `.intro-image`），按 LIVE_VIEW 美化，PC/移动共用。  
- **动态 Tab 列表排除 intro**  
  - 使用计算属性 `customTabs = roomTabs.filter(t => t.tab_key !== 'intro')`，PC/移动两处 `v-for` 使用 `customTabs`，避免「直播介绍」在固定 Pane 与动态列表中重复展示、布局错乱。  
- **Tab 编辑弹窗 - 图片**  
  - 当 `content_type` 为 `image` 或 `mixed` 时，将单一「图片链接」输入框改为与 RoomCreate 封面一致的**双模式**：  
    - 模式切换：`el-radio-group`「本地选择」「输入URL」。  
    - **输入URL**：保留 `el-input` 绑定 `currentTabForm.image_url`，placeholder「输入图片 URL」。  
    - **本地选择**：点击上传区 → `uni.chooseImage` → 调用 `POST /admin/rooms/{room_id}/tabs/image` 上传 → 将返回的 `image_url` 赋给 `currentTabForm.image_url`。  
  - **注意**：使用 Tab 专用上传接口，与房间封面上传独立，多 Tab 多图互不覆盖。  
- **roomId**  
  - 使用 `currentSession.value?.room_id`，与现有 `saveTab`、`createRoomTab` 一致。  
- **与 uni-ui-beauty_v2**  
  - Tab 防溢出、弹窗内表单控件规范（圆角、focus）；上传区样式与封面区一致（token、间距）。

### 3.3 统一交互约定

- 所有「单图输入」（封面、Tab 图片、**直播简介固定 Tab 的图片**）：  
  - 模式切换「本地选择」「输入URL」；  
  - 本地：选择文件 → 上传得到 URL（Tab 图片用 `POST /admin/rooms/{room_id}/tabs/image`）→ 写入对应字段；**已有图片时**在图片下方提供「更换图片」按钮（与点击上传区等效），符合《图片上传与显示规范》3.6。  
  - URL：输入框 + 可选预览。  
- 直播简介 = 固定 Tab，图文与其它 Tab 一致（类型 + 文本 + 图片 本地/URL），满足《图片上传与显示规范》。

## 四、实施顺序与自检

1. **文档**：本方案写入 `docs/直播简介与图文混合-统一方案.md`（已完成）。  
2. **RoomCreate**：创建房间后**始终** createRoomTab 一条「直播介绍」Tab（有/无内容皆创建）；**RoomBasicSettings**：解析 Tab 列表时兼容 `data.items` 或 `data` 直接为数组，找到 intro 则 updateRoomTab、否则 createRoomTab，避免每次保存重复创建。  
3. **LiveView**：固定「直播介绍」从后端 Tab 列表取 `tab_key=intro` 的那条展示；**默认选中「直播介绍」Tab**，不点击也可见；**动态列表使用 customTabs（排除 intro）**；直播介绍 Pane 内图文排版按 LIVE_VIEW（`.intro-tab-card`）；Tab 编辑弹窗内图片改为双模式（本地/URL），本地上传调用 Tab 图片上传接口 `POST /admin/rooms/{room_id}/tabs/image`。  
4. **自检**：直播简介（固定 Tab）选填可提交；图文（文本+图片 本地/URL）可保存并展示；Tab 图片 URL 与本地选择均可保存；与《直播间开始时间与回放-完整实施方案》无冲突。  
5. **图片规范自检**：封面上传/Tab 图片接口返回均为相对路径；前端仅存相对路径；列表/详情/编辑/直播页均通过 getImageSrc/processImageUrl 显示；本地上传均做类型+大小+blob 校验。  
6. **直播简介 = 固定 Tab**：前后端约定 tab_key（如 intro/room）；RoomCreate/RoomBasicSettings 编辑该 Tab；LiveView 固定「直播介绍」从 tabs 取该条展示。

## 六、设计文档需更新内容（后端）

在《直播核心功能设计文档_v6_深度融合最终版.md》中建议补充：

- **路由表**（Section 1）：新增一行  
  `tabs-admin | POST /api/v1/admin/rooms/{room_id}/tabs/image | JWT | ADMIN/SUPERADMIN | file (multipart) | { image_url } | 400/403/404 | 本文 | Tab 图片上传，与房间封面上传独立`
- **API 规范**（Tab 管理 API 小节）：新增 **2.1.1 Tab 图片上传**  
  - **Endpoint**: `POST /api/v1/admin/rooms/{room_id}/tabs/image`  
  - **权限**: `role ∈ {ADMIN, SUPERADMIN}`  
  - **请求**: Path 参数 `room_id`；Body 为 `multipart/form-data`，字段 `file` 为图片文件。  
  - **成功响应（200）**: `success_response(data={ "image_url": "/media/rooms/{room_id}/tabs/tab_{uuid}_{timestamp}.{ext}" })`（相对路径）。  
  - **说明**: 存储路径为 `/media/rooms/{room_id}/tabs/`，每次上传独立文件，不覆盖房间封面，多 Tab 多图互不覆盖。
