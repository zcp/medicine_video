## 2. 文档目的与项目背景

### 2.1 文档目的

本设计文档旨在为"医学直播SaaS平台"移动端搜索功能提供系统性、标准化的设计与开发指导，确保：

1. **用户体验优先**：参考B站成熟设计，提供流畅、直观的搜索体验
2. **移动端优化**：针对触屏操作、弱网环境、流量消耗等移动端特性进行优化
3. **前后端协作高效**：明确API调用规范、数据结构、错误处理等，减少沟通成本
4. **代码质量可控**：提供完整的技术实现方案、组件设计、性能优化建议

### 2.2 项目背景

- **技术架构**：前后端分离，后端接口详见《后端新增api接口和模块设计文档-v2.md》
- **前端技术栈**：基于 uni-app 框架，支持H5、Android App、iOS App、微信小程序等多端部署
- **设计参考**：借鉴Bilibili、抖音等主流视频平台的搜索页面设计，结合医学直播专业场景需求
- **核心目标**：打造专业、高效且符合移动用户习惯的医学直播搜索功能

### 2.3 设计原则

1. **移动优先 (Mobile First)**：所有设计从移动端场景出发，考虑触屏操作、单手使用、弱网环境
2. **搜索效率优先**：提供热门搜索、搜索历史、自动补全，减少用户输入成本
3. **结果展示完整**：四个Tab（综合/直播间/专家/品牌），信息层次清晰
4. **性能优化**：搜索防抖、结果缓存、图片懒加载、虚拟滚动
5. **降级友好**：无结果时提供推荐内容，避免空白页面
6. **Design System统一**：严格遵循全站设计语言（色彩、字体、间距、动效）

## 3. 移动端开发规范

### 3.1 代码规范

#### 3.1.1 基础规范
- **统一风格**：全项目采用 ESLint + Prettier 自动格式化，统一2空格缩进，单引号，无分号
- **TypeScript 强制**：所有新开发页面和组件必须使用 TypeScript，类型声明完整
- **组件化开发**：搜索页面拆分为SearchBar、SearchLanding、SearchResults、RoomCard、ExpertCard等小型组件
- **禁止魔法数字**：所有常量、枚举、配置项集中管理（如 `src/common/constants.ts`）
- **注释规范**：关键业务逻辑、接口调用、复杂计算必须有中文注释，函数/组件需有JSDoc风格注释

#### 3.1.2 移动端特有规范
- **触摸优化**：
  - 所有可点击元素最小尺寸 ≥ 44x44px（iOS规范）或 48x48dp（Android规范）
  - 热门搜索标签、历史记录列表项间距 ≥ 8px，避免误触
- **手势支持**：
  - 支持滑动返回（iOS）
  - 搜索框支持长按清空
- **性能优化**：
  - 搜索结果列表使用虚拟滚动（超过50项）
  - 图片懒加载（封面图、专家头像）
  - 搜索防抖300ms，避免频繁请求

### 3.2 命名规范

## 4. API调用说明（重要）

### 4.1 前端API路径规则

**Base URL配置**（`.env.development`）：
```bash
VITE_BASE_API_URL=https://mp.dayilive.com/api/core
```

**前端调用规则**：
```
实际请求URL = Base URL + API路径（去掉 /api/v1 前缀）
```

**示例对比**：

| 后端接口文档 | 前端实际调用 | 最终请求URL |
|------------|------------|------------|
| `GET /api/v1/search/suggestions` | `GET /search/suggestions` | `GET https://mp.dayilive.com/api/core/search/suggestions` |
| `GET /api/v1/homepage/rooms` | `GET /homepage/rooms` | `GET https://mp.dayilive.com/api/core/homepage/rooms` |
| `POST /api/v1/experts/{id}/follow` | `POST /experts/{id}/follow` | `POST https://mp.dayilive.com/api/core/experts/{id}/follow` |

**Nginx转发说明**：
- 前端请求：`https://mp.dayilive.com/api/core/search/suggestions`
- Nginx转发到后端：`/api/v1/search/suggestions`
- 后端处理：`GET /api/v1/search/suggestions`

**代码示例**：
```typescript
// ❌ 错误：不要在前端代码中包含 /api/v1
const res = await api.get('/api/v1/search/suggestions?limit=6');

// ✅ 正确：直接使用去掉 /api/v1 的路径
const res = await api.get('/search/suggestions?limit=6');
```

> **注意**：本文档后续章节中的API路径以**后端接口文档格式**（`/api/v1/...`）标注，方便与后端文档对照。前端开发时请按照上述规则**去掉 `/api/v1` 前缀**进行调用。

   - **点击行为**：填充关键词并跳转到搜索结果页
   - **删除功能**：单条删除、全部清空
   - **数据格式**：`{ keyword: string, timestamp: number }`

## 8. 移动端安全规范（搜索场景）

### 8.1 XSS防护（跨站脚本攻击）

**搜索场景特别注意**：用户输入的搜索关键词、搜索结果（标题、描述）可能包含恶意脚本

**防护措施**：
- **禁止使用 `v-html`**：直接渲染搜索关键词或API返回内容
- **必须使用 Vue 插值**：`{{ searchKeyword }}` 自动转义HTML标签
- **敏感场景**：搜索关键词、直播标题、专家姓名、品牌名称等必须进行HTML转义

**示例代码**：
```vue
<!-- ✅ 正确：使用插值表达式自动转义 -->
<text class="keyword">{{ searchKeyword }}</text>
<text class="title">{{ room.title }}</text>

<!-- ❌ 错误：使用v-html可能导致XSS -->
<view v-html="searchKeyword"></view>
```

### 8.2 敏感信息脱敏

搜索结果中可能涉及敏感信息，前端必须严格脱敏：

| 信息类型 | 脱敏规则 | 示例 |
|---------|---------|------|
| 专家手机号 | 保留前3后4位 | `138****5678` |
| 专家邮箱 | 保留前2位@后全部 | `li***@hospital.com` |
| 患者姓名（如显示在病例直播标题中） | 仅显示姓+脱敏 | `张**` |
| 医生姓名 | 完整显示（医学平台特性） | `张三 主任医师` |

**实现位置**：`src/utils/security.ts` 中封装脱敏函数

### 8.3 Token安全存储

**搜索功能涉及**：
- 搜索历史记录（需用户登录）
- 专家关注功能（需用户登录）
- 个性化推荐（需用户登录）

**Token使用规范**：
- 使用 `uni.setStorageSync` 加密存储Token（小程序端）
- Token仅存于内存，页面刷新后重新登录（H5端）
- Token过期处理：检测到401错误时，清除Token并跳转登录页

### 8.4 API请求安全

#### 8.4.1 强制HTTPS
所有搜索API请求必须使用 `https://` 协议

#### 8.4.2 Token自动注入
在 `src/api/request.ts` 的请求拦截器中自动注入Token

#### 8.4.3 接口鉴权
前端需校验API返回的权限状态码：

| 状态码 | 含义 | 前端处理 |
|-------|------|---------|
| 401 | 未登录/Token过期 | 清除Token，跳转登录页 |
| 403 | 无权限（如：关注专家需要登录） | Toast提示"请先登录"，跳转登录页 |
| 429 | 请求频率限制（防刷搜索接口） | Toast提示"搜索过于频繁，请稍后再试" |
| 500+ | 服务器错误 | Toast提示"搜索服务异常，请稍后重试" |

### 8.5 日志脱敏

**禁止上报的搜索日志**：
- ❌ 用户搜索关键词原文（可能包含患者信息、病情关键词）
- ❌ 完整的API请求/响应体

**允许上报的日志**：
- ✅ 搜索功能使用频率（不含关键词）
- ✅ 搜索结果点击行为（卡片ID，不含标题）
- ✅ 搜索性能指标（搜索耗时、结果数量）

### 10.2 搜索结果缓存

**优化目标**：减少重复请求，提升响应速度

```typescript
// 缓存最近10次搜索结果，5分钟过期
const searchCache = new Map<string, {
  data: any[];
  timestamp: number;
}>();

const CACHE_EXPIRE_TIME = 5 * 60 * 1000; // 5分钟

async function performSearch(keyword: string) {
  // 检查缓存
  const cached = searchCache.get(keyword);
  if (cached && Date.now() - cached.timestamp < CACHE_EXPIRE_TIME) {
    searchResults.value = cached.data;
    return;
  }
  
  // 调用API
  const res = await api.get('/search', { params: { q: keyword } });
  searchResults.value = res.data.items;
  
  // 更新缓存
  searchCache.set(keyword, {
    data: res.data.items,
    timestamp: Date.now()
  });
  
  // 限制缓存数量
  if (searchCache.size > 10) {
    const firstKey = searchCache.keys().next().value;
    searchCache.delete(firstKey);
  }
}
```

```typescript
  page.value += 1;
  
  try {
    const res = await api.get('/search', {
      params: {
        q: keyword.value,
        page: page.value,
        size: 10
      }
    });
    
    searchResults.value.push(...res.data.items);
    hasMore.value = res.data.page < res.data.total_pages;
  } finally {
    isLoading.value = false;
  }
}
```

### 14.3 核心SQL查询

```sql
SELECT 
    lr.id AS room_id,
    lr.title AS room_title,
    lr.cover_url,
    lr.description,
    
    -- 活跃场次信息
    ls.id AS session_id,
    ls.status AS session_status,
    
    -- 专家信息
    e.id AS expert_id,
    e.name AS expert_name,
    e.title AS expert_title,
    e.hospital AS expert_hospital,
    e.avatar_url AS expert_avatar
    
FROM live_rooms lr

-- 找到当前活跃的场次（或最新的场次）
LEFT JOIN LATERAL (
    SELECT * FROM live_sessions
    WHERE room_id = lr.id
    ORDER BY 
        CASE status
            WHEN 'live' THEN 1
            WHEN 'scheduled' THEN 2
            ELSE 3
        END,
        start_time DESC
    LIMIT 1
) ls ON TRUE

-- 找到场次的主讲专家（优先主讲，其次主持、嘉宾）
LEFT JOIN LATERAL (
    SELECT expert_id, role
    FROM live_session_experts lse
    WHERE lse.session_id = ls.id
    ORDER BY 
        CASE role
            WHEN '主讲' THEN 1
            WHEN '主持' THEN 2
            WHEN '嘉宾' THEN 3
        END,
        lse.sort_order
    LIMIT 1
) lse ON TRUE

-- 获取专家详细信息
LEFT JOIN experts e ON lse.expert_id = e.id

WHERE 
    lr.title ILIKE '%肝胆%' OR lr.description ILIKE '%肝胆%';
```

```python
async def _get_room_active_session(
    self,
    db: AsyncSession,
    room_id: UUID
) -> Optional[dict]:
    """
    获取房间的活跃场次
    优先级：live > scheduled > 最新的其他状态
    """
    query = (
        select(LiveSession)
        .where(LiveSession.room_id == room_id)
        .order_by(
            case(
                (LiveSession.status == 'live', 1),
                (LiveSession.status == 'scheduled', 2),
                else_=3
            ),
            LiveSession.start_time.desc()
        )
        .limit(1)
    )
    
    result = await db.execute(query)
    session = result.scalar_one_or_none()
    
    if session:
        return {
            "session_id": session.id,
            "status": session.status
        }
    return None

async def _get_session_host_expert(
    self,
    db: AsyncSession,
    session_id: UUID
) -> Optional[dict]:
    """
    获取场次的主讲专家
    优先级：主讲 > 主持 > 嘉宾
    """
    query = (
        select(Expert)
        .join(LiveSessionExpert, LiveSessionExpert.expert_id == Expert.id)
        .where(LiveSessionExpert.session_id == session_id)
        .order_by(
            case(
                (LiveSessionExpert.role == '主讲', 1),
                (LiveSessionExpert.role == '主持', 2),
                (LiveSessionExpert.role == '嘉宾', 3),
                else_=4
            ),
            LiveSessionExpert.sort_order
        )
        .limit(1)
    )
    
    result = await db.execute(query)
    expert = result.scalar_one_or_none()
    
    if expert:
        return {
            "expert_id": str(expert.id),
            "name": expert.name,
            "avatar_url": expert.avatar_url,
            "title": expert.title,
            "hospital": expert.hospital
        }
    return None
```
