# 我的页面-个人信息区与账号安全页面设计方案

> **文档版本**：v2.0
> **最后更新**：2026-03-23
> **变更说明**：同步手机号绑定功能实现、第三方账号区域 Mock 展示、菜单顺序调整及接口能力对齐。

## 1. 文档目标

本方案用于统一"我的"页面顶部个人信息区与"账号与安全"页面的产品设计和前端实现口径，确保：

1. 个人信息字段展示完整且层级清晰。
2. 敏感信息（邮箱、手机号、密码、注销）集中在账号安全域，避免首页过度暴露。
3. 接口能力与页面能力一一对应，便于分阶段上线。

---

## 2. 个人信息区设计（我的页面顶部）

### 2.1 展示字段（主信息区）

顶部主信息区展示以下字段：

1. 头像
2. 昵称
3. UID（短码）
4. 账号名
5. 个人简介
6. 角色
7. 状态

### 2.2 布局结构（移动端）

采用四行结构，强调"身份信息优先，账号信息次之"：

```text
+--------------------------------------------------+
| [头像]  昵称 dayi                      [编辑资料] |
|        角色：普通用户        状态：✓ 正常         |
|        UID：A1B2C3...D4    账号名：dayi_live      |
|        个人简介：这里是简介，最多两行展示...      |
+--------------------------------------------------+
```

布局说明：

1. 第一行：头像 + 昵称 + 编辑入口（编辑功能标注开发中）。
2. 第二行：角色与状态采用胶囊标签单独展示，提升识别度；状态标签带颜色区分。
3. 第三行：UID 与账号名作为次级信息并列展示。
4. 第四行：个人简介，最多 2 行，超出省略；为空时展示引导文案.

### 2.3 字段映射规则

| 展示字段 | 数据来源 | 备注 |
|---------|---------|------|
| 昵称 | `nickname` | 兜底 `username` |
| UID | `uuid` / `public_id` | 前端调用 `formatShortPublicId()` 显示短码（前 6 后 4） |
| 账号名 | `username` | 直接展示 |
| 头像 | `avatar_url` | 为空显示默认头像 |
| 简介 | `bio` | 为空显示占位文案 |
| 角色 | `role` | 调用 `mapRoleLabel()` 映射文案 |
| 状态 | `status` | 调用 `mapStatusLabel()` + `mapStatusTone()` 映射文案和颜色 |

### 2.4 枚举文案映射

角色（`mapRoleLabel`）：

| 枚举值 | 显示文案 |
|--------|---------|
| `REGULAR` | 普通用户 |
| `MODERATOR` | 房管 |
| `ADMIN` | 管理员 |
| `SUPERADMIN` | 超管 |

状态（`mapStatusLabel` + `mapStatusTone`）：

| 枚举值 | 显示文案 | 颜色语义 |
|--------|---------|---------|
| `NORMAL` | ✓ 正常 | 绿色（`normal`） |
| `PENDING_REVIEW` | 审核中 | 橙色（`warning`） |
| `BANNED` | 已封禁 | 红色（`danger`） |
| `DELETED` | 已注销 | 红灰（`danger`） |
| `REJECTED` | 已拒绝 | 红色（`danger`） |

### 2.5 空值与异常兜底

1. 昵称为空：显示"用户".
2. UID 为空：显示"-".
3. 账号名为空：显示"未设置".
4. 简介为空：显示引导文案（如"还没有写简介～快来介绍一下自己吧！"）.
5. 头像为空：显示默认头像.

## 4. 账号与安全页面设计

### 4.1 页面定位

"账号与安全"用于承载敏感操作，作为设置菜单入口，将"隐私政策"下沉为该页面内的菜单项.

### 4.2 菜单信息架构（当前实现）

页面分为两个分区：

**账号信息区：**

1. 用户 ID（UID）——点击展示完整 UID，支持复制
2. 邮箱——脱敏显示，换绑入口（暂显示"功能开发中"）
3. 手机号——脱敏显示，未绑定时显示"未绑定 · 去绑定"，已绑定显示"换绑"
4. 登录密码——修改密码
5. 隐私政策——进入协议页（WebView）

**第三方账号区（Mock）：**

6. 微信——未绑定（点击 Toast 提示"即将上线"）
7. Apple——未绑定（点击 Toast 提示"即将上线"）

**底部危险区：**

8. 注销账号（红色危险按钮，二次确认）

### 4.3 页面结构

```text
账号与安全
├─ [账号信息]
│  ├─ 用户 ID（UID）     A1B2C3...D4 · 查看（点击复制）
│  ├─ 邮箱               user***@domain.com · 换绑（开发中）
│  ├─ 手机号             138****8888 · 换绑  /  未绑定 · 去绑定
│  ├─ 登录密码           修改密码（→ 修改密码页）
│  └─ 隐私政策           查看协议（→ WebView）
│
├─ [第三方账号]
│  ├─ 微信               未绑定（Toast：即将上线）
│  └─ Apple              未绑定（Toast：即将上线）
│
└─ [危险操作]
   └─ 注销账号（红色按钮，二次确认 → 调用 DELETE /users/me）
```

### 4.4 手机号绑定交互流程

点击"去绑定"或"换绑"跳转至 `bind-phone` 页面，流程如下：

```text
输入手机号（+86）
    ↓
输入图形验证码（点击图片可刷新）
    ↓
点击"发送验证码" → POST /auth/verification-codes
  { channel: "SMS", scenario: "BIND_PHONE", recipient: 手机号,
    captcha_id, captcha_solution }
    ↓
输入 6 位短信验证码（60s 倒计时，可重发）
    ↓
点击"确认绑定" → POST /users/me/phone
  { phone_number, verification_code }
    ↓
成功：更新 authStore 中 phone_number / is_phone_verified，返回上页
```

> **注意**：发送短信 OTP 时必须同步传入图形验证码，后端以此防止滥发.

### 4.5 交互原则

1. 菜单项统一右箭头，点击进入对应流程.
2. 注销账号放底部危险区，颜色警示，点击二次确认.
3. 邮箱与手机号等敏感信息默认脱敏显示（`maskEmail` / `maskPhone`）.
4. 未实现功能显示"开发中" Toast，避免死链.
5. 第三方账号区采用 Mock 占位，后续接入 SSO 后替换真实绑定状态.

## 5. 接口能力对齐

### 5.1 已完整实现的接口

| 功能 | 接口 | 前端实现文件 |
|------|------|------------|
| 获取当前用户信息（含手机号字段） | `GET /users/me` | `api/auth.ts` → `getCurrentUser` |
| 修改公开资料 | `PATCH /users/me` | `api/auth.ts` → `updateCurrentUser` |
| 修改密码 | `POST /users/me/password` | `api/auth.ts` → `changePassword` |
| 注销账户 | `DELETE /users/me` | `api/auth.ts` → `deleteUserAccount` |
| 发送 OTP（邮件/短信） | `POST /auth/verification-codes` | `api/auth.ts` → `sendVerificationCode` |
| 绑定/更换手机号 | `POST /users/me/phone` | `api/auth.ts` → `bindPhone` |

### 5.2 已定义但前端暂未实现的接口

| 功能 | 接口 | 状态 |
|------|------|------|
| 邮箱换绑 | 后端无独立接口（需 EMAIL OTP） | 前端显示"功能开发中" Toast |
| 第三方账号绑定（微信/Apple） | `POST /auth/sso-login` | 前端 Mock，Toast 提示"即将上线" |
| 忘记密码重置 | `POST /auth/password-reset-request` + `POST /auth/password-reset` | 前端未实现，适合 H5 端，App 端暂缓 |
| 会员中心 | `GET/POST/PATCH /users/me/memberships` | 暂不实现 |

### 5.3 隐私政策

1. 隐私政策为静态协议页，不依赖后端业务接口.
2. 通过 WebView 打开（URL 需替换为真实协议地址，当前为占位符）.

## 6. 数据层变更说明

### 6.1 Store 字段（`src/store/auth.ts`）

`User` 接口新增字段：

```typescript
export interface User {
  user_id: string;
  username?: string;
  email?: string;
  phone_number?: string;       // 新增：手机号
  is_phone_verified?: boolean; // 新增：手机号是否已验证
  avatar?: string;
  nickname?: string;
  bio?: string;
  role?: string;
  status?: string;
}
```

`fetchUserProfile` 中已同步映射上述两个字段.

### 6.2 工具函数（`src/utils/userDisplay.ts`）

新增 `maskPhone(phone)` 脱敏函数，规则：`138****8888`（前 3 位 + `****` + 后 4 位）.

### 6.3 类型定义（`src/types/auth.ts`）

新增：

- `SendOtpRequest` — 发送 OTP 请求体（支持 EMAIL / SMS + 业务场景）
- `BindPhoneRequest` — 绑定手机号请求体（`phone_number` + `verification_code`）
- `BindPhoneResponse` — 绑定手机号响应体

### 6.4 路由注册（`src/pages.json`）

新增路由：

```json
{
  "path": "pages/app/tabbar/my/account-security/bind-phone",
  "style": { "navigationBarTitleText": "绑定手机号" }
}
```
