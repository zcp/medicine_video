## 三、问题与优化目标（当前版本强制要求）

========================================================
【问题】
====

1. **仍然“卡片感”明显**：

* 专家介绍、历史直播等 section 使用了**独立浅底背景 + 圆角容器**，形成“盒子分区”。
* 背景出现多层叠加（页面底色 + section 底色 + 内容），导致“卡片式”观感。

2. **分组依赖容器，而非 spacing**：

* section 之间靠“盒子”分隔，而不是留白节奏。
* 与设计文档的“去油腻/去盒子感”要求不一致。

3. **医疗专业感仍可提升**：

* 信息层级与排版仍偏“平台页”，未充分体现“机构感/克制感”。

========================================================
【优化目标（必须执行）】
============

1. **去卡片化（必须）**

* 删除专家介绍、历史直播等 section 的 **SectionCard 容器**（背景色、圆角、阴影全部去掉）。
* 页面保持 **单一背景层**（Background.Base），分组靠 spacing，不靠盒子。

2. **去油腻（必须）**

* Divider 优先删除；必须使用时，仅允许极浅中性（5%~10% 对比）并由 tokens 推导。
* 用 spacing 建立高级感节奏，不使用粗线/厚边框。

3. **Header 信息层级（必须优化）**

* 姓名（最强）
* 职称（次强）
* 医院 | 科室（弱化，secondary/tertiary）
* 右侧收藏/关注（IconButton 或轻量按钮态；已关注/已收藏状态明显但克制）
* 禁止默认亮蓝，选中/强调必须使用 Color.Primary。

4. **专家介绍排版（必须优化）**

* 通过行高、段间距、结构化分段提升可读性（避免一坨长段）。
* 不引入新卡片容器，仅用 Typography + Spacing 建立层级。

5. **Tag（擅长领域）统一（必须）**

* Tag 只允许使用 tokens 推衍：中性底 + 次要文字，不可高饱和抢视觉。

6. **历史直播 EmptyState 收敛（必须）**

* 不能占据半屏“空洞”；应为轻提示型空状态，减少垂直占用。
* 不要空状态卡片背景。

7. **交互与动效（必须）**

* hover / active / focus-visible / disabled 状态齐全
* 动效时长 180–220ms（Motion tokens）
* 避免 layout shift（收藏状态切换、加载态、文本展开等都不抖动）

## 五、必须解决的 UI/UX 问题（针对专家详情页）

1. **SectionCard 去除（去卡片化核心）**

* 禁止专家介绍/历史直播模块使用独立浅灰背景 + 圆角容器
* 禁止给 section 上阴影（避免“漂浮盒子”）

2. **分组方式替换**

* 用 spacing（module spacing / inner spacing）建立结构节奏
* Divider 只在必要处出现，且必须极浅

3. **Header 区块对齐与一致性**

* 收藏/关注 icon 与标题行对齐（视觉中心对齐，而不是整块居中“飘”）

* 空状态应该像“轻提示”，而不是一个大卡片占屏

## 六、必须执行的高级感规则（来自 Design 文档）

* **去油腻**：优先 Spacing 分组；Divider 若必须存在则极浅（5%~10% Neutral）；禁止粗分割线、厚边框。
* **去卡片化**：内容页 section 不应堆叠强卡片（背景块/圆角/阴影）；保持单背景。
* **色彩清洗**：禁止亮蓝主交互色；active/selected/CTA 必须使用 tokens 的品牌主色（Color.Primary）。
* **点击热区**：关注/收藏、tab、列表项等均 ≥44px。
* **动效**：180–220ms，状态完整。
* **避免 layout shift**：状态变化不造成布局跳动。

## 八、实现指导（去卡片化最小 diff 原则）

### 8.1 结构层（必须改）

* 将原 `SectionCard` / `Card` 包裹替换为语义化 `section` 容器：

  * 不要背景块
  * 不要圆角
  * 不要阴影
  * 只使用 spacing

### 8.2 样式层（必须改）

* 删除（或不再应用）以下视觉属性：

  * `background: var(--bg-card)` / 浅灰块
  * `border-radius: ...`（section 容器层）
  * `box-shadow: ...`

* 新增（或强化）以下节奏：

  * `section + section { margin-top: var(--spacing-8); }`
  * 标题与正文间距 `var(--spacing-3/4)`
  * 段落间距 `var(--spacing-3)`
  * 行高提升（由 Typography token/line-height token 决定）

### 8.3 EmptyState（必须改）

* 将 EmptyState 的垂直 padding 收敛到 tokens 中更小等级
* 视觉居中但不占屏（不要半屏大空洞）

### 8.4 第二阶段：高级感打磨（已实施）

* **Header 与正文结构断点**：首 section（专家介绍）使用类 `section--after-header`，`margin-top: calc(4 * var(--home-spacing-page))`，仅用 spacing 形成呼吸点，无卡片、无分割线。
* **Section 间距统一**：普通 section `margin-top: calc(2 * var(--home-spacing-page))`；首 section 为 `calc(4 * var(--home-spacing-page))`，其余 section 之间节奏一致，使用同一 token。
* **专家介绍分段**：`detail.bio` 按 `\n\n` / `\n` 拆成段落数组 `bioParagraphs`，逐段渲染；段落 `line-height: 1.75`（≥1.65）、`color: var(--home-text2)`，段间距 `var(--home-spacing-module)`。
* **Tag 系统化**：擅长领域与角色 Tag 使用 `background: var(--home-bg)`、`color: var(--home-text2)`、`border-radius: var(--home-r-md)`（Radius.Small，克制），字号 `--home-tag-font`（Meta 级）。
* **EmptyState 收敛**：历史直播空状态包在 `.empty-state-inline`，padding/图标/字号进一步缩小，标题与描述弱化（opacity），无卡片背景，不占半屏。
* **星标对齐 name-row**：ExpertProfile 中 `name-row` 使用 `line-height`/`min-height: var(--expert-name-lineheight)`；`.follow-icon-wrap` 使用 `margin-top: calc((var(--expert-name-lineheight) - var(--expert-action-icon-size)) / 2)` 与姓名行视觉中心对齐，无固定/漂浮定位，热区 ≥44px；未关注 Neutral、已关注 Color.Primary，状态与动效 180–220ms 完整。

## 十、最终版精修 Checklist（与当前实现一致）

以下为专家详情页“最终版”验收清单；当前代码已按第八节实现指导落地，本节用于自检与后续迭代对齐。

### 一、结构与节奏精度

**1. Header 与正文断点控制**

* Header 底部 spacing ≥ 正常 section 间距 +1 级（首 section 使用 `section--after-header`，4×spacing）
* 不使用卡片分隔；若用 Divider 须极浅（5%~10% Neutral）
* 判断标准：第一屏有节奏停顿，而非信息连续塌陷

**2. Section 间距统一**

* 所有 section 之间使用同一 Spacing Token（`--home-spacing-page`），普通 section 为 2×，首 section 为 4×
* 专家介绍 → 擅长领域 → 历史直播 节奏均匀
* 判断标准：滚动时节奏稳定，无突兀跳跃

### 二、排版精修

**3. 专家介绍正文可读性**

* 行高 ≥ 1.65（当前 1.75），段落已按 `\n\n`/`\n` 拆分
* 段间距统一（`--home-spacing-module`），正文为 Secondary Text（`--home-text2`）
* 判断标准：阅读像医学摘要，而非营销文案

**4. 标题层级清晰**

* 姓名视觉最强（`--home-fs-banner` + 字重 600）
* 职称次级，医院/科室更弱（opacity 0.85）
* Section 标题与姓名权重明显区分
* 判断标准：眯眼看仍能分辨主次层级

### 三、组件精修

**5. 星标（关注）IconButton**

* 与 name-row 视觉中心对齐（margin-top calc）
* 热区 ≥ 44×44px；未关注 = Neutral，已关注 = Color.Primary
* hover/active/focus-visible/disabled 完整，动效 180–220ms，无 layout shift
* 判断标准：像系统操作控件，非漂浮装饰

**6. Tag（擅长领域）**

* Neutral 背景（`--home-bg`）+ secondary 文本（`--home-text2`）
* Radius.Small（`--home-r-md`），字号 Meta 级，不抢主标题
* 判断标准：Tag 为辅助信息，非视觉焦点

**7. EmptyState 精修**

* 图标尺寸适中，文本层级弱，垂直 padding 收敛
* 不占半屏，无卡片背景
* 判断标准：像轻提示，非“内容缺失”

### 四、视觉克制

**8. 无多余分割线**：无厚线；Divider 极浅（约 6%）或删除；无边框框住内容。

**9. 单背景确认**：页面仅一层背景色，无 section 背景块，无阴影卡片。

### 五、系统一致性

**10. Design Language 统一**：颜色/圆角/字体/动效均来自 tokens，无默认蓝，无页面私有样式分叉；与登录页、列表页无风格漂移。

### 六、阅读体验测试

* **眯眼测试**：能分辨姓名、Section 标题、正文块、空状态
* **滚动测试**：节奏均匀，无视觉卡顿与布局抖动
* **气质测试**：整体像医院官网（B），而非直播平台（A）

### 七、最终目标状态

> 单背景 + 留白分组 + 克制主色 + 精准排版  
> 看起来像医疗机构系统，而不是互联网活动页。

达到标准：去卡片彻底、排版专业、节奏稳定、主色克制、空状态收敛、无多余装饰、与全局 Design Language 完全统一。
