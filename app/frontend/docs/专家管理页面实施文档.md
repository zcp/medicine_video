# 专家管理页面实施文档

> **文件**：`src/pages/app/admin/expert-list/index.vue`
> **角色**：专家档案全生命周期管理中心
> **对象**：专家（`experts`）+ 未分配专家（`expert_departments.unmapped`）
> **实施日期**：2026-07-26
> **实施方式**：五阶段递增实施
> **最后更新**：2026-07-28 — 布局优化 + loadMore 修复 + 按钮统一

---

## 一、页面定位

| 维度 | 说明 |
|------|------|
| 核心问题 | "哪些专家需要审核？哪些还没有分配科室？如何管理专家档案？" |
| 使用者 | 管理员 / 内容运营 |
| 频率 | 中频（每天都有新专家注册或导入） |
| 依赖关系 | 依赖专家分类管理页维护的科室列表（"分配科室"操作的下拉选项来自 `expert_departments`） |
| 入口 | "我的"页面 → 管理功能菜单 → "专家管理"；管理摘要"未归类专家"卡片 → `expert-list?tab=unmapped`；科室详情"查看关联专家" → `expert-list?department_id=xxx` |

### 与其他管理页面的职责划分

| 页面 | 管理对象 | 核心操作 |
|------|---------|---------|
| **专家分类管理** | 科室（`expert_departments`） | 创建/审核/合并/删除科室 |
| **专家管理（本页）** | 专家（`experts`） | 审核/分配科室/编辑/删除/导入专家 |
| 轮播图管理 | 焦点图（`featured_content`） | CRUD 焦点图 + 图片上传 |

## 四、三 Tab 数据源（关键架构差异）

本页与 `departments/index.vue` 最大的不同：3 个 Tab 使用**两种不同的 API 端点**，返回**两种不同的类型**。

| Tab | 数据源 | 返回类型 | 字段数 | 特点 |
|-----|--------|---------|:--:|------|
| 全部专家 | `GET /admin/experts` | `Expert` | 23 | 完整字段，含 `bio`/`is_featured`/`department_id`/`created_at` |
| 待审核 | `GET /admin/experts?is_verified=false` | `Expert` | 23 | 同上，仅筛选条件不同 |
| 未分配 | `GET /admin/expert-departments/unmapped` | `UnmappedExpert` | 10 | 精简字段，缺 `bio`/`is_featured`/`department_name` |

### 类型桥接函数

两种类型共享展示字段通过直接访问（`item.name`/`item.title`/`item.avatar_url`/`item.is_verified`），差异字段通过类型守卫函数桥接：

```typescript
getDepartmentName(item)  → 'department_name' in item ? Expert.department_name : null
getIsFeatured(item)      → 'is_featured' in item ? Expert.is_featured : false
getBio(item)             → 'bio' in item ? Expert.bio : null
getCreatedAt(item)       → 'created_at' in item ? Expert.created_at : null
getExpertiseAreas(item)  → item.expertise_areas || null  // 两种类型共有
```

## 五、数据流

### 列表加载

```
loadExperts(refresh)
  ├─ refresh=true → page=1, experts=[]
  ├─ activeTab === 'unmapped' ?
  │     getUnmappedExperts({page, size})           → UnmappedExpert[]
  │   : getAdminExperts({
  │       page, size=20,
  │       is_verified? ← Tab 2: false
  │       name?        ← 搜索关键词
  │       category_id? ← 分类筛选
  │       department_id? ← 科室筛选
  │     })                                          → Expert[]
  ├─ res.data.items → experts (refresh? 替换 : 追加)
  └─ res.data.total → total → hasMore
```

### Tab 切换

```
watch(activeTab) → loadExperts(true)
  ├─ all Tab: 无 is_verified 筛选, filter-bar 可见
  ├─ pending Tab: is_verified=false, filter-bar 可见
  └─ unmapped Tab: 切换 API, filter-bar 隐藏
```

### CRUD 操作后刷新策略

```
创建/编辑/批量审核: loadExperts(true) — 全量刷新
删除/分配科室: experts.value = experts.filter(...) — 本地移除（免刷新）
审核: item.is_verified = true — 就地更新（免刷新）
```

## 九、已知限制

| 限制 | 影响 | 后续计划 |
|------|------|------|
| Tab 3 无筛选支持 | `getUnmappedExperts` 不支持 `name`/`category_id` 参数，未分配列表无法搜索或过滤 | 后端新增参数或前端客户端过滤 |
| 批量审核为串行调用 | `Promise.all` 风格循环，N 个专家 N 次请求，大量时较慢 | 后续请求后端新增 `batch-verify` 端点 |
| 批量导入为占位 | 仅显示 Toast 提示，未实现文件上传 | 后续接 FormData + 文件选择器 |
| 编辑 UnmappedExpert 科室不可显示 | `UnmappedExpert` 无 `department_name` 字段，编辑表单科室下拉显示"不指定科室" | 可接 `department_name` 字段 |
| Tab 3 无 `is_verified` 筛选 | 未分配 Tab 展示所有 `department_id IS NULL` 的专家，不区分审核状态 | 若需分离，需后端新增参数 |

## 十、v1.1 优化记录 (2026-07-28)

| 变更 | 说明 |
|------|------|
| **Tab 合并到顶栏** | 原独立 `tab-bar` 行移除，Tab 按钮（[全部] [待审核] [未分配]）放入 `top-bar` 与 `[选择] [＋ 新增]` 同行，`isActive(tab)` 高亮当前 |

| **专长标签内联** | `getExpertiseAreas()` 结果作为 inline tag pills 直接展示在卡片上（替代展开区） |
| **操作按钮改列布局** | `expert-actions` 从横排(`flex row`)改为纵排(`flex column`)，每行一个按钮，紧凑间距 |
| **按钮样式统一** | 全部使用 `header-btn` class → `height: 56rpx; padding: 0 24rpx; font-size: 24rpx; border-radius: 28rpx` |
| **loadMore 自动续加载** | `loadExperts` finally 块加 `autoContinueCheck()`——如果加载完成后列表高度仍不足一屏，自动 `loadMore()` 继续 |
