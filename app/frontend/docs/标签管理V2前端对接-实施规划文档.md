## 四、契约口径要点（写进实现，勿漂移）

1. **上限**：`MAX_SESSION_TAGS = 5` 单一来源（新 `src/constants/live.ts`），标签 chip 计数 N/5、PickerSheet `:max`、满员禁用同步收口；保存前 >5 防御拦截（防御存量数据场景，见 I4-5）。
2. **resolve 成功落 chip**：`created=true` 轻提示「已添加新标签」；`created=false`（并发复用）静默落 chip；两分支**均不调 bind**（resolve 与绑定两步分离是后端设计意图）；落 chip 前按 name（trim+小写）去重；**resolve 结果必须并入本页 tagList**（按 id 防重），否则编辑面板无法反选该 chip。
3. **精确同名判定**（"创建并使用"显示条件）：在**组件内对 items 全量**（非 filteredItems）做 name 精确相等（trim+小写）判断——当前本地过滤无截断、两者等价，但对未来"列表截断/已选但列表外"场景更稳。
4. **绑定失败处理**（create/edit 统一）：
   - 失败 → toast 后端 message（request 层 400/422 已自动 toast 的，页面勿重复；`__toasted` 标记防重）；
   - `code === 4001` → 差集剔除（见 Q5）→ `len > 0` 自动重试一次 replace；剔光则不 bind 只 toast（见 Q6）；
   - 403/3003 → 接受通用 toast（不特判）。
5. **编辑防误清空双闸保留**：`tagsLoaded && tagsModified` 语义不动；resolve/chip 增删均置 `tagsModified`；删光 chips → 提交 `tag_ids: []` 正常清空（后端 replace+[] 语义）。
6. **文案口径**：422/2005 → 全局固定文案；4001 差集剔除 toast「部分标签已停用，已自动移除」；创建页绑定失败合并 toast「直播已创建，但标签保存失败，请到编辑页补设」（避免与成功 toast 叠没，见 D1）。
7. **后端事实锚点**：公开 `GET /content/tags` 无分页无 LIMIT（后端 crud `get_tags` 全量返回、created_at desc、非 Admin 强制 is_active=True）；差集前置校验响应为**数组**（若未来信封变化则放弃自动剔除、仅 toast，防御性降级）。
