# 直播间开始时间与回放 — 完整实施方案（含后端放宽状态约束）

**版本**: 1.0  
**日期**: 2025-01-31  
**更新**: 2025-02-01 补充第六节「回放地址清空与 UnboundLocalError 修复总结」及第五节变更摘要表对应行。  
**目标**: ① 开始时间与回放地址不受会话状态约束，可任意状态修改；② 前端开始时间归属 Session、保存/展示正确；③ 创建页提供回放 URL 时可选「直播中/回放」；④ 清空回放地址可正确保存且页面不残留旧 m3u8。

---

## 一、复核结论：后端修改正确性、最小化与一致性

### 1.1 修改是否正确

- **需求**: 非 `scheduled` 时也能修改开始时间；回放地址填写不受状态约束（如：创建 status=live 的场次并填 m3u8，或对已结束场次补填 start_time / playback_url）。
- **当前后端**: `update_scheduled_session_info` 中：① 常规字段（含 `start_time`）仅当 `session.status == SCHEDULED` 允许更新；② `playback_url` 仅当 `session.status in (READY, FINISHED)` 允许更新。
- **结论**: 后端必须放宽这两处状态校验，修改方向正确。

### 1.2 是否最小化修改

- **仅改一处方法**: `app/services/session_service.py` 的 `update_scheduled_session_info`。
- **具体**:
  1. 删除「常规字段需 SCHEDULED」的整段判断（约 5 行），不再按状态拦截 `start_time` / `status` / `end_time` 等。
  2. 删除「playback_url 需 READY/FINISHED」的判断（约 8 行），保留「有 playback_url 时同步维护 playback_url_hash」的逻辑。
- 不新增接口、不改 Schema、不改 CRUD，不触动 `delete_session`（仍禁止删除 live 场次）。

### 1.3 是否会引入冲突与不一致

- **delete_session**: 仍在使用 `SessionActionForbiddenException` 禁止删除 live 场次，与本次修改无关，无冲突。
- **API 契约**: PATCH `/api/v1/sessions/{session_id}` 的请求/响应格式不变，仅业务规则放宽。
- **依赖方**: 单元测试与集成测试中有两处**依赖旧规则**（非 scheduled 更新返回 403），需同步改为「允许更新并断言成功」，否则会失败；其余测试无需改。

## 三、前端修改（与后端放宽一致）

### 3.1 RoomBasicSettings.vue

- **加载**: 开始时间仅从首个 session 的 `getSessionDetail` 结果赋值：`formData.start_time = data?.start_time ?? ''`（不再依赖 `response.data.start_time`）。
- **保存**:
  1. `updateData` 中不包含 `start_time`，不调用 `updateRoom` 传 start_time。
  2. 若有 `formData.session_id` 且 `formData.start_time` 有值，则**不论当前 session 状态**，都调用 `updateSession(formData.session_id, { start_time: startTimeIso })`（与后端「任意状态可更新」一致）。时间格式转为 ISO（如 `dayjs(formData.start_time).toISOString()` 或 `new Date(formData.start_time).toISOString()`）。
  3. 回放地址：**不论状态**都传当前表单值；且**必须始终将 `playback_url` 放入 session 更新 payload**（见第六节），否则清空回放时后端收不到该字段、页面重载后仍显示旧 m3u8。

### 3.2 RoomCreate.vue（创建页统一路径）

- **无回放地址**：不显示 session 状态选项；点击「立即创建」走 `handleCreate()` → `POST /rooms/{room_id}/sessions`（createSession），仅传 `start_time`。
- **有回放地址**：在回放地址下方展示「创建为」单选项：**直播中**（live）/ **回放**（finished）；点击「立即创建」走 `handleImportCreate()` → `POST /rooms/{room_id}/sessions/import`（importSession），`status` 直接传用户选择（`'live'` 或 `'finished'`，与后端支持一致）。
- **formModel**：`create_mode_when_playback` 默认 `'finished'`，有回放时仅 `'live' | 'finished'`。
- **handleSmartCreate**：`!playbackUrl` → `handleCreate()`；有 `playbackUrl` → `handleImportCreate()`（不再按「直播中」分支到 handleCreate）。
- **类型**：`src/types/session.ts` 中 `SessionImportCreate.status` 为 `'finished' | 'ready' | 'live'`，与后端一致。

### 3.3 与 uni-ui-beauty_v2 的对应

- 两页均为 ADMIN_FORM；遵循 Base + Profile C（表单对齐、分组、操作区）；按钮/输入/单选项规格与现有文档一致，无新增组件。

## 六、回放地址清空与 UnboundLocalError 修复总结（已实施）

本节记录在实施「任意状态可改开始时间与回放地址」后，为修复「清空回放地址报错 / 清空后页面仍显示旧 m3u8」所做的后端与前端补充修改。

### 6.1 问题现象

- **现象一**：仅修改开始时间（不传 `playback_url`）或清空回放地址时，PATCH 接口返回 500，报错 `UnboundLocalError: local variable 'updated_session' referenced before assignment`。
- **现象二**：清空回放地址后保存成功（200），但页面重载后仍自动显示之前的 m3u8 内容。

### 6.2 原因分析

- **UnboundLocalError**：后端 `update_scheduled_session_info` 中，`updated_session = await crud_session.update(...)` 仅写在 `if is_updating_playback:` 内。当请求体未包含 `playback_url`（如只改开始时间或前端未传该字段）时，不会执行该赋值，后续 `logger.info(..., updated_session.room_id)` 与 `return updated_session` 引用未赋值变量导致报错。
- **清空不生效**：前端用 `sessionStore.sessions.find(...)` 得到 `current` 与表单比较后再决定是否把 `playback_url` 放入 payload。房间场次列表接口 `GET /rooms/{room_id}/sessions` **不返回** `playback_url`，故 `current?.playback_url` 恒为 `undefined`。用户清空输入框时 `formData.session_playback_url === ''`，条件 `'' !== (current?.playback_url ?? '')` 即 `'' !== ''` 为 false，导致**从未把 `playback_url` 放入 payload**，后端未更新该字段；保存后 `loadRoomDetail()` 再次拉详情，仍得到旧值，页面遂显示旧 m3u8。

### 6.3 后端修改（session_service.py）

- **文件**：`live-streaming-saas/backend/live_core_service/app/services/session_service.py`，方法 `update_scheduled_session_info`。
- **修改一**：在 `if is_updating_playback:` 内，当 `playback_url` 为空或仅空白时，显式设置 `update_data["playback_url"] = None` 与 `update_data["playback_url_hash"] = None`，避免对空串做 hash 导致多条 session 清空时触发唯一约束冲突。
- **修改二**：将 `updated_session = await crud_session.update(db=self.db, db_obj=session, obj_in=update_data)` **移出** `if is_updating_playback:` 块，置于该 if 之后、`logger.info` 与 `return updated_session` 之前，使得无论本次是否更新回放地址都会执行一次 update 并赋值 `updated_session`，消除 UnboundLocalError。

### 6.4 前端修改（RoomBasicSettings.vue）

- **文件**：`vzan_simul_frontend/src/pages/room/new/RoomBasicSettings.vue`，保存逻辑中构建 `sessionUpdatePayload` 处。
- **修改**：不再用 `current?.playback_url` 判断是否写入 payload（因列表不返回该字段）。改为**始终**将当前表单回放地址写入 payload：`sessionUpdatePayload.playback_url = formData.session_playback_url ?? ''`。这样用户清空时会发送 `playback_url: ''`，后端能正确清空；有值时行为与之前一致；未改时多传一次相同值，对后端幂等。

### 6.5 与文档其他部分的一致性

- 第二节「后端修改」描述的是放宽状态校验与保留 `playback_url_hash` 维护；第六节在此基础上补充了「清空时 hash 置 None」与「update 移出 if 块」两处实现细节，二者不冲突。
- 第三节 3.1 已注明回放地址须始终放入 session 更新 payload，与第六节前端修改一致。
- 第五节变更摘要表已补充本修复对应的两行（见第五节表格中「清空与 UnboundLocalError 修复」「回放地址 payload」两行）。
