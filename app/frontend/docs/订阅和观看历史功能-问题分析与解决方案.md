## 1. 核心问题分析

### 1.1 功能不工作的根本原因

经过深入分析，订阅和观看历史功能不工作的**核心原因**是：

#### ❌ **问题1：前后端数据结构严重不匹配**

**后端返回的数据结构**（根据设计文档）：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 3,
    "page": 1,
    "size": 10,
    "items": [
      {
        "id": "subscription_uuid_1",
        "user_id": "user_uuid",
        "target_id": "room_uuid_789",
        "target_type": "room",
        "is_active": true,
        "created_at": "2025-10-23T14:50:00Z",
        "room_title": "胃肠外科专题讲座",
        "room_cover_url": "/media/rooms/yyy/cover.jpg"
      }
    ]
  }
}
```

**前端期望的数据结构**（SubscriptionWithTarget类型）：
```typescript
{
  id: string
  target_id: string
  target_type: 'room' | 'session'
  room_title: string        // ✅ 后端有
  room_cover_url: string    // ✅ 后端有
  next_session?: SessionInfo  // ❌ 后端没有！
  is_notified?: boolean       // ❌ 后端没有！
  is_read?: boolean           // ❌ 后端没有！
  
  // 前端自己扩展的字段
  title?: string
  cover_url?: string
  status?: string
  expert_name?: string
  // ...
}
```

**关键问题**：
- ✅ 后端返回了 `room_title` 和 `room_cover_url`
- ❌ 后端**没有返回** `next_session`、`is_notified`、`is_read` 字段
- ❌ 前端的待开播/已通知/已过期分类**完全依赖** `next_session` 字段
- ❌ 前端Store中的 `pendingList`、`notifiedList`、`expiredList` 计算属性都会返回空数组

#### ❌ **问题2：前端做了不必要的二次数据获取**

**当前实现**：
```typescript
// Store中的loadSubscriptions方法
const enrichedList = await Promise.all(
  subscriptionList.map(async (sub) => {
    if (sub.target_type === 'room') {
      const roomRes = await getRoomDetail(sub.target_id)  // ❌ 不必要
      return { ...sub, title: roomRes.data?.title }
    } else if (sub.target_type === 'session') {
      const sessionRes = await getSessionDetail(sub.target_id)  // ❌ 不必要
      const expertsRes = await getSessionExperts(sub.target_id)  // ❌ 不必要
      return { ...sub, title: sessionRes?.title, expert_name: expert?.name }
    }
  })
)
```

**问题**：
- 后端已经返回了 `room_title` 和 `room_cover_url`
- 前端却忽略这些字段，重新调用 `getRoomDetail` 和 `getSessionDetail`
- 导致**大量不必要的API请求**（N+1查询问题）
- 性能极差，用户体验糟糕

#### ❌ **问题3：订阅分类逻辑错误**

**前端的分类逻辑**（基于 `next_session`）：
```typescript
// 待开播
const pendingList = computed(() => {
  return subscriptions.value.filter(sub => {
    if (!sub.next_session) return false  // ❌ 永远为false
    return sub.next_session.status === 'scheduled'
  })
})
```

**问题**：
- 后端设计文档中**没有** `next_session` 字段的定义
- 前端假设后端会返回这个字段，但实际上不会
- 导致所有分类列表都是空的

## 2. 后端API设计分析

### 2.1 后端支持的功能

根据《直播核心功能设计文档_v6_用户行为模块设计文档-收藏-观看历史-订阅提醒.md》：

#### ✅ **订阅功能**

| API | 方法 | 路径 | 功能 | 状态 |
|-----|------|------|------|------|
| 添加订阅 | POST | `/api/v1/users/me/subscriptions` | 订阅直播间或场次 | ✅ 支持 |

| API | 方法 | 路径 | 功能 | 状态 |

**后端返回的字段**：
- ✅ `id`, `session_id`, `progress`, `watched_at`
- ✅ `session_title`, `room_cover_url`（通过JOIN获取）
- ❌ **没有** 专家信息字段

### 2.2 后端设计的局限性

#### 🔴 **关键问题：订阅分类功能后端不支持**

**前端需求**：
- 待开播：`start_time > now && status='scheduled'`
- 已通知：`is_notified=true || status='live'`
- 已过期：`end_time < now && status='ended'`

**后端现状**：
- ❌ 后端API**不返回**场次的 `start_time`、`end_time`、`status` 信息
- ❌ 后端数据库表**没有** `is_notified` 和 `is_read` 字段
- ❌ 后端API**不支持**按状态筛选订阅

**结论**：前端的订阅分类功能**无法实现**，除非：
1. 后端修改API，返回 `next_session` 信息
2. 后端添加 `is_notified` 和 `is_read` 字段
3. 或者前端自己调用额外的API获取场次信息（性能差）

## 6. 解决方案

### 6.1 方案对比

#### 方案A：修改后端API（推荐）⭐

**优点**：
- ✅ 彻底解决问题
- ✅ 性能最优（无N+1查询）
- ✅ 前端代码简洁
- ✅ 符合设计规范

**缺点**：
- ❌ 需要后端配合
- ❌ 开发周期较长

**实施步骤**：
1. 后端在订阅表添加 `is_notified` 和 `is_read` 字段
2. 后端API返回时JOIN场次表，返回 `next_session` 信息
3. 后端API返回时JOIN专家表，返回专家信息
4. 前端简化Store逻辑，直接使用后端返回的数据

#### 方案B：前端优化（临时方案）

**优点**：
- ✅ 不需要后端配合
- ✅ 可以立即实施
- ✅ 部分改善用户体验

**缺点**：
- ❌ 无法实现订阅分类功能
- ❌ 仍有性能问题（需要额外API调用）
- ❌ 代码复杂度高

**实施步骤**：
1. 移除不必要的二次数据获取
2. 直接使用后端返回的 `room_title`、`session_title` 等字段
3. 简化订阅分类逻辑（只显示全部订阅）
4. 优化专家信息获取（批量获取或缓存）

#### 方案C：混合方案（平衡方案）⭐⭐

**优点**：
- ✅ 短期内可以工作
- ✅ 为后端优化预留接口
- ✅ 渐进式改进

**缺点**：
- ⚠️ 需要分阶段实施
- ⚠️ 代码需要两次重构

**实施步骤**：
1. **第一阶段**（前端优化）：
   - 移除不必要的API调用
   - 使用后端返回的基本字段
   - 简化订阅分类（暂时不分类或简单分类）
   
2. **第二阶段**（后端优化）：
   - 后端添加必要字段
   - 后端API返回完整信息
   - 前端恢复完整的分类功能

// src/store/subscription.ts

async function loadSubscriptions(force: boolean = false) {
  const res = await getSubscriptions({ page, size })
  
  if (res.data) {
    // 对场次订阅，额外获取场次详情（用于分类和显示）
    const enriched = await Promise.all(
      res.data.items.map(async (sub) => {
        if (sub.target_type === 'session') {
          try {
            // 获取场次详情（用于获取 start_time 和 status）
            const session = await getSessionDetail(sub.target_id)
            // 获取专家信息（用于显示）
            const expertsRes = await getSessionExperts(sub.target_id).catch(() => ({ data: [] }))
            const expert = expertsRes.data?.[0]
            
            return {
              ...sub,
              title: sub.room_title,           // ✅ 使用后端返回的字段
              cover_url: sub.room_cover_url,   // ✅ 使用后端返回的字段
              start_time: session.start_time,  // ⚠️ 额外获取（用于分类）
              status: session.status,          // ⚠️ 额外获取（用于分类）
              expert_name: expert?.name || '房树强',  // Mock数据
              expert_title: expert?.title || '主任医师、教授',
              expert_avatar: expert?.avatar_url,
              expert_hospital: expert?.hospital || '北京大学人民医院 肝胆胰外科'
            }
          } catch (error) {
            return { ...sub, title: sub.room_title, cover_url: sub.room_cover_url }
          }
        }
        // 房间订阅直接使用后端返回的字段
        return { ...sub, title: sub.room_title, cover_url: sub.room_cover_url }
      })
    )
    
    subscriptions.value = enriched
  }
}

// 按状态分类（2个Tab）
const pendingList = computed(() => 
  subscriptions.value.filter(s => 
    s.target_type === 'session' && s.status === 'scheduled'

const expiredList = computed(() =>

function groupHistoryByDate(items: WatchHistoryItem[]): GroupedHistory[] {
  const today = dayjs().startOf('day')
  const yesterday = dayjs().subtract(1, 'day').startOf('day')
  
  const groups = {
    today: [] as WatchHistoryItem[],
    yesterday: [] as WatchHistoryItem[],
    earlier: [] as WatchHistoryItem[]
  }
  
  items.forEach(item => {
    const watchedAt = dayjs(item.watched_at)
    if (watchedAt.isSame(today, 'day')) {
      groups.today.push(item)
    } else if (watchedAt.isSame(yesterday, 'day')) {
      groups.yesterday.push(item)
    } else {
      groups.earlier.push(item)
    }
  })
  
  return [
    { date: '今天', items: groups.today },
    { date: '昨天', items: groups.yesterday },
    { date: '更早', items: groups.earlier }
  ].filter(group => group.items.length > 0)
}
