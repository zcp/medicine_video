## 一、命名与自检规则（导入前对每条词人工核对）

1. 词形：**中性名词/短语**，不承诺疗效、不出现疾病治愈类表述；
2. **禁含子串（命中即换词）**：
   `根治` `治愈` `治好` `包治` `防癌` `抗癌` `抗肿瘤` `降血脂` `100%` `百分百` `第一` `顶级` `唯一` `最强` `永久` `终身` `特效` `祖传` `秘方` `神医` `神药` `壮阳` `丰胸` `祛斑` `祛疤` `减肥药` `注射瘦脸` 及任何药品商品名、部队/军方表述、色情暗示词；
3. 不与医学词库规则命中：如上子串已覆盖主要命中项（对照 medical_lexicon_data.py 全部 27 类词库 + tier.py A 档审计：72 条静态均无 block 命中）；**Admin 导入通道无 422 兜底，本清单自检是唯一合规防线**；导入后仍须以 resolve 通道逐词回归（200/created=false 通过；422 = 用户侧绑不上，必须换词并更新本表）；
4. 全局唯一：name 不可重复；清单内已去重，与 dev 现存词不重名（现词表已清空为前提）；
5. 条数克制：单场次最多绑 5 个，词表为"公共词库"而非穷举——72 条起步，运营后续按需求增量。

## 三、导入执行建议（仅 dev；生产只做增量导入）

1. **导入前去重**：以 admin_yu 登录态 `GET /api/v1/admin/tags`（分页拉全量）按 name 比对，跳过已存在项；
2. 以 admin_yu 登录态逐条 `POST /api/v1/admin/tags {name}`（自动落 source=admin + created_by）。**通道事实**：本通道**无内容安全校验（不会出现 422）**；**重名返回 500/1002 而非 4001**——遇 500 一律人工复核是否已存在，不得按 4001 逻辑自动跳过；
3. **导入后 resolve 回归（关键）**：以 an_test 登录态对每条词 `POST /api/v1/content/tags/resolve {name}`：200 且 `created=false` = 通过；422 = 该词在用户绑定侧会被拦截，**必须换词**并更新本表。**顺序严禁颠倒：先 admin 导入、后 resolve 自检**——空表上先 resolve 会把每条词建成 source=user（= 清理白做）；
4. 前端验证：an_test 打开创建直播 → 添加标签 → 输入"高血压"出联想、可点选、可绑定、回显正常；管理端列表可见全部「运营」徽章词；
5. 导入完成后**勿重跑 `app/seed_tags.py`**（会幂等复活 20 条历史测试词并重建 8 条场次关联）。

## 四、后续治理备注

- 本清单为"运营认可词库"起点；主播 resolve 自建词会以 source=user 出现，运营在管理端据热度与质量决定转正（产品语义=认可保留）或停用滥词；
- 生产启用前如需调整栏目口径，运营可在此基础上增删（新增词同样须过 §一 自检）；
- **维度缺口（已定案 2026-09-06）**：本表全为"主题向"词，不含"直播形式/受众"维度（如 学术讲座/病例讨论/手术演示/手术直播/MDT讨论/住院医培训 等，即 seed_tags.py 曾用的形式类与受众类）。决策：**本次不补**，维持 72 条主题向；后续若产品出现按直播形式筛选标签的入口，由运营按 §一 自检补词、走《生产启用-增量导入与治理预案》增量流程；
- **停用词占名缺陷（已登记）**：管理端"停用"为软删（is_active=false），软删行仍占用全局唯一 name——同名重建会撞唯一约束返回 500；当前无 API 支持物理删词，治理工具缺口待后端排期；
- **生产复用注意事项**：生产若已存在真实 source=user/admin 词，先盘点与 72 条的重名冲突（重名导入会 500），再决定增量导入或治理合并；不得执行全量清理。
