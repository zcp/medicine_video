# 留言管理页面实施文档

> **文件**：`src/pages/app/admin/messages/index.vue`
> **角色**：全站留言内容治理（内容管理员 / 运营主管）
> **对象**：留言（`live_room_messages`）
> **实施日期**：2026-07-30
> **实施方式**：三阶段递增实施

---

## 一、页面定位

| 维度 | 说明 |
|------|------|
| 核心问题 | "全站直播间里用户在说什么？有没有违规内容？如何快速定位和清理？" |
| 使用者 | 内容管理员 / 运营主管 / 超级管理员 |
| 频率 | 高频巡查 + 事件驱动响应（投诉/举报触发追溯） |
| 依赖关系 | 依赖房间存在性校验（清空房间时） |
| 入口 | "我的"页面 → 管理功能菜单 → "留言管理" |

### 与其他管理页面的职责划分

| 页面 | 管理对象 | 核心操作 |
|------|---------|---------|
| 用户管理 | 平台用户（`users`） | 封禁/解封/角色/开播权限 |
| **留言管理（本页）** | 留言（`live_room_messages`） | 查询/搜索/单删/批量删除/清空房间 |
| 内容安全（后续） | 规则（`content_safety_rules`） | 配置审核关键词/正则 block/warn 规则 |

### 留言管理与内容安全的关系

两个系统互补但不重叠：

| 功能 | 留言管理（本页） | 内容安全（后续页面） |
|------|----------------|-------------------|
| 时机 | 事后治理 | 事前拦截 |
| 操作 | 删除已发送的违规留言 | 配置规则阻止违规内容发送 |
| 对象 | 单条/批量留言 | 规则引擎 |
| 使用者 | 运营巡查 | 合规管理员 |

```
┌─────────────────────────────────────────────┐
```

卡片信息优先级：

| 内容 | 纯文本，最多 2 行截断 | `AdminMessageItem.content` |
| 角色标签 | `user_role` 值映射为彩色 Badge | `AdminMessageItem.user_role` |

## 四、数据流

### 4.1 列表加载

```
loadMessages(refresh)
  ├─ refresh=true → page=1, messages=[]
  ├─ params: { page, page_size=20 }
  │   ├─ activeTab === 'today' → { start_time: 今天00:00 }
  │   ├─ activeTab === 'week'  → { start_time: 7天前00:00 }
  │   ├─ searchKeyword → { keyword }
  │   ├─ selectedRoomId → { room_id }
  │   └─ selectedUserId → { user_id }
  ├─ 调 getAdminMessages(params)
  │   └─ 返回 { code, data: { items: AdminMessageItem[], total, page, page_size, filter_summary } }
  ├─ messages = refresh ? items : [...messages, ...newItems]（去重）
  └─ total / filter_summary 更新
```

### 4.2 删除流程

```
单条删除:
  点击 [删除] → uni.showModal("确定删除此留言？")
    └─ 确认 → batchDeleteAdminMessages([messageId])
          ├─ 成功 → messages = messages.filter(m => m.id !== messageId)
          │         → toast "已删除"
          └─ 失败 → toast error.message

批量删除:
  选择模式 → 选中 N 条 → 点击 [批量删除]
    └─ uni.showModal("确定删除选中的 N 条留言？")
          └─ 确认 → batchDeleteAdminMessages(selectedIds)
                ├─ 成功 → exitSelectMode + loadMessages(true)
                └─ 失败 → toast error.message

清空房间:
  点击 [清空房间] → 房间选择弹窗
    └─ 确认房间 → uni.showModal("将删除该房间所有留言")
          └─ 确认 → clearRoomMessages(roomId)
                ├─ 成功 → loadMessages(true) + toast "已清空"
                └─ 失败 → toast error.message
```

### 4.3 Tab 切换

```
watch(activeTab) → loadMessages(true)
  ├─ today: start_time = 当日 00:00
  ├─ week:  start_time = 7天前 00:00
  └─ all:   不传时间参数
```

### 4.4 状态覆盖

| 状态 | 触发条件 | 展示内容 |
|:----:|---------|---------|
| Loading | `isLoading && messages.length===0` | 4 张骨架卡片（skeleton-card） |
| Error | `error && messages.length===0` | ⚠️ + 错误消息 + [点击重试] |
| Empty | `!isLoading && messages.length===0` | 💬 + 差异化文案 |
| 已加载 | `messages.length>0` | 正常卡片列表 |

空状态差异化文案：

| Tab | 无搜索 | 有搜索 |
|:---:|:------:|:------:|
| today | "今日暂无留言" | "没有匹配的留言，试试其他关键词" |
| week | "近7天暂无留言" | 同上 |
| all | "暂无留言数据" | 同上 |

## 五、接口定义

### 5.1 管理端 API 扩展（`src/api/message.ts` 追加）

消息管理 API 使用默认 `BASE_API_URL`（`live_core_service`），与 `room.ts` 中 `getAdminRooms` 一致。

#### GET /admin/messages — 留言列表

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|:----:|:----:|------|
| `page` | int | 否 | 1 | 页码 |
| `page_size` | int | 否 | 20 | 每页数量（1~100） |
| `room_id` | uuid | 否 | — | 按直播间筛选 |
| `user_id` | uuid | 否 | — | 按用户筛选 |
| `keyword` | string | 否 | — | 留言内容关键词搜索 |
| `start_time` | datetime | 否 | — | 开始时间（ISO 8601） |
| `end_time` | datetime | 否 | — | 结束时间（ISO 8601） |

**成功响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 100,
    "page": 1,
    "page_size": 20,
    "items": [
      {
        "id": "uuid",
        "room_id": "uuid",
        "user_id": "uuid",
        "user_role": "REGULAR",
        "content": "留言内容",
        "created_at": "2026-07-30T10:30:00Z",
        "extra": {
          "user_display_name": "张三",
          "user_avatar": "/uploads/avatars/xxx.png"
        }
      }
    ],
    "filter_summary": {
      "room_count": 5,
      "user_count": 8
    }
  }
}
```

#### POST /admin/messages/batch-delete — 批量删除

| 请求字段 | 类型 | 必填 | 说明 |
|---------|------|:----:|------|
| `message_ids` | uuid[] | 是 (min_length=1) | 要删除的留言ID列表 |

**成功响应**：
```json
{
  "code": 200,
  "message": "成功删除5条留言",
  "data": {
    "deleted_count": 5,
    "failed_count": 0
  }
}
```

**注意**：后端在删除前会查询留言所属房间，删除后自动失效对应房间的 Redis 缓存。

#### DELETE /admin/rooms/{roomId}/messages — 清空房间留言

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `roomId` | uuid | path | 目标直播间 ID |

**成功响应**：
```json
{
  "code": 200,
  "message": "已清空该直播间所有留言",
  "data": {
    "deleted_count": 50
  }
}
```

**错误响应**：
- `404 { "code": 2001, "message": "房间不存在" }`
- `403 { "code": 3003, "message": "权限不足：仅管理员可执行此操作" }`

```typescript
  keyword?: string;
```

## 七、管理能力与后端支持度对照

| 管理能力 | 后端支持 | 实现方式 |
|---------|:--------:|---------|
| 留言分页列表 | ✅ | `GET /admin/messages?page=&page_size=` |
| 内容关键词搜索 | ✅ | 参数 `keyword`，后端模糊匹配 `content` |
| 按房间筛选 | ✅ | 参数 `room_id` |
| 按用户筛选 | ✅ | 参数 `user_id` |
| 按时间范围筛选 | ✅ | 参数 `start_time`/`end_time` |
| 单条删除 | ✅ | `POST /admin/messages/batch-delete` 传入单 ID |
| 批量删除 | ✅ | `POST /admin/messages/batch-delete`（含缓存失效） |
| 清空房间 | ✅ | `DELETE /admin/rooms/{roomId}/messages`（含房间存在性校验） |
| 展示用户昵称/头像 | ⚠️ 依赖 `extra` 字段 | 发送端写入 `extra.user_display_name`/`user_avatar`，缺失时回退显示 `user_id` 前8位 + `DEFAULT_AVATAR` |
| 展示房间名称 | ⚠️ 后端CRUD层已JOIN但未暴露 | 优先使用 `extra` 数据回退；建议后端在 `AdminMessageItem` 补 `room_title: Optional[str]` |
| 筛选摘要统计 | ✅ | `filter_summary: { room_count, user_count }` |
| 排序（新在前） | ✅ | 后端默认 `created_at DESC` |
| 权限保护 | ✅ | 后端 `verify_admin_role` 拦截非 ADMIN/SUPERADMIN |

### 后端缺口处理策略

| 缺口 | 影响 | 前端处理 |
|------|------|---------|
| `room_title` 未在响应中暴露 | 卡片无法显示房间名称 | 先显示 `room_id` 前8位占位，待后端加字段后替换为 `room_title` |
| `user_name`/`user_avatar` 无专用字段 | 依赖 `extra` 数据完整性 | 优先读取 `extra`，缺失时显示 `user_id` 前8位 + `DEFAULT_AVATAR` |

## 九、状态管理

### 核心响应式状态（16 个 ref + 7 个 computed）

```typescript
// 列表
messages: AdminMessageItem[]       // 留言数据
isLoading: boolean                  // 首次加载中
isLoadingMore: boolean              // 加载更多中
isRefreshing: boolean              // 下拉刷新中
error: string|null                 // 错误消息
page: number                       // 当前页码（从1开始）
size: 20                           // 每页数量
total: number                      // 总数
hasMore: computed                  // page * size < total
loadedOnce: boolean                // 是否已完成首次加载

// 时间筛选
activeTab: 'today' | 'week' | 'all'   // 时间Tab
tabs: const = [                      // Tab 配置
  { key: 'today', label: '今日' },
  { key: 'week', label: '近7天' },
  { key: 'all', label: '全部' },
```

## 十二、约束与风险

### 12.1 权限约束

| 约束 | 处理方式 |
|------|---------|
| 仅 ADMIN/SUPERADMIN 可访问 | 页面入口 `v-if="authStore.isAdmin"` + 后端 `verify_admin_role` 双重保障 |
| 非管理员访问 | 参考 `live-manage/list.vue:420` 模式，弹出"权限不足"提示并返回 |

### 12.2 风险

| 风险 | 概率 | 缓解 |
|------|:----:|------|
| `AdminMessageItem` 缺少 `room_title` 字段，列表无法显示房间名 | 中 | 先用 `room_id` 前8位占位，后续联调时确认后端加字段 |
| `extra` 字段可能不含 `user_display_name`（较早的留言无此数据） | 中 | 回退显示 `user_id` 前8位，保证功能可用 |
| 批量删除选中大量留言（100+）时请求体过大 | 低 | 建议限制选择数量或分批发送 |
| 清空房间误操作导致大量数据丢失 | 中 | 二次确认弹窗 + 后端物理删除但建议增加软删除标记（后续优化） |
| 后端 LIMIT 100 硬限制 | 低 | 前端分页默认 20 条/页，不构成问题 |
