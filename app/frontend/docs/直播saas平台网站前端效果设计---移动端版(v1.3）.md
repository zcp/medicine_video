

### **医学直播SaaS平台：移动端（App/小程序）设计文档 (V1.3 - 完整功能版)**

#### **1.0 设计目标与概述**

本设计旨在将PC端 `V2.0` 设计文档的专业功能（如：专家、品牌、科室分类、专业问答）与Bilibili的成熟移动端UI/UX范式（如：底部Tab栏、Feed流、沉浸式播放器）相结合，打造一个专业、高效且符合移动用户习惯的医学直播应用。

**参考原型：**
* **Bilibili首页 (`508d557888ce7ea783180f2b8da23c8a.jpg`)**: 提供了顶部搜索、分类Tabs和底部主导航的布局参考。
* **Bilibili视频页 (`b186df293f36b950092908d7ff8a0310.jpg`, `97ae2943b289cabd049181baac9d6dcf.jpg`)**: 提供了“播放器 + 详情 + 互动区”的单页滚动布局参考。

#### **2.0 全局设计 (Global UI)**

#### **[全局模块 G1] 底部主导航栏 (Bottom Tab Bar)**

* **设计**: 这是App/小程序的**一级导航**，取代PC端的顶部导航栏。
* **参考**: Bilibili 首页底部的 `[首页] [关注] [+] [会员购] [我的]`。
* **我们的Tab (V1.2 更新 - 优化版):**
    * `[首页]` (位置①): 内容发现 Feed，默认选中。
    * `[品牌]` (位置②): **(V1.2新增)** 合作品牌专区，提升品牌曝光度和商业价值。
    * `[我的直播]` (位置③ - **C位**): **(SaaS核心)** 主播后台快捷入口，强调平台核心定位。
    * `[专家]` (位置④): 专家列表与聚合页，承载PC端 `[C.5]教授专题` 的功能。
    * `[我的]` (位置⑤): 个人中心，用户设置与个人信息管理。

* **设计理念**:
    * **左侧（①②）**：内容消费层（浏览直播、探索品牌）
    * **中间（③）**：内容生产层（主播核心工作台，C位强调）
    * **右侧（④⑤）**：工具/个人层（专家查找、个人中心）

##### **H2.2 个性化功能详解**

###### **功能概述**
* **目标用户痛点**: 医学专业细分领域多，用户只关注特定几个科室，但每次都要滑动查找
* **解决方案**: 用户可将最常看的科室（如眼科、胃肠外科）固定到筛选器前排，一键直达
* **数量限制**: 最多固定**5个科室**（避免筛选器过长）
* **排序**: 用户可自定义固定科室的显示顺序

###### **操作入口：全部科室页面**

当用户点击 `[全部 ≡]` 后，进入**完整科室列表页面**（全屏弹窗或新页面）：

```
┌─────────────────────────────────────────┐
│  全部科室                    [完成]      │ ← 顶部标题栏
├─────────────────────────────────────────┤
│  🔍 搜索科室名称                         │ ← 搜索框
├─────────────────────────────────────────┤
│  💡 我的关注科室 (最多5个)    [编辑]   │ ← 已固定区域
│  ┌───────────────────────────────────┐  │
│  │ ⭐ 眼科                     [×]   │  │ 点击[编辑]后可拖拽排序
│  │ ⭐ 胃肠外科                 [×]   │  │ 点击[×]取消固定
│  └───────────────────────────────────┘  │
│                                          │
│  提示：点击科室右侧的 ☆ 可以固定到首页  │ ← 首次使用提示（可关闭）
├─────────────────────────────────────────┤
│  全部科室 (按拼音排序)         [A-Z索引]│ ← 未固定科室列表
│                                          │
│  肝胆胰外科                      [☆]    │ 点击☆可固定（最多5个）
│  骨科                            [☆]    │ 达到上限后☆按钮置灰
│  呼吸内科                        [☆]    │
│  心血管内科                      [☆]    │
│  神经外科                        [☆]    │
│  ...                                     │
└─────────────────────────────────────────┘
```

###### **交互流程**

1. **固定科室**:
   - 点击科室右侧的 `☆` 按钮
   - 该科室立即移动到"我的关注科室"区域，图标变为 `⭐`
   - Toast提示："已固定到首页"

2. **取消固定**:
   - 方式A：点击已固定科室的 `×` 按钮
   - 方式B：点击已固定科室的 `⭐` 图标（切换状态）
   - 该科室返回"全部科室"列表，图标变为 `☆`

3. **调整顺序**:
   - 点击"我的关注科室"右侧的 `[编辑]` 按钮
   - 进入排序模式：每个科室左侧出现拖拽手柄 `≡`
   - 长按拖拽调整顺序
   - 点击 `[完成]` 保存排序

4. **数量限制**:
   - 当已固定5个科室时，其他科室的 `☆` 按钮置灰
   - 点击置灰的 `☆` 时，Toast提示："最多固定5个科室，请先取消其他科室"

5. **生效时机**:
   - 点击顶部 `[完成]` 按钮返回首页
   - 筛选器立即刷新，显示用户固定的科室

##### **H2.3 内容逻辑与排序规则**

###### **筛选器Tab显示优先级**
```
[推荐] + [用户固定科室(⭐,按用户排序)] + [平台推荐科室(按热度)] + [全部 ≡]
   ①              ②                              ③                    ④
```

1. **推荐Tab (①)**: 始终固定在第一位
2. **用户固定科室 (②)**: 带⭐标识，按用户设置的顺序显示
3. **平台推荐科室 (③)**: 填充剩余位置（排除已固定的），按观看热度/活跃度排序
4. **全部入口 (④)**: 始终固定在最右侧

###### **筛选器可见数量**
- 默认显示约**8-10个Tab**（具体取决于屏幕宽度和科室名称长度）
- 超出部分需要横向滑动查看

##### **H2.4 技术实现要点**

###### **数据存储**

**LocalStorage结构** (未登录用户或本地缓存):
```typescript
interface UserCategoryPreferences {
  pinnedDepartments: string[];  // 固定的科室ID数组，顺序即为显示顺序
  lastUpdated: number;           // 最后更新时间戳
}

// 示例
{
  pinnedDepartments: ['dept_005', 'dept_012'], // 眼科、胃肠外科
  lastUpdated: 1698765432000
}
```

**服务器存储** (已登录用户，支持跨设备同步):
```typescript
// POST /api/user/preferences
{
  type: 'pinned_departments',
  data: ['dept_005', 'dept_012']
}

// GET /api/user/preferences
// 返回用户的所有偏好设置
```

###### **前端渲染逻辑**

```typescript
function getCategoryTabs() {
  const pinnedDepts = getUserPinnedDepartments(); // 从LocalStorage或API获取
  const allDepts = getAllDepartments();            // 所有科室列表
  const defaultHotDepts = getDefaultHotDepartments(); // 平台热门科室
  
  const tabs = [{ id: 'recommend', name: '推荐', type: 'default' }]; // 第一个始终是"推荐"
  
  // 添加用户固定的科室（带星标）
  pinnedDepts.forEach(deptId => {
    const dept = allDepts.find(d => d.id === deptId);
    if (dept) {
      tabs.push({ 
        id: dept.id, 
        name: `⭐${dept.name}`, 
        type: 'pinned',
        isPinned: true 
      });
    }
  });
  
  // 填充剩余位置（排除已固定的）
  const remainingDepts = defaultHotDepts.filter(d => !pinnedDepts.includes(d.id));
  const visibleCount = Math.min(8, tabs.length + remainingDepts.length); // 最多显示8个
  tabs.push(...remainingDepts.slice(0, visibleCount - tabs.length - 1)); // -1 留给"全部"
  
  // 最后添加"全部"入口
  tabs.push({ id: 'all', name: '全部 ≡', type: 'all' });
  
  return tabs;
}
```

###### **状态管理**

- 固定/取消固定操作实时更新LocalStorage
- 如果用户已登录，debounce后同步到服务器（避免频繁请求）
- 首页筛选器监听LocalStorage变化，自动刷新

###### **性能优化**

- 科室列表支持虚拟滚动（如果科室数量 > 50）
- 搜索功能使用防抖（debounce 300ms）
- 拖拽排序使用原生drag API或成熟库（如react-beautiful-dnd）

#### **[首页模块 H3] 核心内容Feed (Content Feed) - 双列瀑布流 + 视图切换**

* **设计理念**: 这是对PC端布局的**最大改动**。我们放弃PC端的`网格(Grid)`和`分页(Pagination)`，转而使用移动端主流的**双列瀑布流 (Masonry Layout)**，并支持**无限滚动**。
* **布局选型**: 参考Bilibili移动端、小红书、YouTube移动端的成熟方案，默认采用**双列**，理由：
    * ✅ **屏幕利用率更高**：双列可充分利用横向空间（约90% vs 单列50%）
    * ✅ **视觉更丰富**：一屏展示更多内容，降低滑动疲劳
    * ✅ **符合用户习惯**：主流视频/内容平台均采用双列布局

##### **H3.0 视图模式切换 (View Mode Toggle) - V1.2 新增功能 ⭐**

* **功能定位**: 让用户根据场景需求，在"快速浏览"和"深度查看"之间自由切换

###### **H3.0.1 交互触发设计（创新点）**

* **主触发方式：长按首页Tab ⭐**
    * **触发操作**：长按底部导航栏的 `[首页]` Tab（500-600ms）
    * **触发反馈**：
        * 震动反馈（`uni.vibrateShort()`）
        * Tab图标轻微缩放动画
        * 弹出快捷菜单浮层
    * **设计优势**：
        * ✅ 不占用顶部宝贵空间
        * ✅ 充分利用Tab栏的"闲置交互"
        * ✅ 操作路径最短（拇指就在底部）
        * ✅ 符合主流App习惯（微信、抖音都有长按Tab交互）

* **快捷菜单设计**：
    ```
    ┌─────────────────────────────┐
    │  ⚙️ 首页快捷设置              │
    ├─────────────────────────────┤
    │  ☷  双列模式  ✓              │  ← 当前选中
    │  ≡  单列模式                 │
    ├─────────────────────────────┤
    │  🔄  刷新推荐                │
    │  ⬆️  回到顶部                │
    └─────────────────────────────┘
    ```
    * 位置：底部Tab上方弹出（避免手指遮挡）
    * 样式：圆角卡片 + 轻微阴影
    * 动画：从底部滑入（200ms）
    * 关闭：点击选项后自动关闭，或点击空白区域关闭

* **备用触发方式**（可选）：
    * 首页顶部右上角放置一个小图标（`⋯` 或 `⚙️`），点击弹出相同菜单
    * 用于不了解长按操作的用户

* **全局生效范围**：
    * 用户在**任意页面**长按首页Tab都可以触发切换

###### **H3.1.2 交互设计**

**滑动切换（支持连续滑动）**：

* **手势识别**：
    * 用户在焦点图区域**左滑**：切换到下一张
    * 用户在焦点图区域**右滑**：切换到上一张
    * 支持**快速连续滑动**（如：连续左滑3次，快速切换3张卡片）
    * 滑动速度阈值：手指移动速度 > 300px/s 视为快速滑动

* **点击交互**：
    * **点击中间卡片**：跳转到对应的直播间或活动页面
    * **点击左侧卡片**：切换到上一张（同时该卡片移动到中间）
    * **点击右侧卡片**：切换到下一张（同时该卡片移动到中间）

* **切换动画**：
    * 动画时长：**300ms**（流畅但不拖沓）
    * 缓动函数：`cubic-bezier(0.4, 0, 0.2, 1)` (Material Design标准)
    * 同时动画：
        * 位置平移 (translateX)
        * 缩放 (scale)
        * 透明度 (opacity)
        * 亮度 (brightness)

* **无限循环**：
    * 当滑动到最后一张时，继续右滑自动跳转到第一张（无缝循环）
    * 当滑动到第一张时，继续左滑自动跳转到最后一张

##### **M1.3 智能流量提醒 (V1.2核心功能) ⭐**

* **功能目标**: 在用户使用流量网络观看直播时，自动检测并提醒，避免意外消耗大量流量，提升用户体验。

###### **触发时机**

1. **进入直播间时**: 页面加载完成后立即检测网络类型
2. **点击播放按钮时**: 用户主动点击播放时再次检测（如果网络切换）

###### **检测逻辑**

```typescript
// 使用 uni.getNetworkType() API
uni.getNetworkType({
  success: (res) => {
    const networkType = res.networkType;
    // networkType: wifi / 2g / 3g / 4g / 5g / ethernet / unknown / none
    
    const isCellular = ['2g', '3g', '4g', '5g'].includes(networkType);
    
    if (isCellular) {
      showCellularWarning(networkType);
    }
  }
});
```

```

* **预加载策略**:

    * 如果标题超过2行，第2行末尾显示省略号 `...`，并在右侧显示 `[展开 ▼]` 按钮（小字、灰色）
    * **示例**:
      ```

      2025年秋季学术研讨会第三场... [展开 ▼]
      ```

* **展开状态 (Expanded)**:
    * 点击 `[展开 ▼]` 或点击标题本身，显示**完整标题**（不限行数）
    * 按钮文字变为 `[收起 ▲]`
    * 添加淡入动画（fade-in）
    * **示例**:
      ```
      肝胆胰外科微创手术的最新进展与病例讨论会——

      ```

* **自动判断逻辑**:
    * 如果标题 ≤ 2行：不显示 `[展开]` 按钮，直接显示完整标题
    * 如果标题 > 2行：启用智能折叠

##### **M4.2 滚动阶段详解**

###### **阶段1：初始状态（Initial State）**

```
用户刚进入直播间
    ↓
播放器：全尺寸显示（占屏幕约1/3）
直播信息区：完全可见
Tabs：位于信息区下方（可能需要向下滚动才能看到）
Tab内容：不可见
```

###### **阶段2：向下滚动 - 推走信息区（Scroll Down - Collapse Header）**

| 滚动距离 | 播放器状态 | 信息区可见度 | Tabs位置 | Tab内容 |
|---------|-----------|------------|---------|---------|
| **0px** | 全尺寸 | 100% | 屏幕下方 | 不可见 |
| **100px** | 全尺寸 | 50% | 向上移动 | 不可见 |
| **200px** | 全尺寸 | 10% | 接近播放器底部 | 不可见 |
| **240px** | **开始小窗** | 几乎不可见 | 接近顶部 | 不可见 |
| **≥300px** | **小窗固定** | **完全被推走（0%）** | **吸顶固定** ⭐ | **开始滚动** |

```
用户继续向下滑动
    ↓
直播信息区（M2）逐渐被推出屏幕顶部
    ↓
当滚动距离 > 240px 时：
  - 播放器缩小为小窗（右下角，200x112px）
  - 直播信息区完全被推走
  - Tabs到达页面顶部（或播放器底部）
    ↓
**Tabs吸顶（position: sticky; top: 0;）**
    ↓
用户继续向下滑动
    ↓
Tabs位置保持不变（固定在顶部）
    ↓
只有Tab内容区继续向上滚动
```

###### **阶段3：Tab吸顶后的滚动（Tabs Sticky - Content Scrolling）**

```
┌─────────────────────────────────────────┐
│  [小窗播放器 - 右下角固定]              │ ← 小窗模式
├═════════════════════════════════════════┤
│  [详情] [聊天] [问答] [推荐]  ← 吸顶！  │ ← Tabs固定在这里
├─────────────────────────────────────────┤
│  Tab内容第10行                           │ ← Tab内容继续滚动
│  Tab内容第11行                           │
│  Tab内容第12行                           │
│  ...                                     │
└─────────────────────────────────────────┘

用户继续向下滑动
    ↓
Tabs位置不变（保持吸顶）
    ↓
Tab内容继续向上滚动
    ↓
显示更多Tab内容（第20行、第30行...）
```

**关键行为**：
- ✅ Tabs固定在页面顶部（或小窗播放器下方）
- ✅ Tab内容独立滚动
- ✅ 直播信息区（M2）完全被隐藏
- ✅ 用户可以专注浏览Tab内容（聊天、问答、详情等）

###### **阶段4：向上滚动 - 恢复信息区（Scroll Up - Expand Header）**

```
用户向上滑动
    ↓
Tab内容向下滚动
    ↓
Tab内容滚动到顶部了吗？
    ↓ 否
继续滚动Tab内容（Tabs保持吸顶）
    ↓ 是（Tab内容已到顶）
继续向上滑动会触发"恢复模式"
    ↓
Tabs开始向下移动（取消吸顶）
    ↓
直播信息区（M2）重新显示
    ↓
播放器从小窗恢复到全尺寸
    ↓
最终回到初始状态
```

```
【Tab内容滚动到顶部】
┌─────────────────────────────────────────┐
│  [小窗播放器]                            │
├═════════════════════════════════════════┤
│  [详情] [聊天] [问答] [推荐]            │ ← Tabs吸顶
├─────────────────────────────────────────┤
│  Tab内容第1行 ← 已经到顶了！             │
│  Tab内容第2行                            │
└─────────────────────────────────────────┘

        ↓ 用户继续向上滑动
        
【开始恢复】
┌─────────────────────────────────────────┐
│  [播放器开始恢复...]                     │
├─────────────────────────────────────────┤
│  [直播信息区逐渐显示...]                 │
│  肝胆胰外科微创手术...                   │
├─────────────────────────────────────────┤
│  [详情] [聊天] [问答] [推荐]            │ ← Tabs向下移动
├─────────────────────────────────────────┤
│  Tab内容第1行                            │
└─────────────────────────────────────────┘

        ↓ 继续向上滑动
        
【完全恢复到初始状态】
┌─────────────────────────────────────────┐
│                                          │
│         [播放器 - 全尺寸]                │
│                                          │
├─────────────────────────────────────────┤
│  肝胆胰外科微创手术的最新进展...         │
│  🔴 LIVE  1.1万人观看                    │
│  [👨‍⚕️] 张三 教授        [+ 关注]        │
│  ❤️收藏  📥下载资料  🔗分享              │
│  [#微创手术] [#胰腺癌] [+4]             │
├─────────────────────────────────────────┤
│  [详情] [聊天] [问答] [推荐]            │
├─────────────────────────────────────────┤
│  Tab内容第1行                            │

##### **P3.2 昼夜模式选项详解**

###### **选项1：跟随系统 (Auto Mode)**

* **功能**: 自动跟随手机系统的明暗模式设置
* **适用场景**: 用户希望App与系统保持一致
* **技术实现**:
    * 监听系统主题变化事件（`uni.onThemeChange` 或 `window.matchMedia`）
    * 系统切换时，App立即跟随切换
* **提示文案**: "自动切换深色/浅色模式"

###### **选项2：浅色模式 (Light Mode)**

* **功能**: 始终使用浅色主题（白色背景）
* **适用场景**: 用户在光线充足的环境使用，或偏好浅色风格
* **提示文案**: "始终使用浅色主题"

###### **选项3：深色模式 (Dark Mode)**

* **功能**: 始终使用深色主题（深色背景）
* **适用场景**: 用户在夜间或暗光环境使用，或偏好深色风格
* **提示文案**: "始终使用深色主题"
* **颜色规范** (参考Bilibili深色模式):
    * **背景色**: 
        * 主背景 `#0E0E0E` 或 `#141414`（纯黑或深灰）
        * 卡片背景 `#1F1F1F` 或 `#2C2C2C`
    * **文字颜色**:
        * 主文字 `#E5E5E5` 或 `#FFFFFF`
        * 次要文字 `#999999` 或 `#AAAAAA`
        * 三级文字 `#666666`
    * **边框颜色**: `#2F2F2F` 或 `#3A3A3A`
    * **主题色**: 保持不变（如：蓝色 `#509CEC`），但可适当降低饱和度
    * **按钮背景**: 深灰 `#2A2A2A`，悬停 `#3A3A3A`

###### **选项4：定时切换 (Scheduled Mode)**

* **功能**: 用户自定义每天自动切换的时间
* **点击行为**: 进入"定时切换设置"二级页面
* **提示文案**: "设置每天自动切换的时间"

**功能详解**：

* **深色模式开始时间**: 
    * 默认值：21:00（晚上9点）
    * 用户可自定义：如 20:00、22:00 等
    * 点击后弹出时间选择器（HH:MM格式）

* **浅色模式开始时间**:
    * 默认值：07:00（早上7点）
    * 用户可自定义：如 06:00、08:00 等
    * 点击后弹出时间选择器（HH:MM格式）

* **自动切换逻辑**:
    ```
    当前时间 >= 深色模式开始时间 && 当前时间 < 浅色模式开始时间
      → 自动切换到深色模式
    
    当前时间 >= 浅色模式开始时间 && 当前时间 < 深色模式开始时间
      → 自动切换到浅色模式
    ```

* **定时检查机制**:
    * App启动时：检查当前时间，应用对应主题
    * 定时轮询：每分钟检查一次（轻量级任务）
    * 后台唤醒：App从后台返回前台时，重新检查时间

##### **P3.5 切换动画与过渡效果**

**动画设计** (参考Bilibili):

* **过渡时长**: 300ms（流畅但不拖沓）
* **缓动函数**: `cubic-bezier(0.4, 0, 0.2, 1)` (Material Design标准)
* **动画效果**:
    * **渐变过渡**: 背景色和文字颜色平滑渐变，而非突兀切换
    * **淡入淡出**: 页面元素先淡出再淡入（避免视觉闪烁）
    * **保持连续性**: 切换时保持页面滚动位置和状态

##### **P3.7 技术实现要点**

**系统主题检测**:

```typescript
// uni-app API
uni.getSystemInfo({
  success: (res) => {
    const theme = res.theme; // 'light' | 'dark'
    console.log('系统主题:', theme);
  }
});

// 监听系统主题变化
uni.onThemeChange((res) => {
  const theme = res.theme; // 'light' | 'dark'
  if (themeMode === 'auto') {
    applyTheme(theme);
  }
});
```

**定时切换检查**:

```typescript
// 定时检查（每分钟一次）
const checkScheduledTheme = () => {
  if (themeMode !== 'scheduled') return;
  
  const now = new Date();
  const currentTime = `${now.getHours().toString().padStart(2, '0')}:${now.getMinutes().toString().padStart(2, '0')}`;
  
  const darkTime = scheduledDarkTime; // 如 "21:00"
  const lightTime = scheduledLightTime; // 如 "07:00"
  
  // 判断当前应该是什么模式
  let shouldBeDark = false;
  
  if (darkTime < lightTime) {
    // 跨天情况（如：深色21:00-次日07:00）
    shouldBeDark = currentTime >= darkTime || currentTime < lightTime;
  } else {
    // 同一天（如：深色12:00-18:00）
    shouldBeDark = currentTime >= darkTime && currentTime < lightTime;
  }
  
  const targetTheme = shouldBeDark ? 'dark' : 'light';
  
  if (currentTheme !== targetTheme) {
    applyTheme(targetTheme);
  }
};

// 启动定时检查
setInterval(checkScheduledTheme, 60000); // 每60秒检查一次
```

**主题应用函数**:

```typescript
const applyTheme = (theme: 'light' | 'dark') => {
  // 更新根元素class
  const rootElement = document.documentElement;
  rootElement.classList.remove('light-theme', 'dark-theme');
  rootElement.classList.add(`${theme}-theme`);
  
  // 更新状态栏颜色（原生App）
  // #ifdef APP-PLUS
  plus.navigator.setStatusBarStyle(theme === 'dark' ? 'light' : 'dark');
  // #endif
  
  // 保存当前主题
  currentTheme = theme;
  
  // 触发主题变化事件（供其他组件监听）
  uni.$emit('themeChanged', theme);
};
```

| 特性 | 用户价值 | 技术实现 |
|------|----------|----------|
| **三种模式** | 满足不同用户的使用习惯 | 手动/跟随系统/定时切换 |

* **参考Bilibili成功经验**: B站的昼夜模式切换流畅、配色合理，用户满意度高
