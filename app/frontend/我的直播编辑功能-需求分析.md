## ⚠️ 五、品牌关联功能说明

根据后端设计文档分析，**品牌功能**的数据结构如下：

### 现有架构（后端文档）

```
brands（品牌表）
  ├─ id
  ├─ name
  ├─ logo_url
  └─ description

brand_topics（品牌-专题关联表）
  ├─ brand_id → brands.id
  └─ topic_id → topics.id

topics（专题表）
  ├─ id
  ├─ title
  └─ ...

live_rooms（直播间表）
  ├─ id
  ├─ title
  └─ ... （❌ 没有 brand_id 字段）

live_sessions（场次表）
  ├─ id
  ├─ room_id
  └─ ... （❌ 没有 brand_id 字段）
```

### 问题

**当前架构不支持"直播间/场次 ↔ 品牌"的直接关联**

- `brand_topics`表只关联品牌和专题
- `live_rooms`和`live_sessions`表都没有`brand_id`字段

### 解决方案

**方案A：通过专题间接关联（推荐）**

流程：
1. 直播间关联专题（`live_rooms.topic_id`或新增关联表）
2. 专题关联品牌（`brand_topics`表）
3. 通过专题间接获取品牌信息

优点：
- 不需要修改现有表结构
- 符合后端设计文档的专题功能定位

缺点：
- 必须先创建专题
- 关联链路较长

**方案B：新增直接关联（需后端支持）**

修改点：
1. 在`live_rooms`表新增字段：
   ```sql
   ALTER TABLE live_rooms ADD COLUMN brand_id UUID NULL;
   ALTER TABLE live_rooms ADD CONSTRAINT fk_live_rooms_brand_id 
       FOREIGN KEY (brand_id) REFERENCES brands(id) ON DELETE SET NULL;
   ```

2. 或新增关联表：
   ```sql
   CREATE TABLE room_brands (
       room_id UUID NOT NULL,
       brand_id UUID NOT NULL,
       PRIMARY KEY (room_id, brand_id)
   );
   ```

优点：
- 直接关联，逻辑清晰
- 前端实现简单

缺点：
- 需要修改后端表结构和API
- 与现有专题功能冗余

**推荐**：
- **短期**：暂时不实现品牌编辑功能，等待后端明确方案
- **长期**：采用方案A（通过专题关联），集成专题管理功能
