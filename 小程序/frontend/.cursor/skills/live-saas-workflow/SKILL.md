# Live-Saas 工作流

## 本 Skill 做什么

根据**用户当前请求**选择角色与改动范围。  
习惯与分流以 [AI-工作约定](docs/AI-工作约定.md) 为准。  
不下达用户未点名的功能或文档待办。

**相关文档链接**：本 Skill（及 Agent）凡点名仓库内文件，须用可跳转 Markdown 链接（相对仓库根）；禁止裸路径/仅文件名。细则见 [AI-工作约定 §8](docs/AI-工作约定.md)。

## 流程

1. 打开并遵守 [AI-工作约定](docs/AI-工作约定.md)
2. 按本轮诉求归类：探索 / 前端实现 / 文档 / 仅建议
3. **Read** 匹配 Agent 文件：[explorer](.cursor/agents/explorer.md) | [frontend](.cursor/agents/frontend.md) | [docs](.cursor/agents/docs.md)；禁止只贴角色名
4. 新建文档或改前端时，再按下文打开对应规范/模板（按需，不预读全库）；**改 `src/**` 须先有文档依据**（见 [AI-工作约定 §4.1](docs/AI-工作约定.md)）
5. 非单句问答的落地执行 → **必须**启用 Skill [action-checklist](.cursor/skills/action-checklist/SKILL.md)：  
   - 先选**最小化、最友好**方案 → 防填洞 → **把行动清单写进对用户可见的回复** → 按步做 → 自测收尾  
   - 清单须点名依据文档（可跳转链接 + 章节/Endpoint）；默念清单 / 只建内部 Todo = **未执行**
   - 改功能行为时自测还须遵守 [acceptance-handtest](.cursor/skills/acceptance-handtest/SKILL.md)（L2 六句；`docs/05` 不能替代日常手测）
6. 改管理端列表 / 选择器 / 批量操作 → Agent [frontend](.cursor/agents/frontend.md)「管理端表面」原则

## 任务分级（S/M/L）：选闸门，不堆长链

真源：[AI-工作约定 §4.2](docs/AI-工作约定.md)。摘要：

| 级别 | 何时 | 要做 | 不做 |
|------|------|------|------|
| **S** | 文案/样式/单点 | 依据（若碰契约）→ 最小改 → 自测 | 代码提示词落盘、正式报告、强行补全套测试 |
| **M** | 一页/一 API | 钉点或补设计 → 摘录字段 → 改码 → 设计↔代码核对 + 手测 | 默认跑后端 6 步主控；每步检测报告 |
| **L** | 新模块/多层生成 | 完整设计 →（可）代码生成提示词 → 分层出码 → 一致性闸 → 可验收 | 把提示词当业务交付物长期堆积 |

主干口令：**钉需求 → 设计/契约 → 实现 → 对齐 → 可验收**。  
「代码提示词」仅 L（或用户点名）的 AI 脚手架；**可验收**底线见 §4.2，测试文件按需。

## 改代码：文档依据与契约对齐（强制）

细则真源：[AI-工作约定 §4.1](docs/AI-工作约定.md)。摘要：

- **先读再改**：命中模块的后端/前端设计（Endpoint、Schema、字段表），再动 `api` / `types` / 表单 / 解析  
- **严格对齐**：字段名、字段集合（不多不少）、必填/可选、类型与枚举、数量与长度、格式、method/path/权限、响应 `data` 形状  
- **写出摘录**：对用户可见摘录本次必要字段（路径、请求/响应关键字段、约束），禁止只写「已对齐」  
- **缺口提醒**：文档缺失、文档有代码无（或反之）、行业常见但未入库的字段/能力 → 在结果中标明并给建议；**未确认不进代码**  
- **禁止**：无依据发明字段；擅自改名；用别的模块字段表硬套  
- **冲突**：多文档时在清单写明以谁为准；与已上线代码冲突须标明偏差，不得 silently 改契约含义

## 范围

| 用户意图 | 行为 |
|----------|------|
| 明确要改代码或文档 | 在对应角色边界内完成；先可见清单再改 |
| 只要分析或建议 | 不改仓库、不 commit；仍须可见清单（只读步骤） |
| 报 bug / 排查 | 一律走 [action-checklist](.cursor/skills/action-checklist/SKILL.md)（根因 → 最小修复 → 自测）；不得当单句问答跳过 |
| 未提及的主题 | 不主动扩展 |

## 新建文档：命名与模板

权威规范：[通用规范-文件创建规范-v1.0](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)（命名、目录、必填字段、检查清单）。  
新建或重命名文档前**先读该规范**；与模块专属规范冲突时以模块规范为准并记原因。

### 1. 能匹配到模板的，用模板

按文档类型选骨架，**先套模板再填内容**，不要空手自创结构：

| 文档类型 | 模板 / 样本 |
|----------|-------------|
| 后端模块完整设计 | [后端设计文档模板](docs/后端设计文档模板.md) |
| 增量设计（V2/V3…） | [增量设计文档模板](docs/增量设计文档模板.md) |
| 规范类 | [文件创建规范](docs/前端规范样本/通用规范-文件创建规范-v1.0.md) §六「规范类文档模板」 |
| 设计类 / 指南 / HANDOFF | [文件创建规范](docs/前端规范样本/通用规范-文件创建规范-v1.0.md) §五对应必填 + §六可复制模板 |
| 已有编号系列（如现状全景、跨模块决策、页面编排） | **沿用该系列已有文首体例与命名习惯**，不另起一套 |
| 前端单功能设计 | 对齐既有 `Live-Saas-Wechat-*-前端设计文档-vX.Y.md` 同类文件；**须含** [AI-工作约定 §5.1](docs/AI-工作约定.md) 体验钉 + 落地层（见 [文件创建规范 §5.2.1](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)）；勿另开第三本「页面设计」 |

### 1.1 写前端设计文档时的顺序

1. 答体验钉五问（给谁用 / 闭环 / 首屏 / 关键态 / 非目标）  
2. 再写 API/类型/落点（§4.1 零偏差）  
3. 小增量可压缩体验为短表；跨多页才考虑「页面编排」类文档，仍不默认「页面设计」第三本  

### 2. 命名格式（摘要；细节以文件创建规范为准）

- 文档须可识别：主题清晰；规范/设计类带版本；传输场景建议含项目名  
- 规范类：`通用规范-<主题>规范-v<版本>.md`  
- 设计类：`<项目>-<主题>设计文档-v<版本>.md`（本仓项目名常用 `Live-Saas-Wechat`）  
- 开发指南：`<模块>功能模块开发指南-v<版本>.md`  
- 交付：`HANDOFF_<模块>_<范围>_交付说明-v<版本>.md`  
- 问题对齐：`<主题>-问题清单-YYYY-MM-DD.md` 等  
- 代码/配置：英文命名（`.ts` lowerCamelCase，`.vue` 组件 PascalCase，目录 kebab-case）  
- 禁止 Windows 非法字符；文档可中文，代码文件名不夹 `dev`/`prod`、不留无名 `temp`

存放：业务设计进 `docs/`；可复用通用规范进 [前端规范样本](docs/前端规范样本/)；不随意新增顶层目录。

## 改文档 / Skill / Rule / Agent：补丁还是重写

**口令**：意思没变 → 局部补丁；意思变了或靠「不是/不要」纠偏 → 重写该节（短文件可整份重写）。

| 情况 | 做法 |
|------|------|
| 错别字、版本号、日期、修订历史一行、表内改一两格 | 局部补丁 |
| 叠否定句纠正旧表述 | 重写该段/该节 |
| 章节职责或定位变化 | 重写该节；短文件优先整份重写 |
| 长设计文档仅局部口径变化 | 只重写该小节 |

习惯有变：先改 [AI-工作约定](docs/AI-工作约定.md)，再对齐 Cursor 短文件。

## 禁止

- 扩大到用户未提出的模块、文档或重构  
- 不套已有模板却自创一套文档结构/命名  
- 改前端却忽略本应命中的 [前端规范样本](docs/前端规范样本/)  
- 与 [AI-工作约定](docs/AI-工作约定.md) 或 [文件创建规范](docs/前端规范样本/通用规范-文件创建规范-v1.0.md) 冲突的流程  
- 定了角色却不 Read [`.cursor/agents/<角色>.md`](.cursor/agents/)  
- 非单句任务不写可见行动清单、或不按清单做、或不自测收尾  
- 点名相关文档却只写裸路径/文件名、无可跳转 Markdown 链接  
- 改 `src/**` 无文档依据却发明/改写契约字段、路径或响应形状（见 [AI-工作约定 §4.1](docs/AI-工作约定.md)）  
- 声称已对齐却不摘录必要字段，或把未确认的行业常见建议 silently 写进代码  
- 把 [04](docs/04_开发文档规范/)/[05](docs/05_测试规范/)/提示词母版整本塞进每次任务；或 S/M 强制代码提示词落盘与报告博物馆
