# 可验收手测（通用法则）

真源底线：[AI-工作约定 §4.2](docs/AI-工作约定.md)。  
本 Skill 把「自测绿、使用才炸」的防漏测法则写死；**不**替代 [action-checklist](../action-checklist/SKILL.md) 的清单节奏，在其「可验收最小集」上补强 **L2 手测**。

## 何时启用

| 必须 Read 本 Skill | 可不启用 |
|--------------------|----------|
| 改功能行为（页/API 对接/状态机/乐观 UI） | 纯文案、纯样式、单点事实问答 |
| 自测收尾写「验证方式 / 手测步骤」 | 只改文档且不动完成定义 |
| 用户问怎么测、验收、为何自测过了线上还有洞 | — |

口令：**AI 勾清单 ≠ 人已验收**；缺 L2 手测步骤不得宣称功能可验收。

## 三层测法（通用）

```text
L1 契约/代码自测（AI 擅长）
   → 路径、字段、必填、错误码、响应形状对不对？

L2 页面行为手测（人必须做，3～8 步）
   → 真实入口走一遍，屏幕上「该看见的」看见了吗？

L3 回归/自动化（按需）
   → 易碎逻辑才写测；≠ 每次 80% 覆盖率、≠ 每步正式报告
```

| 层 | 谁做 | 过关标准 |
|----|------|----------|
| L1 | AI / 契约摘录 | 与设计文档 Endpoint、字段一致（[§4.1](docs/AI-工作约定.md)） |
| L2 | 你或明确手测步骤 | 完成定义写成「看见什么」，步骤可复现 |
| L3 | 按需 | 锁回归；里程碑再对照 [05 测试规范](docs/05_测试规范/) |

**常见假通过**：只有 L1 绿；乐观更新让「自己那条」出现就勾「讨论 OK」；用空数据对象验「列表有数据」。

## L2 六句（每次改功能行为必过）

自测表或回复中须出现对应手测意图（可压缩成条目，不可默念）：

1. **完成定义**：用户怎样叫做完？→ **看见什么**（不是接口 200）  
2. **入口**：从哪个真实入口进？（首页 / 分享 / 无场次房间模式 / 管理端菜单…）  
3. **依赖时序**：要等 id / 登录态 / Tab 吗？→ **先后顺序反过来再测一遍**  
4. **有数据环境**：列表类用**已知有数据**的对象；空对象只验空态  
5. **写操作拆开验**：本地立刻出现 ≠ 服务端列表已加载（乐观 UI **必拆两项**）  
6. **关键态**：空 / 失败 Toast / 未登录 / 无权限（设计已写的都点）

口令：完成定义写「能发」而不写「能看见历史」→ 必假通过。

## 按功能类型加测（在六句之上）

| 类型 | 额外必测 |
|------|----------|
| 列表 / 分页 | 有数据对象；加载更多；换对象后不串数据 |
| Tab / 多状态页 | 先切 Tab 再等数据；数据后到仍刷新；勿只靠 pager change |
| 乐观更新 | 成功替换临时 id；失败回滚；历史不被冲掉 |
| 表单提交 | 校验、重复点击、提交中禁用 |
| 图片 / 媒体 | 上传成功路径 vs 展示 URL；模拟器与真机分开想 |
| 权限 | 未登录引导；无权限文案与跳转 |

修完回写一行「曾漏测场景」到设计/自测（可选但推荐），避免下次再漏。

## 与 `docs/05_测试规范` 的关系

| 文档 | 定位 | 日常用法 |
|------|------|----------|
| [测试规范文档](docs/05_测试规范/测试规范文档.md) | 平台级 QA 愿景（覆盖率、性能、工具链） | **按需查表**；禁止每个 M 任务照做 80%/JMeter |
| [测试用例](docs/05_测试规范/测试用例.md) | 粗粒度功能清单 | 提测/里程碑补 P0；**不能**单独当前端日常验收 |
| 本 Skill + [§4.2](docs/AI-工作约定.md) | 改功能行为后的可验收底线 | **默认用这个** |

粗用例例：「发送成功并显示在评论区」——乐观更新即可过，**挡不住**「进 Tab 看不见历史」。细验收必须落到六句 + 类型加测。

## 交付时自测表须含（改功能行为）

在 [action-checklist](../action-checklist/SKILL.md) 可验收 A～D 之外，明确：

| # | 检查项 | 结果写法 |
|---|--------|----------|
| L1 | 契约摘录已做 | ✅/N/A |
| L2 | 六句已落实为手测步骤（或已手测） | ✅ + 3～8 步要点 |
| L2+ | 命中类型的加测 | ✅/N/A |
| L3 | 是否需要自动化 | 按需；无则写「本轮不写测」 |

禁止：只有「自测通过」四字；把「编译无报错」当成 L2。

## 与其它 Skill

```text
live-saas-workflow  → 分流 / S/M/L
action-checklist    → 可见清单 + 自测表骨架
acceptance-handtest → 自测里「怎么算测够」（本文件）
```

## 禁止

- 用 L1 冒充 L2  
- 完成定义只写接口成功、不写用户可见结果  
- 空数据环境验收「列表有内容」  
- 乐观 UI 只验本地气泡  
- 把 [05](docs/05_测试规范/) 整本塞进每次任务或要求每步正式报告  
- 按业务模块再拆第四、第五个「测试 Skill」；细则不足时补本文件一节即可
