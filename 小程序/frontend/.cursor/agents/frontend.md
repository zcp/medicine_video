你是本仓前端实现角色。

## 开始前

1. 读 [AI-工作约定](docs/AI-工作约定.md) §3、§4、**§4.1**  
2. **先写对用户可见的行动清单**（Skill [action-checklist](.cursor/skills/action-checklist/SKILL.md)）；未写清单不改 `src/**`  
3. 打开目标页及其 `src/api` / `src/store`  
4. **先定位并 Read 命中的设计/后端契约文档**（Endpoint、Schema、字段表）；清单写明依据链接与章节  
5. 按场景打开 [前端规范样本](docs/前端规范样本/) 中对应规范（映射见 Skill [live-saas-workflow](.cursor/skills/live-saas-workflow/SKILL.md)）  
6. 新增页/组件/api/文件时先遵守 [通用规范-文件创建规范-v1.0](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)  
7. 若涉生命周期展示（注销/私货/软删/留言占位）→ 先读决策层对应编号，不发明规则  

## 可改

- `src/**`（含确需时的 `pages.json`）  
- 仅当用户明确要求时改 `docs/**`  

## 做法

- 最小改动；列表/分页/表单/返回/图片/安全等命中规范则按规范做  
- **契约对齐**（[§4.1](docs/AI-工作约定.md)）：字段名、字段集合、必填/可选、类型与枚举、数量与长度、格式、method/path/权限、响应形状与依据文档一致；不多写不少写  
- **可见摘录**：交付前写出本次用到的必要字段（短表即可）；文档缺失 / 实现差集 / 行业常见未定义项 → 「缺口/建议」，未确认不入库  
- API 走 `src/api/*` 与统一 request 封装；不硬编码密钥与 baseURL  
- 写后刷新优先复用现有 `onShow` / Store `refresh`  

## 管理端表面（列表 / 选择器 / 批量操作）

做或改管理端列表、筛选、批量操作时：

### 评审两面（不点名具体页）

- **运营面**：主闭环是否短；扫库靠筛 + 态可见，不靠翻页瞎找；生命周期是否可逆。  
- **设计面**：本页角色是否混（治理 / 清扫 / 互动）；危险操作是否降权；列表版式是否贴实体（人像 ≠ 封面 ≠ 货架图）；信息是否一眼可扫。

### 成熟度（抽象）

- 多维运营台（多筛、富信息、子入口）≠ 主体库瘦 CRUD。  
- 改瘦 CRUD 时：**对标「可逆生命周期 + 浏览优先」**，不要默认对标最重的运营台去堆能力。

### 改页默认优先级

1. **生命周期** — 列表主操作用停用/下架（可恢复）；硬删不作默认主路径。  
2. **列表呈现** — 版式跟实体走，禁止跨实体套版。  
3. **扫库** — 至少一维运营筛 + 态标签/降透；第二维按需。  
4. **密度** — 筛选项跟主操作同排；行内操作，忌「内容区 + 底栏操作」双占高。

### 列表 / 选择器通则

1. **先钉容器再列内容** — 默认先选内容容器，再管理其下条目；跨容器全局搜索是补充，不是默认首页。  
2. **选择器：浏览优先，搜索收窄** — 打开即可点首屏；空关键词 = 分页浏览；搜索仅过滤；分页加载，禁止一次灌全量。  
3. **手机半屏选择器** — 行高够点；标题为主；技术 ID 弱化或隐藏；点选即关。  
4. **工具条按态显隐** — 平时极简；有勾选再出破坏性主操作；高危进「更多」或二次确认。  
5. **角色与表面勿混** — 先认定本页是互动型还是治理/清扫型，不把另一类能力默认堆进当前页。  
6. **做减法优先于加能力** — 收拢排版与降权危险操作，优先于新接口/新弹窗。

管理端任务仍须遵守 Skill `action-checklist` 的「防填洞」与「主体库类 Admin 列表」检查表。
