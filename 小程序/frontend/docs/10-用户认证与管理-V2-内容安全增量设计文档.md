## 📌 本次增量范围

### 1. 变更目标

| 字段 / 能力 | 方式 | 说明 |
|-------------|------|------|
| `nickname` | 文本规则引擎 `scene=nickname` | `PATCH /me` 写库前校验 |
| 头像图片 | 图片内容审核 API（§12 §1.4.6） | `POST /me/avatar` 落盘**前**校验；**当前仅占位** |

### 2. 变更类型

- 【修改】`PATCH /api/v1/users/me`：`nickname`（及 `bio` 等文本字段）接入 `check_content_safety(scene="nickname")`；**不接受 `avatar_url`**
- 【新增】`POST /api/v1/users/me/avatar`：上传 + `ImageModerationClient`（占位）+ 落盘 + 更新 DB `avatar_url`
- 【移除】`UserUpdateSelf.avatar_url` 字段、`avatar_url` 的 `image_meta` 规则、URL 前缀白名单 Pydantic 校验
- 【新增】`users_service_test` 库部署 `content_safety_rules` / `content_safety_logs`（DDL 见 12 §1.1–§1.3）

### 3. 明确不在本次范围

- 不改动登录、注册、密码、验证码流程
- 不新增独立公告相关能力
- 不改动用户表结构（`users` 表不新增字段）
- **users 库不挂载管理端规则维护 API**（V2.2 nickname 规则由 seed 初始化，见 12 §1.6）
- **不对接真实微信/云厂商图片审核 API**（仅占位 Client，见 §12 §1.4.6）

## 🔍 设计要点

### 1. 双库分治（users 侧）

| 维度 | 说明 |
|------|------|
| 数据库 | `users_service_test` |
| 文本校验场景 | `nickname` |
| 图片审核 | `POST /me/avatar` → `ImageModerationClient`（占位） |
| 默认文本规则 | **4 条**（nickname 四类 block × 1） |
| 规则维护 | seed 初始化；改词需更新 `users/app/content_safety/seed.py` |
| 图片审核配置 | 环境变量 `IMAGE_MODERATION_*`（占位，见 12 §1.4.6） |
| 管理端 API | ❌ V2.2 未挂载；审计日志存本库，**无对外查询 API** |

### 2. 昵称文本规则（与 12 §1.4.2 一致）

| 检测类型 | `match_type` | 说明 |
|----------|--------------|------|
| 外链 | `url` | http、www、短链、跳转域 |
| 联系方式 | `contact` | 手机号、QQ、微信号等 |
| 广告引流 | `fraud` | 加V、私聊、返利、兼职、刷单等 |
| 敏感词 | `keyword` | seed/常量维护词表 |

### 3. 头像图片审核（与 12 §1.4.6 一致）

| 项 | 说明 |
|----|------|
| 接入点 | `POST /api/v1/users/me/avatar`（multipart，`file`） |
| 审核时机 | **落盘前**读取文件字节，调用 `ImageModerationClient.moderate(scene="avatar")` |
| 占位 | `IMAGE_MODERATION_PROVIDER=placeholder`，**不请求外网**；默认 pass，可 stub reject 联调 |
| 通过 | 保存 `uploads/avatars/...`，更新 `users.avatar_url`，返回相对路径 |
| 违规 | 422 / `code=2005`，文件不落盘 |
| 审核故障 | 422 / `code=2004` |

> **禁止**：通过 `PATCH /me` 写入或校验 `avatar_url`；**不再使用** `check_content_safety(scene="avatar")` 与 URL 白名单。

### 4. 决策策略

**昵称（文本）** — 与 12 §1.4.5 一致：

| 决策 | 行为 | HTTP | code |
|------|------|------|------|
| `block` | 拒绝更新 | 422 | 2005 |
| `warn` | 允许更新，写审计日志（`reason_code=2006`） | 200 | 200 |
| `allow` | 正常更新，**不写审计日志** | 200 | 200 |
| 服务异常 | 拒绝更新 | 422 | 2004 |

**头像（图片）** — 与 12 §1.4.6 一致：仅 `pass` / `reject` / `error`，无 warn。

## 1. 核心流程增量

### 1.1 更新资料（PATCH，仅文本字段）

```
PATCH /api/v1/users/me
  Body: { "nickname"?: "...", "bio"?: "..." }   ※ 不含 avatar_url
  → 1. JWT 鉴权
  → 2. 若 Body 含 avatar_url → 400/4001（请使用 POST /me/avatar）
  → 3. nickname 有变更：check_content_safety(scene="nickname", field="nickname")
  → 4. block → 422/2005；文本安全异常 → 422/2004
  → 5. allow/warn：更新 users 表
  → 6. 仅 warn/block 时写入 content_safety_logs
  → 7. 返回用户信息（含只读 avatar_url）
```

### 1.2 上传头像（POST，图片审核占位）

```
POST /api/v1/users/me/avatar
  → 1. JWT 鉴权
  → 2. 校验文件类型/大小
  → 3. ImageModerationClient.moderate(file_bytes)   ※ placeholder，未接真实厂商
  → 4. 违规 → 422/2005
  → 5. 审核异常 → 422/2004
  → 6. 通过 → 保存 uploads/avatars/ → 更新 users.avatar_url
  → 7. 返回 { "avatar_url": "/uploads/avatars/xxx.jpg" }
```

微信小程序：`wx.chooseMedia` → `wx.uploadFile` 至本接口；**禁止**将 `wxfile://` 或外链 PATCH 为头像。

### 1.3 接口示例

**PATCH 传入 avatar_url（拒绝）**：

```json
{
  "code": 4001,
  "message": "avatar_url 请通过 POST /api/v1/users/me/avatar 上传",
  "data": null,
  "timestamp": "2026-07-03T10:00:00Z"
}
```

**昵称违规（block）**：

```json
{
  "code": 2005,
  "message": "内容违规：昵称命中联系方式拦截规则",
  "data": null,
  "timestamp": "2026-07-03T10:00:00Z"
}
```

**头像图片违规（审核拒绝）**：

```json
{
  "code": 2005,
  "message": "图片内容违规",
  "data": null,
  "timestamp": "2026-07-03T10:00:00Z"
}
```

**头像上传成功**：

```json
{
  "code": 200,
  "message": "success",
  "data": { "avatar_url": "/uploads/avatars/uuid.jpg" },
  "timestamp": "2026-07-03T10:00:00Z"
}
```
