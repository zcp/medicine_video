# 搜索服务合并操作指南

## 一、背景与架构变更概述

### 1.1 旧架构（Kafka 方案）

项目原本有两个独立的 backend 服务：

| 服务 | 目录 | 职责 |
|------|------|------|
| **Outer backend** | `backend/` | 独立搜索服务（simple_search_service）+ Kafka 聚合器（kafka_aggregator） |
| **Inner backend** | `live-streaming-saas-v2-main/backend/` | 主服务（live_core_service） |

**旧架构数据流**：
```
用户搜索请求
    ↓
simple_search_service（独立搜索微服务）
    ↓ 发送搜索事件到 Kafka Topic
Kafka Broker
    ↓ 消费消息
kafka_aggregator（聚合器）
    ↓ 批量写入
PostgreSQL（search_keyword_stats 表）
```

**旧架构特点**：
- 搜索服务独立部署，通过 Kafka 消息队列异步聚合搜索数据
- 需要维护 Kafka broker、Zookeeper 等中间件
- 搜索记录通过消息队列异步写入，存在延迟
- 系统复杂度高，运维成本大

### 1.2 新架构（直接写库方案）

现已将搜索功能合并到主服务 `live_core_service` 中，Outer backend 保留但弃用。

**新架构数据流**：
```
用户搜索请求
    ↓
live_core_service（主服务）
    ↓ 直接调用 record_search()
PostgreSQL（user_search_history + search_keyword_stats 表）
```

**新架构特点**：
- 搜索服务合并到主服务，无需独立部署
- 移除 Kafka 依赖，直接通过 PostgreSQL upsert 写入
- 同步写入，数据实时可见
- 系统简单，运维成本低

## 三、数据库设计

### 3.1 表结构

#### user_search_history（用户搜索历史表）

```sql
CREATE TABLE user_search_history (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    keyword VARCHAR(255) NOT NULL,        -- 原始关键词（保留大小写）
    keyword_norm VARCHAR(255) NOT NULL,   -- 标准化关键词（trim + 小写 + 压缩空白）
    search_count INT NOT NULL DEFAULT 1,  -- 同一用户搜同一词的累计次数
    last_searched_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, keyword_norm)         -- 同一用户同一词只保留一条
);

CREATE INDEX idx_user_search_history_user_time 
    ON user_search_history(user_id, last_searched_at DESC);
```

**字段说明**：
- `keyword_norm`：keyword 做 trim + 转小写后的值，用于去重
- `search_count`：同一用户搜同一词的累计次数
- `UNIQUE(user_id, keyword_norm)`：同一用户同一词只保留一条，重复搜时更新 count 和时间

**历史条数控制**：业务层限制每个用户最多保留 20 条，超出时删除最早的。

#### search_keyword_stats（热词统计表）

```sql
CREATE TABLE search_keyword_stats (
    id UUID PRIMARY KEY,
    keyword_norm VARCHAR(255) NOT NULL UNIQUE,  -- 标准化后的关键词，全局唯一
    keyword VARCHAR(255),                        -- 原始关键词（保留大小写）
    total_count BIGINT NOT NULL DEFAULT 0,       -- 所有用户搜索该词的总次数
    last_searched_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_search_keyword_stats_count 
    ON search_keyword_stats(total_count DESC);
```

**字段说明**：
- `keyword_norm`：标准化后的关键词，全局唯一
- `keyword`：原始关键词（保留大小写），用于搜索推荐显示
- `total_count`：所有用户搜索该词的总次数
- `last_searched_at`：最近一次搜索时间，用于过滤冷词

#### 4.2.1 关键词标准化函数

```python
def _normalize_keyword(keyword: str) -> str:
    """标准化关键词：trim + 转小写 + 压缩空白"""
    return " ".join(keyword.strip().lower().split())
```

#### 4.2.2 搜索记录函数（核心）

```python
async def record_search(
    db: AsyncSession,
    user_id: Optional[uuid.UUID],
    keyword: str
) -> None:
    """
    记录一次搜索行为（同步调用，不阻塞搜索结果返回）

    做两件事：
    1. upsert 用户历史表
    2. upsert 热词统计表
    """
    keyword_norm = _normalize_keyword(keyword)
    if not keyword_norm or len(keyword_norm) < 2:
        return

    # 1. upsert 用户历史（仅登录用户）
    if user_id:
        stmt = text("""
            INSERT INTO user_search_history (id, user_id, keyword, keyword_norm, search_count, last_searched_at)
            VALUES (:id, :user_id, :keyword, :keyword_norm, 1, now())
            ON CONFLICT (user_id, keyword_norm)
            DO UPDATE SET
                search_count = user_search_history.search_count + 1,
                last_searched_at = now(),
                updated_at = now()
        """)
        await db.execute(stmt, {
            'id': str(uuid.uuid4()),
            'user_id': str(user_id),
            'keyword': keyword.strip(),
            'keyword_norm': keyword_norm,
        })

        # 控制历史条数：删除超出的旧记录
        await _trim_user_history(db, user_id)

    # 2. upsert 热词统计
    stmt = text("""
        INSERT INTO search_keyword_stats (id, keyword_norm, keyword, total_count, last_searched_at)
        VALUES (:id, :keyword_norm, :keyword, 1, now())
        ON CONFLICT (keyword_norm)
        DO UPDATE SET
            total_count = search_keyword_stats.total_count + 1,
            last_searched_at = now(),
            updated_at = now()
    """)
    await db.execute(stmt, {
        'id': str(uuid.uuid4()),
        'keyword_norm': keyword_norm,
        'keyword': keyword.strip(),
    })

    await db.flush()
    logger.info(f"记录搜索: user={str(user_id)[:8] if user_id else 'anon'}, keyword={keyword_norm}")
```

**关键点**：
- 使用 `INSERT ... ON CONFLICT DO UPDATE`（upsert）模式
- 同时写入 `user_search_history` 和 `search_keyword_stats` 两张表
- `keyword` 字段保存原始关键词（保留大小写），`keyword_norm` 保存标准化后的关键词（用于去重）
- 每个用户最多保留 20 条历史，超出时删除最早的

#### 4.2.3 历史条数控制函数

```python
async def _trim_user_history(db: AsyncSession, user_id: uuid.UUID) -> None:
    """保留最近 MAX_HISTORY_PER_USER 条历史，删除多余的"""
    stmt = text("""
        DELETE FROM user_search_history
        WHERE id IN (
            SELECT id FROM user_search_history
            WHERE user_id = :user_id
            ORDER BY last_searched_at DESC
            OFFSET :offset
        )
    """)
    result = await db.execute(stmt, {
        'user_id': str(user_id),
        'offset': MAX_HISTORY_PER_USER,  # 20
    })
    if result.rowcount > 0:
        logger.info(f"清理用户历史: user={str(user_id)[:8]}, 删除{result.rowcount}条")
```

#### 4.2.7 热门搜索查询函数

```python
async def get_hot_keywords(
    db: AsyncSession,
    limit: int = 10,
    days: int = 7
) -> List[SearchKeywordStats]:
    """
    获取热门搜索词

    简单逻辑：最近 N 天内有搜索的词，按总搜索次数降序排列
    """
    cutoff = datetime.utcnow() - timedelta(days=days)

    stmt = (
        select(SearchKeywordStats)
        .where(SearchKeywordStats.last_searched_at >= cutoff)
        .where(SearchKeywordStats.total_count >= 2)
        .order_by(SearchKeywordStats.total_count.desc())
        .limit(limit)
    )
    result = await db.execute(stmt)
    return list(result.scalars().all())
```

**关键点**：
- 只返回最近 N 天内有搜索的词（默认 7 天）
- 至少被搜过 2 次才会出现在热门搜索中
- 按总搜索次数降序排列

#### 4.2.8 搜索建议查询函数

```python
async def get_suggestions(
    db: AsyncSession,
    keyword: str,
    limit: int = 10
) -> List[str]:
    """
    获取搜索建议（前缀匹配）

    优先级：热词表中以 keyword 开头的词，按搜索次数降序
    """
    keyword_norm = _normalize_keyword(keyword)
    if not keyword_norm:
        return []

    pattern = f"{keyword_norm}%"

    stmt = (
        select(SearchKeywordStats.keyword_norm)
        .where(SearchKeywordStats.keyword_norm.like(pattern))
        .where(SearchKeywordStats.keyword_norm != keyword_norm)
        .order_by(SearchKeywordStats.total_count.desc())
        .limit(limit)
    )
    result = await db.execute(stmt)
    return [row[0] for row in result.all()]
```

**关键点**：
- 使用前缀匹配（`LIKE 'keyword%'`）
- 排除完全相同的关键词
- 按搜索次数降序排列

#### 4.2.9 搜索推荐查询函数（新增）

```python
async def get_recommendations(
    db: AsyncSession,
    keyword: Optional[str] = None,
    user_id: Optional[uuid.UUID] = None,
    limit: int = 8
) -> List[dict]:
    """
    获取搜索推荐
    - 有关键词: ILIKE包含匹配 + 个性化boost（用户历史+50分）
    - 无关键词: 返回全局热词
    """
    if keyword and keyword.strip():
        keyword_norm = _normalize_keyword(keyword)
        # 获取候选词（多取一些用于排序）
        stmt = (
            select(SearchKeywordStats)
            .where(SearchKeywordStats.keyword_norm.ilike(f"%{keyword_norm}%"))
            .order_by(SearchKeywordStats.total_count.desc())
            .limit(limit * 5)
        )
        result = await db.execute(stmt)
        candidates = list(result.scalars().all())

        # 个性化boost：查询用户历史
        user_history = set()
        if user_id:
            hist_stmt = (
                select(UserSearchHistory.keyword_norm)
                .where(UserSearchHistory.user_id == user_id)
                .order_by(UserSearchHistory.last_searched_at.desc())
                .limit(50)
            )
            hist_result = await db.execute(hist_stmt)
            user_history = {row[0] for row in hist_result.all()}

        # 计算得分并排序
        scored = []
        for item in candidates:
            base_score = float(item.total_count or 0)
            if item.keyword_norm in user_history:
                base_score += 50  # 历史匹配加分
            scored.append({
                'keyword': item.keyword or item.keyword_norm,
                'score': base_score
            })
        scored.sort(key=lambda x: x['score'], reverse=True)
        return scored[:limit]
    else:
        # 无关键词，返回全局热词
        stmt = (
            select(SearchKeywordStats)
            .order_by(SearchKeywordStats.total_count.desc())
            .limit(limit)
        )
        result = await db.execute(stmt)
        items = list(result.scalars().all())
        return [
            {'keyword': item.keyword or item.keyword_norm, 'score': float(item.total_count or 0)}
            for item in items
        ]
```

**关键点**：
- 有关键词时：使用 ILIKE 包含匹配（非仅前缀匹配），支持个性化 boost（用户历史 +50 分）
- 无关键词时：返回全局热词
- 返回结果包含 `keyword`（原始关键词）和 `score`（得分）

### 4.6 搜索接口联动（写历史）

**文件**：`backend/live_core_service/app/api/v1/endpoints/homepage_search.py`

在现有的搜索接口 `search_resources_endpoint` 中，搜索成功后调用 `record_search`：

```python
@search_router.get("", response_model=None, tags=["Search API"])
async def search_resources_endpoint(
    q: str = Query(..., min_length=2, description="搜索关键词"),
    page: int = Query(1, ge=1, description="页码"),
    size: int = Query(10, ge=1, le=50, description="每页数量"),
    type: Optional[str] = Query(None, description="资源类型筛选（逗号分隔）"),
    category_id: Optional[UUID] = Query(None, description="分类ID筛选（仅对room有效）"),
    current_user: Optional[dict] = Depends(get_current_user_optional),  # 可选认证
    db: AsyncSession = Depends(get_db)
):
    """
    全局搜索接口

    - 可选认证（登录用户自动记录搜索历史）
    - 支持跨直播间、专家、专题、品牌的模糊搜索
    - 支持分页
    - 支持资源类型筛选
    - 返回匹配分数和高亮文本
    """
    try:
        # 解析type参数（逗号分隔）
        resource_types = None
        if type:
            resource_types = [t.strip() for t in type.split(',')]

        service = HomepageSearchService()
        result = await service.search_resources(
            db, q, page, size, resource_types, category_id
        )

        # 搜索成功后记录搜索行为（不影响搜索结果返回）
        try:
            user_id = None
            if current_user:
                user_id = UUID(current_user.get("user_id") or current_user.get("sub"))
            await record_search(db, user_id, q)
        except Exception as e:
            logger.warning(f"记录搜索行为失败（不影响搜索结果）: {e}")

        return JSONResponse(
            status_code=200,
            content=result
        )

    except InvalidParameterException as e:
        logger.warning(f"搜索参数错误: {str(e)}")
        return JSONResponse(
            status_code=400,
            content=error_response(code=4001, message=str(e))
        )

    except Exception as e:
        logger.error(f"搜索失败: {str(e)}")
        return JSONResponse(
            status_code=500,
            content=error_response(code=5001, message="服务器内部错误")
        )
```

**关键点**：
- 搜索接口改为可选认证（`get_current_user_optional`）
- 搜索成功后调用 `record_search()` 记录搜索行为
- 记录失败不影响搜索结果返回

## 九、常见问题

### Q1: 404 Not Found

**原因：** Docker 镜像未重新构建，容器中运行的仍是旧代码。

**解决：**
```bash
docker compose -f docker-compose.prod.yml build live_core_service
docker compose -f docker-compose.prod.yml up -d live_core_service
```

### Q2: 数据库连接失败

**原因：** PostgreSQL 容器未启动或网络问题。

**解决：**
```bash
docker compose -f docker-compose.prod.yml up -d postgres
```

### Q3: keyword 字段为 NULL

**原因：** 旧的搜索记录没有 keyword 字段值。

**解决：** 新的搜索会自动写入 keyword 字段，旧记录可忽略或手动回填：
```sql
UPDATE search_keyword_stats SET keyword = keyword_norm WHERE keyword IS NULL;
```

### Q4: 搜索历史不显示

**原因：** 未登录用户不会记录搜索历史。

**解决：** 确保用户已登录，并且搜索接口使用了可选认证（`get_current_user_optional`）。

### Q5: 热门搜索为空

**原因：** 没有足够的搜索数据，或者所有搜索都是最近 7 天之前的。

**解决：** 
- 进行一些搜索操作积累数据
- 或者调整 `days` 参数扩大时间窗口：`GET /api/v1/search/hot-keywords?days=30`

### Q6: 搜索建议不准确

**原因：** 搜索建议使用前缀匹配，如果关键词不以用户输入开头则不会出现。

**解决：** 这是设计行为。如需包含匹配，可使用搜索推荐接口：`GET /api/v1/search/recommendations?keyword=xxx`

## 十一、设计原则

| 原则 | 说明 |
|------|------|
| 最少表 | 只用 2 张表，不建日志表 |
| 最少依赖 | 不引入 Redis 缓存，直接查 PostgreSQL |
| 最少接口 | 搜索写历史在搜索接口内部完成，前端不感知 |
| 最少算法 | 热词 = 按搜索次数排序，建议 = 前缀匹配 |
| 复用已有 | 完全复用 live_core_service 的分层架构和响应格式 |

## 十二、后期优化路径（当前不做）

当 MVP 跑通、有真实用户数据后，按需添加：

| 优化项 | 时机 | 改动量 |
|--------|------|--------|
| Redis 缓存热词 | 热词接口 p99 > 200ms | 加一个缓存层，改 CRUD |
| 异步记录搜索 | 搜索接口延迟明显 | 改为 Celery task，改 endpoint |
| 个性化推荐 | 有足够用户行为数据 | 加推荐算法 service |
| 独立日志表 | 需要做运营分析 | 加 search_query_logs 表 |
| 搜索类型筛选 | 有多种搜索入口 | 加 search_type 字段 |

每一步都是独立的、向后兼容的增量改动，不需要推翻现有设计。
