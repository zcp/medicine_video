**模块范围**:
- 2张数据表（`tags`、`session_tags`）
- 9个API接口（Tags 4个、Session_Tags 3个、搜索 2个）

```json
{
```

```json
  "role": "admin",
  "exp": 1717756800
}
```

> **重要说明**: JWT Payload中用户标识字段为 `user_id`（非 `sub`）。

### 业务状态码

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| `200` | 成功 | 所有成功响应 |
| `1002` | 数据库错误 | 数据库操作异常 |
| `2001` | 资源不存在 | 标签ID不存在、场次不存在 |
| `2002` | 资源已存在 | 标签名称或slug重复 |

| `3001` | 未授权 | JWT Token缺失或无效 |
| `3002` | 权限不足 | 非管理员访问管理端接口 |
| `4001` | 参数校验失败 | 请求参数不符合规范 |

## 🎯 设计要点与约定

### 1.1 数据库设计规范

1. **UUID主键**: 所有表使用 `UUID` 类型作为主键
2. **时间戳**: 所有时间字段使用 `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
3. **外键约束**: 所有外键使用 `CONSTRAINT fk_<table>_<column>` 命名规范
4. **软删除**: `tags` 表使用 `is_active` 字段实现软删除
5. **索引策略**: 高频查询字段建立索引，命名规范 `idx_<table>_<column>`
6. **字段注释**: 所有表和关键字段使用 `COMMENT ON` 添加中文注释

### 1.2 API设计规范

1. **HTTP方法**: GET（查询）、POST（创建）、PATCH（部分更新）、DELETE（删除）
2. **URL路径**: 公开读 `/api/v1/content/tags`；管理写 `/api/v1/admin/tags`
3. **认证策略**: 公开读取 + 管理员写入
4. **搜索功能**: 支持按标签搜索场次，支持AND/OR匹配模式

### 1.3 软删除策略

| 表名 | 策略 | 说明 |
|------|------|------|
| `tags` | `is_active` 字段 | 删除时设置 `is_active = false`，查询时默认过滤 |
| `session_tags` | 物理删除 | 关联关系解除时直接删除记录 |

### 1.4 安全与配置规范

**架构分层原则**:
- **API 层**: 仅负责认证（`Depends(get_current_user)` 或 `Depends(get_current_user_optional)`）
- **Service 层**: 负责授权（权限守卫函数）
- **CRUD 层**: 负责SQL级别的权限过滤

**双轨鉴权模式**:
- **严格鉴权（Strict Auth）**: 所有CUD操作，需要有效的JWT Token
- **可选鉴权（Optional Auth）**: 公开读取操作，允许匿名访问

**权限守卫函数**:

```python
def _check_admin_permission(user_role: str) -> None:
    """检查管理员权限，非管理员抛出403异常"""
    if user_role != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail={"code": 3002, "message": "权限不足：需要管理员权限"}
        )
```

**CRUD层权限过滤**:

```python
# 公开查询：默认只返回 is_active = true 的标签
async def get_tags(db: AsyncSession, include_inactive: bool = False):
    query = select(Tag)
    if not include_inactive:
        query = query.where(Tag.is_active == True)
    return await db.execute(query)
```

## 1. 数据库Schema设计（DDL）

### 1.0 前置准备：触发器函数

```sql
-- 自动更新 updated_at 触发器函数（如已创建则跳过）
CREATE OR REPLACE FUNCTION trigger_set_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### 1.1 tags（标签表）

```sql
-- ==========================================================
-- 表：tags（标签表）
-- 说明：存储全局内容标签信息，支持软删除
-- ==========================================================

CREATE TABLE tags (
    id UUID PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) NOT NULL UNIQUE,
    description TEXT,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 唯一索引：slug（用于URL友好标识）
CREATE UNIQUE INDEX idx_tags_slug ON tags(slug);

-- 普通索引：is_active（用于过滤活跃标签）
CREATE INDEX idx_tags_is_active ON tags(is_active);

-- 普通索引：name（用于搜索）
CREATE INDEX idx_tags_name ON tags(name);

-- 触发器：自动更新 updated_at
CREATE TRIGGER set_timestamp_tags
    BEFORE UPDATE ON tags
    FOR EACH ROW
    EXECUTE FUNCTION trigger_set_timestamp();

-- 表注释
COMMENT ON TABLE tags IS '标签表 - 存储全局内容标签信息';
COMMENT ON COLUMN tags.id IS '标签UUID主键';
COMMENT ON COLUMN tags.name IS '标签名称（如：微创手术）';
COMMENT ON COLUMN tags.slug IS 'URL友好标识（唯一）';
COMMENT ON COLUMN tags.description IS '标签描述';
COMMENT ON COLUMN tags.is_active IS '是否启用（软删除标记）';
COMMENT ON COLUMN tags.created_at IS '创建时间（UTC）';
COMMENT ON COLUMN tags.updated_at IS '最后更新时间（UTC）';
```

### 1.2 session_tags（场次-标签关联表）

```sql
-- ==========================================================
-- 表：session_tags（场次-标签关联表）
-- 说明：直播场次与标签的多对多关联关系
-- ==========================================================

CREATE TABLE session_tags (
    session_id UUID NOT NULL,
    tag_id UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (session_id, tag_id),
    CONSTRAINT fk_st_session FOREIGN KEY (session_id)
        REFERENCES live_sessions(id) ON DELETE CASCADE,
    CONSTRAINT fk_st_tag FOREIGN KEY (tag_id)
        REFERENCES tags(id) ON DELETE CASCADE
);

-- 索引：按标签查询关联的场次
CREATE INDEX idx_st_tag_id ON session_tags(tag_id);

-- 索引：按场次查询关联的标签
CREATE INDEX idx_st_session_id ON session_tags(session_id);

-- 表注释
COMMENT ON TABLE session_tags IS '场次-标签关联表 - 多对多关系';
COMMENT ON COLUMN session_tags.session_id IS '直播场次UUID（外键，级联删除）';
COMMENT ON COLUMN session_tags.tag_id IS '标签UUID（外键，级联删除）';
COMMENT ON COLUMN session_tags.created_at IS '关联创建时间';
```

## 2. Pydantic Schemas定义

### 2.1 Tag Schemas

```python
from pydantic import BaseModel, Field, ConfigDict, field_validator
from typing import Optional, List
from uuid import UUID
from datetime import datetime
import re


class TagBase(BaseModel):
    """标签基础Schema"""
    name: str = Field(..., min_length=1, max_length=100, description="标签名称")
    slug: str = Field(..., min_length=1, max_length=100, description="URL友好标识")
    description: Optional[str] = Field(None, description="标签描述")
    is_active: bool = Field(True, description="是否启用")

    @field_validator("slug")
    @classmethod
    def validate_slug(cls, v: str) -> str:
        """校验slug格式：仅允许小写字母、数字、连字符"""
        if not re.match(r"^[a-z0-9\-]+$", v):
            raise ValueError("slug 仅允许小写字母、数字和连字符")
        return v


class TagCreate(TagBase):
    """创建标签请求Schema"""
    pass


class TagUpdate(BaseModel):
    """更新标签请求Schema（全量更新）"""
    name: Optional[str] = Field(None, min_length=1, max_length=100)
    slug: Optional[str] = Field(None, min_length=1, max_length=100)
    description: Optional[str] = None
    is_active: Optional[bool] = None

    model_config = ConfigDict(from_attributes=True)


class TagItem(TagBase):
    """标签响应Schema"""
    id: UUID
    created_at: datetime
    updated_at: datetime

    model_config = ConfigDict(from_attributes=True)


class TagListResponse(BaseModel):
    """标签列表响应Schema（统一分页格式）"""
    code: int = 200
    message: str = "success"
    data: dict  # {total, page, size, items: List[TagItem]}
    timestamp: datetime
```

### 2.2 SessionTags Schemas

```python
class SessionTagsSetRequest(BaseModel):
    """设置场次标签关联请求Schema"""
    tag_ids: List[UUID] = Field(..., description="标签UUID列表")
    mode: Literal["replace", "append"] = Field(..., description="操作模式：replace=替换，append=追加")

    @field_validator('tag_ids')
    @classmethod
    def validate_tag_ids_unique(cls, v: List[UUID]) -> List[UUID]:
        """验证标签ID列表唯一性"""
        if len(v) != len(set(v)):
            raise ValueError('标签ID列表中存在重复项')
        return v


class TagBriefItem(BaseModel):
    """标签简要信息Schema（用于关联响应）"""
    model_config = ConfigDict(from_attributes=True)

    name: str


class SessionTagsSetResponse(BaseModel):
    """场次标签设置响应Schema"""
    code: int = 200
    message: str = "success"
```

## 3. API接口设计（完整CRUD）

### 3.1 Tags 模块API

#### 3.1.1 获取标签列表（公开）

**Endpoint**: `GET /api/v1/content/tags`

**描述**: 获取所有启用的标签列表，支持搜索

**认证**: 公开访问（Public）

**请求参数 (Query)**:
- `q` (str, 可选): 搜索关键词（匹配name、slug、description）
- `search_type` (str, 可选, 默认"name"): 搜索类型（name/slug/description）
- `include_inactive` (bool, 可选, 默认false): 是否包含已禁用的标签

**成功响应** (`200 OK`):
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {
        "id": "uuid-string",
        "name": "微创手术",
        "slug": "minimally-invasive",
        "description": "微创手术相关直播内容",
        "is_active": true,
        "created_at": "2026-01-01T00:00:00Z",
        "updated_at": "2026-01-01T00:00:00Z"
      }
    ]
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收GET请求，解析Query参数
2. **构建查询**: 使用SQLAlchemy构建SELECT查询
3. **过滤条件**: 默认 `WHERE is_active = true`
4. **搜索过滤**: 若 `q` 参数存在，根据 `search_type` 添加对应的LIKE条件
5. **排序**: 按 `created_at DESC` 排序
6. **执行查询**: 异步执行数据库查询
7. **序列化响应**: 使用 `TagItem` Schema序列化结果
8. **返回响应**: 返回统一格式的JSON响应

**HTTP状态码**:
- `200 OK`: 查询成功
- `500 Internal Server Error`: 数据库异常

#### 3.1.3 创建标签（ADMIN）

**Endpoint**: `POST /api/v1/admin/tags`

**描述**: 创建新的内容标签

**认证**: JWT认证 + 管理员权限

**请求体**:
```json
{
  "name": "病例讨论",
  "slug": "case-discussion",
  "description": "病例讨论相关直播内容",
  "is_active": true
}
```

**成功响应** (`201 Created`):
```json
{
  "code": 200,
  "message": "标签创建成功",
  "data": {
    "id": "new-uuid-string",
    "name": "病例讨论",
    "slug": "case-discussion",
    "description": "病例讨论相关直播内容",
    "is_active": true,
    "created_at": "2026-06-07T10:00:00Z",
    "updated_at": "2026-06-07T10:00:00Z"
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**失败响应** (`409 Conflict`):
```json
{
  "code": 2002,
  "message": "标签slug已存在: case-discussion",
  "data": null,
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收POST请求，解析请求体
2. **JWT验证**: 通过 `Depends(get_current_user)` 提取当前用户
3. **权限检查**: 调用 `_check_admin_permission(user.role)` 校验管理员权限
4. **Pydantic校验**: 使用 `TagCreate` Schema校验请求体
5. **唯一性检查**: 查询 `slug` 是否已存在，若存在抛出 `409` 异常（code=2002）
6. **生成UUID**: 生成新的UUID作为主键
7. **插入数据库**: `INSERT INTO tags (...) VALUES (...)`
8. **提交事务**: `await db.commit()`
9. **返回响应**: 返回创建的标签信息

**HTTP状态码**:
- `201 Created`: 创建成功
- `401 Unauthorized`: JWT Token无效（code=3001）
- `403 Forbidden`: 非管理员（code=3002）
- `409 Conflict`: slug已存在（code=2002）
- `422 Unprocessable Entity`: 参数校验失败（code=4001）
- `500 Internal Server Error`: 数据库异常

### 3.3 搜索模块API

#### 3.3.1 按标签搜索场次（公开）

**Endpoint**: `GET /api/v1/content/tags/search/sessions`

**描述**: 根据标签搜索关联的直播场次，支持AND/OR匹配模式

**认证**: 公开访问（Public）

**请求参数 (Query)**:
- `tag_ids` (str, required): 标签UUID列表（逗号分隔，如：`uuid-1,uuid-2`）
- `match_all` (bool, 可选, 默认false): true=AND模式，false=OR模式
- `page` (int, 可选, 默认1): 页码
- `page_size` (int, 可选, 默认20): 每页数量

**成功响应** (`200 OK`):
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 15,
    "page": 1,
    "size": 20,
    "items": [
      {
        "session_id": "uuid-string",
        "title": "腹腔镜胆囊切除术直播",
        "matched_tags": ["微创手术", "肝胆外科"],
        "score": 1.0
      }
    ]
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收GET请求，解析Query参数
2. **参数解析**: 将 `tag_ids` 字符串解析为UUID列表
3. **构建查询**:
   - OR模式: `WHERE tag_id IN (:tag_ids)` → 获取所有匹配的session_id
   - AND模式: `WHERE tag_id IN (:tag_ids) GROUP BY session_id HAVING COUNT(DISTINCT tag_id) = :tag_count`
4. **分页**: 计算 `offset` 和 `LIMIT`
5. **执行查询**: 异步执行数据库查询
6. **关联查询**: 获取匹配场次的详细信息和匹配的标签列表
7. **计算分数**: `score = 匹配标签数 / 总搜索标签数`
8. **序列化响应**: 使用 `SearchResultItem` Schema序列化
9. **返回响应**: 返回统一分页格式的JSON响应

**HTTP状态码**:
- `200 OK`: 搜索成功
- `422 Unprocessable Entity`: tag_ids格式错误（code=4001）
- `500 Internal Server Error`: 数据库异常

## 5. 错误处理与事务管理

### 5.1 错误处理策略

**业务异常**:
- 资源不存在（code=2001）→ HTTP 404
- 资源冲突（code=2002）→ HTTP 409
- 业务逻辑错误（code=2004）→ HTTP 409

**系统异常**:
- 数据库连接失败 → HTTP 503
- 查询超时 → HTTP 504

**参数校验异常**:
- Pydantic校验失败 → HTTP 422（code=4001）

### 5.2 事务管理规范

**单表操作**: 使用单个事务，操作失败自动回滚

**多表操作**（如设置场次标签关联）:
```python
async with db.begin():
    # 1. 删除旧关联
    await db.execute(delete(SessionTag).where(...))
    # 2. 批量插入新关联
    db.add_all(new_associations)
# 自动提交或回滚
```

**并发控制**: 使用数据库唯一约束（如 `slug UNIQUE`）防止并发创建冲突

## 6. 性能优化建议

### 6.1 数据库优化

- **索引优化**: `slug` 唯一索引加速slug查找；`tag_id` 索引加速关联查询
- **查询优化**: 搜索查询使用 `IN` 子句而非多次单条查询
- **连接池**: 使用SQLAlchemy的 `async_session` 连接池管理

### 6.2 缓存策略

- **Redis缓存**: 公开标签列表可缓存5分钟（TTL=300s）
- **缓存键**: `tags:list:active`（公开列表）、`tags:detail:{id}`（单个详情）
- **缓存失效**: 创建/更新/删除标签时清除相关缓存

### 6.3 应用层优化

- **批量操作**: 设置场次标签关联时使用 `executemany` 批量插入
- **搜索优化**: AND模式搜索使用 `GROUP BY + HAVING COUNT` 替代多次查询交集
