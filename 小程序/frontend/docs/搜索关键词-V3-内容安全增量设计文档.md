## 📌 本次增量范围

### 1. 变更目标

对用户输入搜索词统一执行内容安全校验（scene=`search_query`，目标字段 `keyword`），覆盖：
- `GET /api/v1/search?q=...`（综合搜索）
- `GET /api/v1/search/suggestions?keyword=...`（搜索建议）

### 2. 变更类型

- 【修改】搜索与建议接口入参处理流程
- 【新增】`scene=search_query` 规则组接入（live_core 库，默认 4 条 block + 1 条 warn 示例）
- 【新增】高风险关键词拦截与审计留痕
- 【修改】`record_search` 调用时机：仅 allow/warn 才记录历史与热词

### 3. 排除范围

- 不修改热词统计表、历史表结构
- 不新增公告相关能力
- 不引入 Redis 或异步队列
- `GET /api/v1/search/hot-keywords` 为只读热词列表，**不纳入**本次校验（无用户自由输入）

## 🔍 规则与决策

### 1. 双库分治（live_core 侧）

| 维度 | 说明 |
|------|------|
| 数据库 | `live_core_test` |
| 校验场景 | `search_query` |
| 默认规则 | keyword 四类 block（url / contact / fraud / keyword）+ **1 条 search warn 示例**（见 12 §1.4.4） |
| 规则维护 | live_core 管理端 API（GET/POST/PATCH `/api/v1/admin/content-safety/rules`） |
| 审计日志 | 存 live_core 库；管理端 `GET /api/v1/admin/content-safety/logs` 可查询 |

### 2. 检测口径（与 12 §1.4.2 一致）

| 检测类型 | `match_type` | 默认 action |
|----------|--------------|-------------|
| 外链 | `url` | block |
| 联系方式 | `contact` | block |
| 广告引流 | `fraud` | block |
| 敏感词 | `keyword` | block |

> 运营可通过管理端将特定词设为 `warn`（示例规则已 seed）；正常医学检索语义应减少误杀。

### 3. 决策策略（与 12 §1.4.5、§4.2.5 一致）

| 决策 | 行为 | HTTP | code | 历史/热词 |
|------|------|------|------|-----------|
| `block` | 拒绝查询，不执行搜索 | 422 | 2005 | ❌ 不写入 |
| `warn` | 允许查询，写审计日志（`reason_code=2006`） | 200 | 200 | ✅ 记录 |
| `allow` | 正常查询，**不写审计日志** | 200 | 200 | ✅ 记录 |

### 4. 异常策略

- 搜索接口在安全服务异常时默认拒绝：`422 + code=2004`（与 12 §1.4.1 发布/查询型默认拒绝一致）

### 5. API 路径约定（与 12 §1.7 一致）

| 对外网关路径（nginx） | 服务内路径 | 所属服务 |
|----------------------|------------|----------|
| `GET /api/core/search` | `/api/v1/search` | live_core |
| `GET /api/core/search/suggestions` | `/api/v1/search/suggestions` | live_core |

## 1. 核心流程增量

### 1.1 综合搜索（修改后流程，与 12 §4.2.5 一致）

```
GET /api/v1/search?q=...
  → 1. 参数基础校验（q 非空、长度等）
  → 2. check_content_safety(scene="search_query", field="keyword")
  → 3. block → 422/2005，不执行搜索、不写历史、不更新热词
  → 4. 安全服务异常 → 422/2004
  → 5. allow/warn → 执行原有搜索逻辑
  → 6. 仅 warn/block 时写入 content_safety_logs（纯 allow 不写日志）
  → 7. allow/warn → 调用 record_search（历史/热词）
  → 8. 提交事务（如有），返回统一响应
```

### 1.2 搜索建议（修改后流程）

```
GET /api/v1/search/suggestions?keyword=...
  → 1. 参数校验
  → 2. check_content_safety(scene="search_query", field="keyword")
  → 3. block → 422/2005，不返回建议、不写历史/热词
  → 4. 安全服务异常 → 422/2004
  → 5. allow/warn → 返回建议词列表
  → 6. 仅 warn/block 时写入 content_safety_logs（纯 allow 不写日志）
```

### 1.3 违规返回示例（block）

```json
{
  "code": 2005,
  "message": "内容违规：搜索词命中外链拦截规则",
  "data": null,
  "timestamp": "2026-07-03T10:00:00Z"
}
```

### 1.4 warn 返回示例

```json
{
  "code": 200,
  "message": "success",
  "data": { "...搜索结果..." },
  "timestamp": "2026-07-03T10:00:00Z"
}
```

> warn 决策写入审计日志，`reason_code=2006`；HTTP 仍返回 200；搜索历史与热词正常记录。
