## 🔐 核心安全内容矩阵

### 1️⃣ 密钥生成与存储（9.3.1）

**后端要求：**
```
密钥生成 ➜ 加密随机数
格式：stream_{room_id_prefix}_{32字符}
数据库存储 ➜ SHA-256哈希（不可逆）
```

**核心点：**
- ✅ 使用 `secrets.token_urlsafe(32)` 生成
- ✅ 数据库仅存储哈希值
- ✅ 原始密钥仅在创建时返回一次

**代码示例：**
```python
import hashlib
stored_key = hashlib.sha256(stream_key.encode()).hexdigest()
```

---

### 2️⃣ 传输安全（9.3.2）

**强制要求：**
| 要求 | 规范 | 备注 |
|------|------|------|
| 协议 | HTTPS TLS 1.2+ | 无异常 |
| 密码套件 | TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384 | 必须强加密 |
| 响应头 | `Strict-Transport-Security` | HSTS强制HTTPS |
| 缓存策略 | `Cache-Control: no-store, no-cache` | 禁用缓存 |
| 内容安全 | `X-Content-Type-Options: nosniff` | 防MIME嗅探 |
| 点击劫持 | `X-Frame-Options: DENY` | 防点击劫持 |

**完整响应头示例：**
```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
Cache-Control: no-store, no-cache, must-revalidate, private
Pragma: no-cache
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
```

### 3️⃣ 访问控制（9.3.3）

**权限模型：**
```
┌─────────────────────────────────┐
│ GET /api/v1/users/me/rooms      │
│ Authorization: Bearer <JWT>      │
└──────────────┬──────────────────┘
               │
        ┌──────▼──────┐
        │ 验证JWT     │
        │ 提取user_id │
        └──────┬──────┘
               │
        ┌──────▼──────────────┐
        │ Query by user_id    │
        │ 仅返回自己的房间    │
        └──────┬──────────────┘
               │
        ┌──────▼──────────────────┐
        │ 再次验证room.user_id    │
        │ == JWT中的user_id       │
        └──────┬──────────────────┘
               │
        ┌──────▼──────────────┐
        │ 返回stream_key      │
        │ （仅所有者可见）    │
        └─────────────────────┘
```

**关键要点：**
- ✅ Service层（不只是路由层）再次验证权限
- ✅ 管理员通过此接口也无法跨用户查询
- ✅ 返回403而非404（避免信息泄露）

### 4️⃣ 密钥轮换机制（9.3.4）

**新增API：**
```
POST /api/v1/rooms/{id}/rotate-stream-key
```

**请求：**
```json
{
  "keep_old_key": true  // 可选，是否保留旧密钥
}
```

**响应：**
```json
{
  "primary_stream_key": "stream_8a01f0e2_NEW_KEY_32",
  "old_stream_key": "stream_8a01f0e2_OLD_KEY_32",
  "expires_at": "2026-05-14T10:30:00Z"
}
```

**时间线：**
```
T+0分钟    ➜ 轮换请求
           ➜ 生成新密钥，旧密钥标记为待失效
T+1-30分钟 ➜ 旧密钥仍可用于推流（过渡期）
T+30分钟   ➜ 旧密钥自动失效（使用返回403）
```

**频率限制：**
- 10分钟内最多轮换1次
- 超过返回 429 错误

### 6️⃣ 泄露应急处理（9.3.6）

**检测机制：**
| 异常类型 | 触发条件 | 行动 |
|---------|--------|------|
| 异常IP | 推流来源IP与历史不符 | 告警 + 自动禁用（可选） |
| 并发推流 | 单密钥并发连接>1 | 告警 + 记录审计日志 |
| 频繁轮换 | 短时间内频繁轮换 | 告警 + 临时锁定 |

**应急流程：**
1. 检测异常 → 自动禁用密钥
2. 发送告警邮件/短信给用户
3. 用户确认后轮换密钥
4. 审计日志记录整个过程

**审计日志记录：**
```json
{
  "timestamp": "2026-05-13T10:30:00Z",
  "event_type": "stream_key_rotation",
  "user_id": "uuid",
  "action": "rotate",
  "reason": "suspicious_activity",  // user_requested | suspicious_activity | scheduled
  "old_key_hash": "sha256_hash",
  "new_key_hash": "sha256_hash",
  "client_ip": "1.2.3.4",
  "status": "success"
}
```

### 7️⃣ 前端安全实践（15.3）

#### UI展示规范

**❌ 不要这样做：**
```
stream_8a01f0e2_abc123def456ghi789jkl012mno345  ← 完整密钥暴露
```

**✅ 应该这样做：**
```
stream_8a***mno345  [复制]  [重置]  ← 脱敏显示
```

#### 存储策略

**❌ 危险做法：**
```javascript
localStorage.setItem('stream_key', streamKey)  // 永久存储！
```

**✅ 推荐做法（三选一）：**

**方案1：页面会话期间存储（最安全）**
```javascript
sessionStorage.setItem('stream_key', streamKey)
// 页面关闭时自动清除
```

**方案2：内存变量 + 过期清理**
```javascript
let cachedKey = streamKey
setTimeout(() => { cachedKey = null }, 15*60*1000)  // 15分钟清空
```

**方案3：React Ref（组件卸载时清空）**
```javascript
const key = useRef(streamKey)
useEffect(() => {
  return () => { key.current = null }  // 卸载时清空
}, [])
```

#### 复制流程

```javascript
async function copyStreamKey(roomId) {
  // 1. 从内存中获取完整密钥
  const fullKey = streamKeyCache.get(roomId)
  
  // 2. 复制到剪贴板
  await navigator.clipboard.writeText(fullKey)
  
  // 3. 3秒后清空内存
  setTimeout(() => streamKeyCache.delete(roomId), 3000)
  
  // 4. 显示提示
  showToast('密钥已复制，请在3分钟内粘贴到OBS')
}
```

## ✅ 安全验收标准（16.2.1）

新增18项验收检查点，分为5个维度：

### 传输安全（3项）
- [ ] 响应包含 `Strict-Transport-Security` 头
- [ ] 响应包含 `Cache-Control: no-store` 头
- [ ] 使用 TLS 1.2+ 强密码套件

### 访问控制（4项）
- [ ] 用户A无法获取用户B的密钥
- [ ] 管理员通过此接口无法跨用户查询
- [ ] 权限检查在Service层实现
- [ ] 错误返回403而非404

### 数据库安全（3项）
- [ ] 数据库中密钥为SHA-256哈希
- [ ] 无法从备份反推原始密钥
- [ ] 所有查询操作记录审计日志

### 密钥生成与轮换（5项）
- [ ] 新密钥格式一致（`stream_{}_{32}`）
- [ ] 旧密钥30分钟内可用，后自动失效
- [ ] 轮换频率限制（10分钟最多1次）
- [ ] 错误处理不暴露密钥信息

### 监控告警（3项）
- [ ] 异常使用模式被检测
- [ ] 审计日志包含完整上下文
- [ ] 告警规则覆盖主要风险
