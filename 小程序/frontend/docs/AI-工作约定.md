## 3. 接到任务怎么分流

按**用户本轮说了什么**选行；未命中的行不要预读、不要开工。

| 任务类型 | 先读（仅该类需要时） | 可改范围 | 默认角色 |
|----------|----------------------|----------|----------|
| 只问「在哪 / 谁调用」 | 相关 `src/**`；必要时现状全景 | 只读 | `explorer` |
| 改页面 / 组件 / API / Store | 对应代码 + **命中的设计/后端契约文档** + **命中的** `docs/前端规范样本/*` | `src/**` | `frontend` |
| 新建/重命名文档 | `通用规范-文件创建规范-v1.0.md` + 可匹配的模板 | `docs/**` 等用户指定范围 | `docs` |
| 写/改设计或清单 | 本文相关节 + 相关设计文档 | `docs/**` | `docs` |
| 生命周期类展示/规则 | 决策层对应规则编号 | 以用户请求为准 | `frontend` 或 `docs` |
| 只要建议 | 按需只读 | 不改仓库 | 只读 |

未明确要求时：**只分析建议，不改代码、不改决策结论、不 git commit。**

## 4. 执行方式：行动清单 + 自测收尾

非单句问答的任务一律（含：改代码、改文档、排查/修 bug、多步分析、设计梳理）：

1. **先分流并打开对应 Agent 文件**（§3 + `.cursor/agents/` 中匹配的一份；只「心里归类」不算）  
2. **先选最小化、最友好修改方案**（能少改就少改；优先用户可感知、可回退、复用已有口径）  
3. **先把行动清单写进对用户可见的回复**（编号步骤 + 完成定义 + 采用的方案一句话）；**默念清单、只建内部 Todo、读了 Skill 却不写出清单 = 未执行**  
4. **按清单逐步做**；一步一事；清单不对先改清单再做  
5. **自测收尾**：用检查表核对「是否覆盖请求 / 是否越界 / 是否最小友好 / 是否读了匹配 Agent / 任务相关项」；有 ❌ 先处理或标明残留  

**可不启用清单的唯一例外**：纯单点事实问答，且一眼能从已知上下文答出（例：「这个函数在哪个文件」）。报 bug、说「修一下」、多文件排查 → **必须**清单，不得按例外偷懒。

细节与表格式见 Cursor Skill `action-checklist`（非 Cursor 时按同结构在回复里执行即可）。

## 4.1 改代码须有文档依据（契约对齐 · 强制）

改 `src/**`（尤其 `api` / `types` / 表单提交 / 列表解析 / Store）时：**禁止凭感觉发明字段或接口形状**。须先有可指认的文档依据，并**严格对齐**。

### 依据优先级（高 → 低）

1. 本模块**后端设计 / 增量设计**中的 Endpoint、Query/Body、Schema、错误码  
2. 本模块**前端设计文档**中的字段表、必填、交互约束  
3. 跨模块决策 / 页面编排（仅当任务命中其范围）  
4. [`docs/前端规范样本/`](docs/前端规范样本/)（工程写法；不替代业务契约字段）

多份文档冲突：在行动清单写明「以哪份哪节为准」；与**已上线代码**冲突时仍可按 §2「以代码为准并标明偏差」，但**不得在未标明的情况下改契约含义**。

### 必须对齐的「字段与格式」（举例，实施时按命中文档逐项核对）

| 项 | 要求 |
|----|------|
| 字段名 | 与文档一致（含 `snake_case` / 嵌套路径）；禁止擅自改名、驼峰混用当另一字段 |
| 字段集合 | 请求/响应**不多写、不少写**文档未列的业务字段；扩展字段须有文档或显式「偏差说明」 |
| 必填 / 可选 | 与文档 `required` / `Optional` / 表格「必填」列一致；前端校验与提交不得弱于契约 |
| 类型与枚举 | string/number/bool/array/object、枚举字面量与文档一致 |
| 数量与长度 | `maxlength`、数组上下限（如最多 5 个）、分页 `page`/`size` 默认与上限 |
| 格式 | UUID、ISO8601 时间、slug 规则、布尔 Query 等按文档序列化 |
| 路径与方法 | method + path + 权限（Public/JWT/Admin）与文档一致 |
| 响应形状 | `data` 为对象 / `items` / 分页包 / 裸数组等，按文档解析；仅兼容文档已写明的变体 |

### 执行要求

- **行动清单**须写出依据：文档路径（可跳转链接）+ 章节/Endpoint 名；写不清依据则先查文档再改代码  
- **自测**至少一项：「字段/路径/必填是否与依据文档一致」  
- 纯样式/文案且不碰请求响应：可无业务契约，仍须遵守命中的前端规范样本  

### 对照结果必须写出来（对用户可见）

查文档后，在清单或交付说明中**摘录本次用到的必要字段信息**，禁止只写「已对齐文档」而无具体内容。必要部分至少包括：

| 摘录项 | 写到什么粒度 |
|--------|----------------|
| 依据 | 文档链接 + 章节/Endpoint |
| 路径与方法 | method + path + 权限 |
| 请求字段 | 字段名、类型、必填/可选、约束（长度/枚举/数量）；与本次改动无关的可省略并注明「未摘」 |
| 响应形状 | `data` / `items` / 分页关键结构 + 本次消费的字段 |
| 与代码映射 | 对应到将改的 `api`/`types`/表单字段（一句话即可） |

摘录宜短表或短列表；不要整章粘贴。

### 缺失与行业常见缺口：必须提醒并给建议

对照文档与任务后，若发现下列情况，须在**可见结果**中单独标明（建议用「缺口 / 建议」小节），**不得 silently 写进代码**：

| 类型 | 何时提醒 | 结果里写什么 |
|------|----------|--------------|
| 文档缺失 | Endpoint/字段表/必填/错误码在依据文档中找不到或互相矛盾 | 缺什么、在哪份文档应有、建议补文档或向用户确认以谁为准 |
| 实现缺口 | 文档有、当前代码无（或反过来） | 列出差集；建议按文档补齐或标偏差 |
| 行业常见但文档未写 | 该类功能业界/本产品同类页常见能力或字段（例：软删 `is_active`、分页 `total`、审计时间、幂等 `mode`、内容安全驳回码等）而本文档未定义 | **仅建议**：说明常见做法、是否值得补进契约、是否本轮可不做；**禁止**未获用户确认就当正式字段落地 |

口令：**文档有的对齐并写出；文档没有的提醒；行业常见的建议，不擅自发明进代码。**

### 禁止

- 无文档依据却新增 API 字段、改 Query 名、改 Body 形状  
- 「先写前端、文档以后补」冒充已对齐  
- 用另一模块的字段表套到当前接口  
- 只声称「已查文档」却不摘录本次必要字段  
- 把「行业常见建议」直接写成已定契约并改代码（须先提醒用户）  

### 4.2 任务分级（S/M/L）与可验收

按体量选闸门，**禁止**每个小改都跑「需求版块 → 代码提示词落盘 → 正式检测报告」长链。

| 级别 | 典型 | 主干 | 代码生成提示词落盘 | 自动化测试文件 |
|------|------|------|--------------------|----------------|
| **S** | 文案/样式/单点对齐 | 依据 → 改码 → 自测 | 否 | 否（手测即可） |
| **M** | 一页/一 API 对接 | 钉点或补设计 → 改码 → 契约核对 + 手测 | 通常否（对话约束即可） | 按需（易碎逻辑） |
| **L** | 新模块/多层一次生成 | 完整设计 →（可）提示词 → 分层出码 → 多闸对齐 → 验收 | 可以 | 建议补易碎点 |

**可验收（每次改功能行为后的底线）** ≠ 必须有测试文件、≠ 必须有正式报告：

1. 完成定义：主路径能做完（写成用户**看见什么**，不是接口 200）  
2. 契约：路径/关键字段/必填/响应形状已对齐并摘录（碰 API 时）  
3. 关键态：空/错/无权限（设计已写的）  
4. **手测（L2）**：真实入口 + 时序反测 + 有数据环境；乐观 UI 拆开验；细则见 Skill [`acceptance-handtest`](.cursor/skills/acceptance-handtest/SKILL.md)  
5. （按需）自动化测试锁回归；里程碑才写短交付，禁止每步报告博物馆  

[`docs/05_测试规范`](docs/05_测试规范/) 为平台级 QA **按需查表**，不能单独替代上列 L2。  

细节与规范引用映射见 Skill [`live-saas-workflow`](.cursor/skills/live-saas-workflow/SKILL.md)；自测勾选见 [`action-checklist`](.cursor/skills/action-checklist/SKILL.md)；手测法则见 [`acceptance-handtest`](.cursor/skills/acceptance-handtest/SKILL.md)。

## 5. 文档命名、模板与规范样本

1. **能匹配到模板的用模板**：后端完整设计 → `后端设计文档模板.md`；增量 → `增量设计文档模板.md`；规范/设计/指南/HANDOFF → 文件创建规范内模板；已有系列 → 沿用该系列体例。  
2. **文件创建权威**：[`通用规范-文件创建规范-v1.0`](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)。  
3. **前端规范样本**：按场景打开对应篇（场景映射见 Skill [`live-saas-workflow`](.cursor/skills/live-saas-workflow/SKILL.md)），禁止无任务通读全目录。  
4. **`04` / `05` / `06`**：平台级规章库，**按需查表引用**，禁止整本塞进提示词；与本仓样本冲突时，前端写法以 [前端规范样本](docs/前端规范样本/) 与模块设计为准，安全冲突以安全规范为准。

### 5.1 前端设计文档：体验层 + 落地层（强制）

**管线**：后端设计 / 增量 → **一份**前端设计文档（体验 + 契约）→ 再改 `src/**`。  
**禁止**：默认再开第三本「前端页面设计文档」；缺体验时只堆 API 摘录冒充页面设计。  
**不新开** `designer` Agent：体验检查挂在 [`docs`](.cursor/agents/docs.md) 写文档、[`frontend`](.cursor/agents/frontend.md) 锐评/实现。

写或大改 `Live-Saas-Wechat-*-前端设计文档-*.md`（及同类前端设计）时，**先体验后契约**。必填细则与裁剪见 [文件创建规范 §5.2](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)。

**体验钉五问**（动笔契约前先答；可写在文首或「范围/页面」章）：

1. **给谁用？**（普通用户 / 房主开播 / Admin；可多面但须分面写）  
2. **做完哪一件事算成功？**（一句话闭环 + 完成定义）  
3. **首屏只能留什么？**（主操作 / 主列表；次要入口降权或封印）  
4. **空了、满了、没权限时怎么办？**（关键态 + 人话）  
5. **本页明确不做什么？**（非目标封印）

**维度速查**（按模块体量裁剪；小增量可只做五问 + 落地表）：

| 层 | 维度 |
|----|------|
| 体验 | 受众面、闭环、完成定义、非目标、入口导航、信息架构/首屏、主路径、关键态、权限可见与文案、危险/可逆、对标边界 |
| 落地 | 落点文件、API/字段摘录（§4.1）、类型映射、现码差集、分期与验收、命中的规范样本链接 |

口令：**契约零偏差；体验不为每个后端字段都做控件；治理字段可弱展示或本版封印。**

## 6. 改文档与短配置：补丁还是重写

**口令**：意思没变 → 局部补丁；意思变了或靠「不是/不要」纠偏 → 重写该节（短文件可整份重写）。

| 情况 | 做法 |
|------|------|
| 错别字、版本号、日期、修订历史一行、表内改一两格 | 局部补丁 |
| 叠否定句纠正旧表述 | 重写该段/该节 |
| 章节职责或定位变化 | 重写该节；短文件优先整份重写 |
| 长设计文档仅局部口径变化 | 只重写该小节 |

先改本文（若习惯有变），再对齐 Cursor 短文件。

## 7. 输出与协作习惯

- 简体中文；先结论，少铺垫  
- 改动最小化；不顺手重构、不扩写未点名文件  
- 引用规则用编号或规范文件名，不复述长文  
- 密钥与 `.env*` 不进提交；用户未要求不 commit / 不 push

| Skill | [`acceptance-handtest`](.cursor/skills/acceptance-handtest/SKILL.md) | L1/L2/L3、L2 六句手测、类型加测；与 `docs/05` 边界；防「自测绿使用才炸」 |
| 索引 | [`.cursor/skills/README.md`](.cursor/skills/README.md) | Skills 分工说明（非第三套习惯真源） |
| Agent | [`explorer`](.cursor/agents/explorer.md) / [`frontend`](.cursor/agents/frontend.md) / [`docs`](.cursor/agents/docs.md) | 只读 / 改 src（含管理端表面原则）/ 改 docs |

**Agent 用法**：§3 定角色后，**Read** 对应 [`.cursor/agents/<角色>.md`](.cursor/agents/) 并遵守其「开始前 / 可改 / 禁止 / 产出」；禁止只写角色名却不读文件。多角色任务可顺序读多份，仍以用户本轮点名范围为准。

**Skill / Agent 内相关文档链接**：凡点名仓库内文件（`docs/**`、`.cursor/**`、模板、规范样本等），须写成可跳转 Markdown 链接（相对仓库根，如 `[文件创建规范](docs/前端规范样本/通用规范-文件创建规范-v1.0.md)`）；禁止只写无法点击的裸路径或仅文件名。不因此把业务文档目录堆进 Skill 当默认待办。

**不做**：按业务模块堆 Skill；把业务文档目录写成默认待办；十几个重叠 Agent（含单独 `designer`）；读了 Skill 却跳过可见清单/跳过 Agent 文件；前端设计只写契约不写受众/闭环（见 §5.1）。
