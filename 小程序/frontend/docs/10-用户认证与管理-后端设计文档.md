## 📌 核心定位说明

- **JWT认证（JWT）**: 个人信息管理、头像上传、密码修改、手机号/邮箱绑定、账号注销
- **管理员权限（ADMIN）**: 用户列表、用户状态/角色管理

### JWT Token格式说明

```json
{
  "user_id": "uuid-string",
  "username": "admin",
  "role": "admin",
  "exp": 1717756800
}
```

> **重要说明**: JWT Payload中用户标识字段为 `user_id`（非 `sub`）。

### 业务状态码

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| `200` | 成功 | 所有成功响应 |
| `1002` | 数据库错误 | 数据库操作异常 |
| `2001` | 资源不存在 | 用户不存在 |
| `2002` | 资源已存在 | 用户名/邮箱/手机号已注册 |
| `2004` | 业务逻辑错误 | 密码错误、验证码错误、账号已禁用 |
| `3001` | 未授权 | JWT Token缺失或无效 |
| `3002` | 权限不足 | 非管理员访问管理端接口 |
| `4001` | 参数校验失败 | 请求参数不符合规范 |
| `4011` | JWT Token无效 | Token过期或格式错误 |
| `4012` | 验证码错误 | 验证码不匹配或已过期 |
| `4013` | 登录失败 | 用户名或密码错误 |
| `4014` | 账号已禁用 | 用户账号被管理员禁用 |

## 🎯 设计要点与约定

### 1.1 数据库设计规范

1. **UUID主键**: 所有表使用 `UUID` 类型作为主键
2. **时间戳**: 所有时间字段使用 `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
3. **密码安全**: 密码使用SHA256哈希存储（或bcrypt）
4. **软删除**: `users` 表使用 `status` 字段控制账号状态
5. **索引策略**: 用户名、邮箱、手机号建立唯一索引

### 1.2 API设计规范

1. **HTTP方法**: GET（查询）、POST（创建/操作）、PATCH（部分更新）、DELETE（删除）
2. **URL路径**: 使用 `/api/v1/auth/` 和 `/api/v1/users/` 格式
3. **认证策略**: 分层认证（公开/普通用户/管理员）
4. **限流**: 登录、注册、验证码接口需要限流保护

### 1.3 软删除策略

| 表名 | 策略 | 说明 |
|------|------|------|
| `users` | `status` 字段 | 注销时设置 `status = 'deleted'`，查询时默认过滤 |
| `verification_codes` | 物理删除/过期清理 | 验证码使用后标记 `is_used = true`，过期后定期清理 |
| `refresh_tokens` | 物理删除/过期清理 | Token撤销时标记 `is_revoked = true`，过期后定期清理 |

### 1.4 安全规范

**密码安全**:
- 密码最小长度8位
- 密码必须包含大小写字母和数字
- 密码存储使用SHA256哈希（加盐）
- 登录失败次数限制（5次锁定300秒）

**Token安全**:
- Access Token有效期：30分钟
- Refresh Token有效期：7天
- Token刷新时旧Token立即失效

**验证码安全**:
- 验证码有效期：5分钟
- 验证码使用后立即失效
- 同一手机号/邮箱发送频率限制（60秒）

### 1.4 权限设计规范

**架构分层原则**:
- **API 层**: 仅负责认证
- **Service 层**: 负责授权和业务逻辑
- **CRUD 层**: 负责数据库操作

**用户身份提取**:

```python
async def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    """从JWT Token中提取用户身份"""
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        user_id = payload.get("user_id")
        if user_id is None:
            raise HTTPException(status_code=401, detail={"code": 4011, "message": "无效的Token"})
        return {"user_id": user_id, "role": payload.get("role")}
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail={"code": 4011, "message": "Token已过期"})
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail={"code": 4011, "message": "无效的Token"})
```

## 2. Pydantic Schemas定义

### 2.1 Auth Schemas

```python
from pydantic import BaseModel, Field, ConfigDict, field_validator
from typing import Optional, List
from uuid import UUID
from datetime import datetime
from enum import Enum


class ChannelEnum(str, Enum):
    EMAIL = "EMAIL"
    SMS = "SMS"


class ScenarioEnum(str, Enum):
    REGISTER = "REGISTER"
    PASSWORD_RESET = "PASSWORD_RESET"
    LOGIN = "LOGIN"
    BIND_PHONE = "BIND_PHONE"
    BIND_EMAIL = "BIND_EMAIL"


class LoginRequest(BaseModel):
    """登录请求Schema"""
    username: str = Field(..., min_length=1, max_length=50, description="用户名/邮箱/手机号")
    password: str = Field(..., min_length=1, description="密码")
    captcha_id: str = Field(..., description="验证码ID")
    captcha_solution: str = Field(..., description="验证码答案")


class LoginResponse(BaseModel):
    """登录响应Schema"""
    access_token: str
    refresh_token: str
    token_type: str = "bearer"


class RefreshTokenRequest(BaseModel):
    """刷新Token请求Schema"""
    refresh_token: str = Field(..., description="刷新Token")


class CaptchaResponse(BaseModel):
    """验证码图片响应Schema"""
    captcha_id: str
    captcha_image: str  # Base64编码的图片


class VerificationCodeRequest(BaseModel):
    """发送验证码请求Schema"""
    channel: ChannelEnum = Field(..., description="发送渠道")
    recipient: str = Field(..., description="接收者（邮箱或手机号）")
    scenario: ScenarioEnum = Field(..., description="使用场景")
    captcha_id: Optional[str] = Field(None, description="图形验证码ID（scenario=LOGIN 时可省略）")
    captcha_solution: Optional[str] = Field(None, description="图形验证码答案（scenario=LOGIN 时可省略）")


class VerifyCodeRequest(BaseModel):
    """校验验证码并签发 Ticket 请求Schema"""
    channel: ChannelEnum = Field(..., description="发送渠道")
    recipient: str = Field(..., description="接收者（邮箱或手机号）")
    scenario: ScenarioEnum = Field(..., description="使用场景")
    code: str = Field(..., min_length=4, max_length=8, description="OTP 验证码")


class VerifyCodeResponse(BaseModel):
    """校验验证码响应Schema"""
    ticket: str = Field(..., description="短期业务凭据（单次消费，TTL=600s）")
    expires_in: int = Field(default=600, description="Ticket 有效期（秒）")


class PasswordResetRequest(BaseModel):
    """密码重置请求Schema（申请重置）"""
    email: str = Field(..., description="邮箱地址")
    captcha_id: str = Field(..., description="验证码ID")
    captcha_solution: str = Field(..., description="验证码答案")


class PasswordReset(BaseModel):
    """密码重置Schema（执行重置）"""
    reset_token: str = Field(..., description="重置Token")
    new_password: str = Field(..., min_length=8, description="新密码")


class RegisterRequest(BaseModel):
    """邮箱注册请求Schema"""
    username: str = Field(..., min_length=3, max_length=50, description="用户名")
    email: str = Field(..., description="邮箱地址")
    nickname: str = Field(..., min_length=1, max_length=100, description="昵称")
    password: str = Field(..., min_length=8, description="密码")
    verification_code: str = Field(..., description="邮箱验证码（scenario=REGISTER）")

    @field_validator("password")
    @classmethod
    def validate_password(cls, v: str) -> str:
        """校验密码强度"""
        if not any(c.isupper() for c in v):
            raise ValueError("密码必须包含大写字母")
        if not any(c.islower() for c in v):
            raise ValueError("密码必须包含小写字母")
        if not any(c.isdigit() for c in v):
            raise ValueError("密码必须包含数字")
        return v


class PhoneRegisterRequest(BaseModel):
    """手机号注册请求Schema（基于 register_ticket，不接收明文 OTP）"""
    register_ticket: str = Field(..., description="REGISTER 场景的 ticket（由 POST /auth/verification-codes/verify 签发）")
    password: str = Field(..., min_length=8, max_length=128, description="密码")
    nickname: str = Field(..., min_length=1, max_length=50, description="昵称")

    @field_validator("password")
    @classmethod
    def validate_password(cls, v: str) -> str:
        """校验密码强度"""
        if not any(c.isupper() for c in v):
            raise ValueError("密码必须包含大写字母")
        if not any(c.islower() for c in v):
            raise ValueError("密码必须包含小写字母")
        if not any(c.isdigit() for c in v):
            raise ValueError("密码必须包含数字")
        return v


class PhoneRegisterResponse(BaseModel):
    """手机号注册响应Schema"""
    public_id: str
    username: str
```

3. **消费Ticket**: 消费 `register_ticket`（`scenario=REGISTER`），从 Ticket 中提取手机号
4. **唯一性检查**: 检查手机号是否已被注册
5. **密码强度校验**: 校验密码复杂度
6. **密码哈希**: 对密码进行 bcrypt 哈希
7. **生成用户名**: 自动生成 `u_{uuid_hex[:10]}` 格式用户名
8. **插入数据库**: `INSERT INTO users (...)`，设置 `phone_number`、`is_phone_verified = true`，`email = NULL`
9. **提交事务**: `await db.commit()`
10. **签发JWT**: 生成 Access Token + Refresh Token
11. **返回响应**: 返回用户信息及 Token（注册后可直接登录，无需再调登录接口）

**与邮箱注册的差异**:

| 项目 | 邮箱注册（§3.2.1） | 手机号注册（§3.2.2） |
|------|-------------------|---------------------|
| 用户名 | 用户自定义 | 系统自动生成 |
| 邮箱 | 必填，注册时验证 | 不填（可后续绑定） |
| 手机号 | 不处理 | 必填，注册时验证 |
| 验证码方式 | 邮箱 OTP（或图形验证码，以实现为准） | SMS OTP → Ticket |
| 注册后 Token | 不返回，需再登录 | 直接返回 JWT |

## 4. 执行流程详细说明

### 4.1 登录完整流程

```
1. API路由接收POST请求
   → 2. Pydantic校验（LoginRequest）
   → 3. 验证码校验（captcha_id + captcha_solution）
   → 4. 查询用户（WHERE username/email = :username OR phone = :username AND is_phone_verified）
   → 5. 用户存在性检查
   → 6. 账号状态检查（status != 'disabled'）
   → 7. 密码校验（哈希比对）
   → 8. 登录失败计数检查
   → 9. 更新 last_login_at / last_login_ip
   → 10. 生成Access Token + Refresh Token
   → 11. 存储Refresh Token到数据库
   → 12. 返回Token响应
```

### 4.2 注册完整流程

**邮箱注册（`POST /users/register`）**:

```
1. POST /auth/verification-codes  (channel=EMAIL, scenario=REGISTER)
   → 2. 用户收到邮箱 OTP
   → 3. POST /users/register（RegisterRequest，含 verification_code）
   → 4. 校验邮箱 OTP、用户名/邮箱唯一性
   → 5. 密码哈希 → 插入 users（is_email_verified=true, phone=NULL）
   → 6. 返回注册成功（不含 Token，需再登录）
```

**手机号注册（`POST /users/register/phone`）**:

```
1. POST /auth/verification-codes  (channel=SMS, scenario=REGISTER)
   → 2. 用户收到短信 OTP
   → 3. POST /auth/verification-codes/verify  (scenario=REGISTER) → register_ticket
   → 4. POST /users/register/phone（PhoneRegisterRequest，含 register_ticket）
   → 5. 消费 ticket → 校验手机号唯一性 → 自动生成 username
   → 6. 密码哈希 → 插入 users（is_phone_verified=true, email=NULL）
   → 7. 签发 JWT → 返回用户信息 + Token
```

### 4.3 Token刷新完整流程

```
1. API路由接收POST请求
   → 2. 解码Refresh Token获取user_id
   → 3. 查询数据库中的Refresh Token记录
   → 4. Token有效性检查（未撤销、未过期）
   → 5. 撤销旧Refresh Token
   → 6. 生成新的Access Token + Refresh Token
   → 7. 存储新Refresh Token
   → 8. 返回新Token响应
```

## 5. 错误处理与事务管理

### 5.1 错误处理策略

**认证异常**:
- Token无效/过期（code=4011）→ HTTP 401
- 验证码错误（code=4012）→ HTTP 401
- 登录失败（code=4013）→ HTTP 401
- 账号禁用（code=4014）→ HTTP 403

**业务异常**:
- 资源已存在（code=2002）→ HTTP 409
- 业务逻辑错误（code=2004）→ HTTP 422

### 5.2 事务管理规范

**单表操作**: 使用单个事务，操作失败自动回滚

**Token操作**: 撤销旧Token和存储新Token在同一事务中完成

## 6. 性能优化建议

### 6.1 数据库优化

- **索引优化**: 用户名、邮箱、手机号唯一索引加速登录查询
- **查询优化**: 登录查询使用 `WHERE username = :u OR email = :u OR (phone = :u AND is_phone_verified = true)`

- **Redis缓存**: 验证码存储在Redis中（TTL=5分钟）
- **登录失败计数**: 使用Redis存储登录失败次数（TTL=300秒）

### 6.3 应用层优化

- **异步发送**: 邮件/短信发送使用异步任务队列
- **限流**: 登录、注册、验证码接口使用Redis限流
