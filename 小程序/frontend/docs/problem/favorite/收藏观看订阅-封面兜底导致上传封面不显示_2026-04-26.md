# 可执行缺陷单：收藏/观看历史/订阅封面兜底导致上传封面不显示

缺陷ID: FE-MEDIA-20260426-01  
发现时间: 2026-04-26  
当前状态: 前端已修复，待 QA 回归  
优先级: P1  
责任域: FE + 环境配置 + QA

## 1. 一句话结论
列表页封面加载失败的主因不是“上传失败”，而是 `resolveMediaUrl()` 生成本地媒体地址后，又被 `normalizeImageUrl()` 将 `http://localhost` 错升为 `https://localhost`，最终触发加载失败并落入兜底图。

## 2. 复现步骤（可直接执行）
前置条件:
1. 本地后端运行在 `http://localhost:8080`。
2. 任一房间封面地址为 `/media/...` 或 `http://localhost:8080/media/...`。

操作步骤:
1. 进入收藏列表页面。
2. 进入观看历史页面。
3. 进入订阅列表页面。

实际结果:
1. 封面显示兜底图。
2. 控制台出现 `ERR_SSL_PROTOCOL_ERROR`。

期望结果:
1. 三个页面均显示真实封面。
2. 不出现 `https://localhost:8080/media/...` 相关协议错误。

## 3. 证据分级
| 结论 | 证据等级 | 证据 | 备注 |
|---|---|---|---|
| 媒体 URL 完整链路为 `resolveMediaUrl()` → `normalizeImageUrl()` | E1-已验证 | `src/utils/url.ts` 同时负责拼接 `/media` 与协议规范化 | 代码静态证据 |
| 失败后落入兜底图 | E1-已验证 | `CollectionList.vue` / `ViewHistory.vue` 的 `@error` 分支与 fallback | 页面代码证据 |
| 订阅列表受同类问题影响 | E1-已验证 | `SubscriptionList.vue` 已补齐 `resolveMediaUrl()` + `@error` fallback，同样进入该链路 | 页面代码证据 |
| hydrate 机制会放大影响面 | E2-高可信 | `userFavorites.ts` / `userSubscriptions.ts` 会二次补齐封面后继续进入同一 URL 规范化链路 | 需运行时确认补齐链路 |

## 4. 影响范围
功能影响:
1. 收藏列表封面展示。
2. 观看历史封面展示。
3. 订阅列表封面展示。

体验影响:
1. 用户误以为上传封面失败。
2. 列表视觉质量下降，兜底图占比高。
