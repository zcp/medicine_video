# 可执行缺陷单：创建直播后专家关联未保存，详情页出现空“专家介绍”Tab

缺陷ID: FE-BE-EXPERT-20260426-04  
发现时间: 2026-04-26  
当前状态: 部分修复（前端路径纠偏与Tab收敛已完成，待环境对齐验证）  
优先级: P1  
责任域: BE + FE + QA

## 1. 一句话结论
本次问题的主链路不是“创建直播失败”，而是**房间与场次已创建成功，但当前前端场次专家读写路径与目标契约不一致，叠加环境部署/网关对齐风险，最终在运行环境表现为 404**；前端此前又会无条件注入 `expert_intro` 功能性 Tab，导致用户在详情页看到空页签并误判为“专家已保存但内容没显示”。

## 2. 复现步骤（可直接执行）
前置条件:
1. 当前前端调用 `POST /admin/sessions/{id}/experts`，在运行环境返回 404。
2. 当前前端调用 `GET /sessions/{id}/experts`，在运行环境返回 404。
3. 创建直播页选择了至少 1 个专家。

操作步骤:
1. 打开创建直播页，填写标题、简介、封面等必填项。
2. 选择 1 个或多个专家。
3. 提交创建（预告 / 直播 / 回放任一模式均可复现该专家链路问题）。
4. 创建完成后进入首页并打开刚创建的直播间详情页。

实际结果:
1. 日志显示 `POST /admin/sessions/{id}/experts` 404。
2. 房间与场次本身已经创建成功，首页房间数增加，详情页可进入。
3. 专家关联未真正保存。
4. 在未修复前，详情页仍会出现空的“专家介绍”Tab。

期望结果:
1. 选择专家后创建直播，专家关联应被成功写入并在详情页可见。
2. 若专家接口缺失，创建主流程不应失败，但必须明确提示“专家未保存”。
3. 若无真实专家内容，详情页不应显示“专家介绍”空 Tab。

## 4. 根因拆解
### 4.1 主根因
1. **前端接口路径与目标契约不一致**：当前读写使用 `/admin/sessions/{id}/experts` 与 `/sessions/{id}/experts`，与专家链路目标契约存在偏差，导致运行时 404。
2. **环境对齐未确认**：若部署版本或网关路由未对齐，仍会出现 404；需继续核验部署与转发策略。
3. **前端旧策略误导用户**：在未修复前，详情页会基于“有 sessionId/可推断专家”无条件注入 `expert_intro` Tab，即使没有真实专家内容，也会出现空页签。

### 4.2 责任边界
| 层级 | 现状 | 结论 |
|---|---|---|
| FE 创建页 | 已改为专家绑定失败不阻断创建 | 前端主流程已止血（但接口路径仍待纠偏） |
| FE 详情页 | 已增加专家Tab门控 | 前端误导部分修复（fallback 仍待收敛） |
| FE API配置 | 读写路径与目标契约不一致 | 前端待纠偏 |
| BE / Ops | 运行环境与网关是否对齐待确认 | 需联合核验部署版本与路由策略 |

## 5. 用户影响范围
功能影响:
1. 创建直播时选择专家后，专家关系未落库。
2. 详情页无法展示真实场次专家列表。
3. 在旧前端实现下，用户会看到空的“专家介绍”Tab，误以为数据展示异常而非接口缺失。

体验影响:
1. 用户感知为“创建成功但配置不完整”。
2. 主播 / 运营无法验证专家配置是否生效。
3. QA 在回归时容易把“空 Tab”误记为渲染问题，而忽略实际是 API 缺失。

## 12. 风险与回滚
风险:
1. 后端补齐接口后，若返回结构与前端 `normalizeSessionExpertItems()` 预期不一致，仍可能出现展示空态。
2. 历史房间若残留早期创建的 `expert_intro` 管理员 Tab，需依赖 `LiveView` 的“真实内容判断”屏蔽。

回滚策略:
1. 保留“专家绑定失败不阻断创建”的保护逻辑，不建议回滚。
2. 若后端上线接口后结构不稳定，前端继续维持“无真实内容则不显示专家 Tab”的保守策略。
