# 个人页面：前端缓存策略缺失

**发现时间**: 2026-04-22  
**状态**: ✅ 已修复（2026-04-23）— `onShow` 增加模块级 `lastSyncAt` + `SYNC_TTL` 守卫（5 分钟内不重复请求）；计时器与数据同在 `authStore` 语境，无跨 Store 副作用  
**涉及文件**: `src/pages/profile/Profile.vue` · `src/store/user.ts`

---

## 问题：`onShow` 每次进入都无条件请求 `GET /me`

### 现象

```
GET http://localhost:8080/api/users/me  404
  getCurrentUser  @ user.js:5
  syncUserInfo    @ Profile.js:71
  onShow          @ Profile.js:66
```

Tab 页切换时，每次进入个人页都触发一次 `GET /me`，约每 4–5 秒出现一次（小程序底部 4 个 Tab 反复切换时）。

### 根因

`Profile.vue` 的 `onShow` 钩子：

```typescript
onShow(() => {
  syncUserInfo()   // 每次进入都调
})

async function syncUserInfo() {
  const data = await getCurrentUser()   // 直接发请求，无缓存检查
  authStore.setUserInfo(data)
}
```

而 `src/store/user.ts` 中**已有**带 5 分钟缓存的 `shouldRefresh()` 方法：

```typescript
shouldRefresh(): boolean {
  const CACHE_DURATION = 5 * 60 * 1000
  return Date.now() - this.lastUpdateTime > CACHE_DURATION
}
```

但 `Profile.vue` 的 `syncUserInfo` 完全**绕过了这个缓存机制**，每次都无条件请求。

### 影响

| 环境 | 影响 |
|------|------|
| 本地 dev | 每次 tab 切换触发 404，干扰日志 |
| 生产环境 | 每次切到个人页都打服务器，5 分钟内 10 次切换 = 10 次请求，造成不必要压力 |
| 用户体验 | 每次进入个人页都有网络延迟，信息会闪烁刷新 |

### 已修复实现

`Profile.vue` 当前使用模块级 `lastSyncAt` + `SYNC_TTL` 守卫，5 分钟内不重复请求：

```typescript
// Profile.vue — 当前正确实现
let lastSyncAt = 0
const SYNC_TTL = 5 * 60 * 1000

onShow(() => {
  setCustomTabBarSelected(3)
  if (isLoggedIn.value && Date.now() - lastSyncAt > SYNC_TTL) void syncUserInfo()
})

async function syncUserInfo() {
  lastSyncAt = Date.now()   // 先更新计时器，防止失败时持续轮询
  try {
    const resp = await getCurrentUser()
    // ... 更新 authStore
  } catch {
    // ignore
  }
}
```

> 注意：此实现使用页面级 `lastSyncAt` 而非 `user.ts` 的 `shouldRefresh()`，两者逻辑独立，无跨 Store 副作用。
