# 0）全局响应式适配规则（所有页面通用）

## 0.1 断点定义（建议与你 global.scss 对齐）

> 你可以映射到 `$breakpoint-sm / md / lg`

### 手机（Mobile）

* 宽度：`< 480px`
* 主布局：单列、全宽按钮

### 平板（Tablet）

* 宽度：`480px ~ 900px`
* 主布局：卡片居中、宽度限制

### PC（Desktop）

* 宽度：`>= 900px`
* 主布局：居中容器 + 固定宽度（400~460px）

---

## 0.2 容器宽度策略（核心）

所有认证页容器统一规则：

* Mobile：`width: 92vw; max-width: 420px`
* Tablet：`width: 420px; max-width: 460px`
* Desktop：`width: 420px; max-width: 460px`

并保持：

* `margin: 0 auto`
* 永远不会横向滚动

---

## 0.3 垂直位置策略（高级感来源）

* Mobile：容器靠上（top padding 12vh~16vh）
* Desktop：容器居中（top padding 18vh~22vh）

原则：

> C端更靠上（像抖音）
> 后台更居中（像 Vercel）

---

## 0.4 字体与间距缩放规则

### Mobile

* 标题：48~56rpx
* 副标题：26~28rpx
* 输入框间距：16rpx
* CTA 按钮高度：88rpx

### Desktop

* 标题：32px
* 副标题：14~16px
* 输入框间距：14~16px
* CTA 按钮高度：44~48px

# 1）全局页面骨架（所有认证页面共用）

```
[Page Root: auth-page]

  [Background Layer]
  - 白色/浅灰背景
  - 无渐变（consumer 可有极浅 radial）

  [Auth Container: auth-container]
    - width: 92vw / 420~460px
    - responsive max-width
    - padding: 0 24rpx
    - margin: auto

    [Top Header: auth-top]
      - 可选：返回按钮（H5/APP）
      - 标题（小标题，灰色）
      - 右侧入口（如：帮助 / 注册）

    [Main Card / Section: auth-main]
      - consumer: 不强调 card（更像原生页面）
      - admin: 可以轻 card（白底 + border）

      [Brand Area: auth-brand]（可选）
        - logo / icon（40~56rpx）
        - product name（小字）

      [Title Area: auth-title]
        - H1 主标题
        - Subtitle 副标题

      [Primary Action Area: auth-primary]
        - 主输入（手机号/账号）
        - 主按钮 CTA（大 pill）

      [Secondary Actions: auth-secondary]
        - 切换登录方式入口
        - 忘记密码/注册入口

      [Divider: auth-divider]（可选）
        - line + text

      [OAuth Area: auth-oauth]（可选）
        - grid buttons

      [Agreement: auth-agreement]
        - 协议文字 + checkbox

    [Footer: auth-footer]（可选）
      - 版本号 / 公司信息 / ICP
```

# 2）登录页 Wireframe（consumer 模式）

> 对标：抖音 / B站
> 目标：用户进入只看到一个动作：一键登录/手机号登录

---

## 2.1 consumer 登录页结构

```
[Login Page - consumer]

(auth-container)

  auth-top
    ├── [Back]（可选）
    ├── [Text: 登录]（灰色小标题）
    └── [Help / Register]（右侧轻入口）

  auth-main

    auth-brand（可选）
      └── [Logo]

    auth-title
      ├── [H1: 欢迎回来]
      └── [Subtitle: 登录后体验完整功能]

    auth-primary
      ├── [Input: 手机号]（uni-easyinput）
      └── [Primary CTA Button: 获取验证码 / 一键登录]

    auth-secondary（轻入口行）
      ├── [Link: 账号密码登录]（次入口）
      └── [Link: 遇到问题]（可选）

    auth-divider（可选）
      ├── line
      └── text: 或使用以下方式登录

    auth-oauth（可选）
      └── [Grid 2 columns]
          ├── [WeChat Button]
          ├── [Apple Button]
          ├── [Google Button]
          └── [Empty placeholder / auto fill]

    auth-agreement
      ├── checkbox
      └── text: 我已阅读并同意《用户协议》《隐私政策》
```

---

## 2.2 consumer 响应式规则

### Mobile（<480px）

* oauth grid：2 列
* 按钮高度：72rpx
* 主按钮高度：88rpx
* title 顶部留白：12vh

### Tablet（480~900px）

* oauth grid：2 列
* container max-width：460px
* 增加 auth-main padding

### Desktop（>=900px，H5）

* oauth grid：3 列（如果空间够）
* 主按钮高度：48px
* card 可略微加强阴影（subtle）

---

## 2.3 登录页与一键登入页的衔接

* **从一键登入页跳转「账号密码登录」**：跳转至 `/pages/auth/login?form=account`，登录页需在 H5 通过 URL 参数、在小程序/App 通过页面 `onLoad(options)` 读取 `form=account`，并直接展示账号密码表单（admin 形态），无需用户再点「账号密码登录」。
* **从一键登入页跳转「手机号登录」**：跳转至 `/pages/auth/login`（无参数），展示默认手机号+验证码主流程。

# 2.5）手机一键登入页 Wireframe（独立入口页，可选）

> 适用场景：App 或 H5 将「本机一键登录」作为独立入口页时使用；与登录页共用同一设计语言与骨架。

## 2.5.1 一键登入页结构

```
[One-Tap Login Page]

(auth-container)  // 与登录页一致：max-height 88vh/82vh，无卡片化

  auth-main（可滚动 overflow-y: auto，flex: 1 1 0）

    auth-title
      ├── [H1: 欢迎回来]
      └── [Subtitle: 使用本机一键登录，安全快捷]

    auth-primary
      └── [Primary CTA Button: 本机一键登录]（大 pill，主色 #0F766E）

    auth-secondary（auth-links）
      ├── [Link: 手机号登录]  → /pages/auth/login
      └── [Link: 账号密码登录]  → /pages/auth/login?form=account

    auth-divider
      ├── line
      └── text: 或使用以下方式登录

    auth-oauth
      └── oauth-grid（2 列 / ≥900px 为 3 列）
          ├── [Apple 登录]（图标+文字）
          ├── [微信登录]（图标+文字）
          ├── [Google 登录]（图标+文字）
          └── [Placeholder]

  auth-agreement（与 auth-main 平级，flex-shrink: 0）
    └── text: 登录即表示同意《用户协议》与《隐私政策》
```

## 2.5.2 一键登入页响应式与样式

* 与登录页 consumer 完全一致：断点、容器宽度、配色（#0F766E）、主按钮 pill、阴影、auth-links、分割线、oauth-grid、协议区贴底。
* 路由：`/pages/auth/one-tap-login`，需在 `pages.json` 中注册。
* 业务逻辑：支持本机一键的终端（如部分 App/运营商）主按钮直接调一键登录；不支持时（如 H5）可提示「本机一键登录需在 App 内使用」并引导至登录页。

# 12）不同分辨率 / 不同屏幕比例适配策略

## 12.1 超小屏（≤360px）

* 减少标题字号 10%
* oauth grid 仍保持两列，但 gap 减到 12rpx
* 主按钮高度保持不变（体验优先）

## 12.2 大屏手机（≥430px）

* container max-width 420px
* 保持居中，防止拉伸太宽

## 12.3 横屏（Landscape）

* container 垂直居中
* top padding 改为 8vh
* 减少标题与表单间距

# 13）最终交付标准（验收 checklist）

所有认证页面必须满足：

### UI 一致性

* 登录/注册/忘记密码共享同一 tokens（颜色、圆角、阴影）
* 主按钮永远是 pill 样式
* 输入框永远是轻边框 + focus ring

### 交互一致性

* hover/active/focus-visible 全覆盖
* transition 180~220ms
* 不出现 layout shift

### 响应式一致性

* mobile 永远无横向滚动
* oauth grid 永远对齐，不允许“第二行居中一个按钮”
* container 宽度固定规则生效

# 最后一句总结（你现在该怎么做）

你要达到 B站/抖音那种“简约高级”，关键不是再调阴影，而是：

> **consumer 模式：去卡片化、去模块化、只保留一个主按钮 + 轻输入**
> **admin 模式：保持表单但更克制、更 Vercel**
> **所有页面共享一套 tokens**
