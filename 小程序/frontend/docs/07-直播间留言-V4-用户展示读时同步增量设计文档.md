## ⚠️ 重要声明

- **本文档是对 V3 展示语义的增量修订，不是替代留言 CRUD / V2 内容安全**
- **V3 的「改资料不影响历史留言」展示语义已被本版取代**
- **`extra` 仍可在发留言时写入昵称/头像**，仅作降级兜底与写路径兼容，**读展示不以快照为准**
- **未标注内容以 V1.1 / V2 / V3（写路径）/ 16-D3（注销）为准**

## 📌 核心定位说明

### 1. 变更背景

V3 因 users / live_core 分库，采用发送时 JWT 快照进 `extra`，列表不跨服务查用户。  
产品对齐抖音 / B站：**活跃作者改个人中心昵称/头像后，历史留言应展示当前资料**。

### 2. 本次变更类型

- 【修改】C 端 / Admin 留言列表读路径：对本页作者 `POST /internal/users/batch`，覆盖 `user.nickname` / `user.avatar_url` / `user_display_name`
- 【修改】缓存命中路径同样再 enrich（否则改头像后仍见缓存旧脸）
- 【保持】发留言仍写 `extra` 快照；POST / WS 仍可用 JWT 瞬时值
- 【保持】16-D3 注销占位优先级最高

### 3. 核心原则

- ✅ **读时同步**：活跃作者 = 个人中心当前昵称 + 头像
- ✅ **组装顺序**：`extra` 快照 → users.batch 当前资料 → 16-D3 注销覆盖
- ✅ **友好降级**：batch 失败 / 未配置 → 继续用快照，不 500
- ✅ **不回写**历史 `extra`、不改表结构
- ✅ **不要求**改资料后 WS 刷全房间历史（下次拉列表即新）

---

## 🎯 方案说明

```
GET 留言列表（含缓存命中）
  → 本页 user_id 去重
  → fetch_user_profiles（internal batch）
  → 每条：snapshot → live profile → apply_deactivated_display
  → 响应 user / user_display_name
```

**采用**：列表批量调 users 内部接口（与品牌成员补全同一客户端）。  
**不采用**：跨库 JOIN、FDW、注销时回写全表 extra、改头像后主动 WS 刷历史。

## 🔌 响应契约（【修改·语义】）

响应 JSON 形状不变：

```json
{
  "user_display_name": "张医生",
  "user": {
    "nickname": "张医生",
    "avatar_url": "/uploads/avatars/xxx.jpg"
  }
}
```

| 场景 | 展示名 | 头像 |
|------|--------|------|
| 作者活跃 + batch 成功 | 个人中心当前 nickname（空则 username） | 个人中心当前 avatar_url |
| 作者活跃 + batch 失败 | extra 快照 | extra 快照 |
| 作者已注销（16-D3） | 「账号已注销」 | `null` |
