## 1. 核心原则

### 1.1 分页类型区分

| 分页类型 | 数据来源 | 总数来源 | 适用场景 |
|---------|---------|---------|---------|
| **后端分页** | 每次请求后端获取当前页数据 | 后端返回的 `total` | ✅ **推荐**：数据量大（>100条） |
| **前端分页** | 一次性加载所有数据到前端 | 前端数组长度 | ⚠️ 仅适用于：数据量小（<100条） |

### 1.2 黄金法则

> **如果后端返回了 `total` 字段，必须使用后端分页！**

- ✅ **正确**：使用后端返回的 `total` 作为分页总数
- ❌ **错误**：使用前端数组长度作为分页总数
- ❌ **错误**：只加载第一页数据，却使用前端分页逻辑

## 2. 常见错误模式

### ❌ 错误模式 1：前端分页 + 只加载第一页数据

**问题代码**：
```vue
<script setup>
// Store 只加载第一页
await roomStore.fetchRooms({ refresh: true, page: 1, size: 10 })

// 前端分页（错误！）
const paginatedRooms = computed(() => {
  const start = (currentPage.value - 1) * pageSize.value
  const end = start + pageSize.value
  return filteredRooms.value.slice(start, end)  // ❌ 只对10条数据切片
})

// 使用前端数组长度（错误！）
<el-pagination :total="filteredRooms.length" />  // ❌ 显示10而不是2686
</script>
```

**问题**：
- 后端返回 `total: 2686`，但前端只加载了10条
- 分页组件显示"共10个"，无法翻页查看其他数据
- 用户以为只有10条数据

---

### ❌ 错误模式 2：混淆前端过滤和后端分页

**问题代码**：
```vue
<script setup>
// 后端分页
await roomStore.fetchRooms({ page: 1, size: 10 })

// 前端搜索过滤
const filteredRooms = computed(() => {
  if (searchKeyword.value) {
    return rooms.value.filter(r => r.title.includes(searchKeyword.value))
  }
  return rooms.value
})

// 使用过滤后的长度（错误！）
<el-pagination :total="filteredRooms.length" />  // ❌ 应该是后端total
</script>
```

**问题**：
- 搜索时应该请求后端（如果后端支持搜索）
- 或者使用后端返回的 `total`，而不是前端过滤后的长度

---

### ❌ 错误模式 3：翻页不重新请求后端

**问题代码**：
```vue
<script setup>
// 初始化时加载第一页
onMounted(() => {
  await roomStore.fetchRooms({ page: 1, size: 10 })
})

// 翻页时只改变页码，不请求后端（错误！）
const handlePageChange = (page: number) => {
  currentPage.value = page  // ❌ 没有重新请求后端
}
</script>
```

**问题**：
- 翻页时应该重新请求后端获取对应页的数据
- 否则永远只显示第一页的数据

## 3. 正确实现模式

### ✅ 模式 1：纯后端分页（推荐）

**适用场景**：数据量大，后端支持分页和搜索

**实现要点**：
1. Store 存储后端返回的 `total`
2. 分页组件使用 `pagination.total`
3. 翻页/搜索时重新请求后端
4. 表格直接显示当前页数据（不进行前端切片）

**代码结构**：
```vue
<script setup>
// 1. 从 Store 获取数据和分页信息
const { rooms, pagination } = storeToRefs(roomStore)

// 2. 前端过滤（仅用于 excludeRoomIds，不影响分页总数）
const filteredRooms = computed(() => {
  return rooms.value.filter(room => !excludeRoomIds.includes(room.id))
})

// 3. 表格直接使用过滤后的数据（不切片）
const paginatedRooms = computed(() => {
  return filteredRooms.value  // ✅ 直接返回，不切片
})

// 4. 分页组件使用后端总数
<el-pagination :total="pagination.total || 0" />

// 5. 翻页时重新请求后端
const handlePageChange = async (page: number) => {
  currentPage.value = page
  await roomStore.fetchRooms({ refresh: true, page, size: pageSize.value })
}

// 6. 搜索时重新请求后端（如果后端支持）
const handleSearch = async () => {
  currentPage.value = 1
  await roomStore.fetchRooms({ 
    refresh: true, 
    page: 1, 
    size: pageSize.value,
    q: searchKeyword.value  // 后端搜索参数
  })
}
</script>
```

---

### ✅ 模式 2：前端分页（仅适用于小数据量）

**适用场景**：数据量小（<100条），一次性加载所有数据

**实现要点**：
1. 一次性加载所有数据（不传分页参数或传 `size: 1000`）
2. 前端进行分页切片
3. 使用前端数组长度作为总数

**代码结构**：
```vue
<script setup>
// 1. 一次性加载所有数据
onMounted(async () => {
  await roomStore.fetchRooms({ refresh: true, size: 1000 })  // 加载所有
})

// 2. 前端过滤
const filteredRooms = computed(() => {
  let list = rooms.value.filter(...)
  if (searchKeyword.value) {
    list = list.filter(...)  // 前端搜索
  }
  return list
})

// 3. 前端分页切片
const paginatedRooms = computed(() => {
  const start = (currentPage.value - 1) * pageSize.value
  const end = start + pageSize.value
  return filteredRooms.value.slice(start, end)  // ✅ 前端切片
})

// 4. 使用前端数组长度
<el-pagination :total="filteredRooms.length" />  // ✅ 前端总数

// 5. 翻页不需要请求后端
const handlePageChange = (page: number) => {
  currentPage.value = page  // ✅ 只改变页码
}
</script>
```

## 4. 完整代码示例

### 示例：RoomSelectionDialog（后端分页）

```vue
<template>
  <el-dialog :model-value="visible" title="选择直播间" width="90%">
    <!-- 搜索框 -->
    <el-input 
      v-model="searchKeyword" 
      placeholder="搜索直播间标题" 
      @input="handleSearch"
    />
    
    <!-- 统计信息：使用后端总数 -->
    <div>共 {{ pagination.total || 0 }} 个直播间，已选择 {{ selectedCount }} 个</div>
    
    <!-- 表格：直接显示当前页数据 -->
    <el-table :data="paginatedRooms">
      <!-- 列定义 -->
    </el-table>
    
    <!-- 分页组件：使用后端总数 -->
    <el-pagination
      v-model:current-page="currentPage"
      v-model:page-size="pageSize"
      :page-sizes="[10, 20, 50, 100]"
      :total="pagination.total || 0"
      layout="total, sizes, prev, pager, next, jumper"
      @size-change="handleSizeChange"
      @current-change="handleCurrentChange"
    />
  </el-dialog>
</template>

<script setup lang="ts">
import { ref, computed, watch } from 'vue'
import { useRoomStore } from '@/store/room'
import { storeToRefs } from 'pinia'

interface Props {
  visible: boolean
  selectedRooms: any[]
  excludeRoomIds?: string[]
}

const props = withDefaults(defineProps<Props>(), {
  excludeRoomIds: () => []
})

// 响应式数据
const searchKeyword = ref('')
const currentPage = ref(1)
const pageSize = ref(20)

// Store
const roomStore = useRoomStore()
const { rooms, pagination } = storeToRefs(roomStore)

// ✅ 前端过滤（仅用于 excludeRoomIds，不影响分页总数）
const filteredRooms = computed(() => {
  return (rooms.value || []).filter((room: any) => 
    !props.excludeRoomIds.includes(room.id)
  )
})

// ✅ 表格数据：直接使用过滤后的数据（不切片）
const paginatedRooms = computed(() => {
  return filteredRooms.value
})

// ✅ 搜索：重新请求后端（如果后端支持搜索）
const handleSearch = async () => {
  currentPage.value = 1
  try {
    await roomStore.fetchRooms({ 
      refresh: true, 
      page: 1, 
      size: pageSize.value,
      q: searchKeyword.value  // 后端搜索参数
    })
  } catch (e: any) {
    ElMessage.error(e?.message || '搜索失败')
  }
}

// ✅ 翻页：重新请求后端
const handleCurrentChange = async (page: number) => {
  currentPage.value = page
  try {
    await roomStore.fetchRooms({ 
      refresh: true, 
      page, 
      size: pageSize.value 
    })
  } catch (e: any) {
    ElMessage.error(e?.message || '加载失败')
  }
}

// ✅ 改变每页大小：重新请求后端
const handleSizeChange = async (size: number) => {
  pageSize.value = size
  currentPage.value = 1
  try {
    await roomStore.fetchRooms({ 
      refresh: true, 
      page: 1, 
      size 
    })
  } catch (e: any) {
    ElMessage.error(e?.message || '加载失败')
  }
}

// 初始化：打开对话框时加载第一页
watch(() => props.visible, async (newVisible) => {
  if (newVisible) {
    searchKeyword.value = ''
    currentPage.value = 1
    try {
      await roomStore.fetchRooms({ refresh: true, page: 1, size: pageSize.value })
    } catch (e: any) {
      ElMessage.error(e?.message || '加载失败')
    }
  }
})
</script>
```

## 5. 检查清单

在实现分页功能时，请对照以下清单：

### 5.1 数据加载检查

- [ ] **后端是否返回 `total` 字段？**
  - ✅ 是 → 必须使用后端分页
  - ❌ 否 → 可以使用前端分页（仅适用于小数据量）

- [ ] **数据量是否 > 100 条？**
  - ✅ 是 → 必须使用后端分页
  - ❌ 否 → 可以考虑前端分页

### 5.2 代码实现检查

- [ ] **分页总数来源**
  - ✅ 使用 `pagination.total`（后端返回）
  - ❌ 不使用 `filteredRooms.length`（前端数组长度）

- [ ] **表格数据来源**
  - ✅ 后端分页：直接使用 `rooms.value`（不切片）
  - ✅ 前端分页：使用 `filteredRooms.value.slice(start, end)`

- [ ] **翻页处理**
  - ✅ 后端分页：调用 `fetchRooms({ refresh: true, page, size })`
  - ✅ 前端分页：只改变 `currentPage.value`

- [ ] **搜索处理**
  - ✅ 后端搜索：调用 `fetchRooms({ q: keyword })`
  - ✅ 前端搜索：使用 `computed` 过滤（仅适用于前端分页）

- [ ] **每页大小改变**
  - ✅ 后端分页：重新请求 `fetchRooms({ size: newSize })`
  - ✅ 前端分页：只改变 `pageSize.value`

### 5.3 用户体验检查

- [ ] **总数显示是否正确？**
  - ✅ 显示后端返回的总数（如：2686）
  - ❌ 不显示当前页数据量（如：10）

- [ ] **翻页是否正常？**
  - ✅ 点击翻页能加载新数据
  - ❌ 翻页后数据不变

- [ ] **搜索是否正常？**
  - ✅ 搜索后总数更新
  - ✅ 搜索后能正常翻页

## 6. 最佳实践

### 6.1 Store 设计规范

**Store 应该存储**：
```typescript
state: () => ({
  items: [] as Item[],           // 当前页的数据
  pagination: {
    page: 1,                     // 当前页码
    size: 10,                    // 每页大小
    total: 0,                    // ✅ 后端返回的总数
    hasMore: false               // 是否有更多（可选）
  }
})
```

**fetchItems 方法应该**：
```typescript
async fetchItems(options: { 
  refresh?: boolean
  page?: number
  size?: number
  q?: string                    // 搜索关键词
  owner_only?: boolean          // 过滤条件
} = {}) {
  const params = {
    page: options.page || this.pagination.page,
    size: options.size || this.pagination.size,
    ...(options.q && { q: options.q }),
    ...(options.owner_only !== undefined && { owner_only: options.owner_only })
  }
  
  const response = await get('/items', params)
  
  if (response.data) {
    // ✅ 更新当前页数据
    if (options.refresh) {
      this.items = response.data.items || []
    } else {
      this.items.push(...(response.data.items || []))
    }
    
    // ✅ 更新总数（关键！）
    if (typeof response.data.total === 'number') {
      this.pagination.total = response.data.total
    }
    
    // ✅ 更新页码
    this.pagination.page = params.page
    this.pagination.size = params.size
  }
}
```

### 6.2 组件设计规范

**组件应该**：
1. ✅ 从 Store 获取 `items` 和 `pagination`
2. ✅ 使用 `pagination.total` 作为分页总数
3. ✅ 翻页/搜索时调用 Store 的 `fetchItems` 方法
4. ✅ 表格直接显示 `items`（后端分页）或切片后的数据（前端分页）

**组件不应该**：
1. ❌ 自己维护分页状态（应该使用 Store）
2. ❌ 使用前端数组长度作为分页总数（除非是前端分页）
3. ❌ 翻页时不重新请求后端（除非是前端分页）

### 6.3 错误处理

```typescript
// ✅ 正确：捕获错误并提示用户
try {
  await roomStore.fetchRooms({ refresh: true, page: 1 })
} catch (e: any) {
  ElMessage.error(e?.message || '加载失败')
}

// ❌ 错误：不处理错误，用户不知道发生了什么
await roomStore.fetchRooms({ refresh: true, page: 1 })
```

## 7. 常见问题 FAQ

### Q1: 后端返回了 `total`，但前端显示的总数不对？

**A**: 检查以下几点：
1. Store 是否正确保存了 `response.data.total`？
2. 组件是否使用了 `pagination.total` 而不是 `items.length`？
3. 是否有前端过滤影响了总数显示？（应该使用后端总数）

### Q2: 翻页后数据不变？

**A**: 检查以下几点：
1. `handlePageChange` 是否调用了 `fetchRooms`？
2. `fetchRooms` 是否传递了正确的 `page` 参数？
3. Store 的 `fetchRooms` 是否正确更新了 `items`？

### Q3: 搜索后总数不对？

**A**: 检查以下几点：
1. 搜索是否请求了后端？（如果后端支持搜索）
2. 后端搜索是否返回了正确的 `total`？
3. 是否使用了搜索后的 `total` 而不是原始 `total`？

### Q4: 什么时候用前端分页，什么时候用后端分页？

**A**: 
- **后端分页**：数据量大（>100条）、后端支持分页、需要实时数据
- **前端分页**：数据量小（<100条）、一次性加载所有数据、不需要实时更新

**推荐**：优先使用后端分页，除非有特殊需求。

## 8. 总结

### ✅ 正确做法

1. **识别分页类型**：后端返回 `total` → 使用后端分页
2. **使用后端总数**：`pagination.total` 而不是 `items.length`
3. **翻页请求后端**：每次翻页调用 `fetchItems({ page, size })`
4. **搜索请求后端**：如果后端支持，传递搜索参数

### ❌ 常见错误

1. ❌ 只加载第一页，却使用前端分页逻辑
2. ❌ 使用前端数组长度作为分页总数
3. ❌ 翻页时不重新请求后端
4. ❌ 混淆前端过滤和后端分页
