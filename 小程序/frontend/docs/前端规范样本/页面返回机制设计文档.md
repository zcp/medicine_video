## 一、设计概述

### 1.1 设计目标

为了提升用户体验，确保每个页面都能为用户提供清晰可见易懂的返回按钮，能够根据不同的情况返回到之前的页面、上一级页面或主页，同时避免返回空URL等错误。

### 1.2 适用场景

本返回机制适用于所有需要返回功能的页面，包括但不限于：

- **创建页面**：创建资源后返回列表页
- **详情页面**：查看资源详情后返回列表页或上一页
- **编辑页面**：编辑资源后返回详情页或列表页
- **子页面**：从父页面进入的子功能页面

### 1.3 技术栈

- **框架**: Vue 3 + TypeScript
- **路由**: uni-app H5 路由（使用 `uni.navigateTo`、`uni.navigateBack` 等API）
- **工具函数**: `src/utils/navigation.ts`

**⚠️ UI组件库要求**：
- **Element Plus 项目**：使用 `el-page-header` 组件实现返回按钮
- **uni-app + uni-ui 项目**：可以使用自定义返回按钮组件或 `uni.navigateBack` 按钮

**注意**：本文档中的页面返回按钮实现示例使用 Element Plus 的 `el-page-header` 组件。如果项目使用其他UI组件库，需要根据实际组件库调整实现方式。

## 二、设计原则

### 2.1 智能返回策略

返回机制采用三级回退策略，确保用户始终能够返回到有效页面：

1. **优先返回到来源页面**：如果来源页面有效，直接返回
2. **返回到上一级页面**：如果没有来源页面，尝试返回上一级
3. **返回到主页（兜底）**：如果上一级页面无效，跳转到指定的主页

### 2.2 统一实现方式

- ✅ 所有页面使用统一的返回工具函数
- ✅ 返回按钮位置统一（页面顶部）
  - **Element Plus 项目**：使用 `el-page-header` 组件
  - **uni-app + uni-ui 项目**：使用自定义返回按钮组件
- ✅ 返回按钮样式统一
- ✅ 返回逻辑可配置、可扩展

### 2.3 用户体验优先

- ✅ 返回按钮清晰可见
- ✅ 返回逻辑符合用户预期
- ✅ 避免返回空URL或无效页面
- ✅ 有未保存数据时提供确认提示

## 三、返回工具函数设计

### 3.1 文件位置

创建 `src/utils/navigation.ts`：

```typescript
/**
 * 页面导航工具函数
 * 提供统一的页面返回机制
 * 
 * @module utils/navigation
 */

/**
 * 获取来源页面URL
 * @returns 来源页面URL，如果没有则返回null
 */
export const getReferrerUrl = (): string | null => {
  try {
    // uni-app 环境下，可以通过 getCurrentPages() 获取页面栈
    const pages = getCurrentPages();
    if (pages.length > 1) {
      const prevPage = pages[pages.length - 2];
      if (prevPage && prevPage.route) {
        // 构建完整URL（包含查询参数）
        const queryString = prevPage.options
          ? '?' + Object.keys(prevPage.options)
              .map(key => `${key}=${encodeURIComponent(prevPage.options[key])}`)
              .join('&')
          : '';
        return `/${prevPage.route}${queryString}`;
      }
    }
  } catch (error) {
    console.warn('获取来源页面URL失败:', error);
  }
  return null;
};

/**
 * 智能返回函数
 * 
 * @param options 返回选项
 * @param options.fallbackUrl 如果无法返回上一页，则跳转到此URL（必填）
 * @param options.forceFallback 强制使用fallbackUrl，不尝试返回上一页（默认：false）
 * 
 * @example
 * // 基本使用：返回到专家列表页
 * smartNavigateBack({ fallbackUrl: '/pages/expert/ExpertList' });
 * 
 * // 强制跳转到指定页面
 * smartNavigateBack({ 
 *   fallbackUrl: '/pages/expert/ExpertList',
 *   forceFallback: true 
 * });
 */
export const smartNavigateBack = (options: {
  fallbackUrl: string;
  forceFallback?: boolean;
}): void => {
  const { fallbackUrl, forceFallback = false } = options;

  // 验证fallbackUrl
  if (!fallbackUrl || !fallbackUrl.trim()) {
    console.error('smartNavigateBack: fallbackUrl 不能为空');
    return;
  }

  // 如果强制使用fallback，直接跳转
  if (forceFallback) {
    try {
      uni.redirectTo({ url: fallbackUrl });
    } catch (error) {
      console.error('强制跳转失败:', error);
    }
    return;
  }

  // 尝试获取来源页面
  const referrerUrl = getReferrerUrl();

  // 如果有有效的来源页面，尝试返回
  if (referrerUrl && referrerUrl.trim() && !referrerUrl.includes('undefined')) {
    try {
      // 检查页面栈深度
      const pages = getCurrentPages();
      if (pages.length > 1) {
        uni.navigateBack({ delta: 1 });
        return;
      }
    } catch (error) {
      console.warn('返回上一页失败，使用fallback:', error);
    }
  }

  // 如果无法返回上一页，使用fallback
  try {
    uni.redirectTo({ url: fallbackUrl });
  } catch (error) {
    console.error('fallback跳转失败:', error);
  }
};

/**
 * 带确认的返回函数
 * 
 * 适用于编辑页面等有未保存数据的场景
 * 
 * @param options 返回选项
 * @param options.message 确认提示信息（默认：'确定要返回吗？未保存的数据将丢失。'）
 * @param options.title 确认对话框标题（默认：'确认返回'）
 * @param options.fallbackUrl 如果无法返回上一页，则跳转到此URL（必填）
 * 
 * @example
 * // 基本使用：带确认提示返回
 * await confirmNavigateBack({
 *   fallbackUrl: '/pages/expert/ExpertList',
 *   message: '确定要返回吗？未保存的修改将丢失。'
 * });
 */
export const confirmNavigateBack = async (options: {
  message?: string;
  title?: string;
  fallbackUrl: string;
}): Promise<void> => {
  const { 
    message = '确定要返回吗？未保存的数据将丢失。', 
    title = '确认返回',
    fallbackUrl 
  } = options;

  // 验证fallbackUrl
  if (!fallbackUrl || !fallbackUrl.trim()) {
    console.error('confirmNavigateBack: fallbackUrl 不能为空');
    return;
  }

  try {
    // 动态导入确认对话框组件
    // Element Plus 项目：使用 ElMessageBox
    // uni-app 项目：使用 uni.showModal
    // #ifdef H5
    // 检查是否使用 Element Plus
    if (typeof window !== 'undefined' && (window as any).ElementPlus) {
      const { ElMessageBox } = await import('element-plus');
      await ElMessageBox.confirm(message, title, {
        confirmButtonText: '确定',
        cancelButtonText: '取消',
        type: 'warning',
      });
    } else {
      // uni-app 项目使用 uni.showModal
      await new Promise<void>((resolve, reject) => {
        uni.showModal({
          title,
          content: message,
          confirmText: '确定',
          cancelText: '取消',
          success: (res) => {
            if (res.confirm) {
              resolve();
            } else {
              reject('cancel');
            }
          },
          fail: (err) => reject(err),
        });
      });
    }
    // #endif
    
    // #ifndef H5
    // 非H5环境使用 uni.showModal
    await new Promise<void>((resolve, reject) => {
      uni.showModal({
        title,
        content: message,
        confirmText: '确定',
        cancelText: '取消',
        success: (res) => {
          if (res.confirm) {
            resolve();
          } else {
            reject('cancel');
          }
        },
        fail: (err) => reject(err),
      });
    });
    // #endif
    
    // 用户确认后执行返回
    smartNavigateBack({ fallbackUrl });
  } catch (error) {
    // 用户取消，不执行返回
    if (error === 'cancel') {
      return;
    }
    console.error('确认返回失败:', error);
  }
};
```

### 3.2 函数说明

#### 3.2.1 `getReferrerUrl()`

**功能**：获取来源页面URL

**返回值**：
- `string | null`：来源页面URL，如果没有则返回null

**使用场景**：内部使用，一般不需要直接调用

#### 3.2.2 `smartNavigateBack(options)`

**功能**：智能返回函数，自动判断返回方式

**参数**：
- `options.fallbackUrl`（必填）：兜底URL，如果无法返回上一页，则跳转到此URL
- `options.forceFallback`（可选）：是否强制使用fallbackUrl，默认false

**返回值**：`void`

**使用场景**：
- 创建页面保存成功后返回
- 详情页面返回
- 普通编辑页面返回（无未保存数据）

#### 3.2.3 `confirmNavigateBack(options)`

**功能**：带确认的返回函数

**参数**：
- `options.message`（可选）：确认提示信息
- `options.title`（可选）：确认对话框标题
- `options.fallbackUrl`（必填）：兜底URL

**返回值**：`Promise<void>`

**使用场景**：
- 编辑页面有未保存数据时返回
- 表单页面有输入但未提交时返回

### 4.4 编辑页

#### 4.4.1 Element Plus 项目实现

**实现方式**：使用 `el-page-header` 组件实现返回按钮，支持带确认的返回

```vue
<template>
  <AdminLayout>
    <el-page-header @back="handleBack" title="返回">
      <template #content>
        <span class="page-header-title">编辑专家</span>
      </template>
      <template #extra>

        <el-button type="primary" :loading="saving" @click="handleSave">

        </el-button>

    <div class="page-container">
      <!-- ... -->
    </div>
  </AdminLayout>

<script setup lang="ts">
import { ref } from 'vue';
import { confirmNavigateBack, smartNavigateBack } from '@/utils/navigation';

// 跟踪是否有未保存的更改
const hasUnsavedChanges = ref(false);

const handleBack = () => {
  if (hasUnsavedChanges.value) {
    // 有未保存数据时，显示确认对话框
    confirmNavigateBack({
      message: '确定要返回吗？未保存的修改将丢失。',
      title: '确认返回',
      fallbackUrl: '/pages/expert/ExpertList', // 根据实际模块修改
    });
  } else {
    // 没有未保存数据时，直接返回
    smartNavigateBack({ 
      fallbackUrl: '/pages/expert/ExpertList' // 根据实际模块修改
    });
  }
};

  handleBack();
};

const handleSave = async () => {
  // 保存逻辑
  hasUnsavedChanges.value = false; // 保存成功后重置标记
  // 保存成功后返回详情页或列表页
  const id = getCurrentPageId();
  if (id) {
    smartNavigateBack({ 
      fallbackUrl: `/pages/expert/ExpertDetail?id=${id}` 
    });
  } else {
    smartNavigateBack({ 
      fallbackUrl: '/pages/expert/ExpertList' 
    });
  }
};
</script>
```

## 五、使用规范

### 5.1 所有子页面必须实现返回功能

- ✅ 创建页、详情页、编辑页都必须有返回按钮
- ✅ 返回按钮位置统一在页面顶部
  - **Element Plus 项目**：使用 `el-page-header` 组件
  - **uni-app + uni-ui 项目**：使用自定义返回按钮组件
- ✅ 返回按钮样式统一

### 5.2 返回逻辑优先级

1. **优先使用 `smartNavigateBack`**：适用于大多数场景
2. **有未保存数据时使用 `confirmNavigateBack`**：适用于编辑页等场景
3. **所有返回都必须提供 `fallbackUrl`**：作为兜底，避免返回空URL

### 5.3 fallbackUrl 设置规范

**原则**：`fallbackUrl` 应该是该模块的主页或列表页

**示例**：
- 专家管理模块：`/pages/expert/ExpertList`
- 直播间管理模块：`/pages/room/new/RoomList`
- 专题管理模块：`/pages/topic/TopicList`

### 5.4 未保存数据检测

**推荐实现方式**：

```typescript
// 方式1：使用响应式变量跟踪
const hasUnsavedChanges = ref(false);

// 监听表单变化
watch(formData, () => {
  hasUnsavedChanges.value = true;
}, { deep: true });

// 保存成功后重置
const handleSave = async () => {
  // ... 保存逻辑
  hasUnsavedChanges.value = false;
};
```

### 5.5 保存成功后返回

**推荐实现方式**：

```typescript
const handleSave = async () => {
  try {
    // 保存逻辑
    await saveData();
    ElMessage.success('保存成功');
    
    // 延迟返回，让用户看到成功提示
    setTimeout(() => {
      // 如果有ID，返回详情页；否则返回列表页
      const id = getCurrentPageId();
      if (id) {
        smartNavigateBack({ 
          fallbackUrl: `/pages/module/Detail?id=${id}` 
        });
      } else {
        smartNavigateBack({ 
          fallbackUrl: '/pages/module/List' 
        });
      }
    }, 1000);
  } catch (error) {
    ElMessage.error('保存失败');
  }
};
```

## 六、测试要点

### 6.1 正常返回测试

1. **从列表页进入创建页，返回应该回到列表页**
2. **从列表页进入详情页，返回应该回到列表页**
3. **从详情页进入编辑页，返回应该回到详情页**

### 6.2 异常返回测试

1. **直接访问创建页（无来源页面），返回应该跳转到列表页**
2. **页面栈为空时，返回应该跳转到列表页**
3. **返回URL无效时，应该使用fallback跳转**
4. **fallbackUrl为空时，应该输出错误日志，不执行跳转**

### 6.3 带确认返回测试

1. **编辑页有未保存数据时，点击返回应该弹出确认对话框**
2. **确认后应该返回，取消后应该停留在当前页**
3. **确认对话框的提示信息应该清晰易懂**

### 6.4 保存后返回测试

1. **创建成功后应该返回列表页**
2. **编辑成功后应该返回详情页**
3. **返回前应该显示成功提示**
4. **返回延迟时间合理（建议1秒）**

## 八、错误处理

### 8.1 返回函数错误处理

返回函数内部已经处理了各种异常情况：

- ✅ 页面栈为空时使用fallback
- ✅ 获取来源页面失败时使用fallback
- ✅ 返回上一页失败时使用fallback
- ✅ fallbackUrl为空时输出错误日志

### 8.2 常见错误及处理

#### 错误1：返回空URL

**原因**：fallbackUrl未设置或为空

**处理**：函数内部已校验，会输出错误日志

**预防**：确保所有调用都提供有效的fallbackUrl

#### 错误2：返回无效页面

**原因**：fallbackUrl指向不存在的页面

**处理**：uni-app会显示404，用户可以使用浏览器返回按钮

**预防**：确保fallbackUrl指向有效的页面

#### 错误3：页面栈异常

**原因**：页面栈被意外清空或破坏

**处理**：函数内部已处理，会使用fallback跳转

**预防**：避免手动清空页面栈

### 8.3 调试建议

1. **使用浏览器控制台查看日志**
2. **检查页面栈深度**：`console.log(getCurrentPages().length)`
3. **检查来源页面URL**：`console.log(getReferrerUrl())`
4. **验证fallbackUrl有效性**

## 九、扩展说明

### 9.1 与其他导航方式兼容

本返回机制与uni-app的其他导航方式完全兼容：

- ✅ `uni.navigateTo`：正常导航
- ✅ `uni.redirectTo`：页面替换，不影响返回逻辑
- ✅ `uni.switchTab`：切换到tabBar页面
- ✅ `uni.reLaunch`：重新启动应用

### 9.2 自定义返回逻辑

如果某个页面需要特殊的返回逻辑，可以：

1. **直接使用 `smartNavigateBack`，设置 `forceFallback: true`**
2. **自定义返回函数，但仍使用本机制作为兜底**

```typescript
const handleCustomBack = () => {
  // 自定义逻辑
  if (someCondition) {
    // 执行自定义操作
  } else {
    // 使用标准返回机制
    smartNavigateBack({ fallbackUrl: '/pages/module/List' });
  }
};
```

### 9.3 性能考虑

- ✅ 返回函数使用轻量级实现
- ✅ `confirmNavigateBack` 使用动态导入，避免未使用时加载
- ✅ 避免在返回函数中执行耗时操作
