## 📋 适用范围

### 技术栈要求

本规范适用于使用 **uni-app 路由系统** 的前端项目：

- ✅ **uni-app + Vue3** 项目（使用 uni-ui 或 Element Plus）
- ✅ **Vue3 + Element Plus + uni-app H5** 项目（使用 uni-app 路由）

### 核心依赖

- ✅ **路由API**：`uni.navigateTo`、`uni.redirectTo`、`getCurrentPages()` 等 uni-app 路由API
- ✅ **页面配置**：`pages.json` 配置文件
- ✅ **路由系统**：uni-app H5 路由系统

### 不适用场景

- ❌ 纯 Vue Router 项目（不使用 uni-app 路由）
- ❌ React Router 项目
- ❌ 其他非 uni-app 路由系统

## 登录与跨应用跳转设计说明（vzan\_simul\_frontend ↔ user\_service\_frontend）

### 一、整体目标与示例

- **总体目标**
  - **管理类页面**：访问 **直播前端（vzan\_simul\_frontend / live-center）** 的后台 / 管理页面时，必须在「已登录」前提下才能访问。
  - **直播间观看页（LiveView）**：
    - 对于 **public 直播间**：允许匿名或已登录用户直接访问、观看视频与留言列表；
    - 对于 **private 直播间**：仍按权限设计，需登录且具备权限方可访问（由后端根据 `is_private` + 用户身份进行可见性校验）；
    - 在同一页面内，**发送留言 / 互动操作必须登录**，未登录时触发统一登录跳转，登录成功后自动回到原房间。
  - **专题展示页（TopicDisplay）**：
    - 对于 **published 状态的专题**：允许匿名或已登录用户直接访问、浏览专题内容；
    - 对于 **draft/archived 状态的专题**：仍按权限设计，需登录且具备权限方可访问（由后端根据 `status` + 用户身份进行可见性校验，返回 404 伪装）；
    - 在同一页面内，**互动操作必须登录**，未登录时触发统一登录跳转，登录成功后自动回到原专题。
  - 未登录访问受保护页面时，统一跳转到 **用户前端（user\_service\_frontend）** 的登录页进行认证。
  - 登录成功后，根据最初访问的路径，自动跳回直播前端对应页面。
  - 方案同时适用于本地开发（`localhost:517x`）和远程部署（自定义域名）。

**📌 关于本地开发环境的说明**：
- **本地开发环境**（`USE_LOCAL_DEV: true`）：
  - `vite.config.ts` 中 `base = '/'`（通过端口区分不同前端，不需要子路径）
  - **通过端口区分不同前端模块**：
    - `localhost:5175` → `vzan_simul_frontend`（直播前端）
    - `localhost:5174` → `user_service_frontend`（用户前端）
  - **本地开发不需要 `/live-center` 子路径**，因为通过端口已经区分了不同模块
  - callback URL：`http://localhost:5175/#/pages/auth/callback`（**不包含** `/live-center`）
- **生产环境**（`USE_LOCAL_DEV: false`）：
  - `vite.config.ts` 中 `base = '/live-center/'`（部署在子路径下）
  - callback URL：`https://mp.dayilive.com/live-center/#/pages/auth/callback`（**包含** `/live-center`）

- **具体示例（完整链路）**

  **示例 1：管理页面访问（需要登录）**
  1. 在浏览器地址栏输入直播前端房间列表页：

     `http://localhost:5175/#/pages/room/new/RoomList`

  2. 系统检查到当前未登录，自动重定向到用户前端登录页：

     `http://localhost:5174/#/pages/auth/login?external_callback=true&origin=localhost:5175&redirect=/pages/room/new/RoomList`

  3. 在 `http://localhost:5174/#/pages/auth/login` 成功登录后，用户前端将浏览器重定向回直播前端的回调页：

     `http://localhost:5175/#/pages/auth/callback?token=...&redirect=/pages/room/new/RoomList`

  4. 直播前端的回调页读取 `token`、写入登录状态，并按照 `redirect` 跳转到最终目标页：

     `http://localhost:5175/#/pages/room/new/RoomList`

  **示例 2：公共页面访问（可选登录）**
  1. 匿名用户直接访问 published 专题展示页：

     `http://localhost:5175/#/pages/topic/TopicDisplay?topic_id=aa46751a-82cc-4043-bb55-e912aaf0e97b`

  2. 路由拦截允许匿名访问 TopicDisplay 页面，页面正常加载。
  3. 页面向后端请求专题数据，后端根据专题状态（published/draft/archived）和用户权限返回数据：
     - **published 专题**：返回专题数据，前端正常显示内容 ✅
     - **draft/archived 专题（匿名用户）**：后端返回 404（伪装），前端显示"专题不存在或已被删除"
  4. 如果用户在页面内执行互动操作（需要登录），会触发登录跳转流程（同示例 1）。

## 二、URL 与“拦截 / 跳转 / 验证”总览

### 1. 直播前端：哪些 URL 需要拦截

- **需要统一登录校验的 URL（H5）**
  - 除“允许匿名访问的公共页面”外，所有类似下面的路径都需要拦截：
    - `http://localhost:5175/#/pages/room/new/RoomList`
    - `http://localhost:5175/#/pages/room/new/RoomCreate`
    - `http://localhost:5175/#/pages/topic/TopicList`
    - ……（`/#/pages/**` 下的业务/管理页面）
- **允许匿名访问的公共页面（可选登录）**
  - `http://localhost:5175/#/pages/live/new/LiveView?room_id=...`：  
    - 作为直播间主页（观看页），public 房间支持匿名直接进入；  
    - private 房间仍由后端根据 `is_private` + 用户身份进行可见性判断；  
    - 页面中的"发言 / 互动"操作会在未登录时触发统一登录跳转。
  - `http://localhost:5175/#/pages/topic/TopicDisplay?topic_id=...`：  
    - 作为专题主页（展示页），published 状态的专题支持匿名直接进入；  
    - draft/archived 状态的专题仍由后端根据 `status` + 用户身份进行可见性判断（返回 404 伪装）；  
    - 页面中的"互动"操作会在未登录时触发统一登录跳转。
- **不拦截的认证页面（避免死循环）**
  - `http://localhost:5175/#/pages/auth/login`
  - `http://localhost:5175/#/pages/auth/callback`

### 2. 直播前端：拦截在什么时机发生

- **应用启动 / 刷新时**
  - 文件：`src/App.vue`
  - 逻辑：
    - `onLaunch` 中：
      - 先 `authStore.initializeAuth()` 从本地恢复 token。
      - H5 下通过 `authStore.ensureAuthenticated()` 对当前 URL 做一次登录校验。
      - 如当前 URL 的 `hash` 含 `/pages/auth/login` 或 `/pages/auth/callback`，则 **跳过校验**。
    - `onShow` 中：
      - H5 下再次调用 `authStore.ensureAuthenticated()`，但同样跳过认证相关页面。

- **请求返回 401（未授权）时**
  - 文件：`src/utils/request.ts`
  - 逻辑（简化）：
    - 当 `res.statusCode === 401`：
      - 从 `getCurrentPages()` 读取当前页的 `route`（如 `pages/room/new/RoomList`）。
      - 规范成 `/pages/room/new/RoomList`。
      - 调用 `authStore.forceReauth(normalizedPath)` 触发登录流程。
    - **注意**：对于 LiveView 和 TopicDisplay 页面，后端可能返回 404（伪装）而非 401，此时由页面自行处理错误显示，不触发登录跳转。这是为了：
      - **防止枚举攻击**：隐藏 private 资源的存在性
      - **保持一致性**：private 资源不存在和无权限访问都返回 404

### 3. 直播前端：如何跳转到用户前端登录页

- **登录地址来源（统一配置）**
  - 文件：`src/constants/api.ts`
  - 从运行时配置中读取：
    - `getLoginUrl()`：
      - 返回 `window.__ENV.VITE_LOGIN_URL`；
      - 默认值为：`http://localhost:5174/#/pages/auth/login`。

- **构造最终登录 URL 的参数（vzan → user\_service）**
  - 在 `authStore.forceReauth(targetPath)` 和首页兜底逻辑中统一拼接：
    - **基础 URL**：`const loginUrlValue = getLoginUrl()`
    - **query 参数**：
      - `external_callback=true`：标记为“外部应用登录”。
      - `origin=<当前直播前端域名>`：如 `localhost:5175`。
      - `redirect=<targetPath>`：如 `/pages/room/new/RoomList`。
      - `callback=<可选>`：显式回调地址（当前实现中会构造并传递，指向 vzan 自己的 `/pages/auth/callback`）。
        - 如果传递了 `callback` 参数，用户前端会使用该地址进行回跳
        - 如果未传递，用户前端会根据 `origin` 和 `app_path` 自动构造回调地址

- **典型最终登录 URL（本地）**

  ```text
  http://localhost:5174/#/pages/auth/login
    ?external_callback=true
    &origin=localhost:5175
    &redirect=/pages/room/new/RoomList
  ```

### 4. 用户前端：如何识别外部登录并回跳（同时兼容本地与远程）

- **参数解析与识别**
  - 文件：`user_service_frontend/src/pages/auth/login.vue`
  - 函数 `getUrlParams()`：
    - 同时支持：
      - `.../pages/auth/login?external_callback=...`（query 在 `#` 前）
      - `.../#/pages/auth/login?external_callback=...`（query 写在 `hash` 中）
    - 解析字段：
      - `external_callback`：是否外部登录。
      - `origin`：外部应用域名（如本地 `localhost:5175`，远程 `mp.dayilive.com`）。
      - `app_path`：外部应用路径前缀（如直播前端的 `/live-center`，或 download-center 的 `/download-center` 等）。
      - `redirect`：内部要回到的路径（如 `/pages/room/new/RoomList`）。

- **白名单校验（哪些 origin 被信任）** ⚠️ **注意：这是用户前端的白名单，与直播前端的白名单不同**
  - **用途**：验证外部应用（如 vzan）是否可以调用用户前端的登录服务
  - **位置**：在 `handleExternalCallback()` 内的 `allowedOrigins`（硬编码或从配置读取）
  - **本地开发允许的 origin**：
    - `localhost:3000`
    - `localhost:3001`
    - `localhost:5175` ✅（vzan 本地）
    - `127.0.0.1:3000`
    - `127.0.0.1:3001`
    - `127.0.0.1:5175` ✅（vzan 本地）
  - **生产环境示例（需根据实际补全）**：
    - `124.220.235.226`
    - `mp.dayilive.com`
    - 以及未来的 `live-center` 域名等。
  
  **⚠️ 重要说明：**
  - **用户前端的白名单**（此处）：用于验证外部应用是否可以调用登录服务
  - **直播前端的白名单**（`config.js` 中的 `VITE_ALLOWED_ORIGINS`）：用于验证 callback 请求的来源是否可信
  - **两者用途不同，都需要配置**

- **两种回跳模式**

  1. **uni-app H5 模式（当前 vzan 所用，本地 + 远程）**
     - 条件：`app_path` 为空或为直播前端路径（例如 `/live-center`）。
     - 行为：构造回跳 URL：
       - 通用形式：  
         `http(s)://{origin}{app_path}/#/pages/auth/callback?token=...&redirect=...`
       - **本地开发示例：**
         - `origin = 'localhost:5175'`
         - `app_path = ''`（不传或为空）
         - 回跳地址：  
           `http://localhost:5175/#/pages/auth/callback?token=...&redirect=/pages/room/new/RoomList`
         - **注意**：本地开发通过端口区分不同前端（5175 vs 5174），不需要 `/live-center` 子路径
       - **远程部署示例：**
         - 直播前端入口：`https://mp.dayilive.com/live-center/#/pages/...`
         - `origin = 'mp.dayilive.com'`
         - `app_path = '/live-center'`
         - 回跳地址：  
           `https://mp.dayilive.com/live-center/#/pages/auth/callback?token=...&redirect=/pages/room/new/RoomList`
         - **注意**：生产环境部署在 `/live-center` 子路径下，需要包含 `/live-center`
       - 登录成功后，通过 `window.location.href = callbackUrl` 跳转回 vzan，后续由 vzan 的 `callback.vue` 负责写入 token 并根据 `redirect` 落到具体业务页。

  2. **simple-callback + app_path 模式（保留历史逻辑）**
     - 条件：`app_path` 为 download-center 等应用路径（如 `/download-center`）。
     - 行为：
       - 构造：  
         `http(s)://{origin}{app_path}/simple-callback.html?token=...`
       - 用于 download-center 或其他已接入 simple-callback 的系统。

### 5. 直播前端：回调页如何验证与最终跳转

- **文件：**`src/pages/auth/callback.vue`
- **验证与处理步骤（安全验证，P0 优先级）：**
  1. **验证请求来源（Origin 白名单）** ⚠️ **必须实现**：
     - 从 `config.js` 读取 `VITE_ALLOWED_ORIGINS` 配置（逗号分隔的域名列表）
     - 获取当前域名：`window.location.hostname + (window.location.port ? ':' + window.location.port : '')`
     - 验证当前域名是否在白名单中
     - **如果不在白名单中，拒绝处理并抛出错误**（防止 CSRF 攻击）
  
  2. 从当前 uni 页面 `options` + `window.location.search` 中读取 `token`、`redirect`。
  
  3. **验证 token** ⚠️ **必须实现**：
     - `token` 是否存在
     - `token` 是否是 JWT 格式（通过 `token.split('.').length === 3` 验证）
     - `token` 是否过期（解析 payload 中的 `exp` 字段，与当前时间比较）
     - 使用 `validateToken()` 工具函数进行完整验证（详见《环境配置与CORS编程规范.md》）
  
  4. **验证并清理 redirect 参数** ⚠️ **必须实现**（防止开放重定向攻击）：
     - 使用 `validateRedirectPath()` 工具函数验证 redirect 参数
     - 只允许相对路径（必须以 `/pages/` 开头）
     - 不允许外部 URL（包含 `://`）
     - 不允许危险字符（`javascript:`, `data:`, `<` 等）
     - 不允许路径遍历（`../`, `..\\` 等）
     - **如果验证失败，使用默认路径** `/pages/room/new/RoomList`
  
  5. 若存在 `redirect` 且验证通过：
     - 调用 `authStore.setRedirectPath(safeRedirect)`（使用验证后的安全路径）。
  
  6. 写入 token：
     - `authStore.setToken(token)`；
     - `authStore.parseUserFromToken(token)`。
  
  7. 1.5 秒后执行：
     - `authStore.handleAuthRedirect()`：
       - 若有 `redirectPath`（且不为 `/pages/auth/login`），跳转到该路径。
       - 否则跳到默认页 `/pages/room/new/RoomList`。

- **安全工具函数**（应在 `src/utils/auth.ts` 中实现）：
  - `validateToken(token: string)`: 验证 token 格式和过期时间
  - `validateRedirectPath(path: string)`: 验证并清理 redirect 参数
  - 详细实现请参考《环境配置与CORS编程规范.md》第 6 章

## 三、各文件修改要点（按项目）

### 1. 直播前端（vzan\_simul\_frontend）

- **`public/config.js`**
  - **本地开发 (`LOCAL_DEV`) 关键字段：**
    - `VITE_BASE_API_URL: 'http://localhost:8000/api/v1'`
    - `VITE_AUTH_API_URL: 'http://localhost:8002/'`
    - `VITE_LOGIN_URL: 'http://localhost:5174/#/pages/auth/login'`  
      - **注意：H5 使用 hash 路由，这里必须带上 `#/` 才能直接进入登录页。**
    - `VITE_APP_BASE_PATH: '/live-center'`
    - `VITE_ALLOWED_ORIGINS: 'localhost:5175,127.0.0.1:5175,localhost:5174,127.0.0.1:5174'` ⚠️ **安全配置：用于 callback 验证（P0 优先级）**
      - 允许的来源域名列表（逗号分隔），用于验证 callback 请求的来源是否可信
      - 必须包含当前应用的域名（`localhost:5175`）和用户前端的域名（`localhost:5174`）
  - **生产环境 (`PRODUCTION`) 示例：**
    - `VITE_BASE_API_URL: 'https://mp.dayilive.com/api/core/'`
    - `VITE_AUTH_API_URL: 'https://mp.dayilive.com/api/users/'`
    - `VITE_LOGIN_URL: 'https://mp.dayilive.com/#/pages/auth/login'`  
      （用户前端部署在根路径，登录页不带 `/live-center`）
    - `VITE_APP_BASE_PATH: '/live-center'`  
      （直播前端自身部署在 `/live-center` 子路径下）
    - `VITE_ALLOWED_ORIGINS: 'mp.dayilive.com,www.mp.dayilive.com'` ⚠️ **安全配置：用于 callback 验证（P0 优先级）**
      - 生产环境只允许具体的生产域名，不要使用通配符
      - 必须包含当前应用的域名

- **`src/constants/api.ts`**
  - `getEnv()`：优先 `window.__ENV`，回退 `import.meta.env`，最后默认值。
  - **核心导出：**
    - `BASE_API_URL` / `AUTH_API_URL` 从 `VITE_BASE_API_URL` / `VITE_AUTH_API_URL` 读取。
    - `getLoginUrl()`：从 `VITE_LOGIN_URL` 读取，默认 `http://localhost:5174/#/pages/auth/login`。
    - `LOGIN_URL = getLoginUrl()` 仅为兼容常量形式。

- **`src/store/auth.ts`**
  - 删除所有“模拟 JWT 生成”的开发用代码。
  - **`forceReauth(targetPath)`：**
    - 清掉当前登录状态（token、user 等）。
    - `setRedirectPath(targetPath)` 保存当前要回到的页面。
    - H5 平台：
      - 获取 `loginUrlValue = getLoginUrl()`。
      - 计算当前域名 `originDomain` 与回调地址 `callbackUrl`（指向 vzan 自己的 `/pages/auth/callback`）。
      - 根据运行时配置判断是否为本地开发：
        - **本地开发**：`USE_LOCAL_DEV = true`
        - **生产环境**：`USE_LOCAL_DEV = false`
        - **注意**：统一使用 `USE_LOCAL_DEV` 判断环境，不要使用 `VITE_APP_ENV`（详见《环境配置与CORS编程规范.md》）
        - ⚠️ **重要**：使用 `isLocalDev()` 工具函数，该函数**必须包含 fallback 逻辑**（根据 `pathname` 判断），防止 `config.js` 未加载时返回错误值
      - 构造基础登录 URL：  
        `loginUrlValue + '?external_callback=true&origin=' + originDomain + '&callback=' + callbackUrl + '&redirect=' + targetPath`
      - **仅在远程环境下**（`!isLocalDev()`），额外附加 `&app_path=/live-center`：
        - 这里的 `/live-center` 来自 `APP_BASE_PATH = window.__ENV.VITE_APP_BASE_PATH`
        - **本地开发环境不需要** `app_path`，因为通过端口区分不同前端（5175 vs 5174）
      - 最终通过 `window.location.href = loginUrl` 跳转到用户前端登录页。

**📌 关于本地开发环境的路径说明**：
- **本地开发环境**（`USE_LOCAL_DEV: true`）：
  - `vite.config.ts` 中 `base = '/'`（通过端口区分不同前端，不需要子路径）
  - 端口区分：`localhost:5175` → `vzan_simul_frontend`，`localhost:5174` → `user_service_frontend`
  - callback URL：`http://localhost:5175/#/pages/auth/callback`（**不包含** `/live-center`）
  - 不需要传递 `app_path` 参数
- **生产环境**（`USE_LOCAL_DEV: false`）：
  - `vite.config.ts` 中 `base = '/live-center/'`（部署在子路径下）
  - callback URL：`https://mp.dayilive.com/live-center/#/pages/auth/callback`（**包含** `/live-center`）
  - 需要传递 `app_path=/live-center` 参数
  - **`handleAuthRedirect()`：**
    - 若存在 `redirectPath` 且不为 `/pages/auth/login`：
      - `uni.navigateTo({ url: redirectPath })`。
    - 否则：
      - `uni.navigateTo({ url: '/pages/room/new/RoomList' })`。
  - **`ensureAuthenticated(targetPath?)`：**
    - 仅在 H5 平台启用。
    - 若未传 `targetPath`，从 `getCurrentPages()` 推断当前 `route`，规范成 `/pages/...`。
    - 对 `/pages/auth/login` 和 `/pages/auth/callback` **直接返回 true**，不拦截。
    - 对直播间观看页 `/pages/live/new/LiveView` **也直接返回 true**：
      - 作为 public 直播间主页，允许匿名访问页面本身；
      - 登录状态仅影响是否能发言、是否能访问 private 房间等逻辑；
    - 对专题展示页 `/pages/topic/TopicDisplay` **也直接返回 true**：
      - 作为 published 专题主页，允许匿名访问页面本身；
      - 登录状态仅影响是否能访问 draft/archived 专题等逻辑；
    - 其他路径：
      - 若 `isAuthenticated` 且 `token` 未过期 → 返回 true；
      - 否则 → 调用 `forceReauth(path)` 并返回 false。

- **`src/utils/request.ts`**
  - 在 `res.statusCode === 401` 时：
    - 获取 `getCurrentPages()` 最后一页 `route`；
    - 规范成 `/pages/...`；
    - 调用 `authStore.forceReauth(normalizedPath)`。
  - **注意**：对于 LiveView 和 TopicDisplay 页面，后端可能返回 404（伪装）而非 401，此时由页面自行处理错误显示，不触发登录跳转。
  - 其余请求与错误处理逻辑保持不变。

- **`src/pages/index/index.vue`**
  - 在 `onLoad` 时：
    - 若未登录：
      - 设置 `targetPath = '/pages/room/new/RoomList'`；
      - 保存为重定向路径；
      - 构造登录 URL 并跳转到用户前端登录页（同 `forceReauth`）。

- **`src/pages/auth/callback.vue`**
  - 参见前文"回调页如何验证与最终跳转"。

- **`src/pages/topic/TopicDisplay.vue`**
  - `onLoad` 中：**不进行登录检查**，允许匿名访问页面。
  - 页面加载后，通过 `loadTopic()` 向后端请求专题数据。
  - 后端根据专题状态（published/draft/archived）和用户权限返回数据或 404（伪装）：
    - **published 专题**：所有人可以访问，返回数据 ✅
    - **draft/archived 专题（匿名用户）**：返回 404（伪装），前端显示"专题不存在或已被删除" ✅
    - **draft/archived 专题（已登录用户）**：管理员和创建者可以访问，其他人返回 404 ✅

- **`src/App.vue`**
  - `onLaunch`：
    - 初始化认证状态；
    - 对非认证页面执行 `ensureAuthenticated()`。
  - `onShow`：
    - 对非认证页面再次执行 `ensureAuthenticated()`，避免后台切换后状态不一致。

### 2. 用户前端（user\_service\_frontend）

- **`public/config.js`**
  - 与 vzan 一致采用 `config.js` 运行时配置，关键是 `VITE_LOGIN_URL` 配置为自身登录页（含 `#/`）。
- **`src/pages/auth/login.vue`**
  - 改造 `getUrlParams()`：支持从 `search` 和 `hash` 中读取参数。
  - 扩展 `allowedOrigins`，加入 `localhost:5175`、`127.0.0.1:5175`。
  - `handleExternalCallback()` 中增加“简化回调模式”：
    - 使用 `origin + '/#/pages/auth/callback?token=...&redirect=...'` 直接回跳到外部应用（vzan）。
  - 原有 `simple-callback.html + app_path` 流程保留，用于 download-center / 生产环境。

## 六、配置安全性说明 ⚠️ **重要**

### 6.1 前端配置的公开性

**重要说明**：所有前端配置都会暴露在浏览器中，用户可以通过浏览器开发者工具查看到。

**原因**：
- 前端代码都会下载到用户的浏览器
- 前端代码都在用户的浏览器中执行
- 用户可以通过浏览器开发者工具查看所有代码

**无法避免**：这是前端代码的本质，无法隐藏。

**暴露方式**：

1. **运行时配置（config.js）**：
   - 用户可以直接访问 `https://your-domain.com/config.js`
   - 或在浏览器 Console 中输入 `window.__APP_CONFIG__`
   - ✅ **可以看到所有配置值**

2. **构建时注入（.env 文件）**：
   - 配置值在构建时被硬编码到 JavaScript 代码中
   - 用户可以在浏览器开发者工具的 Sources 标签中查看
   - ✅ **可以看到所有配置值**

### 6.2 可以暴露的配置 ✅

以下配置可以暴露在浏览器中：

1. **API 地址**
   ```javascript
   VITE_BASE_API_URL: 'https://mp.dayilive.com/api/core/'
   VITE_AUTH_API_URL: 'https://mp.dayilive.com/api/users/'
   ```
   - ✅ 可以暴露：API 地址通常是公开的

2. **前端 URL**
   ```javascript
   VITE_LOGIN_URL: 'https://mp.dayilive.com/#/pages/auth/login'
   VITE_FRONTEND_USER_URL: 'https://mp.dayilive.com'
   ```
   - ✅ 可以暴露：前端 URL 本身就是公开的

3. **应用标题**
   ```javascript
   VITE_APP_TITLE: '直播SaaS平台'
   ```
   - ✅ 可以暴露：应用标题是公开信息

4. **功能开关**
   ```javascript
   VITE_DEBUG: false
   ```
   - ✅ 可以暴露：功能开关通常可以暴露

5. **应用路径**
   ```javascript
   VITE_APP_BASE_PATH: '/live-center'
   ```
   - ✅ 可以暴露：应用路径是公开信息

6. **安全配置（白名单）**
   ```javascript
   VITE_ALLOWED_ORIGINS: 'mp.dayilive.com,www.mp.dayilive.com'
   ```
   - ✅ 可以暴露：白名单配置可以暴露（用于验证，不是敏感信息）

### 6.3 不能暴露的配置 ❌

以下配置**绝对不能**暴露在浏览器中：

1. **API 密钥 / Secret Key**
   ```javascript
   // ❌ 错误：绝对不能暴露
   VITE_API_SECRET: 'stream_example_1234567890abcdef'
   VITE_STRIPE_SECRET_KEY: 'sk_test_...'
   ```

2. **数据库连接字符串**
   ```javascript
   // ❌ 错误：绝对不能暴露
   VITE_DATABASE_URL: 'postgresql://user:password@host:5432/dbname'
   ```

3. **第三方服务密钥**
   ```javascript
   // ❌ 错误：绝对不能暴露
   VITE_AWS_SECRET_ACCESS_KEY: 'wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY'
   ```

4. **JWT Secret**
   ```javascript
   // ❌ 错误：绝对不能暴露
   VITE_JWT_SECRET: 'your-secret-key'
   ```

5. **管理员密码**
   ```javascript
   // ❌ 错误：绝对不能暴露
   VITE_ADMIN_PASSWORD: 'admin123'
   ```

### 6.4 前端安全模型

**正确的安全模型**：

```
前端（公开）         后端（私有）
├─ API 地址          ├─ API 密钥
├─ 前端 URL          ├─ 数据库连接
├─ 应用标题          ├─ Secret Key
├─ 功能开关          ├─ JWT Secret
├─ 应用路径          └─ 敏感凭证
└─ CORS 配置
```

**原则**：
- ✅ **前端配置是公开的**：无法避免，这是前端代码的本质
- ✅ **敏感信息放在后端**：API 密钥、Secret Key 等应该放在后端
- ✅ **通过后端保护**：敏感操作通过后端 API 进行

### 6.5 安全配置建议

#### 建议1：敏感信息放在后端

```typescript
// ❌ 错误：在前端配置中
VITE_API_SECRET: 'stream_example_1234567890abcdef'

// ✅ 正确：在后端配置中
// 后端环境变量
API_SECRET=stream_example_1234567890abcdef
```

#### 建议2：使用环境变量（后端）

```bash
# 后端 .env 文件（不在前端代码中）
API_SECRET=stream_example_1234567890abcdef
DATABASE_URL=postgresql://user:password@host:5432/dbname
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

#### 建议3：API 密钥通过后端代理

```typescript
// ❌ 错误：前端直接使用 API 密钥
const response = await fetch('https://api.example.com', {
  headers: {
    'Authorization': `Bearer ${VITE_API_KEY}`  // ❌ 暴露密钥
  }
});

// ✅ 正确：通过后端代理
const response = await fetch('/api/proxy', {
  method: 'POST',
  body: JSON.stringify({ url: 'https://api.example.com' })
});
// 后端使用密钥，前端不暴露
```
