## 三、XSS防护规范

### 3.1 核心原则

**所有从API获取或用户输入的内容，在页面渲染时必须进行转义。**

### 3.2 实施要求

#### 3.2.1 禁止使用 v-html

**规范**：严禁使用 `v-html` 指令渲染任何可能包含用户输入内容的HTML字符串。

**示例**：
```vue
<!-- ❌ 错误：直接使用 v-html -->
<div v-html="userContent"></div>

<!-- ✅ 正确：使用文本插值（自动转义） -->
<div>{{ userContent }}</div>

<!-- ✅ 正确：如果必须渲染HTML，使用安全的HTML解析库 -->
<div v-html="sanitizedHtml"></div>
```

**安全处理**：
```typescript
// utils/xss.ts
import DOMPurify from 'dompurify'; // 或其他安全的HTML清理库

export const sanitizeHtml = (html: string): string => {
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['p', 'br', 'strong', 'em'], // 只允许特定标签
    ALLOWED_ATTR: [], // 不允许任何属性
  });
};
```

#### 3.2.2 URL参数校验

**规范**：对URL参数进行合法性校验，特别是用于跳转的 `redirect` 参数。

**示例**：
```typescript
// utils/security.ts
export const validateRedirectUrl = (url: string): boolean => {
  // 只允许相对路径或同源URL
  if (url.startsWith('/')) {
    return true; // 相对路径安全
  }
  
  // 检查是否为同源URL
  try {
    const urlObj = new URL(url, window.location.origin);
    return urlObj.origin === window.location.origin;
  } catch {
    return false; // 无效URL
  }
};

// 使用示例
const redirectUrl = getUrlParam('redirect');
if (redirectUrl && validateRedirectUrl(redirectUrl)) {
  // 安全跳转
  window.location.href = redirectUrl;
} else {
  // 使用默认URL
  window.location.href = '/pages/index/index';
}
```

#### 3.2.3 用户输入转义

**规范**：所有用户输入在显示前必须转义。

**示例**：
```vue
<!-- ✅ 正确：Vue 自动转义 -->
<div>{{ userInput }}</div>

<!-- ✅ 正确：手动转义（如果需要） -->
<div>{{ escapeHtml(userInput) }}</div>
```

```typescript
// utils/xss.ts
export const escapeHtml = (text: string): string => {
  const map: Record<string, string> = {
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#039;',
  };
  return text.replace(/[&<>"']/g, (m) => map[m]);
};
```

## 四、本地缓存加密规范

### 4.1 核心原则

**所有敏感信息在存入本地缓存前，必须使用加密算法进行加密。**

### 4.2 敏感信息定义

**需要加密的敏感信息**：
- ✅ `access_token`（访问令牌）
- ✅ `refresh_token`（刷新令牌）
- ✅ 用户密码（即使已加密）
- ✅ 用户个人信息（手机号、邮箱等）
- ✅ 其他敏感凭证

**不需要加密的信息**：
- ❌ 用户偏好设置（主题、语言等）
- ❌ 非敏感的用户信息（昵称、头像URL等）
- ❌ 应用配置信息

### 4.3 实施要求

#### 4.3.1 加密存储函数

**规范**：创建 `utils/crypto.ts` 提供加密算法（如AES）。

**示例**：
```typescript
// utils/crypto.ts
import CryptoJS from 'crypto-js';

const SECRET_KEY = 'your-secret-key'; // 应该从环境变量读取

/**
 * 加密数据
 * @param data 要加密的数据
 * @returns 加密后的字符串
 */
export const encrypt = (data: string): string => {
  return CryptoJS.AES.encrypt(data, SECRET_KEY).toString();
};

/**
 * 解密数据
 * @param encryptedData 加密后的字符串
 * @returns 解密后的原始数据
 */
export const decrypt = (encryptedData: string): string => {
  const bytes = CryptoJS.AES.decrypt(encryptedData, SECRET_KEY);
  return bytes.toString(CryptoJS.enc.Utf8);
};
```

#### 4.3.2 封装存储函数

**规范**：创建 `utils/storage.ts` 封装加密存储和解密读取的逻辑。

**技术栈适配**：

##### uni-app 项目

```typescript
// utils/storage.ts (uni-app版本)
import { encrypt, decrypt } from './crypto';

/**
 * 加密存储（uni-app）
 * @param key 存储键
 * @param value 要存储的值（会自动JSON序列化）
 */
export const setSecureStorage = (key: string, value: any): void => {
  const jsonString = JSON.stringify(value);
  const encrypted = encrypt(jsonString);
  uni.setStorageSync(key, encrypted);
};

/**
 * 解密读取（uni-app）
 * @param key 存储键
 * @returns 解密后的值（会自动JSON反序列化）
 */
export const getSecureStorage = <T = any>(key: string): T | null => {
  try {
    const encrypted = uni.getStorageSync(key);
    if (!encrypted) return null;
    const decrypted = decrypt(encrypted);
    return JSON.parse(decrypted) as T;
  } catch (error) {
    console.error('解密存储失败:', error);
    return null;
  }
};

/**
 * 删除存储（uni-app）
 */
export const removeSecureStorage = (key: string): void => {
  uni.removeStorageSync(key);
};
```

##### 标准 Web 项目

```typescript
// utils/storage.ts (标准Web版本)
import { encrypt, decrypt } from './crypto';

/**
 * 加密存储（标准Web）
 * @param key 存储键
 * @param value 要存储的值（会自动JSON序列化）
 */
export const setSecureStorage = (key: string, value: any): void => {
  const jsonString = JSON.stringify(value);
  const encrypted = encrypt(jsonString);
  localStorage.setItem(key, encrypted);
};

/**
 * 解密读取（标准Web）
 * @param key 存储键
 * @returns 解密后的值（会自动JSON反序列化）
 */
export const getSecureStorage = <T = any>(key: string): T | null => {
  try {
    const encrypted = localStorage.getItem(key);
    if (!encrypted) return null;
    const decrypted = decrypt(encrypted);
    return JSON.parse(decrypted) as T;
  } catch (error) {
    console.error('解密存储失败:', error);
    return null;
  }
};

/**
 * 删除存储（标准Web）
 */
export const removeSecureStorage = (key: string): void => {
  localStorage.removeItem(key);
};
```

#### 4.3.3 使用规范

**规范**：业务代码禁止直接调用 `uni.setStorageSync` 或 `localStorage.setItem` 存取敏感信息。

**示例**：
```typescript
// ❌ 错误：直接存储敏感信息
uni.setStorageSync('access_token', token);
localStorage.setItem('access_token', token);

// ✅ 正确：使用加密存储
import { setSecureStorage, getSecureStorage } from '@/utils/storage';

// 存储
setSecureStorage('access_token', token);

// 读取
const token = getSecureStorage<string>('access_token');
```

## 五、请求安全规范

### 5.1 请求频率与重放防护

#### 5.1.1 时间戳和随机数

**规范**：前端请求拦截器必须为所有非GET请求添加 `timestamp`（请求时间戳）和 `nonce`（随机数）参数。

**实施位置**：`utils/request.ts` 的请求拦截器

**示例**：
```typescript
// utils/request.ts
import { v4 as uuidv4 } from 'uuid'; // 或使用其他随机数生成方法

// 请求拦截器
const requestInterceptor = (config: RequestConfig) => {
  // 为所有非GET请求添加时间戳和随机数
  if (config.method !== 'GET' && config.method !== 'get') {
    config.data = config.data || {};
    config.data.timestamp = Date.now();
    config.data.nonce = uuidv4(); // 或使用其他随机数生成方法
  }
  return config;
};
```

#### 5.1.2 请求签名

**规范**：前端需配合后端，使用约定的密钥（`client_secret`）对请求参数、`timestamp`、`nonce` 进行签名（如HMAC-SHA256），生成 `signature` 参数并随请求发送。

**示例**：
```typescript
// utils/request.ts
import CryptoJS from 'crypto-js';

const CLIENT_SECRET = 'your-client-secret'; // 应该从环境变量读取

/**
 * 生成请求签名
 * @param params 请求参数
 * @param timestamp 时间戳
 * @param nonce 随机数
 * @returns 签名字符串
 */
const generateSignature = (
  params: Record<string, any>,
  timestamp: number,
  nonce: string
): string => {
  // 1. 将参数按key排序
  const sortedKeys = Object.keys(params).sort();
  
  // 2. 构建签名字符串
  const signString = sortedKeys
    .map(key => `${key}=${params[key]}`)
    .join('&') + `&timestamp=${timestamp}&nonce=${nonce}`;
  
  // 3. 使用HMAC-SHA256签名
  return CryptoJS.HmacSHA256(signString, CLIENT_SECRET).toString();
};

// 请求拦截器
const requestInterceptor = (config: RequestConfig) => {
  if (config.method !== 'GET' && config.method !== 'get') {
    const timestamp = Date.now();
    const nonce = uuidv4();
    const signature = generateSignature(config.data || {}, timestamp, nonce);
    
    config.data = {
      ...config.data,
      timestamp,
      nonce,
      signature,
    };
  }
  return config;
};
```

**注意**：
- `client_secret` 应该从环境变量读取，不能硬编码
- 后端需要进行验签，验证请求的合法性
- 时间戳应该有有效期（如5分钟），过期请求应该被拒绝

## 六、CSRF防护规范

### 6.1 适用范围

**仅适用于 Web/H5 环境**，不适用于小程序和App。

### 6.2 核心原则

**在Web（H5）环境下，所有状态变更的请求（POST/PATCH/DELETE等）必须携带后端通过Cookie或API下发的 `X-CSRF-Token` 请求头。**

### 6.3 实施要求

#### 6.3.1 获取CSRF Token

**规范**：`utils/request.ts` 需包含在H5环境下自动获取并附加此请求头的逻辑。

**示例**：
```typescript
// utils/request.ts

/**
 * 从Cookie中获取CSRF Token（仅H5环境）
 */
const getCsrfToken = (): string | null => {
  // #ifdef H5
  if (typeof document !== 'undefined' && typeof document.cookie !== 'undefined') {
    const csrfCookie = document.cookie
      .split(';')
      .find(c => c.trim().startsWith('csrftoken='));
    return csrfCookie ? decodeURIComponent(csrfCookie.split('=')[1]) : null;
  }
  // #endif
  return null;
};

// 请求拦截器
const requestInterceptor = (config: RequestConfig) => {
  // #ifdef H5
  // 为所有状态变更请求添加CSRF Token
  if (['POST', 'PATCH', 'PUT', 'DELETE'].includes(config.method?.toUpperCase() || '')) {
    const csrfToken = getCsrfToken();
    if (csrfToken) {
      config.header = config.header || {};
      config.header['X-CSRF-Token'] = csrfToken;
    }
  }
  // #endif
  return config;
};
```

#### 6.3.2 后端配合

**规范**：后端需要：
1. 在首次访问时通过Cookie下发 `csrftoken`
2. 验证请求头中的 `X-CSRF-Token` 是否与Cookie中的值匹配
3. 验证失败时返回 403 Forbidden

## 七、Clickjacking防护规范

### 7.1 适用范围

**仅适用于 Web/H5 环境**，不适用于小程序和App。

### 7.2 核心原则

**前端需与运维/后端协作，确保所有H5页面的服务器响应头中包含 `X-Frame-Options: DENY` 或 `X-Frame-Options: SAMEORIGIN`，禁止页面被恶意 `iframe` 嵌套。**

### 7.3 实施要求

#### 7.3.1 后端配置

**规范**：后端需要在HTTP响应头中设置：

```
X-Frame-Options: DENY
```

或

```
X-Frame-Options: SAMEORIGIN
```

**说明**：
- `DENY`：完全禁止页面被嵌入iframe
- `SAMEORIGIN`：只允许同源页面嵌入iframe

#### 7.3.2 前端检查（可选）

**规范**：前端可以添加检查逻辑，防止页面被嵌入iframe。

**示例**：
```typescript
// utils/security.ts

/**
 * 检查页面是否被嵌入iframe（仅H5环境）
 */
export const checkFrameOptions = (): void => {
  // #ifdef H5
  if (typeof window !== 'undefined' && window.self !== window.top) {
    // 页面被嵌入iframe，可以跳转到顶层窗口
    window.top.location.href = window.self.location.href;
  }
  // #endif
};

// 在页面加载时调用
onMounted(() => {
  checkFrameOptions();
});
```

## 八、Token管理规范

### 8.1 核心原则

**前后端需协同实现基于 `access_token` 和 `refresh_token` 的会话管理机制，保障长期会话安全。**

### 8.2 Token存储规范

**规范**：Token必须使用加密存储（参考[本地缓存加密规范](#四本地缓存加密规范)）。

**示例**：
```typescript
// store/auth.ts
import { setSecureStorage, getSecureStorage, removeSecureStorage } from '@/utils/storage';

export const useAuthStore = defineStore('auth', {
  state: () => ({
    accessToken: '',
    refreshToken: '',
  }),

  actions: {
    // 保存Token（加密存储）
    saveTokens(accessToken: string, refreshToken: string) {
      this.accessToken = accessToken;
      this.refreshToken = refreshToken;
      
      // 使用加密存储
      setSecureStorage('access_token', accessToken);
      setSecureStorage('refresh_token', refreshToken);
    },

    // 加载Token（解密读取）
    loadTokens() {
      const accessToken = getSecureStorage<string>('access_token');
      const refreshToken = getSecureStorage<string>('refresh_token');
      
      if (accessToken) this.accessToken = accessToken;
      if (refreshToken) this.refreshToken = refreshToken;
    },

    // 清除Token
    clearTokens() {
      this.accessToken = '';
      this.refreshToken = '';
      removeSecureStorage('access_token');
      removeSecureStorage('refresh_token');
    },
  },
});
```

### 8.3 Token刷新机制

**规范**：当 `access_token` 过期时，自动使用 `refresh_token` 刷新。

**实施位置**：`utils/request.ts` 的响应拦截器

**示例**：
```typescript
// utils/request.ts

// 响应拦截器
const responseInterceptor = async (response: any) => {
  // 如果返回401，尝试刷新Token
  if (response.statusCode === 401) {
    const authStore = useAuthStore();
    const refreshToken = authStore.refreshToken;
    
    if (refreshToken) {
      try {
        // 调用刷新Token接口
        const newTokens = await refreshAccessToken(refreshToken);
        authStore.saveTokens(newTokens.access_token, newTokens.refresh_token);
        
        // 重试原请求
        return request(originalConfig);
      } catch (error) {
        // 刷新失败，跳转登录
        authStore.logout();
        return Promise.reject(error);
      }
    } else {
      // 没有refresh_token，直接跳转登录
      authStore.logout();
      return Promise.reject(new Error('未登录'));
    }
  }
  
  return response;
};
```

### 8.4 Token过期处理

**规范**：Token过期时应该：
1. 自动尝试刷新Token
2. 刷新失败时清除Token并跳转登录
3. 显示友好的错误提示

## 九、验证码机制规范

### 9.1 核心原则

**登录、注册等关键操作必须集成图形验证码，防止自动化脚本的暴力破解。**

### 9.2 适用场景

**需要验证码的操作**：
- ✅ 用户登录
- ✅ 用户注册
- ✅ 忘记密码
- ✅ 重置密码
- ✅ 修改密码
- ✅ 绑定手机号
- ✅ 其他敏感操作

### 9.3 实施要求

#### 9.3.1 验证码显示

**规范**：验证码应该：
- ✅ 在表单提交前显示
- ✅ 支持点击刷新
- ✅ 显示加载状态
- ✅ 处理显示失败的情况

#### 9.3.2 验证码校验

**规范**：验证码应该：
- ✅ 在提交前进行前端校验
- ✅ 后端必须进行二次校验
- ✅ 验证码只能使用一次
- ✅ 验证码有过期时间

#### 9.3.3 跨端显示规范

**规范**：验证码需要支持多端显示（H5、小程序、App）。为确保验证码在多终端稳定、安全地显示，前端与后端需遵循以下规范。

**核心原则**：
- ✅ **强制使用 `image_base64`**：前端必须始终使用后端返回的 `image_base64` 字段作为唯一数据源，并忽略 `image_url` 字段（即使后端返回了该字段）。

**技术栈适配**：

##### uni-app 项目

**H5 平台 (Web)**：
- ✅ 必须将 `image_base64` 字符串转换为 `blob:` URL（绕过浏览器 CSP 对 `data:` URI 的限制）
- ✅ 必须使用原生 `<img>` 标签来渲染该 `blob:` URL
- ✅ 必须使用 `onScopeDispose` 或类似生命周期钩子，在组件卸载时调用 `URL.revokeObjectURL()` 来释放已生成的 `blob:` URL，防止内存泄漏

**小程序平台**：
- ✅ 应优先尝试直接使用添加了 `data:image/png;base64,` 前缀的 `image_base64` 字符串
- ✅ 如直接显示存在兼容性问题或被平台策略限制，必须将 `image_base64` 的内容转存为本地临时文件，并使用该文件路径作为 `src`

**App 平台**：
- ✅ 可以直接使用添加了 `data:image/png;base64,` 前缀的 `image_base64` 字符串

**实现示例**：

```vue
<!-- 页面模板：使用条件编译区分平台 -->
<!-- H5平台：使用原生<img>标签渲染blob: URL -->
<!-- #ifdef H5 -->
<img :src="captchaSrc" class="captcha-img" @click="refreshCaptcha" alt="Captcha" />
<!-- #endif -->

<!-- 非H5平台：使用uni-app的<image>组件 -->
<!-- #ifndef H5 -->
<image :src="captchaSrc" class="captcha-img" @click="refreshCaptcha" />
```

```typescript
// utils/captcha.ts (uni-app项目)
export const useCaptcha = () => {
  const captchaId = ref<string>('');
  const captchaSrc = ref<string>('');
  const isLoading = ref(false);

  // H5平台：base64转blob URL
  // #ifdef H5
  const base64ToBlobUrl = (base64: string): string => {
    const base64Data = base64.replace(/^data:image\/\w+;base64,/, '');
    const byteCharacters = atob(base64Data);
    const byteNumbers = new Array(byteCharacters.length);
    for (let i = 0; i < byteCharacters.length; i++) {
      byteNumbers[i] = byteCharacters.charCodeAt(i);
    }
    const byteArray = new Uint8Array(byteNumbers);
    const blob = new Blob([byteArray], { type: 'image/png' });
    return URL.createObjectURL(blob);
  };
  // #endif

  const refreshCaptcha = async () => {
    isLoading.value = true;
    try {
      const res = await getCaptcha();
      captchaId.value = res.captcha_id;
      
      // #ifdef H5
      // H5平台：转换为blob URL
      const blobUrl = base64ToBlobUrl(res.image_base64);
      // 释放旧的blob URL（如果有）
      if (captchaSrc.value && captchaSrc.value.startsWith('blob:')) {
        URL.revokeObjectURL(captchaSrc.value);
      }
      captchaSrc.value = blobUrl;
      // #endif
      
      // #ifndef H5
      // 非H5平台：直接使用base64
      captchaSrc.value = `data:image/png;base64,${res.image_base64}`;
      // #endif
    } catch (error) {
      console.error('获取验证码失败:', error);
    } finally {
      isLoading.value = false;
    }
  };

  // 组件卸载时释放blob URL（H5平台）
  // #ifdef H5
  onScopeDispose(() => {
    if (captchaSrc.value && captchaSrc.value.startsWith('blob:')) {
      URL.revokeObjectURL(captchaSrc.value);
    }
  });
  // #endif

  return { captchaId, captchaSrc, isLoading, refreshCaptcha };
};
```

**排查清单**：
- ✅ **H5 中验证码看不见或显示为破损图标**：
  1. 检查 `<img>` 标签：确认渲染的是 `<img>` 标签，而不是 `<uni-image>`
  2. 检查 `src` 属性：确认 `src` 的值是以 `blob:http://...` 开头的 URL
  3. 检查 Console 控制台：查看是否有转换错误
  4. 检查 `atob` 合法性：确认后端返回的 base64 没有编码问题
- ✅ **小程序中验证码看不见**：检查 `base64 → 临时文件路径` 的转换逻辑
- ✅ **刷新无效**：确认 `refreshCaptcha` 被正确调用，`captchaSrc` 的值在每次刷新后都发生了变化
