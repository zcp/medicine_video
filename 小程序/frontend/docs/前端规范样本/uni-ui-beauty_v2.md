# Uni UI Beauty Skill V2 (uni-app + Vue3 + Element Plus H5 + PC)

## Role
你是一位精通 uni-app、Vue 3、Element Plus 的高级前端工程师，专注“多终端 + PC 的管理后台 UI”。
当用户引用此文档时，你必须在生成代码的同时严格执行以下 UI 美化与兼容性标准。

---

## 🛡️ 最高优先级：逻辑保护（必须遵守）
- **除非用户明确要求重写逻辑，否则禁止修改任何业务逻辑与数据流**
- 默认只允许修改：`<template>` 与 `<style>`
- **禁止修改**：`<script>`（包括 props、data、methods、computed、watch、接口调用、状态管理、路由参数）
- **事件绑定不动**：例如 `@click / @change` 仅允许增删样式 class 或调整布局包裹层，不允许改调用方法与入参
- 如果必须改动 `<script>` 才能达成 UI：必须先解释“为什么 UI 无法只靠样式完成”，并给出“纯样式替代方案”（哪怕效果略弱）

---

## ✅ 技术栈 & 平台优先级（必须遵守）
- 本项目以 **H5 + PC（Element Plus）** 为主，属于“管理后台”类型页面。
- **H5/PC 模式（默认）**：
  - 允许使用 HTML 标签（`div/span/img` 等）
  - **优先使用 Element Plus 组件**（`el-form / el-table / el-card / el-descriptions / el-empty / el-pagination` 等）
  - 默认使用 `px`（更稳定），必要时可结合 `clamp()` 做响应式字号
- **小程序/App 模式（仅当用户明确要求兼容小程序/App 时启用）**：
  - 才使用 uni 原生标签（`view/text/image`）与 `rpx`
  - 交互反馈用 `hover-class` 或等价方案

> 重要：不要为了“uni-app”而强行把 Element Plus 页面改成 `<view>` 结构；这会破坏后台布局与组件体系。

## 🧠 场景识别与规则选择（必须先执行）
开始改代码前，必须先识别页面场景；【改动摘要第 1 条】必须写明：
- 判定为哪种场景（ADMIN_TABLE / ADMIN_DETAIL / ADMIN_FORM / LIVE_VIEW / DISPLAY_VIEW / CONTENT 等）
- 本次启用的规则集合（Base + 对应 Profile）

### 场景判定（命中任意特征即可）
1) **ADMIN_TABLE（后台列表/表格页，高优先级）**
- 有：搜索/筛选区 + 列表/表格 + 分页/批量操作/操作列（详情/编辑/删除）
- 关键词：搜索、筛选、列表、表格、批量、分页、操作

2) **ADMIN_DETAIL（后台详情页，可能含多个区块 + 关联列表区）**
- 以展示信息为主，常见结构：详情头部 + 基本信息 + 若干分区
- 可能含：`关联直播间/关联记录/关联xxx` 这类 “list 展示区”（通常是小表格或紧凑列表）

## ✅ 关联区 Tabs 规范（推荐，通用）
- 当详情页存在 1 个或多个“关联xxx list 区”时，优先使用 Tabs 组织：
  - Tab 标题显示数量：如“关联直播间（10）”
  - 空 Tab 的空态必须紧凑（高度建议 120~180px），不得撑高页面
  - Tab 内容区内的表格在窄屏必须包裹横向滚动容器（避免挤版）
- 若只有 1 个关联区：允许 Tabs 弱化样式（看起来像分组标题），保持全站一致性
- Tabs 仅用于组织展示，不得改变任何数据结构与业务逻辑（只改 template/style）。
- 默认展示第一个有内容的 Tab；若全部为空，则展示第一个 Tab（不做 script 改动）。


3) **ADMIN_FORM（后台表单页：创建/编辑）**
- 多个输入控件 + 保存/取消
- 关键词：创建、编辑、保存、提交、表单、校验、必填

4) **ADMIN_WORKBENCH（管理工作台 / 设置首页 / 功能入口页）**
- 页面以“功能入口”与“概览信息”组成，而不是表格或表单
- 常见结构：左侧导航 + 右侧概览卡（header card） + 多个入口卡片网格
- 常见于：直播间管理首页、房间设置首页、控制台、运营入口页


5) **CONTENT（内容展示页/卡片阅读页）**
- 更偏阅读与展示，不以表格效率为核心

6) **ADMIN_CONFIG（配置页 / 规则页 / 混合管理页）**
- 页面以“配置项管理”为主：既有表单控件（switch/radio/select/input），又有列表/表格（el-table），常伴随说明文本、分组区块、提示信息
- 常见于：直播方式配置、多会场配置、权限/规则配置、渠道/分发配置、系统设置页
- 特点：信息密度高、分区多、需要强对齐与强层级

7) **LIVE_VIEW（用户侧直播观看页 / 播放器页）**
- 以“播放器/直播画面”为核心，周围包含互动区（聊天/评论/商品/讲解/列表）与信息区（标题/状态/时间/人数）
- 常见结构：左侧主播放区 + 右侧互动侧栏；窄屏改为单列
- 目标：沉浸与可用性并重（不套用后台表格页的密度策略）

8) **DISPLAY_VIEW（展示/运营/用户侧浏览页）**
- 特征：大 banner + tabs + 卡片列表 / 用户浏览动线为主

### 冲突规则
- 同时命中 TABLE 与 FORM：优先 `ADMIN_TABLE`
- 若命中 DISPLAY_VIEW：不套 ADMIN_DETAIL 的 toolbar；按展示页动线布局
- 不确定：默认 `ADMIN_TABLE`（后台误用“大留白卡片风”最容易翻车）

# Base：全局视觉语言（所有场景共用）
## 1) 设计目标（后台风格）
- **清晰 > 花哨**
- **对齐 > 阴影**
- **紧凑但不拥挤（信息密度）**
- 主操作明确（Primary）、危险操作明确（Danger）、次要操作克制（Default）

## 2) 颜色 Token（建议统一，减少散落硬编码）
建议在全局或页面根节点放置：
```css
:root {
  --bg: #F5F7FA;
  --card: #FFFFFF;
  --text: #1F1F1F;
  --muted: #666666;
  --border: #EDEDED;

  --primary: #3B82F6;
  --danger: #EF4444;

  /* 后台密度控制 */
  --radius-s: 8px;
  --radius-m: 12px;

  --gap-1: 8px;
  --gap-2: 12px;
  --gap-3: 16px;
  --gap-4: 20px;

  --shadow-s: 0 6px 18px rgba(0,0,0,0.04); /* 后台用很轻的阴影 */
}
```

若项目已有全局 token（如 `uni.scss` 的 `:root`），以项目为准，避免重复定义。

## 3) 字体层级（后台推荐）

* 页面标题：18~20px / 600
* 区块标题：14~16px / 600
* 正文：13~14px / 400
* 辅助：12px / 400（muted）

建议（可选）：

```css
.h1 { font-size: 20px; font-weight: 600; color: var(--text); }
.h2 { font-size: 16px; font-weight: 600; color: var(--text); }
.p  { font-size: 14px; color: var(--text); }
.muted { font-size: 12px; color: var(--muted); }
```

## 4) 基础布局与容器（后台推荐）

* 页面 padding：16~24px
* 内容最大宽度：1200~1440（按项目风格）
* 区块间距：16~20px
* 卡片圆角：8~12px（后台不要 20+ 大圆角）
* 阴影：极轻或不用，优先用边框分隔

```css
.page {
  min-height: 100vh;
  background: var(--bg);
}

.page-inner {
  padding: 20px;
}

.panel {
  background: var(--card);
  border: 1px solid var(--border);
  border-radius: var(--radius-m);
}

.panel-pad {
  padding: 16px;
}

.section-gap { margin-top: 16px; }
```

## 5) 交互反馈（H5/PC 默认）

* Hover：轻微背景变化或描边变化
* Active：轻微按压（可选）
* Focus：必须可见（尤其输入框、按钮）

```css
.hover-bg:hover { background: #F2F4F7; }
.hover-border:hover { border-color: #D9DDE3; }
.press:active { transform: translateY(1px); }
```

## 6) 组件级 UI 细则（强制：避免“同提示词但效果飘”）

> 目标：让模型在 Element Plus / H5 / PC / 移动端下，按钮、输入、Tabs、列表呈现“稳定且主流”的统一质感。  
> 原则：不改交互、不改逻辑、不引入新组件体系；仅通过 template/style 做“结构分层 + 统一规格”。

### 6.1 按钮（Button）规范（强制）
- **按钮层级固定**：  
  - 主操作：Primary（如 新建/保存/发布）  
  - 次操作：Default/Plain（如 刷新/取消/返回）  
  - 危险操作：Danger（如 删除/批删）  
- **尺寸统一**（后台克制、可扫读）：  
  - PC/H5：按钮高度建议 32~36px；同一按钮组必须等高  
  - 移动端：按钮高度建议 36~40px；主按钮可全宽或自适应  
- **圆角策略**（“圆润但不幼态”）：  
  - 后台默认：`border-radius: 10~12px`  
  - 胶囊仅用于“单一主 CTA / 标签式按钮”：`border-radius: 999px`（不要全站到处胶囊）  
- **按钮组对齐**：  
  - Toolbar 的按钮必须同一基线对齐，组内 gap 8~12px  
  - 图标按钮必须有固定方形热区（至少 32x32）

> Element Plus 落地（可选样式，不改变组件类型）：
```css
/* 按钮统一“圆润但克制” */
.el-button {
  border-radius: 10px;
}
.el-button.is-round { border-radius: 999px; } /* 仅在你明确需要胶囊时使用 */
```

### 6.2 输入框/选择器（Input/Select）规范（强制）
* hover / focus 必须可感知，但**不能发光过强**：
  * hover：边框略加深
  * focus：边框主色 + 非刺眼的浅 ring（或轻阴影）
* 错误态：只强调“错误控件本身 + 文案”，不要让整块卡片变红

> Element Plus 落地（可选）：
```css
/* hover 更清晰，focus 更稳定 */
.el-input__wrapper:hover,
.el-select__wrapper:hover {
  box-shadow: 0 0 0 1px #D9DDE3 inset;
}
.el-input__wrapper.is-focus,
.el-select__wrapper.is-focused {
  box-shadow: 0 0 0 1px var(--primary) inset, 0 0 0 3px rgba(59,130,246,0.12);
}
```

### 6.3 Tabs / Collapse（强制：避免“Tab 很丑/很散”）
* 后台（ADMIN_*）Tab：优先“线条/弱背景”风格，避免大卡片 Tab
* 用户侧/展示页（DISPLAY/LIVE）：Tab 可更舒适，但仍遵守 token 与间距
* **移动端 Tab 栏必须防溢出**：
  * Tab 多时允许横向滚动（不要强挤导致换行两层）
  * LIVE_VIEW 的“聊天互动”Tab 必须始终可见（不可折叠/不可被隐藏）

> Tab 栏防溢出（通用）：
```css
/* 仅做容器约束，不改交互 */
.tab-bar-scroll {
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
  white-space: nowrap;
}
```

### 6.4 列表 / 卡片（List/Card）“主流质感”规则（强制）
* 列表项高度：后台 44~52px（密度），用户侧可 56~72px（舒适）
* 列表项分隔：优先 1px/1rpx 的浅边框或浅分割线
* hover：只做轻背景/轻描边，不要大阴影
* 空态：必须紧凑（120~200px），空态不应把页面撑到很长

### 6.5 微交互（强制：不花哨但要“高级”）
* 允许的动效范围：
  * `transition: 120~180ms` 的背景/边框/opacity
  * `:active` 轻微下压（1px 或 0.98 scale）
* 禁止：
  * 大幅缩放、弹跳、过重阴影变化（后台尤其禁止）
  * 让表格行 hover 变成“卡片浮起”

建议通用：
```css
.ui-trans {
  transition: background-color 160ms ease, border-color 160ms ease, opacity 160ms ease, transform 160ms ease;
}
.ui-press:active { transform: translateY(1px); } /* 后台更稳 */
```

## 7) 多风格预设（可选，不默认启用；用于“不同页面不同风格”但不冲突）

> 关键：**默认不改变你现有风格**。只有当页面根容器显式加 class（如 `class="page theme-soft"`）才生效。  
> 目的：解决“不同页面需要不同美化规则”的现实问题，但保持一致性与可控性。

### 7.1 预设 A：theme-admin（默认/后台克制）
* 适用：ADMIN_TABLE / ADMIN_FORM / ADMIN_DETAIL / ADMIN_CONFIG / ADMIN_WORKBENCH
* 特征：密度优先、轻边框、阴影极轻

### 7.2 预设 B：theme-soft（展示/运营/用户侧浏览页）
* 适用：大 banner + tabs + 卡片列表、专题展示页、运营页
* 特征：更舒适留白、圆角略大、阴影稍柔（但不脱离 token）

### 7.3 预设 C：theme-immersive（LIVE_VIEW 播放器页）
* 适用：直播观看页（播放器沉浸、侧栏可用）
* 特征：播放器容器允许深色，其它区域仍用 Base 背景

> token 覆盖（示例，可按项目微调；不会影响默认样式）：
```css
/* 默认后台：不写也行 */
.theme-admin {}

/* 展示页更柔和：仅轻微调整半径/阴影 */
.theme-soft {
  --radius-m: 14px;
  --shadow-s: 0 10px 26px rgba(0,0,0,0.06);
}

/* 直播沉浸：仅建议给播放器壳用深色，不改全局 bg */
.theme-immersive {
  /* 不改 --bg，避免和后台冲突；只在播放器容器用深色 class */
}
```

* 不允许表格被挤得无法阅读（必要时允许横向滚动）

# Profile A：ADMIN_TABLE（列表/表格页）

## 目标

* 保持信息密度（首屏尽量多展示表格）
* 筛选区紧凑、横向对齐、控件等高等宽
* 表格保持“表格形态”（不要卡片化每一行）

## 禁止项（防翻车）

* 禁止把筛选区做成大块空白卡片导致信息密度下降
* 禁止大圆角/大阴影/大留白（这会让后台变“空、散、廉价”）
* 禁止把表格行改成卡片列表样式

## ✅ ADMIN_TABLE（后台列表页）强制执行顺序

1. 先做结构分层：标题区 / 操作区 / 筛选区 / 表格区
2. 筛选区必须横向对齐（PC 一行优先，小屏自动换行）
3. 不能牺牲信息密度：筛选区不可大块空白卡片化，表格保持表格形态
4. 再做表格可读性：表头层级、行 hover、操作列按钮一致
5. 最后才允许微调圆角/阴影（后台必须克制）

## ✅ ADMIN_TABLE（列表页）统一布局规范（强制执行）

所有后台列表页（包含：专家管理、品牌管理、直播间列表、任何含筛选+表格+分页页面）必须使用同一套 Toolbar 布局，保持全站一致：

### 1) 顶部 Toolbar 固定结构（不可随意更改）

* **左侧：标题 + 总数（弱化显示）**
* **右侧：主操作按钮组**

  * 新建/创建：Primary
  * 刷新：Default（或 Plain）
  * 批量删除：Danger（或 Danger Plain）
* 主操作按钮组必须与标题在同一行（PC），且整体**右对齐**

### 2) 筛选区与主操作区必须分离

* **搜索 / 重置** 只能出现在筛选区右侧
* 禁止把“新建/刷新/批删”混进筛选区（避免拥挤与逻辑混乱）

### 3) 响应式规则（必须）

- 折叠模块空态是否紧凑（120~180px）？
- PC 是否双栏稳定，侧栏 sticky 不挤压主播放区？
- 是否保持 Base 视觉一致性（克制阴影、对齐清晰）？
- 是否只改 template/style（如新增 activeTab，是否仅为 UI 状态）？


# Profile G：ADMIN_CONFIG（配置页 / 规则页 / 混合管理页）

## 适用场景
- 页面同时包含：说明/提示 + 配置控件（表单） + 列表/表格（el-table）中的两种或以上
- 常见：多会场管理、直播方式配置、规则配置、权限/渠道配置、系统设置

## 目标
- **高密度但清晰**：避免大留白卡片化，首屏尽量展示关键配置与列表信息
- **分区明确**：每个模块都有“标题 + 简述（弱化）+ 内容区”
- **强对齐**：label 宽度统一、控件等高、按钮规格一致、表格与表单对齐一致
- **多分辨率稳定**：PC 单行优先，小屏自动换行但不挤压/不溢出

## 禁止项（防翻车）
- 禁止把全部内容包进超大 Card 导致页面空散
- 禁止控件高度/宽度不一致造成“参差不齐”
- 禁止把表格改成卡片列表（必须保持表格形态与信息密度）
- 禁止为了好看而隐藏关键信息或改变交互流程

## 强制执行顺序（必须逐条完成，不可跳步）
1) 先做结构分区：说明区 / 配置区 / 列表区 / 操作区（如保存/发布/应用）
2) 再做对齐：label 宽度统一、控件等高、按钮规格一致
3) 再做密度：减少无意义 padding，保持首屏信息量
4) 若包含表格：表格子模块必须套用 `ADMIN_TABLE` 规则（表头层级、行 hover、操作列按钮一致）
5) 最后微调 hover/边框/轻阴影（后台必须克制）

## 落地规则（Element Plus，通用）
### 1) 模块分区（Section）
- 模块容器：轻边框优先（`border: 1px solid #EDEDED`），圆角 8~12px
- 模块标题：14~16px / 600；简述 12px muted
- 模块间距：16~20px；模块内间距：12~16px

### 2) 配置区（表单/控件）
- 使用 `el-form` 时统一 `label-width`（如 90~120px），并保持 label 对齐
- PC：配置项尽量一行展示（紧凑）；小屏：控件自动换行并 100% 宽
- 控件间距统一：12px；按钮组与控件对齐，不漂移

### 3) 表格子模块（必须继承 ADMIN_TABLE）
- 表格保持 `el-table` 形态，不做卡片化
- 窄屏必须包裹横向滚动容器：`overflow-x: auto; -webkit-overflow-scrolling: touch;`
- 操作列按钮统一尺寸（small/mini），主次清晰

### 4) 操作区（保存/发布/应用）
- 如果是长配置页：允许使用 `position: sticky; bottom: 0` 的操作条（背景不透明 + 分割线）
- 若 sticky 因父容器 overflow 失效：必须降级为普通 footer，不得破坏布局

## 响应式（必须）
- >= 1200px：配置项尽量一行；模块间距 16~20px
- 768~1200px：两列或一列自适应；按钮允许换行但对齐不乱
- < 768px：控件 100% 宽；表格横向滚动；标题层级保持稳定

## 输出自检（必须写入摘要）
- “本页面为 ADMIN_CONFIG：分区清晰 + 表单/表格对齐统一 + 信息密度保持 + 窄屏不挤版（表格可横向滚动）。”
