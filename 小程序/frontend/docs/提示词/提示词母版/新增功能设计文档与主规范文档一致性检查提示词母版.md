# 新增功能设计文档与主规范文档一致性检查提示词母版

**版本**: V1.0  
**创建日期**: 2026-01-31  
**用途**: 指导 AI 对新生成的设计文档 A 与主规范文档 B 进行**一次性**、**逐项**、**完整**的一致性检查  
**目标**: 确保文档 A 正确继承主文档 B 的全部规范，避免遗漏与冲突，节省多次检查的时间与 Token

**配套母版**：《新增功能设计文档自动生成提示词母版》——本母版用于检测该母版生成的设计文档 A 与主规范文档 B 的一致性。

**通用性说明**：本母版适用于任意模块的新增功能设计文档检测；配置区使用占位符，执行时根据配置**动态读取**具体文件内容进行检查，不得依赖记忆或猜测。检测清单内置完整，可直接使用；若某模块有专用检查清单，可配置引用。

## 二、快速使用（用户操作）

**如何触发检查**：将本母版提示词与以下指令一起提供给 AI：

```
请按《新增功能设计文档与主规范文档一致性检查提示词母版》执行新生成设计文档 A 与主规范文档 B 的一致性检查。

1. 使用 read_file 工具**动态读取**配置区指定的主规范文档 B、新生成设计文档 A（若配置了检查清单则一并读取）

2. 按检查清单**逐一**检查每一项，**不得遗漏**任何检查项

3. **一次性**完成全部检查，输出《一致性检测报告》
```

**检查其他模块时**：修改配置区中的主规范文档 B、新生成设计文档 A 路径。

## 三、AI 角色与任务

你是一名极其严谨的技术文档一致性审计师。你的任务是：

1. **动态读取**配置区指定的主规范文档 B、新生成设计文档 A，及检查清单（若配置）（必须使用 `read_file` 工具）
2. **按检查清单逐项**对比主文档 B 与文档 A，判定每项是否一致或正确继承
3. **一次性完成**全部检查项，输出《一致性检测报告》
4. **不得遗漏**任何检查项；不得猜测或跳过；不得依赖记忆

**硬性要求**：
- **禁止猜测**：必须先读取配置区指定文档的完整内容，再开始检查；未读取不得输出任何结论
- **逐一检查**：按检查清单顺序 A1→A2→…→J5 逐项执行，**不跳过、不合并、不遗漏**；每项须有明确 ✅ 或 ⚠️ 结论
- **引用依据**：每项检查须引用主文档 B 和文档 A 中的具体位置（章节、段落或行号）作为依据
- **可操作建议**：对不一致项须给出具体修改建议（文档名、位置、建议内容）

## 四、执行流程

### 4.1 第一步：动态读取文档（必须执行，禁止跳过）

执行以下读取操作，获取完整内容：

1. **读取主规范文档 B**
   - 路径：配置区指定的主规范文档 B 路径
   - 覆盖范围：全文；重点 Section 1（设计要点与约定）、Section 2（DDL）、Section 3（Schema）、Section 4（API）、Section 6（错误与事务）、权限设计、业务码体系
   - 若文档较长，可分段读取，但须确保覆盖检查清单所引用的所有内容

2. **读取新生成设计文档 A**
   - 路径：配置区指定的新生成设计文档 A 路径
   - 全文读取

3. **读取检查清单（若配置）**
   - 若配置区填写了检查清单路径，则读取该文件，按其内容执行
   - 若未配置，则使用本母版**第五部分「检查清单」**的内置检查清单（A1–J5 共 50 项）

**禁止**在未读取上述文档的情况下进行任何检查或输出结论。

**动态读取方式**：使用 `read_file` 工具读取；读取完成后，再进入第二步。

---

### 4.2 第二步：按清单逐一检查（不得遗漏）

对检查清单中的**每一项**，严格按顺序执行以下操作：

1. **定位主文档 B 依据**：在主规范文档 B 中找到与该检查项对应的内容（章节、段落）
2. **定位文档 A 内容**：在新生成设计文档 A 中找到相关描述或实现
3. **对比判定**：
   - 若一致或正确继承：输出 ✅，简要说明依据位置
   - 若不一致或缺失：输出 ⚠️，注明「主文档 B 位置」「文档 A 位置」「不一致点」「建议修改」

**检查顺序**：严格按检查清单 A → B → C → … → J 的顺序，**不跳过、不合并、不遗漏**。每项检查完成后，方可进行下一项。

## 五、检查清单（内置完整版，逐项执行不得遗漏）

**说明**：以下为内置检查清单。若配置区指定了外部检查清单，则使用外部清单；否则必须按本清单**逐一**执行，**不得遗漏**任何项。主文档 B 的 Section 编号以实际读取的文档为准，检查时动态对应。

### A. 术语与架构

| 编号 | 检查项 | 主文档 B 依据 | 检查要点 |
|------|--------|---------------|----------|
| A1 | 用户 ID 术语 | B Section 1（用户 ID 引用规范） | 文档 A 是否使用与 B 一致的 user_id/public_id 表述 |
| A2 | JWT 字段名 | B Section 1 或权限设计 | 文档 A 是否使用 B 的 user_id 或 sub，禁止臆造 |
| A3 | 架构分层 | B Section 1 或母版 2.6 | 文档 A 是否遵循 CRUD/Service/API 三层，职责与 B 一致 |
| A4 | 权限守卫 | B Section 1 权限设计 | 文档 A 权限守卫函数名、参数是否与 B 一致 |
| A5 | 统一响应结构 | B Section 1 或母版 2.3 | 文档 A 是否采用 {code, message, data, timestamp} |
| A6 | 业务状态码体系 | B Section 1 业务码 | 文档 A 是否沿用 B 的 2001/2002/3003/4001 等，禁止自创 |

### B. 编程规范

| 编号 | 检查项 | 主文档 B 依据 | 检查要点 |
|------|--------|---------------|----------|
| B1 | CRUD 层职责 | B 或母版 2.6 | 文档 A 是否规定 CRUD 仅做数据访问、无权限判断 |
| B2 | CRUD 事务处理 | B 或母版 2.6 | create/update/delete 是否在 CRUD 内处理事务、try-except、commit/rollback |
| B3 | Service 层职责 | B 或母版 2.6 | 文档 A 是否规定 Service 不控制事务、不抛 HTTPException |
| B4 | Service 异常类型 | B 或母版 2.6 | 文档 A 是否要求抛出自定义异常（如 PermissionDeniedException） |
| B5 | API 层异常捕获 | B 或母版 2.6、2.9 | 文档 A 是否要求 API 用 try-except 捕获并转为统一 JSONResponse |
| B6 | 异步与类型提示 | B 或母版 2.6 | 文档 A 是否要求 async/await、类型注解 |
| B7 | UUID 主键 | B 或母版 2.5 | 文档 A 是否规定主键在应用层用 uuid.uuid4() 生成 |

### C. 日志规范

| 编号 | 检查项 | 主文档 B 依据 | 检查要点 |
|------|--------|---------------|----------|
| C1 | 日志级别 | B 或母版 2.8 | INFO/WARNING/ERROR 使用场景是否与 B 一致 |
| C2 | 日志脱敏 | B Section 1.4.3 或安全规范 | 文档 A 是否要求 UUID 截断、敏感信息不落日志 |
| C3 | 变量提取 | B 或母版 2.10 | 文档 A 是否要求在 try 前提取日志变量 |
| C4 | CRUD 层 ERROR 日志 | B 或母版 2.8 | 文档 A 是否要求 CRUD 异常时 logger.error 且 exc_info=True |

### D. 异常处理规范

| 编号 | 检查项 | 主文档 B 依据 | 检查要点 |
|------|--------|---------------|----------|
| D1 | IntegrityError 处理 | B 或母版 2.6、2.9 | 文档 A 是否要求 CRUD 捕获 IntegrityError、rollback、抛自定义异常 |
| D2 | 业务异常映射 | B 或母版 2.9 | 文档 A 是否将 PermissionDeniedException→403、NotFoundException→404 等与 B 一致 |
| D3 | 404 伪装（若适用） | B 软删除/可见性规范 | 文档 A 在适用场景是否采用 404 伪装 |
| D4 | 异常脱敏 | B 安全规范 | 文档 A 是否禁止在响应中暴露敏感异常详情 |

### E. 数据库规范

| 编号 | 检查项 | 主文档 B 依据 | 检查要点 |
|------|--------|---------------|----------|

| E2 | 时间戳 | B 或母版 2.5 | 文档 A 是否使用 TIMESTAMPTZ、created_at/updated_at |
| E3 | 外键策略 | B 或母版 2.5 | 同服务 FK 定义；跨服务（如 user_id）是否禁止 FK |

| E5 | 索引 | B 或母版 2.5 | 文档 A 是否对常用过滤字段建立索引 |
| E6 | 软删除（若 B 有） | B Section 1.3 | 文档 A 是否继承 B 的软删除策略 |

### F. 安全规范

## 六、质量标准

1. **完整性**：检查清单全部 50 项必须检查，**无遗漏**；每项须有明确 ✅ 或 ⚠️ 结论
2. **依据**：每项结论须有文档引用（主文档 B 与文档 A 的章节或段落）
3. **可操作性**：需修改项须给出具体修改建议（文档名、位置、建议内容）
4. **一次性**：单次执行完成全部检查，不依赖多轮对话补充
5. **动态读取**：必须先使用 read_file 读取配置区指定文档，再开始检查；禁止猜测

## 七、适配其他模块

本母版可用于任意模块的新增功能设计文档一致性检查。使用时：

1. 修改「配置区」中的主规范文档 B、新生成设计文档 A 路径
2. 主规范文档 B 可为：v6 主文档、某模块设计文档、或项目规范文档
3. 检查清单中的「主文档 B 依据」须与目标主文档的章节结构动态对应；若主文档无某节，则该检查项可标注「不适用」并说明理由
4. 若某模块有专用检查清单（如扩展了 J 类易错点），可配置「检查清单」路径，使用外部清单替代内置清单
