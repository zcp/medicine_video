# 后端自动化代码提示词 → 前端自动化转化分析

**版本**: V1.0  
**日期**: 2026-09-03  
**依据**: 本目录已迁入的后端自动化文档 + 本仓 [AI-工作约定](../../AI-工作约定.md) / [前端规范样本](../../前端规范样本/) / 既有「阶段一～三」前端提示词  
**目标**: 说明如何把后端流水线改写成**前端可执行**的自动化代码提示词（本稿只做分析与映射，不直接改写母版全文）

---

## 1. 后端流水线在做什么（保留什么）

后端主控（[功能模块代码生成自动化流程主控提示词](功能模块代码生成自动化流程主控提示词.md)）核心骨架可复用：

| 可保留的机制 | 说明 |
|--------------|------|
| 主控 + 母版两级 | 主控管顺序与状态；母版管「生成什么提示词/代码」 |
| 配置区参数化 | `design_doc` / `module_name` / `output_base_dir` / `resume_from_step` |
| 断点续传 + 状态文件 | 每步 PENDING→COMPLETED；失败可续跑 |
| 一致性门禁 | 不通过不得进入下一代码生成步 |
| 最小修复 + 最大迭代 | `auto_fix` + `max_fix_iterations` |
| 规划师 / 执行者拆分 | 先产「模块提示词文档」，再产代码 |
| 设计文档为真相源 | 与本仓 §4.1 一致 |

**不要原样保留**：SQLAlchemy / Pydantic / CRUD / FastAPI Endpoint / pytest AsyncMock 等 Python 栈细节。

## 2. 分层映射（后端 → 本仓前端）

| 后端步骤 / 产物 | 前端对应产物 | 本仓落点（示例） |
|-----------------|--------------|------------------|
| SQLAlchemy Model | 领域类型 / 列表项类型 | `src/types/<module>.ts` |
| Pydantic Schema（Create/Update/Response） | 请求体 / 查询 / 响应 `data` 类型 | 同上；与设计文档字段表零偏差 |
| CRUD 层 | API 客户端函数（GET/POST/…） | `src/api/<module>.ts` |
| Service 层 | 页面编排逻辑 / Store action / 组合式函数 | `src/store/*`、`src/composables/*`、页内 setup |
| Endpoint / Router | 路由注册 + 页面入口 | `src/pages.json` + `src/pages/**` |
| API URL 一致性检查 | `config/api` + `api/*.ts` path ↔ 设计文档 Endpoint | [API URL一致性检查提示词母版](../提示词母版/API%20URL一致性检查提示词母版.md) 改配置区 |
| ORM↔Schema 一致性 | `types` ↔ 设计文档 Schema / 错误码 | 用「模型定义和api响应模型一致性」前端改写版 |
| 后端测试代码生成 | 页面/API/工具函数测试（或契约 mock 测） | `test/**`、既有 contentSafety 等测例风格 |
| 权限守卫（依赖注入） | 登录态、角色、管理端入口显隐、请求头 | `src/store/auth.ts`、`src/utils/request.ts`、管理页守卫 |

与既有阶段提示词对齐建议：

- **阶段一** ≈ types + api + request/config（≈ Model + Schema + CRUD 客户端）
- **阶段二** ≈ 可复用组件（≈ 无后端直接对应；保留本仓既有阶段二）
- **阶段三** ≈ pages + store 编排（≈ Service + Endpoint 的「消费端」）

## 3. 建议的前端自动化主控步骤（草案）

```text
前端设计文档（含体验钉 + Endpoint 字段表）
  → [F1] 生成 types/api 代码生成提示词文档
  → [F2] 生成/更新 src/types + src/api（严格按契约字段）
  → [F3] 一致性：types/api path/字段 ↔ 设计文档（门禁）
  → [F4] 生成 pages/store/components 提示词文档（按需）
  → [F5] 提示词文档风格一致性（对照阶段一～三 + 规范样本）
  → [F6] 生成页面/组件/Store 代码（最小改动；遵守文件创建规范）
  → [F7] 路由与入口：pages.json / 导航是否漏挂
  → [F8]（可选）测试提示词 → 测试代码 → 对齐修复主控
```

**硬门禁（相对后端多出来的本仓约束）**：

1. 动手前可见 [action-checklist](../../../.cursor/skills/action-checklist/SKILL.md)  
2. 改 `src/**` 必须摘录设计文档必要字段（[AI-工作约定 §4.1](../../AI-工作约定.md)）  
3. 前端设计须先过体验钉五问（§5.1），禁止只堆 Endpoint  
4. 管理端列表遵守 frontend Agent「管理端表面」  
5. 未确认的行业常见字段**不得** silently 入库

## 4. 配置区应如何改写（示例）

后端：

```text
project_path: live_core_service
output_base_dir: docs/提示词/直播核心功能模块
母版: SQLAlchemy / crud_service_endpoint
```

前端建议：

```text
project_path: .（本仓根）
design_doc: docs/Live-Saas-Wechat-<模块>-前端设计文档-vX.Y.md
backend_contract: docs/<编号>-后端设计文档.md（或增量）  # 冲突时清单写明以谁为准
module_name: tag | category | ...
output_base_dir: docs/提示词/前端模块/<module_name>
types_path: src/types/<module>.ts
api_path: src/api/<module>.ts
pages_glob: src/pages/admin/<module>/** 或 src/pages/...
规范强制引用:
  - docs/前端规范样本/通用规范-文件创建规范-v1.0.md
  - docs/前端规范样本/Vue3与项目编程规范.md
  - （按场景）列表/分页/表单/安全 等样本
```

## 5. `crud_service_endpoint` 母版 → 前端提示词母版提纲

把 [crud_service_endpoint代码生成提示词母版](crud_service_endpoint代码生成提示词母版.md) 的「学院派分层」改成：

| 原章节意图 | 前端改写要点 |
|------------|--------------|
| 角色：Python 后端架构师 | 角色：uni-app + Vue3 + TS 前端实现者；遵守本仓规范样本 |
| 目录结构 app/models/crud/… | `src/types` / `src/api` / `src/store` / `src/pages` / `src/components` |
| 异常 / HTTPException | `request` 统一错误、`uni.showToast`、内容安全错误展示口径 |
| success_response 结构 | 对齐网关 `data` 形状；禁止发明字段 |
| 事务 / db.commit | 前端无 DB 事务；改为「写后失效缓存 / 列表刷新 / Store 同步」 |
| 权限依赖 | Token、角色、管理端路由；UI 不替代服务端鉴权 |
| 测试：pytest Mock | 契约字段断言、列表空态/错态、关键路径交互 |

**产出命名建议**：

- `docs/提示词/前端模块/<模块>---types与api代码生成提示词.md`
- `docs/提示词/前端模块/<模块>---页面与Store代码生成提示词.md`
- `docs/提示词/前端模块/<模块>---测试代码生成提示词.md`

## 6. 自动化测试母版如何转前端

[测试对齐与修复自动化流程主控提示词](../自动化测试/测试对齐与修复自动化流程主控提示词.md) 可几乎原样保留流程哲学：

- 真相源 = 设计文档 / 接口契约  
- 测与实现不一致：优先修测；实现偏离契约：修实现  
- 禁止为过测弱化断言  

替换点：

| 后端 | 前端 |
|------|------|
| `tests/test_*.py` + conftest | 本仓 `test/**` 或后续约定的 vitest/uni 测目录 |
| Mock CRUD/Service | Mock `src/api` 或 MSW；页面用固件数据 |
| 增量不改坏测 | 同：只追加用例与 fixture |
| 数据库 UNIQUE / Faker | 前端测关注：表单校验、分页、空列表、401/403、内容安全错误文案 |

## 7. 建议落地顺序（最小化）

1. **先**用已迁「设计文档母版」写/改前端设计（体验钉 + 契约），不急着全自动写代码。  
2. **再**做一版「API URL / 字段一致性」检查提示词（改写 URL 母版），对本仓现有 `src/api` 试跑一轮。  
3. **然后**写「前端功能模块代码生成自动化流程主控」短文（可从后端主控删改，约保留 30% 骨架）。  
4. 与现有阶段一～三提示词**合并去重**，避免三套生成指令互相打架。  
5. 最后才考虑把主控挂进 `.cursor/skills`（须先改 [AI-工作约定](../../AI-工作约定.md)，再改 skill）。

## 8. 上游 skill/agent 方向问题（结论）

上游自动化偏「从设计文档一键生成整服务 Python 分层」。若本仓 skill 直接仿写，容易：

- 忽略体验钉与管理端表面  
- 用后端路径/字段习惯覆盖前端契约摘录  
- 把「执行报告堆」当成规范真源  

正确方向：**流程骨架可学，分层与落点必须前端化**；规范真源仍是本仓 AI 约定 + 前端规范样本 + 模块设计文档。
