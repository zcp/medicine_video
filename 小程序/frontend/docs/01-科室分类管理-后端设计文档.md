### 统一认证规范

本模块API接口使用以下认证级别：

- **公开访问（Public）**: 无需认证，任何人可访问（如：获取分类列表、获取单个分类）
- **JWT认证（JWT）**: 需要有效的JWT Token（如：管理端操作）
- **管理员权限（ADMIN）**: 需要JWT Token且角色为admin（如：创建、更新、删除分类）

### JWT Token格式说明

```json
{
  "user_id": "uuid-string",
  "username": "admin",
  "role": "admin",
  "exp": 1717756800
}
```

> **重要说明**: JWT Payload中用户标识字段为 `user_id`（非 `sub`），所有需要获取当前用户的接口均通过 `user_id` 字段提取用户身份。

### 业务状态码

| 状态码 | 说明 | 使用场景 |

| `200` | 成功 | 所有成功响应 |
| `1002` | 数据库错误 | 数据库操作异常 |
| `2001` | 资源不存在 | 分类ID不存在 |
| `2002` | 资源已存在 | 分类名称或slug重复 |

| `3002` | 权限不足 | 非管理员访问管理端接口 |
| `4001` | 参数校验失败 | 请求参数不符合规范 |

## 🎯 设计要点与约定

### 1.1 数据库设计规范

1. **UUID主键**: 所有表使用 `UUID` 类型作为主键，不使用自增ID
2. **时间戳**: 所有时间字段使用 `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
3. **外键约束**: 所有外键使用 `CONSTRAINT fk_<table>_<column>` 命名规范
4. **软删除**: `categories` 表使用 `is_active` 字段实现软删除，不物理删除数据
5. **索引策略**: 高频查询字段建立索引，命名规范 `idx_<table>_<column>`
6. **字段注释**: 所有表和关键字段使用 `COMMENT ON` 添加中文注释

### 1.2 API设计规范

1. **HTTP方法**: GET（查询）、POST（创建）、PATCH（部分更新）、DELETE（删除）
2. **URL路径**: 公开读 `/api/v1/content/categories`；管理写 `/api/v1/admin/categories`
3. **认证策略**: 公开读取 + 管理员写入
4. **执行流程**: 每个API包含8-10步详细执行流程说明

### 1.3 软删除策略

| 表名 | 策略 | 说明 |
|------|------|------|
| `categories` | `is_active` 字段 | 删除时设置 `is_active = false`，查询时默认过滤 |
| `live_room_categories` | 物理删除 | 关联关系解除时直接删除记录 |

### 1.4 安全与配置规范

#### 权限设计规范

**架构分层原则**:
- **API 层**: 仅负责认证（`Depends(get_current_user)` 或 `Depends(get_current_user_optional)`）
- **Service 层**: 负责授权（权限守卫函数）
- **CRUD 层**: 负责SQL级别的权限过滤（不使用内存过滤）

**双轨鉴权模式**:
- **严格鉴权（Strict Auth）**: 所有CUD操作，需要有效的JWT Token
- **可选鉴权（Optional Auth）**: 公开读取操作，允许匿名访问

**权限守卫函数**:

```python
def _check_admin_permission(user_role: str) -> None:
    """检查管理员权限，非管理员抛出403异常"""
    if user_role != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail={"code": 3002, "message": "权限不足：需要管理员权限"}
        )
```

**CRUD层权限过滤**:

```python
# 公开查询：默认只返回 is_active = true 的分类
async def get_categories(db: AsyncSession, include_inactive: bool = False):
    query = select(Category)
    if not include_inactive:
        query = query.where(Category.is_active == True)
    return await db.execute(query)
```

**用户身份提取规范**:

```python
async def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    """从JWT Token中提取用户身份"""
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    user_id = payload.get("user_id")  # 注意：是 user_id，非 sub
    if user_id is None:
        raise HTTPException(status_code=401, detail={"code": 3001, "message": "无效的Token"})
    return {"user_id": user_id, "role": payload.get("role")}
```

CREATE OR REPLACE FUNCTION trigger_set_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;

### 1.1 categories（科室分类表）

```sql
-- ==========================================================
-- 表：categories（科室分类表）
-- 说明：存储医学内容分类信息，支持图标、排序、软删除
-- ==========================================================

CREATE TABLE categories (
    id UUID PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) NOT NULL UNIQUE,
    icon VARCHAR(500),
    description TEXT,
    sort_order INTEGER NOT NULL DEFAULT 0,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 唯一索引：slug（用于URL友好标识）
CREATE UNIQUE INDEX idx_categories_slug ON categories(slug);

-- 普通索引：is_active（用于过滤活跃分类）
CREATE INDEX idx_categories_is_active ON categories(is_active);

-- 普通索引：sort_order（用于排序查询）
CREATE INDEX idx_categories_sort_order ON categories(sort_order);

-- 复合索引：is_active + sort_order（用于公开查询排序）
CREATE INDEX idx_categories_active_sort ON categories(is_active, sort_order);

-- 触发器：自动更新 updated_at
CREATE TRIGGER set_timestamp_categories
    BEFORE UPDATE ON categories
    FOR EACH ROW
    EXECUTE FUNCTION trigger_set_timestamp();

-- 表注释
COMMENT ON TABLE categories IS '科室分类表 - 存储医学内容分类信息';
COMMENT ON COLUMN categories.id IS '分类UUID主键';
COMMENT ON COLUMN categories.name IS '分类名称（如：肝胆胰外科）';
COMMENT ON COLUMN categories.slug IS 'URL友好标识（唯一）';
COMMENT ON COLUMN categories.icon IS '分类图标URL（可选）';
COMMENT ON COLUMN categories.description IS '分类描述';
COMMENT ON COLUMN categories.sort_order IS '排序权重（升序，数值越小越靠前）';
COMMENT ON COLUMN categories.is_active IS '是否启用（软删除标记）';
COMMENT ON COLUMN categories.created_at IS '创建时间（UTC）';
COMMENT ON COLUMN categories.updated_at IS '最后更新时间（UTC）';
```

### 1.2 live_room_categories（直播间-分类关联表）

```sql
-- ==========================================================
-- 表：live_room_categories（直播间-分类关联表）
-- 说明：直播间与分类的多对多关联关系
-- ==========================================================

CREATE TABLE live_room_categories (
    room_id UUID NOT NULL,
    category_id UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (room_id, category_id),
    CONSTRAINT fk_lrc_room FOREIGN KEY (room_id)
        REFERENCES live_rooms(id) ON DELETE CASCADE,
    CONSTRAINT fk_lrc_category FOREIGN KEY (category_id)
        REFERENCES categories(id) ON DELETE CASCADE
);

-- 索引：按分类查询关联的直播间
CREATE INDEX idx_lrc_category_id ON live_room_categories(category_id);

-- 索引：按直播间查询关联的分类
CREATE INDEX idx_lrc_room_id ON live_room_categories(room_id);

-- 表注释
COMMENT ON TABLE live_room_categories IS '直播间-分类关联表 - 多对多关系';
COMMENT ON COLUMN live_room_categories.room_id IS '直播间UUID（外键，级联删除）';
COMMENT ON COLUMN live_room_categories.category_id IS '分类UUID（外键，级联删除）';
COMMENT ON COLUMN live_room_categories.created_at IS '关联创建时间';
```

## 2. Pydantic Schemas定义

### 2.1 Category Schemas

```python
from pydantic import BaseModel, Field, ConfigDict, field_validator
from typing import Optional, List
from uuid import UUID
from datetime import datetime
import re


class CategoryBase(BaseModel):
    """分类基础Schema"""
    name: str = Field(..., min_length=1, max_length=100, description="分类名称")
    slug: str = Field(..., min_length=1, max_length=100, description="URL友好标识")
    icon: Optional[str] = Field(None, max_length=500, description="图标URL")
    description: Optional[str] = Field(None, description="分类描述")
    sort_order: int = Field(0, ge=0, description="排序权重")
    is_active: bool = Field(True, description="是否启用")

    @field_validator("slug")
    @classmethod
    def validate_slug(cls, v: str) -> str:
        """校验slug格式：仅允许小写字母、数字、连字符"""
        if not re.match(r"^[a-z0-9\-]+$", v):
            raise ValueError("slug 仅允许小写字母、数字和连字符")
        return v


class CategoryCreate(CategoryBase):
    """创建分类请求Schema"""
    pass


class CategoryUpdate(BaseModel):
    """更新分类请求Schema（全量更新）"""
    name: Optional[str] = Field(None, min_length=1, max_length=100)
    slug: Optional[str] = Field(None, min_length=1, max_length=100)
    icon: Optional[str] = Field(None, max_length=500)
    description: Optional[str] = None
    sort_order: Optional[int] = Field(None, ge=0)
    is_active: Optional[bool] = None

    model_config = ConfigDict(from_attributes=True)


class CategoryItem(CategoryBase):
    """分类响应Schema"""
    id: UUID
    created_at: datetime
    updated_at: datetime

    model_config = ConfigDict(from_attributes=True)


class CategoryListResponse(BaseModel):
    """分类列表响应Schema（统一分页格式）"""
    code: int = 200
    message: str = "success"
    data: dict  # {total, page, size, items: List[CategoryItem]}
    timestamp: datetime
```

### 3.1 Categories 模块API

5. **执行查询**: 异步执行数据库查询
6. **序列化响应**: 使用 `CategoryItem` Schema序列化结果
7. **返回响应**: 返回统一格式的JSON响应

**HTTP状态码**:
- `200 OK`: 查询成功

#### 3.1.3 管理端分页查询分类（JWT）

**Endpoint**: `GET /api/v1/admin/categories`

**描述**: 管理端分页查询分类列表，支持搜索和包含已禁用分类

**认证**: JWT认证 + 管理员权限

**请求参数 (Query)**:
- `page` (int, 可选, 默认1): 页码
- `page_size` (int, 可选, 默认20): 每页数量
- `q` (str, 可选): 搜索关键词（匹配name、slug、description）
- `include_inactive` (bool, 可选, 默认true): 是否包含已禁用的分类

**成功响应** (`200 OK`):
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 50,
    "page": 1,
    "size": 20,
    "items": [
      {
        "id": "uuid-string",
        "name": "肝胆胰外科",
        "slug": "hepatobiliary",
        "icon": "/uploads/categories/hepatobiliary.png",
        "description": "肝胆胰外科相关直播内容",
        "sort_order": 1,
        "is_active": true,
        "created_at": "2026-01-01T00:00:00Z",
        "updated_at": "2026-01-01T00:00:00Z"
      }
    ]
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收GET请求，解析Query参数
2. **JWT验证**: 通过 `Depends(get_current_user)` 提取当前用户
3. **权限检查**: 调用 `_check_admin_permission(user.role)` 校验管理员权限
4. **构建查询**: 使用SQLAlchemy构建SELECT查询
5. **搜索过滤**: 若 `q` 参数存在，添加 `WHERE name ILIKE :q OR slug ILIKE :q OR description ILIKE :q`
6. **分页**: 计算 `offset = (page - 1) * page_size`，添加 `LIMIT` 和 `OFFSET`
7. **执行查询**: 异步执行数据库查询，同时执行 `COUNT` 查询获取总数
8. **序列化响应**: 使用 `CategoryItem` Schema序列化结果
9. **返回响应**: 返回统一分页格式的JSON响应

**HTTP状态码**:
- `200 OK`: 查询成功
- `401 Unauthorized`: JWT Token无效（code=3001）
- `403 Forbidden`: 非管理员（code=3002）
- `500 Internal Server Error`: 数据库异常

## 5. 错误处理与事务管理

### 5.1 错误处理策略

**业务异常**:
- 资源不存在（code=2001）→ HTTP 404
- 资源冲突（code=2002）→ HTTP 409
- 业务逻辑错误（code=2004）→ HTTP 409

**系统异常**:
- 数据库连接失败 → HTTP 503
- 文件存储失败 → HTTP 500

**参数校验异常**:
- Pydantic校验失败 → HTTP 422（code=4001）

### 5.2 事务管理规范

**单表操作**: 使用单个事务，操作失败自动回滚

**多表操作**（如设置直播间分类关联）:
```python
async with db.begin():
    # 1. 删除旧关联
    await db.execute(delete(LiveRoomCategory).where(...))
    # 2. 批量插入新关联
    db.add_all(new_associations)
# 自动提交或回滚
```

**并发控制**: 使用数据库唯一约束（如 `slug UNIQUE`）防止并发创建冲突

## 6. 性能优化建议

### 6.1 数据库优化

- **索引优化**: `slug` 唯一索引加速slug查找；`(is_active, sort_order)` 复合索引加速公开查询
- **查询优化**: 公开查询只返回必要字段；分页查询使用 `LIMIT/OFFSET`
- **连接池**: 使用SQLAlchemy的 `async_session` 连接池管理

### 6.2 缓存策略

- **Redis缓存**: 公开分类列表可缓存5分钟（TTL=300s）
- **缓存键**: `categories:list:active`（公开列表）、`categories:detail:{id}`（单个详情）
- **缓存失效**: 创建/更新/删除分类时清除相关缓存

### 6.3 应用层优化

- **批量操作**: 设置直播间分类关联时使用 `executemany` 批量插入
- **异步处理**: 所有数据库操作使用 `async/await`
