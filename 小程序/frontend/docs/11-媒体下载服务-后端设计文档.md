## 📌 核心定位说明

### 1. 本文档的定位

本文档专注于**媒体下载服务（Media Download Service）**的完整后端实现设计，包括：

**包含模块**:
- **Download_Tasks（下载任务）**: HLS/MP4/图片资源的下载任务管理
- **Download_Failures（下载失败记录）**: 下载失败的分段记录和重试管理
- **Downloaded_Videos（已下载视频）**: 已下载完成的视频资源管理
- **Batch Import（批量导入）**: CSV批量导入下载任务

**模块范围**:
- 3张数据表（`download_tasks`、`download_failures`、`downloaded_videos`）
- 22个API接口（任务管理7个、失败记录8个、视频记录4个、批量导入3个）
- 完整的Pydantic Schemas定义
- 完整的数据库DDL及索引设计
- 独立微服务架构（端口8001）

### 2. 本文档的核心特点

- ✅ **独立微服务**: 媒体下载服务作为独立微服务运行（端口8001）
- ✅ **异步处理**: 使用Celery+Redis进行异步下载任务处理
- ✅ **智能重试**: 支持分段级别的智能重试策略
- ✅ **下载去重**: 支持API层和Worker层的下载去重
- ✅ **批量导入**: 支持CSV批量导入下载任务

### 3. 业务价值说明

**媒体下载服务**:
- 自动化下载HLS/MP4/图片等媒体资源
- 支持大规模并发下载
- 智能重试机制保证下载成功率
- 统一的视频资源管理

## 🎯 设计要点与约定

### 1.1 数据库设计规范

1. **UUID主键**: 所有表使用 `UUID` 类型作为主键
2. **时间戳**: 所有时间字段使用 `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
3. **CHECK约束**: 状态、类型等字段使用CHECK约束限制合法值
4. **索引策略**: 高频查询字段建立索引

### 1.2 API设计规范

1. **HTTP方法**: GET（查询）、POST（创建/操作）、PUT（更新）、DELETE（删除）
2. **URL路径**: 使用 `/api/v1/download/` 格式
3. **认证策略**: 所有API都需要JWT认证
4. **异步操作**: 下载启动、重试等操作通过Celery异步执行

### 1.3 软删除策略

| 表名 | 策略 | 说明 |
|------|------|------|
| `download_tasks` | 物理删除 | 删除任务时通过外键级联删除关联的失败记录 |
| `download_failures` | 物理删除 | 级联删除或定期清理（7天保留期） |
| `downloaded_videos` | 物理删除 | 视频记录删除时同时清理存储文件 |

```python
from pydantic import BaseModel, Field, ConfigDict
from typing import Optional, List
from uuid import UUID
from datetime import datetime
from enum import Enum


class TaskStatus(str, Enum):
    pending = "pending"
    processing = "processing"
    completed = "completed"
    partial_completed = "partial_completed"
    failed = "failed"
    cancelled = "cancelled"


class ResourceTypeEnum(str, Enum):
    m3u8 = "m3u8"
    ts = "ts"
    mp4 = "mp4"
    image = "image"


class DownloadTaskCreate(BaseModel):
    """创建下载任务请求Schema"""
    resource_url: str = Field(..., max_length=2000, description="资源URL")
    resource_type: ResourceTypeEnum = Field(..., description="资源类型")
    video_id: Optional[str] = Field(None, max_length=200, description="视频ID")
    liveroom_id: Optional[str] = Field(None, max_length=200, description="直播间ID")

    @field_validator("resource_url")
    @classmethod
    def validate_resource_url(cls, v: str) -> str:
        """校验资源URL格式"""
        if not v.startswith(("http://", "https://")):
            raise ValueError("资源URL必须以 http:// 或 https:// 开头")
        return v


class DownloadTaskItem(BaseModel):
    """下载任务响应Schema"""
    id: UUID
    user_id: UUID
    video_id: Optional[str] = None
    liveroom_id: Optional[str] = None
    resource_url: str
    resource_type: str
    status: str
    progress: float
    total_segments: int = 0
    downloaded_segments: int = 0
    failed_segments: int = 0
    storage_path: Optional[str] = None
    error_message: Optional[str] = None
    started_at: Optional[datetime] = None
    completed_at: Optional[datetime] = None
    created_at: datetime
    updated_at: datetime

    model_config = ConfigDict(from_attributes=True)


class TaskPageResult(BaseModel):
    """任务分页响应Schema"""
    items: List[DownloadTaskItem]
    total: int
    page: int
    page_size: int
```

## 3. API接口设计（完整CRUD）

### 3.1 任务管理API

#### 3.1.1 创建下载任务（JWT）

**Endpoint**: `POST /api/v1/download/tasks`

**描述**: 创建新的下载任务

**认证**: JWT认证

**请求体**:
```json
{
  "resource_url": "https://example.com/video.m3u8",
  "resource_type": "m3u8",
  "video_id": "video-123",
  "liveroom_id": "room-456"
}
```

**成功响应** (`201 Created`):
```json
{
  "code": 200,
  "message": "下载任务创建成功",
  "data": {
    "id": "new-uuid-string",
    "user_id": "user-uuid",
    "video_id": "video-123",
    "liveroom_id": "room-456",
    "resource_url": "https://example.com/video.m3u8",
    "resource_type": "m3u8",
    "status": "pending",
    "progress": 0.0,
    "created_at": "2026-06-07T10:00:00Z",
    "updated_at": "2026-06-07T10:00:00Z"
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收POST请求
2. **JWT验证**: 通过 `Depends(get_current_user)` 提取当前用户
3. **Pydantic校验**: 使用 `DownloadTaskCreate` Schema校验
4. **去重检查**: 查询是否已存在相同 `resource_url` 的任务
5. **生成UUID**: 生成新的UUID作为主键
6. **插入数据库**: `INSERT INTO download_tasks (...) VALUES (...)`
7. **提交事务**: `await db.commit()`
8. **返回响应**: 返回创建的任务信息

#### 3.1.2 获取任务列表（JWT）

**Endpoint**: `GET /api/v1/download/tasks`

**描述**: 获取当前用户的下载任务列表

**认证**: JWT认证

**请求参数 (Query)**:
- `page` (int, 可选, 默认1): 页码

## 4. 执行流程详细说明

### 4.1 创建下载任务完整流程

```
1. API路由接收POST请求
   → 2. JWT验证（Depends(get_current_user)）
   → 3. Pydantic校验（DownloadTaskCreate）
   → 4. 去重检查（SELECT WHERE resource_url = :url）
   → 5. 生成UUID
   → 6. 插入数据库（INSERT INTO download_tasks）
   → 7. 提交事务（db.commit()）
   → 8. 返回JSON响应（201 Created）
```

### 4.2 启动下载完整流程

```
1. API路由接收POST请求
   → 2. JWT验证
   → 3. 权限检查（verify_user_permission）
   → 4. 状态检查（status == pending/failed）
   → 5. Worker层去重检查（downloaded_videos表）
   → 6. 更新状态为processing
   → 7. 提交事务
   → 8. 发送Celery任务（download_task.delay(task_id)）
   → 9. 返回JSON响应
```

### 4.3 HLS下载完整流程（Celery Worker）

```
1. 接收Celery任务
   → 2. 解析m3u8文件，获取TS分段列表
   → 3. 创建下载失败记录表结构
   → 4. 使用ThreadPoolExecutor并发下载TS分段（max_workers=20）
   → 5. 每个分段下载：
      - 下载成功 → 更新progress
      - 下载失败 → 记录到download_failures表
   → 6. 汇总结果：
      - 失败分段 < 5% → 标记为completed
      - 失败分段 >= 5% → 标记为partial_completed
   → 7. 合并TS分段为完整视频文件
   → 8. 更新download_tasks状态和progress
   → 9. 创建downloaded_videos记录
```

### 4.4 CSV批量导入完整流程

```
1. API路由接收POST请求（multipart/form-data）
   → 2. JWT验证
   → 3. 解析CSV文件
   → 4. 提取所有任务的resource_url + liveroom_id组合
   → 5. 查询数据库中已存在的任务（批量查询）
   → 6. 计算新任务列表（CSV中的 - 数据库中已存在的）
   → 7. 批量插入新任务（executemany）
   → 8. 提交事务
   → 9. 返回导入结果统计
```

## 5. 错误处理与事务管理

### 5.1 错误处理策略

**业务异常**:
- 资源不存在（code=2001）→ HTTP 404
- 状态不允许操作（code=2004）→ HTTP 422

**系统异常**:
- 数据库连接失败 → HTTP 503
- Celery任务发送失败 → HTTP 500

### 5.2 事务管理规范

**单表操作**: 使用单个事务，操作失败自动回滚

**级联删除**: 删除任务时，关联的失败记录通过外键级联删除

### 5.3 并发控制

- **全局并发**: 最多100个同时下载任务
- **单任务并发**: 最多20个同时下载的TS分段
- **超时控制**: 单个分段下载超时30秒
