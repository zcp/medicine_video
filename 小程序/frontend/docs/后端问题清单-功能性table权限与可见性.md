# 功能性 table 权限与可见性问题清单（后端）

- 文档状态：进行中
- 更新时间：2026-01-30
- 最近一次复现验证：2026-01-30

- 问题概述：普通用户调用 tabs/table 接口返回空数据；后端当前仅返回管理员创建的功能性 table，且必须由“创建该功能性 table 的管理员”通过 tabs-admin 接口才能获取到。
- 现状确认：前端已统一使用公开接口 `/rooms/{room_id}/tabs`，管理员的 admin 接口暂不在直播间中调用。
- 影响范围：普通用户无法看到功能性 tabs/table，导致功能不可用、体验不一致。
- 复现步骤：
  1. 使用普通用户登录；
  2. 调用 tabs/table 普通接口；
  3. 返回空数据；
  4. 对比：使用创建者管理员账号调用 tabs-admin 接口可返回数据。
- 期望行为（后端需明确并实现其一或兼容）：
  - 允许具备查看权限的非管理员用户通过普通接口获取功能性 table；或
  - 若功能性 table 必须管理员专属，则对无权限用户返回明确错误码/业务码（而非空数据），并提供可授权机制（角色/标签/白名单等）。
- 后端改动建议：
  1. 在 tabs/table 普通接口增加权限判断与数据下发逻辑（支持可见范围/授权策略），从“创建者限定”调整为“拥有查看权限者”可获取；
  2. 在返回结构中加入可见性字段（如 `visibleTo`/`roles`/`permissions`），便于前端控制；
  3. 对无权用户返回明确错误（如 403 及业务码），避免“空数据”误导；
  4. 更新接口文档，说明权限模型与使用方式。
- 验收标准：
  - 被授权的普通用户通过普通接口可获取并展示功能性 table；
  - 未授权用户收到明确的无权限错误，而非空数据；
  - 管理员（创建者与非创建者）通过对应接口均可正常获取。
- 相关接口/前端调用点：
  - 后端：`tabs-admin`（当前可用）、`tabs/table`（需调整权限与返回策略）；
  - 前端：`src/api/tabs.ts`（调用处）。
- 风险与兼容性：确保不影响现有管理员流程；新增返回字段需与现有前端兼容（前端可按可见性字段进行展示控制）。
