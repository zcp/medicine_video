## 📌 核心定位说明

### 1. 变更背景

V1.1 设计约定留言响应嵌套：

```json
"user": { "nickname": "...", "avatar_url": "..." }
```

并假设 `JOIN room_messages + users`。现网 **users / live_core 分库**，无法直接 JOIN；实现侧仅把 JWT `nickname` 写入 `extra.user_display_name`，**无头像、无嵌套 `user`**，导致前端按设计读 `user.nickname` / `user.avatar_url` 时看不到用户信息。

### 2. 本次变更类型

- 【修改】JWT Access Token 可选携带 `avatar_url`（与既有 `nickname` 同级）
- 【修改】发留言时将昵称 + 头像写入 `live_room_messages.extra` 快照
- 【修改】POST/GET/WS/Admin 留言响应增加嵌套 `user`，保留 `user_display_name` 兼容

### 3. 核心原则

- ✅ **不改表结构**（复用现有 `extra` JSONB）
- ✅ **不做跨服务实时查用户**（列表/缓存友好）
- ✅ **向后兼容**（旧字段 `user_display_name` 保留）
- ✅ **快照语义**：留言展示发送当时的昵称/头像；用户改资料不影响历史留言

---

## 🎯 方案说明

```
登录/刷新 → JWT 含 nickname + avatar_url（可选）
     ↓
POST 留言 → extra = { user_display_name, avatar_url }
     ↓
GET / WS → 从 extra 组装 user: { nickname, avatar_url }
```

**不采用**：列表批量调 users 内部接口、跨库 JOIN、FDW。

## 🔌 响应契约（【修改】）

### POST / GET / WS `new_message`

```json
{
  "id": "...",
  "content": "...",
  "created_at": "...",
  "user_role": "REGULAR",
  "user_display_name": "张医生",
  "user": {
    "nickname": "张医生",
    "avatar_url": "/uploads/avatars/xxx.jpg"
  }
}
```

- `user` / `user_display_name` 均可为 `null`（历史留言无快照、或 JWT 当时无展示字段）
- 头像为空时前端使用默认头像

### JWT Access Payload（【修改】可选字段）

| 字段 | 说明 |
|------|------|
| `nickname` | 既有 |
| `avatar_url` | **新增**；无头像时不写入 |
| `username` | 既有 |

> 旧 Token 无 `avatar_url` 仍可发留言（仅昵称快照）；**refresh / 重新登录**后新 Token 带上头像。
