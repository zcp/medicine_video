## 一、背景与目标

### 1.1 问题

| 现状 | 后果 |
|------|------|
| V2.0 已把运营入口收到「专家分类」，同页仅支持根分类**改名** + 新建时自动 slug | slug / 描述 / 排序 / 停用分类仍依赖旧「科室分类管理」页 |
| 旧页入口已从个人中心、气泡菜单移除 | 细能力「悬空」：文件还在，运营进不去或不直观 |
| 双页长期并存 | 文案混淆（专家分类 vs 科室分类），维护两套表单 |

### 1.2 目标

1. 把旧页**必要**根分类细能力迁入「专家分类」。  
2. 用最小改动：优先复用 `CategoryFormDialog`，扩展分组行操作。  
3. 给出可执行的**退役顺序**，避免未迁完就删页。  
4. **本版（V2.1）不引入**分类 merge / 引用迁移；该类能力改由 [V2.2](./Live-Saas-Wechat-20-专家分类对齐main治理台-前端设计文档-v2.2.md) 规定，落地时须保留本文 Dialog 字段。

### 1.3 业务价值

- 运营只记一个入口：「专家分类」。  
- 《01》分类字段能力不丢。  
- 减少 Admin 菜单噪音，降低误改两处的风险。

## 二、范围定义

### 2.1 做什么（【新增】【修改】【废弃】）

| 类型 | 项 |
|------|-----|
| 【修改】 | 「专家分类」顶栏「新增根分类」/ 分组「编辑分类」改为打开 **`CategoryFormDialog`**（全字段） |
| 【新增】 | 分组行「停用」：确认后调 `deleteCategory`（后端软删 / `is_active=false`，以后端为准） |
| 【新增】 | 可选：顶栏或筛选「含已停用分类」；停用分组降透 +「已停用」标签；「启用」走 `updateCategory({ is_active: true })` |
| 【修改】 | 树模式分组排序：优先按分类 `sort_order` 升序，再渲染其下科室 |
| 【废弃·入口】 | 确认无残留菜单指向 `CategoryList`（Profile / 气泡已摘；全文再扫一遍） |
| 【废弃·页面】 | 迁完并通过测试后：`pages.json` 注销 `CategoryList`；删除或归档 `CategoryList.vue`（`CategoryFormDialog` **保留**，供专家分类复用） |

### 2.2 不做什么

| 永不做（本版） | 原因 |
|----------------|------|
| 分类 merge / migrate / 级联安顿向导 | **V2.1 本文不做**；解封与落点见 [V2.2](./Live-Saas-Wechat-20-专家分类对齐main治理台-前端设计文档-v2.2.md) |
| 图标上传若旧页未作为主路径强依赖 | 现网 `CategoryFormDialog` 无图标字段；不扩大范围。若《01》另有图标入口，本版不迁 |
| 重写第二套根分类表单 | 违背最小化 |
| 改 C 端 Tab / 公开 `getCategoryList` 契约 | 无需求 |
| 删除 `src/api/categories.ts` | C 端与房间选择器仍依赖 |

### 2.3 能力对照（旧页 → 专家分类）

| 旧「科室分类管理」 | 迁入后「专家分类」 | 说明 |
|--------------------|-------------------|------|
| 列表浏览分类 | 树模式分组行 = 分类浏览 | 无独立分类列表亦可 |
| 搜索分类名 | 不强制；可搜**科室**已有 | 分类数量少，分组可扫 |
| 新增分类 | 顶栏 → `CategoryFormDialog` create | 含 name/slug/描述/排序/启用 |
| 编辑分类 | 分组「编辑」→ 同 Dialog edit | 同上 |
| 删除/停用分类 | 分组「停用」+ 确认 | 文案用「停用」，与词条停用口径一致 |
| slug / 描述 / sort_order | Dialog 字段 | 复用旧表单，零偏差对齐《01》类型 |
| 分页拉 Admin 分类 | `getCategoryList` / 必要时 `getAdminCategories` | 树模式需能看见停用项时改 Admin 列表 |

## 三、术语与关键概念

| 术语 | 含义 |
|------|------|
| 根分类 | `categories` 记录；专家分类页分组标题 |
| 专家科室 / 词表 | `expert_departments`；挂在某个 `category_id` 下 |
| 停用分类 | 分类 `is_active=false`（软）；**不等于** Merge 词条，也**不等于**物理删库 |
| 退役 | 去掉独立 `CategoryList` 运营面；表单组件可留 |

## 四、核心流程

### 4.1 新增根分类

```text
专家分类 →「新增根分类」
  → CategoryFormDialog（create）
  → createCategory({ name, slug?, description?, sort_order?, is_active? })
  → 关闭弹窗 → loadCategories + 刷新词表分组
```

### 4.2 编辑根分类

```text
分组行「编辑」
  → CategoryFormDialog（edit，initialData=该分类完整字段）
  → updateCategory(id, patch)
  → 刷新分类缓存与分组标题 / 排序
```

### 4.3 停用 / 启用根分类

```text
分组行「停用」
  → Modal：说明「停用后 C 端默认不可见；其下词条仍在，新建词条勿再挂此分类」
  → deleteCategory(id) 或 updateCategory({ is_active:false })（与现网 CategoryList 一致，优先复用现网 deleteCategory）
  → 刷新

已停用分组「启用」
  → updateCategory({ is_active:true })
  → 刷新
```

### 4.4 退役旧页

```text
细能力上线并自测通过
  → 确认无菜单/深链依赖 CategoryList
  → pages.json 移除路由
  → 删除 CategoryList.vue（保留 CategoryFormDialog.vue）
  → 《01》前端文档补一句：Admin 运营面由《20》专家分类承接
```

## 五、页面与交互设计

### 5.1 专家分类页（在 V2.0 布局上增量）

```text
┌──────────────────────────────────────────┐
│ 专家分类  [选择] [新增根分类]              │
├──────────────────────────────────────────┤
│ 🔍 搜索科室...     [启用中词条▾] [分类:全部▾]│  ← 分类筛可选：全部/仅启用/含停用
├──────────────────────────────────────────┤
│ ▼ 普通外科  排序0  12个科室  [编辑][停用]   │
│   · 词条行…                               │
│   ── [＋ 新增科室] ──                     │
│ ▼ 心内科(已停用)  …          [编辑][启用]  │  ← 仅「含停用」时出现
└──────────────────────────────────────────┘
```

### 5.2 交互规则

| 规则 | 说明 |
|------|------|
| 表单唯一入口 | 禁止再维护专家分类页内简易 `catForm`（name+slug）；【修改】为 Dialog |
| 停用确认 | 若 `expert_count` 汇总 > 0 或组下词条数 > 0，文案加粗提示「其下仍有科室词条」 |
| 已停用分类下「＋新增科室」 | **隐藏**或点击 Toast「请先启用分类」 |
| 词条「改分类」picker | 默认只列 `is_active` 分类；与现网一致 |
| 选择模式 | 仍只针对**词条**待审，不勾选分类行 |

### 5.3 加载分类数据

| 场景 | 数据源 |
|------|--------|
| 默认树 | 启用分类 + 当前词条列表分组（V2.0 已有） |
| 含停用 | `getAdminCategories({ is_active: false })` 或列表不过滤；与启用集合并去重 |
| 编辑回填 | 须有 `slug/description/sort_order/is_active`；若公开列表字段不全，编辑前 `getAdminCategoryDetail(id)` 【按需】 |

> 最小路径：树数据改为 `getAdminCategories` 一次拉取（含停用可筛），避免公开列表缺字段。

## 七、数据结构与字段约定

沿用《01》/ 本仓 `Category`：

| 字段 | 表单 | 说明 |
|------|------|------|
| `name` | 必填 | 1–100 |
| `slug` | 可选（创建建议有；可空则沿用现 Dialog 逻辑） | 小写字母数字连字符 |
| `description` | 可选 | ≤500 |
| `sort_order` | 可选，默认 0 | 越小越靠前 |
| `is_active` | switch | 启用状态 |

无新后端字段；**零偏差**复用既有 Admin categories API。

## 八、API 封装约定

| 用途 | 函数 | 备注 |
|------|------|------|
| 创建 | `createCategory` | 已有 |
| 更新 | `updateCategory` | PATCH；含 `is_active: true` 启用 |
| 停用 | `deleteCategory` | 与 CategoryList 现网一致 |
| 列表 | `getAdminCategories` / `getCategoryList` | 含停用时优先 Admin |
| 详情 | `getAdminCategoryDetail` | 编辑回填字段不足时用 |

无新路由。

## 十、错误处理与兜底

| 情况 | 处理 |
|------|------|
| 停用失败（如 FK RESTRICT / 业务码） | Toast 后端/`getUserFacingErrorMessage`；不本地假删分组 |
