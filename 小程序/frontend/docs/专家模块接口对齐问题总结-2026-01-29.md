# 专家模块接口对齐问题总结（发送给后端）

时间标注：2026-01-29 18:30 CST（UTC 2026-01-29T10:30Z）

## 背景
- 前端在接入“专家详情页（ExpertDetail）”时，出现 404 与数据结构不一致问题。
- 目标：定位“文档 vs 实现”的差异，明确整改项，给出验收标准。

## 现象与复现
- 场景：从“专家列表”进入“专家详情页”。
- 复现请求：
  - 详情（professors 路径）：GET /api/v1/professors/{expert_id} → 404
  - 场次（professors 路径）：GET /api/v1/professors/{expert_id}/sessions?page=1&size=50 → 404
  - 详情（experts 路径）：GET /api/v1/experts/{expert_id} → 200（成功）
  - 场次（experts 路径）：GET /api/v1/experts/{expert_id}/sessions → 200，但返回体结构与文档分页规范不一致，前端最初按 `{ items: [...] }` 解析导致运行时异常（TypeError: Cannot read property 'map' of undefined）。

## 环境与网关
- Base URL：VITE_BASE_API_URL=https://mp.dayilive.com/api/core/
- 请求封装会将以 `/api/v1/*` 开头的路径规范化为 `/api/core/*`（见 [src/utils/request.ts](../src/utils/request.ts)）。
- 因此完整请求示例：
  - https://mp.dayilive.com/api/core/experts/{id}
  - https://mp.dayilive.com/api/core/experts/{id}/sessions
  - https://mp.dayilive.com/api/core/professors/{id}（404）

## 文档 vs 实现（对比分析）
- 资源命名：
  - 文档中存在 `professors` 聚合端点描述（如：GET /api/v1/professors/{expert_id}/content）。
  - 实际实现仅有 `experts` 相关端点（/experts/{id}、/experts/{id}/sessions）。
- 端点形态：
  - 文档包含“聚合端点” `/professors/{id}/content`（专家信息 + 场次分页）。
  - 实际实现采用“拆分端点” `/experts/{id}` 与 `/experts/{id}/sessions`。
- 响应结构：
  - 文档规范分页响应统一为 `{ total, page, size, items }`。
  - 实际 `/experts/{id}/sessions` 返回体不是该分页对象（前端收到的 `data.items` 缺失）。

## 结论
1) 后端当前未提供 `professors` 路由；应以 `experts` 为准。
2) 文档与实现存在差异：名称（professors vs experts）、端点形态（聚合 vs 拆分）、分页结构（items 缺失）。
3) 该差异导致前端页面调用 `/content` 404、并在 sessions 解析时报错。

## 整改建议（行动清单）
建议统一采用“experts + 拆分端点”，并修正文档；如需保留聚合端点，另见方案B。

- 资源名统一（P0）
  - 确认统一使用 `experts`，废弃 `professors` 的文档描述与实现。

- 端点与响应（P0）
  - 详情：GET `/api/v1/experts/{expert_id}` → 200
  - 场次分页：GET `/api/v1/experts/{expert_id}/sessions?page&size`
    - 响应示例：
      ```json
      {
        "code": 200,
        "message": "success",
        "data": {
          "total": 123,
          "page": 1,
          "size": 50,
          "items": [
            {
              "id": "session_uuid",
              "room_title": "……",
              "summary": "……",
              "status": "scheduled|live|ended",
              "start_time": "2026-01-29T08:00:00Z",
              "cover_url": "/media/.../cover.jpg"
            }
          ]
        },
        "timestamp": "2026-01-29T10:30:00Z"
      }
      ```
    - 说明：字段名与前端现有映射保持一致（`room_title`、`cover_url`、`status`、`start_time`）。

- 方案B（可选）：若坚持聚合端点
  - 新增：GET `/api/v1/experts/{expert_id}/content`
  - data 结构：`{ expert_info: {...}, sessions: { total,page,size,items } }`
  - 保持与“拆分端点”相同的字段命名与分页规范。

- 文档修正（P1）
  - 在《直播核心功能设计文档_v6_后端新增api接口和模块设计文档-v2.md》中：
    - 统一资源名为 `experts`。
    - 明确采用“拆分端点”或“聚合端点”的最终方案（建议拆分，聚合作为可选增强）。
    - 全量更新示例响应，确保分页统一为 `{ total, page, size, items }`。

## 验收标准
1) 访问 GET `/api/v1/experts/{id}` 返回 200，`data.id=={id}`。
2) 访问 GET `/api/v1/experts/{id}/sessions?page=1&size=50` 返回 200，且 `data.items` 为数组、`data.total`、`data.page`、`data.size` 存在。
3) 前端页面“专家详情 + 直播列表”无 404、无运行时错误；列表可正常渲染。
