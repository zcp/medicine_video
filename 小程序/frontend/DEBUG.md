# 🐛 调试指南

## 📋 开发模式 vs 生产模式

### **开发模式** (推荐用于调试)
```bash
# 开发模式启动 (代码不压缩，便于调试)
npm run dev:mp-weixin

# 或者使用专门的调试模式
npm run dev:debug
```

**特点:**
- ✅ **代码不压缩** - 保持换行和格式化
- ✅ **完整的变量名** - 不会混淆函数和变量名
- ✅ **sourcemap支持** - 映射到原始源代码
- ✅ **详细的错误信息** - 包含完整的堆栈跟踪

### **生产模式** (发布时使用)
```bash
# 生产模式构建 (代码压缩，优化性能)
npm run build:mp-weixin
```

**特点:**
- 🔥 **代码压缩** - 减小文件大小
- 🔥 **性能优化** - 提升加载速度
- ❌ **调试困难** - 代码被压缩混淆

## 🔧 微信开发者工具调试技巧

### **1. 开启调试模式**
1. 打开微信开发者工具
2. 导入项目：`d:\Live-Saas-Wechat\dist\dev\mp-weixin`
3. 点击右上角 "详情" → "本地设置"
4. 勾选以下选项：
   - ✅ **不校验合法域名、web-view(业务域名)、TLS 版本以及 HTTPS 证书**
   - ✅ **开启调试**
   - ✅ **开启热重载**

### **2. 使用调试器**
1. 点击 "调试器" 标签
2. 在 **Console** 面板查看日志输出
3. 在 **Sources** 面板设置断点
4. 在 **Network** 面板查看网络请求

### **3. 查看源代码**
- **编译后代码**: `dist/dev/mp-weixin/` 目录
- **原始代码**: `src/` 目录
- **映射关系**: 通过sourcemap自动关联

## 🐛 错误定位流程

### **JavaScript 错误**
1. **查看控制台** - 微信开发者工具的Console面板
2. **定位文件** - 错误信息会显示文件名和行号
3. **源码映射** - 点击错误链接直接跳转到源代码
4. **设置断点** - 在Sources面板打断点调试

### **样式问题**
1. **检查样式** - 使用wxml面板查看元素
2. **样式调试** - 在Elements面板修改样式测试
3. **源文件修改** - 在对应的.vue文件中修改样式

### **网络请求问题**
1. **Network面板** - 查看所有网络请求
2. **查看详情** - 点击请求查看Headers、Response
3. **API调试** - 使用调试器断点调试API调用

## 📁 文件结构说明

```
项目结构:
├── src/                    # 📝 源代码 (你编辑的文件)
│   ├── pages/index/index.vue
│   ├── App.vue
│   └── ...
├── dist/dev/mp-weixin/     # 🔧 编译后代码 (调试用)
│   ├── pages/index/index.js    ← 未压缩，便于调试
│   ├── app.js                  ← 未压缩，便于调试
│   └── ...
└── dist/build/mp-weixin/   # 🚀 生产代码 (发布用)
    ├── pages/index/index.js    ← 已压缩，体积小
    ├── app.js                  ← 已压缩，体积小
    └── ...
```

**调试规律:**
- 🐛 **遇到错误** → 查看 `dist/dev/mp-weixin/` 目录下的文件
- ✏️ **修改代码** → 编辑 `src/` 目录下的文件
- 🔄 **自动重编译** → 保存后自动更新 `dist/dev/` 目录

## 💡 调试提示

### **✅ 最佳实践**
- 始终使用 `npm run dev:mp-weixin` 进行开发
- 在源文件(`src/`)中编辑，不要直接修改`dist/`目录
- 利用微信开发者工具的断点功能
- 使用`console.log()`输出调试信息

### **⚠️ 注意事项**  
- `dist/`目录会被自动覆盖，不要直接编辑
- 生产构建时会自动压缩代码
- sourcemap仅在开发模式启用

### **🔍 错误追踪技巧**
- 使用具体的`console.log`标识不同位置
- 为复杂逻辑添加中间状态日志
- 利用`try...catch`捕获和定位错误
