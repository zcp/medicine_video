# 代码检查清单

## 一、命名规范检查

### 1.1 文件命名
- [ ] 使用小写字母
- [ ] 使用下划线分隔单词
- [ ] 文件名具有描述性
- [ ] 避免使用特殊字符

### 1.2 类命名
- [ ] 使用大驼峰命名法
- [ ] 类名具有描述性
- [ ] 避免使用缩写（除非是通用缩写）
- [ ] 继承关系在命名中体现

### 1.3 函数命名
- [ ] 使用小写字母
- [ ] 使用下划线分隔单词
- [ ] 函数名是动词或动词短语
- [ ] 函数名具有描述性

### 1.4 变量命名
- [ ] 使用小写字母
- [ ] 使用下划线分隔单词
- [ ] 变量名具有描述性
- [ ] 避免使用单字母（除非是循环变量）

### 1.5 常量命名
- [ ] 使用大写字母
- [ ] 使用下划线分隔单词
- [ ] 常量名具有描述性
- [ ] 在模块级别定义

## 二、注释规范检查

### 2.1 文件头部注释
- [ ] 包含文件描述
- [ ] 包含作者信息
- [ ] 包含创建时间
- [ ] 包含修改历史（如果有）

### 2.2 类注释
- [ ] 包含类的功能描述
- [ ] 包含使用示例
- [ ] 包含属性说明
- [ ] 包含方法说明

### 2.3 函数注释
- [ ] 包含功能描述
- [ ] 包含参数说明
- [ ] 包含返回值说明
- [ ] 包含异常说明

### 2.4 关键代码注释
- [ ] 复杂逻辑有注释说明
- [ ] 特殊处理有注释说明
- [ ] 注释与代码同步更新
- [ ] 注释清晰易懂

## 三、代码格式检查

### 3.1 缩进
- [ ] 使用4个空格缩进
- [ ] 不使用Tab
- [ ] 缩进层级不超过4层
- [ ] 保持一致的缩进风格

### 3.2 行长度
- [ ] 每行不超过120字符
- [ ] 长行适当换行
- [ ] 换行保持缩进
- [ ] 运算符在行尾

### 3.3 空行
- [ ] 使用空行分隔逻辑块
- [ ] 类定义前后有空行
- [ ] 函数定义前后有空行
- [ ] 相关代码块之间有空行

### 3.4 空格
- [ ] 运算符两侧有空格
- [ ] 逗号后有空格
- [ ] 冒号后有空格
- [ ] 括号内没有多余空格

## 四、异常处理检查

### 4.1 异常类型
- [ ] 使用自定义异常类型
- [ ] 异常类型层次合理
- [ ] 异常名称具有描述性
- [ ] 避免使用通用异常

### 4.2 异常处理

### 4.3 错误码
