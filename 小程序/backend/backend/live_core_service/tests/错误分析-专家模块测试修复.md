## 错误1: LiveSession创建失败

**错误信息**:
```
TypeError: 'description' is an invalid keyword argument for LiveSession
```

**错误原因**:
1. `create_test_session`函数（第66行）使用了`description`字段
2. `LiveSession`模型中**不存在**`description`字段
3. `LiveSession`模型的必需字段是：`room_id`, `status`, `start_time`
4. 测试代码缺少必需字段`start_time`

**解决方案**:
修改`create_test_session`函数（第59-78行）：
- **删除**: `description`字段
- **添加**: `start_time`字段（必需）
- **添加**: 自动创建`LiveRoom`的逻辑（如果未提供room_id）

**修复代码**:
```python
async def create_test_session(db: AsyncSession, **kwargs):
    """创建测试LiveSession的辅助函数"""
    from app.models.live_core import LiveSession, LiveSessionStatus, LiveRoom
    from datetime import datetime
    
    # 如果没有提供room_id，先创建一个LiveRoom
    if 'room_id' not in kwargs:
        room = LiveRoom(
            id=uuid.uuid4(),
            user_id=uuid.uuid4(),
            title=f"测试房间_{uuid.uuid4().hex[:8]}",
            stream_key=f"stream_key_{uuid.uuid4().hex[:16]}"
        )
        db.add(room)
        await db.flush()
        kwargs['room_id'] = room.id
    
    default_data = {
        "status": LiveSessionStatus.SCHEDULED,
        "start_time": datetime.now()  # ✅ 必需字段
    }
    session_data = {**default_data, **kwargs}
    
    session = LiveSession(
        id=uuid.uuid4(),
        **session_data
    )
    db.add(session)
    await db.flush()
    await db.refresh(session)
    return session
```

**错误信息**:
```

```

**错误原因**:
1. 测试代码第240行使用了`await db.commit()`

**修复关键**:
```python
# ❌ 错误

# 验证我们创建的推荐专家的排序
```

## 错误3: test_get_experts_multi_and_total_with_sort 排序测试失败

**错误信息**:
```
AssertionError: Expected 2 experts, found 1
```

**错误原因**:
1. 测试代码第329行和332行使用了`await db.commit()`
2. 创建expert1后立即commit，然后创建expert2
3. commit可能导致会话状态混乱
4. 两个专家的created_at时间戳可能相同（创建速度太快）

**解决方案**:
- **删除**: 第329行和332行的`await db.commit()`
- **添加**: 使用`await asyncio.sleep(0.01)`确保时间戳不同

**修复关键**:
```python
expert1 = await create_test_expert(db, name=f"A专家{unique_suffix}")
# ❌ 删除: await db.commit()

# ✅ 添加延迟确保created_at不同
await asyncio.sleep(0.01)

expert2 = await create_test_expert(db, name=f"B专家{unique_suffix}")
# ❌ 删除: await db.commit()
```

## 错误4: test_update_expert_duplicate_user_id 未抛出预期异常

**错误信息**:
```
Failed: DID NOT RAISE <class 'app.exceptions.DatabaseIntegrityException'>
```

**错误原因**:
1. **根本原因**: `ExpertUpdate` schema缺少`user_id`字段
2. 测试代码第424行创建`ExpertUpdate(user_id=user_id1)`
3. 但`ExpertUpdate` schema中没有定义`user_id`字段
4. Pydantic忽略了未定义的字段，导致update操作没有修改user_id
5. 因此不会触发唯一性约束冲突

**解决方案**:
在`app/schemas/experts.py`的`ExpertUpdate`类中添加`user_id`字段：

```python
class ExpertUpdate(BaseModel):
    """更新专家请求Schema（部分更新）"""
    model_config = ConfigDict(from_attributes=True)
    
    user_id: Optional[uuid.UUID] = Field(None, description="关联用户ID（可选）")  # ✅ 添加此字段
    name: Optional[str] = Field(None, min_length=1, max_length=120, description="专家姓名")
    # ... 其他字段
```

**注意**: 
- 这个测试的commit（第419、421、429行）是**必需的**，因为要测试唯一性约束冲突
- 这是测试commit的特殊场景之一
