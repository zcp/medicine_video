## 剩余问题 (3个) - 根本原因分析

### 问题根源：数据库残留 + CRUD函数的rollback行为

从测试日志可以看到：
```
INFO:sqlalchemy.engine.Engine:INSERT INTO experts (...)
INFO:sqlalchemy.engine.Engine:ROLLBACK  # ← 注意这里！
```

**关键发现**：
1. 数据库中已有397条featured专家记录（旧数据未清理）
2. `create_expert` CRUD函数在flush时捕获`IntegrityError`并rollback
3. 测试创建的新专家被rollback了，导致在查询结果中找不到

**为什么会触发IntegrityError？**
- 数据库中有大量旧的专家记录
- 某些字段（如`user_id`）可能与旧数据冲突
- 导致`create_expert`函数捕获异常并rollback

## 核心教训

### 1. 测试隔离的重要性
- ❌ **错误做法**: 在测试中使用`await db.commit()`
- ✅ **正确做法**: 依赖fixture的自动rollback
- ⚠️ **例外**: 测试唯一性约束时必须commit

### 2. 测试数据的唯一性
- ❌ **错误做法**: 使用简单的硬编码值（如"专家1"）
- ✅ **正确做法**: 使用UUID或Faker生成唯一值
- ⚠️ **注意**: 即使使用Faker，也要添加UUID后缀

### 3. CRUD函数的异常处理
- `create_expert`函数捕获`IntegrityError`并rollback
- 如果字段与数据库冲突，整个操作会被回滚
- 测试必须确保字段值唯一，避免触发回滚

### 4. 数据库维护
- 定期清理测试数据库
- 或者在测试前清空相关表
- 避免累积过多旧数据影响测试
