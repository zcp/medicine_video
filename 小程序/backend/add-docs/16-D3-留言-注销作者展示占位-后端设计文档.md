## 📌 核心定位说明

### 1. 本文档的定位

**留言正文不动**；作者已注销时展示名强制「账号已注销」，头像 `null`。

**模块范围**: 只改读路径组装；0 新表（标记由 D2 提供）。

### 2. 核心特点

- ✅ 产品定案：正文不动 + 账号占位  
- ✅ 与 V4：未注销看**个人中心当前资料**；注销用**本服务标记**覆盖展示  
- ✅ 不依赖 D1；活跃作者 batch 由 07-V4 负责，本包只做注销覆盖  

### 3. 业务价值

公开讨论可留存；已注销身份不再装活人。

## 🎯 设计要点与约定

### 1.1 与 V4 读时同步的关系（必读）

| 场景 | 展示名 | 头像 |
|------|--------|------|
| 作者未在已注销标记中 | **个人中心当前**（07-V4；batch 失败降级 extra 快照） | **个人中心当前**（同上） |
| 作者在已注销标记中 | **「账号已注销」** | **`null`** |

> 组装顺序：**快照兜底 → V4 live → 本包 D3 覆盖**。

### 1.2 变更决策记录（V1.1）

#### 决策 1：如何知道已注销

| 方案 | 结论 |
|------|------|
| D2 写本服务标记，读路径查标记 | ✅ **P0** |
| 按页 batch users.status | ❌ 放弃 |
| 回写全部留言 extra | ❌ 放弃 |

#### 决策 2：头像

| 方案 | 结论 |
|------|------|
| 继续露出快照头像 | ❌ |
| `avatar_url=null` + 前端默认图 | ✅ **写死** |

#### 决策 3：兼容字段

- `user.nickname` = `账号已注销`
- `user_display_name`（若仍返回）= 同步为 `账号已注销`
- `user.avatar_url` = `null`

## 3. API 接口设计

### 3.1 【修改】留言列表（代表性）

**Endpoint**: `GET /api/v1/rooms/{room_id}/messages`（以现网真实路径为准）

**描述**: 分页返回留言；对本页作者查**本地已注销标记**后覆盖展示。

**认证**: 维持现网（Public / Optional / JWT）

**执行流程**:

1. 查留言页（现网）  
2. 收集本页 `user_id` 去重  
3. **本地**查询哪些 id 在 `deactivated_users`（Redis SISMEMBER 批量 / 或 SQL `IN`）  
4. 按 V3 从 extra 组装 `user`  
5. 若已注销 → 覆盖昵称/头像  
6. 标记不可用 → **降级快照**，打 warning，不 500  
7. 返回；**不写库**

**HTTP状态码**: 维持留言模块既有。

---

### 3.2 【修改】Admin 留言列表

**Endpoint**: 现网 Admin messages 路径

**P0**: 与 C 端同一覆盖规则。  
**P1（可选）**: 增加 `author_snapshot_nickname` 仅 Admin 可见，便于审计。

**执行流程**: 同 §3.1。

### 3.3 WS `new_message`

**说明**: 发送瞬间作者未注销，推送仍为快照即可。  
用户注销后，**新拉列表**走 §3.1 覆盖；不必给历史消息广播「改名」事件（P2 可做）。

## 4. 执行流程详细说明

### 4.1 读路径覆盖

```
1. 查 messages 页
2. 本地查 deactivated 标记
3. 命中则昵称占位、头像 null；content 不变
4. 返回
```

### 4.2 与 D2 关系

```
D2 cleanup → 写标记 + 清私货（不删留言）

```
