## 📌 核心定位说明

### 1. 本文档做什么

在规则引擎与《13》32 类词库之上，补齐分层治理，并**对整库逐类做误杀审计**：

| 层级 | 含义 | V1.1 |
|------|------|------|
| L0 规范化 | `normalize_text()` | ✅ 已有 |
| L1 红线硬拦 | 政治/涉赌毒/硬虚假承诺等 | ✅ 保留 block |
| L2 词表精度 | 删裸词 / 短语化 / **分类白名单** | 【修改】整库 |
| L3 场景分档 | A/B/C/D/E | 【新增】 |
| L4 处置梯度 | allow / warn / block 按档 | 【修改】 |
| L5 人工闭环 | 处理记录 → 加白/降级 | 【修改】 |
| L6–L7 | 厂商 API / 自研模型 | P2 / 不做 |

### 2. 业务前提（影响整库策略）

本产品为**医学科普 / 专家直播**向 SaaS，开播与资料文案中出现「治疗、降压、养胃」等**科普讨论**是常态，不等于广告法意义上的违法医疗广告。

因此：

- **不能**把广告违禁词表无差别打在 A/B 档日常 UGC 上  
- **C 档（商品货架）**才是广告法极限词 / 功效宣称的主战场  
- ✅ **通览**：§2.5 一表看齐 32 类档位 / DROP / pattern / 白名单 / 验收句
### 3. 词表治理四招（全文统一）

| 招数 | 代号 | 含义 |
|------|------|------|
| 删除裸词 | **DROP** | 从 `pattern` 去掉过短/过高歧义词 |
| 改为短语 | **PHRASE** | 用更长、更高置信组合替代 |
| 分类白名单 | **WHITE** | 命中后若原文含白名单短语，**仅撤销该类**命中 |
| 按档处置 | **TIER** | 词保留，A/B/C/D 用不同 action |

> 白名单一律**按 `rule_category` 作用域**生效，避免「第一次」放行时把政治类一并放掉。

## 1. 【新增】场景分档

### 1.1 分档定义

| 档 | 名称 | 取向 |
|----|------|------|
| **A** | 开播/互动 UGC | 宜松：短语 + 高歧义 warn；科普词勿裸拦 |
| **B** | 资料/长文 | 中等：硬功效可严；日常医疗讨论仍可 warn |
| **C** | 商业货架 | 宜严：广告法主战场 block |
| **D** | 搜索/`tab_key` | 弱：红线+引流；广告医学大类少 seed |
| **E** | 图片 | 图片审核，不进文本词库 |

| A | `nickname` | `nickname`, `bio` | ✅/待齐 |

| B | 专家自编辑 | `name`/`bio`（借道）；其余字段未校验 | ⚠️/❌ P1 |

## 4. 【新增】分类白名单全集（L2）

### 4.1 引擎语义

```
匹配命中规则 R（category=C）后：
  若 normalize(text) 包含任一 whitelist 短语 P，且 P.scope 含 C（或 scope=* 仅用于绝对化序数等）：
    → 撤销本条命中
  其他 category 命中不受影响
最终决策仍按剩余命中聚合
```

配置建议：

```python
# category -> phrases[]
CONTENT_SAFETY_WHITELIST: dict[str, list[str]] = { ... }
```

P0：代码常量；P1：管理端可增删并热更新缓存。
