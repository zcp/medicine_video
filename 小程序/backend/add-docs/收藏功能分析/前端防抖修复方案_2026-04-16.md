# 前端防抖修复方案 - 收藏功能

**问题**: 用户快速点击收藏按钮导致大量并发请求，引发500和400错误  
**创建时间**: 2026年4月16日 21:39  

## 🚨 **问题现象**

从前端日志可以看出：
- 用户快速点击收藏按钮
- 产生大量并发的 `POST /api/core/users/me/favorites` 请求
- 交替出现500错误（内部服务器错误）和400错误（已收藏该直播间）
- 前端显示"请注意 showLoading 与 hideLoading 必须配对使用"

## 🎯 **根本原因**

1. **前端没有防抖处理** - 用户可以快速重复点击
2. **没有请求状态管理** - 请求进行中时按钮仍可点击
3. **并发请求冲突** - 多个请求同时处理同一个收藏操作

## 💡 **解决方案**

### **方案1: 简单防抖（推荐）**

在收藏按钮的点击事件中添加防抖逻辑：

```javascript
// 在页面data中添加状态管理
data() {
  return {
    isSubmittingFavorite: false,  // 防止重复提交
    favoriteDebounceTimer: null,  // 防抖定时器
    // ... 其他数据
  }
},

methods: {
  async handleFavorite() {
    // 1. 防止重复点击
    if (this.isSubmittingFavorite) {
      console.log('🚫 收藏操作进行中，忽略重复点击')
      return
    }

    // 2. 清除之前的防抖定时器
    if (this.favoriteDebounceTimer) {
      clearTimeout(this.favoriteDebounceTimer)
    }

    // 3. 设置防抖延迟
    this.favoriteDebounceTimer = setTimeout(async () => {
      await this.doFavoriteAction()
    }, 300) // 300ms防抖延迟
  },

  async doFavoriteAction() {
    this.isSubmittingFavorite = true
    
    try {
      // 显示加载状态
      uni.showLoading({
        title: this.isFavorited ? '取消收藏中...' : '收藏中...',
        mask: true
      })

      if (this.isFavorited) {
        // 取消收藏
        await this.$store.dispatch('userFavorites/remove', this.roomId)
        this.isFavorited = false
        uni.showToast({
          title: '已取消收藏',
          icon: 'success'
        })
      } else {
        // 添加收藏
        await this.$store.dispatch('userFavorites/add', this.roomId)
        this.isFavorited = true
        uni.showToast({
          title: '收藏成功',
          icon: 'success'
        })
      }
    } catch (error) {
      console.error('收藏操作失败:', error)
      
      // 用户友好的错误提示
      let errorMessage = '操作失败，请稍后重试'
      if (error.message === '已收藏该直播间') {
        errorMessage = '该直播间已在收藏列表中'
        this.isFavorited = true // 同步状态
      }
      
      uni.showToast({
        title: errorMessage,
        icon: 'none'
      })
    } finally {
      uni.hideLoading()
      this.isSubmittingFavorite = false
    }
  }
}
```

### **方案2: 按钮状态管理**

在模板中禁用按钮状态：

```html
<!-- 收藏按钮 -->
<button 
  class="favorite-btn" 
  :class="{ 'active': isFavorited, 'loading': isSubmittingFavorite }"
  :disabled="isSubmittingFavorite"
  @click="handleFavorite"
>
  <text v-if="!isSubmittingFavorite">
    {{ isFavorited ? '已收藏' : '收藏' }}
  </text>
  <text v-else>处理中...</text>
</button>
```


### **方案3: Store层防重复**

在Vuex store中添加防重复逻辑：

```javascript
// store/modules/userFavorites.js
const state = {
  pendingRequests: new Set(), // 记录进行中的请求
  // ... 其他状态
}

const actions = {
  async add({ commit, state }, roomId) {
    // 检查是否已有相同请求在进行
    const requestKey = `add_${roomId}`
    if (state.pendingRequests.has(requestKey)) {
      console.log('🚫 收藏请求已在进行中，忽略重复请求')
      return
    }

    // 添加到进行中的请求
    state.pendingRequests.add(requestKey)

    try {
      const result = await favoritesApi.addFavorite({ room_id: roomId })
      commit('ADD_FAVORITE', { roomId, data: result })
      return result
    } finally {
      // 无论成功失败都要清除请求标记
      state.pendingRequests.delete(requestKey)
    }
  },

  async remove({ commit, state }, roomId) {
    const requestKey = `remove_${roomId}`
    if (state.pendingRequests.has(requestKey)) {
      console.log('🚫 取消收藏请求已在进行中，忽略重复请求')
      return
    }

    state.pendingRequests.add(requestKey)

    try {
      await favoritesApi.removeFavorite(roomId)
      commit('REMOVE_FAVORITE', roomId)
    } finally {
      state.pendingRequests.delete(requestKey)
    }
  }
}
```

## 🚀 **紧急修复版本**

如果需要快速修复，最简单的方法是在 `handleFavorite` 方法开头添加：

```javascript
// 紧急防抖修复
if (this.isSubmittingFavorite) return;
this.isSubmittingFavorite = true;

// 在try-finally中确保状态重置
try {
  // 原有的收藏逻辑
} finally {
  this.isSubmittingFavorite = false;
}
```

这样可以立即解决重复点击问题！
