## 📌 核心定位说明

### 1. 本文档的定位

本文档专注于 **分类层级（Category Hierarchy）** 与 **专家科室受控词表（Expert Departments）** 的后端实现口径：

**包含模块**:
- **Categories 层级复用**: `parent_id` 两级树；运行时录入路径不写 `categories`（Admin 手动增删改仍可）
- **ExpertDepartments**: 受控词表 + `is_verified` + synonyms 自学习 + 自适应 UPSERT + Admin 管理
- **Experts 绑定**: `department_id` FK + `category_id` 反范式缓存；应用层显式同步（无 DB 触发器）
- **LiveRoomCategories 主分类**: `is_primary` 写入 + 过渡双写 `live_rooms.category_id`
- **发现层 / 搜索**: 房间按多对多 + 子孙展开；专家按 `category_id` 子孙 + JOIN 词表名

**模块范围（以代码为准）**:
- 1 张新表：`expert_departments`
- 2 列新增于 `experts`：`department_id`、`category_id`（均可空，过渡期）
- 复用既有：`categories.parent_id`、`live_room_categories.is_primary`、`live_rooms.category_id`
- **9** 个 Admin 科室 API（挂载于 `/api/v1/admin`）
- 分类 / 房间分类相关既有 API 的行为增强（非新路由为主）
- Schemas / CRUD / Service / 迁移 / seed / 数据迁移脚本

### 2. 一句话架构

> `categories` 运行时只读（结构纯净）+ `expert_departments` 自适应创建（输入容错）+ `is_verified` 审核 + 应用层同步专家缓存列；直播间分类权威为 `live_room_categories`（含 `is_primary`），发现层按子孙展开筛选。

### 3. 业务价值

| 能力 | 效果 |
|------|------|
| 未知科室名录入 | 自动建 `is_verified=false` 词条并启发式归大类，导入不中断 |
| Tab / 搜索 | 按根分类子孙不遗漏；搜索可命中词表名 |
| Admin 治理 | 列表 / 审核 / Merge / 改分类同步 / unmapped |
| 房间卡片 | 返回真实 `primary_category_name`，非硬编码 |

- **禁止** DB 触发器（全项目一致）。  
- 管理员改 `expert_departments.category_id`（专用 PATCH 或通用 PATCH 含 category 变更）时，同事务 `UPDATE experts SET category_id=... WHERE department_id=...`。  
- Merge 跨分类时，转移专家后按目标科室分类再同步。

### 1.3 categories 纯净

- 专家创建 / CSV 导入 / 自适应路径：**只** UPSERT `expert_departments`，**不**自动插入 `categories`。

## 1. 数据库 Schema 设计（DDL）

> 来源：`migrations/20260812_create_expert_departments.sql` + Model。迁移幂等：`IF NOT EXISTS` / `ON CONFLICT DO NOTHING`。

### 1.1 `expert_departments`（专家科室受控词表）

```sql
CREATE TABLE IF NOT EXISTS expert_departments (
    id UUID PRIMARY KEY,
    name VARCHAR(120) UNIQUE NOT NULL,
    category_id UUID NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
    synonyms JSONB NOT NULL DEFAULT '[]'::jsonb,
    is_active BOOLEAN NOT NULL DEFAULT true,
    is_verified BOOLEAN NOT NULL DEFAULT false,
    source VARCHAR(50),
    created_by UUID,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_expert_departments_category_id ON expert_departments(category_id);
CREATE INDEX IF NOT EXISTS idx_expert_departments_is_active ON expert_departments(is_active);
CREATE INDEX IF NOT EXISTS idx_expert_departments_is_verified ON expert_departments(is_verified);
CREATE INDEX IF NOT EXISTS idx_expert_departments_source ON expert_departments(source);
CREATE INDEX IF NOT EXISTS idx_expert_departments_created_by ON expert_departments(created_by);
```

| 字段 | 含义 |
|------|------|
| `name` | 标准科室名，全局唯一 |
| `category_id` | 科室→分类映射真相源 |
| `synonyms` | 同义词 JSON 数组；Merge 自学习，上限 20（Service） |
| `is_verified` | `false`=自适应待审；`true`=已审核 |
| `source` | 如 `auto_match` / `admin_api` / `seed_v4` / `csv_import` 等 |
| `created_by` | 创建人；自适应时常为 NULL |

### 1.2 `experts` 增量列

```sql
ALTER TABLE experts ADD COLUMN IF NOT EXISTS department_id UUID
    REFERENCES expert_departments(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_experts_department_id ON experts(department_id);

ALTER TABLE experts ADD COLUMN IF NOT EXISTS category_id UUID
    REFERENCES categories(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_experts_category_id ON experts(category_id);
```

- **保留**既有 `experts.department VARCHAR`（过渡回填）。  
- 两列过渡期均可空。

### 1.3 既有表（本模块复用，非本迁移新建）

| 表/列 | 用途 |
|-------|------|
| `categories.parent_id` | 两级树；NULL=一级 |
| `live_room_categories(room_id, category_id, is_primary)` | 多对多权威；主分类标记 |
| `live_rooms.category_id` | 过渡双写主分类；**发现筛选不以之为权威** |

### 1.4 种子数据

迁移内嵌按分类名查找后 `INSERT ... ON CONFLICT (name) DO NOTHING`；缺分类名则 `WARNING` 跳过。  
另：`app/core/category_constants.py` 提供 wechat 对齐的 `ROOT_CATEGORIES` / `DEPARTMENT_CATEGORY_MAP`（生殖医学挂「妇产科」等适配）。

## 3. API 接口设计

### 3.1 专家科室 Admin（9 个，全部 JWT + ADMIN/SUPERADMIN）

挂载：`api.py` → `prefix="/admin"` + 路由 `/expert-departments...`  
完整前缀：`/api/v1/admin/expert-departments`

#### 3.1.1 分页列表

**Endpoint**: `GET /api/v1/admin/expert-departments`

**Query**: `page`(默认1)、`size`(默认50, ≤200)、`is_active?`、`is_verified?`、`category_id?`、`q?`(≤100)

**成功 data**: `{ items: ExpertDepartmentItem[], total, page, size }`

#### 3.1.2 创建

**Endpoint**: `POST /api/v1/admin/expert-departments`

**Body**: `ExpertDepartmentCreate`  
**校验**: 目标 `categories` 存在且 `is_active`  
**成功 data**: `{ id, name, category_id }`

#### 3.1.3 部分更新

**Endpoint**: `PATCH /api/v1/admin/expert-departments/{department_id}`

**Body**: `ExpertDepartmentUpdate`  
**副作用**: 若 `category_id` 变更 → 同步关联专家 `category_id`  
**成功 data**: `{ id, name, is_verified }`

#### 3.1.4 软删除

**Endpoint**: `DELETE /api/v1/admin/expert-departments/{department_id}`

**行为**: `is_active=false`  
**成功 data**: `{ message: "科室已软删除" }`

#### 3.1.5 未映射专家

**Endpoint**: `GET /api/v1/admin/expert-departments/unmapped`

**Query**: `page`、`size`  
**行为**: `experts.department_id IS NULL`  
**成功 data.items 字段**: `id, name, title, hospital, avatar_url, category_id, category_name, expertise_areas, is_active, department`（文本）

> 路由声明顺序：`unmapped` 在 `{department_id}` 详情之前，避免被动态路径吞掉。

#### 3.1.6 合并科室

**Endpoint**: `POST /api/v1/admin/expert-departments/merge`

**Body**: `source_id`, `target_id`  
**行为**（`ExpertService.merge_departments`）:
1. 校验 Admin；source ≠ target；双方存在  
2. 转移专家 `department_id`  
3. 跨分类则同步目标下专家 `category_id`  
4. 源名写入目标 `synonyms`（去重，保留最近 ≤20）  
5. 源已审核且目标未审核 → 目标 `is_verified=true`  
6. **物理删除**源科室  

**成功 data**: `{ source_name, target_name, transferred_experts }`

#### 3.1.7 改科室分类（专用）

**Endpoint**: `PATCH /api/v1/admin/expert-departments/{department_id}/category`

**Body**: `{ "category_id": "<uuid>" }`（`embed=True`）  
**行为**: 更新词表分类 + 同步全部关联专家  
**成功 data**: `{ department_name, old_category_id, new_category_id, synced_experts }`

#### 3.1.8 批量审核

**Endpoint**: `POST /api/v1/admin/expert-departments/batch-verify`

**Body**: `BatchVerifyRequest`  
**成功 data**: `{ affected: <int> }`

#### 3.1.9 详情

**Endpoint**: `GET /api/v1/admin/expert-departments/{department_id}`

**成功 data**: `ExpertDepartmentItem`（含 `expert_count`、`category_name`）

### 3.2 分类层级 / 直播间分类（既有路由 + 本轮行为）

| Method | Path | Auth | 本轮要点 |
|--------|------|------|----------|
| GET | `/api/v1/content/categories?tree=` | Public | 复用 V2 树 |
| GET | `/api/v1/admin/categories` | Admin | 可 `parent_id` |
| GET | `/api/v1/admin/categories/{id}/children` | Admin | 子分类 |
| GET | `/api/v1/rooms/{room_id}/categories` | Public | 房间分类列表 |
| POST | `/api/v1/admin/rooms/{room_id}/categories` | Admin | body 含 `primary_category_id`；写 `is_primary` + 双写单列 |
| DELETE | `/api/v1/admin/rooms/{room_id}/categories/{category_id}` | Admin | 解除关联 |

`set_live_room_categories` 行为摘要：

- `replace`：清空后写入；未指定 primary → **首个** `category_ids[0]`；空列表则 `live_rooms.category_id=NULL`  
- `append`：追加；可重置主；若无 primary 且尚无主 → 取列表首个  
- 主分类双写到 `live_rooms.category_id`

### 3.3 专家读写（行为增强，路由既有）

创建 / 更新 / CSV 导入走 `_resolve_department_and_category`：

| 优先级 | 条件 | 结果 |
|:------:|------|------|
| 0 | 显式 `department_id` | 用词表；可用显式 `category_id` 覆盖缓存分类 |
| 1 | 显式 `category_id` / `category_name` | 仅分类；无科室文本则返回 `(None, cat, None)` |
| 2 | name 精确匹配（active 缓存 ≤300） | 绑定词表 |
| 3 | synonyms 包含 | 绑定词表 |
| 4 | `_match_broad_category`（别名表 → 子串） | 可命中已有词条或作为 UPSERT 分类启发 |
| 5 | UPSERT `is_verified=false` | 新词条；冲突则按 name 再取 |
| 6 | 失败 / 空文本 | 归「其他」；无「其他」则 `4001` |

响应必含：`department_id`、`department_name`、`category_id`、`category_name`；过渡期仍含 `department`。

### 3.4 发现层 / 全局搜索（行为增强）

**首页房间**（`crud/homepage_search.get_homepage_rooms_with_details`）:

- 硬过滤：`lr.is_private = false`  
- 分类筛选：`EXISTS (live_room_categories … category_id IN 子孙集)`，子孙由 `get_category_descendant_ids` 递归（含自身）  
- SELECT 子查询 `is_primary=true` → `primary_category_name`

**全局搜索专家**: `experts.category_id IN 子孙` + `LEFT JOIN expert_departments` 对 `ed.name` 关键词匹配。

**房间列表/详情**（`endpoints/room.py`）: 注入 `primary_category_name`。

<a id="sec-flows"></a>

## 4. 执行流程详细说明

### 4.1 自适应解析科室（创建专家 / 导入）

```
1. API 接收创建/导入请求
2. Service._resolve_department_and_category(...)
3. 按优先级匹配 / UPSERT 词表
4. 写入 experts.department_id + experts.category_id
5. 过渡回填 experts.department（展示名）
6. commit
7. _to_expert_item 序列化返回
```

### 4.2 管理员改科室分类

```
1. PATCH .../category 或 PATCH 主体含 category_id
2. check_admin_permission
3. 更新 expert_departments.category_id
4. update_experts_category_by_department（同事务）
5. commit → 返回 synced_experts
```

### 4.3 Merge

```
1. POST .../merge
2. 转移专家 →（跨类）同步 category → 同义词自学习 → verified 升级
3. hard_delete 源科室
4. commit
```

### 4.4 设置直播间分类

```
1. POST /admin/rooms/{id}/categories
2. set_live_room_categories(replace|append, primary_category_id?)
3. 写 live_room_categories.is_primary
4. 双写 live_rooms.category_id
5. 返回分类列表
```

<a id="sec-errors"></a>

## 5. 错误处理与事务管理

- 单请求内多表写：同一 `AsyncSession`，成功路径 `commit`；Integrity 冲突按各函数 `rollback` / 再查。  
- Merge / 改分类 / 自适应创建均不引入跨库事务。  
- 权限失败：`PermissionDeniedException` → 403 / `3003`。  
- 资源不存在：`NotFoundException` → 404 / `2001`。  
- 参数/分类禁用：`InvalidParameterException` → 400 / `4001`。

<a id="sec-perf"></a>

## 6. 性能与实现注意

- 解析路径会话级 `_dept_cache`（≤300 条 active），批量导入避免每行全表扫。  
- 同义词上限 20，防止 Merge 膨胀。  
- 发现层子孙 ID 拼进 SQL `IN (...)`：分类树深度为两级产品约定，规模可控。  
- **无** Redis 缓存层（代码未实现，本文不设计）。
