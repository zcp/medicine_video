## 📌 本次增量范围

### 1. 变更目标

| 能力 | 方式 | 说明 |
|------|------|------|
| 安全底座 | bcrypt + 旧 SHA-256 兼容 | `password.py`；登录成功后滚动升级 |
| 验证码闭环 | OTP 校验 → 签发 Ticket | 后续注册/登录/绑定/重置只认 ticket |
| 手机号 SMS | `SmsProvider` 抽象 | Mock / 腾讯云（已实现）/ 阿里云（骨架） |

| Redis Key | TTL | 用途 |
|-----------|-----|------|
| `otp:{scenario}:{recipient}` | 300s | OTP 明文（JSON，含 attempts） |
| `ticket:{scenario}:{ticket_id}` | 600s | 短期业务凭据，**单次消费** |

|----------|----------|------|

## 1. 核心流程增量

### 1.1 Phase 1：bcrypt 密码底座

```
注册 / 改密 / 手机注册
  → hash_password() → bcrypt $2b$...
登录（邮箱/用户名+密码）
  → verify_password()：兼容 bcrypt 与旧 SHA-256
  → 若为旧哈希且密码正确 → 自动升级为 bcrypt
```

### 1.2 Phase 2：OTP → Ticket 闭环

```
POST /auth/verification-codes
  Body: { channel, recipient, scenario, captcha_id?, captcha_solution? }
  → scenario=LOGIN 时可省略图形验证码
  → 生成 OTP 存 Redis（JSON，max_attempts=5）

POST /auth/verification-codes/verify
  Body: { channel, recipient, scenario, code }
  → 校验 OTP（错误累加 attempts）
  → 成功：删除 OTP，签发 ticket（TTL 600s）
  → 返回 { ticket, expires_in: 600 }
```

### 1.3 Phase 3：手机号注册

```
1. POST /auth/verification-codes  (channel=SMS, scenario=REGISTER)
2. POST /auth/verification-codes/verify  (scenario=REGISTER) → register_ticket
3. POST /users/register/phone
   Body: { register_ticket, password, nickname }
   → 消费 ticket → 创建用户 → is_phone_verified=true → 返回 JWT
```

### 1.4 Phase 3：手机号验证码登录

```
1. POST /auth/verification-codes  (channel=SMS, scenario=LOGIN)
2. POST /auth/verification-codes/verify  (scenario=LOGIN) → login_ticket
3. POST /auth/login/phone
   Body: { login_ticket }
   → 消费 ticket → 查用户 → 签发 JWT
```

### 1.5 Phase 3：绑定手机号（ticket）

```
1. POST /auth/verification-codes  (channel=SMS, scenario=BIND_PHONE)  ※需 JWT 场景由前端带 token
2. POST /auth/verification-codes/verify  (scenario=BIND_PHONE) → bind_ticket
3. POST /users/me/phone
   Body: { phone_number, bind_ticket }
   → consume_ticket(BIND_PHONE) → 校验 recipient 一致 → 更新 phone_number
```

### 1.6 Phase 3：OTP 重置密码

```
1. POST /auth/verification-codes  (channel=SMS|EMAIL, scenario=RESET_PASSWORD)
2. POST /auth/verification-codes/verify  (scenario=RESET_PASSWORD) → reset_ticket（含 user_id）
3. POST /auth/password-reset
   Body: { reset_ticket, new_password }
   → 更新密码 → 吊销旧会话
```

### 1.7 Phase 4：运营商一键登录（方案 A）

```
POST /auth/one-tap-login
  Body: { carrier_token, provider?, agreed_to_terms: true }
  → CarrierAuthProvider.get_phone_number(carrier_token)
  → 开发 Mock：carrier_token = "mock:+8613800138000"
  → 用户不存在 → 自动注册（无密码，social_provider=carrier）
  → 签发 JWT + is_new_user
```

### 1.8 Phase 4：云函数 HMAC 一键登录（方案 B）

```
POST /auth/one-tap-login/cloud-function
  Body: { phone, sign, timestamp }
  → 校验 DCLOUD_API_KEY 已配置
  → 时间戳 60s 内有效
  → HMAC-SHA256(phone + timestamp, DCLOUD_API_KEY) == sign
  → 查/建用户 → 签发 JWT
```
