## 逐项根因（含证据）

### 1. localhost / 真机 API

**根因**：`src/config/api.ts` 与 `request.ts` 默认值仍是：

- `http://localhost:8080/api/core`
- `http://localhost:8080/api/users`

`.env.development` 当前已写成 `10.203.25.156`，但：

1. 未注入/未重建时会回落 localhost；  
2. 历史上确实写过 localhost（注释里还有 prev）；  
3. 媒体 URL 若被拼成 localhost，真机 `<image>` 仍会打到手机本机（与此前头像/封面问题同源）。

**归属**：前端配置。后端无责。

---

### 2. 邮箱发码前不验格式

**根因**（`Register.vue` → `handleEmailSendCode`）：

- 只检查 `emailForm.email.trim()` 非空；  
- **没有** `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`；  
- 格式校验只在 `handleEmailRegister`（点注册）才做。

因此：乱填邮箱 → 先填图形码 → 点发码 → 后端/接口报错 → 图形码被 `refreshCaptcha` 清掉 → 用户感觉白填。

**归属**：前端校验时机错误。

---

### 3. 发码后图形码要不要刷新 / 清输入

**后端**：`_verify_captcha` 校验成功后 **delete Redis key**（一次性消费）。

**前端现状**（邮箱发码成功）：

```text
发码成功 → refreshCaptcha()  // 注释写明：发码已消耗；注册仍需 captcha
```

`refreshCaptcha` 会清空 `captcha_solution`。

**结论**：

| 问题 | 答案 |
|------|------|
| 发码后要不要刷新图形码？ | **要**（旧码已作废） |
| 要不要清输入？ | **要**（旧答案无效） |
| 为何注册又要图形码？ | 现网**邮箱注册接口仍要求 captcha**；发码用的那份已消费，必须用新一轮 |

这不是「刷新写错了」，是产品契约：发码与注册各要一次图形码。体验可优化（注册改用 OTP ticket、或发码后注册不再要图形码），属契约变更。

---

### 4. 密码检测少特殊符号

**后端**（`auth_service._validate_password_strength`）：≥8 + 大小写 + 数字 + 特殊符号 `[!@#$%^&*(),.?\":{}|<>]`。

**前端**：

- `useOtpTicket.validateStrongPassword`：无特殊符号；  
- `Register.vue` / `ChangePassword.vue` 强度条同样只有 4 项。

用户按前端绿灯提交 → 后端拒（弱密码）或改密失败。

**归属**：前端规则未对齐后端。

---

### 5. 登录账号提示不准

**根因**（`Login.vue` → `handlePasswordLogin`）：

- 仅判「账号/密码非空 + 图形码」；  
- 含 `@` 但不完整的邮箱、残缺手机号，**无前端格式提示**，直接打登录接口；  
- 失败只展示后端笼统 message。

验证码登录侧 `detectLoginRecipient` 反而有格式识别；密码登录没复用。

**归属**：前端；后端登录失败文案可顺带细化（可选）。

---

### 6. 专家页上下滑内容不一致

**多个叠加根因**：

1. **Public 分页致命 bug**（`store/expert.ts` `fetchExperts` Public 分支）：  
   - 每页结果 `this.list = sorted`，**不与上一页合并**；  
   - Admin 分支有 merge，Public 没有。  
   → 上拉「加载更多」会**整表换成第 N 页**，内容跳变。

2. **本地 `name.localeCompare` 重排**：与后端分页顺序不一致，字母索引/轻微滚动更乱。

3. **触底机制失效风险**：`ExpertList.vue` 用内部 `scroll-view`，加载更多挂在页面 `onReachBottom`；scroll-view 吃掉滚动时，触底常常不触发（文案「上拉加载更多」也无 `@scrolltolower`）。

4. `pageSize` 默认 **10**（store 初始化），符合「一页 10 个」观感，本身不是 bug。

**归属**：前端（Public 合并 + 滚动事件）。

### 7. 留言长按删除/复制无反应

**根因**（`MessageItem.vue` → `handleLongPress`）：

```ts
if (!canDelete.value) return   // 别人的留言：直接无菜单
// 仅本人/管理员：showActionSheet(['删除留言'])
```

- **别人的留言**：故意无任何反馈 → 「长按复制无反应」。  
- **自己的留言**：有删除；若仍测不出，再查 `current-user-id` 与 `message.user_id` 是否同形（UUID/字符串不一致会导致 `isOwnMessage=false`，也会静默 return）。

后端删除 API 存在；复制纯前端剪贴板，无后端 API。

**归属**：前端交互缺失（+ 可能 user_id 比对问题）。

### 9. 绑了手机号页面不显示；能否一号多绑

**显示不出来（根因）**：

| 层 | 字段 |
|----|------|
| 后端 `UserResponse` / GET `/me` | `phone_number` |
| 前端 `UserInfo` / `ProfileEdit` | 读 `data.phone` |

`me.phone = data.phone` → 永远拿不到 `phone_number` → `v-if="me.phone"` 不渲染。  
绑定日志有、页面无：**字段名错位**。

**一号多绑**：

- DB：`phone_number` **unique**；  
- Service：`bind_phone_number` 查重 → 「该手机号已被其他账号绑定」。  
→ **不允许**不同账号绑同一手机。

**归属**：展示=前端；唯一性=后端已具备。

### 10. 修改密码 400「参数校验失败」

**根因（双端）**：

1. **前端字段名错误（主因）**  
   - 类型/API 注释写 `old_password`；  
   - `ChangePassword.vue` 提交 `{ old_password, new_password }`；  
   - 后端 `PasswordChangeRequest` 要的是 **`current_password`**（Optional）+ `new_password`。  

   FastAPI 忽略未知字段 → `current_password=None` → 有密码用户走 `InvalidPasswordError("必须提供当前密码")`。

2. **后端文案误导**  
   - `InvalidPasswordError` 被映射成 `message="参数校验失败"`（看起来像参数 schema 错，其实是业务「当前密码」问题）。

3. **次因**：前端改密强度同样缺特殊符号；即使用对字段名，弱密码会走 `WeakPasswordError`（文案不同）。

日志 `statusCode:400, message:参数校验失败` 与上述 1+2 高度吻合。

**归属**：前端改字段名为主；后端改错误文案为辅。

### 11. 专家绑了回放，详情不同步

**根因**：状态枚举映射错误，不是「没拉接口」。

- 详情页会调 `fetchExpertSessions`（有请求）。  
- 后端状态：`scheduled` / `live` / `finished` / `ready` / `processing` / `error`。  
- 前端 `ExpertSession.status` 只建模 `'scheduled'|'live'|'ended'`。  
- 映射：`status: (it.status as any) || 'ended'` → `finished`/`ready` **原样保留**。  
- UI：  
  - 历史直播：`status === 'ended'`  
  - 直播中：`live`  
  - 即将开始：`scheduled`  

→ 带回放的 `finished`/`ready` 场次**落不进任何区块**，表现为「绑了回放详情不同步」。

**归属**：前端状态归一化（`finished`/`ready` → 历史/回放）。后端 sessions API 本身有数据。

### 12. 通知能收到，无红点

**根因**：未读数取错接口/字段。

- 后端有独立：`GET /users/me/notifications/unread-count` → `{ unread_count }`。  
- 列表 `NotificationListResponse` 只有 `items/total/page/size/has_more`，**没有 `unread_count`**。  
- 前端 `notifications.ts` / `Home.vue`：`getNotificationList({page:1,size:1})` 再读 `data.unread_count` → 永远不是 number → 红点不更新。  
- `TopBar` 有红点 UI（`unreadCount > 0`），数据源是坏的。  
- `api.ts` 也未配置 unread-count 路径。

**归属**：前端。后端能力已就绪。

**根因**：`CreateLive.vue`（及同类）`picker-mask` 只有 `@tap` 关闭，**没有** `@touchmove.stop.prevent` / `catchtouchmove`。  
小程序/H5 经典滚动穿透：弹层内滑不动或滑到头后，事件落到底层页面。

**归属**：纯前端。

### 16. 内容违规显示成服务器错误

**可能路径（需按具体操作点确认）**：

1. **前端**：`request.ts` 对 `statusCode >= 500` 固定「服务器内部错误」；部分 422 无 string message 时泛化成「填写内容有误」。  
2. **前端**：`handleContentSafetyError` 已在留言/创建直播/资料等接入，但**并非所有写接口 catch 都调用**。  
3. **后端**：内容拦截在留言等路径返回 422 + 业务文案；若未捕获落到通用 Exception → 500「内部服务器错误」。

**归属**：联调时对具体接口看 status/code；多数展示问题在前端兜底文案，少数接口需后端补捕获。
