## 📌 背景与边界

### 1. 背景说明

当前直播间“标题、简介、Tab 文案”属于高风险可编辑字段，需要统一纳入内容安全校验。

### 2. 场景口径（与 12 §1.4.3 一致）

三个 scene **相互独立**，不做 tab_key → room_description 映射：

| scene | 目标字段 | 写入位置 |
|-------|----------|----------|
| `room_title` | `title` | 房间创建/更新 |
| `room_description` | `description` | 房间简介更新 |
| `room_tab` | `tab_key` / `title` / `text_content` | Tab 创建/更新 |

以上三个 scene 的每个文本字段均须执行 **url / contact / fraud / keyword** 四类检测（与 12 §1.4.2 一致）。

> `room_tab` 中：`tab_key` 为系统标识，`title` 为 Tab 展示名称，`text_content` 为 Tab 正文。三者均为可编辑文本，必须同等校验。

### 3. 本次范围

- 【修改】直播间标题更新流程：接入 `scene=room_title` 校验
- 【修改】直播间简介更新流程：接入 `scene=room_description` 校验
- 【修改】Tab 创建/更新流程：接入 `scene=room_tab` 校验（tab_key / title / text_content）
- 【新增】live_core 库对应场景默认规则（含 room_tab 三字段 × 四类检测）

### 4. 排除范围

- 不包含公告（`room_notice`）
- 不新增业务表（内容安全表见 12 §1.1–§1.2，由 live_core 库维护）
- 不改动公开查询接口返回结构

## 🔍 规则与决策

### 1. 双库分治（live_core 侧）

| 维度 | 说明 |
|------|------|
| 数据库 | `live_core_test` |
| 校验场景 | `room_title` / `room_description` / `room_tab` |
| 默认规则 | live_core seed 29 条中本模块占 20 条（room_title 4 + room_description 4 + room_tab 12） |
| 规则维护 | live_core 管理端 API（GET/POST/PATCH `/api/v1/admin/content-safety/rules`） |
| 审计日志 | 存 live_core 库；管理端 logs API 可查询 |

### 2. 检测口径（与 12 §1.4.2 一致）

| 检测类型 | `match_type` | 默认 action |
|----------|--------------|-------------|
| 外链 | `url` | block |
| 联系方式 | `contact` | block |
| 广告引流 | `fraud` | block |
| 敏感词 | `keyword` | block |

### 3. 决策策略（与 12 §1.4.5 一致）

| 决策 | 行为 | HTTP | code |
|------|------|------|------|
| `block` | 拒绝写入 | 422 | 2005 |
| `warn` | 允许写入，写审计日志（`reason_code=2006`） | 200 | 200 |
| `allow` | 正常写入，**不写审计日志** | 200 | 200 |

### 4. 服务异常策略

- 写入路径在安全服务异常时默认拒绝：`422 + code=2004`

### 5. API 路径约定（与 12 §1.7 一致）

| 对外网关路径（nginx） | 服务内路径 | 说明 |
|----------------------|------------|------|
| 房间 CRUD（`/api/core/rooms/...`） | `/api/v1/...` | room_title / room_description 校验 |
| Tab CRUD（`/api/core/rooms/.../tabs`） | `/api/v1/.../tabs` | room_tab 校验 |

## 1. 核心流程增量

### 1.1 更新直播间标题（修改后流程）

```
房间创建/更新（title 变更）
  → 1. JWT 鉴权 + 权限校验（创建者或 Admin）
  → 2. 参数校验（长度、空值）
  → 3. check_content_safety(scene="room_title", field="title")
  → 4. block → 422/2005；安全服务异常 → 422/2004
  → 5. allow/warn → 写库
  → 6. 仅 warn/block 时写入 content_safety_logs（纯 allow 不写日志）
  → 7. 提交事务，返回成功
```

### 1.2 更新直播间简介（修改后流程）

```
房间简介更新（description 变更）
  → 1. JWT 鉴权 + 权限校验
  → 2. 参数校验
  → 3. check_content_safety(scene="room_description", field="description")
  → 4. block → 422/2005；安全服务异常 → 422/2004
  → 5. allow/warn → 写库
  → 6. 仅 warn/block 时写入 content_safety_logs（纯 allow 不写日志）
  → 7. 提交事务，返回成功
```

### 1.3 Tab 创建/更新（修改后流程，与 12 §4.2.4 一致）

```
Tab 创建/更新
  → 1. JWT 鉴权 + 权限校验（创建者或 Admin）
  → 2. 参数校验
  → 3. check_scene_fields(scene="room_tab", {tab_key, title, text_content})
     ※ 仅校验本次提交的字段；三字段均须走四类检测
  → 4. block → 422/2005；安全服务异常 → 422/2004
  → 5. allow/warn → 写库
  → 6. 仅 warn/block 时写入 content_safety_logs（纯 allow 不写日志）
  → 7. 提交事务，返回成功
```

### 1.4 违规返回示例

```json
{
  "code": 2005,
  "message": "内容违规：标题命中联系方式拦截规则",
  "data": null,
  "timestamp": "2026-07-03T10:00:00Z"
}
```
