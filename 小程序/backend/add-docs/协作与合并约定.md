# 协作与合并约定（两人分工不打架）

## 1. 分工原则

- 以“服务”为边界分工：尽量一个人负责一个 service（`live_core_service`/`media_download_service`/`users`）。
- 必须同时改同一 service 时，再按“路由/模块目录”拆分（例如 endpoints A 与 endpoints B）。
- 尽量避免同时改：`app/main.py`、`app/core/config.py`、`app/api/v1/api.py` 这类容易冲突的入口聚合文件。

## 2. 分支策略（建议）

- 每个 bug 一个分支：`bugfix/<服务名>-<简短描述>`
- 提交信息建议：
  - `fix(live-core): ...`
  - `fix(users): ...`
  - `fix(media-download): ...`

## 3. 合并方式（建议）

- 优先使用 PR 合并（即便是内部仓库也建议走同一流程）。
- 合并前双方都做：
  - 代码自检：只动必要行；无无关格式化；无大重构
  - 运行 service 相关的 tests（如果存在）
  - Docker 环境至少启动一次，确认没有 import error/启动失败

## 4. 冲突处理

- 如果冲突发生在路由聚合文件：
  - 先确认 prefix/tags 是否一致
  - 保持原有 include_router 顺序（除非有明确理由）

## 5. “临时文档”的约定

- `add-docs/` 里的内容：
  - 可以先不进主分支；也可以合并进主分支后在下个版本删除
  - 严禁写入任何真实密钥、手机号、患者信息
