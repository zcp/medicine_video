## 🎯 设计要点与约定

### 1.1 数据库设计规范

1. **UUID主键**: 所有表使用 `UUID` 类型作为主键
2. **时间戳**: 所有时间字段使用 `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`
3. **外键约束**: `room_id` 关联 `live_rooms(id)`，`user_id` 关联 `users(id)`
4. **级联删除**: 删除直播间时级联删除所有留言
5. **索引策略**: `room_id` + `created_at` 复合索引加速分页查询

### 1.2 API设计规范

1. **HTTP方法**: GET（查询）、POST（创建）、DELETE（删除）
2. **URL路径**: 使用 `/api/v1/rooms/{roomId}/messages` 格式
3. **认证策略**: 发送留言需要JWT，查看留言可公开或需要登录
4. **分页**: 留言列表使用游标分页（基于时间戳）或偏移分页

### 1.3 软删除策略

| 表名 | 策略 | 说明 |
|------|------|------|
| `room_messages` | 物理删除 | 留言为一次性数据，删除时直接物理删除 |

### 1.4 内容安全

- 留言内容最大长度限制（500字符）
- 基础的内容过滤（可扩展为敏感词过滤）
- 管理员可删除任何留言

### 1.5 安全与配置规范

**架构分层原则**:
- **API 层**: 仅负责认证（`Depends(get_current_user)` 或 `Depends(get_current_user_optional)`）
- **Service 层**: 负责授权（权限守卫函数）
- **CRUD 层**: 负责SQL级别的权限过滤

**双轨鉴权模式**:
- **严格鉴权（Strict Auth）**: 发送留言和删除留言，需要有效的JWT Token
- **可选鉴权（Optional Auth）**: 查看留言列表，允许匿名访问

**权限守卫函数**:

```python
def _check_message_delete_permission(message_user_id: UUID, current_user: dict) -> None:
    """检查留言删除权限：管理员可删除任何留言，普通用户只能删除自己的留言"""
    if current_user["role"] == "admin":
        return
    if str(message_user_id) != str(current_user["user_id"]):
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail={"code": 3002, "message": "权限不足：只能删除自己的留言"}
        )
```

**CRUD层权限过滤**:

```python
# 用户端查询：只返回指定直播间的留言
async def get_room_messages(db: AsyncSession, room_id: UUID, page: int = 1, page_size: int = 20):
    query = (
        select(RoomMessage)
        .where(RoomMessage.room_id == room_id)
        .order_by(RoomMessage.created_at.desc())
        .offset((page - 1) * page_size)
        .limit(page_size)
    )
    return await db.execute(query)
```

### 1.1 room_messages（直播间留言表）

```sql
-- ==========================================================
-- 表：room_messages（直播间留言表）
-- 说明：存储直播间用户留言信息
-- ==========================================================

CREATE TABLE room_messages (
    id UUID PRIMARY KEY,
    room_id UUID NOT NULL,
    user_id UUID NOT NULL,
    content VARCHAR(500) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_msg_room FOREIGN KEY (room_id)
        REFERENCES live_rooms(id) ON DELETE CASCADE,
    CONSTRAINT fk_msg_user FOREIGN KEY (user_id)
        REFERENCES users(id) ON DELETE CASCADE
);

-- 索引：按直播间查询留言（按时间倒序）
CREATE INDEX idx_msg_room_created ON room_messages(room_id, created_at DESC);

-- 索引：按用户查询留言
CREATE INDEX idx_msg_user_id ON room_messages(user_id);

-- 表注释
COMMENT ON TABLE room_messages IS '直播间留言表 - 用户留言信息';
COMMENT ON COLUMN room_messages.id IS '留言UUID主键';
COMMENT ON COLUMN room_messages.room_id IS '直播间UUID（外键，级联删除）';
COMMENT ON COLUMN room_messages.user_id IS '用户UUID（外键，级联删除）';
COMMENT ON COLUMN room_messages.content IS '留言内容（最大500字符）';
COMMENT ON COLUMN room_messages.created_at IS '留言时间（UTC）';
```

## 2. Pydantic Schemas定义

```python
from pydantic import BaseModel, Field, ConfigDict
from typing import Optional, List
from uuid import UUID
from datetime import datetime


class LiveRoomMessageCreate(BaseModel):
    """发送留言请求Schema"""
    content: str = Field(..., min_length=1, max_length=500, description="留言内容")

    @field_validator("content")
    @classmethod
    def validate_content(cls, v: str) -> str:
        """校验留言内容：去除首尾空白，检查是否为空"""
        v = v.strip()
        if not v:
            raise ValueError("留言内容不能为空")
        return v


class UserInfo(BaseModel):
    """用户基本信息Schema（嵌套在留言响应中）"""
    nickname: Optional[str] = None
    avatar_url: Optional[str] = None

    model_config = ConfigDict(from_attributes=True)


class LiveRoomMessageItem(BaseModel):
    """留言响应Schema"""
    id: UUID
    room_id: UUID
    user_id: UUID
    content: str
    created_at: datetime
    user: Optional[UserInfo] = None  # 关联的用户信息

    model_config = ConfigDict(from_attributes=True)


class MessagePageResult(BaseModel):
    """留言分页响应Schema"""
    items: List[LiveRoomMessageItem]
    total: int
    page: int
    page_size: int


# ─── Admin管理端 Schemas ─────────────────────────────────


class AdminMessageQueryParams(BaseModel):
    """管理员全局留言查询参数"""
    room_id: Optional[UUID] = Field(None, description="按直播间筛选")
    user_id: Optional[UUID] = Field(None, description="按用户筛选")
    keyword: Optional[str] = Field(None, max_length=100, description="留言内容关键词模糊搜索")
    start_time: Optional[datetime] = Field(None, description="起始时间")
    end_time: Optional[datetime] = Field(None, description="结束时间")
    page: int = Field(default=1, ge=1, description="页码")
    page_size: int = Field(default=20, ge=1, le=100, description="每页数量")


class BatchDeleteRequest(BaseModel):
    """批量删除留言请求"""
    message_ids: List[UUID] = Field(..., min_length=1, max_length=200, description="待删除留言ID列表")


class AdminMessageItem(LiveRoomMessageItem):
    """管理端留言条目（在用户端基础上增加管理信息）"""
    room_title: Optional[str] = Field(None, description="直播间标题，便于管理端识别")
    user_nickname: Optional[str] = Field(None, description="用户昵称")
    user_role: Optional[str] = Field(None, description="用户角色")
    ip_address: Optional[str] = Field(None, description="留言IP（可选）")


class AdminMessagePageResult(BaseModel):
    """管理端留言分页响应"""
    items: List[AdminMessageItem]
    total: int
    page: int
    page_size: int
    filter_summary: Optional[dict] = Field(None, description="筛选条件摘要，如 { 'keyword': '广告', 'room_count': 3 }")
```

## 3. API接口设计（完整CRUD）

### 3.1 留言API

#### 3.1.1 获取直播间留言列表（公开/登录）

**Endpoint**: `GET /api/v1/rooms/{roomId}/messages`

**描述**: 获取指定直播间的留言列表（分页，按时间倒序）

**认证**: 公开访问（Public）或JWT认证

**路径参数**:
- `roomId` (UUID, required): 直播间UUID

**请求参数 (Query)**:
- `page` (int, 可选, 默认1): 页码
- `page_size` (int, 可选, 默认20): 每页数量（最大100）

**成功响应** (`200 OK`):
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 150,
    "page": 1,
    "page_size": 20,
    "items": [
      {
        "id": "uuid-string",
        "room_id": "room-uuid",
        "user_id": "user-uuid",
        "content": "老师讲得真好！",
        "created_at": "2026-06-07T10:30:00Z",
        "user": {
          "nickname": "张医生",
          "avatar_url": "/uploads/avatars/user1.jpg"
        }
      }
    ]
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收GET请求，解析路径参数和Query参数
2. **构建查询**: JOIN `room_messages` 和 `users` 表
3. **过滤条件**: `WHERE room_id = :roomId`
4. **排序**: 按 `created_at DESC` 排序
5. **分页**: 计算 `offset` 和 `LIMIT`
6. **执行查询**: 异步执行数据库查询，同时执行 `COUNT` 查询获取总数
7. **序列化响应**: 使用 `LiveRoomMessageItem` Schema序列化
8. **返回响应**: 返回统一分页格式的JSON响应

**HTTP状态码**:
- `200 OK`: 查询成功
- `500 Internal Server Error`: 数据库异常

#### 3.1.2 发送留言（JWT）

**Endpoint**: `POST /api/v1/rooms/{roomId}/messages`

**描述**: 在指定直播间发送留言

**认证**: JWT认证

**路径参数**:
- `roomId` (UUID, required): 直播间UUID

**请求体**:
```json
{
  "content": "老师讲得真好！"

```

**成功响应** (`201 Created`):
```json
{
  "code": 200,
  "message": "留言发送成功",
  "data": {
    "id": "new-uuid-string",
    "room_id": "room-uuid",
    "user_id": "user-uuid",
    "content": "老师讲得真好！",
    "created_at": "2026-06-07T10:30:00Z",
    "user": {
      "nickname": "张医生",
      "avatar_url": "/uploads/avatars/user1.jpg"
    }
  },
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收POST请求，解析路径参数和请求体
2. **JWT验证**: 通过 `Depends(get_current_user)` 提取当前用户
3. **Pydantic校验**: 使用 `LiveRoomMessageCreate` Schema校验请求体
4. **直播间存在性检查**: 查询 `live_rooms` 表确认直播间存在
5. **业务校验**: 检查直播间是否允许留言（如是否已关闭）
6. **生成UUID**: 生成新的UUID作为主键
7. **插入数据库**: `INSERT INTO room_messages (...) VALUES (...)`
8. **提交事务**: `await db.commit()`
9. **WebSocket推送（可选）**: 将新留言推送给同一直播间的其他用户
10. **返回响应**: 返回创建的留言信息

**HTTP状态码**:
- `201 Created`: 发送成功
- `401 Unauthorized`: JWT Token无效（code=3001）
- `404 Not Found`: 直播间不存在（code=2001）
- `422 Unprocessable Entity`: 参数校验失败（code=4001）

#### 3.1.3 删除留言（管理员/本人）

**Endpoint**: `DELETE /api/v1/rooms/{roomId}/messages/{messageId}`

**描述**: 删除留言（管理员可删除任何留言，普通用户只能删除自己的留言）

**认证**: JWT认证

**路径参数**:
- `roomId` (UUID, required): 直播间UUID
- `messageId` (UUID, required): 留言UUID

**成功响应** (`200 OK`):
```json
{
  "code": 200,
  "message": "留言删除成功",
  "data": null,
  "timestamp": "2026-06-07T10:00:00Z"
}
```

**执行流程**:

1. **接收请求**: API路由接收DELETE请求，解析路径参数
2. **JWT验证**: 通过 `Depends(get_current_user)` 提取当前用户
3. **存在性检查**: 查询留言是否存在
4. **权限检查**:
   - 管理员（role=admin）可删除任何留言
   - 普通用户只能删除自己发布的留言（`user_id == current_user_id`）
   - 不满足条件抛出 `403` 异常
5. **物理删除**: `DELETE FROM room_messages WHERE id = :messageId`
6. **提交事务**: `await db.commit()`
7. **返回响应**: 返回删除成功响应

**HTTP状态码**:
- `200 OK`: 删除成功
- `401 Unauthorized`: JWT Token无效（code=3001）
- `403 Forbidden`: 无权删除他人留言（code=3002）
- `404 Not Found`: 留言不存在（code=2001）

## 5. 错误处理与事务管理

### 5.1 错误处理策略

**业务异常**:
- 资源不存在（code=2001）→ HTTP 404
- 权限不足（code=3002）→ HTTP 403
- 业务逻辑错误（code=2004）→ HTTP 422

**系统异常**:
- 数据库连接失败 → HTTP 503

### 5.2 事务管理规范

**单表操作**: 使用单个事务，操作失败自动回滚

**批量操作**: 批量删除使用单条 `DELETE ... WHERE id IN (...)` 语句，天然原子性

**并发控制**: 
- 单条留言删除无特殊并发控制需求
- 批量删除时如遇部分留言已被其他管理员删除，不影响其他留言的删除
- 建议在 Service 层返回 `deleted_count` 和 `failed_count` 以便追踪

### 5.3 Admin角色校验的两种实现方式

**方式一：API层守卫（推荐）**

```python
# 在 get_current_user 之后，额外校验 role
async def verify_admin_role(current_user: dict = Depends(get_current_user)):
    if current_user.get("role") != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail={"code": 3003, "message": "权限不足：仅管理员可执行此操作"}
        )
    return current_user

# 在路由中使用双依赖
@router.get("/admin/messages")
async def admin_get_messages(
    query: AdminMessageQueryParams = Depends(),
    current_user: dict = Depends(verify_admin_role),  # 先过admin校验
):
    ...
```

**方式二：Service层校验**

复用现有 `_check_message_delete_permission` 的模式，在 Service 层统一校验 admin 角色。推荐方式一，更直观、更早拦截非admin请求。

## 6. 性能优化建议

### 6.1 数据库优化

- **索引优化**: 
  - `(room_id, created_at DESC)` 复合索引加速直播间留言分页查询
  - `user_id` 索引加速按用户筛选
  - **（可选）** 如 `keyword` 模糊搜索频繁，可追加 `pg_trgm` 扩展 + GIN 索引：
    ```sql
    CREATE EXTENSION IF NOT EXISTS pg_trgm;
    CREATE INDEX idx_msg_content_trgm ON room_messages USING gin (content gin_trgm_ops);
    ```
- **查询优化**: JOIN查询用户信息时只选择必要字段（nickname, avatar_url）
- **分页优化**: 大量留言时建议使用游标分页（基于 `created_at`）

### 6.2 缓存策略

- **Redis缓存**: 热门直播间的最近留言可缓存（TTL=60s）
- **缓存键**: `room:{roomId}:messages:recent`

### 6.3 应用层优化

- **WebSocket**: 使用WebSocket实现留言实时推送，减少轮询
- **限流**: 限制用户发送留言的频率（如：每5秒最多1条）
