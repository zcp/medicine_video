# 16-D 跨模块落地分包索引

**版本**: V1.1  
**日期**: 2026-07-22  
**基于**: 《16-跨模块数据交互分析-一对一枚举与串联归类决策清单》  
**原则**: **最小化 / 最友好 / 最快可落地**——能复用现网就复用；P0 只做「不做错 + 用户立刻感知的缺口」；重方案一律后置。

---

## 总原则（V1.1 统一口径）

| # | 原则 | 含义 |
|---|------|------|
| 1 | **先约束、再加码** | 现网已符合的只写回归测试，不写新接口 |
| 2 | **能读过滤就不写扩散** | 软删/下架优先 C 端过滤，避免批量改子表 |
| 3 | **注销私货：有软删字段就软藏** | `is_active=false` 即可对用户不可见，少打物理删 |
| 4 | **留言占位不回写、不按页跨库** | D2 打本地标记；读路径只查本服务 |
| 5 | **兄弟包禁止交叉删** | D2 不删房/不删留言；D4 不按 user 清；D1 不调删房 |

## 建议落地顺序（最快路径）

1. **D4**（改动最小、无跨服务，半天级）  
2. **D5**（多为核对过滤，漏点才改）  
3. **D1**（补测试 + CR 清单，几乎无功能码）  
4. **D2** → **D3**（唯一跨服务编排；先 D2 再 D3）  
5. **D0** 会员闸门（与《10》对齐，可插在 D2 前）

### B. 跨文档口径一致性（V1.1 修正点）

| # | 问题（V1.0） | 处理 |
|---|--------------|------|
| 1 | D1 把 batch status、房间展示、写门禁都塞进 P0，过重 | **砍掉**；失管=既有禁登+吊销 |
| 2 | D3 按页调 users 与 V3「列表不跨服务」张力大 | 改为 **D2 写本服务标记**，D3 只读本地 |
| 3 | D2「一律物理删」与用户行为「软删留分析」冲突 | 改为 **有 `is_active` 则软藏**；其余再物理删/解绑 |
| 4 | D5「读过滤 + 写 OFF_SALE」双轨过重 | **P0 仅读过滤**（商品列表已有 `_get_brand` 校验） |

| 6 | D2 错误码写 3001、实现像 403 | 统一 **403 鉴权失败**（对齐现网 internal） |
| 7 | 「冷却后硬删」易被读成 D1 要做 | 明确 **仅 SOP**，硬删走既有删房→D4 |
| 8 | 已售商品 | D5 维持：现网无订单；不可售=停新卖 |
