### 1. 变更目标

| 能力 | 方式 | 说明 |
|------|------|------|
| 邮箱验证码登录 | `login_ticket` + EMAIL | `POST /auth/login/email`，对称 `/login/phone` |
| 复用发码/验码 | 既有 OTP API | `channel=EMAIL, scenario=LOGIN` |
| 邮件发送 | 既有 `EmailProvider` | 开发 `mock`；联调/生产 `smtp` |

### 2. 变更类型

- 【新增】`POST /api/v1/auth/login/email`：消费 LOGIN ticket（`channel=EMAIL`）→ JWT
- 【新增】`EmailLoginRequest` Schema；`AuthService.login_by_email_ticket`
- 【文档】Ticket 消费表补齐 EMAIL LOGIN；网关路径对齐小程序

- 不强制要求 `is_email_verified=true`（与 V3 手机登录不强制 `is_phone_verified` 对齐；可后续收紧）

## 🔍 设计要点

### 1. 与 V3 手机号验证码登录对称

| 步骤 | 手机（V3） | 邮箱（本 V5） |
|------|------------|---------------|
| 1 发码 | `channel=SMS, scenario=LOGIN` | `channel=EMAIL, scenario=LOGIN` |
| 2 验码 | `POST /verification-codes/verify` → `login_ticket` | 同左 |
| 3 登录 | `POST /auth/login/phone` `{ login_ticket }` | **`POST /auth/login/email` `{ login_ticket }`** |
| Ticket 校验 | `channel == "SMS"`，按手机号查用户 | **`channel == "EMAIL"`，按邮箱查用户** |

### 2. 核心流程

```
1. POST /auth/verification-codes
   Body: { channel: "EMAIL", recipient: "user@example.com", scenario: "LOGIN" }
   → LOGIN 免图形验证码（与 V3 一致）
   → EmailProvider 发送 OTP（Redis TTL 300s）

2. POST /auth/verification-codes/verify
   Body: { channel: "EMAIL", recipient, scenario: "LOGIN", code }
   → 签发 ticket（TTL 600s，payload 含 channel/recipient）

3. POST /auth/login/email
   Body: { login_ticket }
   → 消费 ticket（单次）
   → channel 必须为 EMAIL，否则 3001
   → get_by_email(recipient) → 无用户 / 非 NORMAL → 失败
   → 更新 last_login_at → 签发 JWT
```

### 3. Ticket 机制（相对 V3 增补一行）

| scenario | 消费端点 | 说明 |
|----------|----------|------|
| `LOGIN` | `POST /auth/login/phone` | 手机号验证码登录（`channel=SMS`） |
| `LOGIN` | **`POST /auth/login/email`** | **邮箱验证码登录（`channel=EMAIL`）** |
| `REGISTER` | `POST /users/register/phone` | 手机号注册（本 V5 不改） |
| `BIND_PHONE` | `POST /users/me/phone` | 绑定手机（本 V5 不改） |
| `RESET_PASSWORD` | `POST /auth/password-reset` | OTP 重置（EMAIL/SMS 均已支持） |

> 同一 `purpose=LOGIN` 的 ticket 只能被对应 channel 的端点消费；交叉调用必须拒绝。

### 4. API 路径（nginx 网关）

| 对外网关路径 | 服务内路径 | 说明 |
|-------------|------------|------|
| `POST /api/users/auth/verification-codes` | `/api/v1/auth/verification-codes` | 已有 |
| `POST /api/users/auth/verification-codes/verify` | `/api/v1/auth/verification-codes/verify` | 已有 |
| **`POST /api/users/auth/login/email`** | **`/api/v1/auth/login/email`** | **本 V5 新增** |

> nginx：`location /api/users/auth/ { proxy_pass http://users_api/api/v1/auth/; }`，**无需新 location**。

### 5. Schema

```python
class EmailLoginRequest(BaseModel):
    login_ticket: str = Field(..., description="LOGIN 场景 ticket（channel=EMAIL）")
```

成功响应 `data` 对齐手机登录，建议字段：

| 字段 | 说明 |
|------|------|
| `access_token` / `refresh_token` / `token_type` | JWT |
| `user_public_id` / `username` / `nickname` | 用户信息 |
| `email_masked` | 掩码邮箱（对称 `phone_masked`） |

### 6. 错误码（对齐 `/login/phone`）

| HTTP | code | 场景 |
|------|------|------|
| 400 | 4004 | ticket 无效/过期/已消费 |
| 401 | 3001 | channel 非 EMAIL、用户不存在、凭证无效 |
| 401 | 3002 | 账户状态异常 |
| 500 | 1002 | 系统/数据库错误 |

### 7. EmailProvider 与环境变量

| `EMAIL_PROVIDER` | 行为 |
|------------------|------|
| `mock` | 不真发邮件；OTP 仍写 Redis（开发/自测） |
| `smtp` | SMTP 真发（需 `SMTP_HOST/PORT/USER/PASSWORD/FROM`） |

生产：`validate_production_config()` 拒绝 `EMAIL_PROVIDER=mock`（现码已有）。

### 8. 与密码登录边界

| 方式 | 端点 | 凭证 |
|------|------|------|
| 用户名/邮箱/手机 + 密码 | `POST /auth/login` | password + 图形验证码 |
| 邮箱 OTP | **`POST /auth/login/email`** | `login_ticket` |
| 手机 OTP | `POST /auth/login/phone` | `login_ticket` |

## 1. 接口示例

**请求**：

```http
POST /api/users/auth/login/email
Content-Type: application/json

{ "login_ticket": "xYz..." }
```

**成功**：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "access_token": "...",
    "refresh_token": "...",
    "token_type": "bearer",
    "user_public_id": "...",
    "username": "superadmin",
    "nickname": "超级管理员",
    "email_masked": "su***@test.com"
  },
  "timestamp": "2026-07-16T08:00:00Z"
}
```

**ticket channel 不匹配（SMS ticket 打到 email）**：

```json
{ "code": 3001, "message": "登录凭证无效" }
```
