# 技术栈选型报告

## 一、架构设计原则

### 1.1 分层结构
- 清晰划分客户端、前端、后端、媒体服务、数据存储和 DevOps
- 有助于后期扩展与维护

### 1.2 微服务模块化
- 采用"适度拆分"策略
- 允许逐步模块化关键服务（如直播流控制、聊天服务、回放服务等）
- 利于横向扩展

### 1.3 技术组合
- FastAPI + Vue + PyCharm + PostgreSQL + SQLAlchemy + Pydantic + RDS
- 适配医疗行业直播SaaS的高安全性、高并发与快速交付需求

## 二、技术栈详情

### 2.1 前端技术栈
| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 前端框架 | Vue 3 + Vite + JavaScript | 快速开发、性能好、生态成熟 |
| 样式方案 | Tailwind CSS | 响应式设计、一致性高，适配医疗风格 |
| 前后通信 | Axios + WebSocket | 支持 REST + 实时交互，适合直播互动 |
| 状态管理 | Pinia | 轻量级状态管理，适合Vue 3 |
| 开发工具 | ESLint + Prettier | 代码规范和格式化 |
| 构建工具 | Vite | 快速的开发服务器和构建工具 |

### 2.2 后端技术栈
| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 后端框架 | FastAPI + Python | 高性能异步框架，类型安全 |
| 数据建模 | SQLAlchemy（ORM） | 与 FastAPI 深度集成，便于数据库操作 |
| 数据验证 | Pydantic（数据模型） | 参数校验 + 响应序列化，API 规范性好 |
| 数据库 | PostgreSQL（托管于 AWS RDS） | 支持 JSON Schema 分租户、RDS 免运维 |

### 2.3 媒体服务技术栈
| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 流媒体服务器 | SRS（Simple Realtime Server） | 支持 RTMP / HLS / WebRTC，适合直播 |
| 视频处理 | FFmpeg | 转码录制截图，全能工具 |

### 2.4 存储与缓存技术栈
| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 缓存与队列 | Redis | 用于聊天室、限流、任务等 |
| 对象存储 | Cloudflare R2 / MinIO / OSS | 存直播回放/素材，CDN 加速 |

### 2.5 部署与运维技术栈
| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 网关代理 | Nginx | 反向代理、WebSocket 支持好 |
| 部署方式 | Docker + Docker Compose | 快速部署、环境一致 |
| CI/CD | GitHub Actions / GitLab CI | 自动测试与版本发布 |
| 云平台 | 阿里云 / 腾讯云 / AWS | 海内外兼顾，RDS/OSS 选项丰富 |

## 三、技术亮点

### 3.1 数据层设计
- SQLAlchemy + Pydantic：代码解耦、数据模型清晰
- RDS 托管 PostgreSQL：自动备份、灾备、免维护
- PostgreSQL Schema 多租户隔离

### 3.2 流媒体设计
- RTMP 推流 → HLS/WebRTC 播放：跨平台支持
- WebSocket 实时互动：弹幕、聊天室、连麦

### 3.3 运维设计
- DevOps 持续部署：支持快速迭代上线

## 四、优化建议

### 4.1 监控与日志
- 日志监控系统：Prometheus + Grafana / ELK

### 4.2 任务处理
- 自动转码与调度：Celery + Redis + FFmpeg

### 4.3 扩展性
- 多实例与扩展部署支持：Nginx + Kubernetes

### 4.4 数据分析
- 用户行为分析：Kafka + ClickHouse

### 4.5 开发工具
- API 测试与文档工具：FastAPI 自带 Swagger UI
