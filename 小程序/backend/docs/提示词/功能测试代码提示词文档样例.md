##### **测试数据隔离 (Test Data Isolation)**

* **指令**: 为了防止测试之间因违反数据库 `UNIQUE` 约束而产生冲突，所有唯一性字段（如 `username`, `email`, `product_code`, `transaction_id`）**必须**是随机生成的，以确保每次测试运行时的数据都是独一 un二的。
* **实现**:
    * 推荐安装并使用 `faker` 库 (`pip install Faker`)，因为它可以生成符合特定格式和长度要求的、更真实的数据。
    * 所有生成的随机数据**必须**严格遵守 `app/schemas/users.py` 中 Pydantic 模型的验证规则。
* **具体要求 (Requirements)**:
    * **`username`**:
        * **规则**: 必须符合 `schemas.UserBase` 中定义的 `min_length=1` 和 `max_length=50`。
        * **Faker 范例**: `fake.user_name()` 结合一个随机后缀，例如 `f"{fake.user_name()}_{uuid.uuid4().hex[:6]}"` 以确保唯一性。
    * **`email`**:
        * **规则**: 必须是一个有效的邮箱格式。
        * **Faker 范例**: `fake.email()`。
    * **`phone_number` (已补充)**:
        * **规则**: 长度不能超过20个字符。
        * **Faker 范例**: fake.phone_number() (可能需要根据具体格式进行调整)
    * **`product_code`**:
        * **规则**: 必须符合 `schemas.MembershipProductCreate` 中定义的 `min_length=1` 和 `max_length=50`。
        * **Faker 范例**: 使用大写字母和数字的组合，例如 `f"PROD_{''.join(random.choices(string.ascii_uppercase + string.digits, k=10))}"`。
    * **`transaction_id`**:
        * **规则**: 长度不能超过255个字符。
        * **Faker 范例**: `f"txn_{uuid.uuid4().hex}"`。
    * **禁止硬编码**: 在测试的“准备 (Arrange)”阶段，**严禁**使用硬编码的字符串（如 `'usera'`) 作为唯一性字段的值，除非测试目的就是为了验证重复性约束。
