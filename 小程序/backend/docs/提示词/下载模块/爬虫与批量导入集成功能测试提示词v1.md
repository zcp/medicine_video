### 2.3 Mock和Spy原则

**何时使用Mock**:
- 外部API调用（微赞API、网络请求）
- 文件系统操作（CSV读写）
- 数据库操作（对于单元测试）
- 耗时操作（爬取、下载）

**何时使用真实对象**:
- 纯逻辑运算
- 配置解析
- 数据转换
- 集成测试中的数据库操作

### 2.4 断言原则

- 使用明确的断言语句
- 包含失败时的错误信息
- 验证核心功能，不过度断言
- 区分正常流程和异常流程

### 2.5 响应状态码（统一响应模式）

**重要**：根据统一响应规范，所有API接口都返回 **HTTP 200**，业务状态码在响应体的 `code` 字段中。

| HTTP状态码 | 响应体code字段 | 场景 |
|:---|:---|:---|
| 200 | 201 | 爬取和导入全部成功 |
| 200 | 207 | 爬取成功，导入部分成功 |
| 200 | 400 | 爬虫配置错误、参数错误 |
| 200 | 500 | 数据库错误、系统错误 |

**测试断言示例**：
```python
assert response.status_code == 200  # HTTP状态码固定为200
response_data = response.json()
assert response_data["code"] == 201  # 业务状态码在body的code字段
```

### 2.6 同步/异步测试区分

**重要说明**：
1. **服务层测试**：`download_service.py` 中的所有方法都是**同步方法**，因此服务层测试必须使用**同步测试函数**（`def test_...`），不使用 `@pytest.mark.asyncio` 装饰器。
2. **API接口测试**：API 接口是异步的，必须使用**异步测试函数**（`async def test_...`）和 `@pytest.mark.asyncio` 装饰器。

**示例对比**：
```python
# ✅ 正确：服务层测试（同步）
def test_crawl_and_import_success(self, download_service):
    result = download_service.crawl_and_import_tasks(...)
    assert result['crawl_status'] == 'success'

# ✅ 正确：API测试（异步）
@pytest.mark.asyncio
async def test_api_crawl_and_import_success(self, client):
    response = await client.post("/api/v1/download/tasks/crawl-and-import", ...)
    assert response.status_code == 200
```

### 2.7 测试辅助函数规范

**重要**：所有辅助函数（如生成测试数据的函数）应直接定义在测试文件中，**不要修改 `conftest.py`**，因为其他测试文件依赖它。

**示例**：
```python
# ✅ 正确：在测试文件中定义辅助函数
def generate_sample_csv_data(num_rows=10):
    """生成示例CSV数据"""
    return [...]

# ❌ 错误：不要在 conftest.py 中添加新的辅助函数
```

## 十二、常见测试问题与解决

### Q1: Mock不生效

**问题**: Mock设置后，仍然调用了真实方法

**解决方案**:
```python
# ❌ 错误：Mock位置不对
@patch('app.crawlers.vzan_crawler.requests')
def test_something(mock_requests):
    pass

# ✅ 正确：Mock完整路径
@patch('app.crawlers.vzan_crawler.requests.get')
def test_something(mock_get):
    pass
```

### Q2: 异步测试报错

**问题**: 测试同步代码时报 "coroutine was never awaited"

**解决方案**:
- 确认被测试的服务层方法是同步的（不是`async def`）
- 测试方法不要使用`@pytest.mark.asyncio`
- 使用同步数据库会话（`sync_db_session`）

### Q3: 临时文件残留

**问题**: `/tmp/` 下有大量测试文件

**解决方案**:
- 使用 `pytest` 的 `tmp_path` fixture
- 在 `conftest.py` 中添加全局清理

### Q4: 测试数据污染

**问题**: 测试之间相互影响

**解决方案**:
- 使用事务回滚
- 每个测试后清理数据库
- 使用唯一的测试数据（UUID）
