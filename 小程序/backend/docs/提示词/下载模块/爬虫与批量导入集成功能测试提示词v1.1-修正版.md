### 2.3 Mock和Spy原则

**何时使用Mock**:
- 外部API调用（微赞API、网络请求）
- 文件系统操作（CSV读写）
- 数据库操作（对于单元测试）
- 耗时操作（爬取、下载）
- **浏览器操作（Playwright）** ✅ 必须Mock

**何时使用真实对象**:
- 纯逻辑运算
- 配置解析
- 数据转换
- 集成测试中的数据库操作

### 2.4 断言原则

- 使用明确的断言语句
- 包含失败时的错误信息

- 区分正常流程和异常流程
- **验证实际返回值，不要猜测** ✅

### 2.5 响应状态码（统一响应模式）

**重要修正**：区分HTTP状态码和业务状态码

| 场景 | HTTP状态码 | 响应体code字段 | 响应格式 |
|:---|:---|:---|:---|
| 爬取和导入全部成功 | **200** | 201 | `{"code": 201, "message": "...", "data": {...}}` |
| 爬取成功，导入部分成功 | **200** | 207 | `{"code": 207, "message": "...", "data": {...}}` |
| 爬取成功，导入全部跳过 | **200** | **400** | `{"code": 400, "message": "爬取成功，但导入全部失败", "data": {...}}` |
| **Pydantic验证失败** | **422** | N/A | `{"detail": [{"type": "...", "msg": "..."}]}` ✅ |
| 爬虫配置错误、参数错误 | **200** | 400 | `{"code": 400, "message": "...", "data": null}` |
| 数据库错误、系统错误 | **200** | 500 | `{"code": 500, "message": "...", "data": null}` |

**测试断言示例**：
```python
# ✅ 正确：测试业务成功

data = response.json()
assert data["code"] == 201  # 业务状态码在body的code字段

# ✅ 正确：测试Pydantic验证失败
assert response.status_code == 422  # Pydantic验证返回422
data = response.json()
assert "detail" in data  # FastAPI的422响应格式
```
