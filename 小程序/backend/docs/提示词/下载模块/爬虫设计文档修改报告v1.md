## 二、详细修改内容

### 2.1 配置管理 (`CrawlerSettings`)

#### 修改项
1. **`CRAWLER_TIMEOUT`**: 默认值从 `300` 秒改为 `10` 秒，最小值从 `60` 改为 `1`
   - **原因**: 实际代码中 `self.timeout = 10`（行 27）
   
2. **移除 `CRAWLER_MAX_RETRIES`**: 
   - **原因**: 实际代码未显式使用重试逻辑，`requests` 库默认不重试

3. **`CRAWLER_TEMP_DIR`**: 默认路径从 `/tmp/crawler_csv` 改为 `/tmp/vzan_crawler`
   - **原因**: 实际代码中使用 `os.path.join(tempfile.gettempdir(), 'vzan_crawler')`（行 35-38）

4. **`CRAWLER_MAX_ROWS`** 重命名为 **`CRAWLER_BATCH_SIZE`**: 
   - 默认值从 `10000` 改为 `100`
   - 用途从"单次爬取最大行数"改为"批量写入 CSV 的数据条数"
   - **原因**: 实际代码中 `self.liveroomlist_batchsize = 100`（行 25）

#### 修改后配置
```bash
# 爬虫通用配置
CRAWLER_TIMEOUT=10                   # 爬虫单个请求超时时间（秒，默认10）
CRAWLER_TEMP_DIR=/tmp/vzan_crawler   # CSV临时文件存储目录
CRAWLER_BATCH_SIZE=100               # 批量写入CSV的数据条数（默认100）
```

### 2.2 爬虫基类 (`BaseCrawler`)

#### 修改项
1. **`__init__` 方法**: 移除 `max_retries` 参数提取，保留 `timeout`（默认值改为 `10`）

2. **`crawl()` 方法签名**:
   - **修改前**: `crawl(self, url: str, **kwargs) -> Path`
   - **修改后**: `crawl(self, config: Dict, **kwargs) -> Dict`
   - **原因**: 实际代码中爬虫不需要 URL 参数（使用固定 API 端点），且配置通过 `config` 字典传入

3. **`crawl()` 返回值**:
   - **修改前**: 返回 `Path`（CSV 文件路径）
   - **修改后**: 返回 `Dict`（爬取结果摘要）
   ```python
   {
       "csv_file": str,             # 主 CSV 文件路径
       "incremental_file": str,     # 增量 CSV 文件路径
       "failed_file": str,          # 失败记录文件路径
       "total_rows": int,           # 总爬取行数
       "failed_rows": int,          # 失败行数
       "incremental_rows": int      # 本次新增行数
   }
   ```
   - **原因**: 实际实现生成多个文件（主文件 + 增量文件 + 失败文件），需要更丰富的返回信息

### 2.3 微赞爬虫实现 (`VzanCrawler`)

#### 2.3.1 类结构和初始化

**新增内容**:
1. **API 端点常量**: 定义 4 个微赞 API 端点作为类常量
   ```python
   API_LIVEROOM_LIST = "https://live-liveapi.vzan.com/api/v1/topic/get_topicdatas"
   API_LIVEROOM_URL_PREFIX = "https://inter.dayilive.com/live/page/"
   API_TOPIC_CONFIG_PREFIX = "https://live-play.vzan.com/api/topic/topic_config?isPcBrowser=true&topicId="
   API_VIDEO_CONFIG_PREFIX = "https://live-play.vzan.com/api/topic/video_config?tpId={enc_tpid}&domain=inter.dayilive.com&agentId="
   ```

2. **输出文件路径**: 定义 3 个输出文件路径
   ```python
   self.liveroom_list_file = self.temp_dir / "liveroomlist_vzan_api.csv"
   self.liveroom_list_inc_file = self.temp_dir / "liveroomlist_inc_vzan_backup.csv"
   self.failed_file = self.temp_dir / "failed_liveroomlist_urls_vzan.txt"
   ```

3. **动态临时目录**: 根据操作系统（Windows/Linux）动态生成临时目录路径

#### 2.3.2 核心方法

**新增/详细说明的方法**:

1. **`crawl(config, **kwargs) -> Dict`**: 主入口方法
   - 参数: `page_size` (每页数据量), `max_pages` (最大爬取页数)
   - 返回: 爬取结果摘要（包含 3 个文件路径 + 统计信息）

2. **`_execute_vzan_crawl(token, page_size, max_pages, existing_ids) -> Dict`**: 核心爬取逻辑
   - 说明: 实现分页爬取、增量爬取、批量写入等完整流程
   - 关键步骤:
     1. 获取第一页确定总数
     2. 计算总页数
     3. 分页爬取（每页调用 `_get_liveroom_list`）
     4. 提取数据（调用 `_extract_liveroomlist_data`）
     5. 过滤新增数据（基于 `existing_ids`）
     6. 批量写入（每 100 条写入一次）

3. **`_get_liveroom_list(token, page, psize) -> Optional[Dict]`**: 调用微赞 API 获取直播间列表
   - **重要**: 明确说明完整的请求头（包含 `lid`, `zbid`, `admin-token` 等微赞 API 必需参数）
   ```python
   headers = {
       'accept': 'application/json, text/plain, */*',
       'accept-language': 'en-US,en;q=0.9',
       'admin-token': 'undefined',
       'appcode': 'agent_setting',
       'authorization': f'Bearer {token}',
       'content-type': 'application/json;charset=UTF-8',
       'generalizeshopid': '0',
       'lid': '11749549',  # 固定值，微赞 API 必需
       'origin': 'https://live.vzan.com',
       'referer': 'https://live.vzan.com/',
       'user-agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36',
       'zbid': '11749549'  # 固定值，微赞 API 必需
   }
   ```

4. **`_extract_liveroomlist_data(response_data) -> Tuple[List[Dict], List[Dict]]`**: 多步骤数据提取
   - **详细说明**: 
     1. 从 `get_topicdatas` 响应中提取基础信息（id, title, status 等）
     2. 调用 `topic_config` API 提取 `enc_tpid`
     3. 调用 `video_config` API 提取视频 URL 和封面图
   - **错误隔离**: 单条数据失败不影响其他数据，失败数据单独记录

5. **`_extract_enc_tpid(topic_url) -> str`**: 从 topic_config API 提取 enc_tpid

6. **`_extract_play_url(video_url) -> Tuple[str, str]`**: 从 video_config API 提取播放 URL 和封面图

7. **`_load_existing_ids() -> set`**: 从主 CSV 文件加载已爬取的直播间 ID（用于增量爬取）

8. **`_save_to_csv(data, filepath, mode) -> None`**: 保存数据到 CSV 文件
   - **CSV 字段**: 明确定义与批量导入所需字段对应的 13 个字段
   ```python
   fieldnames = [
       'liveroom_id',      # 对应 '直播间ID'
       'liveroom_title',   # 对应 '标题'
       'liveroom_url',     # 对应 '直播间url'
       'resource_url',     # 对应 '播放url'（批量导入的核心字段）
       'resource_type',    # 对应资源类型（固定为 'hls'）
       'created_at',       # 对应 '创建时间'
       'start_time',       # 对应 '开始时间'
       'live_type',        # 对应 '直播类型'
       'status',           # 对应 '直播状态'
       'cover_url',        # 对应 '封面图片'
       'view_count',       # 对应 '观看次数'
       'zb_id',            # 对应 'zbID'
       'enc_tpid'          # 对应 'enc_tpid'
   ]
   ```
   - **注意**: `resource_url` 字段映射到实际爬取的 `video_url`，这是批量导入的核心字段

#### 2.3.3 增量爬取支持

**新增说明**: 
- 爬虫支持增量爬取，通过读取已有 CSV 文件中的直播间 ID，跳过已爬取的数据
- 新增数据会同时写入主文件（追加模式）和增量文件
- 首次爬取时，所有数据都是新增数据

### 2.4 服务层方法 (`crawl_and_import_tasks`)

#### 修改项

1. **参数调整**:
   - **移除 `crawl_url`**: 微赞爬虫使用固定 API 端点，不需要此参数
   - **`skip_duplicates` 说明更新**: 明确为"跳过重复任务组合（resource_url + liveroom_id + liveroom_title）"
   - **`**crawl_kwargs` 说明**: 明确可传递的参数（`page_size`, `max_pages`）

2. **返回值调整**:
   ```python
   {
       "crawl_status": "success" | "failed",
       "crawl_rows": int,           # 爬取到的行数
       "crawl_file": str,           # 主 CSV 文件路径
       "incremental_file": str,     # 增量 CSV 文件路径（新增）
       "failed_file": str,          # 失败记录文件路径（新增）
       "import_result": {...},      # 导入结果
       "error_message": str         # 错误信息
   }
   ```

3. **实现流程**: 新增详细的 10 步实现流程说明
   1. 提取变量（user_id）用于异常处理日志
   2. 验证 crawler_type 参数
   3. 从环境变量读取爬虫配置（username, password, token）
   4. Token 解密（使用 TokenEncryption.decrypt）
   5. 创建爬虫实例（使用 CrawlerFactory.create）
   6. 执行爬取（调用 crawler.crawl）
   7. 读取生成的 CSV 文件（优先读取增量文件，如果为空则读取主文件）
   8. 调用 batch_import_tasks_from_csv 方法导入数据
   9. 根据配置决定是否删除临时 CSV 文件
   10. 返回爬取和导入的综合结果

4. **异常处理**: 新增 7 种异常类型的处理说明
   - `CrawlerConfigError`: 返回业务错误码 400
   - `CrawlerTimeoutError`: 返回业务错误码 500，记录超时日志
   - `CrawlerAPIError`: 返回业务错误码 500，记录 API 错误日志
   - `FileNotFoundError`: CSV 文件未生成，返回业务错误码 500
   - `ValueError`: 参数验证失败，返回业务错误码 400
   - 数据库异常: 执行 rollback，返回业务错误码 500
   - 未知异常: 记录详细日志，返回业务错误码 1000

5. **日志记录**: 新增 3 个级别的日志记录说明
   - INFO: 爬取开始、爬取完成、导入开始、导入完成
   - WARNING: 部分数据导入失败
   - ERROR: 爬取失败、导入失败、文件操作失败

### 2.5 API 接口设计 (`POST /tasks/crawl-and-import`)

#### 2.5.1 请求参数

**修改项**:
1. **移除 `crawl_url`**: 改为使用固定 API 端点
2. **`skip_duplicates` 说明更新**: 明确为"重复任务组合（resource_url + liveroom_id + liveroom_title）"
3. **`crawl_options` 字段更新**:
   - **修改前**: `max_rows`, `start_date`, `end_date`
   - **修改后**: `page_size`, `max_pages`

#### 2.5.2 响应格式

**修改项**:
1. **成功响应**:
   - 新增 `incremental_file` 字段（增量 CSV 文件路径）
   - 新增 `failed_file` 字段（失败记录文件路径）
   - `crawl_rows` 说明更新为"本次爬取的总行数（包括增量）"
   - `failed_rows` 和 `skipped_rows` 中新增 `liveroom_title` 字段
   - `reason` 说明更新为"任务组合已存在（相同的resource_url + liveroom_id + liveroom_title）"

2. **错误响应**:
   - 爬取失败响应中新增 `crawl_file`, `incremental_file`, `failed_file` 字段（值为 `null`）
   - 错误信息更新为"Connection timeout after 10s"（与实际超时时间一致）

#### 2.5.3 HTTP 状态码

**保持不变**: 统一使用 HTTP 200，业务状态码在 response body 的 `code` 字段中返回
- `code: 200`: 成功
- `code: 207`: 部分成功
- `code: 400`: 参数错误
- `code: 500`: 爬取/导入失败
