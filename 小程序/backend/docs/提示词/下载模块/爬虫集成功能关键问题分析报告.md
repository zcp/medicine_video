## 三、问题2：`clean_old_files()` 风险

### 3.1 问题描述

`dynamicCrawler_vzan.py` 中有一个 `clean_old_files()` 方法，它会删除爬取的CSV文件。

### 3.2 `clean_old_files()` 行为分析

**删除的文件**：
```python
files_to_clean = [
    self.liveroom_list_savefile,        # ⚠️ 删除主文件
    self.liveroom_details_savefile,
    self.failed_liveroomlist_url,       # ⚠️ 删除失败文件
    self.failed_liveroomdetails_url,
    self.failed_liveroom_watchers_url
]
```

**关键发现**：
- ✅ **增量文件不会被删除**（`liveroom_list_savefile_inc` 不在清理列表中）
- ⚠️ **主文件会被删除**
- ⚠️ **失败文件会被删除**

### 3.3 当前调用情况

在 `dynamicCrawler_vzan.py` 的 `main()` 函数中：

```python
# 第1183行
#crawler.clean_old_files()  # ✅ 已注释，不会被调用
```

**结论**: 当前实现中，`clean_old_files()` 是被注释掉的，不会影响CSV文件。

### 3.4 潜在风险

⚠️ **如果未来取消注释或在其他地方调用**：
1. 在爬取后导入前调用 → CSV文件被删除 → 导入失败
2. 在爬取前调用 → 删除旧文件 → 正常（但会丢失历史数据）

### 3.5 解决方案

✅ **在文档中增加说明**：

1. **在 VzanCrawler 适配器实现中添加警告**：

```python
#### 4.2.5 重要警告

⚠️ **关于 clean_old_files() 方法**：

`DuanShuCrawler_vzan` 类中有一个 `clean_old_files()` 方法，它会删除以下文件：
- 主文件 (`liveroom_list_savefile`)
- 失败文件 (`failed_liveroomlist_url`)

**注意**：
1. ✅ **不要在爬取后、导入前调用此方法**，否则CSV文件会被删除
2. ✅ 增量文件不会被删除（不在清理列表中）
3. ✅ 当前 `dynamicCrawler_vzan.py` 的 `main()` 中已注释此方法
4. ✅ VzanCrawler 适配器**不应调用**此方法

**正确的清理时机**：
- 在 `crawl_and_import_tasks` 服务层方法的 finally 块中清理
- 根据 `CRAWL_IMPORT_DELETE_TEMP_FILE` 配置决定是否删除
```

2. **在服务层方法实现中明确说明**：

```python
**【第十一步：清理临时文件】**（finally块）
- 如果 `settings.CRAWL_IMPORT_DELETE_TEMP_FILE == True`
- **删除方式**：使用 `os.remove()` 直接删除文件
- **不要调用** `crawler.clean_old_files()` 方法
- 删除 `csv_path`, `incremental_file`, `failed_file`
- 捕获删除异常，仅记录警告

**实现代码**：
```python
finally:
    # 清理临时文件
    if settings.CRAWL_IMPORT_DELETE_TEMP_FILE:
        # ⚠️ 重要：只删除增量文件和失败文件，不删除主文件
        files_to_delete = [
            incremental_file,  # ✅ 删除增量文件（已导入，无需保留）
            failed_file        # ✅ 删除失败文件（可选）
        ]
        # ❌ 不删除主文件：csv_path (需要保留作为下次增量爬取的基准)
        
        for file_path in files_to_delete:
            try:
                if file_path and os.path.exists(file_path):
                    os.remove(file_path)
                    logger.info(f"已删除临时文件: {file_path}")
            except Exception as e:
                logger.warning(f"删除临时文件失败: {file_path}, 错误: {str(e)}")
        
        # 记录主文件保留
        if csv_path and os.path.exists(csv_path):
            logger.info(f"保留主文件用于下次增量爬取: {csv_path}")
```

## 四、问题3：Playwright依赖未说明

### 4.1 问题描述

`DuanShuCrawler_vzan` 在 `__init__` 中会启动 Playwright：

```python
self.playwright = sync_playwright().start()
self.browser = self.playwright.chromium.launch(headless=False)
```

**问题**：
1. 当前代码生成指令没有说明这个依赖
2. VzanCrawler 适配器创建 `DuanShuCrawler_vzan` 实例时会自动启动浏览器
3. 可能导致资源泄漏（浏览器未关闭）

### 4.2 影响

⚠️ **风险**：
1. 浏览器进程未关闭，导致资源泄漏
2. 多次调用时可能导致多个浏览器实例
3. headless=False 会显示浏览器窗口，不适合生产环境

### 4.3 解决方案

✅ **在文档中添加说明**：

1. **在 VzanCrawler 实现流程中添加**：

```python
#### 4.2.6 浏览器资源管理

⚠️ **重要**：`DuanShuCrawler_vzan` 在初始化时会启动 Playwright 浏览器。

**影响**：
1. 初始化时自动启动浏览器（headless=False，会显示窗口）
2. 爬取完成后需要调用 `self.crawler.close()` 关闭浏览器
3. 未关闭会导致浏览器进程泄漏

**VzanCrawler 实现要求**：

在 `crawl()` 方法的 finally 块中添加：
```python
def crawl(self, config: Dict, **kwargs) -> Dict:
    try:
        # ... 爬取逻辑 ...
        return crawl_result
    except Exception as e:
        logger.error(f"VzanCrawler: 爬取失败 - {str(e)}", exc_info=True)
        raise CrawlerError(f"爬取失败: {str(e)}")
    finally:
        # 关闭浏览器，释放资源
        try:
            if hasattr(self, 'crawler') and self.crawler:
                self.crawler.close()
                logger.info("VzanCrawler: 已关闭浏览器")
        except Exception as e:
            logger.warning(f"VzanCrawler: 关闭浏览器失败 - {str(e)}")
```

**注意**：
- ✅ 务必在 finally 块中关闭浏览器
- ✅ 即使爬取失败，也要关闭浏览器
- ✅ 捕获关闭异常，防止掩盖原始错误
```
