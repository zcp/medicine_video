## 2. 被测逻辑总览（供你理解，不要重写）

业务爬虫已经根据“**最终版爬取方案 V2（三重循环 + 页面级停止 + 失败重试）**”实现：

1. **状态库：**

   * 使用 SQLite 数据库 `vzan_crawler.db` 作为状态库，替代原来的 CSV 全量状态文件。
   * 表结构（简化）：

     * `liversoms(id TEXT PRIMARY KEY, ..., starttime TEXT, video_url TEXT, error_reason TEXT, ...)`
     * `failed_pages(page_url TEXT PRIMARY KEY)`。

2. **时间锚点：**

   * `latest_success_time` **必须** 基于 `starttime` 计算，而不是 `addtime`：

     ```sql
     SELECT MAX(starttime) FROM liversoms
     WHERE video_url IS NOT NULL AND video_url != '';
     ```

3. **成功 / 失败判断：**

   * 成功记录：`video_url IS NOT NULL AND video_url != ''`。
   * 失败记录：`video_url IS NULL OR video_url = ''`。

4. **三重循环逻辑（在 `parse_all_liveroomlist_data` 中）：**

   * **循环 1：Page 失败重试**

     * 从 `failed_pages` 中读取 `pages_to_retry`，用 `request_page_by_url()` 重新请求，并调用 `process_page_items()` 处理。
   * **循环 2：增量爬取（页面级停止 + 页内不提前 break）**

     * 通过 `get_liveroom_list()` 按页获取数据，调用 `process_page_items()`，如果整页都是旧数据，则停止翻页。
   * **循环 3：ID 失败重试**

     * 通过 `load_failed_ids_from_db()` 刷新失败 ID 集合，对每个 ID 调用 `crawl_single_item_by_id()` 重试。

5. **去重逻辑：**

   * SQLite 层面：`liversoms.id` 为主键，使用 `INSERT OR REPLACE`，保证每个 ID 最终只保留一条记录。
   * 本轮增量 CSV：使用 `inc_ids_processed`（Python 集合）对写入 `liveroomlist_inc_vzan_backup.csv` 的数据做 ID 级去重。

## 3. 测试代码的目标

请基于上面的代码与策略，为 `dynamicCrawler_vzan_v3.py` 生成一套**自动化测试代码**（建议使用 `pytest`，如不指定也可以使用 `unittest`），重点验证：

1. **不会重复记录爬取数据：**

   * 同一个直播间 ID **在数据库中只会有一条最终记录**（通过 `id` 主键 + `INSERT OR REPLACE` 保证）；
   * 同一个直播间 ID **在一次运行所产生的 inc CSV 文件里最多出现一次**（通过 `inc_ids_processed` 保证）。

2. **不会漏爬“应该被爬取”的数据：**

   * 在给定的模拟数据中，所有“**新数据**（starttime > latest_success_time）”会被处理；
   * 所有“**历史失败数据**（DB 里 video_url 为空）”会在循环 3 被重试；
   * 确认“**页内不因为时间条件提前 break**”，不会出现“第 3 条旧数据 → 第 4~10 条漏爬”的情况。

3. **正确区分并保存成功 / 失败记录：**

   * `save_single_to_db()` 必须按照 `video_url` 是否为空来决定成功 / 失败状态是否写入 DB。
   * DB 中成功记录的 `video_url` 不为空，失败记录的 `video_url` 为空且 `error_reason` 有意义描述。

4. **latest_success_time 逻辑正确：**

   * `load_state_from_db()` 只从 `video_url 非空` 的记录中取 `MAX(starttime)` 作为 `latest_success_time`；
   * 失败记录（video_url 为空）即使 starttime 更晚，也不应该影响 `latest_success_time`。

5. **三重循环顺序与行为符合策略：**

   * **循环 1**：只处理 `failed_pages` 中的页面；
   * **循环 2**：按页增量：

     * 页面级停止条件：当 `page_is_entirely_old == True 且 latest_success_time 不为空` 时停止；
     * 页内不提前 break，只通过 `process_page_items()` 返回的 `page_is_entirely_old` 控制是否停止翻页。
   * **循环 3**：必须在循环 2 之后再次从 DB 刷新失败 ID 集合，并逐个重试。

6. **Page 级失败处理：**

   * 发生页面请求异常时，当前页要被记录到 `failed_pages`；
   * 下次运行时，这些页会被循环 1 取出重试；
   * 本轮结束时，只把本轮仍然失败的页写回 `failed_pages`。
