# 一致性检测提示词母版 - 使用指南

**版本**: V1.0  
**创建日期**: 2026-01-18  
**适用工具**: Cursor IDE

---

## 📖 快速开始

本指南将帮助你在 Cursor 中使用**一致性检测提示词母版**，为指定功能模块生成一致性检测提示词文档。

---

## 🎯 使用场景

当你需要为某个功能模块生成一致性检测提示词时，可以使用本母版：

1. **SQLAlchemy模型与Pydantic Schema一致性检查提示词**
   - 用于检测ORM模型与API Schema的一致性
   - 检查字段命名、数据类型、Create/Update/Response Schema等

2. **SQLAlchemy模型与数据库设计文档一致性验证提示词**
   - 用于检测ORM模型与DDL规范的一致性
   - 检查表映射、字段对应、数据类型、索引、外键等

---

## 📝 使用步骤

### 步骤1: 准备输入信息

在使用母版之前，你需要准备以下信息：

**必需信息**:
- **功能模块名称**（中文）：如 `专题功能`、`内容管理模块` 等
- **模块名**（英文，小写，下划线分隔）：如 `topic`、`content_management` 等
- **项目路径**：如 `live_core_service`、`backend/live_core_service` 等

**可选信息**:
- **功能模块描述**：功能模块的简要描述（可选）
- **检测类型**：`SQLAlchemy与Pydantic` / `SQLAlchemy与DDL` / `两种都生成`（默认）
- **设计文档路径**：如 `docs/03_系统设计/专题功能完整设计文档-修正版.md`（用于DDL检测）

### 步骤2: 在Cursor中使用@引用母版文档

在 Cursor 的聊天窗口中，使用 `@` 符号引用母版文档：

```
@docs/提示词/提示词母版/一致性检测提示词母版.md
```

### 步骤3: 提供输入信息

在引用母版文档后，提供你的输入信息。你可以使用以下格式：

#### 格式1: 简洁格式（推荐）

```
@docs/提示词/提示词母版/一致性检测提示词母版.md

请为以下功能模块生成一致性检测提示词：

功能模块名称: 专题功能
模块名: topic
项目路径: live_core_service
检测类型: 两种都生成
设计文档路径: docs/03_系统设计/专题功能完整设计文档-修正版.md
```

#### 格式2: 详细格式

```
@docs/提示词/提示词母版/一致性检测提示词母版.md

请为以下功能模块生成一致性检测提示词：

**功能模块信息**:
- 功能模块名称: 专题功能
- 模块名: topic
- 项目路径: live_core_service
- 功能模块描述: 专题聚合功能，用于聚合多个分类和直播间
- 检测类型: 两种都生成
- 设计文档路径: docs/03_系统设计/专题功能完整设计文档-修正版.md
```

#### 格式3: 只生成一种检测类型

```
@docs/提示词/提示词母版/一致性检测提示词母版.md

请为以下功能模块生成一致性检测提示词：

模块名: topic
项目路径: live_core_service
检测类型: SQLAlchemy与Pydantic
```

## ❓ 常见问题

### Q1: 如何确定模块名？

**A**: 模块名通常是功能模块的英文名称，使用小写字母和下划线分隔。例如：
- `专题功能` → `topic`
- `内容管理模块` → `content_management`
- `用户管理模块` → `user_management`

### Q2: 检测类型应该选择哪个？

**A**: 
- 如果你需要检测**ORM模型与API Schema的一致性**，选择 `SQLAlchemy与Pydantic`
- 如果你需要检测**ORM模型与数据库设计文档的一致性**，选择 `SQLAlchemy与DDL`
- 如果你需要**两种检测都进行**，选择 `两种都生成`（默认）

### Q3: 设计文档路径是必需的吗？

**A**: 
- 如果生成 `SQLAlchemy与DDL` 检测提示词，**设计文档路径是必需的**，因为需要从设计文档中提取DDL规范
- 如果只生成 `SQLAlchemy与Pydantic` 检测提示词，设计文档路径是**可选的**

### Q4: 生成的提示词文档保存在哪里？

**A**: 默认情况下，生成的提示词文档会保存到：
```
docs/提示词/提示词母版/
```

如果你需要保存到其他位置，可以在请求中明确指定。

### Q5: 可以使用相对路径吗？

**A**: 是的，所有路径都可以使用相对路径（相对于项目根目录）。例如：
- `live_core_service` 或 `backend/live_core_service`
- `docs/03_系统设计/专题功能完整设计文档-修正版.md`

## 🎓 最佳实践

1. **明确指定检测类型**：虽然默认会生成两种，但明确指定可以避免生成不需要的文档

2. **提供完整信息**：提供所有必需信息可以确保生成的提示词文档更准确

3. **检查生成的文档**：生成后，检查一下生成的提示词文档是否符合你的需求

4. **保存到合适的位置**：如果项目有特定的文档组织结构，可以在请求中指定保存位置

5. **参考现有文档**：如果项目中有类似的功能模块提示词文档，可以参考其格式和内容

## 🔄 工作流程示例

### 完整工作流程

1. **准备阶段**
   - 确定功能模块名称和模块名
   - 确认项目路径

   - 根据检测结果修复代码问题
