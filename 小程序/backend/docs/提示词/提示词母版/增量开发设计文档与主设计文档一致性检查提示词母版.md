## 二、快速使用（用户操作）

**如何触发检查**：将本母版提示词与以下指令一起提供给 AI：

```
请按《增量开发设计文档与主设计文档一致性检查提示词母版》执行专家模块主文档与增量文档的一致性检查。

1. 读取配置区指定的主设计文档、增量设计文档、检查清单（若检查清单引用 CRUD/Service 增量提示词，则一并读取）

2. 按检查清单逐项检查，输出《一致性检查报告》

3. 一次性完成检查清单全部检查项，不得遗漏
```

**检查其他模块时**：修改配置区中的主设计文档、增量设计文档、检查清单路径为对应模块的路径。

## 三、AI 角色与任务

你是一名极其严谨的技术文档一致性审计师。你的任务是：

1. **动态读取**配置区指定的主设计文档、增量设计文档、检查清单，及增量提示词（若检查清单引用）（使用 read_file 工具）
2. **按检查清单逐项**对比两份文档，判定每项是否一致
3. **一次性完成**全部检查项，输出《一致性检查报告》
4. **不得遗漏**任何检查项；不得猜测或跳过

**硬性要求**：
- **禁止猜测**：必须先读取配置区指定文档的完整内容，再开始检查；不得依赖记忆或猜测
- **逐项检查**：按检查清单顺序逐项执行，不跳过、不合并、不遗漏
- **引用依据**：每项检查须引用文档中的具体位置（章节、行号或段落）作为依据
- **可操作建议**：对不一致项须给出具体修改建议（文档名、位置、建议内容）

## 四、执行流程

### 4.1 第一步：动态读取文档（必须执行）

执行以下读取操作，获取完整内容：

1. **读取主设计文档**
   - 路径：配置区指定的主设计文档路径
   - 覆盖范围：按检查清单要求覆盖主文档相关章节（如设计要点、表结构、Schemas、API、错误处理等）

2. **读取增量设计文档**
   - 路径：配置区指定的增量设计文档路径
   - 全文读取

3. **读取检查清单**
   - 路径：配置区指定的检查清单路径
   - 全文读取，按清单顺序执行

4. **读取 CRUD/Service 增量提示词（若需）**
   - 当检查清单包含对增量代码生成提示词的检查项（如 L 类易错点）时，读取配置区「CRUD/Service 增量提示词」中列出的路径

**禁止**在未读取文档的情况下进行任何检查或输出结论。

**动态读取方式**：使用 `read_file` 工具读取上述文档的完整内容；若文档较长，可分段读取，但须确保覆盖检查清单所引用的所有内容。

---

### 4.2 第二步：按清单逐项检查

对检查清单中的**每一项**，执行以下操作：

1. **定位主文档依据**：在主设计文档中找到与该检查项对应的内容（章节、段落）
2. **定位增量文档内容**：在增量设计文档中找到相关描述
3. **对比判定**：
   - 若一致：输出 ✅，简要说明依据位置
   - 若不一致或缺失：输出 ⚠️，注明「主文档位置」「增量文档位置」「不一致点」「建议修改」

**检查顺序**：严格按检查清单 A → B → C → … → L 的顺序，不跳过、不合并。

---

## 五、检查清单摘要（供 AI 快速对照）

执行时须与配置区指定的检查清单文件逐项对照。以下为**专家模块**清单结构摘要，其他模块以检查清单文件为准，**完整内容须从检查清单文件动态读取**：

### 方向 A：增量文档服从主文档

- **A 术语与架构**：user_id、role、架构分层、权限守卫、响应结构、状态码、JWT
- **B 编程规范**：异步、UUID、用户身份提取、HTTP、路径、执行流程、CRUD 过滤
- **C 日志规范**：脱敏、UUID 前 8 位、日志级别、变量提取、contact_info
- **D 异常规范**：业务异常、错误码、IntegrityError、404 伪装、异常脱敏
- **E 数据库规范**：UUID 主键、时间戳、外键、user_id 类型、索引、软删除
- **F 安全规范**：环境变量、.env、配置验证、CORS、敏感信息、错误消息脱敏
- **G 事务规范**：提交前校验、异常回滚、BusinessException、唯一约束

### 方向 B：主文档吸纳增量文档

- **H 新增内容**：批量导入接口、BatchImportExpertsResult、experts 表 is_active
- **I 修改内容**：软删除、ExpertCreate/Update/Item、get_featured_experts、get_experts_multi_and_total、delete_expert、_check_expert_visibility、API 响应、Admin GET experts
- **J 补充内容**：check_is_followed 执行流程、_check_user_resource_permission、批量导入 API 层要求、set_session_experts 校验、get_expert 约定、批量导入文件校验

### 交叉引用与易错点

- **K 交叉引用**：依赖表、阅读顺序、修订说明、增量提示词引用
- **L 易错点**：批量导入权限、check_is_followed 权限、get_experts_multi_and_total、关注列表 CRUD、批量导入异常处理、_check_expert_visibility 参数

## 六、质量标准

1. **完整性**：检查清单全部项检查，无遗漏
2. **依据**：每项结论须有文档引用（章节或段落）
3. **可操作性**：需修改项须给出具体修改建议
4. **一次性**：单次执行完成全部检查，不依赖多轮对话补充

---

## 七、适配其他模块

本母版可用于其他模块的一致性检查。使用时：

1. 修改「配置区」中的主设计文档、增量设计文档、检查清单路径
2. 若该模块有专用检查清单，使用该清单；若无，可复用专家模块检查清单（见配置区路径）或基于其定制
3. 检查清单中的「主文档具体依据」须与目标主文档的章节结构对应
