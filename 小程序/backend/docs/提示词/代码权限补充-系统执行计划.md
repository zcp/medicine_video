## 执行原则

### 1. 最小幅度修改原则

```python
✅ 只添加：
- 权限相关的参数（user_id, user_role, current_user_id, role）
- 权限守卫函数调用
- 权限异常捕获

✅ 只修改：
- 方法签名（增加权限参数）
- 方法调用（增加权限参数传递）

❌ 禁止：
- 修改任何业务逻辑执行流程
- 删除或重命名任何现有方法
- 改变任何方法的返回值结构（除非提示词明确要求新增字段）
- 重写任何已有业务逻辑代码
```

### 2. 三层职责分工原则

```python
API 层 (Endpoint):
- 负责: Authentication (认证)
- 任务: 解析 "你是谁" (User vs Anonymous)
- 禁止: 不做任何权限判断
- 必须: 将 user_id 和 role 传递给 Service 层
- 禁止: 不直接抛出 HTTPException

Service 层:
- 负责: Authorization (鉴权)
- 任务: 判定 "你能看吗/你能改吗"
- 必须: 调用权限守卫函数
- 必须: 决定是否允许访问
- 必须: 抛出 PermissionDeniedException (业务异常)

CRUD 层:
- 负责: 数据访问 + SQL 层面权限过滤
- 任务: 在 WHERE 条件中应用权限过滤
- 必须: 接收 current_user_id 和 role 参数
- 必须: 应用权限过滤逻辑
```

### 3. 双轨鉴权模式应用

```python
Strict Auth (写操作):
- 使用: get_current_user
- 适用: 所有写操作 (POST, PUT, PATCH, DELETE)
- 行为: 无 Token → 401, Token 无效 → 401

Optional Auth (读操作):
- 使用: get_current_user_optional
- 适用: 所有读操作 (GET)
- 行为: 无 Token → None, Token 无效 → 401
- 严禁: 不能降级为匿名 (Token 无效时必须报 401)
```
