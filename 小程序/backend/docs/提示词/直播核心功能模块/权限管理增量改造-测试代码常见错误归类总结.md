# 权限管理增量改造 - 测试代码常见错误归类总结

本文档基于 `权限管理增量改造-测试代码常见错误及解决方案.md`，对所有错误进行了系统化归类总结。

## 错误类型归类（共16类）

### 类型1：缺少 role 参数

**错误信息**：
- `TypeError: xxx() missing 1 required positional argument: 'role'`

**错误原因**：
权限改造后，Service层方法新增了 `role` 参数用于权限检查，但测试代码调用时未传递该参数。

**涉及的方法**：
- `upload_topic_banner()`
- `import_create_session()`
- `create_new_room()`
- `update_topic()`
- `delete_topic()`
- `create_category()`
- `update_category()`
- `add_rooms_to_category()`
- `update_room_sort_order()`
- `remove_rooms_from_category()`
- `create_tab()`
- `update_tab()`
- `create_message()`

**解决方法**：
在方法调用前定义 `role` 变量（如 `role = "REGULAR"` 或 `role = "ADMIN"`），并在调用时传递该参数。

---

### 类型2：变量名未定义

**错误信息**：
- `NameError: name 'regular_user_id' is not defined`
- `NameError: name 'regular_user_token' is not defined`
- `NameError: name 'regular_user_role' is not defined`
- `NameError: name 'another_user_id' is not defined`
- `NameError: name 'headers' is not defined`

**错误原因**：
测试函数使用了变量但没有在函数参数中声明为 fixture，或使用了未定义的变量名。

**解决方法**：
1. 在测试函数签名中添加缺失的 fixture 参数（如 `regular_user_id: uuid.UUID`）
2. 在测试函数内部定义变量（如 `role = "REGULAR"` 而不是使用未定义的 `regular_user_role`）
3. 在使用前定义变量（如 `headers = {"Authorization": f"Bearer {token}"}`）

---

### 类型3：异常类型不匹配

**错误信息**：
测试通过但异常类型不正确，或 `pytest.raises` 捕获的异常类型不匹配。

**错误原因**：
测试中使用了旧的或错误的异常类型名称。

**涉及的错误映射**：
- `TopicPermissionDeniedException` → `PermissionDeniedException`

**解决方法**：
更新导入语句和 `pytest.raises` 中的异常类型。

---

### 类型4：Async Generator Fixture 访问属性问题

**错误信息**：
- `AttributeError: 'async_generator' object has no attribute 'id'`
- `ValueError: 无法从fixture中获取id：generator已被消费且未解析`
- `StopAsyncIteration`

**错误原因**：
`published_topic`、`draft_topic`、`public_room`、`private_room` 等 fixture 是异步生成器（async generator），在特定情况下（如嵌套循环、pytest版本问题）pytest无法自动解析，导致直接访问 `.id` 属性失败。

**解决方法**：
1. **方案A（推荐）**：在循环外部直接迭代 fixture generator：
   ```python
   async for pt in published_topic:
       published_topic_id = pt.id
       break
   async for client, app, db in topic_client:
       # 使用 published_topic_id
   ```

2. **方案B**：使用辅助函数（仅用于简单循环场景）：
   ```python
   async def get_fixture_id(fixture_obj):
       if hasattr(fixture_obj, 'id') and not inspect.isasyncgen(fixture_obj):
           return fixture_obj.id
       if inspect.isasyncgen(fixture_obj):
           async for obj in fixture_obj:
               return obj.id
       raise ValueError("无法从fixture中获取id")
   ```

**关键点**：
- 对于嵌套循环（如 `async for client in async_client:` + `async for db in db_session:`），将 fixture 解析放在外层循环内、内层循环之前
- 对于 `topic_client` 等会消费 `db_session` 的 fixture，在其循环之前解析所有依赖 `db_session` 的 fixture
- 避免重复消费 async generator

### 类型5：CRUD层参数名不匹配

**错误信息**：
- `KeyError: 'role'`

**错误原因**：
Service 层参数名为 `role`，但 CRUD 层参数名为 `current_user_role`。在断言中使用 `call_args[1]['role']` 会失败。

**解决方法**：
将断言改为 `call_args[1]['current_user_role']`。

---

### 类型6：Mock对象状态不符合权限要求

**错误信息**：
- `app.exceptions.TopicNotFoundException: Topic not found`

**错误原因**：
测试中创建的 mock topic 默认是 `DRAFT` 状态，匿名用户无法访问，导致权限检查失败。

**解决方法**：
1. 为匿名用户测试创建 `PUBLISHED` 状态的 topic
2. 手动设置 `mock_topic.status = TopicStatus.PUBLISHED`
3. 设置 `mock_room.is_private = False`（对于房间测试）

---

### 类型7：FastAPI HTTPException 响应格式不一致

**错误信息**：
- `KeyError: 'code'`

**错误原因**：
FastAPI 的默认 `HTTPException` 返回格式是 `{"detail": "..."}`，没有 `code` 字段。测试期望包含自定义格式 `{"code": ...}`。

**解决方法**：
在测试中兼容两种错误格式：
```python
if "code" in response_json:
    assert response_json["code"] in [1001, 401]
else:
    assert "detail" in response_json  # FastAPI默认错误格式
```

---

### 类型8：权限检查返回状态码变更

**错误信息**：
- `assert 403 == 404`
- `assert 3002 == 2004`
- `assert 3002 == 2005`

**错误原因**：
权限检查逻辑变更，现在抛出 `PermissionDeniedException`（403，code 3002），而不是 `NotFoundException`（404，code 2001）。或业务逻辑异常（如 `SessionActionForbiddenException`）返回 403，而不是 404。

**错误码对应关系**：
- `PermissionDeniedException` → 403, code 3002
- `SessionActionForbiddenException`（更新session） → 403, code 2004
- `SessionActionForbiddenException`（删除session） → 403, code 2005
- `NotFoundException` → 404, code 2001

**解决方法**：
更新测试期望状态码和错误码。

---

### 类型9：响应字段缺失

**错误信息**：
- `KeyError: 'is_private'`

**错误原因**：
响应中可能缺少某些字段（可能来自其他测试数据）。

**解决方法**：
在访问字段前检查字段是否存在，并且只检查本测试创建的数据：
```python
for item in data["items"]:
    if item["id"] in [str(room1.id), str(room2.id)]:  # 只检查本测试创建的数据
        if "is_private" in item:  # 检查字段是否存在
            assert item["is_private"] == False
```

### 类型10：AssertionError - 断言期望的参数与实际不符

**错误信息**：
- `AssertionError: expected call not found. Expected: get(..., user_id='...') Actual: get(...)`

**错误原因**：
Service 层方法内部调用 CRUD 层的 `get` 时只传递 `room_id`，不传递 `user_id`。权限检查在 Service 层完成，CRUD 层只负责数据查询。

**解决方法**：
更新断言，移除不存在的 `user_id` 参数：
```python
# 修改前
mock_get.assert_called_once_with(db=None, room_id=room_id, user_id=user_id)

# 修改后
mock_get.assert_called_once_with(db=None, room_id=room_id)
```

---

### 类型11：SQLAlchemy表达式布尔值判断错误

**错误信息**：
- `TypeError: Boolean value of this clause is not defined`
- `DatabaseOperationException: 数据库查询失败: Boolean value of this clause is not defined`

**错误原因**：
SQLAlchemy 的 SQL 表达式对象不能直接用于布尔判断（如 `if search_conditions:`）。

**解决方法**：
使用 `is not None` 或 `is None` 来判断：
```python
# 修改前（错误）
if search_conditions:  # ❌ SQLAlchemy 表达式不能用于布尔判断
    query = query.where(search_conditions)

# 修改后（正确）
if search_conditions is not None:  # ✅ 使用 is not None 判断
    query = query.where(search_conditions)
```

**影响范围**：
- `app/crud/room.py::list_with_search`

### 类型12：批量导入需要管理员权限

**错误信息**：
- `assert 403 == 200`
- `WARNING app.api.v1.endpoints.batch_import:权限不足: public_id=..., role=REGULAR`

**错误原因**：
批量导入功能（`/api/v1/rooms/import/batch`）需要管理员权限（`ADMIN` 或 `SUPERADMIN`），但测试使用的是普通用户（`role=REGULAR`）。

**解决方法**：
1. 创建管理员客户端 fixture：
   ```python
   @pytest.fixture
   async def async_client_with_admin_role(regular_user_id: uuid.UUID, admin_user_role: str):
       # ... 使用 admin_user_role ("ADMIN")
   ```

2. 在测试中使用管理员客户端：
   ```python
   async for admin_client in async_client_with_admin_role:
       batch_response = await admin_client.post(
           "/api/v1/rooms/import/batch?mode=apply",
           files={'file': ('test.csv', csv_file, 'text/csv')}
       )
       assert batch_response.status_code == 200
       break
   ```

### 类型13：错误消息语言不匹配

**错误信息**：
- `AssertionError: assert 'not found' in '资源不存在'`

**错误原因**：
后端返回中文错误消息，但测试期望英文消息。

**解决方法**：
更新断言，兼容中英文两种消息：
```python
# 修改前
assert "not found" in response_json["message"].lower()

# 修改后
assert "资源不存在" in response_json["message"] or "not found" in response_json["message"].lower()
```

### 类型14：测试数据一致性问题

**错误信息**：
- `assert 3002 == 2004`（期望业务逻辑异常，实际得到权限异常）

**错误原因**：
测试中创建的 room 使用了默认的硬编码 `user_id`，但 `regular_user_token` 中的 `user_id` 是另一个（来自 fixture），导致权限检查失败，抛出 `PermissionDeniedException`（3002），无法到达业务逻辑检查。

**解决方法**：
在创建测试数据时传入正确的 `user_id`，使用 `regular_user_id` fixture，确保数据属于当前用户：
```python
# 修改前
room = await create_test_room_in_db(db)  # ❌ 使用默认user_id

# 修改后
room = await create_test_room_in_db(db, user_id=regular_user_id)  # ✅ 使用当前用户的user_id
```

---

### 类型15：Mock db未正确设置

**错误信息**：
- `AttributeError: 'NoneType' object has no attribute 'execute'`

**错误原因**：
Service 方法需要访问 `self.db`，但测试中创建 Service 时传入 `db=None`。

**解决方法**：
1. 为 Service 提供 mock db：`RoomService(db=MagicMock())`
2. Mock CRUD 层的数据库操作

---

### 类型16：后端代码导入错误

**错误信息**：
- `ImportError: cannot import name 'NotFoundException' from 'app.exceptions'`
- `NameError: name 'NotFoundException' is not defined`

**错误原因**：
后端代码使用了异常类但没有从 `app.exceptions` 导入。

**解决方法**：
在后端代码的导入语句中添加缺失的异常类：
```python
from app.exceptions import NotFoundException
```

## 错误类型统计

| 错误类型 | 出现频率 | 严重程度 | 影响范围 |
|---------|---------|---------|---------|
| 类型1：缺少 role 参数 | ⭐⭐⭐⭐⭐ | 高 | Service层所有方法 |
| 类型2：变量名未定义 | ⭐⭐⭐⭐ | 中 | 所有测试文件 |
| 类型4：Async Generator Fixture | ⭐⭐⭐⭐ | 中 | 集成测试文件 |
| 类型7：响应格式不一致 | ⭐⭐⭐ | 中 | API层测试 |
| 类型8：状态码变更 | ⭐⭐⭐ | 中 | API层测试 |
| 类型11：SQLAlchemy布尔判断 | ⭐ | 低 | CRUD层（已修复后端） |
| 其他类型 | ⭐⭐ | 低-中 | 特定场景 |

## 最佳实践建议

1. **统一使用 fixture**：所有测试用户、Token、资源都应通过 fixture 提供，避免硬编码
2. **正确的 fixture 解析顺序**：对于依赖 `db_session` 的 fixture，在消费 `db_session` 的循环之前解析
3. **兼容性检查**：在访问响应字段前检查字段是否存在
4. **错误格式兼容**：兼容 FastAPI 默认错误格式和自定义格式
5. **参数名一致性**：注意 Service 层和 CRUD 层参数名的差异（`role` vs `current_user_role`）
6. **测试数据一致性**：确保测试数据中的 `user_id` 与 Token 中的 `user_id` 一致
