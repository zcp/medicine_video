#### **3.6. 设计文档规范提取 (Design Document Specifications)**

从设计文档中提取的关键规范：

**数据库设计规范**:

1. **UUID主键生成规范**:
   - **在应用层生成**: 所有UUID主键必须在应用层通过 `uuid.uuid4()` 生成
   - **不使用数据库DEFAULT**: 不使用PostgreSQL的 `gen_random_uuid()` 函数

2. **时间戳字段规范**:
   - 统一使用 `TIMESTAMPTZ`（带时区的时间戳）
   - `created_at`: 创建时间，`DEFAULT CURRENT_TIMESTAMP`（对应 `server_default=func.now()`）
   - `updated_at`: 更新时间，通过触发器自动更新（对应 `onupdate=func.now()`）

3. **外键约束命名规范**:
   - 格式：`fk_<表名>_<字段名>`
   - 示例：`fk_session_tags_session_id`

4. **索引命名规范**:
   - 格式：`idx_<表名>_<字段名>`
   - 示例：`idx_tags_name`

5. **软删除策略**:
   - 标签表（tags）和分类表（categories）使用 `is_active` 字段实现软删除
   - 关联表（session_tags）使用硬删除（直接DELETE）

**安全与配置规范**:

1. **敏感信息处理规范**:
   - 禁止在代码中硬编码密码、密钥等敏感信息
   - 禁止在 `__repr__` 方法中暴露敏感字段
   - 禁止在注释、文档字符串中包含真实的敏感信息示例

2. **日志安全规范**:
   - `__repr__` 方法应避免暴露敏感信息
   - 仅显示必要的标识信息（如id、名称等），不包含密码、密钥等

```python
class Tag(Base):
    """
    内容标签表
```

```python
class Category(Base):

    icon = Column(String(255), nullable=True, comment='分类图标名称或URL')
    description = Column(Text, nullable=True, comment='分类描述')
    sort_order = Column(Integer, nullable=False, default=0, comment='排序权重，数字越小越靠前，用于前端展示顺序')

    updated_at = Column(TIMESTAMP(timezone=True), nullable=False, server_default=func.now(), onupdate=func.now())

        Index('idx_categories_sort_order', 'sort_order'),
        Index('idx_categories_is_active', 'is_active'),
        # 注意：部分索引 idx_categories_active_sort 需要在DDL中定义
```

##### **4.2.3. SessionTag 模型（场次-标签关联表）**

**表名**: `session_tags`

**字段定义**（根据设计文档Section 2.3）:
- `session_id`: UUID, NOT NULL, 外键到 `live_sessions.id`, 主键之一
- `tag_id`: UUID, NOT NULL, 外键到 `tags.id`, 主键之一
- `created_at`: TIMESTAMPTZ, NOT NULL, DEFAULT CURRENT_TIMESTAMP

**主键**: 复合主键 `(session_id, tag_id)`

**外键约束**（根据设计文档）:
- `fk_session_tags_session_id`: `session_id` → `live_sessions.id`, ON DELETE CASCADE
- `fk_session_tags_tag_id`: `tag_id` → `tags.id`, ON DELETE CASCADE

**索引定义**（根据设计文档）:
- `idx_session_tags_session_id`: 单字段索引，字段 `session_id`
- `idx_session_tags_tag_id`: 单字段索引，字段 `tag_id`

**关联关系**:
- 与 `Tag` 的多对一关系：`tag = relationship("Tag", back_populates="session_tags")`
- 与 `LiveSession` 的多对一关系：`session = relationship("LiveSession", foreign_keys=[session_id])`

**完整模型定义示例**:

```python
class SessionTag(Base):
    """
    直播场次与标签的多对多关联表
    
    用于定义直播场次与标签的多对多关联关系。
    使用硬删除策略（直接DELETE）。
    """
    __tablename__ = "session_tags"
    
    # 复合主键
    session_id = Column(
        UUID(as_uuid=True), 
        ForeignKey("live_sessions.id", ondelete="CASCADE"), 
        primary_key=True,
        comment='场次ID，关联live_sessions表'
    )
    tag_id = Column(
        UUID(as_uuid=True), 
        ForeignKey("tags.id", ondelete="CASCADE"), 
        primary_key=True,
        comment='标签ID，关联tags表'
    )
    
    # 时间戳
    created_at = Column(TIMESTAMP(timezone=True), nullable=False, server_default=func.now())
    
    # 索引定义
    __table_args__ = (
        Index('idx_session_tags_session_id', 'session_id'),
        Index('idx_session_tags_tag_id', 'tag_id'),
    )
    
    # 关联关系
    tag = relationship("Tag", back_populates="session_tags")
    session = relationship("LiveSession", foreign_keys=[session_id])
    
    def __repr__(self):
        return f"<SessionTag(session_id={self.session_id}, tag_id={self.tag_id})>"
```

#### **4.3. 索引创建方式**

**⚠️ 关键要求**: 所有索引必须使用 `__table_args__` 显式命名，**不能使用** `index=True`

**正确示例**:
```python

__table_args__ = (
    # 单字段索引
    Index('idx_tags_name', 'name'),
    Index('idx_tags_is_active', 'is_active'),
    
    # 组合索引
    Index('idx_categories_active_sort', 'is_active', 'sort_order'),
)
```

**不推荐的方式**（必须在提示词中明确说明）:
```python
# ❌ 不要这样做（虽然可以工作，但与现有代码风格不一致）
name = Column(String(80), nullable=False, unique=True, index=True)
```

#### **4.6. __repr__方法**

**⚠️ 安全要求**: `__repr__` 方法中**禁止暴露敏感信息**（如密码、密钥、完整连接字符串等）

**推荐格式**: 仅显示必要的标识信息（如id、名称等）

**示例**:
```python
def __repr__(self):
    return f"<Tag(id={self.id}, name={self.name})>"
# ✅ 正确：只显示id和name
# ❌ 错误：return f"<User(id={self.id}, password={self.password})>"  # 暴露密码
```
