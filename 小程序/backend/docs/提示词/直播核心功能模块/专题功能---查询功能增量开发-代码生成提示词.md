### 2.1 核心开发原则（⚠️ 必须严格遵守）

1. **最小幅度修改原则**：
   - ✅ **只增加**查询参数和相应的筛选逻辑
   - ✅ **只修改**方法签名（增加 `title`、`topic_id` 参数，使用 Optional 类型）
   - ✅ **只修改**SQL查询逻辑（增加业务筛选条件）

   - ❌ **禁止**删除或重命名任何现有方法

2. **权限控制不变原则**：
   - 权限控制逻辑**保持不变**，仅确保其正确性

3. **性能优先原则**：
   - 所有筛选条件**必须**在数据库层面通过 SQL WHERE 条件实现
   - **严禁**查出所有数据后在 Python 代码中过滤（性能陷阱）
   - 分页查询的总数计算必须应用相同的 WHERE 条件

4. **向后兼容原则**：
   - 新增的查询参数必须使用 `Optional` 类型，并提供默认值 `None`
   - 不传递新参数时，功能行为与修改前完全一致
   - 现有客户端代码无需修改即可继续使用

```python
async def get_multi_and_total(
    db: AsyncSession,
    skip: int = 0,
    limit: int = 10,
    status: Optional[TopicStatus] = None,
    title: Optional[str] = None,  # ← 新增：专题标题筛选
    topic_id: Optional[uuid.UUID] = None,  # ← 新增：专题ID筛选
    user_id: Optional[uuid.UUID] = None,
    current_user_id: Optional[uuid.UUID] = None,
    current_user_role: Optional[str] = None
) -> Tuple[List[Topic], int]:
    """
    分页获取专题列表，支持按状态、标题、ID、用户ID筛选（带权限过滤）
    
    Args:
        db: 数据库会话
        skip: 跳过的记录数（用于分页）
        limit: 返回的最大记录数
        status: 专题状态筛选条件（可选）
        title: 专题标题筛选，支持模糊匹配（可选）  # ← 新增
        topic_id: 专题ID筛选，精确匹配（可选）  # ← 新增
        user_id: 用户ID筛选条件（可选，用于业务筛选特定用户的专题）
        current_user_id: 当前用户的public_id（匿名时为None，用于权限过滤）
        current_user_role: 当前用户的角色（匿名时为None，用于权限过滤）
    
    Returns:
        Tuple[List[Topic], int]: (专题列表, 总记录数)
    """
    logger.debug(
        f"查询专题列表: skip={skip}, limit={limit}, status={status}, "
        f"title={title}, topic_id={topic_id}, user_id={user_id}, "
        f"current_user_id={current_user_id}, current_user_role={current_user_role}"
    )
    
    # 构建基础查询
    stmt = select(Topic)
    count_stmt = select(func.count()).select_from(Topic)
    
    # 1. 先应用业务筛选条件（包括新增的title和topic_id）
    business_filters = []
    if title:  # ← 新增：专题标题模糊匹配（不区分大小写）
        business_filters.append(Topic.title.ilike(f'%{title}%'))
    if topic_id:  # ← 新增：专题ID精确匹配
        business_filters.append(Topic.id == topic_id)
    if status is not None:
        business_filters.append(Topic.status == status)
    if user_id is not None:
        business_filters.append(Topic.user_id == user_id)
    
    # 2. 再应用权限过滤条件（独立于业务筛选条件，修正后的逻辑）
    permission_filters = []
    if current_user_role in ['ADMIN', 'SUPERADMIN']:
        # 管理员：无权限过滤，看所有
        pass
    elif current_user_id:
        # 普通用户：Published OR (Draft/Archived AND Own)
        # ✅ 修正：权限过滤独立于业务筛选条件，始终应用完整的权限规则
        permission_filters.append(
            or_(
                Topic.status == TopicStatus.PUBLISHED,
                and_(
                    Topic.status.in_([TopicStatus.DRAFT, TopicStatus.ARCHIVED]),
                    Topic.user_id == current_user_id
                )
            )
        )
    else:
        # 匿名用户：Only Published
        permission_filters.append(Topic.status == TopicStatus.PUBLISHED)
    
    # 3. 合并所有筛选条件（AND关系）
    all_filters = permission_filters + business_filters
    
    if all_filters:
        stmt = stmt.where(and_(*all_filters))
        count_stmt = count_stmt.where(and_(*all_filters))
    
    # 获取总数（必须应用相同的WHERE条件）
    total_result = await db.execute(count_stmt)
    total = total_result.scalar()
    
    # 应用排序和分页
    stmt = stmt.order_by(Topic.created_at.desc()).offset(skip).limit(limit)
    
    # 执行查询
    result = await db.execute(stmt)
    topics = result.scalars().all()
    
    return list(topics), total
```

**关键修改点**：
1. ✅ **只增加**了 `title` 和 `topic_id` 两个 Optional 参数
2. ✅ **只修改**了业务筛选条件的构建逻辑（增加了title和topic_id的筛选）
3. ✅ **修正**了权限过滤逻辑（使其独立于业务筛选条件）
4. ✅ **保持了**原有的分页、排序、状态筛选逻辑
5. ✅ **保持了**原有的返回类型和语义

### 6.4 关键技术实现细节

#### title 模糊匹配实现

**实现方式**：
使用PostgreSQL的 `ILIKE` 操作符（SQLAlchemy中的 `ilike` 方法）

**代码示例**：
```python
if title:
    business_filters.append(Topic.title.ilike(f'%{title}%'))
```

**技术特点**：
- **不区分大小写**：`ilike` 是 `like` 的不区分大小写版本
- **模糊匹配**：`%{title}%` 表示包含指定字符串的匹配
- **性能考虑**：`LIKE '%text%'` 模式查询对B-tree索引效果有限，如需高性能可考虑PostgreSQL全文索引

**SQL示例**：
```sql
-- 当 title = "专题" 时，生成的SQL条件
WHERE topics.title ILIKE '%专题%'
-- 会匹配："专题一"、"我的专题"、"专题列表" 等
```

#### topic_id 精确匹配实现

**实现方式**：
使用等值比较（`==` 操作符）

**代码示例**：
```python
if topic_id:
    business_filters.append(Topic.id == topic_id)
```

**技术特点**：
- **精确匹配**：使用主键字段（UUID类型）
- **高性能**：主键字段已有索引，查询性能优秀
- **类型安全**：topic_id在API层已转换为UUID类型

**SQL示例**：
```sql
-- 当 topic_id = "123e4567-e89b-12d3-a456-426614174000" 时，生成的SQL条件
WHERE topics.id = '123e4567-e89b-12d3-a456-426614174000'::uuid
```

#### 业务筛选与权限过滤的组合逻辑

**组合方式**：
业务筛选条件和权限过滤条件使用 **AND关系** 组合

**执行顺序**：
1. **先应用业务筛选条件**：title、topic_id、status、user_id
2. **再应用权限过滤条件**：根据用户身份（Admin/Regular/Anonymous）应用权限规则
3. **合并条件**：使用AND关系组合所有条件

**SQL示例（Regular用户查询title包含"专题"的draft专题）**：
```sql
-- 业务筛选条件
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'

-- 权限过滤条件
WHERE (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))

-- 最终SQL（AND关系组合）
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'
  AND (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))

-- 简化后（因为status='draft'，第一个OR条件为false）
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'
  AND topics.user_id = current_user_id
```

**结果**：只能查询到自己创建的、标题包含"专题"的draft专题 ✅
