## 3. 目标代码文件摘要

### 3.1 模型层（app/models/experts.py）

**模型类**:
- `SessionExpertRole` - 专家角色枚举（主讲、主持、嘉宾）
- `Expert` - 专家信息表
- `UserExpertSubscription` - 用户关注专家表
- `LiveSessionExpert` - 场次专家关联表

**关键字段**:
- Expert: id, user_id(unique), name, title, hospital, is_featured, sort_order
- UserExpertSubscription: id, user_id, expert_id, unique(user_id, expert_id)
- LiveSessionExpert: id, session_id, expert_id, role, sort_order, unique(session_id, expert_id, role)

### 3.2 CRUD层（app/crud/experts.py）

**Expert CRUD函数（7个）**:
1. `create_expert(db, expert_data)` - 创建专家
2. `get_expert(db, expert_id)` - 获取专家
3. `get_expert_by_user_id(db, user_id)` - 根据user_id获取专家
4. `get_featured_experts(db, limit)` - 获取推荐专家列表
5. `get_experts_multi_and_total(db, skip, limit, name, is_featured, hospital, sort)` - 分页获取专家列表
6. `update_expert(db, expert_id, expert_data)` - 更新专家
7. `delete_expert(db, expert_id)` - 删除专家（软删除）

**UserExpertSubscription CRUD函数（5个）**:
8. `create_subscription(db, user_id, expert_id)` - 创建关注记录
9. `get_subscription(db, user_id, expert_id)` - 查询关注记录
10. `get_user_subscriptions(db, user_id)` - 获取用户关注列表
11. `delete_subscription(db, user_id, expert_id)` - 删除关注记录
12. `get_subscriptions_by_expert_ids(db, user_id, expert_ids)` - 批量查询关注记录

**LiveSessionExpert CRUD函数（3个）**:
13. `get_session_experts(db, session_id, role)` - 获取场次专家列表
14. `get_expert_sessions(db, expert_id, role, skip, limit)` - 获取专家参与的场次列表
15. `set_session_experts(db, session_id, expert_data_list)` - 设置场次专家列表

**关键特性**:
- 异步函数（async/await）
- UUID在应用层生成
- 异常处理：IntegrityError → DatabaseIntegrityException
- 使用selectinload避免N+1查询
- 日志记录（UUID脱敏）

### 3.3 Service层（app/services/expert_service.py）

**权限守卫函数（3个）**:
- `_check_admin_permission(role)` - 检查管理员权限
- `_check_user_resource_permission(resource_owner_id, current_user_id, role)` - 检查用户专属资源操作权限
- `_check_expert_visibility(expert, current_user_id, role)` - 检查专家可见性

**专家信息管理Service方法（7个）**:
- `get_featured_experts(limit)` - 获取推荐专家列表
- `get_expert_detail(expert_id, current_user_id, role)` - 获取专家详情
- `get_expert_sessions(expert_id, page, size, role, current_user_id, role_user)` - 获取专家场次列表
- `create_expert(expert_data, current_user_id, role)` - 创建专家
- `get_experts_list(page, size, name, is_featured, hospital, sort, current_user_id, role)` - 获取专家列表
- `update_expert(expert_id, expert_data, current_user_id, role)` - 更新专家
- `delete_expert(expert_id, current_user_id, role)` - 删除专家

**专家关注Service方法（4个）**:
- `follow_expert(expert_id, current_user_id, role)` - 关注专家
- `unfollow_expert(expert_id, current_user_id, role)` - 取消关注
- `get_followed_experts(current_user_id, role, include_live_status)` - 获取关注列表
- `check_is_followed(expert_id, current_user_id, role)` - 检查是否已关注

**场次专家关联Service方法（2个）**:
- `set_session_experts(session_id, expert_data_list, current_user_id, role)` - 设置场次专家列表
- `get_session_experts(session_id, role, current_user_id, role_user)` - 获取场次专家列表

**关键特性**:
- 权限检查在Service层
- 事务管理（commit/rollback）
- 异常转换：DatabaseIntegrityException → InvalidParameterException
- 业务验证（user_id绑定检查等）

### 3.4 API层（app/api/v1/endpoints/experts.py）

**专家信息管理API（7个）**:
1. `GET /featured-experts` - 获取推荐专家列表（公开）
2. `GET /{expert_id}` - 获取专家详情（公开，Optional Auth）
3. `GET /{expert_id}/sessions` - 获取专家场次列表（公开，Optional Auth）
4. `POST /admin/experts` - 创建专家（Strict Auth，Admin）
5. `GET /admin/experts` - 获取专家列表（Strict Auth，Admin）
6. `PATCH /admin/experts/{expert_id}` - 更新专家（Strict Auth，Admin）
7. `DELETE /admin/experts/{expert_id}` - 删除专家（Strict Auth，Admin）

**专家关注API（4个）**:
8. `POST /users/me/followed-experts` - 关注专家（Strict Auth）
9. `DELETE /users/me/followed-experts/{expert_id}` - 取消关注（Strict Auth）
10. `GET /users/me/followed-experts` - 获取关注列表（Strict Auth）
11. `GET /{expert_id}/is-followed` - 检查是否已关注（Strict Auth）

**场次专家关联API（2个）**:
12. `POST /sessions/{session_id}/experts` - 设置场次专家列表（Strict Auth，Admin）
13. `GET /sessions/{session_id}/experts` - 获取场次专家列表（公开，Optional Auth）

**关键特性**:
- 双轨鉴权：Strict Auth / Optional Auth
- 异常处理：NotFoundException, PermissionDeniedException, InvalidParameterException
- 响应格式：success_response, error_response
- UUID格式验证
- 日志记录（UUID脱敏）

## 5. Mock策略

### 5.1 CRUD层测试

**不使用Mock**（真实数据库测试）:
- 使用pytest fixtures创建真实的数据库会话
- 使用事务回滚清理测试数据（**重要：测试函数不应调用 `await db.commit()`，依赖fixture的自动rollback**）
- 验证数据库约束（unique, foreign key, cascade delete）

**⚠️ 关键规范 - 测试隔离**：
- ❌ **禁止**在普通测试函数中调用 `await db.commit()`（会导致测试隔离失败）
- ✅ **使用** `await db.flush()` 让数据对当前会话可见
- ✅ **依赖** `db_session` fixture的自动 `rollback()` 清理测试数据
- ✅ **例外场景**：测试唯一性约束冲突时，第一条数据**必须** commit 以触发约束检查

**正确示例**：
```python
# ✅ 正确：不commit，依赖fixture的rollback
@pytest.mark.asyncio
async def test_create_expert_success(db_session):
    async for db in db_session:
        expert = await crud_experts.create_expert(db, expert_data)
        # 不需要commit！CRUD函数内部的flush()足够了
        assert expert.id is not None
        break  # 退出循环，触发fixture的自动rollback

# ✅ 正确：测试唯一性约束必须commit
@pytest.mark.asyncio
async def test_create_expert_duplicate_user_id(db_session):
    async for db in db_session:
        expert1 = await crud_experts.create_expert(db, expert_data1)
        await db.commit()  # ✅ 必须commit，否则唯一性约束不生效
        
        with pytest.raises(DatabaseIntegrityException):
            expert2 = await crud_experts.create_expert(db, expert_data2)
            await db.commit()  # ✅ 这里commit会触发IntegrityError
        break

# ❌ 错误：普通测试中commit会破坏隔离
@pytest.mark.asyncio
async def test_get_expert_wrong(db_session):
    async for db in db_session:
        expert = await crud_experts.create_expert(db, expert_data)
        await db.commit()  # ❌ 数据被真正提交，无法回滚！
        break
```

**补充说明（与测试母版对齐的简化规则）**：
- 本模块 CRUD 测试遵循通用测试母版中的简化 commit 规则：
  - 默认情况下，测试函数中**不要**调用 `await db.commit()`，依赖 `db_session` fixture 的自动 `rollback()` 做测试隔离。
  - 仅在以下场景中允许使用 `commit()`：
    1. 测试唯一性约束（如 `experts.user_id`、`UNIQUE(user_id, expert_id)` 等），需要 `commit` 第一条记录以触发数据库唯一性检查。
    2. 将来如果新增涉及级联删除 / 外键约束的测试（当前专家模块中较少），可以在对应父/子记录创建后使用 `commit` 验证级联行为。
    3. 在通用辅助函数内部，如确有需要持久化共用测试数据时，可以在辅助函数内 `commit`，但测试函数本身不再重复 `commit`。
