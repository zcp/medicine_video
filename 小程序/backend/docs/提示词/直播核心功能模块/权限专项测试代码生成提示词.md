### 4.3 用户身份解析规范 (MANDATORY - ⚠️ 关键)

**⚠️ 重要**：API层和Service层的用户身份处理规范：

1. **API层用户提取规范**：
   - `current_user` 永远是一个 JWT payload `dict`，而不是 ORM `User` 模型
   - **⚠️ 关键**：JWT Payload 使用 `user_id` 字段（而非 JWT 标准的 `sub` 字段）
   - 必须使用以下模式解析：
   ```python
   from typing import Dict
   from fastapi import Depends
   from app.core.deps import get_current_user
   
   current_user: Dict = Depends(get_current_user)
   # ⚠️ 关键：优先使用 user_id，兼容 sub（向后兼容）
   user_id = uuid.UUID(current_user.get("user_id") or current_user.get("sub"))
   role_str = current_user.get("role", "REGULAR").upper()
   ```

2. **Service层用户参数规范**：
   - Service层方法**不得**接受实体类 `User`
   - **必须**统一为 `user_id: UUID` 和 `role: str`（字符串格式：`"REGULAR"`、`"ADMIN"`、`"SUPERADMIN"`）
   ```python
   async def some_action(
       self,
       user_id: UUID,
       role: str,  # 字符串格式，不是Enum
       ...
   ):
       ...
   ```

3. **测试中的使用**：
   - 在测试中，`role` 参数可以使用两种方式：
     - **方式1（推荐）**：使用现有的 fixture：`regular_user_role: str`、`admin_user_role: str`
     - **方式2**：直接使用字符串：`role = "REGULAR"` 或 `role = "ADMIN"`
   - 不要使用Enum类型作为 `role` 参数
   - **⚠️ 关键**：JWT Token 生成时使用 `user_id` 字段（不是 `sub`）：
   ```python
   # conftest.py 中的 Token 生成示例
   token_data = {
       "user_id": str(regular_user_id),  # ← 使用 user_id，不是 sub
       "role": regular_user_role,
       "type": "access"
   }
   return create_access_token(token_data)
   ```

## 10. 常见错误预防措施（基于16类错误总结）

**⚠️ 重要**：以下错误预防措施必须严格遵守，避免重复16类常见错误。

### 10.1 类型1：缺少 role 参数

**预防措施**：
- ✅ 所有Service方法调用都必须传递 `role` 参数
- ✅ 使用字符串格式：`"REGULAR"`、`"ADMIN"`
- ✅ 可以使用两种方式：
  - **方式1（推荐）**：使用现有的 fixture：`regular_user_role: str`、`admin_user_role: str`
  - **方式2**：直接使用字符串：`role = "REGULAR"` 或 `role = "ADMIN"`
- ✅ 不要使用未定义的 fixture 或变量名，应使用上述两种方式之一

### 10.2 类型2：变量名未定义

**预防措施**：
- ✅ 所有使用的 fixture 必须在测试函数签名中声明
- ✅ 变量使用前必须定义
- ✅ 使用现有的 fixture 名称，不要自创

### 10.3 类型3：异常类型不匹配

**预防措施**：
- ✅ 使用正确的异常类型：
  - `TopicNotFoundException` (404, code 2001)
  - `RoomNotFoundException` (404, code 2001)
  - `PermissionDeniedException` (403, code 3002)
  - `SessionActionForbiddenException` (403, code 2004/2005)
- ✅ 从 `app.exceptions` 正确导入异常类型

### 10.4 类型4：Async Generator Fixture 访问属性问题

**预防措施**：
- ✅ 使用 `topic_client` 时，在进入循环前解析所有依赖 `db_session` 的 fixture
- ✅ 使用直接迭代模式：`async for pt in published_topic: published_topic_id = pt.id; break`
- ✅ 避免在循环内部重复消费 async generator

### 10.5 类型6：Mock对象状态不符合权限要求

**预防措施**：
- ✅ 为匿名用户测试创建正确状态的 mock 对象
  - Topic: `status="published"`（不是 `"draft"`）
  - Room: `is_private=False`（不是 `True`）
- ✅ 确保 mock 对象的状态符合测试场景

**示例**：
```python
# ✅ 正确（匿名用户测试）

```

### 10.6 类型7：FastAPI HTTPException 响应格式不一致

**预防措施**：
- ✅ 兼容两种错误响应格式
- ✅ 在访问 `code` 字段前检查字段是否存在

**示例**：
```python
response_json = response.json()
if "code" in response_json:
```
