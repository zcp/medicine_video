### 3.2. 业务逻辑与执行流程 (Business Logic & Flow)

#### 检测点 2.1 (步骤一致性)
**状态**: ✅ **[一致]**

**检测结果**:
Doc-API和Doc-CRUD中的执行流程与Doc-Design完全一致。

**关键业务流程验证**:

1. **创建品牌**:
   - ✅ Doc-Design (4.1.1节): 权限检查 → 唯一性验证 → 创建记录 → 返回结果
   - ✅ Doc-API: `_check_admin_permission(role)` → `await crud.create_brand(...)` → 构造响应
   - ✅ Doc-CRUD: `try` → 创建Brand实例 → `db.add()` → `await db.commit()` → `except IntegrityError` → 转换为`DatabaseIntegrityException`

2. **删除品牌（硬删除）**:
   - ✅ Doc-Design (4.1.7节): 权限检查（SUPERADMIN） → 404检查 → 引用关系检查（brand_topics + brand_rooms） → 删除记录
   - ✅ Doc-API: 提取`hard_delete`参数 → 调用Service → 捕获异常
   - ✅ Doc-Service: 权限检查（SUPERADMIN） → `check_brand_references()` → 如果有引用抛出`ConflictException` → `await crud.delete_brand(hard_delete=True)`
   - ✅ Doc-CRUD: `await db.delete(brand)` → `await db.commit()`

3. **批量关联专题**:
   - ✅ Doc-Design (4.2.1节): 权限检查 → 品牌404检查 → 批量验证专题ID → 批量插入（幂等性）
   - ✅ Doc-API: `_check_admin_permission()` → 验证品牌 → 批量验证专题ID → `batch_add_brand_topics()`
   - ✅ Doc-CRUD: 使用`INSERT ... ON CONFLICT DO NOTHING`保证幂等性

4. **绑定直播间品牌（全量替换策略）**:
   - ✅ Doc-Design (4.3.1节): 权限检查 → 直播间404检查 → 批量验证品牌ID（is_active=True） → 全量替换（先删后插）
   - ✅ Doc-API: `_check_admin_permission()` → 验证直播间 → 批量验证品牌ID → `bind_room_brands()`
   - ✅ Doc-CRUD: `async with db.begin()` → `delete(BrandRoom)` → `db.add_all(new_relations)` → 自动commit

**结论**: 所有关键业务流程的步骤顺序、逻辑判断、异常处理完全一致。
