### 📝 新增的日志脱敏规范内容

#### 规范定义

根据设计文档 Section 1.4.1（日志脱敏规范），所有API接口在记录日志时必须对以下敏感信息进行脱敏：

**脱敏对象**:
1. JWT Token完整字符串
2. Authorization请求头
3. 数据库连接URL中的密码
4. 专家的联系方式（contact_info字段）

#### 实现方式

**1. 使用统一的日志脱敏工具函数 `sanitize_log_message()`**
```python
from app.utils.logging import sanitize_log_message
```

**2. JWT Token脱敏规则**:
- JWT Token仅记录前8个字符：`token[:8] + "..."`
- 示例：`"User {user_id} created expert with token {token[:8]}..."`

**3. contact_info字段脱敏规则**:
- contact_info字段仅记录字段存在性，不记录具体内容
- 示例：`"Expert contact info: {contact_info is not None if contact_info else 'not provided'}"`

#### 正确示例

**❌ 错误**：直接记录完整Token
```python
logger.info(f"User {user_id} created expert with token {token}")
logger.info(f"Expert contact info: {expert.contact_info}")
```

**✅ 正确**：脱敏记录Token
```python
logger.info(f"User {user_id} created expert with token {token[:8]}...")
logger.info(f"Expert contact info: {contact_info is not None}")
```

#### 日志记录位置

**CRUD层**：
- `create_expert`: 记录专家创建操作（脱敏user_id、token）
- `update_expert`: 记录专家更新操作（脱敏user_id、token）
- `delete_expert`: 记录专家删除操作（脱敏user_id、token）
- `create_expert_follow`: 记录关注操作（脱敏user_id、token）
- `delete_expert_follow`: 记录取消关注操作（脱敏user_id、token）

**API层**：
- 所有端点的INFO日志：记录操作用户ID（脱敏token）
- 所有端点的ERROR日志：记录错误信息（脱敏token）
- 所有端点的异常处理：记录异常信息（脱敏token）
