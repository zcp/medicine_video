## 3. 检查清单 (Checklist)

### 3.1 表级一致性

1. **表名一致性**  
   - 检查 `__tablename__` 是否分别为：`user_favorites`、`watch_history`、`user_subscriptions`，与 DDL 完全一致。  

2. **主键定义**  
   - 确认每张表都有 `id UUID PRIMARY KEY`（或设计文档中定义的主键字段），类型和约束与 DDL 对齐。  

### 3.2 字段级一致性

对每张表逐字段比较：

1. **字段名称**  
   - `user_id`、`room_id`、`session_id`、`is_active`、`is_latest`、`target_type`、`created_at` 等字段是否全部存在且命名一致；  
   - 是否存在 DDL 中没有定义、但在模型中多出的字段（如无设计说明的额外状态字段）。  

2. **字段类型**  
   - `UUID` → `PG_UUID(as_uuid=True)`；  
   - `BOOLEAN` → `Boolean`；  
   - `INT` → `Integer`；  
   - `TIMESTAMPTZ` → `TIMESTAMP(timezone=True) + server_default=func.now()`；  
   - 枚举字段 `subscription_target_type` → `SAEnum(SubscriptionTargetType, ...)`。  

3. **非空与默认值**  
   - 检查 DDL 中 `NOT NULL` 与 `DEFAULT` 是否在 ORM 中以 `nullable=False` 与 `default`/`server_default` 体现；  
   - 核对 `is_active`、`is_latest`、时间戳字段的默认值是否与 DDL（或设计文档文字描述）一致。  

### 3.3 约束与索引

1. **唯一约束**  
   - `user_favorites`：`UNIQUE (user_id, room_id)` ↔ `UniqueConstraint("user_id", "room_id", name="uq_user_favorites_user_room")`；  
   - `user_subscriptions`：`UNIQUE (user_id, target_type, room_id, session_id)` ↔ `UniqueConstraint(..., name="uq_user_subscriptions_user_target")`。  

2. **索引**  
   - 检查用户行为较频繁的查询路径是否按 DDL 设计定义了索引：  
     - 收藏：如 `idx_user_favorites_user_id`、`idx_user_favorites_room_id`；  
     - 观看历史：`idx_watch_history_user_session`、`idx_watch_history_is_latest`；  
     - 订阅：`idx_user_subscriptions_user_id`。  

3. **外键与 ondelete 行为**  
   - 检查 `room_id` / `session_id` 字段的外键是否指向了正确的表与字段（`live_rooms.id`、`live_sessions.id`），并与设计文档中 `ON DELETE CASCADE` 等行为一致。
