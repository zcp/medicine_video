

### **医学直播SaaS平台：移动端（App/小程序）设计文档 (V1.2 - 品牌Tab优化版)**

#### **1.0 设计目标与概述**

本设计旨在将PC端 `V2.0` 设计文档的专业功能（如：专家、品牌、科室分类、专业问答）与Bilibili的成熟移动端UI/UX范式（如：底部Tab栏、Feed流、沉浸式播放器）相结合，打造一个专业、高效且符合移动用户习惯的医学直播应用。

**参考原型：**
* **Bilibili首页 (`508d557888ce7ea783180f2b8da23c8a.jpg`)**: 提供了顶部搜索、分类Tabs和底部主导航的布局参考。
* **Bilibili视频页 (`b186df293f36b950092908d7ff8a0310.jpg`, `97ae2943b289cabd049181baac9d6dcf.jpg`)**: 提供了“播放器 + 详情 + 互动区”的单页滚动布局参考。

#### **2.0 全局设计 (Global UI)**

#### **[全局模块 G1] 底部主导航栏 (Bottom Tab Bar)**

* **设计**: 这是App/小程序的**一级导航**，取代PC端的顶部导航栏。
* **参考**: Bilibili 首页底部的 `[首页] [关注] [+] [会员购] [我的]`。
* **我们的Tab (V1.2 更新 - 优化版):**

    * `[品牌]` (位置②): **(V1.2新增)** 合作品牌专区，提升品牌曝光度和商业价值。
    * `[我的直播]` (位置③ - **C位**): **(SaaS核心)** 主播后台快捷入口，强调平台核心定位。
    * `[专家]` (位置④): 专家列表与聚合页，承载PC端 `[C.5]教授专题` 的功能。
    * `[我的]` (位置⑤): 个人中心，用户设置与个人信息管理。

* **设计理念**:
    * **左侧（①②）**：内容消费层（浏览直播、探索品牌）
    * **中间（③）**：内容生产层（主播核心工作台，C位强调）
    * **右侧（④⑤）**：工具/个人层（专家查找、个人中心）

##### **H2.1 视觉设计**

* **布局特性**:
    * 此Tabs**吸顶 (Sticky)**，当用户向下滚动时，它会"粘"在顶部栏下方，始终可见。
    * 水平滚动，支持左右滑动查看更多科室。
    * 右侧渐变遮罩提示"可滑动查看更多"。

* **未个性化状态（新用户/未登录）**:
    ```
    [推荐] [肝胆胰外科] [胃肠外科] [心血管] [骨科] ... [全部 ≡]
    ```
    显示平台推荐的热门科室（由后端配置或按热度排序）

* **个性化后状态（已固定科室）**:
    ```
    [推荐] [⭐眼科] [⭐胃肠外科] [肝胆胰] [心血管] [骨科] ... [全部 ≡]
              ↑         ↑
        用户固定的科室（带星标⭐，优先显示）
    ```
    
* **Tab样式规范**:
    * **推荐Tab**: 始终第一位，选中时底部蓝色下划线，字体加粗
    * **星标科室Tab**: 科室名前显示 `⭐` 图标，选中时底部蓝色下划线
    * **普通科室Tab**: 纯文字，选中时底部蓝色下划线
    * **全部Tab**: 图标 `≡` + 文字 "全部"，带左侧竖线分隔符

##### **H2.2 个性化功能详解**

###### **功能概述**
* **目标用户痛点**: 医学专业细分领域多，用户只关注特定几个科室，但每次都要滑动查找
* **解决方案**: 用户可将最常看的科室（如眼科、胃肠外科）固定到筛选器前排，一键直达
* **数量限制**: 最多固定**5个科室**（避免筛选器过长）
* **排序**: 用户可自定义固定科室的显示顺序

###### **操作入口：全部科室页面**

当用户点击 `[全部 ≡]` 后，进入**完整科室列表页面**（全屏弹窗或新页面）：

```
┌─────────────────────────────────────────┐
│  全部科室                    [完成]      │ ← 顶部标题栏
├─────────────────────────────────────────┤
│  🔍 搜索科室名称                         │ ← 搜索框
├─────────────────────────────────────────┤
│  💡 我的关注科室 (最多5个)    [编辑]   │ ← 已固定区域
│  ┌───────────────────────────────────┐  │
│  │ ⭐ 眼科                     [×]   │  │ 点击[编辑]后可拖拽排序
│  │ ⭐ 胃肠外科                 [×]   │  │ 点击[×]取消固定
│  └───────────────────────────────────┘  │
│                                          │
│  提示：点击科室右侧的 ☆ 可以固定到首页  │ ← 首次使用提示（可关闭）
├─────────────────────────────────────────┤
│  全部科室 (按拼音排序)         [A-Z索引]│ ← 未固定科室列表
│                                          │
│  肝胆胰外科                      [☆]    │ 点击☆可固定（最多5个）
│  骨科                            [☆]    │ 达到上限后☆按钮置灰
│  呼吸内科                        [☆]    │
│  心血管内科                      [☆]    │
│  神经外科                        [☆]    │
│  ...                                     │
└─────────────────────────────────────────┘
```

###### **交互流程**

1. **固定科室**:
   - 点击科室右侧的 `☆` 按钮
   - 该科室立即移动到"我的关注科室"区域，图标变为 `⭐`
   - Toast提示："已固定到首页"

2. **取消固定**:
   - 方式A：点击已固定科室的 `×` 按钮
   - 方式B：点击已固定科室的 `⭐` 图标（切换状态）
   - 该科室返回"全部科室"列表，图标变为 `☆`

3. **调整顺序**:
   - 点击"我的关注科室"右侧的 `[编辑]` 按钮
   - 进入排序模式：每个科室左侧出现拖拽手柄 `≡`
   - 长按拖拽调整顺序
   - 点击 `[完成]` 保存排序

4. **数量限制**:
   - 当已固定5个科室时，其他科室的 `☆` 按钮置灰
   - 点击置灰的 `☆` 时，Toast提示："最多固定5个科室，请先取消其他科室"

5. **生效时机**:
   - 点击顶部 `[完成]` 按钮返回首页
   - 筛选器立即刷新，显示用户固定的科室

##### **H2.3 内容逻辑与排序规则**

###### **筛选器Tab显示优先级**
```
[推荐] + [用户固定科室(⭐,按用户排序)] + [平台推荐科室(按热度)] + [全部 ≡]
   ①              ②                              ③                    ④
```

1. **推荐Tab (①)**: 始终固定在第一位
2. **用户固定科室 (②)**: 带⭐标识，按用户设置的顺序显示
3. **平台推荐科室 (③)**: 填充剩余位置（排除已固定的），按观看热度/活跃度排序
4. **全部入口 (④)**: 始终固定在最右侧

###### **筛选器可见数量**
- 默认显示约**8-10个Tab**（具体取决于屏幕宽度和科室名称长度）
- 超出部分需要横向滑动查看

**用户A（固定了眼科、胃肠外科）**：

**用户B（固定了神经外科、骨科、心血管、呼吸内科、肿瘤科）**：
```
[推荐] [⭐神经外科] [⭐骨科] [⭐心血管] [⭐呼吸] [⭐肿瘤] [肝胆胰] ... [全部 ≡]
```

**用户C（未登录/未个性化，显示默认）**：
```
[推荐] [肝胆胰外科] [胃肠外科] [心血管] [骨科] [神经外科] ... [全部 ≡]
```

###### **Tab点击行为**
- 点击 `[推荐]`: Feed流显示算法/运营推荐的混合内容
- 点击 `[具体科室]`: Feed流只显示该科室的直播/回放（包括星标科室）

##### **H2.4 技术实现要点**

###### **数据存储**

**LocalStorage结构** (未登录用户或本地缓存):
```typescript
interface UserCategoryPreferences {
  pinnedDepartments: string[];  // 固定的科室ID数组，顺序即为显示顺序
  lastUpdated: number;           // 最后更新时间戳
}

// 示例
{
  pinnedDepartments: ['dept_005', 'dept_012'], // 眼科、胃肠外科
  lastUpdated: 1698765432000
}
```

**服务器存储** (已登录用户，支持跨设备同步):
```typescript
// POST /api/user/preferences
{
  type: 'pinned_departments',
  data: ['dept_005', 'dept_012']
}

// GET /api/user/preferences
// 返回用户的所有偏好设置
```

###### **前端渲染逻辑**

```typescript
function getCategoryTabs() {
  const pinnedDepts = getUserPinnedDepartments(); // 从LocalStorage或API获取
  const allDepts = getAllDepartments();            // 所有科室列表
  const defaultHotDepts = getDefaultHotDepartments(); // 平台热门科室
  
  const tabs = [{ id: 'recommend', name: '推荐', type: 'default' }]; // 第一个始终是"推荐"
  
  // 添加用户固定的科室（带星标）
  pinnedDepts.forEach(deptId => {
    const dept = allDepts.find(d => d.id === deptId);
    if (dept) {
      tabs.push({ 
        id: dept.id, 
        name: `⭐${dept.name}`, 
        type: 'pinned',
        isPinned: true 
      });
    }
  });
  
  // 填充剩余位置（排除已固定的）
  const remainingDepts = defaultHotDepts.filter(d => !pinnedDepts.includes(d.id));
  const visibleCount = Math.min(8, tabs.length + remainingDepts.length); // 最多显示8个
  tabs.push(...remainingDepts.slice(0, visibleCount - tabs.length - 1)); // -1 留给"全部"
  
  // 最后添加"全部"入口
  tabs.push({ id: 'all', name: '全部 ≡', type: 'all' });
  
  return tabs;
}
```

###### **状态管理**

- 固定/取消固定操作实时更新LocalStorage
- 如果用户已登录，debounce后同步到服务器（避免频繁请求）
- 首页筛选器监听LocalStorage变化，自动刷新

###### **性能优化**

- 科室列表支持虚拟滚动（如果科室数量 > 50）
- 搜索功能使用防抖（debounce 300ms）
- 拖拽排序使用原生drag API或成熟库（如react-beautiful-dnd）

##### **H2.7 设计亮点总结**

| 功能点 | 用户价值 | 技术实现 |
|--------|----------|----------|
| **星标固定** | 快速访问常看科室，节省查找时间 | LocalStorage + 服务器同步 |
| **优先显示** | 个性化首页，提升内容发现效率 | 动态排序算法 |
| **数量限制** | 避免筛选器过长，保持简洁 | 最多5个 + 达到上限后置灰提示 |
| **自定义排序** | 完全掌控显示顺序，符合个人习惯 | 拖拽排序 + 持久化存储 |
| **跨设备同步** | 登录后多设备共享偏好设置 | 服务器存储 + API同步 |
| **首次引导** | 降低学习成本，提升功能发现率 | 轻量级弹窗 + 可关闭提示条 |

#### **[首页模块 H3] 核心内容Feed (Content Feed) - 双列瀑布流**

* **设计理念**: 这是对PC端布局的**最大改动**。我们放弃PC端的`网格(Grid)`和`分页(Pagination)`，转而使用移动端主流的**双列瀑布流 (Masonry Layout)**，并支持**无限滚动**。
* **布局选型**: 参考Bilibili移动端、小红书、YouTube移动端的成熟方案，采用**双列**而非单列，理由：
    * ✅ **屏幕利用率更高**：双列可充分利用横向空间（约90% vs 单列50%）
    * ✅ **视觉更丰富**：一屏展示更多内容，降低滑动疲劳
    * ✅ **符合用户习惯**：主流视频/内容平台均采用双列布局
* **关键融合 (V1.2 更新)**: 
    * **品牌** 和 **专家** 均已移至底部独立Tab，不再插入Feed流
    * Feed流只保留**直播/回放卡片**和**焦点图**，内容更纯粹、浏览体验更连贯

##### **H3.1 焦点图 (Carousel Banner)**

* **布局位置**：在 `[H2] 分类筛选器` 正下方，Feed流的最顶部（第一个元素）。
* **滚动行为**：**跟随页面正常滚动**（向下滚动时焦点图会被滚上去，不占据屏幕空间）。
    * ⚠️ 注意：焦点图**不是吸顶 (Sticky)**，吸顶的是 `[H2] 分类筛选器`。
    * 用户返回顶部或刷新页面时，焦点图重新可见。
* **设计规范**：
    * **尺寸**：宽度100%，高度约屏幕宽度的40-50%（保持16:9或2:1比例）
    * **数量**：3-5张轮播图（由运营后台配置）
    * **自动播放**：3秒间隔自动切换
    * **手动滑动**：支持左右滑动切换
    * **指示器**：底部显示小圆点指示当前位置（如：● ○ ○）
* **内容类型**：
    * 大型学术会议宣传
    * 重点直播预告
    * 平台活动推广
    * 品牌合作广告位
* **交互**：点击焦点图跳转到对应的直播间或活动页面
* **运营位价值**：这是平台**最高价值的流量入口**，用户进入首页时第一眼可见

```
│  ┌─────────┐   ┌─────────┐             │
│  │封面图   │   │封面图   │             │
│  │标题...  │   │标题...  │             │
│  │主播/数据│   │主播/数据│             │

│                                          │

```

###### **卡片设计规范**

* **布局方式**：双列，卡片等宽，卡片间距8-12px
* **列宽计算**：`(屏幕宽度 - 左右边距 - 中间间距) / 2`
* **卡片圆角**：8px（统一圆角风格）
* **卡片阴影**：轻微阴影（`box-shadow: 0 2px 8px rgba(0,0,0,0.08)`）提升层次感

###### **卡片内容结构**

```
┌─────────────────────┐
│                     │
│   [封面图 16:9]     │ ← LIVE/预告/回放标签（左上角）
│                     │   观看人数标签（右下角，半透明黑底）
├─────────────────────┤
│ [直播标题]          │ ← 最多2行，超出省略（...）
│ 肝胆胰外科微创...   │
├─────────────────────┤
│ 👨‍⚕️ 张三 | 协和医院  │ ← 小字、灰色
│ 1.2万观看 · 10/28   │ ← 小字、灰色
└─────────────────────┘
```

* **封面图 (Cover Image)**:
    * 比例：16:9（标准视频比例）
    * 状态标签：左上角显示 `LIVE`(红色) / `预告`(蓝色) / `回放`(灰色)
    * 观看数：右下角半透明黑底显示"1.2万人观看"（仅直播中显示）
    * 图片懒加载：滚动到可视区域才加载，提升性能

* **直播标题 (Title)**:
    * 字体：加粗，14-15px
    * 颜色：深色（`#333` 或 `#1a1a1a`）
    * 行数限制：最多2行，超出显示省略号

##### **M1.3 智能流量提醒 (V1.2核心功能) ⭐**

* **功能目标**: 在用户使用流量网络观看直播时，自动检测并提醒，避免意外消耗大量流量，提升用户体验。

###### **触发时机**

1. **进入直播间时**: 页面加载完成后立即检测网络类型
2. **点击播放按钮时**: 用户主动点击播放时再次检测（如果网络切换）

###### **检测逻辑**

```typescript
// 使用 uni.getNetworkType() API
uni.getNetworkType({
  success: (res) => {
    const networkType = res.networkType;
    // networkType: wifi / 2g / 3g / 4g / 5g / ethernet / unknown / none
    
    const isCellular = ['2g', '3g', '4g', '5g'].includes(networkType);
    
    if (isCellular) {
      showCellularWarning(networkType);
    }
  }
});
```

###### **交互流程**

```
用户进入直播间
     ↓
检测网络类型
     ↓
  流量网络？
     ↓ 是
检查"不再提示"设置

```

##### **M1.5 播放器性能优化**

* **预加载策略**:
  - 首屏优先加载480p，用户选择高清晰度时切换
  - 预加载前30秒内容，后续按需加载

* **自适应码率 (ABR)**:
  - 根据网络速度自动调整清晰度
  - 弱网环境自动降至480p/360p
  - 网络恢复后自动切换回高清

* **内存管理**:
  - 页面切换到后台时暂停播放（节省流量和电量）
  - 返回前台时恢复播放
  - 页面卸载时释放播放器资源

* **埋点统计**:
  - 播放时长、卡顿次数、清晰度切换次数
  - 网络类型、首屏加载时间
  - 用户退出时机（播放多久后退出）

#### **[直播间模块 M2] 直播信息区 (Info Area) - 渐进式展开设计**

* **设计理念**: 紧贴播放器下方，承载PC端 `[G1]` 和 Bilibili 的信息元素。采用**Progressive Disclosure Design（渐进式展开设计）**，解决移动端屏幕空间有限的痛点，在保持界面简洁的同时确保信息完整性。

* **核心原则**:
    * ✅ **默认简洁**: 初始状态显示最关键的信息，避免信息过载
    * ✅ **按需展开**: 用户点击即可查看完整内容
    * ✅ **体验流畅**: 展开/收起动画流畅自然（300ms过渡）
    * ✅ **智能判断**: 系统自动检测内容长度，仅对"超长内容"启用折叠

    * 添加淡入动画（fade-in）
    * **示例**:
      ```

      2025年秋季学术研讨会第三场：聚焦腹腔镜下胰十二指
      肠切除术（LPD）的技术要点与并发症管理 [收起 ▲]
      ```

* **自动判断逻辑**:
    * 如果标题 ≤ 2行：不显示 `[展开]` 按钮，直接显示完整标题
    * 如果标题 > 2行：启用智能折叠

##### **M2.5 内容标签 (智能折叠)**

* **设计痛点**: 医学直播的标签往往很多（如：`#微创手术` `#胰腺癌` `#病例讨论` `#术式创新` `#腹腔镜` `#MDT` ...），全部显示会占用大量空间。

* **初始状态 (Collapsed)**:
    * 最多显示 **3个标签**（如果标签总数 ≤ 3，则全部显示）
    * 如果标签 > 3个，显示前3个 + `[+N]` 按钮（N为剩余标签数）
    * **示例**:
      ```
      [#微创手术] [#胰腺癌] [#病例讨论] [+4]
      ```

* **展开状态 (Expanded)**:
    * 点击 `[+N]` 按钮，显示**所有标签**（多行显示，自动换行）
    * 按钮变为 `[收起 ▲]`
    * **示例**:
      ```
      [#微创手术] [#胰腺癌] [#病例讨论] [#术式创新]
      [#腹腔镜] [#MDT] [#围术期管理] [收起 ▲]
      ```

* **标签交互**:
    * 每个标签都是可点击的
    * 点击标签后，跳转到该标签的聚合页（显示所有包含此标签的直播）

##### **M2.7 技术实现要点**

* **前端逻辑**:
    * 使用 `line-clamp` CSS属性或JavaScript计算文本行数
    * 折叠/展开状态用 `useState` 管理（React/Vue）
    * 展开动画使用 `max-height` + `transition` 实现流畅过渡

* **性能优化**:
    * 标签数量阈值可配置（默认3个，可通过后台设置调整）
    * 展开状态在用户切换Tab后自动重置为"折叠"（避免页面过长）

* **无障碍支持**:
    * 展开按钮添加 `aria-expanded` 属性
    * 标题添加 `aria-label` 完整内容（即使折叠状态下也能被屏幕阅读器读取）

#### **[直播间模块 M3] 核心功能Tabs (Content Tabs)**

* **设计**: 这是**融合设计的核心**。它承载了PC端 `[G3]`（左侧Tabs）和 `[H1]`（右侧聊天）的全部功能。
* **参考**: Bilibili 的 `[简介] [评论]` Tabs。
* **我们的Tabs (专业版):**
    * `Tab 1: 详情`:
        * **内容**: 承载PC端 `[G3 - Tab 1: 直播介绍]`。
        * 显示详细的图文 `议程`、`病例背景`、`相关资料下载` 列表。
    * `Tab 2: 聊天/公告`:
        * **内容**: 承载PC端 `[H1: 实时互动]`。
        * 顶部是`公告`区 (仅管理员发布)，下方是`聊天`滚屏区和输入框。
    * `Tab 3: 专业问答`:
        * **内容**: 承载PC端 `[G3 - Tab 2: 专业问答]`。**这是与Bilibili最大的区别，必须保留。**
        * 提供 `[我要提问]` 按钮，并用列表显示 `[已回答]` 和 `[待回答]` 的问题。
    * `Tab 4: 相关推荐`:
        * **内容**: 承载PC端 `[H3]` 和 Bilibili `[合集]` 的功能。
        * 以卡片列表形式显示 `[本场主播的其他直播]` 或 `[相关课程推荐]`。

#### **8.0 页面六：全屏播放器 (Full-Screen Player)**

* **触发**: 在直播间页面点击播放器的"全屏"按钮。
* **原型参考**: Bilibili 全屏播放 (`b186df293f36b950092908d7ff8a0310.jpg` 点击全屏)
* **布局**: 强制横屏 (Landscape)，沉浸式全屏体验。

#### **[全屏模块 F1] 播放器控件 (Standard Controls)**

* **设计**: 播放器UI层，点击屏幕时浮现，3秒后自动隐藏。
* **内容**: `[播放/暂停]` `[时间轴(Timeline)]` `[音量]` `[退出全屏]`。

#### **[全屏模块 F2] 移动端增强控件 (Mobile Overlays)**

* **设计**: 效仿Bilibili，在控件层上增加移动端特有功能。
* **内容**:
    * `[清晰度]` (切换: 1080p, 720p...)
    * `[倍速播放]` (回放时可用: 0.75x, 1.0x, 1.5x, 2.0x)
    * `[弹幕(Danmaku)]` (可选功能，如果您的平台支持)

#### **[全屏模块 F3] SaaS功能浮窗 (SaaS Overlays)**

* **设计**: 这是为了在全屏时不中断观看，又能进行SaaS互动。
* **内容**: 在播放器角落（如右侧）提供两个**常驻小图标**：
    * `[聊天图标]`: 点击后，从右侧滑出**半透明**的聊天窗口（覆盖在视频上），用户可以边看边聊。
    * `[问答图标]`: 点击后，滑出**半透明**的Q&A窗口，用户可以查看和提交问题。
