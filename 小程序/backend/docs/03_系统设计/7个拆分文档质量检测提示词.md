## 🔍 检测维度一：与原文档（v2文档）的一致性检测

### 1.1 内容完整性检测

**检测方法**：逐一对比每个拆分文档与原文档中对应模块的内容

**检测清单**：

#### ✅ 1.1.1 数据表定义一致性
- [ ] **DDL完整性**：拆分文档中的表定义是否与原文档Section 2中对应表的DDL完全一致
- [ ] **字段定义**：所有字段名称、类型、约束、默认值是否一致
- [ ] **索引定义**：所有索引（包括复合索引、部分索引）是否一致
- [ ] **外键约束**：外键约束名称、引用表、ON DELETE行为是否一致
- [ ] **触发器定义**：触发器名称、触发时机、执行函数是否一致
- [ ] **注释完整性**：表注释和字段注释是否一致

**检测示例**：
```
检测项：user_favorites表定义
- 原文档位置：Section 2.7
- 拆分文档位置：用户行为模块文档 Section 2.1
- 对比字段：id, user_id, room_id, is_active, created_at
- 对比索引：idx_user_favorites_user_id, idx_user_favorites_room_id
- 对比约束：uq_user_favorites_user_room, fk_user_favorites_room_id
```

#### ✅ 1.1.2 Pydantic Schemas一致性
- [ ] **Schema名称**：所有Schema类名是否一致
- [ ] **字段定义**：字段名称、类型、可选性、默认值是否一致
- [ ] **验证器**：field_validator、model_validator是否一致
- [ ] **Pydantic V2语法**：是否都使用`model_config = ConfigDict(from_attributes=True)`
- [ ] **响应Schema**：响应Schema结构是否一致

**检测示例**：
```
检测项：FavoriteCreate Schema
- 原文档位置：Section 3.8
- 拆分文档位置：用户行为模块文档 Section 3.1
- 对比字段：room_id (uuid.UUID)
- 对比验证：无验证器
```

#### ✅ 1.1.3 API接口定义一致性
- [ ] **Endpoint路径**：所有API的路径是否完全一致
- [ ] **HTTP方法**：GET/POST/PATCH/DELETE是否一致
- [ ] **认证要求**：Strict Auth / Optional Auth / Admin Auth是否一致
- [ ] **请求参数**：Query参数、Path参数、请求体字段是否一致
- [ ] **响应结构**：成功响应、失败响应的结构是否一致
- [ ] **错误码**：错误码定义是否一致
- [ ] **执行流程**：8-10步执行流程是否一致（步骤数量、逻辑顺序）

**检测示例**：
```
检测项：POST /api/v1/users/me/favorites
- 原文档位置：Section 4.8.1
- 拆分文档位置：用户行为模块文档 Section 4.1.1
- 对比认证：需要JWT Token
- 对比请求体：{"room_id": "uuid"}
- 对比响应：200 OK / 2002 Conflict
- 对比执行流程：8步 vs 8步（逐项对比）
```

#### ✅ 1.1.4 设计规范一致性
- [ ] **UUID主键生成**：是否都说明"在应用层通过uuid.uuid4()生成"
- [ ] **时间戳字段**：是否都使用TIMESTAMPTZ
- [ ] **JWT字段**：是否都使用user_id（而非sub）
- [ ] **HTTP方法**：是否都使用PATCH（而非PUT）
- [ ] **软删除策略**：软删除/硬删除策略是否一致
- [ ] **响应格式**：统一响应结构是否一致
- [ ] **分页格式**：分页响应格式是否一致

### 1.2 内容冲突检测

**检测方法**：查找拆分文档中是否存在与原文档冲突的内容

**检测清单**：

- [ ] **表定义冲突**：拆分文档是否错误地修改了原文档中已定义的表结构

- [ ] **错误码冲突**：错误码定义是否与原文档冲突
- [ ] **设计原则冲突**：是否违反了原文档的设计原则（如：增量设计、最小侵入等）
