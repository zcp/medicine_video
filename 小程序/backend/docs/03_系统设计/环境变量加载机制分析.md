## 1. 当前环境变量加载机制

### 1.1 代码中的环境变量加载位置

#### ✅ **app/main.py** (第14行)
```python
from dotenv import load_dotenv

# 加载环境变量
load_dotenv()
```

**行为分析**:
- `load_dotenv()` **无参数**时，默认行为：
  1. 查找当前工作目录的 `.env` 文件
  2. 如果找到，加载其中的环境变量
  3. 如果未找到，**不会报错**，继续执行
  4. **不会覆盖**已存在的环境变量（优先级：系统环境变量 > .env文件）

**关键点**: ⚠️ **不会读取 `.env.example`**，只读取 `.env` 文件

---

#### ✅ **run.py** (第6行)
```python
from dotenv import load_dotenv

load_dotenv(dotenv_path=os.path.join(os.path.dirname(__file__), '.env'))
```

**行为分析**:
- 明确指定 `.env` 文件路径
- 本地开发时使用此文件启动应用

---

### 1.2 环境变量优先级

**优先级从高到低**:
1. **系统环境变量** (最高优先级)
2. **Docker Compose `env_file` 注入的环境变量**
3. **`.env` 文件中的变量** (通过 `load_dotenv()` 加载)
4. **代码中的默认值** (如 `os.getenv("KEY", "default")`)


```bash

  ↓

  ↓
main.py 第14行: load_dotenv()  # 再次加载（如果 .env 存在）
  ↓
结果: 使用 .env 文件中的配置 ✅
```

**结论**: ✅ **本地开发使用 `.env` 文件**

### 2.2 Docker 部署场景

**文件结构**:
```
live-streaming-saas/
├── compose-app.yml   # Docker Compose 配置
├── .env.docker       # Docker部署配置（不提交到Git）
└── backend/
    └── live_core_service/
        ├── .env.example  # 配置模板
        └── app/
            └── main.py   # 应用入口
```

**compose-app.yml 配置** (第8行):
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    env_file: .env.docker  # ← 关键：从 .env.docker 加载环境变量
```

**执行流程**:
```bash
# Docker Compose 启动
docker-compose -f compose-app.yml up
  ↓
Docker Compose 读取 compose-app.yml
  ↓
发现 env_file: .env.docker
  ↓
将 .env.docker 中的所有环境变量注入到容器环境变量中
  ↓
容器启动，执行: uvicorn app.main:app --host 0.0.0.0 --port 8000
  ↓
main.py 第14行: load_dotenv()  # 尝试加载 .env（如果存在）
  ↓
结果: 
  - 如果容器内有 .env 文件 → 使用 .env（但会被环境变量覆盖）
  - 如果容器内无 .env 文件 → 直接使用环境变量（来自 .env.docker）✅
```

**结论**: ✅ **Docker部署使用 `.env.docker` 文件（通过 env_file 注入）**

## 3. Docker Compose 环境变量注入机制

### 3.1 env_file 工作原理

**compose-app.yml** (第8行):
```yaml
services:
  live_core_service:
    env_file: .env.docker
```

**Docker Compose 行为**:
1. **读取 `.env.docker` 文件**（相对于 `compose-app.yml` 所在目录）
2. **解析文件内容**（格式：`KEY=VALUE`）
3. **注入到容器环境变量**（相当于在容器内执行 `export KEY=VALUE`）
4. **优先级高于 `.env` 文件**（如果容器内存在 `.env`，环境变量会覆盖它）

---

### 3.2 环境变量注入示例

**假设 `.env.docker` 内容**:
```bash
POSTGRES_SERVER=postgres
POSTGRES_PORT=5432
POSTGRES_DB=live_core_test
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_production_password
JWT_SECRET_KEY=your_production_jwt_secret_key_min_32_chars
CORS_ORIGINS=https://yourdomain.com
ENVIRONMENT=production
DEBUG=false
```

**容器内的环境变量**:
```bash
# 相当于在容器内执行了：
export POSTGRES_SERVER=postgres
export POSTGRES_PORT=5432
export POSTGRES_DB=live_core_test
export POSTGRES_USER=postgres
export POSTGRES_PASSWORD=your_production_password
export JWT_SECRET_KEY=your_production_jwt_secret_key_min_32_chars
export CORS_ORIGINS=https://yourdomain.com
export ENVIRONMENT=production
export DEBUG=false
```

**main.py 中的 `load_dotenv()`**:
- 如果容器内**有** `.env` 文件 → 加载 `.env`，但环境变量会覆盖它
- 如果容器内**没有** `.env` 文件 → 直接使用环境变量（来自 `.env.docker`）

---

### 3.3 环境变量优先级（Docker场景）

**优先级从高到低**:
1. **Docker Compose `environment:` 直接定义** (最高优先级)
   ```yaml
   environment:
     POSTGRES_DB: "live_core_test"  # ← 这个会覆盖 env_file
   ```
2. **Docker Compose `env_file:` 注入的环境变量**
3. **容器内 `.env` 文件** (通过 `load_dotenv()` 加载)
4. **代码中的默认值**

## 4. 部署时环境切换方案

### 4.1 当前方案分析

**优点**:
- ✅ **无需修改代码**：`main.py` 中的 `load_dotenv()` 保持不变
- ✅ **灵活切换**：通过不同的 `env_file` 文件切换环境
- ✅ **环境隔离**：不同环境使用不同的配置文件

**当前配置**:
- 本地开发: `.env` 文件
- Docker部署: `.env.docker` 文件（通过 `env_file` 注入）
- 测试: `.env.example` 文件

---

### 4.2 推荐的环境切换方案

#### 方案A: 使用不同的 env_file（推荐）✅

**compose-app.yml**:
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    env_file: .env.docker  # 开发环境
    # env_file: .env.production  # 生产环境（注释切换）
```

**不同环境的 compose 文件**:
```yaml
# compose-app.dev.yml
services:
  live_core_service:
    env_file: .env.docker  # 开发环境配置

# compose-app.prod.yml
services:
  live_core_service:
    env_file: .env.production  # 生产环境配置
```

**启动命令**:
```bash
# 开发环境
docker-compose -f compose-app.dev.yml up

# 生产环境
docker-compose -f compose-app.prod.yml up
```

**优点**:
- ✅ 无需修改代码
- ✅ 环境隔离清晰
- ✅ 配置管理简单

---

#### 方案B: 使用环境变量覆盖（灵活）

**compose-app.yml**:
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    env_file: .env.docker  # 基础配置
    environment:
      ENVIRONMENT: ${ENVIRONMENT:-production}  # 可通过命令行覆盖
      DEBUG: ${DEBUG:-false}
```

**启动命令**:
```bash
# 开发环境
ENVIRONMENT=development DEBUG=true docker-compose -f compose-app.yml up

# 生产环境
ENVIRONMENT=production DEBUG=false docker-compose -f compose-app.yml up
```

**优点**:
- ✅ 灵活，可通过命令行参数覆盖
- ✅ 适合CI/CD场景

---

#### 方案C: 使用 profiles（Docker Compose 3.9+）

**compose-app.yml**:
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    profiles:
      - dev
      - prod
    env_file:
      - .env.docker  # 基础配置
      - .env.${ENV:-dev}  # 根据ENV环境变量选择配置文件
```

**启动命令**:
```bash
# 开发环境
ENV=dev docker-compose --profile dev up

# 生产环境
ENV=prod docker-compose --profile prod up
```

**优点**:
- ✅ 支持多环境配置
- ✅ 配置灵活

---

### 4.3 推荐方案：方案A（最简单实用）

**文件结构**:
```
live-streaming-saas/
├── compose-app.yml          # 默认（开发环境）
├── compose-app.prod.yml     # 生产环境
├── .env.docker              # 开发环境配置
├── .env.production          # 生产环境配置
└── backend/
    └── live_core_service/
        ├── .env.example     # 配置模板
        └── app/
            └── main.py      # 无需修改 ✅
```

**compose-app.yml** (开发环境):
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    env_file: .env.docker  # 开发环境配置
```

**compose-app.prod.yml** (生产环境):
```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    env_file: .env.production  # 生产环境配置
```

**启动命令**:
```bash
# 开发环境
docker-compose -f compose-app.yml up

# 生产环境
docker-compose -f compose-app.prod.yml up
```

**优点**:
- ✅ **无需修改 main.py 代码**
- ✅ 环境隔离清晰
- ✅ 配置管理简单
- ✅ 符合 Docker Compose 最佳实践

## 5. 最佳实践建议

### 5.1 环境变量文件管理

**文件命名规范**:
- `.env.example` - 配置模板（提交到Git）
- `.env` - 本地开发配置（不提交）
- `.env.docker` - Docker开发环境配置（不提交）
- `.env.production` - Docker生产环境配置（不提交）

**Git 忽略规则**:
```gitignore
# 环境变量文件（包含敏感信息）
.env
.env.docker
.env.production
.env.local
.env.*.local

# 但保留模板文件
!.env.example
```

---

### 5.2 配置安全建议

#### ✅ **开发环境** (`.env.docker`)
```bash
# 可以使用较弱的密码（仅用于开发）
POSTGRES_PASSWORD=dev_password_123
JWT_SECRET_KEY=dev_jwt_secret_key_min_32_chars_for_development_only
CORS_ORIGINS=*
DEBUG=true
ENVIRONMENT=development
```

#### ✅ **生产环境** (`.env.production`)
```bash
# 必须使用强密码和密钥
POSTGRES_PASSWORD=<强密码，至少16字符>
JWT_SECRET_KEY=<强密钥，至少64字符，使用 openssl rand -hex 32 生成>
CORS_ORIGINS=https://yourdomain.com,https://www.yourdomain.com
DEBUG=false
ENVIRONMENT=production
```

---

### 5.3 main.py 代码保持不变

**当前 main.py** (第14行):
```python
load_dotenv()  # 无需修改 ✅
```

**为什么无需修改**:
1. ✅ `load_dotenv()` 会优先使用环境变量（如果存在）
2. ✅ Docker Compose 的 `env_file` 会将环境变量注入到容器
3. ✅ 环境变量优先级高于 `.env` 文件
4. ✅ 如果容器内没有 `.env` 文件，直接使用环境变量

**结论**: ✅ **main.py 代码无需修改，通过不同的 `env_file` 文件切换环境**

---

### 5.4 部署流程建议

#### **开发环境部署**:
```bash
# 1. 确保 .env.docker 文件存在并配置正确
# 2. 启动服务
docker-compose -f compose-app.yml up -d
```

#### **生产环境部署**:
```bash
# 1. 确保 .env.production 文件存在并配置正确（强密码、强密钥）
# 2. 启动服务
docker-compose -f compose-app.prod.yml up -d

# 3. 验证配置
docker-compose -f compose-app.prod.yml exec live_core_service \
  python -c "from app.core.config import settings; print(f'Environment: {settings.ENVIRONMENT}')"
```
