# 删除直播间 - 应用层级联删除 - 实现说明

## 1. 背景与问题

- **现象**：当直播间关联了专家（`live_session_experts` 有记录）或品牌（`brand_rooms` 有记录）时，直接删除房间会触发 `DatabaseIntegrityException`（外键约束冲突）。
- **原因**：虽然后端模型与数据库外键均配置了 `ON DELETE CASCADE`，但在部分场景下（如 ORM 删除顺序、事务边界等）仍可能触发完整性错误。为不依赖数据库级联顺序，在应用层显式按依赖顺序删除关联数据，再删除房间。

## 2. 实现方案概览

- **CRUD 层**：新增 `delete_room_related(db, room_id)`，在同一事务内按依赖顺序删除所有关联表数据，不提交；异常时回滚并抛出 `DatabaseOperationException`。
- **Service 层**：在 `delete_room` 中，在权限校验通过后、调用 `remove(room)` 前，先调用 `delete_room_related`，再执行 `remove`（由 `remove` 统一提交）。
- **API 层**：在删除房间接口中捕获 `DatabaseIntegrityException`，返回 409 及友好提示，避免 500。

## 3. 修改文件与函数

| 层级   | 文件路径 | 修改内容 |
|--------|----------|----------|
| CRUD   | `app/crud/room.py` | 新增 `delete_room_related(db, room_id)`；增加 `delete` 及关联模型导入；`remove` 不变。 |
| Service| `app/services/room_service.py` | 仅修改 `delete_room`：在调用 `crud_room.remove` 前增加 `await crud_room.delete_room_related(self.db, room_id)`。 |
| API    | `app/api/v1/endpoints/room.py` | 增加 `DatabaseIntegrityException` 导入；在 `delete_room` 接口中增加对 `DatabaseIntegrityException` 的捕获，返回 409。 |

## 4. 删除顺序（delete_room_related）

1. **依赖 session 的表**（按该房间下 `live_sessions` 的 id 列表）：  
   `live_session_experts` → `session_statistics` → `session_tags` → `live_room_messages`（按 session_id）→ `watch_history`
2. **依赖 room 的表**：  
   `brand_rooms` → `topic_category_rooms` → `live_room_categories`（科室关联）→ `live_room_official_accounts`（公众号关联）→ `live_room_messages`（按 room_id）→ `live_room_tabs` → `user_favorites`
3. **该房间的场次**：  
   `live_sessions`（room_id = room_id）  
房间本身由 `remove(db, room)` 删除并提交事务。

## 5. 异常与日志

- **delete_room_related**：内部 try/except，异常时 `await db.rollback()`，记录 `logger.error`，抛出 `DatabaseOperationException`；成功时记录 `logger.info`（含 room_id、sessions_count）。
- **delete_room（API）**：捕获 `DatabaseIntegrityException` 时返回 409，`message` 为「无法删除：存在关联数据，请先解除品牌/专家等关联或联系管理员」，并记录 `logger.warning`。

## 6. 设计文档可补充内容

- **删除房间**：在“删除直播房间”流程中注明：  
  - Service 在删除房间前会先调用 CRUD 的 `delete_room_related(room_id)` 删除所有关联数据（场次专家、品牌房间、专题房间、留言、Tab、收藏、场次等），再调用 `remove(room)` 删除房间并提交。  
  - 若仍发生完整性冲突，API 返回 409（code=2005），提示先解除关联或联系管理员。
