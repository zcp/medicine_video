# 爬虫与批量导入集成设计文档 v2.2

**文档版本**: v2.2  
**创建日期**: 2025-01-13  
**最后更新**: 2025-11-19  
**文档目的**: 设计并实现爬虫程序与批量导入功能的自动化集成，实现"自动爬取 → 生成CSV → 自动导入"的完整流程

本版本在 v1 基础上做最小幅度升级，以适配最新爬虫实现（dynamicCrawler_vzan_v3）：
- 将主状态从 CSV 迁移到 SQLite（vzan_crawler.db），维护表 liversoms、failed_pages；
- 不再使用"主 CSV"作为状态与导入来源，仅保留"增量 CSV"用于导入；
- 服务层与返回结构保持兼容，优先使用增量 CSV 导入；当无增量时不再回退到主 CSV。
- 批量导入默认开启去重（skip_duplicates=True），仅使用 `(user_id, resource_url, liveroom_id)`；导入前对 `resource_url` 标准化，并将标准化后的 m3u8 URL 入库。
- **v2.1 新增**：支持前端传递 token 和 cookie 参数，优先级为前端传递 > 配置读取（便于后端测试）；对 token 和 cookie 进行格式验证（Schema 层和服务层双重保障）；所有日志中禁止记录 token 和 cookie 的实际值。
- **v2.2 新增**：确保增量文件在API调用之前创建，即使API失败文件也存在（至少包含表头）；token/cookie错误时抛出异常而不是静默返回；增量文件不存在或为空时直接返回空结果（正常情况），不再回退到主文件；API层正确区分"没有数据导入"（正常）和"导入失败"（错误）；Playwright 浏览器资源管理：在单独线程中创建，保存线程池引用，确保关闭操作在同一线程中执行，失败时使用进程级别清理作为兜底。

## 一、需求分析

### 1.1 业务背景

当前系统存在两个独立的功能模块：
1. **爬虫模块**（dynamicCrawler_vzan_v3）：从指定 API 爬取直播间数据，状态入 SQLite，并输出本轮增量 CSV
2. **批量导入模块**（`batch_import_tasks_from_csv`）：从 CSV 文件批量创建下载任务

两个模块之间存在以下问题（沿用 v1，同时引入 SQLite 后的改进）：
- 原需要手动执行爬虫脚本生成 CSV；现由服务层统一调度；
- 原依赖主 CSV；现主状态改为 SQLite，仅保留增量 CSV 用于导入；
- 配置与安全、自动化流程诉求不变。

### 1.2 核心需求

#### 1.2.1 功能需求

**FR1 - 爬虫配置管理**
- 将爬虫配置（token、cookie、用户名、密码等）从代码中移除，通过环境变量管理
- 支持前端通过API传递 token 和 cookie（优先级高于配置），便于后端测试
- 支持多个爬虫源的配置
- 配置变更不需要修改代码

**FR2 - 自动化爬取与导入**
- 提供统一的 API 接口，一键完成"爬取 → 导入"流程
- 返回详细的执行结果（爬取成功数、导入成功数、失败详情等）
- v2 补充：爬虫返回以 incremental_file（增量 CSV）为主；crawl_file（主 CSV）可能为 None；可选返回 db_file（SQLite）
- v2 补充：导入阶段默认开启去重（skip_duplicates=True），去重键为 `(user_id, resource_url, liveroom_id)`；在去重前对 `resource_url` 标准化，并以标准化后的 URL 写入数据库。

**FR3 - 错误隔离与容错**
- 爬取失败不影响后续导入（如果有历史数据）
- 单行数据错误不中断整体流程
- 详细的错误日志和错误返回

**FR4 - 安全性**
- Token 和 Cookie 等敏感信息加密存储（配置中的token）
- 支持前端传递 token 和 cookie，优先级高于配置读取
- 对 token 和 cookie 进行格式验证（Schema 层和服务层双重保障）
- 所有日志中禁止记录 token 和 cookie 的实际值，仅可记录来源
- API 接口需要用户认证（JWT）
- 爬虫执行限流，防止滥用

#### 1.2.2 非功能需求

**NFR1 - 性能要求**
- 单次爬取支持最多10,000条数据
- 爬取+导入总耗时不超过5分钟
- 支持异步执行（不阻塞API响应）

**NFR2 - 可维护性**
- 爬虫代码与业务代码解耦
- 配置集中管理
- 完整的日志记录

**NFR3 - 可扩展性**
- 支持添加多种爬虫源（vzan、抖音、快手等）
- 爬虫逻辑插件化

#### 3.2.1 爬虫基类

`app/crawlers/base_crawler.py`（在 v1 契约基础上补充 SQLite/增量返回说明）：

```python
class BaseCrawler(ABC):
    @abstractmethod
    def crawl(self, config: Dict, **kwargs) -> Dict:
        """
        Returns:
            Dict: 爬取结果摘要（至少包含以下键，子类可扩展）

                    "failed_file": str|None,         # 失败记录文件路径（如有）
                    "total_rows": int,               # 推荐由 SQLite 统计
                    "failed_rows": int,              # 推荐由 SQLite 统计
                    "incremental_rows": int          # 增量 CSV 行数
                }
            可选扩展：
                {
                    "db_file": str|None              # SQLite 状态库路径
                }
        """
```

#### 3.2.2 微赞爬虫实现

`app/crawlers/vzan_crawler.py`（最小改动说明）：

- 适配 `dynamicCrawler_vzan_v3.py`：状态写入 SQLite（`db_file`），失败分页记录写入 `failed_pages`；
- 仅输出"增量 CSV"（如 `liveroomlist_inc_vzan_backup.csv`），不再写"主 CSV"；
- `total_rows`、`failed_rows` 优先从 SQLite 统计；
- 列名转换保持"中文 → 英文"与幂等校验（`liveroom_id`、`resource_url`、`resource_type`）。

**关键实现细节**（v2.2）：
- **文件创建时机**：`dynamicCrawler_vzan_v3.py` 的 `parse_all_liveroomlist_data` 方法在API调用之前创建增量文件，确保即使API失败，文件也存在（至少包含表头）
- **异常处理**：当token/cookie错误时，`parse_all_liveroomlist_data` 会抛出异常（而不是静默返回），异常消息明确说明是token/cookie错误
- **异常传播**：异常会被 `vzan_crawler.py` 的 `crawl` 方法捕获并转换为 `CrawlerError`，最终传播到服务层和API层
- **资源管理（v2.2补充）**：Playwright 浏览器对象在单独线程中创建（通过 `ThreadPoolExecutor`），`vzan_crawler.py` 需要保存线程池引用（`self._executor`），确保关闭操作在同一线程中执行；如果创建线程已退出，使用进程级别的清理作为兜底方案

文件路径信息（以实现为准）：

| 文件类型 | 属性名 | 路径示例 |
|:---|:---|:---|
| SQLite 状态库 | `db_file` | `backend/vzan_crawler/vzan_crawler.db` |
| 增量 CSV | `liveroom_list_savefile_inc` | `backend/vzan_crawler/liveroomlist_inc_vzan_backup.csv` |
| 失败记录（可选） | `failed_liveroomlist_url` | `backend/vzan_crawler/failed_liveroomlist_urls_vzan.txt` |

**CSV 列名说明**（与 v1 保持一致）：
- 中文 → 英文映射：`直播间ID → liveroom_id`、`播放url → resource_url`、`标题 → liveroom_title`、`直播间url → liveroom_url`；
- 新增列：`resource_type='hls'`；
- 幂等：英文表头跳过转换，仅做校验；
- 仅当 `liveroom_id` 与 `resource_url` 均非空时写入。

#### 3.2.3 爬虫工厂

`app/crawlers/__init__.py`：

```python
from typing import Dict
from .base_crawler import BaseCrawler
from .vzan_crawler import VzanCrawler
from app.core.exceptions import CrawlerError

class CrawlerFactory:
    """爬虫工厂，根据类型创建爬虫实例"""
    
    _crawlers = {
        'vzan': VzanCrawler,
        # 未来可扩展其他爬虫
        # 'douyin': DouyinCrawler,
        # 'kuaishou': KuaishouCrawler,
    }
    
    @classmethod
    def create(cls, crawler_type: str, config: Dict) -> BaseCrawler:
        """
        创建爬虫实例
        
        Args:
            crawler_type: 爬虫类型（vzan, douyin等）
            config: 爬虫配置字典
        
        Returns:
            BaseCrawler: 爬虫实例
        
        Raises:
            CrawlerError: 不支持的爬虫类型
        """
        crawler_class = cls._crawlers.get(crawler_type)
        if not crawler_class:
            raise CrawlerError(f"不支持的爬虫类型: {crawler_type}")
        
        return crawler_class(config)
```

### 3.3 服务层方法设计

#### 3.3.1 crawl_and_import_tasks

在 `app/services/download_service.py` 中的方法签名和详细流程：

**方法签名**：
```python
def crawl_and_import_tasks(
    self,
    crawler_type: str,
    user_id: uuid.UUID,
    skip_duplicates: bool = True,
    auto_start: bool = False,
    token: Optional[str] = None,  # 新增：可选参数，前端传递的token
    cookie: Optional[str] = None,  # 新增：可选参数，前端传递的cookie
    **crawl_kwargs
) -> Dict:
```

**详细流程**：

【第一步：变量提取（安全异步异常处理）】
- 提取 `user_id_for_logging = str(user_id)`
- 提取 `crawler_type_for_logging = crawler_type`
- **注意**：不提取 token 和 cookie 到日志变量（安全要求）

【第二步：记录开始日志】
- `logger.info(f"Starting crawl_and_import - User: {user_id_for_logging}, Crawler: {crawler_type_for_logging}")`
- **禁止**在日志中记录 token 和 cookie 的值

【第三步：try-except 包裹整体业务逻辑】

【第四步：执行业务逻辑】
1. 验证 crawler_type 参数（使用 `CrawlerFactory.get_supported_types()` 或白名单）
2. **处理 token 和 cookie（优先级：前端传递 > 配置读取）**
   - 如果方法参数中提供了 `token` 和 `cookie`，优先使用前端传递的值
   - 如果前端未传递，则从环境变量配置（`VZAN_TOKEN`、`VZAN_COOKIE`）中读取
   - 对最终使用的 token 和 cookie 进行格式验证（双重保障）：
     - Token：长度必须在10-500之间，不能包含 `<`, `>`, `"`, `'`, `;`, `\n`, `\r` 等非法字符
     - Cookie：长度必须在10-2000之间，不能包含 `<`, `>`, `\n`, `\r` 等非法字符
     - 验证失败抛出 `CrawlerConfigError`
   - **重要**：所有日志中不记录 token 和 cookie 的值，仅可记录来源（前端传递或配置读取）
3. 从环境变量读取其他爬虫配置（username, password）
   - 如果最终使用的 token 来自配置（前端未传递），且配置中的 token 是加密的，则进行解密
   - 如果最终使用的 token 来自前端传递，则直接使用（前端传递的是原始 token，不需要解密）
   - Cookie 的处理逻辑相同：前端传递优先，否则从配置读取（配置中的 cookie 通常不需要加密）
4. 创建爬虫实例（`CrawlerFactory.create`），将最终确定的 token 和 cookie 传入配置
5. 执行爬取（`crawler.crawl`）
6. 选择导入文件（重要：仅使用增量文件）
   - 检查 `incremental_file` 是否存在且非空（`incremental_rows > 0`）
   - 如果增量文件存在且非空：使用增量文件导入；记录日志 `logger.info("使用增量文件导入 ...")`
   - 如果增量文件不存在或为空：直接返回空结果（正常情况，不是错误），不导入数据；记录日志 `logger.info("无新增数据需要导入 ...")`
   - **注意**：不再回退到主文件（`csv_file`），避免重复导入历史数据
7. 读取 CSV 内容并调用 `batch_import_tasks_from_csv`（内部已做异常/事务处理）
8. 清理临时文件：可删除增量 CSV 和失败记录文件；不要删除 SQLite（db_file）以保留状态
9. 记录成功日志：`logger.info(f"Crawl and import completed ...")`（注意：不记录token/cookie）

**资源管理（v2.2补充）**：
- 在 `finally` 块中调用 `crawler.close()` 确保浏览器资源被关闭
- `vzan_crawler.py` 的 `close()` 方法使用保存的线程池引用（`self._executor`）在同一线程中关闭浏览器
- 如果线程池已关闭或关闭失败，使用进程级别的清理（`_force_cleanup_browser_processes()`）作为兜底

【第五步：异常处理】
- CrawlerConfigError：记录错误日志（不包含token/cookie）并返回业务错误码（400）
- CrawlerError：记录错误日志（不包含token/cookie）并返回业务错误码（500）
  - **v2.2 补充**：token/cookie错误会通过 `CrawlerError` 传播，异常消息明确说明是token/cookie错误
- FileNotFoundError：记录错误日志并返回业务错误码（400）
  - **v2.2 补充**：由于增量文件在API调用之前创建，正常情况下不应出现此错误
- SQLAlchemyError：`self.db.rollback()` 并返回 500
- 其他 Exception：记录错误（不包含token/cookie）、rollback 并抛出或包装返回

【第六步：返回结果】
- 统一返回 Dict，包含 crawl_status, crawl_rows, crawl_file(可能为 None), incremental_file, failed_file, import_result（BatchImportResult），error_message（可选）；可在 data 中附带 db_file（可选）。

- `crawler_type`: 爬虫类型（必填）
- `skip_duplicates`: 是否跳过重复任务（默认true）
- `auto_start`: 导入后是否自动启动（默认false）
- `token`: VZAN Token（可选，不传则使用配置中的VZAN_TOKEN）
- `cookie`: VZAN Cookie（可选，不传则使用配置中的VZAN_COOKIE）
- `crawl_options`: 爬虫特定参数（可选）

注意:
- `crawl_url` 不需要（微赞爬虫使用固定 API）
- `crawl_options` 传递给爬虫 `crawl()` 方法
- `token` 和 `cookie` 优先级：前端传递 > 配置读取（便于后端测试）
- `token` 和 `cookie` 格式验证规则：
  - Token：长度必须在10-500之间，不能包含 `<`, `>`, `"`, `'`, `;`, `\n`, `\r` 等非法字符
  - Cookie：长度必须在10-2000之间，不能包含 `<`, `>`, `\n`, `\r` 等非法字符
  - 验证在 Schema 层（Pydantic validator）和服务层（最终使用前）双重进行
- `skip_duplicates=true` 时，服务层将按 `(user_id, resource_url, liveroom_id)` 去重；在去重前对 `resource_url` 进行标准化，并把标准化后的 m3u8 URL 保存到数据库。
- **安全要求**：所有日志中不会记录 `token` 和 `cookie` 的值，仅记录是否使用前端传递或配置读取

## 五、安全设计

### 5.1 Token和Cookie安全管理

#### 5.1.1 Token和Cookie获取策略

**优先级规则**：
1. **前端传递优先**：如果API请求中提供了 `token` 和 `cookie` 参数，优先使用前端传递的值
2. **配置回退**：如果前端未传递，则从环境变量配置（`VZAN_TOKEN`、`VZAN_COOKIE`）中读取
3. **便于测试**：后端测试时可直接使用配置，生产环境建议前端传递

**服务层实现逻辑**：
```python
# 在 DownloadService.crawl_and_import_tasks() 中
# 优先级：前端参数 > 配置读取
final_token = token if token else settings.VZAN_TOKEN
final_cookie = cookie if cookie else settings.VZAN_COOKIE

# 对最终使用的值进行格式验证（双重保障）

    if not final_token or len(final_token) < 10 or len(final_token) > 500:

    if any(char in final_token for char in ['<', '>', '"', "'", ';', '\n', '\r']):

if final_cookie:
    final_cookie = final_cookie.strip()
    if not final_cookie or len(final_cookie) < 10 or len(final_cookie) > 2000:
        raise CrawlerConfigError("cookie格式无效：长度必须在10-2000之间")
    if any(char in final_cookie for char in ['<', '>', '\n', '\r']):
        raise CrawlerConfigError("cookie包含非法字符")
```

#### 5.1.2 Token加密存储（配置中的Token）

方案: 使用Fernet对称加密

```python
from cryptography.fernet import Fernet
import os

class TokenEncryption:
    """Token加密工具"""
    
    def __init__(self):
        encryption_key = os.getenv('TOKEN_ENCRYPTION_KEY')
        if not encryption_key:
            raise ValueError("TOKEN_ENCRYPTION_KEY环境变量未设置")
        self.cipher = Fernet(encryption_key.encode())
    
    def encrypt(self, token: str) -> str:
        """加密token"""
        return self.cipher.encrypt(token.encode()).decode()
    
    def decrypt(self, encrypted_token: str) -> str:
        """解密token"""
        return self.cipher.decrypt(encrypted_token.encode()).decode()
```

使用流程:
1. 初次配置时，管理员手动加密token: `python scripts/encrypt_token.py <原始token>`  
2. 将加密后的token写入 `.env` 文件: `VZAN_TOKEN=<加密后的token>`  
3. 应用启动时，自动解密token使用（仅当前端未传递token时）

**注意**：
- 如果前端通过API传递了 `token` 参数，则直接使用前端传递的值（不进行解密，因为前端传递的是原始token）
- 如果前端未传递 `token`，则从配置中读取并解密（配置中存储的是加密后的token）
- Cookie 的处理逻辑相同：前端传递优先，否则从配置读取（配置中的cookie通常不需要加密）

#### 5.1.3 Token刷新机制

- 如果token过期，记录错误日志并通知管理员

### 6.1 异常分类

```python
class CrawlerError(Exception):
    """爬虫基础异常"""
    pass

class CrawlerConfigError(CrawlerError):
    """爬虫配置错误"""
    pass

class CrawlerTimeoutError(CrawlerError):
    """爬虫超时错误"""
    pass

class CrawlerAPIError(CrawlerError):
    """爬虫API调用错误"""
    pass
```

### 6.1.2 异常处理流程

**异常传播路径**（v2.2）：
1. `dynamicCrawler_vzan_v3.py` 的 `parse_all_liveroomlist_data` 抛出 `Exception`（token/cookie错误时）
2. `vzan_crawler.py` 的 `crawl` 方法捕获并转换为 `CrawlerError`
3. `download_service.py` 的 `crawl_and_import_tasks` 捕获 `CrawlerError`，设置 `crawl_status='failed'` 并返回
4. API层检查 `crawl_status`，如果是 `failed`，返回错误响应给前端

```python
try:
    # 1. 执行爬取
    result = crawler.crawl(config, **options)
except CrawlerConfigError as e:
    return JSONResponse(status_code=200, content=create_error_response(message=f"爬虫配置错误: {str(e)}", code=400))
except CrawlerTimeoutError as e:
    return JSONResponse(status_code=200, content=create_error_response(message=f"爬取超时: {str(e)}", code=500))
except CrawlerAPIError as e:
    return JSONResponse(status_code=200, content=create_error_response(message=f"API调用失败: {str(e)}", code=500))
except CrawlerError as e:
    # v2.2: token/cookie错误会通过CrawlerError传播
    return JSONResponse(status_code=200, content=create_error_response(message=f"爬取失败: {str(e)}", code=500))
except Exception as e:
    logger.error(f"Crawl failed with unexpected error: {str(e)}", exc_info=True)
    return JSONResponse(status_code=200, content=create_error_response(message="系统内部错误", code=1000))
```

| CSV/SQLite 文件损坏 | 低 | 低 | 完整性校验、备份 |

### 10.2 业务风险
| 风险项 | 影响 | 概率 | 应对措施 |
|:---|:---|:---|:---|

| 重复任务大量导入 | 中 | 低 | 强制启用去重、导入前预检查 |
| 恶意使用 | 中 | 低 | 限流、权限管理 |
