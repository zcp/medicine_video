## 📌 新增需求说明

### 需求概述

在专题列表查询接口 (`GET /api/v1/topics`) 中新增两个查询参数，支持按专题标题和专题ID进行查询筛选：

1. **专题标题查询** (`title`)：
   - 支持模糊匹配（不区分大小写）
   - 使用SQL的 `ILIKE` 操作符实现
   - 匹配模式：`%{title}%`（包含指定字符串）

2. **专题ID查询** (`topic_id`)：
   - 支持精确匹配
   - 使用主键字段（UUID类型）进行查询
   - 性能优秀（主键索引）

### 权限控制需求（保持不变）

查询功能必须遵守既有的权限控制规则，不同用户身份的可查询范围如下：

#### 1. 匿名用户（Anonymous）
- **可查询范围**：仅 `status='published'` 的专题
- **说明**：无论提供任何查询参数（title、topic_id、status等），权限过滤始终限制为已发布状态的专题
- **示例**：
  - 查询 `GET /api/v1/topics?title=专题` → 只能查询到已发布且标题包含"专题"的专题
  - 查询 `GET /api/v1/topics?topic_id=xxx&status=draft` → 查询结果为空（无权访问draft专题）

#### 2. 普通用户（Regular User）
- **可查询范围**：所有 `status='published'` 的专题 + 自己创建的专题（`user_id=current_user_id`）
- **权限规则**：`status='published'` OR (`status IN ('draft', 'archived')` AND `user_id=current_user_id`)
- **说明**：
  - 可以查询所有已发布的专题（无论创建者是谁）
  - 可以查询自己创建的draft和archived专题
  - 不能查询他人创建的draft和archived专题
- **示例**：
  - 查询 `GET /api/v1/topics?title=我的专题&status=draft` → 只能查询到自己创建的、标题包含"我的专题"的draft专题
  - 查询 `GET /api/v1/topics?topic_id=xxx`（他人创建的draft专题） → 查询结果为空

#### 3. 管理员（Admin / SuperAdmin）
- **可查询范围**：所有状态的专题（无限制）
- **说明**：不受权限过滤限制，可以查询所有专题，包括所有状态的专题
- **示例**：
  - 查询 `GET /api/v1/topics?title=专题&status=draft` → 可以查询到所有标题包含"专题"的draft专题

### 权限控制实现原则

1. **权限过滤与业务筛选分离**：
   - 业务筛选条件（title、topic_id、status、user_id）：用户主动提供的筛选条件
   - 权限过滤条件：根据用户身份自动应用的访问控制规则
   - 两者使用 **AND关系** 组合，确保权限安全

2. **权限过滤独立于业务筛选**：
   - 权限过滤条件必须独立于业务筛选条件，不受业务筛选参数影响
   - 权限过滤始终应用完整的权限规则（Published OR (Draft/Archived AND Own)）
   - 如果业务筛选条件与权限过滤冲突，结果集自然为空

3. **列表查询的SQL层实现**（针对get_topic_list接口）：
   - 对于列表查询，筛选和权限过滤必须在CRUD层的SQL查询中完成
   - 禁止查出所有数据后在内存中过滤（性能陷阱）
   - **说明**：单资源操作（get_topic_detail、update_topic等）的权限检查在Service层实现（使用权限守卫函数），这是合理的架构设计，因为需要先获取资源对象才能进行权限判断

### 前端界面调整

- 前端界面中的"页面标题"应改为"**专题标题**"
- 前端界面中的"页面ID"应改为"**专题ID**"

**修改后**：

```python
# 构建基础查询
stmt = select(Topic)
count_stmt = select(func.count()).select_from(Topic)

# 1. 先应用业务筛选条件
business_filters = []
if title:  # ← 新增：专题标题模糊匹配（不区分大小写）
```

**关键技术点**：

- `topic_id` 使用 `==` 进行精确匹配（主键字段已有索引，性能良好）

**当前的权限过滤逻辑**（保持不变）：
```python
# 2. 再应用权限过滤条件（根据用户身份决定可见范围，独立于业务筛选条件）
permission_filters = []
if current_user_role in ['ADMIN', 'SUPERADMIN']:
    # 管理员：无权限过滤，可查看所有状态的专题
    pass
elif current_user_id:
    # 普通用户：Published OR (Draft/Archived AND Own)
    permission_filters.append(
        or_(
            Topic.status == TopicStatus.PUBLISHED,
            and_(
                Topic.status.in_([TopicStatus.DRAFT, TopicStatus.ARCHIVED]),
                Topic.user_id == current_user_id
            )
        )
    )
else:
    # 匿名用户：Only Published
    permission_filters.append(Topic.status == TopicStatus.PUBLISHED)
```

## 第五部分：关键技术实现细节

### 5.1 专题标题模糊查询实现

#### 实现方式
使用PostgreSQL的 `ILIKE` 操作符（SQLAlchemy中的 `ilike` 方法）

#### 代码示例
```python
if title:
    business_filters.append(Topic.title.ilike(f'%{title}%'))
```

#### 技术特点
- **不区分大小写**：`ilike` 是 `like` 的不区分大小写版本
- **模糊匹配**：`%{title}%` 表示包含指定字符串的匹配
- **性能考虑**：`LIKE '%text%'` 模式查询对B-tree索引效果有限，如需高性能可考虑PostgreSQL全文索引

#### SQL示例
```sql
-- 当 title = "专题" 时，生成的SQL条件
WHERE topics.title ILIKE '%专题%'
-- 会匹配："专题一"、"我的专题"、"专题列表" 等
```

### 5.2 专题ID精确查询实现

#### 实现方式
使用等值比较（`==` 操作符）

#### 代码示例
```python
if topic_id:
    business_filters.append(Topic.id == topic_id)
```

#### 技术特点
- **精确匹配**：使用主键字段（UUID类型）
- **高性能**：主键字段已有索引，查询性能优秀
- **类型安全**：topic_id在API层已转换为UUID类型

#### SQL示例
```sql
-- 当 topic_id = "123e4567-e89b-12d3-a456-426614174000" 时，生成的SQL条件
WHERE topics.id = '123e4567-e89b-12d3-a456-426614174000'::uuid
```

### 5.3 业务筛选与权限过滤的组合逻辑

#### 组合方式
业务筛选条件和权限过滤条件使用 **AND关系** 组合

#### 执行顺序
1. **先应用业务筛选条件**：title、topic_id、status、user_id
2. **再应用权限过滤条件**：根据用户身份（Admin/Regular/Anonymous）应用权限规则
3. **合并条件**：使用AND关系组合所有条件

#### SQL示例（Regular用户查询title包含"专题"的draft专题）

**业务筛选条件**：
```sql
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'
```

**权限过滤条件**：
```sql
WHERE (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))
```

**最终SQL**：
```sql
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'
  AND (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))
```

**简化后**（因为status='draft'，第一个OR条件为false）：
```sql
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'draft'
  AND topics.user_id = current_user_id
```

**结果**：只能查询到自己创建的、标题包含"专题"的draft专题 ✅

## 第六部分：权限控制验证

### 6.1 权限控制规则（保持不变）

| 用户类型 | 可查询的专题范围 | 说明 |
|---------|----------------|------|
| **匿名用户** | 仅 `status='published'` 的专题 | 无论业务筛选条件如何，权限过滤始终限制为published |
| **普通用户（Regular）** | `status='published'` 的专题 + 自己创建的专题（`user_id=current_user_id`） | 权限过滤条件：Published OR (Draft/Archived AND Own) |
| **管理员（Admin）** | 所有状态的专题 | 无权限过滤限制 |

### 6.2 权限控制示例

#### 场景1：匿名用户查询 `title="专题"`

**请求**：
```
GET /api/v1/topics?title=专题
```

**业务筛选条件**：
```sql
WHERE topics.title ILIKE '%专题%'
```

**权限过滤条件**：
```sql
WHERE topics.status = 'published'
```

**最终SQL**：
```sql
WHERE topics.title ILIKE '%专题%'
  AND topics.status = 'published'
```

**结果**：✅ 只能查询到已发布且标题包含"专题"的专题

#### 场景2：Regular用户查询 `topic_id="xxx"`，该专题是其他人的draft专题

**请求**：
```
GET /api/v1/topics?topic_id=xxx
Authorization: Bearer <token>  # Regular用户token
```

**业务筛选条件**：
```sql
WHERE topics.id = 'xxx'::uuid
```

**权限过滤条件**（假设该专题status='draft'且user_id != current_user_id）：
```sql
WHERE (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))
```

**最终SQL**：
```sql
WHERE topics.id = 'xxx'::uuid
  AND (topics.status = 'published' 
    OR (topics.status IN ('draft', 'archived') 
        AND topics.user_id = current_user_id))
```

**结果**：✅ 查询结果为空（无权访问他人的draft专题），符合权限控制要求

```
GET /api/v1/topics?title=专题&status=draft
Authorization: Bearer <token>  # Admin用户token
```

```sql
  AND topics.status = 'draft'
```

**权限过滤条件**：

```sql
WHERE topics.title ILIKE '%专题%'
```

**结果**：✅ 可以查询到所有标题包含"专题"的draft专题（无权限限制）
