## 3. 文档一致性分析

### 3.1 学院派架构风格一致性

#### 3.1.1 分层架构

文档A（第3节）定义的学院派架构：
```
API (router) 层: 接收HTTP请求 → 解析参数 → 注入db和current_user → try...except块
    ↓
Service (业务) 层: 业务逻辑 + 权限验证 → 抛自定义异常（严禁HTTPException）
    ↓
CRUD (数据) 层: 数据库原子操作 → 事务处理（commit/rollback）
```

文档C（第1节、第4节）的实现：
```python
# API层: 依赖注入
@router.get("/rooms/{id}")
async def get_room_detail(
    room_id: str,
    current_user: Optional[User] = Depends(get_current_user_optional)
):
    try:
        room = await room_service.get_room_detail(room_id, current_user)
        return success_response(data=room)
    except NotFoundException as e:
        return JSONResponse(status_code=404, content=error_response(...))

# Service层: 权限守卫
def get_room_detail(self, room_id: str, current_user: Optional[User]) -> Room:
    room = self.repo.find(room_id)
    if not room:
        raise NotFoundException("Room not found")
    check_visibility(room, current_user)  # 鉴权逻辑
    return room

# 守卫函数: 统一可见性校验
def check_visibility(room: Room, user: Optional[User]) -> None:
    if room.visibility == Visibility.PUBLIC:
        return
    if not user:
        raise NotFoundException("Room not found")  # 404伪装
    if user.role in [Role.ADMIN, Role.SUPERADMIN]:
        return
    if room.owner_public_id == user.public_id:
        return
    raise NotFoundException("Room not found")
```

**一致性评分: ⭐⭐⭐⭐⭐ (5/5)**
- ✅ API层只做认证（Authentication）
- ✅ Service层负责鉴权（Authorization）
- ✅ 异常处理严格遵循"Service抛自定义异常、API层捕获转换"模式
- ✅ CRUD层未在文档C中修改，保持原有事务处理逻辑

@router.post("/internal/srs/on_publish")
async def on_publish_callback(
    request: Request,
    payload: OnPublishPayload,
    signature: str = Header(...)
):
    # 1. IP白名单校验
    if request.client.host not in SRS_ALLOWED_IPS:
        raise HTTPException(status_code=403, detail="IP not allowed")
    
    # 2. HMAC签名校验
    expected_sig = hmac.new(
        SRS_CALLBACK_SECRET.encode(),
        payload.json().encode(),
        hashlib.sha256

    if signature != expected_sig:
        raise HTTPException(status_code=401, detail="Invalid signature")
