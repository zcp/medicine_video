## 🎯 核心功能需求

### 功能定义
- **下架状态**：直播间标记为下架后，普通用户（包括其他Regular用户）无法看到该直播间
- **创建者可见**：直播间创建者在下架后仍然可以看到自己的直播间
- **管理员可见**：Admin和SuperAdmin可以看到下架的直播间
- **URL直接访问**：即使用户通过URL直接访问下架的直播间，也会被拒绝（返回404，除非是创建者或管理员）
- **Session继承**：下架直播间的所有Session对普通用户不可见（继承Room的下架状态）

### 权限矩阵

| 用户类型 | 下架前可见 | 下架后可见 | 说明 |
|---------|-----------|-----------|------|
| **Anonymous（匿名）** | ✅ 公开房间 | ❌ 所有房间 | 下架后完全不可见 |
| **Regular User（普通用户，非创建者）** | ✅ 公开+自己的房间 | ❌ 所有房间 | 下架后完全不可见 |
| **Room Owner（创建者）** | ✅ 自己的房间 | ✅ 自己的房间 | **下架后仍可见** |
| **Admin/SuperAdmin** | ✅ 所有房间 | ✅ 所有房间 | 始终可见 |

### 关键权限逻辑修正

**重要修正**：下架后，创建者仍然可以看到自己的直播间。这与`is_private=true`的权限逻辑一致：
- `is_private=true`时，创建者可见（第85行：`room.user_id == user_id`）
- 下架后（`is_offline=true`），创建者也应该可见

**修改后的权限检查逻辑**：
```python
def _check_room_visibility(self, room, user_id, role):
    # ← 新增：优先检查下架状态
    if room.is_offline:
        if role in ['ADMIN', 'SUPERADMIN']:
            return  # 管理员可见
        if user_id and room.user_id == user_id:
            return  # 创建者可见
        raise NotFoundException("Room not found")  # 其他用户不可见
    
    # 原有的 is_private 检查逻辑保持不变
    # ...
```

## 🔍 关键问题分析

### 问题1：CRUD层是否需要过滤下架房间？

**答案：需要！**

**原因分析**：
1. **设计规范要求**：权限设计文档第121行明确要求"CRUD层负责在SQL层面应用权限过滤逻辑——禁止内存过滤"
2. **性能考虑**：在SQL层面过滤（CRUD层）比在内存中过滤（Service层）更高效，避免查询大量数据后再过滤
3. **现有实现模式**：查看`room.py`的`get_multi_and_total`方法（第111-160行），已经在CRUD层实现了is_private的SQL过滤
4. **一致性原则**：下架过滤应与is_private过滤采用相同的架构模式

**实施要求**：
- CRUD层的列表查询方法（`get_multi_and_total`、`list_with_search`等）必须在WHERE条件中加入`is_offline=false`过滤（管理员和创建者除外）
- 单个查询方法（`get`）不需要过滤，由Service层的`_check_room_visibility`检查

### 问题2：其他模块（Brand、Topic等）如何与Room交互？

**重要发现**：其他模块都是**直接访问数据库**，不是调用Room的CRUD/Service方法。

**检查结果**：
- **Brand模块**：CRUD层直接JOIN `LiveRoom`表（`brand.py`第559行），Service层直接查询`LiveRoom`（`brand_service.py`第655、717、762行）
- **Topic模块**：CRUD层直接JOIN `LiveRoom`表（`topic.py`第698行），已实现is_private过滤，但缺少is_offline过滤
- **Homepage Search模块**：直接查询`live_rooms`表，使用原生SQL（`homepage_search.py`第339行）
- **User Behavior模块**：Service层验证Room存在性（`user_behavior_service.py`第124行），但没有权限检查

**结论**：需要在所有这些模块的CRUD层查询中添加`is_offline`过滤，在Service层添加权限检查。

    )
