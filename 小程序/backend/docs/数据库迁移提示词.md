# 数据库迁移提示词

## 1. 迁移目标
基于以下模型定义生成完整的数据库迁移文件，确保PostgreSQL数据库结构与模型定义完全一致：

###1.1 基于以下模型定义生成迁移文件，包含所有表：
   - download_tasks（下载任务表）
   - download_segments（下载分片表）
   - download_failures（下载失败记录表）
   - download_configs（下载配置表）
   - downloaded_videos（已下载视频表）
   - downloaded_video_segments（已下载视频分片表）

###1.2. 每个表的具体要求：
   - 所有表使用 UUID 作为主键
   - 所有外键关系使用 ondelete="CASCADE"
   - 所有字段的类型、长度、约束必须与模型定义完全一致s
   - 所有索引和唯一约束必须与模型定义完全一致
   - 所有 CheckConstraint 必须完全匹配
   - 所有默认值必须正确设置

###1.3. 特别注意：
   - 使用 postgresql.UUID 类型
   - 确保所有字符串字段的长度限制正确
   - 确保所有时间戳字段使用正确的类型和默认值
   - 确保所有布尔值字段使用正确的类型和默认值
   - 确保所有数值字段使用正确的类型和精度
   - 确保所有枚举字段的 CheckConstraint 正确

###1.4. 迁移文件需要包含：
   - 正确的表创建顺序（考虑外键依赖）
   - 所有字段的精确类型定义
   - 所有约束（主键、外键、唯一、非空等）
   - 所有索引
   - 所有默认值
   - 所有 ondelete 行为

## 2.迁移文件验证
###2.1. 检查生成的SQL语句
   - 验证表创建顺序是否正确
   - 验证所有字段定义是否准确
   - 验证所有约束和索引是否完整
###2.2. 使用SQLAlchemy反射验证
   ```python
   from sqlalchemy import MetaData, Table
   metadata = MetaData()
   Table('table_name', metadata, autoload_with=engine)
   ```
