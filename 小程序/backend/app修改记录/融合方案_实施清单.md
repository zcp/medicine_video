## 二、解决的问题清单（按严重度排序）

| # | 问题 | 当前状态 | 融合方案解决 |
|:--|:-----|:--------|:-----------|
| 1 | `department` 自由文本与 `category_id` 无一致性约束 | 384 专家自由文本 | → expert_departments FK + PostgreSQL 触发器同步 |
| 2 | 新科室（如"结构性心脏病组"）匹配不到时无法处理 | 报错/中断导入 | → 自动创建 is_verified=false + 启发式匹配到心内科 |
| 3 | categories 表被 241 条测试垃圾污染 | 261条，只有20条真实 | → categories 运行时只读，不写入 |
| 4 | 新专家可能在分类筛选下丢失 | 归入"其他"不可见 | → 自动归类到正确的大类 |
| 5 | 742 个测试房间无分类且会出现在首页 | 无过滤机制 | → 补齐分类 + 前端分类Tab展示 |
| 6 | `category_id` 全局 UNIQUE 约束阻止子分类 | 无分层能力 | → 部分索引替换 |
| 7 | 同科室不同写法创建重复记录 | "冠脉介入组" vs "冠脉支架组" | → synonyms 自学习合并 |

## 三、融合方案解决后能做到的（6个以前做不到的事）

1. **操作时输入科室名，系统自动归类 → 永不报错** 
   _当前状态：输入一个未识别的科室名，报错并中断创建。_
   
2. **Tab 筛选时换到任何分类都能找到所有相关专家**
   _当前状态：没填 category_id 的专家在 Tab 上不可见。_
   
3. **同一科室的各种写法最终归并到标准名称**
   _当前状态：自由文本，41 个值各自独立，无归并。_
   
4. **查询"哪些专家没有映射到标准科室"直接出结果**
   _当前状态：没有这个功能。_
   
5. **管理员修改科室分类 → 所有关联专家自动同步**
   _当前状态：需要逐个修改专家的 category_id。_
   
6. **直播间卡片显示真实分类名而非硬编码 "--"**
   _当前状态：RoomList.vue 和 detail.vue 均为硬编码文本。_

## 四、需要改动的位置（精确清单）

- categories 表加 `parent_id, is_public` + 部分唯一索引（迁移 SQL）
- **新建** expert_departments 表 + 索引
- experts 表加 `department_id` FK → 删 `department` 列 → `category_id` 改 NOT NULL
