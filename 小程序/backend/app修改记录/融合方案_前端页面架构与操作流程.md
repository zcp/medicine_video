# 融合方案 — 前端页面架构与操作流程

## 一、742 个房间无分类：数据解释

### 数据对比

| 来源 | 房间总数 | 已分类 | 无分类 | 说明 |
|:----|:--------|:------|:------|:-----|
| 冻结方案文档 | 81 | 12 | 69 | 之前业务数据清点 |
| 当前数据库实际 | **796** | 54 | **742** | 数据库已大幅增长 |

**差异原因**：冻结方案文档编写时的 81 个房间是业务数据清点的结果。之后数据库积累了 715 个房间（来自开发测试、批量导入、环境演练等）。当前 `live_rooms` 表没有任何 `is_test` 标志位能区分真实数据与测试数据。

**对融合方案的影响**：不阻断。742 个无分类房间中，真实业务房间需要通过 Step 3（数据迁移）按标题/关键词匹配分类。测试房间不受影响（不需要分类）。

## 四、专家分类 Tab 和直播间分类 Tab 的一致性

### 核心原理

```
专家和直播间共享同一套 categories 表

专家筛选:
  SELECT * FROM experts WHERE category_id = :selected_category_id

直播间筛选:
  SELECT * FROM live_rooms
  WHERE EXISTS (
    SELECT 1 FROM live_room_categories
    WHERE room_id = live_rooms.id AND category_id = :selected_category_id
  )
```

**两个 Tab 使用的是同一个 `category_id`，只是查询逻辑不同。**

### 一致性保证

```
                 categories（唯一真相源）
                 ┌──────────────────────┐
                 │ 普通外科              │
                 │ 神经外科              │
                 │ 心内科                │
                 │ ... 20个根分类        │
                 └──────┬───────────────┘
                        │
          ┌─────────────┼──────────────┐
          ▼             │              ▼
  ┌───────────────┐     │      ┌──────────────────────┐
  │ 专家分类Tab    │     │      │ 直播间分类Tab         │
  │               │     │      │                      │
  │ [普通外科]     │  ← 同一个 → │ [普通外科]            │
  │ [神经外科]     │  categories.id  │ [神经外科]            │
  │ [心内科]       │               │ [心内科]              │
  │ ...           │               │ ...                  │
  │               │               │                      │
  │ 点击"心内科":  │               │ 点击"心内科":         │
  │  SELECT *     │               │  SELECT *            │
  │  FROM experts │               │  FROM live_rooms     │
  │  WHERE        │               │  WHERE EXISTS (...   │
  │  category_id  │               │  category_id =       │
  │  = 心内科.id  │               │  心内科.id)           │
  └───────────────┘               └──────────────────────┘
```

### 具体例子

```
首页 → 用户点击「心内科」Tab

  ┌─ 心内科直播间 ─────────────────────┐
  │ 冠脉介入手术直播（主分类: 心内科）    │
  │ 心律失常消融直播（主分类: 心内科）    │
  │ 心力衰竭诊断直播（主分类: 心内科）    │
  └────────────────────────────────────┘

  ┌─ 心内科专家 ───────────────────────┐
  │ 孙医生  冠心病介入组 / 心内科        │
  │ 钱医生  心律失常组 / 心内科          │
  │ 周医生  结构性心脏病组 / 心内科      │
  └────────────────────────────────────┘

  即使 "冠心病介入组" 和 "结构性心脏病组" 是 is_verified=false
  （自动创建的科室），但它们都挂在 心内科 下。
  点击「心内科」Tab 时，这些专家能被正常筛选出来。

  用户看不到这些具体的子科室名，只看到它们都在「心内科」大类下。
  ✅ Tab 栏始终显示 20 个根分类，不受自动创建的科室影响
  ✅ 点击任何 Tab，能找到所有属于该大类的专家和直播间

│  │   ├─ 神经外科                                     │   │

│  └──────────────────────────────────────────────────┘   │

说明：
  - 分类选择器只加载 20 个根分类（GET /categories?is_public=true 或
    GET /categories?parent_id=NULL）
  - 不显示子分类和 is_verified=false 的科室（不影响直播间的分类选择）
  - 一个直播间最少选 1 个分类（主分类），最多选 5 个分类
  - 主分类用于卡片展示（is_primary=true）
  - 所有分类都用于筛选命中
```
