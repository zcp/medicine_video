# 环境变量配置方案分析

## 📋 当前配置分析

### 当前使用方式

所有服务都使用同一个 `.env.docker` 文件：

```yaml

  env_file: .env.docker

  env_file: .env.docker

  env_file: .env.docker
```

## 📊 配置分类

### 共享配置（所有服务都需要）

| 配置项 | 使用服务 | 是否共享 |
|--------|---------|---------|
| `POSTGRES_SERVER` | 所有 | ✅ 是 |
| `POSTGRES_PORT` | 所有 | ✅ 是 |
| `POSTGRES_USER` | 所有 | ✅ 是 |
| `POSTGRES_PASSWORD` | 所有 | ✅ 是 |
| `JWT_SECRET_KEY` | live_core, user | ✅ 是 |
| `JWT_ALGORITHM` | live_core, user | ✅ 是 |
| `CORS_ORIGINS` | live_core, user | ✅ 是 |
| `CELERY_BROKER_URL` | live_core, media_download | ✅ 是 |
| `CELERY_RESULT_BACKEND` | live_core, media_download | ✅ 是 |

### 服务特定配置

| 服务 | 特定配置 |
|------|---------|
| **live_core_service** | `ROOM_MEDIA_ROOT_PATH`, `UPLOAD_*`, `PLAYBACK_BASE_URL` |
| **user_service** | `VITE_CLIENT_ID`, `USER_POOL_SECRET`, `APP_HOST`, `REDIRECT_URL`, `ISSUER` |
| **media_download_service** | `DOWNLOAD_DIR`, `VZAN_*`, `CRAWLER_*` |
| **postgres** | 无特定配置 |
| **celery_worker** | 与 live_core_service 相同 |

## 💡 方案对比

### 方案一：公共 .env.docker（当前方案）

**配置方式**：
```yaml
services:
  live_core_service:
    env_file: .env.docker
  user_service:
    env_file: .env.docker
  # ...
```

**优点**：
- ✅ **简单**：只需维护一个文件
- ✅ **一致性**：共享配置自动同步
- ✅ **减少重复**：数据库、JWT、Redis 等配置只需写一次
- ✅ **易于管理**：修改共享配置只需改一处

**缺点**：
- ❌ **耦合度高**：所有服务配置混在一起
- ❌ **安全性**：敏感信息集中在一个文件
- ❌ **灵活性差**：难以针对不同服务设置不同值
- ❌ **可读性差**：文件可能很大，难以找到特定服务的配置

### 方案二：每个服务独立的 .env 文件（你想要的方案）

**配置方式**：
```yaml
services:
  live_core_service:
    env_file: 
      - .env.shared      # 共享配置
      - ./backend/live_core_service/.env  # 服务特定配置
  user_service:
    env_file:
      - .env.shared
      - ./backend/users/.env
  # ...
```

**优点**：
- ✅ **模块化**：每个服务配置独立
- ✅ **安全性**：敏感信息分散，降低风险
- ✅ **灵活性**：可以为不同服务设置不同值
- ✅ **可维护性**：配置清晰，易于查找
- ✅ **团队协作**：不同团队可以独立管理自己的配置

**缺点**：
- ⚠️ **配置重复**：共享配置需要在多个文件中维护
- ⚠️ **同步问题**：修改共享配置需要更新多个文件
- ⚠️ **复杂度增加**：需要管理多个文件

### 方案三：混合方案（推荐⭐）

**配置方式**：
```yaml
services:
  live_core_service:
    env_file:
      - .env.shared           # 共享配置（数据库、JWT、Redis等）
      - .env.live_core        # 服务特定配置
  user_service:
    env_file:
      - .env.shared
      - .env.user
  # ...
```

**优点**：
- ✅ **最佳平衡**：共享配置统一管理，服务配置独立
- ✅ **灵活性**：可以为不同服务设置不同值
- ✅ **可维护性**：配置清晰，易于管理
- ✅ **安全性**：敏感信息可以分散

**缺点**：
- ⚠️ **需要维护两个文件**：共享配置 + 服务配置

## 🎯 推荐方案：混合方案（方案三）

### 文件结构

```
live-streaming-saas/
├── .env.shared              # 共享配置（数据库、JWT、Redis等）
├── .env.live_core           # live_core_service 特定配置
├── .env.user                # user_service 特定配置
├── .env.media_download      # media_download_service 特定配置
└── compose-app.yml
```

### 配置示例

#### .env.shared（共享配置）

```bash
# ============================================
# 共享配置 - 所有服务共用
# ============================================

# 数据库配置
POSTGRES_SERVER=localhost
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_secure_password_here

# JWT 配置（live_core 和 user 服务共享）
JWT_SECRET_KEY=your_jwt_secret_key_here_min_32_chars
JWT_ALGORITHM=HS256

# CORS 配置
CORS_ORIGINS=*

# Celery 配置（live_core 和 media_download 服务共享）
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/0

# 通用配置
DEBUG=true
ENVIRONMENT=development
```

#### .env.live_core（live_core_service 特定）

```bash
# ============================================
# Live Core Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=live_core_test

# 应用特定配置
ROOM_MEDIA_ROOT_PATH=/app/media
UPLOAD_MAX_SIZE=10485760
UPLOAD_ALLOWED_EXTENSIONS=jpg,jpeg,png,gif
PLAYBACK_BASE_URL=http://localhost:8000
```

#### .env.user（user_service 特定）

```bash
# ============================================
# User Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=users_service_test

# 用户服务特定配置
VITE_CLIENT_ID=your_client_id
USER_POOL_SECRET=your_user_pool_secret
APP_HOST=https://yourdomain.com
REDIRECT_URL=https://yourdomain.com/callback
ISSUER=https://yourdomain.com
```

#### .env.media_download（media_download_service 特定）

```bash
# ============================================
# Media Download Service 特定配置
# ============================================

# 数据库名称（覆盖共享配置）
POSTGRES_DB=media_download_test

# 下载服务特定配置
DOWNLOAD_DIR=/app/storage
VZAN_USERNAME=your_username
VZAN_PASSWORD=your_password
VZAN_TOKEN=your_token
VZAN_COOKIE=your_cookie
CRAWLER_TIMEOUT=10
CRAWLER_TEMP_DIR=/tmp/vzan_crawler
```

### compose-app.yml 配置

```yaml
services:
  live_core_service:
    build: ./backend/live_core_service
    restart: unless-stopped
    ports: ["8000:8000"]
    environment:
      POSTGRES_DB: "live_core_test"  # 也可以在 compose 中直接设置
      ROOM_MEDIA_ROOT_PATH: "/app/media"
    env_file:
      - .env.shared
      - .env.live_core
    volumes:
      - /var/www/html/live-core-media:/app/media
    networks:
      - live-network

  user_service:
    build: ./backend/users
    restart: unless-stopped
    ports: ["8002:8002"]
    environment:
      POSTGRES_DB: "users_service_test"
    env_file:
      - .env.shared
      - .env.user
    networks:
      - live-network

  media_download_service:
    build: ./backend/media_download_service
    restart: unless-stopped
    ports: ["8001:8001"]
    environment:
      POSTGRES_DB: "media_download_test"
    env_file:
      - .env.shared
      - .env.media_download
    volumes:
      - media_download:/media_download/storage
    networks:
      - live-network

  celery_worker:
    build: ./backend/live_core_service
    restart: unless-stopped
    env_file:
      - .env.shared
      - .env.live_core  # 与 live_core_service 相同
    command: celery -A app.tasks.celery_app worker --include=app.tasks.session_processing -l info -c 10
    networks:
      - live-network

  postgres:
    image: postgres:15-alpine
    restart: unless-stopped
    ports: ["5432:5432"]
    env_file:
      - .env.shared  # 只需要共享配置
    volumes:
      - ./init-db.sh:/docker-entrypoint-initdb.d/init-db.sh:ro
      - pgdata:/var/lib/postgresql/data
    networks:
      - live-network
```

## ✅ 最终推荐

### 推荐使用：混合方案（方案三）

**理由**：
1. ✅ **平衡最佳**：既保持了共享配置的统一管理，又实现了服务配置的独立
2. ✅ **符合微服务理念**：每个服务配置独立，便于团队协作
3. ✅ **易于维护**：共享配置集中管理，服务配置清晰分离
4. ✅ **安全性更好**：敏感信息可以分散到不同文件
5. ✅ **灵活性高**：可以为不同服务设置不同值

### 实施步骤

1. **创建共享配置**：`.env.shared`
2. **创建服务配置**：`.env.live_core`, `.env.user`, `.env.media_download`
3. **修改 compose-app.yml**：使用多个 `env_file`
4. **测试验证**：确保所有服务正常启动

## ⚠️ 注意事项

### 1. 环境变量优先级

Docker Compose 中环境变量的优先级（从高到低）：
1. `environment` 中直接设置的值
2. `env_file` 中后加载的文件（覆盖先加载的）
3. `env_file` 中先加载的文件

**示例**：
```yaml
env_file:
  - .env.shared      # 先加载
  - .env.live_core   # 后加载，会覆盖 .env.shared 中的同名变量
```

### 2. 敏感信息管理

- ✅ 使用 `.gitignore` 排除所有 `.env*` 文件
- ✅ 创建 `.env.example` 作为模板（不包含真实值）
- ✅ 使用密钥管理工具（如 HashiCorp Vault）管理生产环境密钥

### 3. 配置同步

- ⚠️ 修改共享配置时，需要确保所有服务都能正常工作
- ✅ 使用配置管理工具或脚本自动同步共享配置

## 📝 总结

**你的需求是合理的**，使用每个模块独立的 env 文件有以下优势：

1. ✅ **模块化**：每个服务配置独立，符合微服务架构
2. ✅ **安全性**：敏感信息分散，降低风险
3. ✅ **可维护性**：配置清晰，易于查找和管理
4. ✅ **团队协作**：不同团队可以独立管理自己的配置

**推荐使用混合方案**：
- 共享配置（数据库、JWT、Redis）放在 `.env.shared`
- 服务特定配置放在各自的 `.env` 文件中
- 在 `compose-app.yml` 中使用多个 `env_file` 加载

这样既保持了配置的统一性，又实现了模块化。
